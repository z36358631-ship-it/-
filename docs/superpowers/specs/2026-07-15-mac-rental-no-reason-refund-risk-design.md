# Mac 端租号“3天无理由”与退款风控设计

## 1. 目标

将确认订单页的“启动保障险”调整为“3天无理由”，按订单支付时间、目标游戏累计运行时长和用户退款风险判定无理由退款资格。同时增加后台可配置的高频退款规则，在付款前明确提示命中用户本单不再享受无理由退款。

本次只取消高频退款用户的无理由退款权益。Steam 登录失败、游戏启动失败、账号异常等履约问题仍可申请售后。

## 2. 权益文案

确认订单页使用以下权益名称和副文案：

| 权益名称 | 副文案 |
|---|---|
| 100% 正版 | 家庭共享 官方正版 |
| 一键启动 | 开始游戏 仅需一键 |
| 永不顶号 | 游戏期间独占不限制 |
| 存档无忧 | 自动同步个人存档 |
| 3天无理由 | 游戏时长30分钟内，3天内无理由退款 |

原“启动保障险”、中国人保、保险期限、理赔期限及保险退款文案从 Demo 和 PRD 中移除。

## 3. 无理由退款规则

订单同时满足以下条件时，可选择“3天无理由”申请售后：

1. 当前时间不晚于支付成功时间加 72 小时。
2. 目标游戏累计成功运行时长不超过 30 分钟。
3. 下单时未命中高频退款规则，订单快照中的无理由退款资格为可用。
4. 订单未结束售后、未退款且仍处于允许申请售后的状态。

“3天”从支付成功时间起算；“30分钟”按订单目标游戏进程成功启动后的累计运行时长计算，下载、登录失败和启动失败不计入。

超出3天、超过30分钟或被风控取消资格时，仅隐藏或禁用“3天无理由”问题类型，并展示具体原因；履约问题类型继续保留。

## 4. 高频退款风控

### 4.1 后台配置

后台“系统设置”增加“无理由退款风控”：

- 统计周期：正整数，单位为天。
- 退款笔数：正整数，统计周期内完成的无理由退款订单数。
- 规则开关：关闭后不执行付款前限制。
- 默认演示值：30天内完成3笔无理由退款即命中。

只统计退款原因为“3天无理由”且渠道退款成功的订单；履约问题退款、审核拒绝、退款失败和仅提交未完成的申请不计入。

保存配置需二次确认并写入操作记录。规则修改只影响后续新订单，不回溯修改历史订单资格。

### 4.2 付款前判定

用户点击支付后，服务端按当前规则统计其滚动周期内的无理由退款笔数：

- 未命中：直接进入原购买确认弹窗。
- 命中：先展示退款风险确认弹窗，再进入原购买确认弹窗。

风险弹窗文案：

> 近期退款数量较多，再次购买将无法享受3天无理由退款，请确认后购买。

操作：

- “暂不购买”：关闭弹窗并停留在确认订单页。
- “确认并继续”：记录用户确认，进入原购买确认弹窗；支付成功后订单保存无理由退款资格为不可用。

## 5. 订单快照

新订单保存以下字段，历史订单不因后台规则变化而改变：

| 字段 | 说明 |
|---|---|
| `no_reason_refund_eligible` | 本单是否享受3天无理由退款 |
| `no_reason_refund_rule_version` | 下单时命中的规则版本 |
| `no_reason_refund_denied_reason` | 不可用原因，如 `frequent_refund` |
| `risk_window_days` | 下单时统计周期 |
| `risk_refund_threshold` | 下单时退款笔数阈值 |
| `recent_no_reason_refund_count` | 判定时用户近期已完成的无理由退款笔数 |
| `risk_confirmed_at` | 用户确认风险提示的时间 |
| `game_play_minutes` | 当前订单目标游戏累计运行分钟数 |
| `client_version` | 最近一次成功上号时的 Mac 客户端版本 |
| `os_version` | 最近一次成功上号时的 macOS 系统版本 |
| `device_model` | Mac 机型名称或型号标识 |
| `cpu_model` | CPU 型号 |
| `gpu_model` | GPU 型号 |
| `memory_gb` | 运行内存容量，单位 GB |

订单详情在资格不可用时展示“本单不享受3天无理由退款”，不影响履约售后入口。

## 6. 售后交互

售后问题类型增加“3天无理由”。弹窗打开时实时计算时间与游戏时长，并结合订单资格快照决定是否可选：

- 可用：平铺展示“3天无理由”，用户仍需填写问题描述后提交。
- 超过72小时：展示不可用原因“已超过支付后3天”。
- 游戏时长超过30分钟：展示不可用原因“游戏时长已超过30分钟”。
- 高频退款限制：展示不可用原因“本单购买时已取消无理由退款权益”。

后台售后列表和详情增加退款类型、订单无理由退款资格、累计游戏时长、规则版本及限制原因，审核时不得绕过订单快照。

## 7. 运营后台用户与设备信息

### 7.1 数据采集

用户每次一键上号时上报客户端版本、macOS 版本、机型、CPU、GPU 和运行内存；上号成功后写入订单最近一次成功设备快照。设备信息变化时更新快照并保留更新时间，不采集或展示硬件序列号、完整设备指纹等敏感标识。

订单期间的游戏时长只累计订单目标游戏。客户端在目标游戏成功启动后开始发送心跳，在进程退出、订单到期、退款、会话撤销或心跳超时后停止累计；重复、乱序心跳按会话和时间段去重。

### 7.2 后台列表

订单与售后列表增加两列：

- 用户/设备：首行展示脱敏用户 ID，副行展示机型、客户端版本和 macOS 版本摘要。
- 游戏时长：展示该订单期间目标游戏的累计运行时长，如“2小时18分钟”；不足1分钟显示“<1分钟”，无有效运行记录显示“未启动”。

CPU、GPU 和运行内存不直接铺在列表中，避免列宽过载，进入订单详情查看。

### 7.3 订单与售后详情

后台订单抽屉增加“用户与运行环境”区块，完整展示：

- 脱敏用户 ID。
- Mac 客户端版本。
- macOS 系统版本。
- 机型。
- CPU。
- GPU。
- 运行内存。
- 订单期间目标游戏累计时长。
- 最近一次设备快照更新时间。

字段未上报时显示 `--`，不得使用推测值。售后审核时该区块与启动三态、失败阶段、错误码和用户问题描述同时展示。

## 8. Demo 与标注

- 系统设置弹窗支持编辑规则开关、统计天数和退款笔数并确认保存。
- Demo 当前用户默认命中“30天/3笔”，用于演示付款前风险弹窗。
- 支持通过修改后台阈值演示未命中分支。
- 交互标注统一使用“触发条件 / 展示说明 / 交互说明”三段结构，并覆盖权益、风险设置、付款前弹窗、订单资格、用户设备信息、游戏时长和售后校验。

## 9. PRD 与截图

- 将启动保障相关章节改为“3天无理由退款”。
- 删除中国人保、保险期限、理赔期限和保险指标。
- 增加后台退款风控配置、订单快照、用户设备信息、订单期间游戏时长、售后资格和相关埋点。
- 重新生成受影响的确认订单、售后申请、订单详情、后台订单与设置截图，并发布新的固定 CDN 版本。

## 10. 异常与边界

- 风控接口超时：禁止静默按可退款下单；提示“退款权益确认失败，请稍后重试”，不进入支付。
- 用户确认风险后价格或库存变化：重新确认价格和库存，但保留本次风险确认结果，超时后重新判定。
- 支付失败或订单取消：不产生无理由退款资格消耗记录。
- 退款完成回调重复：同一订单只计入一次近期退款笔数。
- 游戏时长上报重复或乱序：按会话和时间段去重，不重复累计。
- 设备信息未上报或客户端版本过低：后台对应字段显示 `--`，不阻断订单履约，但记录数据缺失率。
- 用户在订单期间更换设备：后台展示最近一次成功上号设备快照，游戏时长按订单聚合，不因设备切换清零。
- 后台规则关闭：新订单默认享受3天无理由，但仍受72小时和30分钟限制。

## 11. 验收标准

1. 五项权益文案与设计一致，页面不再出现启动保障险或中国人保。
2. 后台可配置开关、天数和退款笔数，保存需确认并产生操作记录。
3. 命中用户支付前先看到风险弹窗，取消不支付，确认后进入原购买确认。
4. 命中订单保存不可享受无理由退款的快照，规则修改后历史订单不变化。
5. 未命中且支付后不超过72小时、游戏时长不超过30分钟的订单可提交“3天无理由”。
6. 超时、超游戏时长或命中风控时不能选择无理由退款，但履约售后仍可提交。
7. 后台列表和详情能看到资格、游戏时长、规则版本和限制原因。
8. 后台列表展示用户/设备摘要和订单游戏时长，详情完整展示客户端版本、macOS 版本、机型、CPU、GPU、运行内存及快照时间。
9. 缺失设备字段显示 `--`；切换设备后更新快照且订单游戏时长不清零。
10. Demo 冒烟测试、标注结构校验、Markdown 链接和截图校验全部通过。
