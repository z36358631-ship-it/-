# 盖世游戏按游戏资产分流的新手首玩设计

## 1. 文档信息

- 关联任务：`GUANWANGGAID-39 新用户引导`
- 设计日期：2026-08-26
- 适用端：盖世游戏 App，竖屏与掌机横屏
- 设计阶段：方案已确认，供后续实现计划、Demo 与 PRD 修订使用
- 核心结论：新用户不需要先理解“新手、资源、秒玩、游客模式”等产品概念，应先按自己已有的游戏资产选择路径，并在行动过程中获得必要说明，尽快完成第一次成功游玩。

## 2. 要解决的问题

### 2.1 目标用户与目标

| 用户人群 | 用户现状 | 首次目标 | 产品应提供的最短路径 |
|---|---|---|---|
| Steam 里已有游戏 | 有 Steam 账号且购买过游戏 | 找到自己拥有的游戏并启动 | Steam 登录 → 个人游戏库 → 启动游戏 |
| 手机里已有游戏文件 | 本地已有可导入的游戏资源 | 找到文件并成功导入、启动 | 扫描或手选文件 → 导入 → 启动游戏 |
| 暂时没有游戏资产 | 没有游戏文件，或没有可用 Steam 游戏 | 先真实体验一次游戏 | 国内：15 分钟秒玩；海外：现有免费游戏下载路径 |
| 暂时不想选择 | 只想先浏览产品 | 进入首页后仍知道如何开始 | 进入首页 → 复用“继续”组件承接最低门槛路径 |

“第一次成功游玩”统一定义为：游戏成功进入可接收用户输入的可玩场景。登录成功、看到游戏库、选中文件、完成导入、点击启动和进入排队都不是成功游玩。

### 2.2 当前问题

当前准备方式使用“我有游戏想玩”“我是新手，想先看看”“以后再说”进行身份式分流，存在三个问题：

1. “我是新手”与“我有游戏”并非互斥状态，用户难以准确自判。
2. “以后再说”与两条行动路径同级，约一半曝光用户直接跳过；进入首页后又缺少对未完成首玩路径的续接。
3. 各分支只记录部分入口点击，无法判断 Steam、本地文件或秒玩用户是否真正进入可玩场景。

## 3. 数据证据与边界

### 3.1 近 7 天现状

| 指标 | 数值 | 可支持的判断 |
|---|---:|---|
| 准备方式页曝光 | 51 万 | 当前入口覆盖规模较大 |
| 选择“我有游戏”或“我是新手” | 25.3 万 | 约 49.6% 用户进入行动分支 |
| 选择“以后再说” | 约 25.7 万 | 跳过率约 50.4%，入口对用户的行动指引不足 |
| 选择“我有游戏” | 18.1 万 | 有资产意向是最大已选人群 |
| 进入文件选择/扫描 | 4.6 万 | 占“我有游戏”约 25.4%，仅代表进入扫描，不代表导入或游玩成功 |
| 推算选择 Steam | 约 13.5 万 | 由 18.1 万减 4.6 万推算；无登录、游戏库或启动后续数据 |
| 推算选择“我是新手” | 约 7.2 万 | 由 25.3 万减 18.1 万推算 |
| 点击秒玩进入游戏 | 3,682 | 占“我是新手”约 5.1%；只代表入口点击，不等于成功游玩 |
| 点击秒玩“查看更多” | 3.16 万 | 占“我是新手”约 43.9%；只能说明首屏秒玩选择不足，不能判断用户不喜欢免费游戏 |

### 3.2 证据边界

- 免费游戏下载路径当前没有完整埋点，不能比较它与秒玩的成功效率。
- Steam 登录、个人库、启动和最终可玩没有完整链路，不能判断 Steam 分支的真实转化。
- 文件扫描后的识别、导入和启动没有完整链路，不能把 4.6 万当作导入成功人数。
- 秒玩“查看更多”后的选游戏、启动和可玩没有记录，不能把 3.16 万当作流失或成功。
- 本期先改进可判断性和补齐测量；不基于缺失数据承诺某一分支必然提升留存或付费。

## 4. 方案比较

| 方案 | 表现 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| A. 沿用新手/有游戏身份分流 | 继续展示“我有游戏”“我是新手”“以后再说” | 改动最小 | 状态不互斥，用户仍需理解产品概念，无法解决首页迷茫 | 不采用 |
| B. 按游戏资产直接分流 | Steam、有本地文件、暂无游戏三条主路径，浏览首页为弱入口 | 用户可凭已知事实自判；每条路径对应明确行动；便于分群测量 | 需要维护分支状态与首页续接 | 采用 |
| C. 自动识别后直接推荐 | 自动检测 Steam、本地文件或付费意愿 | 理论上操作最少 | 授权前无法识别 Steam；系统文件权限有限；不能推断付费意愿 | 不采用 |

推荐 B。它不要求新增识别能力，也不把用户先贴成“新手/老手”，而是把用户已知的资产状态直接翻译为下一步行动。

## 5. 总体体验原则

1. 先行动、后解释：首屏只让用户选择已有资产，账号、费用、下载和耗时在执行前说明。
2. 不问付费意愿：不出现“是否愿意充值”一类问题；国内无资产用户先使用已赠送的 15 分钟秒玩。
3. 失败可换路：任何分支失败或发现不符合自身情况时，均可返回并切换其他路径。
4. 不中断首页浏览：保留“先逛逛首页”，但降为文字入口，不与三条首玩路径同级。
5. 不新增首页模块：用户中断或跳过后，复用首页现有“继续”组件承接未完成路径。
6. 以可玩为终点：所有分支统一上报 `playable_ready`，避免把中间点击当作首玩成功。

## 6. 首屏设计

### 6.1 页面结构与文案

页面标题：`你现在有哪种游戏？`

辅助文案：`选择最符合你的情况，我们带你直接开始玩`

按以下顺序展示三个主选项：

| 顺序 | 主文案 | 辅助文案 | 点击去向 |
|---:|---|---|---|
| 1 | `Steam 里有游戏` | `登录 Steam，查看并启动已购买的游戏` | Steam 登录 |
| 2 | `手机里有游戏文件` | `扫描或选择文件，导入后开始游戏` | 本地游戏导入 |
| 3（国内） | `暂时没有游戏，先免费玩` | `赠送 15 分钟，选一个游戏立即开玩` | 秒玩游戏选择 |
| 3（海外） | `暂时没有游戏，先找免费游戏` | `选择免费游戏，下载后开始玩` | 现有免费游戏下载路径 |

底部使用弱化文字入口：`先逛逛首页`。

### 6.2 展示与交互

- 三个主选项使用当前准备方式页已有的可点击卡片样式，不新增顶部教程、问卷或说明弹窗。
- “先逛逛首页”使用文字按钮，视觉权重低于主选项；点击后直接进入首页，不弹二次确认。
- 首次进入不默认选中任何路径；点击主选项后直接进入对应分支。
- 从分支返回时回到本页，并保留最近一次选择的视觉反馈；用户可改选其他路径。
- 页面只描述用户已有状态，不使用“资源”“引擎”“游客模式”等内部概念。

## 7. 分人群流程

### 7.1 Steam 里有游戏

流程：

`选择 Steam 里有游戏 → 拉起 Steam 登录 → 登录成功 → 进入个人游戏库 → 选择游戏 → 发起启动 → playable_ready`

规则：

1. 登录前说明将拉起 Steam，并仅用于同步用户个人游戏库；不提前解释不影响当前操作的账号概念。
2. 登录成功后进入现有个人游戏库，不新增中转页。
3. 从该入口进入的游戏使用 Steam 启动方式。
4. 登录取消、登录失败或游戏库为空时，原页提供重试，并提供返回准备方式切换路径的能力。
5. 游戏库为空时可引导用户切换至国内 15 分钟秒玩；海外切换至现有免费游戏下载路径，不承诺云游戏。
6. 仅 Steam 登录成功不写入首次成功，直到收到 `playable_ready`。

### 7.2 手机里有游戏文件

流程：

`选择手机里有游戏文件 → 进入现有导入页 → 扫描或手动选择 → 识别文件 → 导入 → 选择/启动游戏 → playable_ready`

规则：

1. 沿用现有导入页的“扫描”和“手动选择”能力，不新增文件管理器。
2. 申请文件权限前说明用途；用户拒绝扫描权限后仍可尝试系统文件选择能力。
3. 扫描无结果、文件不支持、导入失败时保留重试与重新选择，并可返回准备方式切换路径。
4. 国内用户无可用文件时可切换至 15 分钟秒玩；海外切换至现有免费游戏下载路径。
5. 选中文件、识别成功或导入成功都不是首次成功，直到收到 `playable_ready`。

### 7.3 暂时没有游戏资产

#### 国内包

流程：

`选择暂时没有游戏，先免费玩 → 进入秒玩游戏选择 → 选择任意可用游戏 → 启动 → playable_ready → 15 分钟结束时沿用现有充值提醒`

规则：

1. 用户不需要先绑定游戏平台账号、导入文件或充值。
2. 首屏明确“赠送 15 分钟”，避免用户误解为永久免费；不在选择路径前询问充值意愿。
3. 秒玩游戏首屏和“查看更多”均沿用现有能力；补齐选择、启动和可玩的完整埋点。
4. 排队、启动失败或游戏不可用时允许重试、换游戏或返回切换路径。
5. 15 分钟结束后的充值提醒沿用现有产品规则，本期不重做计费、礼包或续费流程。

#### 海外包

流程：

`选择暂时没有游戏，先找免费游戏 → 进入现有免费游戏路径 → 查看下载大小/预计耗时 → 下载 → 启动 → playable_ready`

规则：

1. 海外当前不展示云游戏，不出现“15 分钟秒玩”、云游戏、新手礼包或实名认证相关文案。
2. 复用现有免费游戏列表、详情和下载能力，不新增海外专属游戏页。
3. 在用户确认下载前展示下载大小；可估算时展示预计耗时，不承诺固定几分钟完成。
4. 下载中断、空间不足或安装失败时沿用现有处理，并允许返回切换路径。

### 7.4 先逛逛首页

流程：

`点击先逛逛首页 → 进入首页 → “继续”组件展示首玩入口 → 用户点击 → 进入最低门槛路径或最近未完成路径`

规则：

1. 点击后直接进入首页，不弹挽留、二次确认、Toast 或教程蒙层。
2. 用户尚未选择过任何路径时，首页“继续”组件默认承接最低门槛路径：国内为 `免费秒玩 15 分钟`，海外为 `找一款免费游戏`。
3. 用户已进入过某条路径但未成功游玩时，“继续”组件承接最近一次未完成路径。
4. 用户完成首次成功游玩后，“继续”组件恢复现有的继续最近游戏逻辑。

## 8. 首页“继续”状态规则

| 用户状态 | “继续”组件主文案 | 点击结果 |
|---|---|---|
| 未选路径，国内 | `免费秒玩 15 分钟` | 进入秒玩游戏选择 |
| 未选路径，海外 | `找一款免费游戏` | 进入现有免费游戏路径 |
| Steam 登录未完成 | `继续登录 Steam` | 返回 Steam 登录 |
| Steam 已登录但未启动 | `继续从 Steam 游戏库开始` | 进入个人游戏库 |
| 文件尚未选中/扫描未完成 | `继续导入游戏` | 返回现有导入页 |
| 文件已导入但未成功游玩 | `继续启动已导入的游戏` | 进入对应游戏详情或启动位置 |
| 秒玩已选游戏但未成功游玩 | `继续免费秒玩` | 回到已选游戏的启动位置；不可用时回到秒玩列表 |
| 免费游戏下载中 | `继续下载游戏` | 返回当前下载任务或游戏详情 |
| 已有 `playable_ready` 记录 | 沿用现有文案 | 沿用现有继续最近游戏逻辑 |

状态优先级：首次成功记录 > 最近未完成路径 > 未选路径默认入口。仅保存当前用户最近一次有效路径，不并列展示多个首玩任务。

## 9. 状态保存与恢复

### 9.1 最小状态

| 字段 | 取值 | 用途 |
|---|---|---|
| `first_play_path` | `steam` / `local_file` / `instant_play` / `free_download` / `browse` | 记录最近一次选择 |
| `first_play_stage` | `selected` / `authorized` / `content_ready` / `launch_requested` / `playable` | 记录该路径最远进度 |
| `first_play_game_id` | 游戏 ID 或空 | 恢复已选游戏；不得保存账号敏感信息或本地完整文件路径到埋点 |
| `first_play_completed` | `true` / `false` | 控制首页“继续”恢复首玩或正常逻辑 |
| `updated_at` | 客户端时间戳 | 冲突时采用最近一次有效状态 |

### 9.2 恢复规则

- App 切后台、进程重启或横竖屏切换时，保留当前路径、阶段和已选游戏。
- 横竖屏切换只重排布局，不重置页面、选择、登录结果、导入任务、下载任务或滚动位置。
- 未达到 `playable` 时退出分支，进入首页后由现有“继续”组件恢复。
- 用户主动返回准备方式并改选路径时，新路径成为“最近未完成路径”；原分支业务数据不删除，但不再占用首页“继续”。
- 登录账号切换时，Steam 个人库和首玩游戏按现有账号隔离规则处理；游客转登录后只迁移非敏感的首玩完成状态。
- `first_play_completed=true` 后不再回退；之后启动失败不重新触发新手首玩引导。

## 10. 异常与切换路径

| 当前路径 | 异常 | 当前页处理 | 可切换去向 |
|---|---|---|---|
| Steam | 用户取消授权/授权失败 | 保留错误提示与重试 | 返回准备方式；国内秒玩；海外免费游戏下载 |
| Steam | 游戏库为空 | 展示真实空态，不伪造推荐为个人库 | 国内秒玩；海外免费游戏下载；本地导入 |
| 本地文件 | 权限拒绝 | 说明用途，可用时保留手动选择 | Steam；国内秒玩；海外免费游戏下载 |
| 本地文件 | 扫描无结果/文件不支持 | 保留重试、重新选择 | Steam；国内秒玩；海外免费游戏下载 |
| 国内秒玩 | 游戏不可用/排队或启动失败 | 重试或换游戏 | Steam；本地导入 |
| 海外免费下载 | 空间不足/下载或安装失败 | 沿用现有错误处理与重试 | Steam；本地导入 |
| 任一路径 | 网络中断 | 保留当前进度；联网后重试，不重复写入成功 | 返回首页，由“继续”恢复 |
| 首页续接 | 对应内容已失效 | 进入该分支可用列表或起始页 | 返回准备方式重选 |

任何异常都不得将中间状态写为 `playable`，也不得因为失败自动扣除或重新发放新手权益。

## 11. 横竖屏设计

### 11.1 竖屏

- 沿用当前手机端准备方式页结构，标题与说明在上，三个主选项纵向排列，弱化入口位于内容底部。
- 内容超出一屏时允许纵向滚动；弱化入口不得遮挡第三个主选项。
- 返回分支后恢复选项与滚动位置。

### 11.2 掌机横屏

- 沿用现有横屏视觉与导航规范；三个主选项在可用宽度内横向并列，空间不足时使用现有两列/换行规则，不压缩成不可读卡片。
- 遥控器/手柄焦点顺序为：Steam → 本地文件 → 暂无游戏 → 先逛首页；焦点切换不得触发选择。
- 横竖屏切换后焦点回到当前选项或当前主操作，不回到页面第一项。

## 12. 埋点与指标

### 12.1 统一事件

| 事件 ID | 触发时机 | 核心参数 |
|---|---|---|
| `onboarding_start_method_view` | 资产分流首屏可交互时 | `market`,`orientation`,`entry`,`experiment_id` |
| `onboarding_start_method_select` | 用户点击主路径或“先逛逛首页” | `market`,`path`,`position`,`experiment_id` |
| `first_play_path_view` | 对应分支首个页面可交互时 | `market`,`path`,`resume_source` |
| `first_play_stage_result` | 分支关键阶段产生成功或失败结果时 | `path`,`stage`,`result`,`failure_reason`,`game_id` |
| `first_play_path_switch` | 用户从当前分支改选其他路径时 | `from_path`,`from_stage`,`to_path`,`reason` |
| `first_play_home_continue_view` | 首次成功前首页“继续”组件曝光 | `path`,`stage`,`market` |
| `first_play_home_continue_click` | 点击首玩状态的“继续”组件 | `path`,`stage`,`market` |
| `game_launch_request` | 用户明确发起启动 | `path`,`game_id`,`launch_source`,`market` |
| `playable_ready` | 游戏进入可接收输入的可玩场景 | `path`,`game_id`,`launch_source`,`market`,`elapsed_ms` |

约束：

- `path` 枚举为 `steam`、`local_file`、`instant_play`、`free_download`、`browse`。
- `stage` 按分支使用 `login`、`library`、`scan`、`file_select`、`import`、`game_select`、`download`、`install`、`launch`。
- `result` 为 `success`、`failure`、`cancel`；失败原因使用受控枚举，不上传自由文本、Steam 凭证或本地完整文件路径。
- 同一启动会话生成 `launch_session_id`，`game_launch_request` 与 `playable_ready` 通过该字段关联并幂等去重。
- `elapsed_ms` 从首次点击资产路径开始，到 `playable_ready` 的耗时；恢复路径时继续使用同一首玩会话，超过现有会话有效期后新建会话。

### 12.2 分人群漏斗

| 人群 | 必看漏斗 | 关键诊断指标 |
|---|---|---|
| Steam | 首屏曝光 → 选择 Steam → 登录成功 → 个人库曝光 → 发起启动 → `playable_ready` | 登录取消/失败率、空库率、首次可玩耗时 |
| 本地文件 | 首屏曝光 → 选择本地文件 → 扫描/手选 → 识别成功 → 导入成功 → 发起启动 → `playable_ready` | 权限拒绝率、无结果率、导入失败率 |
| 国内无资产 | 首屏曝光 → 选择免费玩 → 选游戏 → 发起秒玩 → `playable_ready` | “查看更多”后启动率、排队/启动失败率、15 分钟结束后充值率 |
| 海外无资产 | 首屏曝光 → 选择免费游戏 → 开始下载 → 下载/安装成功 → 发起启动 → `playable_ready` | 下载大小分层完成率、空间不足率、首次可玩耗时 |
| 先逛首页 | 首屏曝光 → 进入首页 → “继续”曝光 → “继续”点击 → 分支进入 → `playable_ready` | 首页续接点击率、从跳过到首次可玩的转化 |

### 12.3 结果指标与护栏

主指标：

1. 新用户 24 小时首次可玩率 = 首次进入准备方式后 24 小时内产生 `playable_ready` 的去重用户数 ÷ 准备方式页曝光去重用户数。
2. 各资产人群首次可玩率 = 各路径 `playable_ready` 去重用户数 ÷ 各路径选择去重用户数。
3. 首次可玩耗时 P50/P90 = 首次路径选择到首个 `playable_ready` 的耗时。

护栏指标：

- 准备方式页直接进入首页比例。
- 分支失败率、切换率与首页续接点击率。
- 新用户次日/7 日留存率。
- 国内秒玩用户 7 日充值率、退款/投诉率；不得只以首玩率上涨判断成功。
- 海外免费下载完成率；与国内秒玩分开统计，不跨市场比较绝对值。

## 13. 明确不做

- 不做 Steam 或本地游戏资产的授权前自动识别。
- 不询问用户是否愿意充值，不新增付费意愿问卷。
- 不新增任务中心、任务卡、奖励系统、教程蒙层、挽留弹窗或二次确认。
- 不重做 Steam 登录、个人游戏库、文件扫描/选择、秒玩列表、免费游戏下载和充值流程。
- 不新增首页模块，只改变现有“继续”组件在首次成功前的内容与跳转。
- 不新增推荐算法，不根据缺失数据自动为用户判断偏好。
- 不把国内 15 分钟秒玩能力扩展到海外。
- 不修改新手权益的发放、计时、回收和充值规则。

## 14. 验收标准

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 国内新用户进入准备方式页 | 展示 Steam、本地文件、15 分钟免费玩三个主选项；“先逛逛首页”为弱化文字入口 |
| AC-02 | 海外新用户进入准备方式页 | 第三项为免费游戏下载，不出现秒玩、15 分钟、礼包或实名认证文案 |
| AC-03 | 选择 Steam | 拉起 Steam 登录；成功后进入个人游戏库，取消、失败或空库时可重试或切换路径 |
| AC-04 | 选择本地文件 | 进入现有导入页，可扫描或手选；权限拒绝、无结果和导入失败均可恢复或切换路径 |
| AC-05 | 国内选择暂无游戏 | 无需先绑定游戏平台账号、导入文件或充值，即可选游戏并使用 15 分钟秒玩 |
| AC-06 | 海外选择暂无游戏 | 进入现有免费游戏路径，下载前展示文件大小，可估算时展示预计耗时 |
| AC-07 | 选择先逛首页 | 直接进入首页，无确认弹窗；“继续”组件展示当前市场最低门槛路径 |
| AC-08 | 分支中断后进入首页 | “继续”组件承接最近未完成路径，点击回到正确阶段，不重置已完成进度 |
| AC-09 | 用户改选路径 | 新路径成为首页唯一续接路径，旧路径不与其并列展示 |
| AC-10 | 首次成功游玩 | 仅在游戏可接收输入时记录 `playable_ready`，并将“继续”恢复为现有继续最近游戏逻辑 |
| AC-11 | 中间步骤成功 | Steam 登录、个人库曝光、文件导入、下载完成和点击启动均不得单独写入首次成功 |
| AC-12 | 横竖屏切换 | 当前页面、路径、阶段、选项、滚动位置、下载/导入进度与焦点不丢失 |
| AC-13 | App 重启/切后台 | 未完成路径可由首页“继续”恢复；已完成首次成功不回退到新手引导 |
| AC-14 | 完整埋点 | 五类入口均可从首屏曝光追踪至 `playable_ready`，启动请求与可玩事件可通过会话 ID 关联 |
| AC-15 | 数据口径 | 免费游戏无埋点、扫描入口和秒玩点击不得被报表标记为成功游玩 |
| AC-16 | 范围控制 | 不出现新增任务中心、教程蒙层、推荐算法、新页面或海外云游戏能力 |
