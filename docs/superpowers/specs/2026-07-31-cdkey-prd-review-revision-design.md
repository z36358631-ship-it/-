# CDKEY 售卖需求评审修订设计

## 1. 目标

根据 2026 年 7 月 31 日 CDKEY 需求评审结论，产出一份可供产品、开发和测试继续评审的修订版 PRD。修订版以评审结论为准，清除旧 PRD 中与供应商 API 供货模式冲突的设计，并明确已确定规则、异常处理、验收标准和上线阻塞项。

采用“原始材料留档 + 新增评审修订版”的方式：

1. 在新 PRD 的版本信息中保留原始 V1.0 记录，并追加 2026 年 7 月 31 日评审修订记录。
2. 旧 PRD 与评审结论冲突时，以本次评审结论为准，并在版本变更摘要中列出废止规则。
3. 已明确的结论写入正文和验收标准；存在争议或需外部确认的内容进入“必须确认（阻塞上线）”。
4. 不把会议中的口误、讨论过程或未形成结论的建议写成正式规则。

## 4. 已确认的产品规则

### 4.1 范围与业务模式

- 本期仅覆盖盖世游戏国内包的 CDKEY 售卖闭环，不支持海外包购买。
- 用户可在端内完成浏览、选择商品、支付、获取 CDKEY、直接激活或后续一键激活。
- 本期采用供应商 API 供货模式。后台创建 SKU 并关联供应商商品 ID，价格、活动价、库存、取码和激活能力以供应商接口为准。
- 废止旧 PRD 中“后台维护零售价、批量导入本地 CDKEY、配置本地库存预警”的实施方案。
- CDKEY 盲盒、玩家寄售和售卖属于后续可能方向，不纳入本期。

### 4.2 商品价格与卡片展示

- 同一游戏存在多个可售 SKU 时，列表、榜单、搜索和其他商品卡片展示当前可购买 SKU 的最低价格。
- 不展示折扣百分比，不展示“史低”等标签。
- 供应商返回有效活动价时，展示活动价并显示固定标签“特惠”；无有效活动价时仅展示价格。
- 详情页和确认订单页必须展示 SKU、适用范围、价格及活动信息，支付金额以创建订单时的价格快照为准。
- 价格或库存接口异常时，不允许进入支付；商品展示为暂不可购买并提供重试入口。

### 4.3 登录、实名与未成年人校验

- 游客触发购买时必须先转为正式登录账号；登录完成后返回原商品继续操作。
- 小米渠道用户在下单前执行未成年人校验。识别为未成年人时直接拦截，不创建订单、不进入支付，也不采用消费金额限额。
- 小米渠道拦截提示为“未成年人暂不支持购买此商品”。
- 支付前服务端再次执行小米渠道未成年人校验，避免客户端绕过或校验结果过期。
- 小米渠道身份状态未知或校验接口失败时按失败关闭处理，禁止继续下单，并提示“身份信息校验失败，请稍后重试”。
- 是否对全部国内渠道强制实名认证、成年校验，以及实名信息是否用于跨境申报，尚未形成结论，列为上线阻塞项。

### 4.4 SKU、发货方式与账号校验

- SKU 名称、版本和适用范围由供应商商品信息决定；无可选版本时不展示多选控件。
- 发货方式包括“直接激活”和“仅 CDKEY”。
- 选择“直接激活”时必须选择 Steam 收货账号；选择“仅 CDKEY”时不展示收货账号。
- 直接激活只能选择区服符合 SKU 适用范围且未拥有该游戏的 Steam 账号。
- 默认账号不适用时清空默认选择，并在账号区域提示原因；不允许使用不适用账号提交支付。
- 用户已拥有游戏或没有可用账号时，可切换 Steam 账号或改选“仅 CDKEY”，系统不得擅自切换发货方式。
- “仅 CDKEY”允许重复购买。如用户当前盖世账号已绑定 Steam 账号且系统可识别其游戏库，检测到该账号已拥有游戏时，在确认订单页提示重复购买风险，但不拦截购买。
- 两种发货方式分别展示后台可配置的说明文案；确认支付前再次展示商品、SKU、适用范围、发货方式、收货账号和实付金额。

### 4.5 支付与供应商履约

- 国内包支持微信支付和支付宝支付，不提供海外支付方式。
- 待支付订单有效期沿用 30 分钟；待支付期间只保留订单，不锁定供应商 CDKEY 库存。
- 支付成功后调用供应商取码接口。取码成功后，根据用户选择进入发码或直接激活流程。
- 供应商接口调用必须使用订单号作为幂等键，避免超时重试造成重复取码、重复激活或重复退款。
- 用户支付成功后出现库存不足、取码失败或供应商接口不可用，系统自动发起原路退款，不要求用户申请。
- 自动激活失败时保留已取得的有效 CDKEY，订单进入待激活状态；用户可重试激活或进入订单详情复制 CDKEY。
- 直接激活成功后跳转游戏库对应游戏；用户关闭结果页后仍可从订单中心查询履约结果。

### 4.6 订单与 CDKEY 展示

- “我的”页面提供订单中心入口。
- 进入订单中心时，如存在待支付订单则默认进入待支付页；不存在待支付订单时默认进入全部订单。
- 客户端展示状态至少覆盖：待支付、履约中、激活中、待激活、已完成、已取消、退款中、已退款、退款失败。
- “仅 CDKEY”发货成功后在订单详情明文展示 CDKEY，并提供复制和一键激活入口。
- “直接激活”订单在订单详情保留本次使用的 CDKEY 记录和履约结果；激活失败时提供复制和重试入口。
- 复制成功提示“已复制”。按钮点击后应防重复操作，网络异常时显示失败原因和重试入口。

### 4.7 退款与逆向流程

- 支付成功但未完成发货的库存不足、取码失败或接口异常订单，由系统自动原路退款。
- 后台对除待支付外的已付款订单保留人工退款入口；运营审核后决定同意或拒绝。
- “CDKEY 已展示或已激活原则上不支持退款”必须在确认订单前展示，但不得覆盖未履约、未成年人保护或其他法定退款情形。
- “仅 CDKEY”订单人工退款成功后，供应商支持回收时先作废或回收卡密；客户端不再展示明文，并隐藏复制和一键激活入口。供应商无法回收时记录坏账并按商务协议归责。
- “直接激活”订单完成激活后的例外退款属于不可逆履约场景，后台保留退款能力，已消耗 CDKEY 不执行回收；损失按供应商协议和内部审批结果记录。
- 退款不删除订单，订单保留并展示“已退款”状态。

### 4.8 后台能力

- 后台 SKU 必须关联盖世游戏的游戏 ID、SKU 版本、适用范围、供应商和供应商商品 ID。
- 后台不维护本地 CDKEY 明细，不提供批量导码、明文查看、本地库存删除和本地库存预警能力。
- 后台展示供应商同步的当前价格、活动价、库存状态和最近同步时间。
- 后台支持分别配置确认订单提示、两种发货方式说明和订单详情提示。
- 后台订单页展示支付、取码、激活和退款结果，并保留人工退款操作及操作日志。

## 5. 状态与数据流设计

### 5.1 主流程

1. 客户端获取供应商商品聚合数据并展示最低可售价格。
2. 用户进入详情页，选择 SKU、发货方式和适用账号。
3. 客户端完成登录、渠道未成年人及账号适用性前置校验。
4. 服务端创建带价格快照的待支付订单。
5. 支付成功后服务端调用供应商取码接口。
6. 仅 CDKEY 订单完成发码；直接激活订单继续调用激活能力。
7. 履约失败按失败类型进入待激活或自动退款流程。

### 5.2 状态流转

|当前状态|触发事件|条件|下一状态|失败处理|
|---|---|---|---|---|
|待支付|支付成功|支付回调校验通过|履约中|重复回调按订单号幂等处理|
|待支付|30 分钟到期|未支付|已取消|释放订单，不涉及供应商库存|
|履约中|取码成功|仅 CDKEY|已完成|保存卡密并开放复制、一键激活|
|履约中|取码成功|直接激活|激活中|保存卡密并调用激活能力|
|履约中|取码失败|缺货、接口失败或超时达到重试上限|退款中|自动发起原路退款|
|激活中|激活成功|供应商返回成功|已完成|记录结果并跳转游戏库|
|激活中|激活失败|CDKEY 仍有效|待激活|开放重试和复制入口|
|退款中|退款成功|支付渠道确认退款|已退款|按发货方式处理卡密展示|
|退款中|退款失败|支付渠道返回失败|退款失败|告警并转人工处理，禁止重复退款|

## 6. 必须确认的上线阻塞项

1. 实名与跨境合规：香港收款主体是否构成跨境交易，是否必须采集实名信息、向海关申报，以及个人信息处理和传输方案。
2. 其他渠道未成年人规则：除小米渠道外，是否强制成年校验，使用何种可信数据源，以及校验失败时的处理方式。
3. 供应商与接口：最终供应商、报价/库存/取码/激活/查询/作废接口契约、超时策略、测试环境和 SLA。
4. 商务与退款责任：缺货、错码、接口异常、未成年人退款、卡密已展示和已激活不可回收时的退款责任与坏账承担。
5. 自动退款能力：支付渠道原路退款的时效、失败重试次数、人工接管机制和用户通知方式。

以上事项未确认时可以继续完成产品和技术设计，但不得作为可上线状态验收通过。

## 7. PRD 结构

修订版 PRD 按以下结构输出：

1. 版本信息。
2. 背景、目标、成功指标、范围与不做事项。
3. 用户场景、核心体验路径和业务流程。
4. C 端详细规则：商品展示、详情与确认订单、支付履约、订单中心、退款。
5. B 端详细规则：SKU 映射、供应商数据、运营文案、订单和退款。
6. 状态流转、系统集成、非功能需求和异常降级。
7. 埋点事件与参数。
8. 运营准备、验收标准和待确认项。

## 8. 验证要求

- 文档自检必须确认旧 PRD 的本地导码、本地定价、折扣百分比和“史低”规则已全部移除。
- 每条评审结论至少在正文或验收标准中出现一次。
- 必须覆盖小米渠道未成年人在下单前和支付前被拦截的用例。
- 必须覆盖支付后缺货、供应商接口超时、重复支付回调、重复取码、激活失败、自动退款失败和退款后卡密处理。
- 必须检查国内包与海外包差异，海外包不得出现购买入口。
- Markdown 标题、表格和列表需可直接导入飞书。

## 9. 三视角快速评审结论

- 用户视角：方案可用；必须明确账号区服、已拥有游戏、重复购买和不可退款提示，避免用户付款后才发现限制。
- 开发视角：旧 PRD 的本地库存模式与供应商 API 模式冲突；修订版必须以 API 模式为唯一实施基线，并补齐价格快照、幂等、超时和状态流转。
- 商业视角：实名跨境、供应商协议和退款坏账责任是上线硬门槛；相关内容已列为阻塞项，不在本次文档中擅自定论。
