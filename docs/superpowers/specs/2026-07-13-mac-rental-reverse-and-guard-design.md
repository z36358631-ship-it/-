# Mac 租号逆向流程与游戏拦截设计

## 1. 目标

在现有 `Mac端租号功能-标注版.html` 中补齐支付后履约、一键上号、非租号游戏安装/启动拦截、用户退款和后台退款/资源回收闭环。

## 2. 范围

### 2.1 新增 Mac 页面

| 页面 | 用途 |
|---|---|
| 订单详情 | 统一承载剩余时长、一键上号、续租、申请售后/退款及处理进度 |
| 履约与上号 | 展示支付成功、分配账号、Steam 登录、存档处理和游戏启动步骤 |
| 安装/启动拦截 | 当租赁账号尝试下载、安装或启动非当前订单游戏时，阻断操作并提供安全出口 |
| 售后/退款申请 | 选择问题类型、展示退款资格、填写问题和提交诊断信息 |
| 退款详情 | 展示待审核、退款中、已退款、已拒绝、退款失败或资源释放异常 |

### 2.2 扩展后台能力

保留现有“订单与售后”页，新增订单/售后详情抽屉、退款处置步骤、渠道退款结果、账号解绑/释放结果和异常处理。不再将点击“退款”直接改为已退款。

## 3. 正向履约流程

```text
支付成功
  -> 分配同游戏/同版本可租账号
  -> 创建上号会话
  -> Steam 登录
  -> 校验目标 AppID 是否属于当前订单
     -> 否：进入安装/启动拦截页
     -> 是：检查游戏安装与账号登录要求
        -> 未安装：安装确认
        -> 已安装：处理云/本地存档与 Steam 离线状态
  -> 启动游戏
  -> 到期/退款/强制结束后清理 token 并释放账号
```

履约页使用稳定的步骤器，不通过 Toast 代替过程。每个步骤支持成功、进行中、失败和等待用户操作状态。

## 4. 非租号游戏拦截

### 4.1 拦截范围

租赁账号会话有效期内，对以下操作执行相同 AppID 白名单校验：

- 开始下载。
- 创建或继续安装任务。
- 启动已安装的游戏。
- 通过 Steam 快捷方式、命令行或本地执行文件启动。

白名单包含当前订单的主游戏 AppID、运行必需的官方 DLC/共享组件及运营审核通过的附属 AppID。无法识别、校验超时或不在白名单时默认拦截。

### 4.2 拦截页内容

- 标题根据场景显示“已拦截非租赁游戏安装”或“已拦截非租赁游戏启动”。
- 展示当前租赁订单/允许游戏、被拦截游戏、目标 AppID、操作类型和拦截原因。
- 安装场景立即暂停并从下载队列移除未授权任务；启动场景不创建游戏进程。
- 主操作“返回当前租赁游戏”，次操作“切换我的 Steam 账号”，风险操作“结束租赁并释放账号”。
- 切换个人账号后允许用户重新发起原操作，但不自动恢复被拦截任务。

### 4.3 审计与风控

每次拦截记录 orderId、脱敏 accountId、deviceId、允许 AppID、目标 AppID、操作类型、拦截原因和时间。同一设备/订单短时间多次拦截需在后台标记风险，但不展示或记录账号凭据。

## 5. 退款逆向流程

```text
订单详情 -> 申请售后/退款
  -> 选择“24 小时内启动失败”等问题
  -> 系统校验订单、支付、启动记录和时间窗口
     -> 不符合：展示不可自助退款原因，保留转人工售后
     -> 符合：提交退款申请
  -> 后台审核
     -> 拒绝：返回原因，订单继续履约
     -> 通过：发起原路退款
  -> 渠道退款成功
  -> 失效上号会话与租赁 token
  -> 解绑订单与 Steam 账号
  -> 检测后释放账号；失败则转异常库存
  -> 订单/退款详情展示最终结果
```

退款、订单结束、上号权限失效和账号释放为一个可补偿的编排流程。任一步失败时不伪造“全部成功”，保留 operationId 供后台重试和审计。

## 6. 共享状态模型

### 6.1 订单

`PENDING_PAYMENT -> ALLOCATING -> RENTING -> AFTER_SALES_REVIEW -> REFUNDING -> REFUNDED`

异常分支：`ALLOCATION_FAILED`、`REFUND_REJECTED`、`REFUND_FAILED`、`RESOURCE_RELEASE_FAILED`。

### 6.2 账号

`RENTABLE -> OCCUPIED -> RELEASING -> RENTABLE`，释放或健康检测失败转 `ABNORMAL`。

### 6.3 上号会话

`CREATED -> ACCOUNT_ASSIGNED -> LOGGING_IN -> LOGGED_IN -> LAUNCHING -> PLAYING -> EXPIRED/REVOKED`。

拦截事件不改变订单主状态，但记录在当前上号会话下。

## 7. Demo 交互编排

1. 模拟支付成功后进入履约页，而不是直接跳订单列表。
2. 履约页可切换“正常启动”、“非租赁游戏安装”和“非租赁游戏启动”三个演示分支。
3. 订单列表“查看详情”进入订单详情；“申请售后”进入售后/退款申请。
4. 提交退款申请后，订单与后台工作台同步显示待审核。
5. 后台审核通过后演示渠道退款、账号解绑/释放和审计记录，客户端退款详情同步变为已退款。

## 8. 标注覆盖

新页面继续使用交互标注和异常/边界标注，至少覆盖：

- 支付成功但账号分配失败。
- Steam 登录失败和上号会话超时。
- 非租赁游戏下载/安装/启动。
- AppID 无法识别或校验服务不可用。
- 24 小时退款资格不符合。
- 重复退款、渠道退款失败和账号释放失败。

## 9. 验证

- 新增的 Mac 页面全部可从左侧流程导航直接访问。
- 正常下单可从支付走到上号/启动成功。
- 安装和启动任一非白名单 AppID 都进入拦截页，原操作不继续。
- 退款申请、后台审核、渠道退款和账号释放能够前后台联动。
- 所有新标注 ID 唯一且存在目标，现有 smoke test 扩展覆盖新页面和关键分支。
- 只修改组合 demo HTML，不修改六个原始 Mac 页面。
