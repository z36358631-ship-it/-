# Mac 租号 Steam 分阶段登录助手设计

## 1. 目标

将现有“Steam 登录页 + 盖世登录助手左右双栏”改为低侵入的分阶段辅助流程：Steam 登录页保持主界面，盖世仅提供可收起的小型浮动助手；先协助填写账号、密码，用户提交后再按需获取 Steam Guard 验证码。

## 2. 已确认方案

采用“两阶段、非模态、显式推进”：

1. 打开手动登录后，启动或聚焦 Steam 登录页。
2. 页面右上角出现可拖动、可收起的盖世登录助手，不挤压 Steam 页面。
3. 第一阶段只展示账号、密码和复制操作。
4. 用户在 Steam 输入账号、密码并点击登录后，在助手点击“账号密码已输入，获取验证码”。
5. 助手原位切换为验证码阶段，此时才向服务端请求 Steam Guard 验证码。
6. 验证码阶段不再同时展示账号和密码，只展示验证码、倒计时、复制和刷新。
7. 登录成功以 Steam 会话或后续下载、启动校验为准，不以按钮点击直接判定成功。

## 3. 界面设计

### 3.1 Steam 登录页

- 保持完整登录页面，不再使用左右等宽双栏。
- 账号和密码输入框属于 Steam 界面，盖世不注入内容、不模拟坐标点击。
- Steam 进入验证码页后，用户从浮动助手复制验证码并粘贴。

### 3.2 盖世登录助手

- 默认展示为右上角小型浮动卡片，宽度约 300–320px。
- 卡片采用盖世深色视觉、轻边框与轻阴影，视觉层级低于 Steam 登录表单。
- 支持拖动、收起；收起后仅保留“登录助手 · 当前步骤”的胶囊入口。
- 展开时一次只展示当前阶段所需信息。
- 应用失焦、订单失效、退款、换号或关闭助手后，立即隐藏明文并清理验证码。

### 3.3 状态内容

| 状态 | 展示内容 | 用户操作 |
|---|---|---|
| 账号密码 | 当前租赁账号、密码、查看/复制按钮 | 输入 Steam 后点击“账号密码已输入，获取验证码” |
| 获取中 | 验证码请求状态 | 等待服务端返回 |
| 验证码 | 五位验证码、剩余有效时间 | 复制验证码；失效后刷新 |
| 验证中 | 不展示敏感凭据 | 等待 Steam 登录结果 |
| 成功 | “Steam 已登录”短反馈 | 助手自动关闭 |
| 失败 | 当前失败原因 | 返回账号密码或重新获取验证码 |
| 已收起 | 登录助手名称与当前步骤 | 点击重新展开 |

## 4. 状态机

`IDLE → PRIMARY_READY → GUARD_LOADING → GUARD_READY → AUTH_PENDING → DONE`

异常状态：

- `ORDER_INVALID`：订单已到期、退款、换号或凭据被回收，关闭助手并清理敏感信息。
- `CODE_EXPIRED`：验证码过期，保留“获取新验证码”操作。
- `FAILED`：登录失败，按失败类型返回账号密码阶段或验证码阶段。
- `CLOSED`：用户关闭助手，仅关闭当前展示，不改变订单与账号绑定。

## 5. 实现边界

- MVP 不申请 macOS 辅助功能或屏幕录制权限。
- MVP 不识别 Steam CEF 页面控件，不自动填充账号、密码或验证码。
- 仅检测 Steam 进程/窗口是否打开；无法聚焦时提示用户进入 Steam 登录页。
- 验证码由用户显式操作后按需请求，客户端不得保存 Steam Guard shared secret。
- 自动识别 Steam Guard 页面可作为后续增强，高置信识别失败时仍回退到手动按钮。

## 6. 数据与埋点

- 记录助手打开、收起、重新展开。
- 记录账号复制、密码复制、验证码请求、验证码返回、验证码复制和刷新。
- 记录手动登录最终成功、失败及失败阶段。
- 不记录账号、密码、验证码明文。

## 7. 异常处理

- 验证码请求失败：保留当前阶段，显示“验证码获取失败，请重试”。
- 验证码过期：清空旧验证码并显示“获取新验证码”。
- Steam 未打开：提示“Steam 未打开，请先启动 Steam”，不阻塞助手查看。
- 凭据授权失效：立即关闭助手并提示“登录信息已失效，请重新取号”。
- 网络中断：账号密码仍可查看与复制；验证码请求不可用并允许重试。

## 8. 快速评审结论

- 用户视角：分阶段展示符合“先账号密码、后验证码”的真实流程，并减少敏感信息暴露。
- 开发视角：显式推进不依赖辅助功能权限和 Steam 页面识别，兼容性最稳定。
- 商业视角：改动集中在手动登录助手，不扩大业务范围，可直接降低手动登录放弃率。

## 9. 自检

- 无账号、密码、验证码同屏展示。
- 无左右双栏挤压 Steam 登录页。
- 无点击按钮即判定 Steam 登录成功。
- 无自动填充、坐标点击或屏幕识别依赖。
- 无 `TODO`、`TBD` 或待定交互。
