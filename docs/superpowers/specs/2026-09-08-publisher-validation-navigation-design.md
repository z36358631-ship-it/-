# 发布校验反馈与错误定位设计

## 目标

解决开发者提交上架审核后反馈不明显、难以定位缺失项的问题，同时避免向用户暴露 `activeVersion` 等内部字段名。

## 范围

- 仅修改开发者端 Demo 02 的版本发布页。
- 不改变必填规则、资质门禁、提交接口、审核状态和发布流程。
- 不修改 Demo 01 和运营审核后台 Demo 09。

## 页面表现

### 模块缺失数

版本发布页五个定位项分别显示缺失必填数：

- 游戏资料：合并基础信息、分类与平台、开发者信息、游戏素材、其他设置。
- PC 包体：统计包体相关缺失项。
- 商品与 SKU：统计商品、定价与包体关联缺失项。
- 发行设置：统计发行区域、兴趣标签、发行状态和生效时间缺失项。
- 资质认证：统计当前发行区域适用的资质缺失项。

数量为零时不显示角标。角标数量、顶部“还差 N 项”和缺失清单使用同一次校验结果。

### 提交失败定位

点击“提交上架审核”后：

1. 校验全页并标记全部错误字段。
2. 若存在错误，展开“请补充以下信息”。
3. 页面完成重绘后，滚动并聚焦首个错误字段。
4. 用户点击缺失清单或模块定位项，可继续定位其他问题。

页面同时只能聚焦一个字段，不依次自动跳转多个字段。

### 资质错误

- 缺失清单不显示 `activeVersion`，不暴露内部字段名。
- 资质错误继续阻断提交，并计入“资质认证”角标。
- 提交失败时若首错为资质，直接定位资质模块；模块内展示业务文案和填写入口。

## 实现约束

- 将现有九类校验 section 显式归并为五个定位模块。
- 角标接入现有摘要增量更新，字段修改后立即刷新数量和显示状态。
- 中英文均提供可读的数量说明和无障碍标签。
- 不新增弹窗、Toast、页面或额外确认步骤。

## 验收

1. 初始缺失状态下，五个定位项的角标之和等于顶部“还差 N 项”。
2. 修复某模块最后一个错误后，该模块角标立即消失。
3. 点击提交后自动展开缺失项，并定位首个错误字段。
4. 缺失清单中不出现 `activeVersion`。
5. 仅缺资质时，“资质认证”显示角标，提交后定位资质模块且仍阻断提交。
6. 中英文切换后计数、文案和定位结果一致。
