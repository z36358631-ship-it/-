# Android 首页与搜索原生广告 Demo 设计

> 日期：2026-07-20
>
> 状态：已完成方案确认，待书面规格复核
>
> 目标文件：`demos/Android广告接入-交互标注版.html`

## 1. 目标与范围

在现有 Android 广告交互标注 Demo 中调整两个原生广告资源位：

1. 重构 `H1` 首页原生广告，使广告只在首页第二屏出现，并支持横竖屏真实滚动。
2. 新增 `S1` 搜索结果原生广告，按确定的列表位置和批次规则混入搜索结果。
3. 删除首页中的“新人福利”图标、标签和入口。
4. 同步运营后台的投放配置、A/B 测试和效果统计展示。

本次不改变 `O1`、`C1`、`G1`、`Q1`、`L1` 的业务规则，不新增广告平台，不调整后台频控模型。

## 2. 实现方向

采用真实 HTML/CSS 内容流，不在原截图上遮盖或绝对定位拼接广告。首页和搜索页使用独立的可滚动内容层；横竖屏共用内容数据，根据方向切换排版。这样可以稳定演示第二屏、列表插入、方向切换和滚动位置恢复。

## 3. H1 首页第二屏原生广告

### 3.1 通用规则

- Demo 提供“竖屏”和“横屏”切换。
- 首页设备容器内部可以上下滚动，外部标注页结构保持不变。
- 第一屏保持盖世首页自然内容，不展示商业广告。
- 广告进入第二个设备视口范围后才可见。
- 页面中不显示“新人福利”图标、悬浮礼物、橙色标签或对应入口。
- 广告加载失败时直接显示自然内容，不保留空白卡位。
- 点击广告打开现有模拟广告落地页；关闭后恢复原方向和原滚动位置。
- 广告卡持续显示高对比“广告”标识，不使用“编辑精选”“新人福利”等自然推荐语义。

### 3.2 竖屏布局

- 第二屏插入一张全宽大图原生游戏广告卡。
- 卡片宽度与首页主要内容卡左右边界对齐。
- 卡片包含游戏横图、游戏名称、简短类型信息、评分和“广告”标识。
- 广告卡作为页面内容流的一部分，不悬浮、不遮挡底部导航。

### 3.3 横屏布局

- 第二屏维持三列游戏卡网格。
- 广告占三列中的一格，宽度约为内容区的三分之一。
- 广告卡的圆角、图片比例、标题和评分基线与自然游戏卡一致。
- “广告”标识固定显示在卡片安全区内，不被图片裁切或标题覆盖。

## 4. S1 搜索结果原生广告

### 4.1 页面布局

- 新增独立用户端资源位 `S1 · 搜索结果原生广告`。
- 竖屏参考用户提供的搜索综合页和游戏结果页：顶部包含返回、搜索框和分类 Tab，内容按单列或双列自然结果展示。
- 横屏沿用盖世横屏搜索视觉：顶部搜索区、分类 Tab 和游戏卡网格。
- 两个方向均支持真实上下滚动和“加载下一批”演示。

### 4.2 首批位置规则

- 列表位置包含自然结果和广告，不是“20条自然结果之外再加3条广告”。
- 首批共 20 个展示位置，其中第 `2`、`8`、`20` 位固定为广告。
- 因此首批由 17 条自然结果和 3 条广告组成，广告密度为 15%。
- 第 2 位广告紧跟第 1 条自然结果之后。

### 4.3 后续批次规则

- 第 20 位之后，每新增一批仍为 20 个展示位置，其中包含 3 条广告。
- 每批广告位置随机生成且互不重复。
- 同一批次内广告不得相邻。
- 新一批第一个位置与上一批最后一个位置不得形成广告首尾连排。
- 随机结果按“搜索词 + 批次号”缓存；重绘、切换标注或方向切换时不得改变已生成位置。
- 重置 Demo 时清除缓存并重新生成后续批次位置；首批 `2/8/20` 永远不变。

### 4.4 广告卡规则

- 广告卡沿用所在方向的自然游戏结果形态，避免额外弹窗或悬浮层。
- 广告卡持续显示高对比“广告”标识。
- 广告卡不得使用自然评分来源、榜单名次、编辑精选或新人福利标签伪装平台推荐。
- 点击广告打开模拟广告落地页；关闭后恢复搜索词、分类、批次和滚动位置。
- 无填充时由自然结果补位，列表总位置连续，不显示空白或失败文案。

## 5. 运营后台同步

- 投放配置新增 `S1 · 搜索结果原生广告`。
- `H1` 的平台/方向由“Android 竖屏”改为“Android 横竖屏”。
- `S1` 支持国内/海外分别配置用户范围、投放比例、频率和状态。
- A/B 测试可以选择 `S1`，并保留无广告对照组。
- 效果统计新增 `S1` 行，并展示第 2、8、20 位的曝光、点击率和收入拆分。
- 搜索广告护栏至少包含搜索退出率、自然结果点击率和次日留存变化；达到后台阈值时标红并允许停投。

## 6. 交互标注

### 6.1 H1

| 类型 | 说明 |
|---|---|
| 触发条件 | 用户进入首页，命中地区、人群、频控、实验和广告填充规则，并向下滑动到第二屏。 |
| 展示说明 | 竖屏展示全宽大图卡；横屏在三列游戏网格中展示一张三分之一宽卡。 |
| 交互说明 | 页面可上下滚动；点击广告进入落地页，关闭后回到原滚动位置。 |
| 异常与边界 | 无填充时自然内容补位；第一屏、底部导航和新人福利均不承载广告。 |

### 6.2 S1

| 类型 | 说明 |
|---|---|
| 触发条件 | 用户提交搜索并进入结果页，命中地区、人群、频控、实验和广告填充规则。 |
| 展示说明 | 首批第 2、8、20 位为广告；后续每批 20 位随机 3 条，广告不相邻。 |
| 交互说明 | 页面支持横竖屏和加载下一批；点击广告进入落地页，返回后列表位置不变。 |
| 异常与边界 | 无填充由自然结果补位；随机位置按搜索词和批次缓存；广告始终明确标识。 |

## 7. 验收标准

1. 用户端导航同时存在 `H1` 和 `S1`，名称与后台一致。
2. `H1` 横竖屏均能在设备容器内真实滚动，第一屏无广告，第二屏才出现广告。
3. `H1` 竖屏广告为全宽大图卡，横屏广告只占三列网格的一格。
4. 横竖屏首页均无“新人福利”图标、标签和入口。
5. `S1` 首批第 2、8、20 位准确显示广告，其余 17 位为自然结果。
6. `S1` 加载下一批后每 20 位恰有 3 条广告，位置随机、不重复、不相邻，且不与上一批首尾连排。
7. 方向切换或重新渲染不会改变已生成的搜索广告位置。
8. 广告无填充时不留空白，内容流仍连续。
9. 点击 H1/S1 广告并关闭落地页后，页面方向、内容批次和滚动位置保持不变。
10. 运营后台投放配置、A/B 测试和效果统计均出现 `S1`，`H1` 显示为 Android 横竖屏。
11. 具体交互侧栏分别列出触发条件、展示说明、交互说明以及异常与边界。
12. 原有其他资源位和后台三个页面仍能正常切换与交互。

## 8. 风险控制

- 搜索第 2 位曝光靠前，Demo 必须以明显“广告”标识降低误导风险。
- 15% 是当前确定的演示密度，不代表默认全量配置；正式上线仍由后台和 A/B 实验控制。
- 搜索广告效果必须按第 2、8、20 位分别统计，避免高曝光位置掩盖后置广告的真实表现。
- 正式放量以搜索退出率、自然结果点击率和留存护栏判断，不以广告点击或流水单独决策。
