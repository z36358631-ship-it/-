# 发行人计划发布与兑换实名认证门槛设计

## 1. 结论

发布任务和兑换京东卡统一增加实名认证前置校验：

- 点击“发布任务”时，未实名用户立即拉起实名认证弹窗；实名成功后进入创建任务页。
- 点击可兑换商品时，未实名用户立即拉起实名认证弹窗；实名成功后恢复该商品的兑换确认弹窗。
- 实名成功只恢复用户原动作，不自动提交任务、不自动兑换或扣减盖世币。
- 已实名用户沿用原流程；任务提交接口和兑换接口仍需再次校验实名状态，不能只依赖前端状态。

## 2. 交互与异常

| 场景 | 处理规则 |
|---|---|
| 未实名点击发布任务 | 展示“完成实名认证”；确认实名成功后进入创建任务页，取消则留在原页。 |
| 实名状态在填写期间失效 | 点击“提交并进行机器审核”时再次拦截；实名成功后保留已填写内容，由用户再次提交。 |
| 未实名点击可兑换商品 | 展示“完成实名认证”；确认实名成功后打开原商品兑换确认弹窗，用户仍需再次点击“确认兑换”。 |
| 实名状态在确认期间失效 | 兑换请求由服务端拒绝，不创建订单、不预占卡密、不扣减盖世币，并重新拉起实名认证流程。 |
| 实名失败或取消 | 不进入创建页、不打开兑换确认弹窗、不产生资产或订单变化。 |

## 3. 三视角快速审查

- 用户视角：在投入填写任务或确认兑换前告知门槛，减少完成操作后才被拦截的挫败；认证后恢复原意图，不要求重新寻找入口或商品。
- 开发视角：入口校验改善体验，服务端提交校验保证安全；恢复兑换时只打开确认弹窗，避免认证回调造成误扣币。
- 商业视角：发布与兑换均关联任务资金、奖励资产和履约，统一实名主体便于限次、风控、审计和争议处理，同时不阻止未实名用户浏览任务与商品。

## 4. 验收口径

1. 未实名点击两个发布入口均出现实名认证弹窗，认证成功后进入创建任务页。
2. 未实名点击可用京东卡商品出现实名认证弹窗，认证成功后出现该商品兑换确认弹窗。
3. 实名成功后不会自动提交任务、自动生成兑换订单或扣减余额。
4. 已实名用户点击发布与兑换时不增加额外步骤。
5. PRD、C 端 Demo、内嵌维护脚本、离线交互测试和公网点击测试使用同一口径。
