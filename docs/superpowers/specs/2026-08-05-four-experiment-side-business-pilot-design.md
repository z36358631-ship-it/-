# 四实验副业真实试投设计

## 1. 决策结论

本轮同时验证四个独立实验，但使用一套发布、埋点和日报底座：

1. 《九格异兽》：横屏、10–12 分钟、山海异兽题材的轻量单人自走棋。
2. 《纸镇失控》：竖屏、8–10 分钟、原创民俗纸境题材的主动塔防肉鸽。
3. AI 产品部部署服务：为产品经理、创业者和小团队安装中文 AI 产品工作流。
4. 48 小时可玩验证冲刺：把产品或游戏想法制作成可操作 H5、需求说明和评审报告。

四个实验部署在新的个人 Cloudflare 项目中，不使用现有“盖世游戏”官网域名、仓库、品牌、用户数据或内部业务材料。四个实验首轮均为需求验证，不接真实支付，不虚构订单、玩家、收入或评价。

### 1.1 身份互换后的创业判断

如果由 AI 以郑群超的现实约束独立决策，不应把全部回款希望压在消费者游戏上：

- 两款游戏承担“玩法与传播”验证，具备较高上限，但流量和付费不确定。
- 两套产品化服务承担“更快回款”验证，利用现有产品、PRD、Demo、AI 团队和游戏制作能力出售明确结果。
- 内容账号不作为独立商业模式；内容只服务于四个实验获客。
- 不先建设 SaaS、账号体系、会员、支付和复杂后台，先验证是否有人开始体验、完成体验、主动复玩、查看报价或提交咨询。

## 2. 目标、时间与成功定义

### 2.1 首轮目标

- 输出四个手机和桌面浏览器可访问的公开链接。
- 每个链接均提供真实可操作内容，而不是静态介绍图或虚假按钮。
- 所有关键行为进入同一个实时数据看板。
- 完成首个 7 日真实试投，每天生成截至前一日 23:59 的数据摘要。
- 根据行为数据将每个实验判定为保留、返工或停止。

### 2.2 “明早可体验”的定义

2026 年 8 月 6 日上午的交付目标是首轮可体验版本，不等同于完整商业成品：

- 游戏必须能从开始进入完整胜负结算并立即重开，不能只展示角色或棋盘。
- 服务实验必须能查看案例、了解固定范围与价格，并提交真实咨询意向。
- 公开页面必须有有效 URL、HTTPS、移动端适配和实际事件上报。
- 若外部渠道账号尚未登录，公开链接和数据系统仍可上线，但不能把“已公开”描述成“已经获得真实流量”。

### 2.3 7 日决策口径

内部 AI 试玩用于发现规则、交互和稳定性问题，不冒充真实用户数据。市场结论只使用公开链接产生的真实访问与行为事件。

| 结果 | 判定规则 |
|---|---|
| 保留 | 达到实验对应核心信号，且存在可复现的用户完成、复玩或咨询行为 |
| 返工 | 有真实流量但主要漏斗未达线，且能定位到首屏、教学、玩法或报价问题 |
| 停止 | 两轮定位明确的修改后仍无核心行为，或无法获得目标流量且没有可执行获客路径 |

样本不足时只报告“证据不足”，不把比例波动包装成趋势。

## 3. 实验一：《九格异兽》

### 3.1 用户与问题

目标用户是玩过《金铲铲之战》、TFT、自走棋或轻构筑游戏，但不愿投入 30–40 分钟、记忆大量装备与赛季规则的轻中度策略玩家。

用户现有方式是继续玩成熟自走棋、转向短局卡牌肉鸽，或放弃一局时间不可控的策略游戏。实验要验证的是：保留阵容、羁绊和站位的决策感后，10–12 分钟单人局是否仍然值得连续玩两局。

### 3.2 核心循环

`三选一招募 → 调整九格阵型 → 激活阵眼与羁绊 → 自动战斗 → 选择强化 → 下一轮`

- 横屏运行，首战在开始后 30 秒内发生。
- 自己的阵地为 3×3 九格，最多上阵 5 只异兽。
- 单局 6 轮，第 6 轮为 Boss；胜败后可立即使用新种子重开。
- 首版包含 8 只原创异兽、3 类羁绊，每只异兽只有普攻、1 个自动技能和 1 个标签。
- 每轮固定获得资源，招募区展示 3 个候选；不做利息、连胜连败、人口升级或共享卡池。
- 同种异兽两只可共鸣升为二阶；不做三星或复杂合成链。

### 3.3 原创差异机制：阵眼

每轮在九格中生成两个公开阵眼：

- 烈阵眼：增强下一次攻击技能，但降低承伤稳定性。
- 生阵眼：强化治疗、护盾或首次濒死保护。

敌人的核心威胁和阵眼位置在布阵前公开。玩家需要在阵容成长与当轮克制之间做取舍，不能固定照抄一套站位。结算时明确展示哪些羁绊、阵眼和站位影响了结果，避免战斗只能观看却无法复盘。

### 3.4 视觉与交互

- 使用原创厚涂异兽、青铜绿、矿物金和深墨背景，不照搬任何现代《山海经》游戏、影视或插画作品。
- 采用“点选异兽 → 点选格子”的可靠触控，不把拖拽作为唯一操作。
- 战斗中保持攻击来源、目标、技能范围和伤害结果可读；低端机可降低粒子数量。
- 竖屏访问时显示明确旋转提示，不在竖屏中压缩棋盘继续运行。

### 3.5 实验事件与门槛

事件：`game_view`、`game_start`、`round_start`、`unit_recruit`、`unit_place`、`formation_lock`、`round_result`、`game_complete`、`replay_click`。

首轮建议门槛：

- 访问到开局转化率至少 25%。
- 已开局用户到达第 3 轮至少 40%。
- 首局完成率至少 20%。
- 首局完成用户立即重开率至少 15%。
- 若 100 个真实开局后重开率仍低于 8%，优先判定核心复玩不足，不增加大图鉴、赛季或局外养成掩盖问题。

## 4. 实验二：《纸镇失控》

### 4.1 用户与问题

目标用户是熟悉塔防、割草、肉鸽三选一和微信小游戏节奏，希望单手操作、快速清屏并在一局内形成流派的泛休闲玩家。

本实验不使用强季节性的“春节年兽”包装。改为全年可玩的原创民俗纸境：纸镇每夜出现影祟，玩家通过纸偶守卫和裁纸术守住灯芯。

### 4.2 核心循环

`选择纸偶 → 固定灯位布防 → 波中主动裁纸 → 波后选择纸术 → Boss 结算`

- 竖屏运行，一局 5 个普通波次加 1 个 Boss，目标时长 8–10 分钟。
- 一张折线路线地图、5 个固定灯位，不做自由摆塔和路径阻塞。
- 三种纸偶：单体快攻、范围爆破、减速控场。
- 五种普通敌人、一个精英模板和一个原创 Boss。
- 每波结束从 3 个纸术中选择 1 个，首版提供 9–12 个数值或简单规则强化。

### 4.3 原创差异机制：裁纸斩

玩家在冷却完成后横向或斜向划过屏幕：

- 划线命中的敌人被标记并短暂减速。
- 纸偶攻击标记目标时触发一次额外撕裂伤害。
- 同一划线连续命中多个敌人会提高撕裂倍率，形成可操作的清屏高潮。

玩家开始后 10 秒内必须产生第一次主动操作，45 秒内必须出现一次可理解的连锁清屏，避免普通塔防前期只剩等待。

### 4.4 视觉与交互

- 使用朱红、墨黑、米白的原创剪纸和皮影视觉，单位轮廓、路线和攻击来源优先于装饰纹样。
- 纸张质感通过分层 2D 图片、阴影、缩放和摆动实现，不做高成本骨骼或物理纸张模拟。
- 底部操作区避开全面屏安全区；切到后台时暂停波次与冷却，恢复后不补算离线时间。

### 4.5 实验事件与门槛

事件：`game_view`、`game_start`、`first_action`、`tower_build`、`paper_slash`、`upgrade_pick`、`wave_complete`、`game_complete`、`replay_click`。

首轮建议门槛：

- 访问到开局转化率至少 30%。
- 开局后 15 秒内有效操作率至少 70%。
- 已开局用户到达第 3 波至少 45%。
- 首局完成率至少 25%。
- 首局完成用户立即重开率至少 15%。
- 若大多数玩家只靠纸偶等待、不主动使用裁纸斩，判定差异机制失败并返工。

## 5. 实验三：AI 产品部部署服务

### 5.1 用户与价值

目标用户：个人产品经理、创业者、5–30 人产品研发团队。

核心问题：已经使用 AI，但仍需反复解释背景、手动拆任务、在多个提示词和工具间切换，无法形成稳定的 PRD、评审、Demo、优先级和任务跟踪流程。

核心承诺：不是出售提示词包，而是把一套能工作的中文 AI 产品部安装到客户现有环境中。

### 5.2 可体验落地页

页面提供一个无需登录的交互案例：用户点击“把一段会议记录转成可执行需求”，页面依次展示任务识别、产品经理、用户研究、评审、原型和任务板的协作结果。案例使用完全虚构的通用产品需求，不使用盖世游戏内部文档、截图、名称、数据或流程。

页面包含：

- 服务适合与不适合的对象。
- 部署前后对比。
- AI 员工分工和真实产物示例。
- 固定交付边界、实施周期和客户需提供的信息。
- 价格卡与咨询表单。

首轮测试价格：

- 需求诊断：¥299。
- 标准部署：¥999。
- 团队定制：¥2999 起。

价格点击只验证意愿，不跳转到虚假支付页面。用户提交咨询后明确提示“当前为首批试点申请，不代表已付款或自动成交”。

### 5.3 实验事件与门槛

事件：`service_view`、`demo_start`、`demo_complete`、`case_open`、`pricing_view`、`pricing_click`、`lead_start`、`lead_submit`。

首轮建议门槛：

- 有效访问到交互案例开始率至少 20%。
- 案例完成用户查看价格率至少 20%。
- 有效访问到价格点击率至少 5%。
- 100 个目标用户有效访问中至少产生 3 个真实咨询，且至少 1 个愿意进入需求诊断沟通。

## 6. 实验四：48 小时可玩验证冲刺

### 6.1 用户与价值

目标用户：创业者、产品负责人、独立开发者、小游戏团队和营销互动项目负责人。

核心问题：想法在会议和文档里争论数周，仍无法让用户、老板、研发或投资人实际操作；直接开发正式产品成本过高。

核心承诺：在固定范围内，把一个想法制作成可操作的高保真 H5 垂直切片，并提供需求说明、AI 模拟评审和下一步投入建议。

### 6.2 可体验落地页

页面包含：

- 从输入到交付的四步流程。
- 可直接打开的两款游戏案例入口。
- 一个通用产品页面案例，不能使用公司内部项目作为商业案例。
- 明确的包含项、不包含项、修改轮次和交付格式。
- 价格卡与咨询表单。

首轮测试价格：

- 单页面产品 Demo：¥999。
- 完整交互验证：¥2999。
- 游戏可玩切片：¥5999 起。

“48 小时”只适用于需求已锁定、素材和账号不构成阻塞的标准范围；复杂系统先进行付费诊断，不承诺无限修改。

### 6.3 实验事件与门槛

事件：`service_view`、`case_open`、`scope_expand`、`pricing_view`、`pricing_click`、`lead_start`、`lead_submit`。

首轮建议门槛：

- 有效访问到案例打开率至少 25%。
- 案例访问到价格查看率至少 15%。
- 有效访问到价格点击率至少 5%。
- 100 个目标用户有效访问中至少产生 3 个真实咨询，且至少 1 个愿意提供需求进行报价。

## 7. Cloudflare 发布与数据架构

### 7.1 发布结构

使用一个新的个人 Cloudflare Worker 项目承载静态资源、事件 API、聚合数据 API 和 D1 数据库：

```text
公开首页
├── /nine-grid-beasts
├── /paper-town
├── /ai-product-team
├── /prototype-sprint
└── /dashboard
        ↓
同源 POST /api/events
        ↓
Cloudflare Worker 校验与写入
        ↓
Cloudflare D1
        ↓
GET /api/dashboard/summary
```

首次上线使用 Cloudflare 提供的 HTTPS 域名。正式域名、备案、支付和品牌注册不属于首轮试投。

### 7.2 数据表

最小数据对象：

- `experiments`：实验标识、名称和版本。
- `events`：匿名会话、实验、事件、时间、页面、UTM 来源和允许的事件属性。
- `daily_summaries`：按上海时区聚合的每日访问、漏斗和转化。
- `leads`：用户主动提交的联系方式、需求摘要、来源、同意状态和提交时间。

浏览器首次访问生成随机匿名 ID 并存入本地存储；不使用指纹，不把 IP、User-Agent 全量或 Cookie 标识写入业务表。事件保留 30 天，咨询信息保留 90 天；试投结束后可导出汇总并删除明细。

### 7.3 数据看板

公开数据看板只展示聚合指标，不显示联系方式、需求原文和单个用户轨迹：

- 当日、昨日和累计有效访问。
- 来源渠道与 UTM 活动。
- 四实验核心漏斗。
- 游戏完成率、重开率和中位有效时长。
- 服务价格点击率、咨询数和咨询转化率。
- 数据更新时间、样本量提示和异常说明。

咨询明细不进入公开页面，后续通过受保护的管理接口或 Cloudflare 控制台查看。

### 7.4 日报

- Cloudflare Cron 每天 01:30 UTC（北京时间 09:30）生成上一自然日摘要。
- 每日报告包含真实数字、相较前日变化、样本量、异常、结论和下一项调整。
- 第一天没有流量时如实报告 0，并优先检查投放入口，而不是修改玩法。
- 默认连续观察 7 天；第 7 天输出保留、返工或停止结论。

## 8. 真实投放方案

部署公开链接不等于完成投放。每个渠道必须使用独立 UTM 参数，才能区分产品问题和渠道问题。

### 8.1 游戏

优先渠道：

1. 用户已有的游戏玩家群、朋友圈或游戏社区账号。
2. itch.io 游戏页，用于获得独立游戏和 HTML5 玩家。
3. 适合发布可玩链接的国内独立游戏、小游戏或自走棋社区。

投放文案不使用“国产金铲铲”“复刻金铲铲”等混淆表达，只说明“10 分钟原创异兽构筑”或“主动划屏的剪纸塔防”。

### 8.2 产品化服务

优先渠道：

1. 闲鱼或其他允许发布数字服务的平台。
2. 产品经理、创业者、独立开发者社群。
3. V2EX、即刻、小红书等用户已有且允许相关内容的平台。

外部发帖、上传 itch.io、创建服务商品或联系潜在客户均使用用户本人账号。虽然用户已经批准本轮真实投放，首次登录每个平台时仍需用户完成验证码、设备确认和平台协议；不得规避平台限制或批量骚扰陌生用户。

## 9. 原创、知识产权与商业边界

- 《山海经》原始母题和民俗纸境只作为公共文化来源，所有角色造型、技能、名称、UI、关卡、代码、音乐和文案重新创作。
- 不使用竞品截图描摹，不复制商店、棋盘、图标、装备、角色、羁绊、数值和信息层级的独特组合。
- 每项资产保留来源、许可、生成提示、修改记录和最终用途；字体、音效与代码依赖必须允许对应商业用途。
- 游戏名均为工作名，正式商业发布前检索应用商店、搜索引擎、域名和中国商标相关类别。
- AI 产品部与原型服务不得使用雇主的内部 PRD、数据、用户反馈、设计稿、品牌素材、账号、客户名单或未公开经验作为营销案例。
- 本设计降低风险但不构成法律保证；正式收费和扩大投放前对名称、核心角色和首屏表达进行定向法律检查。

## 10. 错误处理与测试

### 10.1 共同错误处理

- 事件上报失败不能阻断游戏或案例体验；事件进入有限本地队列并在网络恢复后重试。
- 同一事件使用客户端事件 ID 去重；服务端拒绝未知实验、未知事件、超长属性和高频异常请求。
- 表单提交明确区分校验失败、网络失败和提交成功；失败时保留用户已填写内容。
- 页面刷新、切后台和横竖屏变化后保持合法状态；无法恢复的游戏局明确重新开始，不伪造续局。
- Cloudflare API 或 D1 不可用时，看板显示最后更新时间和数据暂不可用，不显示虚假 0。

### 10.2 验证范围

- 规则测试：两款游戏的胜负、升级、技能、阵眼、波次和重开。
- 浏览器测试：桌面 Chrome、安卓视口、iPhone 视口、横竖屏、安全区和后台恢复。
- 性能测试：限制同屏单位、对象池、粒子降级；核心页面首屏和游戏运行无阻断错误。
- 数据测试：每个事件触发一次、属性正确、失败重试不重复、日报口径与原始事件一致。
- 表单测试：必填、长度、重复提交、敏感数据不出现在公开看板。
- AI 玩家评审：每款游戏至少五种玩家视角完成两局并给出证据；只作为内部质量门禁。
- 人工验收：用户能通过四个公开 URL 完成对应主链路，并在数据看板看到测试事件。

## 11. 实施顺序与范围控制

1. 完成规格与实施计划。
2. 用户登录新的个人 Cloudflare 账号，创建独立 Worker 与 D1 资源。
3. 建立四路径静态壳、统一事件 SDK、事件 API 和数据看板。
4. 实现《九格异兽》完整单局，内部试玩通过后接入正式原创视觉。
5. 实现《纸镇失控》完整单局，内部试玩通过后接入正式原创视觉。
