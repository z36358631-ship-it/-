# 发行平台开发者数据看板设计

## 目标与范围

为已经登录且拥有厂商权限的发行平台开发者提供单游戏数据看板，补齐从站内曝光、访问、购买意向到下单、成功获取、成功履约的转化链路，并继续承载销量、免费领取、退款、拒付、收入预估和待结算数据。开发者可以判断销量变化来自流量、详情承接、交易转化还是履约异常。

本期只统计买断游戏本体和永久 DLC，端只覆盖 Android 与 Mac，履约方式只覆盖直接购买与 CDKEY。页面只提供经营观察、脱敏订单定位和财务摘要；财务主体、账单确认、差异申诉、发票与付款继续由现有“开发者财务结算”模块负责。

## 现状与方案选择

当前 `10-销售数据与对账demo.html` 已有销售、退款、收入和账单样例，但与统一 02 Demo 脱离；其账单确认和差异申诉又与 15 财务结算重复。统一 02 已在单游戏工作区提供“经营数据”，但只有交易结果，没有解释交易结果的站内转化链路；页面标题区还重复展示“发行经营数据”、游戏名、Game ID 和说明文案，占用首屏。

对比三种方案：

1. 保留孤立 10 Demo：改动小，但继续割裂统一入口。
2. 把经营数据并入 15 财务结算：页面边界变重，分析角色会接触不必要的财务操作。
3. 在统一 02 的单游戏工作区完善“数据看板”，首屏串联站内转化与交易结果，脱敏订单和收入结算仍使用独立页签，正式对账跳转 15。

采用方案 3。它符合开发者“先看经营变化，再按异常订单定位，最后进入正式对账”的任务顺序，也避免维护两套账单流程。

## 信息架构

开发者先从“游戏管理”进入一个有权限的游戏，再在该游戏左侧功能区进入“经营数据”。数据看板固定当前 Game ID；游戏名称由面包屑提供上下文，内容区页头只显示主标题“数据看板”，不再重复展示眉题、游戏名、Game ID 或副说明。右侧保留“数据口径”、只读标识和数据更新时间。

“数据看板”内部包含三个页签：

1. **经营概览**：公共筛选、站内转化漏斗、来源分析、六项交易指标、趋势、商品构成和地区分布。
2. **订单明细**：展示当前游戏的脱敏订单；支持订单号、商品类型、履约方式、地区、平台、状态和时间筛选，并可打开只读详情。
3. **收入与结算**：展示预估收入公式、待结算金额、锁定账单摘要和“前往对账结算”入口。

## 指标口径

| 指标 | 口径 |
|---|---|
| 有效曝光 UV | 筛选期内，当前游戏或对应独立 DLC 素材达到有效曝光条件的去重访问者数；重复曝光按访问者、游戏或 SKU 和筛选期去重。 |
| 游戏卡点击 UV | 在有效曝光后点击当前游戏或独立 DLC 卡片的去重访问者数；曝光点击率＝游戏卡点击 UV ÷ 有效曝光 UV。 |
| 详情页访问 UV | 当前游戏详情页成功展示的去重访问者数；卡片到详情率＝详情页访问 UV ÷ 游戏卡点击 UV。自然直达从本阶段进入，不进入曝光点击率分母。 |
| 购买／领取点击 UV | 在详情页点击“购买”或“免费领取”的去重访问者数；详情意向率＝购买／领取点击 UV ÷ 详情页访问 UV。 |
| 创建订单 UV | 成功创建买断游戏本体或永久 DLC 订单的去重用户数；下单率＝创建订单 UV ÷ 购买／领取点击 UV。 |
| 成功获取 UV | 支付成功或 0 元领取成功的去重用户数；获取成功率＝成功获取 UV ÷ 创建订单 UV。该指标不等于销量或收入。 |
| 履约成功 UV | 账号权益生效或 CDKEY 成功交付的去重用户数；履约完成率＝履约成功 UV ÷ 成功获取 UV。成功获取与履约成功的差额用于识别待履约异常。 |
| 曝光到获取转化率 | 成功获取 UV ÷ 有效曝光 UV。无有效曝光的自然直达、站外直达不计算该比率。 |
| 付费销量 | 应付金额大于 0 且完成履约的订单数。直接购买以账号权益生效为准，CDKEY 以 Key 成功交付为准；后续退款和拒付不回写毛销量。 |
| 免费领取 | 应付金额等于 0 且完成履约的订单数。履约失败或处理中不计入。 |
| 退款 | 渠道确认退款成功的订单数和实际退款金额；处理中只展示状态，不计退款终态。 |
| 拒付 | 区分待裁决风险和败诉扣减；待裁决不扣收入，败诉后才扣减。 |
| 净销量 | 付费销量减去完全退款订单和拒付败诉订单；同一订单冲突时只扣一次，部分退款只扣金额。 |
| 预估收入 | 销售额减成功退款、拒付败诉、税费、渠道费和平台分成，再加调整项；任一必要金额或汇率缺失时显示“估算中”。 |
| 待结算 | 已锁定账单尚未清偿的金额；正式金额和状态以财务结算模块为准。 |

站内漏斗统一使用 UV，交易区使用订单数和金额，页面不得将人数与订单数直接相减。行为事件以登录用户 ID 优先，未登录时使用匿名访问者 ID；支付／领取按订单或领取终态去重，履约按订单与履约方式去重。分母为 0、数据缺失或阶段不适用时显示“--”及原因，不显示 0%。

漏斗采用入口队列口径：筛选期内发生的首次有效站内曝光或详情访问为入口，后续 7×24 小时内归因到同一游戏或 SKU；来源采用最后一次有效的非直接触点，并在成功获取时冻结。交易指标继续按履约完成时间统计，页面明确提示“漏斗按入口时间，销量按履约完成时间”，两组数据不能直接相减。

所有金额保留原币种、结算币种和汇率快照。Demo 使用固定人民币样例展示交互，不在产品规则中固化分成比例。

## 页面与交互

### 经营概览

- 默认时间为近 30 天，当前游戏固定，默认全部商品类型、全部来源、全部地区和全部平台。
- 公共筛选包含时间、商品类型、来源位置、地区和平台，同时作用于站内转化与交易结果。履约方式和订单状态属于交易筛选，只作用于交易指标、订单和收入，不得反向过滤曝光、点击等上游事件。
- 首屏先展示站内转化漏斗：有效曝光、游戏卡点击、详情页访问、购买／免费领取点击、创建订单、成功获取和履约成功。每层显示 UV、相较上一层的转化率和环比；顶部展示曝光到获取总转化率。
- 漏斗下方展示来源分析表，至少覆盖首页推荐、找游戏、排行榜、搜索、专题活动、站外活动、自然直达和其他，并展示曝光 UV、点击 UV、详情访问 UV、成功获取 UV、点击率和获取转化率。自然直达的曝光与点击率显示“--”。
- 趋势区支持在有效曝光、详情访问、购买／领取点击和成功获取之间切换，并按日展示；本期不增加小时粒度、图表下载或平台平均值。
- 六项卡片依次展示付费销量、免费领取、退款成功、拒付风险、预估收入和待结算；卡片补充口径或金额说明。
- 趋势图按日展示付费销量和免费领取；商品构成区分游戏本体与永久 DLC，履约构成区分直接购买与 CDKEY。
- 游戏本体卡片曝光只归属游戏本体；DLC 只有在独立卡片、独立模块或独立详情产生曝光时才统计 DLC 上游转化，不把游戏本体曝光摊分给 DLC。
- 切换任一公共筛选后，漏斗、来源、交易指标和图表使用同一数据截止时间刷新；无匹配数据时显示明确空态，不把未知值显示为 0。
- “数据口径”打开只读弹窗，解释计入条件、更新时间、脱敏范围和正式结算边界。

### 订单明细

- 一行一笔订单，展示完整且不可反查玩家的对账流水号、脱敏平台订单号、完成时间、游戏与 SKU、商品类型、履约方式、地区、平台、渠道、原币种金额和业务状态。
- 样例覆盖交易完成、免费领取、退款处理中、已退款、拒付待裁决、拒付胜诉、拒付败诉和已关闭。
- 点击一行或“查看详情”打开右侧抽屉。详情展示订单快照、履约结果和资金影响；不展示玩家身份、设备、支付账号、支付凭证、Key 明文、退款原文或内部日志。
- 关闭抽屉后保留筛选、页签和滚动上下文。数据加载失败时保留筛选并允许重试。

### 收入与结算

- 预估收入按销售额、退款成功、拒付败诉、税费、渠道费、平台分成和调整项逐项展示，不使用固定比例计算。
- 待裁决拒付单列风险金额，不进入预估收入扣减。
- 待结算只展示已锁定且尚未清偿的账单摘要；迟到退款、拒付和费用调整进入下一账期调整项，不修改已锁定账单。
- “前往对账结算”打开 `15-开发者财务结算demo.html#/settlement`；“查看对账流水”打开 `15-开发者财务结算demo.html#/settlement/flows`。跳转携带当前厂商、时间、游戏和履约筛选的演示上下文。

## 权限与数据隔离

- 服务端根据登录会话绑定的厂商权限确定数据范围，不信任前端传入的厂商编号。
- 企业认证通过且拥有经营数据权限的账号可查看聚合与脱敏订单；资格暂停后保留历史只读查看能力。
- 无有效厂商权限或未完成认证时不展示真实经营数据，统一显示权限空态。
- 分析角色只能查看经营数据；账单确认、差异申诉、发票和付款由财务结算模块的相应权限控制。
- 订单在用户侧被删除只影响用户订单列表，不影响开发者销量、收入、退款、拒付和对账数据。

## 组件与数据流

独立 `PublisherDataDashboard` 运行时组件负责转化样例、来源样例、筛选、指标计算、页签、弹窗和订单详情。统一 02 的模板只负责把组件挂载到当前游戏的 `data` 工作区，应用运行时负责固定当前 Game ID、保存页签状态并在每次重绘后调用组件绑定。

数据流分为两条：登录会话与当前 Game ID 校验权限 → 读取行为事件快照 → 生成入口队列和来源归因 → 聚合转化漏斗；登录会话与当前 Game ID 校验权限 → 读取订单、履约、逆向交易和锁定账单快照 → 聚合交易与收入。两条链路使用同一数据截止时间，但分别遵守入口时间和履约完成时间口径。正式实现时计算由服务端完成，前端只展示口径版本和结果；Demo 在浏览器内用固定样例模拟。

## 异常与恢复

- 无数据：显示“当前筛选条件下暂无数据”，保留筛选器和重置入口。
- 不适用：自然直达或站外直达没有可归因曝光时，上游阶段显示“--”；CDKEY 没有真实下载或激活回传时不推算数据。
- 批次异常：数据延迟、字段缺失或身份合并导致漏斗阶段暂时非单调时显示“数据校验中”和最近成功批次，不沿用旧值伪装实时结果。
- 隐私阈值：来源分组不足 10 UV 时显示“<10”，隐藏该行比率或合并到“其他”。
- 数据估算中：涉及缺失费用或汇率的金额显示“估算中”，不按 0 补齐。
- 无权限：不渲染真实数据或可推断记录存在性的提示。
- 退款与拒付冲突：状态显示“核对中”，不重复冲减。
- 财务页面不可打开：当前页面状态不变，用户可再次点击入口。

## 验证方案

- 静态验证：构建脚本成功，新增 JavaScript 通过语法检查，`git diff --check` 通过。
- 浏览器验证：覆盖单游戏入口、精简页头、三个页签、站内漏斗、来源分析、趋势指标切换、公共与交易筛选边界、空态、全部订单状态、订单详情抽屉、数据口径弹窗、财务跳转和 390px 响应式。
- 口径验证：对固定样例断言七步漏斗、逐层转化率、自然直达不适用、来源聚合、付费销量、免费领取、退款、拒付、净销量、预估收入和待结算；确认订单状态与履约方式不改变上游曝光分母，待裁决拒付不扣收入。
- 文档验证：PRD 页面图来自当前 Demo，产品流程为横向单图，图片使用固定提交 SHA 的公开 HTTPS 链接，并区分公网可访问与飞书转存验证。

## 明确不做

- C 端购买、激活、下载和退款操作。
- 包体、版本发布、折扣和分区定价管理。
- 用户身份、Key 明文、支付凭证和内部处理材料展示。
- 在数据看板内重复财务主体、账单确认、差异申诉、发票和付款流程。
- 预约、评分评价、社区互动、广告投放深度分析、排行榜名次／波动分析和平台平均点击率／转化率；排行榜仍可作为站内来源位置参与归因。
- 没有真实回传时推算 CDKEY 激活、下载或首次启动数据。

## TapTap 参考与适配

TapTap 当前开发者中心的单游戏看板按商店数据、销售分析、评分评价和社区数据分组。公开生产前端资源可核实商店数据包含浏览、下载、预约、转化效果、排名和广告投放转化；转化效果按页面或功能展示素材展示数、点击数、点击率、转化数和转化率，并支持时间、平台与位置等筛选。

本项目借鉴“素材曝光—点击—转化”和按站内位置定位来源的结构，但不照搬预约、APK 下载、iOS 商店唤起、评分评价或社区互动。盖世本期对象为买断游戏本体与永久 DLC，因此转化终点改为支付／领取成功与履约成功。
