# 开发者平台 01／02 统一 Demo 与权限联动设计

## 1. 目标与范围

本次以现有 02 游戏创建与发行 Demo 为主应用，将 01 的登录、开发者账号、企业认证和相关运营页编入同一份单文件 HTML。开发者从登录、企业认证、创建游戏到版本发布、发布记录和资质认证，全程使用同一套账号、游戏和审核状态。

本期解决四个问题：

1. 02 不再强制模拟“企业认证已通过”，而是继承 01 的真实登录与企业认证状态。
2. 个人开发者、认证申请中的开发者、认证未通过的开发者、企业开发者和资格暂停账号看到不同的页面内容和操作权限。
3. 01 与 02 的页面、样式、导航、语言、当前游戏和状态存储保持统一。
4. 修复直接打开、刷新、返回、退出登录、HTMLPreview 跳转和多账号／多游戏数据串联问题。

暂停此前开发者数据中心的新增工作。本设计不扩展 C 端、评分评价、社区互动、支付、包体折扣或结算能力。

## 2. 交付形态

### 2.1 统一应用

构建时为 01 和 02 生成同一套应用壳、样式、运行时依赖和路由集合：

- 01 兼容入口：`01-开发者平台与资料demo.html`
- 02 主入口：`02-游戏创建与发行demo.html`
- 02 兼容入口：保留 `02-CDKEY商品与供给demo.html`，内容与主入口保持一致
- 两个入口都能在单一 HTML 内访问本期有效的 P01 和 P02 路由，不再依赖跨 HTML 相对跳转
- 01 入口默认进入登录／开发者平台页面；02 入口根据会话进入当前游戏，没有有效会话时进入统一登录页

现有公开链接继续可用。旧文件名作为兼容入口，不删除、不跳到 jsDelivr 源文件。

### 2.2 页面范围

统一 Demo 编入 01 当前正式声明的页面：

- P01-01：登录
- P01-03：开发者注册、主体资料和企业认证
- P01-08：开发者账号与身份映射管理
- P01-09：企业认证内容配置
- P01-10：帮助中心

02 本期只编入 P02-01，用于承载游戏创建、游戏列表和单游戏工作台；原有 CDKEY、数据中心等与本期无关的 P02 页面不进入统一侧边栏。01 中此前已经明确允许占位的非核心内容继续使用统一样式的占位页，不新增业务流程。

## 3. 账号身份与权限模型

`registration.accountTier` 表示账号注册层级，`qualification.status` 表示企业认证结果。只有 `qualification.status === "approved"` 才取得企业发行权限。审核中和未通过不会提前升级为企业开发者。

统一派生以下页面能力，页面只消费能力，不各自推断账号状态：

- `canCreateGameDraft`
- `canEditReleaseDraft`
- `canSubmitRelease`
- `canViewReleaseHistory`
- `canManageGameQualifications`
- `canManageVendor`
- `isPublisherReadOnly`

### 3.1 状态矩阵

| 企业认证状态 | 页面身份 | 版本发布 | 发布记录 | 资质认证 | 厂商设置 |
| --- | --- | --- | --- | --- | --- |
| 未提交 | 个人开发者 | 可编辑、保存草稿；顶部提示；提审禁用 | 空状态，说明提审后生成记录 | 只读查看要求；不能上传或提交 | 隐藏 |
| 审核中 | 个人开发者／企业认证审核中 | 可编辑、保存草稿；提审禁用 | 仅查看既有历史，没有历史则为空状态 | 只读，显示认证进度 | 隐藏 |
| 未通过 | 个人开发者／待修改 | 草稿保留；提审禁用 | 仅查看既有历史 | 只读，提供修改企业资料入口 | 隐藏 |
| 已通过 | 企业开发者 | 完整编辑、保存、提交；版本审核中可撤销 | 展示版本快照、审核和发行记录 | 可上传、修改、提交、补件；资质审核中可撤销 | 显示 |
| 资格暂停 | 企业权限暂停 | 现有资料只读，禁止新增和提交 | 历史记录只读 | 生效与历史资质只读 | 只读或隐藏 |

个人开发者可以创建游戏项目、填写版本资料和保存草稿。个人开发者不能提交版本发布审核、提交游戏资质审核或管理厂商资料。

## 4. 三个核心 Tab

### 4.1 版本发布

个人开发者与企业开发者复用同一表单骨架，避免企业认证通过后重新填写资料。个人开发者页面顶部显示与企业认证状态对应的提示；“保存草稿”可用，“提交发布审核”置灰并说明前置条件。

企业开发者按现有资料完整性、资质版本和版本审核状态决定操作：草稿可保存和提交，审核中只读并允许撤销，需修改时展示原因并恢复编辑，审核通过后展示不可变快照并通过新版本继续修改。

版本发布页不再维护第二份完整资质表单，只显示当前引用的有效资质版本、状态和“前往资质认证”。资质材料统一由资质认证 Tab 管理。

### 4.2 发布记录

发布记录只保存实际提交后的不可变版本快照，不把普通保存草稿记作审核记录。

- 未产生提交记录：显示空状态，并说明完成企业认证且提交版本后生成记录
- 企业已认证：展示版本号、提交时间、审核状态、发行状态、引用资质版本和详情
- 资格暂停：保留历史，只读查看

### 4.3 资质认证

个人开发者只读查看全球服和中国大陆两类资质要求。页面顶部提供与账号状态相符的“申请企业认证”“查看认证进度”或“修改认证资料”入口。

企业开发者可以上传和修改资质、提交审核、处理补件及撤销审核。全球服与中国大陆沿用已确认的材料规则：中国大陆发行补充版号等国内发行材料；全球服不要求国内版号。上传和修改资质均形成独立审核申请，已生效版本在新申请审核期间继续有效。

## 5. 01 与 02 的交互联动

### 5.1 登录与进入游戏

1. 未登录访问任一受保护路由，进入统一登录页。
2. 登录后恢复当前账号及该账号最后访问的游戏。
3. 从游戏列表进入游戏时，恢复 `gameId`、工作区和目标 Tab。
4. 没有游戏时进入游戏列表或创建草稿入口，不生成虚构企业权限。

### 5.2 企业认证入口

- 未提交：进入企业认证申请页
- 审核中：进入企业认证进度页
- 未通过：进入带审核意见的资料修改页
- 资格暂停：进入资格状态页

从 01 返回 02 后立即重新计算权限；认证通过后保留此前版本草稿并开放提交审核，不要求重新填写。

### 5.3 标识生成

统一采用 01 的现有口径：创建游戏项目后生成 Game ID；APPID 在后续正式节点生成。02 删除“创建项目同时生成 APPID”的冲突表现。

## 6. 状态与存储

### 6.1 会话状态

会话状态保存：版本号、账号键、是否登录、有效期、厂商 ID 和最后访问游戏 ID。会话过期或退出登录时清除受保护上下文并进入登录页。

### 6.2 账号与游戏数据隔离

业务数据按以下层级保存：

```text
accounts
└─ accountKey
   ├─ registration
   ├─ qualification
   ├─ vendorId
   └─ publisherWorkspaces
      └─ gameId
         ├─ draft
         ├─ qualifications
         └─ releaseRecords
```

不同账号之间、同一账号的不同游戏之间不能读取或覆盖对方数据。旧全局工作区存储首次读取后迁移到当前账号和游戏，并停止继续写旧键。

### 6.3 跨文件兼容

统一 HTML 内使用 Hash 路由切换，不发生跨文件跳转。旧入口或外部链接需要切换文件时，使用统一导航函数识别普通浏览、`file://` 和 HTMLPreview 环境。

`window.name` 仅作为旧入口的短期交接兜底，包含版本、账号、认证、厂商、当前游戏、目标页面和有效期；读取并验证后立即清除。它不作为长期业务存储。

## 7. 页面与状态一致性

1. 01 和 02 使用同一顶部栏、侧边栏、语言状态、账号菜单、字体、色彩和组件。
2. 中文界面显示“英语”，英文界面语言切换实际生效。
3. 页面跳转后定位到内容顶部，页内锚点仅在明确点击模块导航时定位。
4. 企业认证、游戏资质审核、游戏版本审核和发行状态分别保存，不复用一个状态字段。
5. 统一状态文案：
   - 企业认证：未提交／审核中／未通过／已通过／资格暂停
   - 游戏资质：未提交／审核中／需补充／已生效
   - 游戏版本：草稿／审核中／需修改／审核通过
   - 发行状态：未上线／已上线／已下架
6. 02 的模块标题和路由语义统一为游戏创建与发行；旧 CDKEY 文件名仅作为兼容入口，不再决定页面业务含义。

## 8. 异常处理

- 会话缺失或过期：进入登录页，不默认赋予企业权限
- 交接数据版本错误、过期或重复读取：忽略并清除
- 当前游戏不存在或不属于当前账号：回到游戏列表
- 企业认证状态在页面停留期间变化：窗口重新聚焦或存储事件触发权限刷新
- 审核提交和撤销重复操作：只允许第一个终态成功，后续操作不重复写记录
- 资格暂停：保留历史数据，禁止新的保存、提交和撤销操作

## 9. 验收标准

### 9.1 账号状态

逐一验证未登录、个人未认证、企业认证审核中、企业认证未通过、企业认证已通过和资格暂停六种状态。

### 9.2 页面权限

每种状态分别检查版本发布、发布记录、资质认证和厂商设置的内容、提示、按钮可用性、直接调用拦截和返回路径。

### 9.3 状态串联

- 从 01 登录和企业认证进入 02 后身份一致
- 从 02 返回 01 修改认证，再回 02 后权限即时变化
- 个人开发者草稿在认证通过后继续存在
- 已认证企业可以提交版本与资质审核，审核中可以撤销

### 9.4 导航与隔离

- 01、02 两个历史入口均可打开统一应用
- HTMLPreview、`file://` 和本地 HTTP 环境均能正确跳转
- 刷新、浏览器返回和退出登录不会恢复错误页面或权限
- 两个账号及同账号两个游戏的数据互不串联

### 9.5 回归

构建脚本、路由清单和浏览器测试同步更新。自动化至少覆盖登录门禁、六种账号状态、三个 Tab、企业认证往返、审核撤销、历史入口兼容、HTMLPreview 导航及账号／游戏隔离。

- 不新增 C 端购买流程
- 不继续扩展 CDKEY 或开发者数据中心页面，现有源文件保留
- 不新增评分评价和社区互动
- 不改变已确认的全球服／中国大陆资质材料规则
- 不删除现有公开文件或破坏已有预览链接
