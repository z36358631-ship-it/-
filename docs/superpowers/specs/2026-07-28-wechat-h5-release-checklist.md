## 3. 判定规则

### 3.1 阻断级别

| 级别 | 定义 | 发布处理 |
|---|---|---|
| P0 | 安全、隐私、合规、白屏、无法进入、数据泄露、错误版本大面积生效、无法回滚等灾难性问题 | 任一失败立即 **NO-GO**；灰度中发现则立即停止扩量并回滚 |
| P1 | 核心玩法、触控、音频、生命周期恢复、胜负结算、重玩、主要设备兼容、监控告警等关键问题 | 任一失败为 **NO-GO**，必须修复并完成回归 |
| P2 | 不影响核心任务的轻微视觉或体验问题 | 可申请带风险上线，但必须记录负责人、修复日期、影响范围并取得产品和发布负责人书面批准 |

### 3.2 Go/No-Go 硬门槛

仅当以下条件全部满足时才可判定 **GO**：

1. 所有 P0、P1 检查项均已勾选通过，且证据可打开、可追溯到本次版本。
2. P2 未关闭项均有风险接受记录、负责人和明确修复日期。
3. 微信开发者工具编译、预览和真机调试已执行，不能以浏览器结果代替。
4. iOS 至少 2 台、Android 高/中/低档至少各 1 台完成微信真机矩阵。
5. 三款游戏均完成开场、首次操作、核心机制、成功、失败和无需刷新重玩。
6. HTTPS、证书、备案、业务域名、主体、类目、隐私和审核边界均已确认。
7. CDN 版本隔离、缓存命中、防旧资源污染、灰度、监控、告警和回滚演练全部通过。
8. 发布窗口内值守人、回滚操作者和审批人均在线，回滚包已验证可用。

出现以下任一情况直接判定 **NO-GO**：

- P0 或 P1 未通过、未执行或缺证据。
- 证据版本、域名、设备或时间无法与本次发布对应。
- 真机结果被桌面浏览器、模拟器或静态校验替代。
- 使用 `touristappid`、未备案域名、未配置业务域名或证书链异常。
- 回滚操作未演练，或无法在 10 分钟内恢复已验证稳定版本。

## 4. 执行与证据规范

- 每项执行后勾选复选框，并在“实际结果”列填写 `通过` 或 `失败：缺陷编号`。
- 证据根目录命名：`YYYYMMDD-H5版本-小程序版本-release-evidence/`。
- 单项证据命名：`日期-版本-平台-设备-用例ID-序号.扩展名`。
- 截图必须包含关键画面；设备信息、微信版本和系统版本需单独截图。
- 视频应包含操作前状态、连续操作过程、结果和设备系统时间，不接受仅截取成功瞬间的视频。
- 网络证据应保留请求 URL、状态码、响应头、缓存状态、资源指纹和时间；日志应保留时间、版本、会话/运行标识和错误栈。
- 日志、截图、视频和 URL 必须脱敏，不得包含 `OpenID`、`session_key`、手机号、长期令牌、Cookie、Authorization 或其他个人信息。
- 表中“证据位置”由执行人填写实际相对路径或受控链接，不得只写“见群聊”。
