# Mac 扫码登录结果态精简设计

## 目标

减少扫码登录结果态的重复信息，让用户在 Mac 端只看到一个明确状态和一个恢复操作；移动端只承担跨端结果通知，不再展示独立结果页。

## 当前问题

- Mac 端授权失败、登录取消、二维码过期同时在页面标题、二维码遮罩、二维码外按钮、状态行和说明文字中重复表达。
- Mac 端二维码容器和外部刷新按钮都可点击，操作入口重复，也可能产生双重触发和重复焦点。
- 移动端成功和授权失败使用整页结果卡，打断用户原本位于“我的”页的浏览状态。
- Mac 登录成功后展示“欢迎回来”结果卡，增加一次无业务价值的关闭操作，没有直接恢复用户登录前的任务。

## 已确认方案

### 1. Mac 异常结果态

授权失败、登录取消、二维码过期统一使用同一结构：

- 页面标题保持“扫码登录”，不再改为异常状态名称。
- 二维码容器增加遮罩，遮罩内只保留状态文案和“刷新二维码”按钮。
- 三种状态文案分别为“登录未完成”“登录已取消”“二维码已过期”。
- 删除二维码外的“刷新二维码”按钮、红点状态行和重复说明。
- 二维码容器本身不再承担按钮语义，不设置 `role="button"` 或 `tabindex`，也不响应点击、Enter 或 Space。
- 只有遮罩内的真实“刷新二维码”按钮可操作，点击后生成全新 challenge，不重试或恢复旧请求。
- 按钮支持正常键盘焦点和原生 Enter、Space 操作。

### 2. 移动端结果反馈

移动端在结果发生后返回“我的”页，只显示一次 Toast，不展示成功或失败结果页。

|结果|Toast 文案|触发条件|
|---|---|---|
|登录成功|Mac端登录成功|Mac 已持久化会话包并 ACK，服务端进入 `used`|
|授权失败|登录未完成，请重新扫码|服务端首次进入 `authorization_failed`|
|用户取消|登录已取消，请重新扫码|服务端首次进入 `cancelled`|
|二维码过期|二维码已过期，请重新扫码|服务端首次进入 `expired`|

- Toast 展示 2 秒。
- 同一登录请求按请求 ID 去重，每个最终结果只提示一次；轮询和重试不得重复弹出或持续重置 Toast。
- `authorizing` 和 `ready_to_claim` 仍保留现有等待反馈，不提前返回“我的”页。
- 成功 Toast 不得在 `ready_to_claim` 阶段出现。

### 3. Mac 登录成功

- Mac 会话持久化并 ACK、服务端进入 `used` 后，关闭扫码登录界面。
- 不展示“欢迎回来”“登录成功”或平台继承结果弹窗。
- 恢复用户打开登录界面前正在访问的 Mac 页面，并立即刷新该页面的登录态和用户数据。
- 打开登录界面前保存经过校验的返回目标，包括页面和必要参数；成功后不能直接依赖浏览器或窗口历史返回。
- 返回目标不存在、已失效或当前账号无权访问时，进入 Mac 默认登录后页面。
- 焦点恢复到返回页面的主要内容区域，避免用户误以为登录界面异常消失。

## 状态与页面关系

|服务端状态|移动端|Mac 端|
|---|---|---|
|`waiting_scan`|“我的”页或扫码页|展示可扫描二维码|
|`pending_confirm`|扫码确认页|二维码遮罩提示等待手机确认|
|`authorizing`|显示正在登录|显示正在同步账号|
|`ready_to_claim`|显示正在完成登录|领取并持久化会话包|
|`used`|回“我的”页，显示一次成功 Toast|关闭登录界面，恢复登录前页面|
|`authorization_failed`|回“我的”页，显示一次失败 Toast|二维码内显示“登录未完成”和刷新按钮|
|`cancelled`|回“我的”页，显示一次取消 Toast|二维码内显示“登录已取消”和刷新按钮|
|`expired`|回“我的”页，显示一次过期 Toast|二维码内显示“二维码已过期”和刷新按钮|

## 方案取舍

- 未采用三种异常共用一条 Toast：虽然实现更简单，但用户无法判断失败、取消或过期。
- 未采用移动端持续提示条：结果已由 Mac 页面承接，持续提示会增加“我的”页长期状态。
- 未保留移动端结果页和 Mac 成功弹窗：两者都会增加一次无业务价值的停留或关闭操作。

## 影响范围

- 更新扫码登录交互标注 Demo 的 Mac 异常态、移动端结果态和 Mac 成功态。
- 更新 PRD 的 V1.2 版本记录、C 端状态反馈、异常边界和验收标准。
- 重制受影响的取消、成功、授权失败和二维码过期截图；其他页面保持不变。
- 服务端状态机、安全交换协议、全成全败和会话回收规则不变。

## 验收标准

1. Mac 三种异常态的页面标题均为“扫码登录”。
2. Mac 三种异常态只有二维码遮罩内一个状态文案和一个“刷新二维码”按钮，二维码外无重复按钮、红点状态行或异常说明。
3. 二维码容器不可点击、不可获得按钮焦点；遮罩内按钮可通过鼠标、Enter 和 Space 生成新二维码。
4. 移动端成功、授权失败、取消和过期均回到“我的”页，每个请求只显示一次对应 Toast。
5. `ready_to_claim` 不显示成功 Toast；只有进入 `used` 后才显示。
6. Mac 成功后不出现弹窗，直接恢复登录前页面并呈现已登录数据。
7. 返回目标失效或无权限时进入 Mac 默认登录后页面。
8. Demo 左侧 10 个状态、右侧交互说明和异常边界仍能正常切换。

## 三视角快速评审

- 用户视角：通过。异常信息集中到二维码内，成功后直接继续原任务；需保证返回页面立即刷新登录态并恢复焦点。
- 开发视角：通过。二维码容器取消按钮语义，只保留真实刷新按钮；移动端 Toast 按请求 ID 去重，成功严格等待 `used`。
- 商业视角：通过。界面精简不影响结果传达，服务端继续保留失败状态码、埋点和日志用于定位问题。

## 不做事项

- 不修改移动端“我的”页布局。
- 不新增成功页、异常页、弹窗或持续提示条。
- 不改变二维码有效期、授权窗口、平台继承范围和会话安全协议。
