# 盖世游戏 Android 广告接入规划设计

> 日期：2026-07-17
>
> 状态：待产品、运营、研发评审
>
> 范围：Android 首期广告商业化；会员相关能力不在本期范围

## 1. 目标与原则

在不显著损伤留存、游戏启动体验和平台推荐可信度的前提下，验证广告商业化的真实收益，并形成可由运营后台控制、可稳定实验、可实时熔断的广告能力。

本期原则：

1. 国内流量优先接入穿山甲，海外流量优先接入 AdMob。
2. 原生广告可覆盖符合规则的全部用户；强打断广告仅对老用户小流量实验。
3. 广告比例、用户流量、频控均由后台配置，不在客户端写死。
4. 运营可调整配置，但无广告长期对照组、禁投流程和技术熔断不受普通运营配置覆盖。
5. 先取得真实的 `ad_paid`、eCPM、填充和用户损伤数据，再决定是否扩大密度或增加广告网络。
6. 广告收益以“增量净收益”衡量，不以广告平台流水单独判断成功。

## 3. 资源位规划

### 3.1 首期候选

| ID | 位置 | 形式 | 初始建议 | 风险 | 优先级 |
|---|---|---|---|---|---|
| P1 | 横屏“玩游戏”页“秒玩人气热游”首组至少 2 张自然卡后 | 原生赞助游戏卡 | 单次访问最多 1 张 | 低 | P0 |
| H1 | 首页“为你推荐”横向列表至少 3 张自然卡后 | 原生赞助游戏卡 | 由运营配置内容占比 | 中 | P0 实验 |
| C1 | 云游戏页点击“签到”后的结果弹层 | 主动激励视频，基础奖励到账后可选加倍 | 奖励值与开放策略由运营配置 | 低到中 | P1 实验 |
| G1 | 零时长用户主动领取额外时长 | 激励视频 | 首次与日常奖励分开配置 | 低到中 | P1 |
| Q1 | 免费通道长排队页“加速排队”区域 | 主动激励视频 | 完整观看后进入加速通道并领取时长 | 中 | P1 实验 |
| L1 | PC 游戏正常启动等待的右侧安全区 | 静态或无声原生广告；固件准备与客户端启动共用一个资源位 | 阶段开关、频率和比例由运营配置 | 中到高 | P1 实验 |
| O1 | 老用户真正冷启动 | 开屏/App Open | 仅小流量实验 | 高 | P3 |

搜索无结果页和游戏详情页不设置商业赞助位：前者会污染搜索可信度，后者会干扰用户判断与启动决策。

### 3.2 禁投范围

以下范围不允许通过普通运营配置开放被动广告、自动广告或插屏：

- 用户点击“立即游戏/秒玩/启动”之后，除本节明确允许的 G1、Q1、L1 外，不展示其他被动、自动或插屏广告；
- 组件安装、资源检查、调度、连接和加载默认禁投；正常 PC 游戏的“固件/运行环境准备”和“Steam 与客户端启动”仅允许 L1 右侧静态或无声原生广告；
- 启动失败、兼容性错误、弱网、重连和崩溃恢复；
- 游戏运行中、虚拟按键、控制器和操作面板；
- 登录、实名、隐私授权、权限、支付；
- 下载、领取、导入、配置、空间不足和排障；
- 个人游戏库的用户资产列表；
- 从游戏、云游或其他 App 返回盖世时的插屏或开屏。

G1 必须发生在启动请求创建前。奖励到账后再创建独立的游戏启动请求；启动请求创建后，除正常 PC 启动等待阶段的 L1 外，后续链路不再出现其他广告。

排队阶段唯一例外是 Q1：仅当用户位于免费通道、服务端预计等待超过后台阈值、未在同一会话成功使用 G1/Q1 且用户主动点击时展示一次激励广告。Q1 不自动弹窗，广告播放期间保留排队心跳和原位置；除该次主动触发外，排队阶段广告曝光仍为 0。

L1 的例外边界仅限正常启动等待：两个阶段共用同一 `startup_session_id`、广告请求、素材和曝光身份；阶段切换不刷新素材。启动完成、启动失败、兼容错误、弱网、重连或排障时立即隐藏广告。广告不得延长启动时间，也不得遮挡进度、错误信息或品牌状态。

## 4. 各资源位详细规则

### 4.1 P1 玩游戏页赞助卡

- 在“秒玩人气热游”首组先展示至少 2 个自然游戏，再展示赞助卡。
- 不进入“最近常玩”“我的游戏库”等用户资产区域。
- 不伪装为榜单名次、编辑推荐、玩家评分或热门标签。
- 卡片可沿用游戏卡尺寸，但必须持续显示“广告”或“赞助”标识。
- 不遮挡秒玩、启动或下载操作。
- 每次访问最多 1 张，不自动刷新。
- 广告未填充时直接回退自然内容，不保留空白占位。

### 4.2 H1 首页原生混投

- `experiment_traffic_ratio` 与 `content_ad_ratio` 分开配置。
- `experiment_traffic_ratio` 表示进入 H1 策略的稳定用户比例。
- `content_ad_ratio` 表示 H1 合格内容机会中使用付费广告的比例。
- “今日推荐”保持纯自然内容，不被广告替换。
- 广告位于“为你推荐”横向列表，先展示至少 3 张自然游戏，再插入同规格赞助游戏卡。
- 付费素材必须写“广告”或“赞助推荐”，不得使用“今日推荐”“编辑精选”语义。
- 不自动播放有声视频，不自动刷新。
- 无广告或加载失败时回退自营内容。

后台允许运营在 0%～100% 范围配置内容占比，但：

- 默认上线配置由实验方案给出，不写死在客户端；
- 高于 30% 时后台展示明显风险提示并要求二次确认；
- 每次变更生成新 `policy_version`，保留操作者、时间、旧值和新值；
- 自动熔断触发后，普通运营配置不能绕过熔断恢复，需由授权角色确认。

### 4.3 C1 签到时长加倍激励

入口位于现有云游戏页“每日签到”卡的“签到”按钮，不在默认页面提前增加广告按钮。主流程：

```text
用户点击“签到”
→ 服务端先发放基础签到时长
→ 展示“签到成功，获得 X 分钟”结果弹层
→ 用户可选择“看广告再领 X 分钟”或“完成”
→ 完整观看并通过幂等校验
→ 补发与基础签到同额的加倍时长
```

规则：

- 原签到权益不以观看广告为前提；点击“签到”不能直接自动播放广告。
- 基础奖励先到账，广告失败、提前退出或校验失败不补发加倍奖励，也不回收基础奖励。
- 基础奖励、加倍奖励、开放人群和投放频率由后台/服务端配置，客户端不写死“1 小时”。
- 无广告填充时只完成普通签到，不展示空弹层或失效入口。
- 加倍奖励使用独立 `reward_id` 幂等发放，重复回调不得重复加时长。
- ROI 必须扣除额外时长的实际使用成本；基础签到 1 小时时，额外同额奖励的完全分摊成本可能显著高于单次激励广告收入，只能通过实验验证，不能按广告流水直接判断成功。

### 4.4 G1 零时长激励

主流程：

```text
用户在启动前进入时长不足状态
→ 展示“看约 X 秒广告，获得 Y 分钟”
→ 用户主动选择观看或离开
→ 广告完整观看
→ 服务端幂等校验
→ 奖励到账
→ 用户确认或系统继续原启动意图
```

规则：

- 首次奖励建议 5 分钟，生命周期最多 1 次；具体分钟数后台可配。
- 日常奖励建议 3 分钟，每日最多 1 次；次数与分钟数后台可配。
- 必须提供非广告出口，不得把广告包装成唯一选择。
- 广告失败或回调超时不扣用户次数。
- 已完成观看但回调延迟时，服务端必须支持补发。
- 不允许奖励视频后串联插屏或第二条视频。
- 奖励发放必须以服务端交易号幂等，重复发奖可追溯。

云容量按实时集群控制：

| 实时利用率 | 建议策略 |
|---:|---|
| 低于 75% | 正常开放首次和日常奖励 |
| 75%～85% | 降低奖励分钟、限制非高峰或减少次数 |
| 高于 85% | 隐藏入口，不新增免费时长 |

服务器当前为包月成本、平均利用率约 70%。财务同时记录现金边际成本和完全分摊成本。按完全分摊约 0.80 元/小时计算，3 分钟约 0.04 元，5 分钟约 0.0667 元。

日常奖励继续放量的最低条件：

```text
每次完整观看的实际广告收入
>= 单次奖励完全成本 × 1.3
```

### 4.5 Q1 排队加速激励

触发条件：

- 用户正在免费通道排队，未进入付费快速通道；
- 服务端预计等待时间大于后台 `queue_wait_threshold_minutes`；
- Q1 开关、人群、地区、版本、奖励频控和广告可用性均合格；
- 同一 `game_intent_session_id` 尚未成功使用 G1 或 Q1；
- 用户主动点击“看广告加速排队”，不允许自动播放。

展示与结算：

- 入口沿用原排队页“加速排队”区域，建议文案为“看广告加速排队”“约 15 秒｜加速排队并领取 5 分钟｜今日剩 1 次”；秒数、分钟和次数由服务端返回。
- 完整观看并通过服务端校验后，用户进入后台配置的加速通道并获得秒玩时长；客户端只展示服务端返回的新预计等待时间，不承诺固定提升名次。
- 广告播放期间继续维持排队心跳并保留原位置。提前关闭、播放失败或校验失败不发权益、不扣次数、不改变原排队位置。
- 校验超时显示“权益确认中”，自动查询 `reward_id`，不得要求用户重看。
- 广告播放期间若已经排到，直接进入游戏并只发秒玩时长；用户已退出排队但完成观看时，只发时长、不重新入队。
- `reward_id` 为幂等键，重复回调不得重复发时长或重复切换通道。
- G1 与 Q1 同一游戏意图会话互斥；任一成功发放权益后，另一入口立即隐藏。

公平性保护：

- 加速通道容量和等级由排队服务控制，运营只选择服务端允许的枚举值；
- 持续监控未观看 Q1 用户的等待时间中位数与 P90；相对对照上升 3%预警、达到 5%停止 Q1；
- 不能用广告收益覆盖普通排队用户等待恶化，ROI 必须扣除排队外部性。

### 4.6 L1 PC 游戏启动等待原生广告

L1 覆盖同一 PC 启动会话中的两个正常等待阶段：

1. 固件/运行环境准备；
2. Steam 与客户端启动。

展示规则：

- 两阶段属于同一个 L1 资源位，共用 `startup_session_id`、`ad_request_id`、素材和曝光身份；阶段切换不刷新素材、不生成第二次曝光。
- 广告固定在横屏画面右侧安全区，Demo 874×402 画布参考为 `top:58px; right:22px; width:204px; height:140px`，实际客户端按安全区比例适配。
- 只允许静态或无声原生素材，持续显示“广告/AdChoices”；禁止全屏插屏、视频贴片、自动播放声音、页面变暗和倒计时等待。
- 不遮挡底部进度条、进度文字、错误提示、Steam/客户端关系图、麦克风入口和 GameFusion 标识。
- 广告请求、加载和渲染不得增加启动耗时；游戏准备完成时立即进入游戏，不等待广告达到时长。
- 启动失败、兼容错误、弱网、重连、排障或右侧安全区不足时立即隐藏或不展示。
- 无填充、超时或 SDK 异常时恢复原纯黑页面，不保留空框、不改变启动布局。
- 两阶段开关、人群、投放比例和频率全部由运营后台配置；产品只定义固定位置和不可绕过的保护规则。

点击广告时启动任务继续执行。用户关闭模拟落地页后返回最新启动状态；若游戏已准备完成，则直接进入游戏。

### 4.7 O1 老用户低频开屏

真正冷启动定义为：App 进程已结束，由用户主动点击桌面图标启动。

以下情况全部排除：

- 后台恢复；
- Push、Deep Link 或外部分享唤起；
- 游戏或云游返回；
- 支付或登录回跳；
- 崩溃恢复；
- 版本更新后首次启动；
- 长时间沉默后的首次回流。

合格老用户默认定义为注册满 7 天且成功启动游戏不少于 3 次，后台可进一步收紧。广告未预加载完成时直接进入首页，不能为了等待广告延长启动。

## 5. 后台配置设计

### 5.1 广告位基础配置

每个 `placement_id` 独立支持：

- 总开关；
- 国家/地区；
- Android 版本、App 版本、渠道、设备性能和网络类型；
- 新用户、老用户、注册天数、成功游戏次数；
- 广告网络、广告格式、素材行业白名单/黑名单；
- 生效时间、结束时间；
- 填充失败回退策略；
- 一键熔断。

### 5.2 三类比例必须独立

| 参数 | 含义 | 示例 |
|---|---|---|
| `experiment_traffic_ratio` | 有多少稳定用户进入某实验策略 | H1 10% 用户 |
| `content_ad_ratio` | 合格内容机会中有多少使用广告 | H1 30% 内容机会 |
| `frequency_cap` | 单个用户在周期内最多看到多少次 | 1 天 1 次、7 天 3 次、永久 1 次 |

任一参数调整不得隐式修改另外两个参数。

### 5.3 频控表达能力

后台至少支持：

- 每会话 N 次；
- 每日 N 次；
- X 天 N 次；
- 生命周期 N 次；
- 两次展示最短间隔；
- 跨广告位冷却；
- “O1 已展示后，本会话不再展示其他非自愿全屏广告”等仲裁规则。
- “G1 或 Q1 已在同一游戏意图会话成功发放权益后，另一入口立即隐藏”的互斥规则。

Q1 还需独立配置等待阈值、赠送时长、加速等级和奖励次数。C1 配置基础奖励展示、加倍奖励与奖励频控。L1 配置阶段一/阶段二开关、素材格式、投放比例和频率；两个阶段仍使用同一 `placement_id`。以上字段与互斥开关作为同一策略版本发布。国内穿山甲和海外 AdMob 分 Tab 独立保存。

产品文档只规定后台必须具备这些表达能力，不替运营锁定“一天一次”“X 天 X 次”或其他正式投放值；Demo 中出现的数值仅用于演示配置能力。

### 5.4 配置治理

- 所有配置发布前展示预计覆盖用户和预计曝光变化。
- 高风险变更需要二次确认。
- 配置发布生成 `policy_version`，支持一键回滚上一版本。
- 保留操作者、审批者、发布时间、变更原因和差异记录。
- 客户端配置缓存失效时使用最近一版安全配置；无可用配置时默认不展示广告。

## 6. 广告网络与路由

- 国内约 60% 流量优先使用穿山甲。
- 海外约 40% 流量优先使用 AdMob。
- 首期不额外接入更多广告 SDK。
- 客户端通过统一广告接口调用不同网络适配器，业务页面不直接依赖具体 SDK。
- 地区、网络或隐私状态无法确认时不请求广告。
- 在获得真实 eCPM、填充率、崩溃率和包体影响后，再决定是否接入聚合或备用网络。

## 7. 实验设计

### 7.1 实验前置

先运行 2～3 天 A/A：所有组均不展示新广告，仅验证稳定分桶、事件完整性、收入回调、用户特征和页面指标是否均衡。

### 7.2 H1 与 P1 首轮互斥实验

| 组别 | 比例 | 策略 |
|---|---:|---|
| 长期无新广告组 | 10% | 不进入本期任何新广告实验 |
| 阶段对照组 | 70% | 当前不展示 H1/P1 |
| H1 组 | 10% | 仅受 H1 配置影响 |
| P1 组 | 10% | 仅受 P1 配置影响 |

灰度顺序：`1% → 5% → 10%`。达到目标比例后冻结实验配置，至少观察 14 天；需要判断 7 日留存（retention D7）时，总实验周期建议 21 天。

实验按 `user_id` 稳定分桶并采用意向分析，不能只分析成功曝光用户。

### 7.3 G1 实验

在零时长埋点积累足够样本后，对合格用户分组：

| 组别 | 比例 | 策略 |
|---|---:|---|
| 对照 | 50% | 保持现有零时长流程 |
| 首次奖励 | 25% | 仅生命周期首次奖励 |
| 首次＋日常 | 25% | 首次奖励加每日奖励 |

建议观察 21～28 天，并单独测算云容量、奖励后真实游戏分钟和业务收入蚕食。

### 7.4 Q1 实验

| 组别 | Demo 初始比例 | 策略 |
|---|---:|---|
| 对照组 | 50% | 现有免费排队，不展示 Q1 |
| 仅加时长组 | 25% | 完整观看后只发秒玩时长 |
| 加速＋时长组 | 25% | 完整观看后发时长并切换加速通道 |

比例由运营在后台按国内/海外独立配置，以上只作 Demo 初始值。实验按“进入免费排队且预计等待超过阈值”的用户做意向分析；除广告收入外，必须同时比较排队退出率、进入游戏率、实际等待时间和非广告用户等待时间。Q1 与 G1 同一游戏意图会话互斥。

### 7.5 C1 实验

C1 至少比较“普通签到”和“普通签到＋可选广告加倍”两组，比例、奖励时长与频率由运营按地区配置。除广告收入外，必须比较签到完成率、视频完成率、额外时长实际使用率、云成本、后续付费和留存；基础签到权益在两组中保持一致。

### 7.6 L1 实验

L1 至少保留无广告对照组和右侧原生广告实验组，阶段一/阶段二可由运营分别开关，但两阶段共用同一 L1 请求。除广告收入外，必须比较启动耗时、启动成功率、启动取消率、错误率和广告点击后返回启动链路的恢复情况。

### 7.7 O1 实验

| 组别 | 比例 | 策略 |
|---|---:|---|
| 对照 | 90% | 无开屏 |
| 生命周期一次 | 5% | 永久最多一次 |
| 周期低频 | 5% | 每 7 天最多一次 |

仅在 H1/P1/G1 稳定后开始，观察 21～28 天。

## 8. 收益和 ROI

### 8.1 情景估算

使用原生 eCPM 5/10/15 元、填充率 80%、渲染率 95%进行敏感性分析：

| 资源位 | 全量可执行月收入情景 | 置信度 |
|---|---:|---|
| H1，受限内容占比 | 约 1.2 万～4.5 万元 | 中低 |
| P1 | 约 0.8 万～4.5 万元 | 中低 |
| C1 | 待签到人数、视频完成率、额外时长使用率和云成本 | 低 |
| G1 | 待零时长人数、完成率和真实收入回调 | 低 |
| Q1 | 待校准长排队人数、完成率、进入游戏增量和普通用户等待外部性 | 低 |
| L1 | 以 `game_play_success` 约 105.25 万次/周为机会量上限粗估约 1.7 万～5.2 万元，仍需乘合格率、投放率和有效曝光率 | 低 |
| O1，7 天 1 次 | 约 1 万～3.5 万元 | 低 |

各资源位覆盖用户重叠，且受全局频控影响，以上数字不能直接相加。首阶段应先证明单个原生资源位可以稳定贡献约 1 万～5 万元/月且不触发用户损伤；多个位置验证后，4 万～10 万元/月可作为阶段性情景。10 万～20 万元需要更高 eCPM、更多密度或 O1 贡献，不作为首期承诺。

### 8.2 ROI 统一口径

```text
增量净收益
= 实验组广告实际结算收入 - 对照组广告收入
- 被替换自营推荐的价值
- 奖励云时长成本
- 加速通道对普通排队用户造成的等待外部性
- 对业务付费的蚕食
- 留存损失对应的 LTV
- 接入及维护成本分摊
```

主决策指标为“增量净收益/合格用户”和“增量总 LTV”，不是广告曝光数、CTR 或广告 ARPDAU。

## 10. 指标与熔断

### 10.1 共同指标

- 增量广告净收入/合格用户；
- request、fill、render、viewable impression、eCPM；
- 次日/7 日留存（retention D1/D7）；
- 会话数、会话时长、游戏启动率和启动成功率；
- 自然内容点击、详情进入和云游进入；
- Crash-free users、ANR、首屏可交互时间；
- 广告后快速返回、卸载、投诉和负反馈。
- C1 签到成功、加倍入口曝光、视频完成、奖励成功、额外时长实际使用和增量云成本；
- Q1 入口曝光、点击、完成、双权益成功、加速前后预计等待、实际等待、排队退出和进入游戏；
- 未观看 Q1 用户的等待时间中位数与 P90。
- L1 两阶段机会、共享请求延续率、有效曝光、点击、启动耗时、启动成功率、启动取消率和错误状态误展示数。

### 10.2 统计止损

- 次日留存（retention D1）绝对下降不少于 0.5 个百分点，或相对下降不少于 3%；
- D7 留存绝对下降不少于 0.3 个百分点，或相对下降不少于 2%；
- 游戏启动成功率绝对下降不少于 1 个百分点，或相对下降不少于 3%；
- 自然内容点击相对下降 2%预警、下降 5%停止；
- O1 冷启动 10 秒内退出率增加不少于 1 个百分点；
- P95 首屏可交互时间增加超过 300ms。
- C1 增量广告收入无法覆盖额外已使用时长成本与付费蚕食时停止放量；
- Q1 加速＋时长组的排队退出率高于对照 3%预警、高于 5%停止；
- 未观看 Q1 用户等待时间中位数或 P90 相对对照上升 3%预警、达到 5%停止。
- L1 游戏启动成功率、启动耗时或启动取消率达到共同止损阈值时停止；任何可确认的广告延迟启动直接熔断。

业务指标在预设检查点判断，避免频繁查看造成错误结论。

### 10.3 无需统计显著的事故熔断

- 广告出现在任一禁投流程；
- Crash-free users 下降不少于 0.2 个百分点或 ANR 增加不少于 0.1 个百分点；
- C1 基础签到奖励因广告流程漏发，或加倍奖励出现重复发放；
- G1 奖励漏发率超过 0.2%；
- Q1 时长漏发率超过 0.2%，或出现重复发时长、重复加速；
- 出现可确认的重复发奖；
- L1 出现在启动失败、兼容错误、弱网、重连或排障状态，遮挡进度/错误/品牌信息，或阶段切换生成第二次广告曝光；
- 频控违规率超过 0.1%；
- 收入回调与广告平台账单偏差超过 5%；
- 出现赌博、现金贷、色情擦边、仿系统弹窗、虚假关闭或诱导点击素材。

## 11. 上线顺序

```text
统一广告接口、后台配置、埋点、稳定分桶、熔断
→ 2～3 天 A/A
→ H1 与 P1 互斥小流量实验
→ 放大增量净收益更优的原生广告位
→ C1 签到加倍激励实验（按额外时长实际使用成本核算）
→ G1 零时长激励实验
→ Q1 排队加速＋时长激励实验（与 G1 同会话互斥）
→ L1 PC 启动右侧原生广告实验
→ O1 老用户低频开屏实验
```

运营可在各阶段调整比例和频控，但每次调整必须产生新策略版本；正在进行统计判断的实验原则上冻结核心参数，若中途调整则作为新实验版本重新计算。

## 12. 验收要点

1. 运营可以分别配置实验流量比例、内容广告占比和频控，三者互不联动。
2. 同一 `user_id` 在同一实验版本中稳定分桶，重启、跨天或配置刷新不改变分组。
3. 禁投流程无法通过普通广告位配置绕过。
4. 广告无填充、加载失败或超时不阻塞页面和游戏流程。
5. 所有展示和收益可关联到广告位、策略版本、实验组、用户和请求。
6. C1 点击签到先发放基础奖励；广告加倍必须由用户二次主动选择，失败不影响基础奖励，重复回调不重复发放。
7. G1 服务端发奖幂等，支持回调延迟补偿和重复发奖审计。
8. Q1 仅由免费通道长排队用户主动触发；播放期间保持排队，结算按当前排队状态幂等发放双权益或仅发时长。
9. G1/Q1 同一游戏意图会话互斥，校验超时不得要求用户重看广告。
10. L1 两个正常启动阶段共用一个请求和曝光身份；固定在右侧安全区，不延迟启动，完成或异常立即隐藏。
11. 后台支持单广告位一键熔断，配置变更可审计、可回滚。
12. 国内与海外路由正确，隐私或地区状态不明时默认不请求广告。
13. H1/P1 不伪装为自然排名、编辑推荐或用户资产。
14. 搜索页和详情页不展示商业赞助；游戏运行中、启动失败和重连流程广告曝光数必须为 0；正常 PC 启动等待仅允许 L1，排队阶段仅允许主动 Q1。
