# 盖世游戏 Android 广告接入规划设计

> 日期：2026-07-17
>
> 状态：待产品、运营、研发评审
>
> 范围：Android 首期广告商业化；会员相关能力不在本期范围

## 1. 目标与原则

在不显著损伤留存、游戏启动体验和平台推荐可信度的前提下，验证广告商业化的真实收益，并形成可由运营后台控制、可稳定实验、可实时熔断的广告能力。

本期原则：

1. 国内流量优先接入穿山甲，海外流量优先接入 AdMob。
2. 原生广告可覆盖符合规则的全部用户；强打断广告仅对老用户小流量实验。
3. 广告比例、用户流量、频控均由后台配置，不在客户端写死。
4. 运营可调整配置，但无广告长期对照组、禁投流程和技术熔断不受普通运营配置覆盖。
5. 先取得真实的 `ad_paid`、eCPM、填充和用户损伤数据，再决定是否扩大密度或增加广告网络。
6. 广告收益以“增量净收益”衡量，不以广告平台流水单独判断成功。

```text
实际展示量
= 合格机会数
× 广告请求率
× 填充率
× 渲染成功率
× 可见率
× 频控系数
```

## 3. 资源位规划

### 3.1 首期候选

| ID | 位置 | 形式 | 初始建议 | 风险 | 优先级 |
|---|---|---|---|---|---|
| P1 | “玩游戏”页第一组完整自然内容后 | 原生赞助游戏卡 | 单次访问最多 1 张 | 低 | P0 |
| H1 | 首页“今日推荐”大卡混投；不得默认占据第一推荐 | 原生信息流/原生大卡 | 由运营配置内容占比 | 中 | P0 实验 |
| G1 | 零时长用户主动领取额外时长 | 激励视频 | 首次与日常奖励分开配置 | 低到中 | P1 |
| D1 | 游戏详情核心启动、兼容和配置内容之后 | 相关游戏/外设赞助卡 | 需先补滚动深度数据 | 低 | P2 |
| S1 | 搜索无结果页 | 相关赞助推荐 | 需先补机会量 | 低 | P2 |
| O1 | 老用户真正冷启动 | 开屏/App Open | 仅小流量实验 | 高 | P3 |

### 3.2 禁投范围

以下范围不允许通过普通运营配置开放：

- 用户点击“立即游戏/秒玩/启动”之后，直到首个可操作游戏画面出现前的完整链路；
- 固件安装、组件安装、资源检查、排队、调度、客户端启动、连接、加载；
- 启动失败、兼容性错误、弱网、重连和崩溃恢复；
- 游戏运行中、虚拟按键、控制器和操作面板；
- 登录、实名、隐私授权、权限、支付；
- 下载、领取、导入、配置、空间不足和排障；
- 个人游戏库的用户资产列表；
- 从游戏、云游或其他 App 返回盖世时的插屏或开屏。

G1 必须发生在启动请求创建前。奖励到账后再创建独立的游戏启动请求；启动请求一旦创建，后续链路不再出现广告。

## 4. 各资源位详细规则

### 4.1 P1 玩游戏页赞助卡

- 先展示 4～6 个自然游戏或一个完整自然内容组，再展示赞助卡。
- 不进入“最近常玩”“我的游戏库”等用户资产区域。
- 不伪装为榜单名次、编辑推荐、玩家评分或热门标签。
- 卡片可沿用游戏卡尺寸，但必须持续显示“广告”或“赞助”标识。
- 不遮挡秒玩、启动或下载操作。
- 每次访问最多 1 张，不自动刷新。
- 广告未填充时直接回退自然内容，不保留空白占位。

### 4.2 H1 首页原生混投

- `experiment_traffic_ratio` 与 `content_ad_ratio` 分开配置。
- `experiment_traffic_ratio` 表示进入 H1 策略的稳定用户比例。
- `content_ad_ratio` 表示 H1 合格内容机会中使用付费广告的比例。
- 如果首页大卡存在轮播或多卡，广告不得成为默认第一张。
- 如果首页只有唯一首位大卡，广告应下移到第一组自然内容之后，不直接替换唯一核心推荐。
- 付费素材必须写“广告”或“赞助推荐”，不得继续使用“今日推荐”“编辑精选”语义。
- 不自动播放有声视频，不自动刷新。
- 无广告或加载失败时回退自营内容。

后台允许运营在 0%～100% 范围配置内容占比，但：

- 默认上线配置由实验方案给出，不写死在客户端；
- 高于 30% 时后台展示明显风险提示并要求二次确认；
- 每次变更生成新 `policy_version`，保留操作者、时间、旧值和新值；
- 自动熔断触发后，普通运营配置不能绕过熔断恢复，需由授权角色确认。

### 4.3 G1 零时长激励

主流程：

```text
用户在启动前进入时长不足状态
→ 展示“看约 X 秒广告，获得 Y 分钟”
→ 用户主动选择观看或离开
→ 广告完整观看
→ 服务端幂等校验
→ 奖励到账
→ 用户确认或系统继续原启动意图
```

规则：

- 首次奖励建议 5 分钟，生命周期最多 1 次；具体分钟数后台可配。
- 日常奖励建议 3 分钟，每日最多 1 次；次数与分钟数后台可配。
- 必须提供非广告出口，不得把广告包装成唯一选择。
- 广告失败或回调超时不扣用户次数。
- 已完成观看但回调延迟时，服务端必须支持补发。
- 不允许奖励视频后串联插屏或第二条视频。
- 奖励发放必须以服务端交易号幂等，重复发奖可追溯。

云容量按实时集群控制：

| 实时利用率 | 建议策略 |
|---:|---|
| 低于 75% | 正常开放首次和日常奖励 |
| 75%～85% | 降低奖励分钟、限制非高峰或减少次数 |
| 高于 85% | 隐藏入口，不新增免费时长 |

服务器当前为包月成本、平均利用率约 70%。财务同时记录现金边际成本和完全分摊成本。按完全分摊约 0.80 元/小时计算，3 分钟约 0.04 元，5 分钟约 0.0667 元。

日常奖励继续放量的最低条件：

```text
每次完整观看的实际广告收入
>= 单次奖励完全成本 × 1.3
```

### 4.4 O1 老用户低频开屏

真正冷启动定义为：App 进程已结束，由用户主动点击桌面图标启动。

以下情况全部排除：

- 后台恢复；
- Push、Deep Link 或外部分享唤起；
- 游戏或云游返回；
- 支付或登录回跳；
- 崩溃恢复；
- 版本更新后首次启动；
- 长时间沉默后的首次回流。

合格老用户默认定义为注册满 7 天且成功启动游戏不少于 3 次，后台可进一步收紧。广告未预加载完成时直接进入首页，不能为了等待广告延长启动。

## 5. 后台配置设计

### 5.1 广告位基础配置

每个 `placement_id` 独立支持：

- 总开关；
- 国家/地区；
- Android 版本、App 版本、渠道、设备性能和网络类型；
- 新用户、老用户、注册天数、成功游戏次数；
- 广告网络、广告格式、素材行业白名单/黑名单；
- 生效时间、结束时间；
- 填充失败回退策略；
- 一键熔断。

### 5.2 三类比例必须独立

| 参数 | 含义 | 示例 |
|---|---|---|
| `experiment_traffic_ratio` | 有多少稳定用户进入某实验策略 | H1 10% 用户 |
| `content_ad_ratio` | 合格内容机会中有多少使用广告 | H1 30% 内容机会 |
| `frequency_cap` | 单个用户在周期内最多看到多少次 | 1 天 1 次、7 天 3 次、永久 1 次 |

任一参数调整不得隐式修改另外两个参数。

### 5.3 频控表达能力

后台至少支持：

- 每会话 N 次；
- 每日 N 次；
- X 天 N 次；
- 生命周期 N 次；
- 两次展示最短间隔；
- 跨广告位冷却；
- “O1 已展示后，本会话不再展示其他非自愿全屏广告”等仲裁规则。

### 5.4 配置治理

- 所有配置发布前展示预计覆盖用户和预计曝光变化。
- 高风险变更需要二次确认。
- 配置发布生成 `policy_version`，支持一键回滚上一版本。
- 保留操作者、审批者、发布时间、变更原因和差异记录。
- 客户端配置缓存失效时使用最近一版安全配置；无可用配置时默认不展示广告。

## 6. 广告网络与路由

- 国内约 60% 流量优先使用穿山甲。
- 海外约 40% 流量优先使用 AdMob。
- 首期不额外接入更多广告 SDK。
- 客户端通过统一广告接口调用不同网络适配器，业务页面不直接依赖具体 SDK。
- 地区、网络或隐私状态无法确认时不请求广告。
- 在获得真实 eCPM、填充率、崩溃率和包体影响后，再决定是否接入聚合或备用网络。

## 7. 实验设计

### 7.1 实验前置

先运行 2～3 天 A/A：所有组均不展示新广告，仅验证稳定分桶、事件完整性、收入回调、用户特征和页面指标是否均衡。

### 7.2 H1 与 P1 首轮互斥实验

| 组别 | 比例 | 策略 |
|---|---:|---|
| 长期无新广告组 | 10% | 不进入本期任何新广告实验 |
| 阶段对照组 | 70% | 当前不展示 H1/P1 |
| H1 组 | 10% | 仅受 H1 配置影响 |
| P1 组 | 10% | 仅受 P1 配置影响 |

灰度顺序：`1% → 5% → 10%`。达到目标比例后冻结实验配置，至少观察 14 天；需要判断 D7 留存时，总实验周期建议 21 天。

实验按 `user_id` 稳定分桶并采用意向分析，不能只分析成功曝光用户。

### 7.3 G1 实验

在零时长埋点积累足够样本后，对合格用户分组：

| 组别 | 比例 | 策略 |
|---|---:|---|
| 对照 | 50% | 保持现有零时长流程 |
| 首次奖励 | 25% | 仅生命周期首次奖励 |
| 首次＋日常 | 25% | 首次奖励加每日奖励 |

建议观察 21～28 天，并单独测算云容量、奖励后真实游戏分钟和业务收入蚕食。

### 7.4 O1 实验

| 组别 | 比例 | 策略 |
|---|---:|---|
| 对照 | 90% | 无开屏 |
| 生命周期一次 | 5% | 永久最多一次 |
| 周期低频 | 5% | 每 7 天最多一次 |

仅在 H1/P1/G1 稳定后开始，观察 21～28 天。

## 8. 收益和 ROI

### 8.1 情景估算

使用原生 eCPM 5/10/15 元、填充率 80%、渲染率 95%进行敏感性分析：

| 资源位 | 全量可执行月收入情景 | 置信度 |
|---|---:|---|
| H1，受限内容占比 | 约 1.2 万～4.5 万元 | 中低 |
| P1 | 约 0.8 万～4.5 万元 | 中低 |
| G1 | 待零时长人数、完成率和真实收入回调 | 低 |
| D1 | 粗估 1 万～8 万元 | 低 |
| O1，7 天 1 次 | 约 1 万～3.5 万元 | 低 |

各资源位覆盖用户重叠，且受全局频控影响，以上数字不能直接相加。首阶段应先证明单个原生资源位可以稳定贡献约 1 万～5 万元/月且不触发用户损伤；多个位置验证后，4 万～10 万元/月可作为阶段性情景。10 万～20 万元需要更高 eCPM、更多密度或 O1 贡献，不作为首期承诺。

### 8.2 ROI 统一口径

```text
增量净收益
= 实验组广告实际结算收入 - 对照组广告收入
- 被替换自营推荐的价值
- 奖励云时长成本
- 对业务付费的蚕食
- 留存损失对应的 LTV
- 接入及维护成本分摊
```

主决策指标为“增量净收益/合格用户”和“增量总 LTV”，不是广告曝光数、CTR 或广告 ARPDAU。

## 9. 埋点与数据契约

### 9.1 通用广告漏斗

```text
experiment_assignment
→ ad_eligible
→ ad_request
→ ad_fill / ad_fail
→ ad_render
→ ad_impression
→ ad_click
→ ad_close
→ ad_paid
```

通用字段：

- `user_id`
- `session_id`
- `placement_id`
- `experiment_id`
- `bucket_id`
- `policy_version`
- `network`
- `country_group`
- `ad_format`
- `content_position`
- `request_id`
- `launch_type`
- `revenue_micros`
- `currency`
- `error_code`

广告曝光使用 SDK 有效曝光和可见口径，不能在列表创建或请求成功时上报。

### 9.2 G1 专项事件

```text
cloud_zero_balance_launch
reward_offer_exposure
reward_offer_click
reward_video_start
reward_video_complete
reward_grant_request
reward_grant_success / reward_grant_fail
reward_launch_continue
reward_cloud_minutes_used
```

需关联奖励交易号、奖励分钟、到账耗时、实际使用分钟、实时集群利用率及后续业务转化。

### 9.3 O1 专项字段

`app_launch` 必须补充：

- 冷启动/热启动；
- 桌面图标/Push/Deep Link/外部回跳；
- 崩溃恢复；
- 更新后首启；
- 距离上次活跃时间；
- 是否满足老用户条件。

## 10. 指标与熔断

### 10.1 共同指标

- 增量广告净收入/合格用户；
- request、fill、render、viewable impression、eCPM；
- D1、D7 留存；
- 会话数、会话时长、游戏启动率和启动成功率；
- 自然内容点击、详情进入和云游进入；
- Crash-free users、ANR、首屏可交互时间；
- 广告后快速返回、卸载、投诉和负反馈。

### 10.2 统计止损

- D1 留存绝对下降不少于 0.5 个百分点，或相对下降不少于 3%；
- D7 留存绝对下降不少于 0.3 个百分点，或相对下降不少于 2%；
- 游戏启动成功率绝对下降不少于 1 个百分点，或相对下降不少于 3%；
- 自然内容点击相对下降 2%预警、下降 5%停止；
- O1 冷启动 10 秒内退出率增加不少于 1 个百分点；
- P95 首屏可交互时间增加超过 300ms。

业务指标在预设检查点判断，避免频繁查看造成错误结论。

### 10.3 无需统计显著的事故熔断

- 广告出现在任一禁投流程；
- Crash-free users 下降不少于 0.2 个百分点或 ANR 增加不少于 0.1 个百分点；
- G1 奖励漏发率超过 0.2%；
- 出现可确认的重复发奖；
- 频控违规率超过 0.1%；
- 收入回调与广告平台账单偏差超过 5%；
- 出现赌博、现金贷、色情擦边、仿系统弹窗、虚假关闭或诱导点击素材。

## 11. 上线顺序

```text
统一广告接口、后台配置、埋点、稳定分桶、熔断
→ 2～3 天 A/A
→ H1 与 P1 互斥小流量实验
→ 放大增量净收益更优的原生广告位
→ G1 零时长激励实验
→ D1 详情页与 S1 搜索无结果探索
→ O1 老用户低频开屏实验
```

运营可在各阶段调整比例和频控，但每次调整必须产生新策略版本；正在进行统计判断的实验原则上冻结核心参数，若中途调整则作为新实验版本重新计算。

## 12. 验收要点

1. 运营可以分别配置实验流量比例、内容广告占比和频控，三者互不联动。
2. 同一 `user_id` 在同一实验版本中稳定分桶，重启、跨天或配置刷新不改变分组。
3. 禁投流程无法通过普通广告位配置绕过。
4. 广告无填充、加载失败或超时不阻塞页面和游戏流程。
