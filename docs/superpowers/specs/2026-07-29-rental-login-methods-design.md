# 游戏租号双登录方式设计

## 一、设计目标

用户取号成功后可自行选择“一键上号”或“手动登录”。手动登录提供 Steam 账号、密码和动态令牌验证码获取器，同时保证两种方式共用同一账号占用，且登录信息只在有效使用单内可访问。

本设计不改变已确认的权益结构：

1. 每位用户全平台仅可购买一次首次时租体验。
2. 后续可购买当前单款游戏永久版。
3. 月度会员可畅玩后台配置的会员游戏库。
4. 月度会员同一时间仅可占用一个游戏账号。

## 二、核心决策

### 2.1 登录方式

账号分配成功后打开“选择登录方式”弹窗，并列展示：

1. **一键上号**：客户端自动建立 Steam 租赁会话并登录。
2. **手动登录**：用户进入登录信息弹窗，自行复制账号、密码并获取动态令牌验证码。

两种方式共用当前订单或会员使用单已分配的账号，不重新取号、不重复占用库存。用户选择一种方式失败后，可返回选择另一种方式。

### 2.2 展示入口

1. 首次体验或永久版支付并成功分配账号后，自动打开“选择登录方式”弹窗。
2. 月度会员选择游戏并成功创建会员使用单后，自动打开相同弹窗。
3. 有效使用单的订单详情持续提供“一键上号”和“登录信息”两个入口。
4. 待支付、已结束、已退款、已取消、账号释放中或账号异常的订单，不展示登录入口。

### 2.3 手动登录信息

登录信息弹窗包含：

- Steam 账号：默认部分遮罩，支持查看和复制。
- Steam 密码：默认完全遮罩，支持查看和复制。
- Steam 令牌验证码：默认不获取；用户点击“获取验证码”后请求服务端并展示验证码及剩余有效时间。
- 使用提示：说明信息仅用于当前使用单，不要分享；到期、换号、退款或结束使用后失效。

动态验证码格式和有效期以供应方返回为准。界面不固定为六位数字；Steam Guard 常见为五位字母数字组合。

## 三、交互流程

### 3.1 一键上号

取号成功 → 选择“一键上号” → 服务端校验使用单与账号绑定 → 客户端建立租赁会话 → 登录成功后进入下载或启动流程。

失败时保留当前账号占用，展示失败原因及“重试一键上号”“改用手动登录”。只有明确判定账号不可用时才执行换号。

### 3.2 手动登录

取号成功 → 选择“手动登录” → 二次校验使用单状态 → 打开登录信息 → 用户按需查看或复制账号和密码 → 点击“获取验证码” → 服务端再次校验并返回当前验证码 → 用户完成 Steam 登录。

账号、密码和验证码的每次查看、复制、获取都重新校验：

- 当前用户与订单归属一致。
- 使用单状态有效。
- 当前账号仍绑定该使用单。
- 当前设备或租赁会话满足授权条件。
- 操作未超过限频阈值。

### 3.3 再次进入

用户关闭弹窗后，可在订单详情再次点击“登录信息”。重新进入时不复用页面内存中的明文值，客户端重新请求短时授权并获取当前登录信息。

### 3.4 权益切换

首次体验升级永久版且复用原账号时，原使用单结束，新使用单接管账号后重新签发登录信息访问权限。

月度会员切换游戏时，必须先结束旧使用单、撤销旧登录权限并释放账号，再为新游戏分配账号。旧账号释放失败时保留原使用单，不创建第二个会员使用单，也不展示新账号登录信息。

## 四、安全与数据设计

### 4.1 服务端授权

客户端不得直接保存账号库明文凭据。每次访问登录信息时，由服务端签发绑定“用户、使用单、账号、设备”的短时授权；授权到期后必须重新校验。

接口只在有效使用单内返回当前所需字段。账号密码与验证码不进入客户端持久化存储、缓存文件、崩溃日志、埋点、操作记录、导出文件或客服后台普通详情。

### 4.2 凭据回收硬门槛

手动登录功能只能用于支持凭据回收的自建账号或供应方账号。发生到期、退款、换号、强制结束或用户主动归还时，必须执行：

1. 撤销当前账号的租赁登录会话或全部非保留授权会话。
2. 轮换账号密码，或由供应方提供等效的凭据失效能力。
3. 清除当前使用单的登录信息访问授权。
4. 确认回收成功后，才将账号重新标记为可租。

任一步失败时，账号进入“回收异常”库存并停止分配，由后台生成告警和人工处理任务。不能只隐藏客户端界面后直接复用账号。

### 4.3 客户端防护

- 账号和密码默认遮罩，用户主动操作后才显示。
- 验证码按需获取，不在弹窗打开时自动返回。
- 应用窗口失去焦点时重新遮罩密码和验证码。
- 复制后提示用户妥善保管；如剪贴板内容仍为本次复制值，客户端可在限定时间后清除，但不得宣称可以阻止用户另行保存。
- 登录信息区域叠加当前订单号和用户标识水印，降低截图外传风险。
- 连续多次查看、复制或获取验证码触发限频；异常设备或高风险操作需重新验证登录态。

### 4.4 审计边界

安全审计只记录操作结果和上下文，不记录敏感值：

- 可记录：用户 ID、订单 ID、使用单 ID、账号资源 ID、设备 ID、操作类型、结果、错误码、时间。
- 禁止记录：Steam 账号原文、密码、验证码、共享密钥、授权令牌、供应方接口密钥。

## 五、异常处理

| 场景 | 处理方式 |
|---|---|
| 账号尚未分配 | 不打开登录方式选择，提示正在分配；超时后进入换号或退款流程 |
| 使用单已失效 | 关闭登录信息弹窗、清除页面明文并提示权益已结束 |
| 账号绑定变化 | 当前授权立即失效，重新进入时读取新账号信息 |
| 验证码获取失败 | 保留账号和密码，提示稍后重试；不返回过期验证码 |
| 验证码即将过期 | 显示剩余时间；到期后隐藏旧验证码并允许重新获取 |
| 查看或复制过于频繁 | 暂停操作并显示恢复时间，不影响当前有效订单 |
| 一键上号失败 | 保留账号占用，允许重试或切换手动登录 |
| 凭据回收失败 | 账号进入回收异常，不重新分配；使用单结束状态与回收状态分别记录 |
| 供应方不支持凭据回收 | 该账号不得进入可租池；系统改配满足要求的账号，无可用账号时停止履约并进入换号或退款流程 |
| 网络断开 | 已遮罩字段保持遮罩；未获取的敏感信息不使用本地旧缓存展示 |

## 六、后台调整

账号资源增加以下能力状态：

- 支持一键上号。
- 支持手动登录。
- 支持动态验证码。
- 支持会话撤销。
- 支持密码轮换或等效凭据失效。
- 最近凭据回收结果与时间。

账号只有在“手动登录、验证码、会话撤销、凭据失效”能力均通过健康检测后，才可进入可租池并创建新的使用单，保证每位取号成功的用户都能选择两种登录方式。

运营后台只允许有对应权限的人员触发账号健康检查和回收重试。普通运营、客服和操作记录详情均不展示账号密码或验证码。

## 七、埋点与监控

新增事件只记录方式、结果和耗时：

- 登录方式选择：`one_click`、`manual`。
- 登录信息页打开结果。
- 账号查看、密码查看、复制和验证码获取结果。
- 一键上号切换手动登录。
- 凭据回收结果和回收耗时。

所有事件禁止携带账号、密码、验证码和授权令牌。核心指标包括两种登录方式选择率、登录成功率、方式切换率、验证码获取成功率、凭据回收失败率和相关售后率。

## 八、验证范围

1. 有效首次体验、永久版和会员使用单均可选择两种登录方式。
2. 两种方式共用同一账号，不产生第二次取号或库存占用。
3. 已结束、已退款、已取消和回收异常状态不能查看登录信息。
4. 每次查看、复制和获取验证码均执行服务端状态校验。
5. 验证码到期后旧值不可继续展示。
6. 会员切换游戏先回收旧账号，再展示新账号登录信息。
7. 回收失败的账号不回到可租库存。
8. 日志、埋点、导出和后台普通详情不出现敏感明文。

## 九、范围边界

本期不提供账号邮箱、邮箱验证码、共享密钥、供应方后台入口或凭据导出；不承诺阻止用户通过拍照、外部设备或其他方式保存已主动展示的信息。
