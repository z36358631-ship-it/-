# 盖世游戏兼容性网页收敛改版设计规格

**日期：** 2026-08-07

**状态：** 已确认，待实现
**参考页面：** <https://gamenative.app/compatibility/>

## 1. 结论

将现有“游戏兼容库”复杂 Demo 收敛为一个兼容性查询页：复用 GameNative Compatibility 的页面结构和低操作成本，但完整保留盖世游戏的黑金视觉体系。

页面只保留三项即时筛选、热门游戏入口和兼容结果展示。删除双入口、分级筛选、游戏详情、GPU 详情、配置详情及配置下载/应用流程。

## 2. 用户、问题与现状

### 2.1 目标用户

准备在 Android 设备上通过盖世游戏运行 PC 游戏，但不确定当前设备是否可玩、预计帧率和需要什么运行环境的用户。

### 2.2 用户问题

- 下载或导入游戏前无法快速判断能否运行。
- 普通用户往往知道手机型号，但不知道对应 GPU。
- 兼容结果若缺少游戏版本、运行环境和验证时间，容易被误解为永久有效的承诺。

### 2.3 当前解决方式

用户需要在社区、视频、群聊或零散的测试记录中搜索同机型经验，再自行比对游戏版本、Android、盖世版本和内核版本。

现有 Demo 已实现游戏/GPU 双入口、复杂筛选、四层视图及配置下载应用，但完成一次“这款游戏在我的设备上能否运行”的判断需要理解过多概念和层级。

### 2.4 参考站做法

GameNative Compatibility 使用“游戏 / GPU / 评分”三个可搜索选择器，任一条件生效后直接展示兼容记录表。结果包含游戏、设备、GPU、Android、App 版本、评分、平均 FPS、标签、备注、配置和创建时间。

可借鉴点：

- 筛选与结果同页，选择后立即刷新。
- 无需进入详情页即可完成兼容判断。
- 桌面表格信息密度高，数据口径直接可见。

应规避点：

- 直接要求用户选择 GPU，认知门槛较高。
- 评分像输入条件又像查询结果，需明确为可选筛选。
- 移动端横向表格不利于快速阅读。
- 参考站品牌视觉不适合直接移植到盖世游戏。

## 3. 设计原则

1. **结构参考，品牌不复制：** 复用参考站的信息结构和即时查询方式，视觉保持盖世游戏黑金风格。
2. **一个页面完成判断：** 不增加详情页、抽屉、确认按钮或中间流程。
3. **用户语言优先：** 支持手机型号和 GPU 联合搜索，本机识别成功时优先展示本机。
4. **结论必须可追溯：** 兼容评价与游戏版本、运行环境、样本和更新时间同时出现。
5. **一份数据，两种布局：** 桌面表格和移动卡片仅是响应式呈现差异，不维护两套业务逻辑。

## 4. 页面结构

页面从上到下包含五个区域：

1. 返回入口。
2. 标题“游戏兼容性”和一句说明。
3. 三项筛选卡片。
4. 热门游戏或兼容结果容器。
5. Demo 环境中的桌面/移动预览控制。

### 4.1 筛选卡片

三项筛选为：

| 字段 | 默认状态 | 操作 |
|---|---|---|
| 选择游戏 | 未选择 | 支持中英文名、别名搜索；候选项显示本地封面和名称 |
| 设备 / GPU | 本机识别成功时显示本机，否则未选择 | 支持手机型号、芯片名称和 GPU 名称搜索 |
| 最低评价（可选） | 全部 | 支持 5、4 及以上、3 及以上、2 及以上、1 及以上 |

选择任一条件后立即计算结果，不设置“查询”或“确定”按钮。每个已选条件可单独清除。

### 4.2 热门游戏

无筛选条件时，在结果容器中展示六款热门游戏的真实封面和名称。点击封面等价于选中该游戏，并立即展示兼容结果。

热门游戏不是独立页面，不增加分类、排行榜、收藏或轮播。

### 4.3 兼容结果

桌面端使用表格，移动端使用单列紧凑卡片。两端字段一致：

- 游戏封面与名称。
- 设备型号与 GPU。
- 游戏版本。
- Android、盖世游戏和内核版本。
- 兼容评价。
- 平均 FPS。
- 问题标签。
- 简短备注。
- 验证样本或验证时间。

默认按兼容评价从高到低排序；评价相同时按验证时间从近到远排序。桌面端允许点击“兼容评价”和“验证时间”表头切换排序，移动端沿用同一排序结果，不增加单独排序控件。

## 5. 核心交互

### 5.1 通过热门游戏查询

1. 用户打开页面，看到热门游戏。
2. 用户点击游戏封面。
3. 游戏筛选自动填入，结果容器原位切换为兼容记录。

### 5.2 通过手机型号或 GPU 查询

1. 用户打开“设备 / GPU”选择器。
2. 输入手机型号、芯片或 GPU 名称。
3. 选择候选项后立即展示该设备或 GPU 的记录。
4. 若同时选择游戏和最低评价，则组间按 AND 过滤。

### 5.3 清除与恢复

- 清除单项筛选后立即用剩余条件重新计算。
- 清除全部筛选后恢复热门游戏。
- 无结果时保留当前条件，显示“暂无符合条件的兼容记录”和“清空筛选”。
- 切换桌面/移动预览时保留筛选和排序状态。

## 6. 视觉规范

### 6.1 盖世游戏风格

- 页面背景使用纯黑或接近纯黑，不使用 GameNative 的紫青渐变。
- 卡片使用深灰底、低对比描边和轻量阴影。
- 主色使用盖世游戏金黄，正文为白色，说明文字为低饱和灰色。
- 沿用现有 Demo 的字体、圆角、间距、标签和键盘焦点样式。
- 封面使用项目内本地资源，不依赖外链或运行时网络。

### 6.2 响应式

桌面端：

- 页面内容最大宽度约 1150px。
- 三项筛选横向等分排列。
- 热门游戏一行六张封面。
- 结果使用可读的紧凑表格，不要求用户进入详情。

移动端：

- 三项筛选纵向排列。
- 热门游戏使用两列封面网格。
- 结果使用单列卡片，避免横向滚动。
- 卡片首屏优先展示游戏、设备、评价和 FPS；环境、标签、备注及验证时间在同一卡片内继续展示。

## 7. 组件与数据流

页面保留一个单文件离线 Demo，由以下边界清晰的组件组成：

- `Header`：返回、标题和说明。
- `FilterPanel`：三项可搜索选择器和单项清除。
- `PopularGames`：无筛选时的热门游戏快捷入口。
- `ResultTable`：桌面结果布局。
- `ResultCards`：移动结果布局。
- `StatePanel`：加载、错误、空数据和无结果状态。

统一状态：

```js
{
  gameId: null,
  targetType: null,
  targetId: null,
  ratingMin: null,
  sortField: "rating",
  sortDirection: "desc",
  context: null,
  catalogStatus: "ready"
}
```

统一数据流：

```text
本地 Mock / App 注入数据
  → Adapter 校验与标准化
  → 单一筛选和排序函数
  → 桌面表格或移动卡片渲染
```

桌面和移动布局不得各自实现筛选、排序或数据转换。

## 8. 数据口径

最小数据对象包括：

```js
{
  games: [{ id, name, aliases, version, coverKey }],
  targets: [{ id, type, displayName, deviceModel, soc, gpu }],
  runs: [{
    id, gameId, targetId, gpu, androidVersion, appVersion,
    kernelVersion, rating, avgFps, tags, notes,
    sampleCount, verifiedAt
  }]
}
```

校验规则：

- `rating` 只接受 1～5。
- `avgFps` 限制在 0～240；缺失时显示“—”。
- 运行记录必须关联有效游戏和设备/GPU。
- 封面只接受受控的本地资源键。
- 标签、备注和名称在渲染前转义并限制长度。
- 缺少关键环境时显示“未记录”，不推测兼容结论。

## 9. 异常与边界

| 场景 | 处理 |
|---|---|
| 本机未识别 | 设备筛选保持未选择，仍可手动搜索 |
| 无任何筛选 | 展示热门游戏，不请求或渲染全量记录 |
| 筛选无结果 | 保留条件，显示清空入口 |
| 目录加载失败 | 显示重新加载，不伪造兼容结论 |
| 游戏、目标或记录数据失效 | Adapter 丢弃无效项，页面继续可用 |
| FPS、备注或标签缺失 | 对应字段显示“—”或隐藏空标签 |
| 封面资源失效 | 使用盖世游戏风格占位封面 |
| 方向或视口变化 | 保留筛选、排序和结果，不产生横向溢出 |

## 10. 明确不做

- 按游戏查 / 按 GPU 查双 Tab。
- 分级筛选目录、移动端筛选抽屉和确认按钮。
- 游戏详情、GPU 详情和配置详情。
- 配置查看、导出、下载或直接应用。
- 收藏、分享、对比、排行榜、教程和统计看板。
- 登录、会员、付费和云游戏兜底。
- GameNative 品牌配色、Logo 或英文文案复制。

## 11. 验收标准

- 页面结构与 GameNative Compatibility 一致：标题、三项筛选卡片、结果容器同页完成查询。
- 视觉完整使用盖世游戏黑金体系，不出现紫青渐变品牌风格。
- 初始展示六款带本地真实封面的热门游戏。
- 点击热门游戏可直接产生兼容结果。
- 游戏、设备/GPU 和最低评价均可筛选和单独清除。
- 手机型号、芯片和 GPU 名称均可命中目标。
- 桌面端使用结果表格，移动端使用同数据的紧凑卡片。
- 每条结果完整展示兼容评价、平均 FPS、游戏版本、运行环境及验证信息。
- 兼容评价和验证时间排序正确，切换视口后状态保留。
- 加载、错误、空数据、无结果和异常数据状态不会导致页面失效。
- 390×844 和桌面宽度下无横向溢出。
- HTML、脚本、样式和封面均可离线运行，不产生外部网络请求。
- 自动验证不再依赖旧详情页、复杂筛选或配置下载应用契约。

## 12. 验证方式

1. 静态检查 HTML 契约、内联脚本语法、离线资源及禁用外链。
2. Playwright 验证热门游戏直达、三项筛选、清除、排序和无结果恢复。
3. 注入异常目录，验证 Adapter 丢弃无效数据且页面继续可用。
4. 分别截取桌面初始、桌面结果、移动初始、移动结果和无结果状态。
5. 检查桌面与移动字段一致、无横向溢出、无控制台错误和外部请求。
