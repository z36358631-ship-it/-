# 开发者与运营对账确认 Demo 设计

> 状态：方案已确认。先完成 Demo，PRD 在 Demo 确认后整理。

## 1. 目标与边界

将现有“月度账本汇总”调整为“按游戏确认结算单”：开发者维护财务主体、查看并确认结算记录；运营审核财务主体、配置开发者结算比例、查询并导出结算记录；财务继续在线下打款。

本轮修改开发者财务 Demo 与运营财务 Demo，不修改发行、支付订单、退款执行和 PRD。

## 2. 统一数据口径

### 2.1 月份

- 账单月份：支付、退款或拒付事件归属月。
- 结算月份：固定为账单月份 N+1。例如账单月份为 `2026-07`，结算月份为 `2026-08`。
- 退款、拒付或支付商延迟数据在后续月份入账时，不改写已锁定账单，作为新账单月份的补扣项，仍在 N+1 结算。

### 2.2 金额与结算项

- 所有列表金额统一使用 CNY。
- 用户支付金额：用户支付总额。
- 实际到账金额：用户支付金额－退款－拒付－销售税－支付费。
- 结算比例：账单绑定的开发者比例快照。
- 结算金额：实际到账金额 × 结算比例，按分四舍五入。
- 正常收入的结算项为“游戏销售分成”。
- 迟到退款和拒付分别生成“退款补扣”“拒付补扣”；用户支付金额为 0，实际到账金额和结算金额为负数。

### 2.3 结算比例

- 配置维度为开发者，一期不支持按游戏配置。
- 默认值为 70%，运营可设置 0%–100% 的整数。
- 每个开发者、每个生效账单月只能存在一个有效版本。
- 账单使用“生效账单月不晚于当前账单月”的最新版本。
- 修改比例时必须填写生效账单月和变更原因，并记录操作人、操作时间、变更前后值。
- 新比例只重算未锁定账单；已锁定或已确认账单保留原比例快照。
- 只有具备财务配置权限的运营人员可以修改比例。

## 3. 开发者端

### 3.1 页面结构

财务模块保留两个入口：

1. 财务主体
2. 对账结算

### 3.2 财务主体

默认展示当前生效版本，包含：

- 企业法定名称
- 联系人姓名
- 手机号
- 邮箱
- 银行账户户名
- 开户银行
- 银行账号
- 开户支行／联行信息
- 银行账户证明附件

银行账户户名需与企业法定名称一致。银行账户证明附件必填，支持 JPG、PNG、WEBP，单文件不超过 10 MB。

交互：

- 默认按钮为“修改”。
- 点击“修改”进入编辑态，显示“取消”“提交审核”。
- “取消”放弃未提交修改并恢复只读态。
- “提交审核”校验必填项、手机号、邮箱和附件；失败时定位首个错误字段。
- 提交成功后生成待审核版本，页面恢复只读并显示“审核中”；当前生效版本继续用于已锁定账单。
- 审核通过后新版本生效；审核驳回后展示原因并允许再次修改。
- 历史版本和已锁定账单不被新版本回写。

### 3.3 对账结算

筛选项：

- 账单月份
- 结算月份
- 游戏
- 状态

表格列固定为：

1. 游戏 ID
2. 游戏名称
3. 账单月份
4. 结算月份
5. 结算项
6. 用户支付金额（CNY）
7. 结算比例
8. 实际到账金额（CNY）
9. 结算金额（CNY）
10. 状态
11. 操作

状态仅包含“待确认”“已确认”。待确认行显示“确认”，已确认行显示“—”。列表顶部提供“批量确认”，只处理勾选的待确认记录。

单条或批量确认前显示确认弹窗，包含记录数和结算金额合计。确认成功后状态改为“已确认”，不提供撤销入口。列表和导出每页 20 条，默认展示穷举态，悬浮球可切换缺省态。

## 4. 运营后台

### 4.1 页面结构

“财务结算”保留两个横向页签：

1. 财务主体
2. 对账管理

### 4.2 财务主体

- 列表展示开发者／财务主体、审核类型、审核状态、当前结算比例、生效账单月、更新时间和操作人。
- 审核类型为“首次”或“变更”。
- 点击申请后，从右侧打开详情抽屉，展示开发者提交的字段、附件和版本差异。
- 运营可通过或驳回；驳回必须填写原因。
- “结算设置”在同一详情抽屉中维护开发者结算比例，不增加独立页签。
- 比例保存前校验 0%–100%、生效账单月和变更原因，保存后展示审计记录。

### 4.3 对账管理

筛选项：

- 开发者／财务主体
- 游戏
- 账单月份
- 结算月份
- 结算项
- 状态

表格列固定为：

1. 开发者／财务主体
2. 游戏 ID
3. 游戏名称
4. 账单月份
5. 结算月份
6. 结算项
7. 用户支付金额（CNY）
8. 结算比例
9. 实际到账金额（CNY）
10. 结算金额（CNY）
11. 状态

运营后台不代替开发者确认。页面保留勾选和“导出已确认记录”；未勾选时导出当前筛选结果中的已确认记录，勾选时只导出选中的已确认记录，待确认记录自动排除。导出字段与列表一致，并增加财务主体名称和结算比例版本。

## 5. 状态与数据流

```text
财务主体：已生效 → 编辑 → 审核中 → 已生效／已驳回
结算记录：生成待确认记录 → 开发者单条或批量确认 → 已确认 → 运营导出 → 财务线下打款
结算比例：运营配置版本 → 到达生效账单月 → 未锁定账单使用新比例 → 锁定后保存快照
```

财务主体、结算比例和结算记录使用独立版本。任一资料变更不得覆盖历史结算记录。

## 6. Demo 状态

默认穷举态至少包含：

- 待确认和已确认结算记录
- 游戏销售分成、退款补扣和拒付补扣
- 连续三个账单月份及对应 N+1 结算月份
- 财务主体已生效、编辑、审核中和已驳回
- 结算比例 70% 默认值及一次历史变更记录
- 有数据、筛选无结果和缺省态

## 7. 验收

- 前后台表格字段、金额和状态一致。
- 每条记录的结算月份均为账单月份 N+1。
- 结算金额等于实际到账金额乘结算比例，误差不超过 1 分。
- 0% 和 100% 可保存，负数补扣可正确计算。
- 已确认记录不显示确认操作，批量确认忽略已确认记录。
- 财务主体编辑、取消、提交、通过和驳回形成完整闭环。
- 新主体版本和新比例不改写历史账单。
- 导出字段与筛选结果一致，线下打款导出只含已确认记录。
- 前后台每页 20 条，1280 px 和 390 px 无页面级横向溢出。
