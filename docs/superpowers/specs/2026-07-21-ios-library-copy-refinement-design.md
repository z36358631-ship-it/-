# IOS应用库页面文案调整设计

## 背景

当前游戏库一级 Tab 显示“PC 游戏”，与“IOS应用库”的命名粒度不一致；ACE 风险弹窗包含面向内部评审的过程性说明，不应向用户展示。

## 已确认方案

1. 游戏库一级 Tab 从“PC 游戏”改为“PC游戏库”。
2. ACE 风险弹窗删除“最终文案以法务与安全评审结果为准”。
3. 保留现有 `tersafe.framework` 风险说明、账号风控与封号风险说明、第三方 IPA 免责说明及两个操作按钮。

## 同步范围

- 标注版 HTML Demo 的一级 Tab、左侧流程导航和交互标注。
- PRD 中的版本记录、目标、路径、模块设计、页面说明和埋点名称。
- 飞书功能点中的页面名称和 ACE 弹窗描述。
- PRD 所有受影响的真实交互截图。

## 不变范围

- 不调整页面布局、颜色、按钮样式和交互逻辑。
- 不改变 ACE 检测时机、匹配规则、SHA-256 确认规则和首次启动补提醒规则。
- PRD 内部仍保留法务与安全评审作为上线准备要求，仅从 C 端弹窗可见文案中删除。

## 验证

1. Demo 一级 Tab 显示“PC游戏库 / IOS应用库”。
2. ACE 弹窗不再出现“最终文案”或“评审结果为准”。
3. ACE 弹窗仍显示封号风险、第三方 IPA 免责说明、“取消安装”和“了解风险，仍要安装”。
4. 受影响截图重新生成，图片链接返回 HTTP 200、`image/png` 且文件非空。

## 快速评审

- 用户视角：通过，两个一级 Tab 命名粒度一致，弹窗不再出现内部过程文案。
- 开发视角：通过，仅文案替换，不影响状态和事件处理。
- 业务视角：通过，用户端删除评审说明，PRD 内仍保留上线前的法务与安全评审要求。

## 自检

- 无 `TBD`、`TODO` 或占位文案。
- 用户可见文案与内部上线要求的边界清晰。
- 未增加新功能、页面或交互。
