# 开发者后台后续三份 Demo 设计

## 1. 目标

在现有开发者平台与企业认证 Demo 上继续补齐开发者接入能力，并按业务闭环拆为三份可独立打开、可互相跳转的单文件 HTML Demo。

本设计遵循会议分工：

- 本方负责游戏创建、资质、商店展示资料、发行范围、合同状态、APPID／SDK／API、资源下载和通知中心。
- 协作方负责传包、包体管理、测试发布、商品版本、定价、正式发布、上线和下架的前后台。
- 两方以 `vendor_id + game_id + app_id` 为共同上下文，通过状态和深链衔接，不重复建设页面或写入同一业务对象。

## 2. 方案结论

### 2.1 第一性原理

1. 开发者应能持续推进技术接入，不应因资质准备相对滞后而停在创建游戏或上传包体前。
2. 商店展示资料与商品售卖配置是不同对象：前者描述用户看到什么，后者决定卖什么、多少钱和何时上下架。
3. 三份 Demo 必须共享同一游戏与状态版本，否则通知、资质和包体状态会互相矛盾。
4. 本轮只实现已明确归属本方的页面；协作方模块只以只读状态和业务深链接入。

### 2.2 奥卡姆剃刀

采用三份业务闭环 Demo：

1. **Demo 06｜游戏创建与发行资料**：游戏、展示资料、资质、发行范围、合同状态及运营审核。
2. **Demo 07｜开发接入与资源中心**：APPID、环境、API 凭据、测试账号、开发文档和下载中心。
3. **Demo 08｜消息通知中心**：业务通知、系统公告、已读状态和业务深链。

不按五个功能点拆成五份文件，避免合同、资质、资料和范围脱节；也不合成一个大文件，避免状态、路由和维护继续膨胀。

### 2.3 反思审查

- **用户视角：通过。** 首包上传后常驻提示待补资质；资质未提交或审核中时仍可继续测试／发行申请，并明确其状态会进入运营审核。
- **开发视角：通过。** 三份 Demo 使用同一场景契约、存储命名空间和 Hash 深链；通知只消费事件，不反向修改业务状态。
- **商业视角：通过。** 范围覆盖开发者接入、资料准备和结果触达，且不重复协作方的包体、定价和发布链。

## 3. 共同规则

### 3.1 资质与申请

1. 创建游戏和上传包体不要求先提交游戏资质。
2. 首个包体上传成功后，游戏列表和概览显示“待补游戏资质”。首包状态由协作方模块提供。
3. 游戏资质独立提交和审核，可晚于包体上传。
4. 资质未提交、审核中、待补或拒绝时，不禁用测试或发行申请。
5. 测试／发行申请由协作方模块发起；申请快照记录当时的资质状态和版本，供运营审批。
6. 本轮不实现测试／发行申请弹窗、测试任务、价格确认、正式发布或上下架操作。

### 3.2 数据所有权

| 对象 | 写入方 | 本轮用法 |
|---|---|---|
| 游戏基础资料 | Demo 06 | 创建、编辑、提交审核 |
| 商店展示资料 | Demo 06 | 创建、编辑、提交审核 |
| 游戏资质 | Demo 06 | 提交、补充、查看结果 |
| 发行范围 | Demo 06 | 编辑国家／地区、PC 平台和计划发行时间 |
| 合同状态 | 运营端 | 开发者只读；运营录入线下合作结果 |
| APPID、环境和测试账号 | Demo 07 | 查看和管理技术接入信息 |
| SDK／工具资源 | Demo 07 管理端 | 草稿、发布、下线；开发者下载 |
| Build、SKU、价格、测试和发布 | 协作方模块 | 本轮只读消费，不提供编辑动作 |
| 业务通知 | 来源业务模块 | Demo 08 聚合和展示，不反向改业务状态 |
| 系统公告 | Demo 08 管理端 | 草稿、发布和下线 |

### 3.3 共享场景契约

三份 Demo 至少共享以下字段：

```text
vendor_id
game_id
app_id
first_build_uploaded
build_id
qualification_status
qualification_version
profile_status
profile_version
release_scope_status
release_scope_version
contract_status
contract_version
contract_valid_to
event_id
event_source
entity_id
event_type
event_status
event_time
deep_link
```

Demo 使用统一 `localStorage` 命名空间保存演示状态，并支持 URL 场景参数切换默认、审核中、待补、拒绝、失败和无权限状态。各页使用稳定 Hash 路由，刷新、复制链接、浏览器前进和后退后仍能还原页面。

## 4. Demo 06｜游戏创建与发行资料

### 4.1 开发者端页面

1. **游戏管理**：展示游戏列表、平台、Game ID、APPID、资料状态、首包状态、资质待办和更新时间；支持搜索及新建游戏。
2. **新建游戏**：填写中文名、英文名、开发商、发行商和目标 PC 平台；创建成功后生成 Game ID 与 APPID，并进入游戏概览。
3. **游戏概览**：展示资料进度、首包只读状态、资质待办、发行范围、合同状态及各模块入口。
4. **商店展示资料**：维护中英文名称、短简介、详细介绍、图片、视频、语言、Windows／macOS／Linux 展示配置和平台标签；不展示 SKU、价格或售卖状态编辑。
5. **游戏资质**：按自研或代理展示权属主体、授权链、有效期、授权地区／平台／渠道、第三方内容声明和证明附件；支持提交、补充和结果查看。
6. **发行范围**：按国家／地区选择销售范围，配置 Windows／macOS／Linux 和计划发行时间；不含币种、价格、折扣或上下架。
7. **合同状态**：只读展示合同编号、合作类型、有效期、状态和确认时间；证据链接仅运营可见。

### 4.2 运营端页面

1. **游戏资料审核**：按游戏、厂商、状态和时间筛选；查看本次版本、上一通过版本和字段差异；支持通过或拒绝。
2. **游戏资质审核**：查看材料、授权关系、覆盖地区／平台／渠道和历史补充记录；支持通过、要求补充或拒绝。
3. **发行范围审核**：核对开发者提交范围与已确认授权范围；支持通过或拒绝，不直接改开发者原值。
4. **合同状态维护**：录入线下合同编号、合作类型、有效期、确认人、确认时间、证据链接和状态；不提供线上签署或合同正文编辑。

### 4.3 边界调整

现有 Demo 06 中以下能力须移除或改为只读：

- “商品与 SKU”编辑、商品类型、版本内容和供给方式。
- 价格状态、销售状态、Build、测试和发布信息的写入操作。
- “申请平台测试／发行”弹窗和审核快照提交动作。
- 资质或中国大陆资质导致申请按钮禁用的前端门禁。

## 5. Demo 07｜开发接入与资源中心

### 5.1 开发者端页面

1. **接入概览**：展示 APPID、当前环境、接入进度、测试账号数和资源更新。
2. **APPID 与环境**：展示开发／生产环境、API 凭据状态和回调基础信息；支持复制标识及二次确认后重置密钥，新密钥只展示一次。
3. **测试账号与权限**：新增、停用和查看测试账号；配置允许访问的游戏、环境和能力；不管理测试包、测试任务或测试结果。
4. **开发文档**：展示 SDK、API、上传、测试和发布文档目录，点击后打开既有外部文档地址；不在后台自建第二套技术文档正文。
5. **下载中心**：展示 SDK、版本说明和必要调试工具；支持按平台、资源类型和版本筛选，查看更新说明并下载。

### 5.2 管理端页面

1. **资源列表**：展示名称、编号、类型、平台、版本、语言、状态和更新时间，支持搜索和筛选。
2. **新建／编辑资源**：配置文件、版本号、更新说明、适用平台、语言和依赖；创建后为草稿。
3. **发布管理**：发布草稿、下线线上资源和查看历史版本；发布失败时线上沿用原版本。

首期不做 API 调用监控、复杂 Webhook 编排、上传 CLI 或 CI/CD。

## 6. Demo 08｜消息通知中心

### 6.1 开发者端页面

1. **消息列表**：支持全部／未读、类型筛选、关键词搜索和分页；展示标题、摘要、业务对象、时间及已读状态。
2. **消息详情**：展示完整通知、结果、原因、时间和业务对象；提供“查看详情”深链。
3. **已读管理**：支持单条已读、批量已读和未读数同步；业务消息删除不在本期范围。
4. **业务深链**：资料／资质进入 Demo 06；构建／测试／发布进入协作方模块；结算进入对应页面；目标失效或无权时仍保留通知正文。

通知类型包括认证、游戏资料、游戏资质、构建、测试、发布、结算和系统公告。

### 6.2 运营端页面

1. **系统公告列表**：支持搜索、状态筛选、新建、编辑、发布和下线。
2. **系统公告编辑**：维护中英文标题与富文本正文；新建后为草稿，逐条发布。
3. **发布结果**：展示公告发布状态、时间和失败原因；不维护认证、构建、测试、发布或结算通知模板。

## 7. 状态、异常与安全

1. 列表覆盖加载中、空列表、筛选无结果、加载失败和无权限。
2. 附件上传失败只重试当前文件，不清除其他输入；图片和视频失败显示文件名及失败原因。
3. 提交时若当前版本已被处理，提示刷新并展示最新结果，不覆盖先完成结果。
4. API 密钥重置须二次确认；新密钥只展示一次，日志不记录明文。
5. 下载链接失效或下载失败时保留资源版本信息并允许重试。
6. 消息深链失效或无权时显示明确结果，不泄露目标对象详情。
7. 开发者端继承首页所选语言；运营端界面固定中文，“中文／English”只切换被配置的对外内容。

## 8. 验收标准

1. 输出三份可离线打开的单文件 HTML，并复用现有开发者后台视觉和组件。
2. 覆盖 1440、1280、390 和 320 像素宽度，无页面级横向溢出。
3. 键盘可操作导航、Tab、筛选、表单、弹窗和关闭动作。
4. Hash 深链、刷新、前进、后退及跨 Demo 返回正常。
5. 三份 Demo 对同一 `game_id / app_id` 展示一致状态。
6. 首包上传后出现资质待办；资质未提交、审核中、待补或拒绝时，不禁用测试／发行申请入口。
7. Demo 06 不提供 SKU、价格、包体、测试、发布、上线或下架编辑。
8. Demo 07 密钥重置、测试账号管理和资源下载状态可完整演示。
9. Demo 08 的已读数、列表与详情同步，业务深链按来源进入正确页面。
10. 开发者端中英文场景和运营端固定中文规则一致。

## 9. 实施顺序

1. 先调整 Demo 06，移除越界能力并补齐游戏创建、资质并行和运营审核。
2. 再建设 Demo 07，并以 Demo 06 生成的 APPID 作为共享上下文。
3. 最后建设 Demo 08，接入前两份 Demo 和协作方模块的模拟业务事件。
4. 三份 Demo 完成后统一执行状态一致性、响应式和深链回归。
