# Mac MODS 已安装筛选精简设计

- 日期：2026-07-31
- 状态：用户已通过明确修改指令确认
- 范围：Mac MODS Demo 与对应 PRD；APP 不改

## 1. 目标

减少“已安装”页顶部控件，只保留用户最常用的全量查看和更新处理入口。

## 2. 设计

“已安装”页保留两个筛选：

```text
全部 / 可更新
```

同时移除“已启用”“未启用”按钮及对应筛选状态。启用值仍显示在已安装卡片和详情中，用户仍可进入详情执行启用或停用；本次仅减少列表筛选维度，不删除启停能力。

筛选规则：

- 默认选中“全部”。
- “可更新”包含存在新版本或更新任务失败、仍可重试的已安装 MOD。
- 搜索与筛选同时存在时取交集。
- 切换筛选后回到列表顶部。
- 无结果继续显示“没有符合当前筛选的已安装 MOD”。
- 当前设备没有已安装 MOD 时显示“当前设备尚未安装 MOD”，并提供“浏览可用 MOD”。
- 非法或旧筛选值统一回退到“全部”。
- 更新失败卡片和详情继续显示启用值，详情保留启用或停用入口。

## 3. 文档

输出一份仅 C 端的标准 PRD，说明 Mac 端筛选精简、状态边界、异常处理和验收标准。国内包与海外包交互一致，不涉及云游戏、登录、实名或渠道差异。PRD 不使用图片。

## 4. 验收

- 已安装页只显示“全部”“可更新”两个筛选。
- 页面不出现“已启用”“未启用”筛选按钮。
- 两个筛选均可点击并正确更新列表。
- 卡片和详情继续展示启用值，启用、停用能力不变。
- 搜索与“可更新”筛选取交集，无结果文案正确。
- 初始空状态可返回“浏览”，更新失败详情仍可启停旧版。
- APP Demo 无改动。

## 5. 三视角审查

- 用户视角：减少低频筛选后，已安装页更简洁；启用状态仍可在卡片和详情中识别。
- 开发视角：同步收敛 UI 选项、筛选函数和 reducer 白名单，可避免旧状态形成不可见筛选。
- 业务视角：不改变安装、更新和启停能力，仅降低界面噪音，范围可控。
