# Mac 原生版本管理 PRD 精简与发布设计

## 目标

将现有 404 行 PRD 收敛为一份可直接评审和执行的当前版本文档，删除历史冲突、重复验收、过程记录和 AI 式说明，同时保留开发、测试必需规则；随后发布固定 Git 图片并同步到飞书文档。

## 已确认方案

用户已选择 A 方案：只保留当前执行口径，不保留 V1.0、V1.1 的重复正文或历史附录。

## 内容结构

1. 版本信息：只说明本次精简版及其依据。
2. 背景与目标：说明 Mac 用户当前无法识别、选择和管理原生版本的问题。
3. 本期范围：保留平台标识、版本选择、下载入口、安装路径、下载与切换；明确不做卸载和空间管理。
4. 功能规则：按用户实际操作顺序描述入口、点击区域、状态变化和异常反馈。
5. 异常与边界：覆盖路径不可用、空间不足、下载取消、提交前复验和数据加载失败。
6. 验收标准：合并基础、V1.1、V1.2 的重复用例，只保留一张当前验收表。
7. 群同步素材：每条一行描述，紧跟对应功能图，支持在飞书中整体复制。

## 功能图

使用 6 张已经验收的截图，发布到 `public/prd/mac-native-version-management/`：

- 版本切换初始状态
- 选择 Mac 原生版后的详情下载入口
- Mac 原生版安装完成后的版本状态
- 安装路径平铺并默认选择最大空间
- 无合格安装路径
- 下载中锁定路径和版本

图片使用包含实际文件的 40 位 Git commit SHA 生成 jsDelivr 原图地址。每个地址必须返回 HTTP 200 和 `image/png`。

## Git 与飞书发布

- 从最新 `origin/master` 建立独立 worktree，避免夹带主工作区的无关改动。
- 第一次提交发布设计、计划和图片；获得固定 SHA 后，把 URL 写入 PRD，再提交并推送。
- 飞书文档按 PRD 标题、章节、表格、列表和内嵌图片排版；文末保留“群同步素材”，确保描述与图片相邻。

## 验证

- PRD 不含 V1.0/V1.1 历史正文、自检记录、模拟评审结果或卸载实现。
- 路径选择规则必须明确“完整路径平铺、合格路径按空间降序、默认最大值”。
- 图片数量、固定 SHA URL 数和远程验证通过数一致。
- Markdown 不包含本地路径、相对图片路径、`localhost`、`@main` 或 `@master`。
- 现有 Demo 行为和代码不改动。

## 快速评审

- 用户视角：通过。正文按操作链路组织，群同步内容可以直接复制。
- 开发视角：通过。当前规则覆盖版本状态、唯一下载入口、路径优先级和锁定条件。
- 商业视角：通过。只保留本期能力，不扩展卸载或空间管理，范围可控。
