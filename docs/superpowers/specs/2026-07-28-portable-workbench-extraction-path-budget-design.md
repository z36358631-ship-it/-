# 个人产品经理工作台便携版解压路径修复设计

## 背景与结论

最终便携版 EXE 在真实验收的首次解包阶段连续三次失败。错误均为临时运行时目录中的 `codex` 路径不存在：

```text
ENOENT: no such file or directory, lstat '<runtime>\\.extract-...\\codex'
```

根因不是资源缺失或哈希损坏，而是 Windows PowerShell `Expand-Archive` 的路径长度边界。失败场景的临时目录长度为 173 个字符，压缩包内最长相对路径为 86 个字符，加上目录分隔符后总长正好为 260 个字符。独立复现表明：

- 输出路径总长为 260 个字符时，`Expand-Archive` 失败且没有创建 `codex` 目录。
- 当前 PowerShell 命令未设置 `-ErrorAction Stop`，该非终止错误可能仍以进程退出码 0 返回。
- 相同压缩包解压到短路径时，26 个文件全部存在，`codex.exe` 大小与构建清单一致。
- EXE 在较短的 `LOCALAPPDATA` 路径下能够完成解包并启动，进一步排除了嵌入资源损坏。

本次采用局部修复：缩短临时解压目录名，并确保 PowerShell 解压错误转换为进程失败。继续保留单文件 EXE，不改动工作台界面、业务功能、工作区数据格式或 Codex 调用方式。

## 设计目标

1. 在当前验证器使用的长 `LOCALAPPDATA` 路径下完成首次解包。
2. PowerShell 解压遇到路径、权限、磁盘或压缩包错误时立即失败，不进入 Manifest 校验阶段伪装成文件缺失。
3. 继续只运行通过归档 SHA-256 与逐文件 Manifest 校验的运行时。
4. 解包失败后不保留临时 ZIP、半成品临时目录或可被误用的版本目录。
5. 不改变已验证缓存的复用、损坏缓存重建和并发启动行为。

## 非目标

- 不替换 ZIP 技术栈，不增加第三方解压依赖。
- 不迁移运行时缓存目录，不引入跨磁盘移动。
- 不修改工作台 UI、API、数据库、工作流或权限模型。
- 不承诺未经实机验证的 Windows 10/11 跨机器认证。

## 修复设计

### 临时目录命名

将当前包含完整 `payloadVersion` 的临时目录名：

```text
.extract-<payloadVersion>-<pid>-<16 hex>
```

缩短为仅包含进程号和随机值的名称：

```text
.x-<pid>-<16 hex>
```

`payloadVersion` 仍用于最终缓存目录名和 Manifest 一致性校验，不再重复出现在临时目录名中。随机值继续保证同机并发解包互不覆盖；最终缓存仍通过原子重命名发布。

### 解压错误传播

PowerShell 命令为 `Expand-Archive` 增加 `-ErrorAction Stop`。任何非终止错误都会使 PowerShell 进程返回失败，Node 启动器随后进入既有失败清理和脱敏日志流程，不再等待 Manifest 校验间接发现缺失文件。

### 数据流

```text
读取 SEA 资源
  → 校验归档 SHA-256
  → 写入临时 ZIP
  → 解压到短临时目录
  → 校验逐文件大小与 SHA-256
  → 原子重命名为版本缓存
  → 启动便携 Launcher
```

任何一步失败都不会发布版本缓存；`finally` 负责删除临时 ZIP 和短临时目录。

## 错误与安全处理

- 路径长度、权限、磁盘空间和 ZIP 解析错误由 PowerShell 直接返回。
- 文件大小或哈希不一致继续立即失败，不进行宽松重试。
- 仅对既有的短暂文件系统错误执行有界校验重试。
- 解包失败不得创建 `session.json`、Broker 或工作区数据库。
- 日志继续脱敏令牌、授权头、API Key、认证文件名和 64 位十六进制值。
- 不复用半解包、损坏或旧版本运行时，也不回退到全局 Node、npm 或 Codex。

## 测试与验收

### 自动回归

1. 新增临时目录命名测试，验证名称不包含 `payloadVersion`、保持唯一且留出足够路径预算。
2. 新增 PowerShell 参数测试，验证使用 `-ErrorAction Stop`。
3. 保留归档哈希、Manifest、原子缓存、损坏重建、陈旧锁和 junction 防护测试。
4. 运行全部工作台自动测试，要求 0 失败。

### 真实 EXE 验收

重新构建单文件 EXE 后执行便携验证器，必须通过：

- 受限 `PATH` 下首次解包和启动；
- 内置 Codex 的真实只读 Run；
- 三个产品工作流；
- 隔离写入与恢复；
- 重复启动复用；
- 强杀后的陈旧状态恢复；
- 损坏缓存自动重建。

验证报告必须记录最终 EXE 大小、SHA-256、签名状态、当前机器验证结果，并明确标注“当前机器已验证，干净机待验证”。

## 方案评审

- 用户视角：局部修复无需用户手动清缓存，失败时仍保持清晰日志，不改变首次使用流程。
- 开发视角：路径预算已有可重复证据；缩短临时叶子目录并强制 PowerShell 报错是最小、可测试的改动。
- 交付视角：保留单文件 EXE 核心交付形态，避免重新设计解包或回退多文件版本带来的成本。
