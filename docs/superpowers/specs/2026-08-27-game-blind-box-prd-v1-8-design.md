# 游戏盲盒 PRD V1.8 精简方案

## 目标

在不改 Demo 和业务规则的前提下，精简《游戏盲盒需求》PRD，并用一张真实页面流程图说明本期链路。

## 本轮范围

- PRD 版本升为 V1.8。
- 删除套话、重复结论和非执行信息。
- 同一规则只保留一处完整说明，其余位置引用规则编号。
- 将文字版产品流程替换为一张横向流程图。
- 不改 Demo、候选池、随机规则、按钮、横竖屏规则和埋点口径。

## 文档结构

1. 需求背景：只写目标用户、现状、问题和本期边界。
2. 方案：只写方案概述和产品流程图。
3. 业务规则：作为候选池、随机、去重、异常和按钮行为的唯一来源。
4. C 端设计：使用一个三列表格，只写页面可见内容、操作和状态，不重复算法。
5. 非功能要求：只保留埋点、兼容、动画性能、运营素材和版权要求。
6. 待确认：只保留仍影响开发或验收的事项。

## 流程图

采用横向 5 步，每步使用当前 Demo 的真实页面状态：

1. 游戏库看到盲盒卡。
2. 点击卡片，打开盲盒弹窗。
3. 弹窗内快速切换游戏封面、名称、评分和类型标签。
4. 动画停止，显示命中游戏及“查看详情”“再抽一次”。
5. 点击“查看详情”，进入现有游戏详情页。

流程终点为游戏详情页。后续获取、下载和启动沿用现有流程，不在图中展开。

合成图使用较宽原图，PRD 中缩放展示；箭头和步骤标题置于截图之间，随机切换标为弹窗中间态，不表现为新页面。

## 表达规则

- 一句话只写一个意思。
- 先写触发，再写结果；异常紧跟对应规则。
- 优先使用“看到、点击、关闭、返回、进入”等常用词。
- 不删触发条件、适用范围、成功结果、失败恢复和冲突优先级。
- 文案简短，但不得用缩写或省略主语造成歧义。

## 验证

- 运行 PRD 质量校验。
- 检查重复规则、前后冲突和遗留占位词。
- 核对流程图与当前 Demo 一致。
- 图片提交后，使用固定 40 位 Git SHA 链接并验证远程访问。
- 更新工作流状态卡和任务板记录。

## 不在本轮处理

- Demo 样式和交互调整。
- 推荐算法、权重和候选池变更。
- 游戏详情及后续获取、下载、启动流程。
- 新入口、后台、奖励、灰度和新埋点。
