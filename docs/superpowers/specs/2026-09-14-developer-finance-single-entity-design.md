# 开发者财务单主体收口设计

## 目标

开发者端只面向当前登录厂商展示一个财务主体，减少同一主体、版本和币种重复出现在结算列表造成的理解成本。运营端仍按主体版本和账户版本保留完整核账能力。

## 页面结构

### 财务主体

- 页面仅展示当前厂商唯一的财务主体。
- 顶部为“财务主体、收款资料与审核状态”卡片，展示审核状态、配置状态和主体类型。
- 下方为“财务主体资料”，展示企业名称、注册地址、财务联系人、开户银行、收款账户、税务居民地和结算币种。
- 保留“修改”和“查看变更历史”。修改资料仍按原流程提交审核，通过后生效。
- 不展示多主体列表，不提供主体筛选。

### 对账结算

- 每个结算月只展示一条当前厂商汇总记录。
- 筛选项只保留“结算月”和“游戏”。游戏默认“全部游戏”，可切换单款游戏。
- 选择“全部游戏”时，金额为该月全部游戏合计；选择单款游戏时，金额为该月该游戏合计。
- 列表不再展示财务主体、主体版本和结算币种列。
- 金额列标题统一标明“金额（USD）”，单元格只显示数字或美元符号，不重复显示 `USD`。
- “应结算金额”同时显示美元结算额和人民币参考额。人民币参考额按账期锁定汇率计算，文案明确“约”，不改变实际结算币种。
- 结算详情继续展示游戏构成、第三方支付商、税种、实际税率、税额、支付费和汇率；主体版本和账户版本仅作为详情中的账期快照信息。

## 数据口径

- 月度汇总键：`开发者 + 结算月`；游戏筛选后增加 `Game ID`。
- 美元应结算额：`用户实付 - 退款 - 拒付 - 销售税 - 支付费 - 平台分成 - 预扣税`。
- 人民币参考额：`美元应结算额 × 账期锁定 USD/CNY 汇率`。
- 同一开发者同一月份只能有一个生效财务主体版本和一个收款账户版本；历史版本只影响对应账期快照。
- 支付、退款和拒付继续保存为不可变事件，不因前端聚合方式变化而改写。

## 边界

- 本次只调整开发者端财务主体和对账结算的展示、筛选与聚合。
- 运营端主体汇总、游戏明细、导出和线下打款流程不变。
- 不新增人民币结算能力；人民币仅为参考展示。
- PRD 等 Demo 确认后统一整理。

## 验收

- 财务主体页只有一个主体，结构与参考图一致。
- 对账结算默认展示全部游戏月度总额，切换游戏后金额同步变化。
- 金额单元格不重复出现 `USD`。
- 应结算金额同时展示美元和人民币参考额。
- 详情可追溯支付商、税率、税费、支付费和锁定汇率。
- 1440×900、1280×800 和 390×844 无页面级横向溢出。
