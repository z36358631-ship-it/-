# Mac 扫码登录 PRD 飞书表格格式优化设计

## 1. 目标

删除飞书正文中与顶部文档标题重复的首行，并参考《APP端MODS需求》优化全文表格。只调整文档呈现，不修改产品逻辑、页面、文案含义、Toast、弹窗、图片或服务端协议。

## 2. 问题

- Markdown 首行一级标题导入飞书后，与飞书顶部标题重复。
- 9 张表均按等宽分列，短字段占用过多空间，长说明频繁换行。
- 4.2 使用五段固定模板，信息完整但阅读密度低，模板感较强。
- 标准 Markdown 无法保存表格列宽，Git 不能完整复现飞书成品版式。

## 3. 修改范围

### 3.1 Markdown 内容

- 删除正文首行一级标题，保留从“## 一、版本信息”开始的正文。
- 4.2 保持“模块名称｜图示｜展示&交互说明”三列和现有 15 个页面状态。
- 4.2 每行说明改为以下自然编号，逐项换行并加粗标签：
    1. **触发条件：**
    2. **页面展示：**
    3. **操作流程：**
    4. **状态反馈：**
    5. **异常处理：**
- 不增加、删除或改写产品规则。

### 3.2 飞书表格

表格整体宽度按参考文档放宽，并按内容长度调整列宽：

|表格|列宽比例|
|---|---|
|版本信息|16 / 12 / 16 / 40 / 16|
|范围|22 / 78|
|模块职责|22 / 78|
|4.2 页面与状态|21 / 38 / 41|
|服务端状态|16 / 29 / 18 / 37|
|非功能需求|17 / 55 / 28|
|埋点|31 / 29 / 40|
|指标|24 / 52 / 24|
|验收标准|18 / 27 / 45 / 10|

允许根据飞书实际渲染在上述比例附近微调，优先保证图示完整、说明少换行、短字段不占大列。

## 4. 发布方式

1. Markdown 作为内容源，提交 Git 并保留固定图片链接。
2. 将更新后的 Markdown 导入飞书。
3. 在飞书中按本设计手动调整 9 张表的整体宽度和列宽。
4. 飞书作为最终阅读版，Git 作为可追溯内容源。

重新导入 Markdown 会丢失手动列宽。后续重新导入时，必须按本设计恢复列宽并重新验收。

## 5. 验收标准

- 飞书顶部标题只出现一次，正文不再重复标题。
- 9 张表均完成列宽调整，无机械等宽分列。
- 4.2 保持 15 个页面状态、13 张页面图和原有业务规则。
- 4.2 每行均使用 1—5 自然编号、换行和加粗标签。
- 图片、长说明、状态字段和优先级列无明显挤压。
- 14 张图片继续使用固定提交 SHA，均可正常显示。
- Markdown 与飞书正文内容一致；差异仅限飞书列宽。

## 6. 快速评审

- 用户视角：通过。标题去重、表格放宽后更容易定位页面、状态和规则。
- 开发视角：Markdown 无法保存列宽；采用“Git 管内容、飞书管版式”，并在本设计记录比例。
- 交付视角：通过。统一调整 9 张表比只修改 4.2 更完整，不增加产品范围。
