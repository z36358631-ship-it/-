# 移除外部 Key 与运营后台设计

## 目标

发行平台只处理盖世 Key。企业开发者可自行建渠道和批次，再通过文件或 API 向渠道供码；平台不接收、保管或核对 Steam、Epic、GOG 等外部 Key。

## 当前方案

1. 开发者端仅保留渠道管理、批次管理、分销数据和帮助教程。
2. 盖世 Key 由开发者在当前游戏下创建，文件批次可下载，API 批次可按原凭据续量。
3. 分销数据只展示平台能验证的发放、兑换、未兑换和兑换率，不承担三方销量、售后或结算。
4. 删除平台商品／SKU、外部 Key 入站、双账本、供给异常和对账等运营能力及对应路由、数据、埋点和文案。
5. 旧 `02-CDKEY商品与供给demo.html` 及历史拆分 Demo 不物理删除，但从当前 README、PRD、入口和测试契约移除。

## 数据流

企业认证通过 → 创建渠道 → 创建盖世 Key 批次 → 文件下载或 API 取码 → 查看发放与兑换数据。

## 异常与边界

- 渠道或批次停用时，停止 API 新取码；已发 Key 继续有效。
- 文件批次的首次下载与启停状态解耦；完整下载后不可再下。
- API 数量不足时，开发者在原批次追加数量，接口地址、`client_id` 和 Secret 不变。
- 历史外部 Key 页面不再提供当前入口，不作为本期业务证据。

## 验收

1. 当前 Demo 可完成渠道和批次的增删查改、启停、文件下载、API 接入与续量、分销数据查询。
2. 当前 Demo、源码、Fixture、PRD、README 和聚焦测试中不再出现“外部 Key”“双账本”“外部 Key 入站”等旧口径。
3. 当前路由不再含外部 Key 异常、商品／SKU 运营、外部 Key 配置和双账本对账页。
4. 渠道分销回归、PRD 质量和图片链接校验通过。
