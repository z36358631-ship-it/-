# 发行人计划功能开关与灰度外放设计

## 1. 目标

为“发行人计划”增加后台总开关和 20%／50%／100% 灰度比例，在风险可控的前提下逐步开放功能，并支持立即关闭新曝光。

本设计中的“灰度外放”指发行人计划功能对用户的开放范围，不是投稿作品是否向外部平台发布。

## 2. 用户与问题

- 运营人员需要分批开放发行人计划，观察功能稳定性和核心转化，异常时可快速停止新曝光。
- 普通用户需要在同一灰度轮次内保持稳定命中，避免入口时有时无。
- 已发布任务、已参与投稿和待结算用户需要继续履约，不能因关闭或缩量而失去任务管理、审核或结算能力。

## 3. 方案选择

采用“功能级总开关＋稳定用户分桶”。

- 不采用“投稿作品外放灰度”：它会错误改变投稿审核和作品状态，不符合本次功能灰度目标。
- 不同时建设白名单、渠道、地区、版本等多维策略：本期只需要 20%／50%／100% 三档，避免扩大范围。

## 4. 范围

### 4.0 沿用的发行人计划主流程

本次灰度能力是发行人计划主流程前的一层准入控制，不替代此前已确认的审核与结算规则：

1. 发布者提交任务前完成实名认证；提交成功后冻结任务预算并进入机器审核。
2. 机器审核覆盖任务文字、描述、投稿要求、标签、图片内容安全、OCR 敏感词、账号资格、当日次数和预算。
3. 全部检查明确通过时任务自动发布；明确拒绝时审核不通过并按原来源退回预算；超时、无响应或结果不确定时转人工异常处理，不能自动放行。
4. 创作者提交外站作品链接后，系统获取作品标题、描述、标签、发布时间、时长和点赞数；数据完整有效且规则校验通过时，自动进入“数据校验通过，待人工结算”。
5. 数据获取失败、作品不可访问、删除、转私密、关键字段缺失、重复投稿或命中风险时，进入重试、人工处理、驳回或风险挂起，不按 0 点赞结算。
6. 投稿数据校验通过时，系统按单稿奖励上限预留任务预算；预计奖励按 `min（当前点赞数 × 每赞单价，单稿奖励上限）` 计算。
7. 最终发奖由运营按任务级结算批次人工确认；结算金额按 `min（结算快照点赞数 × 每赞单价，单稿奖励上限）` 由系统只读计算，人工不能修改点赞数、单价、上限或金额。
8. 人工确认后幂等发放盖世币；存在抓取失败或风险投稿时先处理异常，不能重复发奖或默认放行。

### 4.1 B 端配置

在发行人计划现有后台设置区域增加：

| 配置 | 规则 |
|---|---|
| 功能开关 | 开启后按灰度比例判断新用户是否可进入；关闭后停止新曝光和新参与 |
| 灰度比例 | 仅支持 20%、50%、100% |
| 当前状态 | 展示“已关闭”或“已开启 · X%” |
| 保存 | 沿用现有后台保存交互；保存成功后生成新配置版本并记录操作人和时间 |

关闭开关时灰度比例不可编辑，但保留最后一次比例；再次开启时默认沿用该比例。后台不新增一级导航、独立页面或自定义比例输入。

### 4.2 C 端表现

- 命中灰度：正常展示发行人计划入口，并允许浏览、发布任务或参与任务；具体动作仍执行原有登录、实名、创作者认证、预算和审核规则。
- 未命中灰度：不展示新的发行人计划入口；直接访问时由服务端拦截新进入，客户端沿用现有不可用处理，不新增页面、弹窗或 Toast。
- 功能关闭：等同 0% 新曝光，但不改变存量履约。

### 4.3 存量履约保护

开关关闭或比例缩小时：

- 已发布任务继续展示、审核、下架和结算。
- 已参与投稿继续审核、数据校验和结算。
- 已有任务关系的用户仍可通过“我的任务”、既有通知或任务详情继续处理存量事项。
- 不再允许未命中用户发布新任务、参与新任务或建立新的任务关系。

## 5. 灰度判定

服务端是最终判定方。判定顺序为：

1. 判断用户是否已有需要继续履约的任务关系；有则保留对应存量访问权限。
2. 判断功能总开关；关闭时拒绝新曝光和新参与。
3. 读取当前灰度比例。
4. 使用稳定主体标识进行分桶。
5. 桶值小于灰度比例时命中。

稳定分桶规则：

```text
bucket = hash(subject_id + "publisher_plan" + rollout_seed) % 100
eligible = enabled && bucket < rollout_percent
```

- 登录用户使用 `account_id`，未登录用户使用稳定的 `installation_id`。
- 同一灰度轮次的 `rollout_seed` 不变；20% 扩到 50% 时，原 20% 用户继续命中。
- 登录状态变化后按账号重新判定，并以服务端结果刷新入口。
- 调整比例只影响后续访问和新操作，不撤销已建立的任务关系。
- `rollout_seed` 由服务端维护，本期后台不提供修改入口。

## 6. 配置与日志

灰度配置至少包含：

| 字段 | 说明 |
|---|---|
| `enabled` | 功能总开关 |
| `rollout_percent` | 20、50 或 100 |
| `rollout_seed` | 当前灰度轮次固定盐值 |
| `config_version` | 配置版本 |
| `updated_by` | 操作人 |
| `updated_at` | 生效时间 |

每次保存记录修改前后值。比例非法或保存失败时不覆盖上一版有效配置。

## 7. 数据与观察

每次灰度判定记录：主体类型、桶值、灰度比例、是否命中和配置版本。灰度放量至少观察：

- 入口曝光人数与点击率。
- 页面进入成功率。
- 任务发布成功率、投稿参与成功率。
- 页面错误率、接口失败率及用户投诉。

20% → 50% → 100% 由运营手动调整，不自动扩量。发生严重异常时关闭总开关，停止新曝光；存量履约继续。

## 8. 异常处理

- 配置读取失败：新曝光按关闭处理；存量履约按已有任务关系继续。
- 配置值非法：服务端拒绝保存，继续使用上一版有效配置。
- 客户端展示与服务端判定不一致：以服务端为准，客户端刷新入口和操作状态。
- 重复请求或并发更新：以配置版本控制覆盖顺序，保留完整操作记录。

## 9. 验收标准

1. 后台可开启或关闭发行人计划，并只能选择 20%、50%、100%。
2. 开关关闭后，新用户看不到入口且无法通过直达链接或接口建立新任务关系。
3. 同一账号、同一灰度轮次跨设备和跨会话命中结果一致。
4. 20% 扩到 50% 时原命中用户仍命中；缩量后不影响已建立的任务关系。
5. 100% 时所有符合原有业务条件的用户均可进入。
6. 配置异常时不错误全量开放，上一版有效配置可追溯。
7. 开关关闭或缩量后，已发布任务、已投稿内容和待结算记录仍可继续履约。
8. 投稿审核状态、预算冻结和人工结算规则不因灰度判定发生变化。
9. 发布任务全部明确通过机器审核后自动发布；不确定结果只进入人工异常处理。
10. 投稿内容数据完整获取且校验通过后自动进入待人工结算；最终发奖必须由运营人工确认系统计算结果。

## 10. 方案快速评审

- 用户视角：通过。灰度未命中不显示为审核失败，避免创作者误解内容质量或合规有问题。
- 开发视角：通过。使用稳定分桶、服务端判定和配置版本，避免调档后结果抖动。
- 商业视角：通过。总开关、三档比例、核心指标和立即回退构成可验证的最小方案。

## 11. 不在本期范围

- 投稿作品向外部平台自动分发。
- 白名单、地区、渠道、客户端版本等多维灰度条件。
- 1%～100% 自定义比例。
- 自动扩量或自动回滚。
- 新建独立灰度后台、消息中心或审批流。
