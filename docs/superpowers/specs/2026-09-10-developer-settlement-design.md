# PC 发行平台开发者结算设计

> 状态：方案已确认，作为 PRD-15、开发者结算 Demo 与平台财务后台的设计基线。

## 1. 目标

为完成游戏销售后的资金闭环，平台需要把支付商提供的交易事实转换为可核对、可确认、可付款、可回溯的开发者结算结果。

一期采用“统一账本＋人工付款”：支付商负责收款、原路退款及拒付结果；平台负责账本、核账、账单、差异和付款登记；开发者负责配置财务主体、确认账单并按需提交发票。

## 2. 已有链路与模块边界

```text
02 商品、SKU 与定价
→ 10 订单、支付、履约、退款与拒付
→ 15 对账、结算与付款
```

- 02 产生商品、SKU、地区和成交规则。
- 10 固化订单价格并形成支付、退款、拒付及履约事实。
- 15 只消费已确认的交易事实，不修改商品、玩家订单或支付商终态。
- 支付商通过 API、回调或对账文件连接平台，不使用独立运营工作台。

结算数据必须按业务来源隔离：

- 平台直销账本：玩家订单、支付、退款、拒付及开发者收入分成。
- 外部 Key 采购账本：供应商 Key 入库、采购成本和供应商应付。
- 盖世 Key 渠道账本：生成、分配、交付、兑换、撤销，以及渠道预付款或销售分成。

三本账可在财务后台汇总查看，但不能共用流水状态和计算口径；只有合同主体、结算币种及周期一致时才可合并付款，账单中仍需分项展示来源。

## 3. 竞品结论

TapTap 可借鉴：

- 财务主体独立于游戏管理。
- 首次配置和资料变更均需审核。
- 审核前限制结算操作。
- 保留生效版本和变更历史。

不直接照搬：

- 现有页面偏国内广告收益提现，不能覆盖全球游戏销售、跨境收款和多币种核账。
- “提现签约”不适用于平台按月结算。
- 财务资料之外，还必须保存结算规则、汇率、费用及账单快照。

## 4. 一期完整流程

```text
玩家订单／退款／拒付
→ 支付商回调、查单或对账文件
→ 平台统一交易账本
→ 每月 1—10 日生成上月账单
→ 开发者确认或提交差异
→ 平台处理差异并锁单
→ 按合同要求提交、审核发票
→ 财务人工打款并登记结果
→ 开发者查看付款状态和凭证
```

外部 Key 和盖世 Key 分别从其独立账本进入月度结算，不并入支付商交易明细。

账单金额必须能够由关联流水逐笔汇总还原。任何人工调整必须记录金额、币种、原因、证据和操作人。

## 5. 开发者前台

### 5.1 财务主体

- 从已通过的企业认证读取企业名称、注册地和证件信息。
- 补充收款人、地址、财务邮箱、银行国家或地区、开户行、账户及税务资料。
- 银行字段随收款地区和结算币种变化：境内 CNY 使用境内银行字段；跨境收款要求 SWIFT/BIC 等字段。
- 结算币种来自合同，只读展示；变更需联系商务更新合同。
- 首次配置和资料变更均需审核，提交后保存不可变申请快照。
- 新资料审核期间旧版本继续生效；主体、税号或收款账户变更时暂停付款。
- 支持查看提交内容、撤销审核、补充资料、生效版本和变更历史。
- 财务邮箱完成格式校验和验证码验证后才能提交。

### 5.2 财务对账

- 展示本期预估、月度对账单和脱敏对账流水。
- 账单展示销售、退款、拒付、税费、支付费、平台分成、固定采购、调整项和应结算金额。
- 流水保存交易原币、结算币、汇率、汇率版本、折算金额、规则版本和关联账单。
- 支持按账期、账单状态、游戏、SKU、业务来源、履约方式、流水类型和关键词查询；列表每页 20 条。
- 开发者可下载账单、查看全部流水、确认账单或提交差异。
- “确认账单”只进入已确认，平台财务复核后才能锁单。
- 财务主体从未生效时可查看预估数据，但不能确认正式账单。已生效后因收款资料变更而暂停付款，不影响历史账单确认和差异处理。

### 5.3 差异处理

- 已有流水差异：关联一条或多条流水，平台值只读，填写期望值和依据。
- 交易遗漏：填写开发者侧订单号或业务参考号，不强制选择平台流水。
- Key 数量差异：填写批次、渠道、平台数量和期望数量。
- 费用、税费、汇率差异：关联流水或账单项，填写期望金额。
- 每次提交和补充均保存内容、附件、时间、处理人及结果，不覆盖原记录。

### 5.4 发票

- 仅合同要求时展示，不作为所有开发者的统一步骤。
- 记录发票号、开票日期、金额、币种和附件。
- 金额和币种必须与锁定账单一致。
- 持续展示提交快照、审核状态和退回原因。

### 5.5 付款记录

- 展示付款单号、关联账单、金额、收款账户、计划付款日、更新时间和状态。
- 展示生成、处理、汇出、完成、失败或退回的时间线。
- 真实汇出且存在回执后才可下载付款凭证。
- 失败或退回时说明原因、是否需要修改资料、预计重试时间及新付款尝试关系。
- 开发者不能发起打款，也不能自行标记到账。

## 6. 平台运营／财务后台

### 6.1 财务主体审核

- 查询首次和变更申请，查看不可变提交快照。
- 支持通过、退回补充、拒绝、暂停和恢复。
- 收款账户等敏感变更采用经办、复核分离。
- 保留前后版本、审核意见、证据和操作日志。

### 6.2 支付商核账

- 导入支付商交易、费用、退款、拒付及结算文件，或接收对应 API 数据。
- 按平台订单号、支付商流水号、金额、币种和状态匹配平台账本。
- 分别核对外部 Key 采购批次，以及盖世 Key 的渠道预付款、分配、交付、兑换和销售分成。
- 将缺失、重复、金额不符、币种不符和终态冲突放入异常队列。
- 一期允许人工导入和复核；自动 API 对账后置。

### 6.3 账单管理

- 按结算主体、业务来源、规则版本、账期和结算币种生成账单。
- 支持查看构成、登记调整项、重新计算、作废、重开、确认和锁定。
- 锁单后禁止覆盖；修正必须生成新版本并保留旧版本。
- 差异未关闭时不得锁单；财务主体从未生效时不得进入正式结算；付款暂停只阻止付款，不阻止历史账单确认和差异处理。

### 6.4 差异与发票

- 差异支持受理、分派、要求补充、人工取消补充、确认、驳回及登记下期调整。
- 发票支持查看、下载、通过和退回；审核记录绑定账单版本。

### 6.5 付款管理

- 只为已锁定且满足财务主体、发票和合同条件的账单生成付款单。
- 支持登记人工打款、经办复核、暂缓、取消、失败、退回和重试。
- 同一应付款项使用“一张付款单＋多次付款尝试”，避免并行付款单造成重复付款。
- 付款金额必须等于账单待付余额；预扣税、银行费、结转和拆款必须单独列明。

## 7. 支付商连接能力

- 支付成功、退款和拒付结果回调。
- 主动查单和回调丢失补偿。
- 对账文件或 API 导入。
- 平台订单号、支付商流水号和结算批次号映射。
- 签名校验、幂等处理、重放防护和重复数据拦截。
- 金额、币种、费用、汇率、时区和账期校验。
- 原路退款结果及拒付终态同步。

一期不建设支付商前台，不要求支付商直接向开发者自动出款。

## 8. 状态模型

### 8.1 财务主体

```text
未配置 → 草稿 → 审核中 → 已生效
                  ├→ 待补充 → 审核中
                  ├→ 已拒绝 → 草稿
                  └→ 已撤销 → 草稿
已生效 → 变更审核中 → 新版本生效
                   └→ 旧版本继续生效／付款按敏感字段规则暂停
```

### 8.2 账单

```text
草稿 → 待确认 → 已确认 → 已锁定
          └→ 有异议 → 待确认／已确认
草稿／待确认／已确认 → 已作废 → 新版本账单
```

账单状态与付款状态分别维护，不能用“已锁定”代表已经付款。

### 8.3 付款

```text
待具备条件 → 待付款 → 处理中 → 已汇出 → 已完成
                         ├→ 失败 → 新付款尝试
                         ├→ 退回 → 修改资料／新付款尝试
                         ├→ 暂缓
                         ├→ 已结转
                         └→ 已取消
```

付款事件时间必须单调递增，终态不得直接回退。

## 9. 核心数据模型

- `SettlementRuleSnapshot`：结算模式、分成或采购规则、币种、税费、费用、汇率规则及生效时间。
- `SettlementLedgerEntry`：业务来源、结算对手方、唯一流水号、订单／SKU／Key 链路、类型、原币金额、费用、汇率、折算金额及规则快照。
- `Statement`：开发者、账期、版本、关联流水、构成、调整项、应结算额和确认／锁定信息。
- `Dispute`：差异类型、关联对象、平台值、期望值、附件和处理时间线。
- `Invoice`：账单版本、发票号、日期、金额、币种、附件和审核记录。
- `PayoutOrder`：账单待付余额、收款版本、付款条件和总体状态。
- `PayoutAttempt`：每次打款金额、渠道、银行参考号、状态、回执和失败原因。
- `AuditLog`：对象、前后值、原因、时间、操作者和复核人。

资金字段使用最小货币单位整数或 Decimal，展示精度按币种规则处理，不能使用二进制浮点数直接计算。

## 10. 权限与安全

- 开发者侧至少区分企业主账号、财务管理员和只读成员。
- 非授权成员不能查看完整银行、税务、账单和付款凭证。
- 平台侧区分财务经办、财务复核、运营只读和审计。
- 银行账号按权限脱敏，附件使用受控预览和下载。
- 导出记录开发者、筛选条件、操作者、时间和结果。
- CSV 需要标准转义并防止公式注入。

## 11. 异常与约束

- 渠道数据未齐：账单保持草稿，未知费用显示“估算中／--”，不能记为 0。
- 汇率缺失：相关流水不进入正式账单，并进入异常队列。
- 重复回调或文件：依靠业务唯一键幂等，不重复入账。
- 迟到退款或拒付：不能覆盖已锁账单，进入下期调整并关联原流水。
- 财务资料变更：保存新申请，不能改写历史账单使用的收款版本。
- 部分付款：记录本次金额和剩余金额，不伪造成整单已付款。
- 付款失败重试：新增付款尝试，不复制应付金额生成无关系付款单。

## 12. 优先级

### P0：一期闭环

- 财务主体与变更审核。
- 收入分成、固定采购及规则快照。
- 统一交易账本和人工支付商核账。
- 外部 Key 采购、盖世 Key 渠道预付款和销售分成的独立账本。
- 多币种交易与合同结算币种。
- 月度账单、确认、差异和锁单。
- 条件式发票。
- 人工付款登记、凭证和状态。
- 权限、审计、导出和通知。

### P1：效率提升

- 支付商 API 自动对账。
- 批量生成、锁定和付款复核。
- 起付门槛和跨期结转。
- 异常队列、预警和处理时效。
- 税务凭证下载。

### P2：自动化

- 自动分账和自动出款。
- 多支付商智能路由。
- 结算预测和成本优化。
- 自动税务服务。

## 13. Demo 与验收范围

开发者 Demo：财务主体、财务对账、付款记录三个一级页面，覆盖正常、待补充、暂停、差异、失败和退回状态。

平台后台 Demo：财务主体审核、支付商核账、账单管理、差异／发票、付款管理和审计查询。

开发者端与平台后台右下角均提供“场景”悬浮球：

- 默认使用“穷举态”，展示各模块的主要正常、处理中和异常状态，便于完整评审。
- 切换为“缺省态”后，模拟新主体首次进入：财务主体未配置，暂无账单、流水、差异、发票和付款记录。
- 切换只替换 Demo 数据集，不写入业务状态，不改变当前页面结构和权限规则。
- 悬浮球展开后只保留“穷举态／缺省态”两个选项；当前选项有明确选中态，切换后保留当前一级页面并回到第一页。
- 悬浮球固定在右下角，不遮挡抽屉按钮、分页及返回顶部入口。

验收重点：

1. 任一账单均可由关联流水汇总还原，应结算金额无随机或硬编码差异。
2. 开发者确认、平台锁单和付款状态严格分离。
3. 财务主体从未生效时阻断正式结算，差异未关闭时阻断锁单，付款暂停时只阻断付款。
4. 账单锁定后修改交易、规则或财务资料，不改变原账单快照。
5. 同一账单的付款、失败和重试关系清晰，不产生重复付款。
6. 所有列表每页 20 条，筛选、分页、导出和详情读取同一数据范围。
7. 抽屉和确认框支持键盘关闭、焦点约束及关闭后焦点恢复。
8. 所有金额按币种精度计算和展示，导出结果与页面及账单一致。
9. 平台直销、外部 Key 和盖世 Key 渠道流水不能跨账本混算，合并付款时仍可追溯各来源金额。
10. 首次打开默认为穷举态；悬浮球可在穷举态与缺省态间往返切换，页面内容、分页和空状态同步正确。

## 14. 方案审查结论

- 用户视角：通过。开发者能从财务主体一路追溯到付款结果，不需要理解支付商内部流程。
- 开发视角：有条件通过。必须先统一账本、金额类型、快照和状态机，不能继续依赖页面硬编码数据。
- 商业视角：通过。一期人工付款降低外部依赖，账本和审计保证后续自动化不推倒重做。
