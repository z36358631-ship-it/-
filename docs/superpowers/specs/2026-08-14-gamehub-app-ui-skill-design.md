# GameHub APP UI 模板 Skill 设计规格

## 1. 目标

建立一个可复用的 `gamehub-app-ui` Skill，使后续盖世游戏 APP Demo 不再因执行批次不同而出现按钮、卡片、导航、字号、间距和页面骨架漂移。

本期只覆盖 APP 竖屏与掌机横屏。Mac 必须使用独立平台适配层，禁止直接复用 APP 横屏页面。

## 2. 证据范围

- Figma 文件：`MZmfinxCqrfQUlDou1uB1N`，共 11 个页签。
- V6.1.1 实机图：`_outputs/盖世游戏V6.1.1使用说明手册/图片和附件`，共 45 张。
- 页签和实机图覆盖率必须均为 100%；每项必须标明形成页面配方、形成组件、形成规则或仅作废弃反例。
- Figma 旧 API Token 已失效，新 Skill 不保存任何凭证。

## 3. 架构选择

采用混合式总 Skill：

1. 薄总控：负责来源读取、冲突裁决、页面路由、完成门槛和输出规范。
2. 三层令牌：原始值、语义值、组件值。
3. 组件契约：统一导航、按钮、卡片、平台标识、弹窗、菜单、状态反馈等重复结构。
4. 页面配方：锁定完整页面骨架、组件组合、横竖差异、状态和允许的例外。
5. 来源清单：保存 Figma 页签、节点、45 张实机图尺寸与 SHA-256。
6. 预览与校验：离线单文件 HTML 展示组件和页面配方；脚本检查覆盖、结构、离线性与浏览器运行。

不采用“每个组件一个 Skill”。该方案会导致触发冲突、重复加载和版本失控。

## 4. 冲突裁决

按冲突类型择优，而不是固定服从某一来源：

1. 用户本轮明确要求或已确认决定。
2. 当前版本真实结构、设备安全区、实际截断和滚动行为：V6.1.1 实机图优先。
3. 新增功能、精确组件尺寸、颜色、状态和最新视觉：对应 Figma 页签优先。
4. 跨页面同类结构不一致：选择视觉完成度更高、可复用性更强且与当前产品更自然融合的方案。
5. 废弃页只建立禁止项，不进入默认模板。
6. 无法达到高置信度时记录冲突双方、选择、理由、影响和置信度，不伪装成事实。

## 5. 页面范围

页面配方按六类组织：

- 新手与账号：隐私、欢迎、选游戏、绑定/导入、盖世/Steam/EPIC 登录。
- 首页与发现：首页、搜索默认/结果、游戏详情。
- 玩游戏与排行榜：云游戏、PC 游戏、云游组队、复古、时长、排行榜。
- 游戏库与管理：多平台游戏库、导入、PC 详情、更多菜单、秒玩、版本、删除、编辑、按键布局。
- 我的与系统：我的、设备、设置、关于、下载、模式切换。
- 掌机横屏：首页、四类玩游戏、游戏库、排行榜、搜索、详情和切回竖版。

Figma 的社区、CDKEY/广告/MODS、发行人任务商城、控制器映射/边玩边下、云游戏组队、版本优化、运营活动和 Logo 页分别形成扩展业务配方或组件规则。

## 6. 组件范围

- 基础：颜色、文字、间距、圆角、阴影、模糊、图标和品牌标识。
- 应用框架：状态栏、顶部栏、竖屏底部导航、横屏顶部导航、安全区、滚动容器。
- 通用控件：按钮、图标按钮、Tab、筛选、标签、角标、列表、网格、菜单、弹窗、抽屉。
- 游戏内容：封面卡、搜索卡、平台标识、详情头、评分、元数据、启动方式。
- 账号平台：账号卡、平台入口、绑定状态、更多菜单、账号库摘要。
- 反馈状态：加载、空、失败、禁用、冲突、同步中、兼容性状态。
- 业务扩展：社区、CDKEY、广告、MODS、任务商城、云游戏组队、控制器映射、运营活动。

## 7. 输出契约

使用 Skill 生成 Demo 时必须：

- 先读取对应页面配方和必要组件，不加载无关业务。
- 先还原现有页面，再加入新增需求。
- 横竖版使用独立布局结构，共享业务状态，不允许整体旋转或缩放。
- 输出单文件 HTML，CSS/JS/图标内联，不使用 CDN、iframe、emoji 或远程图片。
- 使用真实中文文案和真实 DOM，不用截图底图冒充页面。
- 列出所用页面配方、组件和来源；列出冲突裁决与未覆盖项。
- 不擅自新增页面、弹窗、Toast、流程或平台能力。

## 8. 可预览交付

生成 `demos/UI规范/盖世游戏APP-UI模板与页面配方预览.html`：

- 左侧可按基础、组件、竖屏页面、横屏页面、扩展业务和来源切换。
- 中间展示真实 DOM 组件与代表性页面配方。
- 支持方向、状态和组件变体切换。
- 右侧展示用途、状态、组成、来源、冲突说明和调用示例。
- 完全离线，浏览器直接打开。

## 9. 视觉还原返工（用户 2026-08-14 确认）

此前预览只证明组件结构、来源覆盖和交互可运行，不能证明与 UI 原稿视觉一致。该版本不得作为最终高保真成品。

采用“Figma 图层 + 实机图 + 真实局部素材 + 视觉回归”的混合复刻：

- 以实机图 `1080×2400`、`2400×1080` 原始画布建立页面，再在展厅中等比缩放。
- 媒体、游戏封面、Banner、Hero 等复杂美术内容优先使用原稿局部裁切或 Figma 导出；导航、文本、按钮、Tab、卡片、弹层和状态必须是真实 DOM。
- 代表页至少覆盖 screen-08、09、10、18、20、30、36、41、44。
- 展厅支持“原稿 / 实现 / 差异图”查看，不允许把原稿层叠在实现上冒充还原。
- 每个代表页生成同尺寸实现截图，通过结构锚点、色彩、边缘和感知差异计算还原结果。
- `95%` 是交付硬门槛：代表页平均分和每个关键组件分均不得低于 95%；未达标继续修正或明确标为未通过，不能只凭脚本关键词宣称通过。
- 像素差异受字体光栅化、系统状态栏和动态媒体帧影响，验收同时保留自动指标与人工肉眼审查。

## 10. 验收

- Figma 11/11 页签进入来源清单和覆盖矩阵。
- 实机图 45/45 进入 Manifest，包含尺寸、方向、分类和 SHA-256。
- 页面配方、组件、令牌、冲突政策、使用说明和来源均可从 `SKILL.md` 一层链接到达。
- 预览可遍历，所有按钮有反馈，0 `pageerror`，无外部请求。
- 自动校验输出来源覆盖、引用、结构、禁止项、离线性和浏览器运行结果。
- 前向测试至少覆盖新增平台入口、我的页账号卡、搜索横竖版、掌机横屏详情和组件展厅。
- 视觉验证必须输出 `PASS visualFidelity`，并提供原稿、实现、差异图和页面级评分报告。

## 11. 三视角评审

- 用户视角：组件一致且页面结构真实，能减少重复返工；覆盖报告必须可见。
- 设计视角：组件统一基础能力，页面配方保留真实例外；冲突必须有来源记录。
- 维护视角：总控保持精简，按页面和组件渐进加载；版本锁定避免公共组件更新无声破坏旧页面。

结论：混合像素级复刻方案已经用户确认；结构化示意预览需要返工后才能重新进入评审。
