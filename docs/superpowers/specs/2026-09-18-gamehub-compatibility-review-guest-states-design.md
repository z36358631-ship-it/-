# GameHub 兼容性评价客态实例设计

**日期：** 2026-09-18

**需求：** GUANWANGGAID-25 兼容性评价改版 v1.2

**阶段：** 设计已确认，待书面规格复核

## 1. 目标

在现有兼容性评价列表中补齐“其他玩家”的客态实例，让 Demo 明确展示用户如何查看并进入其他玩家分享的本次启动方案，同时穷举方案入口应显示和应隐藏的边界。

本次只补客态列表实例和对应验证，不新增详情异常页，不改“我的评价”流程，不向普通用户暴露快照技术状态。

## 2. 设计原则

采用“自然混排”：其他玩家评价继续按现有列表规则排列，不按方案状态单独分组，不增加“未分享”“方案失效”等状态标签。

只有当前用户真实可查看、可进入的有效方案才展示入口；其余状态保留评价原有内容、设备信息、星级、兼容类型和问题描述，不出现空白占位、残留点击热区或焦点节点。

## 3. 客态状态矩阵

| 状态编号 | 其他玩家评价状态 | 列表表现 | 交互 |
|---|---|---|---|
| G-01 | 3～5 星；快照存在；`status=available`；`snapshot.reviewId=review.id` | 展示“本次启动方案”和“本次游玩 xx分xx秒” | 点击进入现有完整方案详情 |
| G-02 | 3～5 星；用户未分享快照 | 只展示普通评价 | 无方案入口 |
| G-03 | 3～5 星；快照为 `deprecated` | 只展示普通评价，不说明失效原因 | 无方案入口 |
| G-04 | 3～5 星；快照为 `invalid` | 只展示普通评价，不说明异常原因 | 无方案入口 |
| G-05 | 1～2 星；无论是否残留快照引用 | 完整展示设备信息与问题描述，不展示方案 | 无方案入口 |
| G-06 | 快照存在，但 `snapshot.reviewId !== review.id` | 只展示普通评价 | 无方案入口 |
| G-07 | 评价被后台隐藏 | 整条评价不进入 C 端列表 | 无交互 |

## 4. 筛选与自然混排

- “全部”：展示全部可见评价，包含有有效方案和无方案入口的其他玩家评价。
- “同配置”：沿用“同游戏＋同 GPU”口径；匹配的其他玩家评价按同一显隐规则展示。
- “支持最多”：只改变排序，不改变方案入口显隐。
- “我的”：仅展示当前用户评价，不混入其他玩家实例。

Demo 不新增“客态”筛选项、状态切换器、测试面板或交互说明。

## 5. 数据与渲染约束

方案入口不得只依赖评价记录中的 `reviewState` 或列表摘要。每次渲染必须读取当前快照并同时满足：

```text
review.stars >= 3
AND snapshot exists
AND snapshot.status == available
AND snapshot.reviewId == review.id
```

任一条件不满足时，方案卡片不进入 DOM。隐藏方案不得留下高度、点击区域、键盘焦点或无障碍名称。

客态实例应至少包含：一个有效方案、一个未分享方案、一个已废弃快照、一个无效快照和一个 1～2 星问题评价。后台隐藏与归属不一致状态可通过数据和自动化测试覆盖，不需要在界面伪造说明。

## 6. Demo 与证据调整

- 更新 C 端种子数据，补齐缺失的客态状态，但不重复制造视觉相同的说明卡。
- 保留有效客态方案进入现有完整详情的真实点击链路。
- 在截图脚本中增加一张 390×844 客态自然混排截图，明确展示其他玩家及其有效方案入口。
- 不修改 B 端 Demo；后台现有快照追溯规则保持不变。

## 7. 验收条件

1. “全部”列表同时存在其他玩家的有效方案评价和普通无方案评价，视觉自然混排。
2. G-01 展示且仅展示一个可聚焦、可点击的方案入口，点击打开与评价一对一对应的快照详情。
3. G-02～G-06 均无方案卡片、空占位、点击热区和焦点节点。
4. G-05 的设备信息、问题描述、星级和兼容类型完整保留。
5. G-07 不出现在 C 端列表。
6. “我的”筛选不出现其他玩家；现有编辑、删除和分享流程无回归。
7. 390×844 与 844×390 无水平溢出或脚本错误。
8. 新增客态截图完成原尺寸人工审查，且 Demo 中不出现状态标注或评审说明。

## 8. 明确不改

- 不新增方案详情的加载中、加载失败、失效或设备不兼容演示入口。
- 不重新展示不可用方案卡片。
- 不修改启动失败流程、全平台累计 30 分钟门槛、邀评频控和星级口径。
- 不创建个人云方案，不恢复成功率、验证次数或多人聚合信息。
- 不调整 B 端快照模型、导出字段和删除生命周期。
