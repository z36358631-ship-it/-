# PM Skills 安装与 to-prd 单一入口整合设计

## 1. 背景

本地目录 `分享skills/pm-skills-main/pm-skills-main` 包含一套产品经理 Skills：

- 21 个正式 `pm-*` Skills：
  - 1 个总控：`pm-master`
  - 13 个执行类 Skills
  - 7 个专家顾问与方法论 Skills
- 2 个遗留重复 Skills：`space-image2proto`、`space-url2proto`

现有环境已经安装 `to-prd`，并在以下两个位置保留副本：

- 全局：`C:\Users\z3635\.codex\skills\to-prd`
- 工作区：`C:\Users\z3635\官网改动\.agents\skills\to-prd`

新套件中的 `pm-prd-writer` 与现有 `to-prd` 触发范围高度重叠。若直接同时安装，两者可能同时响应“写 PRD”“需求文档”等请求，并分别使用不同模板，造成输出结构和公司规范不一致。

## 2. 目标

1. 安装 21 个正式 PM Skills，使产品策划、研究、评审、数据、实验、路线图、原型和复盘能力可被 Codex 调用。
2. 保留 `to-prd` 作为唯一 PRD 主入口。
3. 将 `pm-prd-writer` 中有价值的通用方法合并进 `to-prd`。
4. 保留盖世游戏、国内/海外差异、飞书格式和图片发布校验等现有公司规则。
5. 避免 PRD Skill 重复触发、模板分叉和后续双份维护。
6. 在修改前创建可恢复备份，并同步全局与工作区的 `to-prd`。

## 3. 非目标

- 不安装 `space-image2proto` 和 `space-url2proto` 两个遗留重复 Skills。
- 不删除现有 `to-prd` 的公司专用规则。
- 不将所有通用 PRD 章节强制写入每份文档。
- 不在本次任务中修改业务 PRD、Demo、测试数据或其他现有项目文件。
- 不为缺失的外部工具自动安装插件、MCP 服务或系统依赖。

## 4. 方案选择

### 4.1 采用方案

采用“单一核心＋兼容桥接”：

- `to-prd` 是唯一 PRD 规范和执行核心。
- `pm-prd-writer` 保留 Skill 名称，用作 `pm-master` 和 PM Skills 链路的兼容桥接。
- `pm-prd-writer` 不再维护独立模板，而是读取并执行相邻的 `to-prd`。

### 4.2 未采用方案

#### 同时保留两套独立 PRD Skills

问题：

- 触发词重叠。
- 同一请求可能得到不同结构。
- 公司模板和通用模板会分别演进。
- `pm-master` 与用户直接调用可能得到不同结果。

#### 用 `pm-prd-writer` 替换 `to-prd`

问题：

- 会丢失盖世游戏专用写法。
- 会丢失国内/海外差异检查。
- 会丢失飞书 Markdown 和固定 Git 提交图片校验。
- 通用模板默认内容偏重，不适合所有日常需求。

## 6. to-prd 整合结构

### 6.1 保留的现有能力

以下规则继续作为强约束：

- 盖世游戏 PRD 命名和八章主体结构。
- C 端、B 端、C+B 端的范围裁剪。
- 盖世游戏国内包与海外包差异检查。
- 飞书兼容 Markdown 格式。
- 图示位于表格“图示”列。
- 图片必须使用固定 Git 提交 SHA 的公开 HTTPS 地址。
- 图片发布前需要用户授权。
- 图片 URL 必须通过 HTTP 状态和 `Content-Type` 远程验证。
- 修改既有 PRD 时保留历史版本和原内容。
- 输出后执行前端、测试、运营三个视角的模拟评审。

### 6.2 合并的新能力

从 `pm-prd-writer` 合并：

1. **需求体检**
   - 检查需求来源。
   - 检查用户当前替代方案。
   - 检查成功指标是否明确。
   - 风险不足以阻止用户继续写作，但必须显式标注。

2. **信息澄清**
   - 提取已知信息。
   - 列出信息缺口。
   - 将问题分为必须、建议、可后补。
   - 用户允许自行判断时，以 `[假设]` 标记。

3. **功能描述增强**
   - 用户故事。
   - 前置条件与后置条件。
   - 角色和权限。
   - 状态流转。
   - 异常和边界条件。
   - 数据字典。

4. **验收增强**
   - 每个核心功能包含可执行验收条件。
   - 汇总 `[待确认]`、`[假设]` 和 `[高风险假设]`。
   - 每条待确认项提供默认建议和影响范围。

5. **失败兜底**
   - 当目标、目标用户、核心流程等关键要素中有两个以上不明确时，不伪造完整 PRD。
   - 改为输出“需求梳理文档”，包含当前理解、关键问题、方案方向和下一步建议。

### 6.3 按复杂度裁剪

为避免日常小需求生成过度冗长的文档，使用“核心必填＋条件扩展”：

#### 核心必填

- 版本信息。
- 背景、目标和成功指标。
- 范围与不做事项。
- 核心用户场景和路径。
- 功能模块及交互。
- 异常边界。
- 非功能需求。
- 埋点与验收。
- 待确认项。

#### 条件扩展

- 多角色或后台系统：增加角色权限表。
- 存在复杂状态：增加状态流转表或 Mermaid 状态图。
- 存在重要业务对象：增加数据字典。
- 存在跨系统依赖：增加系统集成与降级说明。
- 存在版本拆分：增加里程碑和版本规划。
- 需求证据不足：增加高风险假设并建议先调研或验证。

## 7. pm-prd-writer 兼容桥接

`pm-prd-writer` 的职责调整为：

1. 仅在 `pm-master` 路由到它、用户明确输入 `/pm-prd-writer`，或 PM Skills 链路要求继续写 PRD 时触发。
2. 读取 `../to-prd/SKILL.md`，并将后续行为完全交给 `to-prd`。
3. 不维护第二套 PRD 模板。
4. PRD 完成后继续输出 PM Skills 链路所需的“交接摘要”：
   - 本步结论。
   - 待确认项。
   - 下游评审、埋点或实验所需输入。

普通“写 PRD”“需求文档”请求直接由 `to-prd` 触发，避免两个 Skill 同时竞争。

## 8. 文件与版本策略

### 8.1 备份

修改前创建带时间戳的备份目录，分别保存：

- 全局 `to-prd` 原始副本。
- 工作区 `to-prd` 原始副本。

备份仅用于本次升级恢复，不覆盖现有备份。

### 8.2 同步原则

- 工作区 `.agents/skills/to-prd` 作为可版本控制的维护源。
- 全局 `.codex/skills/to-prd` 作为 Codex 实际安装副本。
- 整合完成后，两处的 `SKILL.md`、`references` 和 `scripts` 保持一致。
- 后续修改先更新工作区维护源，验证后同步到全局安装副本。

### 8.3 安装冲突

- 目标目录已存在时，不直接覆盖。
- 本次源目录中的正式 `pm-*` Skill 当前均未安装，可以正常复制。
- `pm-prd-writer` 不直接复制原始目录，使用经过整合的兼容桥接版本。

## 9. 执行数据流

```text
用户提出产品任务
  ↓
pm-master 判断任务类型
  ├─ 非 PRD → 路由对应 pm-* Skill
  └─ PRD → pm-prd-writer 兼容桥接
                    ↓
                 to-prd
                    ↓
        需求体检 → 范围确认 → 模板裁剪
                    ↓
      生成 PRD → 自查 → 多视角模拟评审
                    ↓
     有图片？——否——→ 交付 PRD 与待确认项
        │
        是
        ↓
  获得发布授权 → 固定 SHA 发布 → 远程校验
        ↓
  交付 PRD、图片验证结果和 PM 链路交接摘要
```

用户直接输入 `/to-prd` 或普通 PRD 请求时，跳过 `pm-master` 和兼容桥接，直接进入同一核心流程。

## 10. 异常处理

### 10.1 引用资源缺失

- 安装后检查每个 Skill 引用的 `references`、`assets` 和本地路径。
- 缺失的可选资源记录为依赖提示。
- 缺失的必需资源导致验证失败，不能声明安装完成。

### 10.2 外部工具不可用

- `pm-image2pencil` 依赖 Pencil MCP；不可用时保留 Skill，但在调用时明确说明依赖缺失。
- `pm-url2proto` 可能需要 Node.js、npm 和网络；安装 Skill 不自动执行依赖安装。
- 不因工具暂不可用而删除其他可独立工作的 Skills。

### 10.3 图片发布未授权或失败

- 未授权时停止外部发布，只保留未完成状态，不伪造公开图片地址。
- URL 返回非 200、类型错误或数量不匹配时，不声明 PRD 可导入飞书。

### 10.4 同步失败

- 任一 `to-prd` 副本同步失败时，保留备份并报告差异。
- 两处未一致前，不声明整合完成。

## 11. 验证方案

### 11.1 结构验证

- 对 21 个安装目录运行 Skill 快速校验。
- 检查目录名与 frontmatter `name` 一致。
- 检查每个 Skill 只有允许的 `name` 和 `description` frontmatter 字段。
- 检查引用资源存在。

### 11.2 重复与触发检查

- 确认没有安装 `space-*` 遗留目录。
- 扫描 PRD 相关 Skill 描述，确认普通 PRD 请求只匹配 `to-prd`。
- 确认 `pm-prd-writer` 仅作为明确调用和链路兼容入口。
- 确认 `pm-master` 仍能路由到兼容桥接。

### 11.3 同步检查

- 比较全局和工作区 `to-prd` 的文件清单。
- 比较同名文件 SHA-256。
- 检查备份目录包含修改前的完整副本。

### 11.4 PRD 场景验证

使用三个代表性案例：

1. **仅 C 端新需求**
   - 输出 C 端详细设计。
   - 不输出空的 B 端详细设计。
   - 包含用户路径、异常和验收条件。

2. **C 端＋B 端复杂需求**
   - 同时输出 C、B 两端。
   - 包含权限、状态流转、数据字典和系统依赖。
   - 国内/海外差异按实际范围裁剪。

3. **修改已有带图 PRD**
   - 版本记录追加而非覆盖。
   - 保留原内容并标记新增修改。
   - 图片使用固定提交 SHA。
   - 图片数量、URL 数量和远程验证通过数一致。

### 11.5 验收标准

- 21 个正式 PM Skills 均通过基础结构验证。
- 2 个遗留 `space-*` Skills 未安装。
- 普通 PRD 请求只有 `to-prd` 一个主入口。
- `pm-master → pm-prd-writer → to-prd` 链路明确且无第二套模板。
- 全局和工作区的 `to-prd` 内容一致。
- 三个 PRD 场景检查全部通过。
- 未修改本次范围之外的用户文件。

## 12. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 两份 `to-prd` 再次分叉 | 不同工作区输出不同 PRD | 建立工作区维护源和 SHA 同步检查 |
| 新模板导致 PRD 过重 | 日常小需求效率下降 | 使用核心必填＋条件扩展 |
| `pm-prd-writer` 抢普通 PRD 请求 | 重复触发 | 缩窄 description，只保留显式和链路触发 |
| 外部依赖暂不可用 | 个别原型 Skill 无法执行 | 安装与运行依赖分离，调用时再检查 |
| 当前工作区存在大量无关改动 | 误提交用户文件 | 每次只添加和提交明确路径 |
| 图片发布需要外部权限 | PRD 无法完成飞书图片验收 | 未授权时停止发布并明确状态 |

## 13. 最终交付

- 全局安装的 21 个正式 PM Skills。
- 单一主入口的 `to-prd`。
- 兼容桥接版 `pm-prd-writer`。
- 全局与工作区同步的 `to-prd` 资源。
- 修改前备份。
- 结构、同步、触发和三类 PRD 场景验证结果。
