# 开发者平台财务统一入口设计

> 状态：已确认方案 A。本规格只替换《开发者平台与财务结算整合设计》的交付入口策略，财务业务规则仍以当前财务整合 Demo 和 PRD 为准。

## 1. 目标

将 `开发者平台财务整合demo.html` 中的财务主体、对账结算及全部交互合并到 `开发者平台demo.html`，让开发者使用一个入口完成游戏管理和财务操作。

## 2. 交付策略

- `开发者平台demo.html` 作为唯一主入口，直接包含 `P15-01 财务主体` 和 `P15-02 对账结算`。
- `开发者平台财务整合demo.html` 继续保留，用于兼容历史评审链接，不删除、不新增导航入口。
- 旧地址和主地址共用同一财务模型、页面样式和交互代码，后续修改不维护两份业务实现。

## 3. 页面与导航

- 开发者厂商级侧栏保持“游戏管理／财务主体／对账结算／厂商设置”。
- 点击财务主体进入 `#/P15-01`，点击对账结算进入 `#/P15-02`，全程不跳出主 HTML。
- 财务页继续复用主平台顶栏、侧栏、面包屑、帮助入口和场景悬浮球，不注入第二套应用壳。
- 企业认证状态与财务缺省态的联动保持现状。

## 4. 构建方案

- 将财务路由并入开发者平台模块的默认路由清单。
- 开发者平台默认构建始终注入 `publisher-finance.css`、财务共享模型和 `demo15/app.js`。
- 原 `--variant=finance-integrated` 构建目标保留，与主构建共用路由和源码，避免回归。
- 生成物仍为无外部依赖的单文件 HTML，不使用 iframe 或页面跳转拼接。

## 5. 数据与交互边界

- 复用当前财务模型和演示数据，不修改结算口径、财务主体字段、N+1 账期或导出字段。
- 复用当前已确认的企业认证联动、财务主体变更、附件预览、对账确认、明细查看、导出和缺省态。
- 路由切换时关闭旧页弹层，保留财务页内已应用的筛选和场景状态。

## 6. 验收标准

1. 打开 `开发者平台demo.html#/P15-01` 和 `#/P15-02` 均显示完整财务页，不是占位或加载失败。
2. 从游戏管理、厂商设置和对账结算往返时，URL 始终保持在 `开发者平台demo.html`。
3. 财务主体及对账结算已有浏览器用例全部转向并通过主 Demo。
4. 原开发者平台登录、认证、游戏管理和厂商设置回归通过。
5. 1440×900、1280×800 和 390×844 无根页面水平溢出，财务表格仅在内容区滚动。
6. 主 Demo 与历史财务整合 Demo 均可从固定 Git 提交地址打开，主 Demo 为新交付地址。

## 7. 明确不改

- 不删除历史财务 Demo。
- 不修改发行平台运营后台财务 Demo。
- 不新增财务 Tab、弹窗、字段、状态、计算或通知。
- 不更新 PRD 和 PRD 截图；本轮只统一 Demo 入口。
