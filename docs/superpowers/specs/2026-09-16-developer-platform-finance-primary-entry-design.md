# 开发者平台 P01-01 财务主体覆盖设计

> 状态：已确认直接覆盖。本规格替换上一版“新增财务入口”方案；财务业务规则仍以当前财务整合 Demo 和 PRD 为准。

## 1. 目标

将 `开发者平台财务整合demo.html#/P15-01` 的财务主体页，直接覆盖到 `开发者平台demo.html#/P01-01`。用户打开原主地址时，首页即为财务主体，不再显示原 P01-01 页面。

## 2. 交付策略

- `开发者平台demo.html#/P01-01` 映射到财务主体内容，页面标题、交互和状态与原 `P15-01` 一致。
- `P15-01` 继续作为兼容路由，与 `P01-01` 共用同一实现；`P15-02` 保留对账结算。
- `开发者平台财务整合demo.html` 继续保留，用于兼容历史评审链接，不删除、不新增导航入口。
- 旧地址和主地址共用同一财务模型、页面样式和交互代码，后续修改不维护两份业务实现。

## 3. 页面与导航

- `#/P01-01` 和 `#/P15-01` 都渲染财务主体，财务侧栏高亮“财务主体”。
- 点击对账结算进入 `#/P15-02`；再返回财务主体时使用主路由 `#/P01-01`。
- 财务页继续复用主平台顶栏、侧栏、面包屑、帮助入口和场景悬浮球，不注入第二套应用壳。
- 企业认证状态与财务缺省态的联动保持现状。

## 4. 构建方案

- 将财务路由和财务源码并入开发者平台默认构建。
- 路由层把 `P01-01` 规范化为财务主体页，但保留浏览器地址中的 `#/P01-01`。
- 开发者平台默认构建始终注入 `publisher-finance.css`、财务共享模型和 `demo15/app.js`。
- 原 `--variant=finance-integrated` 构建目标保留，与主构建共用路由和源码，避免回归。
- 生成物仍为无外部依赖的单文件 HTML，不使用 iframe 或页面跳转拼接。

## 5. 数据与交互边界

- 复用当前财务模型和演示数据，不修改结算口径、财务主体字段、N+1 账期或导出字段。
- 复用当前已确认的企业认证联动、财务主体变更、附件预览、对账确认、明细查看、导出和缺省态。
- 路由切换时关闭旧页弹层，保留财务页内已应用的筛选和场景状态。

## 6. 验收标准

1. 打开 `开发者平台demo.html#/P01-01` 显示完整财务主体，不再显示原 P01-01 内容。
2. `#/P15-01` 依然可访问同一财务主体页，`#/P15-02` 可访问对账结算。
3. 财务主体及对账结算已有浏览器用例全部转向并通过主 Demo。
4. 1440×900、1280×800 和 390×844 无根页面水平溢出，财务表格仅在内容区滚动。
5. 主 Demo 与历史财务整合 Demo 均可从固定 Git 提交地址打开，主 Demo 为新交付地址。

## 7. 明确不改

- 不删除历史财务 Demo。
- 不修改发行平台运营后台财务 Demo。
- 不保留原 P01-01 页面作为主地址的默认内容。
- 不新增财务 Tab、弹窗、字段、状态、计算或通知。
- 不更新 PRD 和 PRD 截图；本轮只统一 Demo 入口。
