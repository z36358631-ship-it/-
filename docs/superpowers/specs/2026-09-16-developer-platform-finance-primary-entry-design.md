# 开发者平台首访与财务入口设计

> 状态：已按新开发者首访链路确认。本规格替换上一版“P01-01 默认显示财务主体”的方案。

## 1. 目标

开发者平台主地址默认展示公开首页和登录入口。新开发者登录后依次完成账号注册、企业认证申请；企业认证通过后，才进入工作台并使用财务能力。

## 2. 页面与权限

- `#/P01-01`：公开首页、登录／注册入口，未登录时不显示工作台侧栏。
- `#/P01-03`：首次登录后的开发者注册和企业认证流程。
- `#/P02-01`：企业认证通过后的游戏管理工作台。
- `#/P15-01`：财务主体；`#/P15-02`：对账结算。
- 未登录用户直接访问工作台或财务路由时，统一回到 `#/P01-01`。
- 企业认证未通过时保留认证申请、审核中、补充资料和未通过状态，不自动授予工作台权限。

## 3. 导航

- 财务页侧栏包含游戏管理、财务主体、对账结算、厂商设置。
- 财务主体链接固定指向 `#/P15-01`，不再占用登录路由 `#/P01-01`。
- 四个入口仅在有效登录且企业认证通过后展示并可切换。
- 财务页继续复用主平台顶栏、侧栏、面包屑、帮助入口和演示状态，不新增应用壳。

## 4. 数据边界

- 移除为财务首页自动创建演示登录和企业认证通过状态的逻辑。
- 识别并清除上一版自动生成的 `demo:finance-primary` 会话，避免旧浏览器继续误判为已认证；其他账号会话不受影响。
- 保留用户真实保存的登录、注册和认证状态。
- 财务字段、结算口径、N+1 账期、导出、主体变更和对账确认逻辑不变。

## 5. 验收标准

1. 清空浏览器存储后打开主地址，显示公开首页和“登录”，不显示财务页或工作台侧栏。
2. 未登录直接访问 `#/P15-01`、`#/P15-02`，自动回到 `#/P01-01`。
3. 首次登录后进入注册与企业认证流程，不直接进入财务主体。
4. 企业认证通过后可进入 `#/P02-01`、`#/P15-01`、`#/P15-02`，四个侧栏入口正常切换。
5. 历史财务整合 Demo 保留，财务数据和交互不回归。

## 6. 明确不改

- 不删除历史财务 Demo。
- 不修改运营后台财务 Demo。
- 不新增页面、字段、弹窗、状态、计算或通知。
- 本轮不更新 PRD，仅修正 Demo 首访与路由权限。
