# GameHub 6.1.1（123）产品验收设计

## 1. 目标与基线

本次处理任务板工单 `GUANWANGGAID-17`。用户已确认：虽然工单标题为“V6.2.0版本验收”，实际验收对象是 MuMu 模拟器中 `GameHub 6.1.1 (123)` 的以下两项需求：

1. 《盖世游戏》控制器映射云方案。
2. 《盖世游戏》游戏库布局调整。

验收环境固定为：

- 设备：MuMu 模拟器。
- App：GameHub 6.1.1（versionCode 123）。
- Git SHA：`42115b9b4`。
- 渠道：Official。
- 服务环境：测试环境。
- APK：`功能验收/验收包/GameHub_beta_6.1.1_123_202608121110.apk`。
- APK SHA256：`834FB3362B6CC3FB322A70AF10294A82652D5DF122FFF9711E6A3FB8BBAEF710`。
- 控制器侧边栏入口：在云游戏画面按 `Esc`。

验收目的不是验证“页面是否存在”，而是确认用户能在当前包中顺利完成游戏库浏览与平台入口操作，并能在云游戏中发现、应用和管理控制器映射方案；同时识别需求不一致、体验问题、异常边界和发布风险。

- 能由当前环境验证的性能、兼容和异常状态。

### 2.2 游戏库布局调整

### 2.3 不扩展范围

## 3. 执行方案

采用“全量可追溯验收”：215 条用例均有独立判定，同屏静态项可以合并一次操作和一张截图，但记录中必须逐条反链用例编号。

执行顺序：

1. 记录包、环境、模拟器和账号基线。
2. 验收游戏库竖屏首页及 PC/复古子 Tab。
3. 验收 Steam、Epic、导入子页面和各账号状态。
4. 切换横屏，回归首页、子页面、网格、状态保持与响应体验。
5. 启动支持云游戏的游戏，按 `Esc` 调出侧边栏。
6. 验收控制器映射入口、开关、引导、方案广场和方案操作。
7. 在条件允许时覆盖创建、编辑、分享、导入、持久化、设备切换与异常路径。
8. 对 FAIL 用例最少复现一次；对偶发问题记录复现次数与复现率。
9. 汇总结果、标注问题截图、生成飞书同步文案并复核所有证据引用。

执行中优先暴露 P0/P1 主链路问题，但不会因此停止剩余无依赖用例。

## 4. 判定模型

每条用例只能使用以下一种状态：

| 状态 | 定义 |
|---|---|
| `PASS` | 实际表现与已确认需求一致，且未发现明显体验问题。 |
| `FAIL` | 可复现地不符合需求，或存在足以影响用户完成任务的体验问题。 |
| `BLOCKED` | 因账号、数据、硬件、网络、服务端、权限或环境条件不足无法执行。 |
| `N/A` | 经确认不适用于本次包、平台或本轮范围。 |

计算规则：

- 执行数 = PASS + FAIL。
- 通过率 = PASS /（PASS + FAIL）。
- BLOCKED 与 N/A 不进入通过率分母，但必须单独列出原因。
- 未执行用例不得默认为 PASS。
- 同一缺陷影响多条用例时，问题可以合并记录，但每条用例仍独立判定。

问题优先级：

- `P0`：核心流程完全不可用、崩溃、严重数据或账号风险、无法继续验收。
- `P1`：主路径明显受阻、关键需求缺失、严重错乱或高频体验问题。
- `P2`：次要流程、文案、样式、边界或低频体验问题。
- `建议`：不违反明确需求，但有可说明价值与代价的体验优化建议。

## 5. PRD 冲突处理

以下内容在资料中存在冲突，不由验收人员自行猜测；实测结果按事实记录，同时在问题表列为“待产品定版”：

1. 控制器是否为独立双开关、单选激活，或“双开关 + 输入优先级”。
2. 总开关关闭后拔出物理手柄，是否仍强制恢复虚拟按键。
3. 云分享是直接生成分享码，还是先经过“发布到云端”确认。
4. 复制内容是纯分享码还是完整分享文案。
5. 游戏库 PRD 中 Steam 好友、成就、创意工坊是本期新增还是回归范围。
6. Epic 已绑定态入口使用头像还是问号图标。
7. 横屏复古游戏入口是固定宽度还是撑满整行。

若实际产品表现明显违反其中一套需求，记录为“需求口径待定”，不直接计为 FAIL；若同时造成确定的用户任务失败，可另建体验问题并按影响定级。

证据规则：

- 原图保留未经编辑的完整界面。
- FAIL 证据复制为标注图，用红色矩形和编号定位问题；不得覆盖关键文案。
- Toast、动画、旋转、加载、热插拔等动态问题使用录屏或前后截图。
- 同屏证据可支持多条用例，但结果记录必须列出全部关联编号。
- 每个问题至少含一份可定位的证据；不能以口头观察代替。

## 8. 操作与风险控制

- 安装当前本地 APK、切换 App 测试环境、浏览页面、创建测试方案和输入无效分享码属于本轮正常验收操作。
- 删除方案、退出已绑定账号、移除好友、取消订阅、覆盖用户数据等破坏性动作，执行前单独向用户确认。
- 发布方案到云端可能形成对其他测试用户可见的数据，执行前单独确认。
- 任何飞书发送或其他对外沟通，执行前单独确认。
- 登录授权、验证码、账号密码和权限弹窗由用户接管或在确认后处理，不自动越过。
- MuMu 操作每次以最新画面为依据；输入结果未知时重新观察，不盲目重试。

本轮验收完成需同时满足：

1. 215 条用例全部得到 PASS、FAIL、BLOCKED 或 N/A 判定。

8. 工单评论包含变更、验证、结果和剩余风险，工单移至 `in_review`，不直接移至 `done`。
