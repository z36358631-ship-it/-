# GameHub 6.1.1（123）产品验收设计

## 1. 目标与基线

本次处理任务板工单 `GUANWANGGAID-17`。用户已确认：虽然工单标题为“V6.2.0版本验收”，实际验收对象是 MuMu 模拟器中 `GameHub 6.1.1 (123)` 的以下两项需求：

1. 《盖世游戏》控制器映射云方案。
2. 《盖世游戏》游戏库布局调整。

验收环境固定为：

- 设备：MuMu 模拟器。
- App：GameHub 6.1.1（versionCode 123）。
- Git SHA：`42115b9b4`。
- 渠道：Official 中文为功能基线；Global 为海外版回归渠道。
- 服务环境：测试环境。
- APK：`功能验收/验收包/GameHub_beta_6.1.1_123_202608121110.apk`。
- APK SHA256：`834FB3362B6CC3FB322A70AF10294A82652D5DF122FFF9711E6A3FB8BBAEF710`。
- 控制器侧边栏入口：在云游戏画面按 `Esc`。
- Global 切换：长按“我的-设置”，将渠道标识改为 `global`，保存后结束 App 进程并重新启动。
- Global 语言：中文、英文、俄语、日语、巴西葡萄牙语。

验收目的不是验证“页面是否存在”，而是确认用户能在当前包中顺利完成游戏库浏览与平台入口操作，并能在云游戏中发现、应用和管理控制器映射方案；同时识别需求不一致、体验问题、异常边界和发布风险。

## 2. 验收范围

### 2.1 控制器映射云方案

执行 `控制器映射云方案测试用例 - Sheet1.csv` 的 118 条用例，覆盖：

- 侧边栏入口、总开关、状态持久化和其他侧边栏设置。
- 虚拟手柄、物理手柄、手动切换和热插拔状态。
- 问号引导弹窗。
- 推荐、排行、自定义及游戏专用方案页面。
- 搜索、列表、详情、应用、编辑、复制、删除。
- 创建、保存、发布、分享码导出和导入。
- 编辑器返回、未保存修改及即时生效。
- 能由当前环境验证的性能、兼容和异常状态。

### 2.2 游戏库布局调整

执行 `盖世游戏 V6.1.1需求测试用例 - 游戏库改版需求.csv` 的 97 条用例，覆盖：

- 竖屏、横屏的 PC 游戏和复古游戏首页。
- Steam、Epic、导入游戏入口。
- 搜索、排序、筛选、游戏卡片和平台标识。
- Steam 未绑定/已绑定、数据、好友、成就和创意工坊。
- Epic 未绑定/已绑定和退出后的状态恢复。
- 导入游戏及系统文件选择器。
- 横竖屏切换、状态保持和可见体验问题。

### 2.3 不扩展范围

- 不把工单截图中的其他版本需求纳入本轮验收。
- 不替代 iOS、Mac、真机或多机型专项验收。
- 不因当前环境缺少账号、手柄或服务端数据而虚构通过结论。
- 不修改 App 源码或服务端配置。
- 不向飞书群实际发送消息；只产出可直接复制的同步文案。外部发送需用户再次授权。
- 不把 215 条功能用例机械复制为五套；非中文语言按关键页面、主链路和本地化风险矩阵执行。

### 2.4 Global 与多语言回归

Global 验收使用三级矩阵：

1. **Official 中文全量层：**完整执行 215 条功能用例，建立功能正确性基线。
2. **Global 中文渠道层：**验证渠道切换与冷启动持久化，并覆盖游戏库和控制器映射全部关键主链路，识别海外渠道特有的资源、接口、配置和入口差异。
3. **Global 外语本地化层：**英文、俄语、日语、巴西葡萄牙语分别执行语言切换、保存、冷启动持久化和关键页面/主链路回归。

每种 Global 语言至少覆盖：

- 渠道与语言设置保存后，结束 App 进程并重新启动，渠道和语言仍保持。
- 游戏库竖屏与横屏首页、PC/复古 Tab、Steam/Epic/导入入口、搜索/排序/筛选和至少一个二级页面。
- 云游戏启动、按 `Esc` 调出侧边栏、控制器映射入口、引导、方案广场、方案详情、应用、编辑保存及重启恢复。
- 空态、Toast、弹窗、按钮、Tab、动态数量、方案名称、作者与使用次数等动态文案。
- 未翻译、串语、乱码、缺字、变量或占位符错误、截断、重叠、按钮溢出、换行异常、字体基线和语言切换后文案未刷新。

本地化重点：

- 俄语、巴西葡萄牙语重点检查长文本对标题、按钮、Tab、卡片和弹窗的挤压与溢出。
- 日语重点检查字形缺失、错误回退字体和标点换行。
- 英文重点检查大小写、术语一致性和按钮/导航可读性。
- Global 中文重点检查是否误用国内渠道资源、入口、服务或文案。

## 3. 执行方案

采用“全量可追溯验收”：215 条用例均有独立判定，同屏静态项可以合并一次操作和一张截图，但记录中必须逐条反链用例编号。

执行顺序：

1. 记录包、环境、模拟器和账号基线。
2. 在 Official 中文环境验收游戏库竖屏首页及 PC/复古子 Tab。
3. 验收 Steam、Epic、导入子页面和各账号状态。
4. 切换横屏，回归首页、子页面、网格、状态保持与响应体验。
5. 启动支持云游戏的游戏，按 `Esc` 调出侧边栏。
6. 验收控制器映射入口、开关、引导、方案广场和方案操作。
7. 在条件允许时覆盖创建、编辑、分享、导入、持久化、设备切换与异常路径，完成 Official 中文 215 条用例。
8. 将渠道改为 `global` 并冷启动，使用 Global 中文执行渠道层关键链路回归。
9. 依次切换英文、俄语、日语、巴西葡萄牙语；每次保存后冷启动，再执行本地化层矩阵。
10. 对 FAIL 用例最少复现一次；对偶发问题记录复现次数与复现率。
11. 汇总结果、标注问题截图、生成飞书同步文案并复核所有证据引用。

执行中优先暴露 P0/P1 主链路问题，但不会因此停止剩余无依赖用例。

## 4. 判定模型

每条用例只能使用以下一种状态：

| 状态 | 定义 |
|---|---|
| `PASS` | 实际表现与已确认需求一致，且未发现明显体验问题。 |
| `FAIL` | 可复现地不符合需求，或存在足以影响用户完成任务的体验问题。 |
| `BLOCKED` | 因账号、数据、硬件、网络、服务端、权限或环境条件不足无法执行。 |
| `N/A` | 经确认不适用于本次包、平台或本轮范围。 |

计算规则：

- 执行数 = PASS + FAIL。
- 通过率 = PASS /（PASS + FAIL）。
- BLOCKED 与 N/A 不进入通过率分母，但必须单独列出原因。
- 未执行用例不得默认为 PASS。
- 同一缺陷影响多条用例时，问题可以合并记录，但每条用例仍独立判定。
- Global 本地化矩阵按“语言 × 检查点”独立判定；一种语言通过不得替代另一种语言。
- 冷启动定义为结束 App 进程后重新启动，不以页面刷新、返回桌面后恢复或热重载代替。

问题优先级：

- `P0`：核心流程完全不可用、崩溃、严重数据或账号风险、无法继续验收。
- `P1`：主路径明显受阻、关键需求缺失、严重错乱或高频体验问题。
- `P2`：次要流程、文案、样式、边界或低频体验问题。
- `建议`：不违反明确需求，但有可说明价值与代价的体验优化建议。

## 5. PRD 冲突处理

以下内容在资料中存在冲突，不由验收人员自行猜测；实测结果按事实记录，同时在问题表列为“待产品定版”：

1. 控制器是否为独立双开关、单选激活，或“双开关 + 输入优先级”。
2. 总开关关闭后拔出物理手柄，是否仍强制恢复虚拟按键。
3. 云分享是直接生成分享码，还是先经过“发布到云端”确认。
4. 复制内容是纯分享码还是完整分享文案。
5. 游戏库 PRD 中 Steam 好友、成就、创意工坊是本期新增还是回归范围。
6. Epic 已绑定态入口使用头像还是问号图标。
7. 横屏复古游戏入口是固定宽度还是撑满整行。

若实际产品表现明显违反其中一套需求，记录为“需求口径待定”，不直接计为 FAIL；若同时造成确定的用户任务失败，可另建体验问题并按影响定级。

- 安装当前本地 APK、切换 App 测试环境、浏览页面、创建测试方案和输入无效分享码属于本轮正常验收操作。

- 删除方案、退出已绑定账号、移除好友、取消订阅、覆盖用户数据等破坏性动作，执行前单独向用户确认。
- 发布方案到云端可能形成对其他测试用户可见的数据，执行前单独确认。
- 任何飞书发送或其他对外沟通，执行前单独确认。
- 登录授权、验证码、账号密码和权限弹窗由用户接管或在确认后处理，不自动越过。
- MuMu 操作每次以最新画面为依据；输入结果未知时重新观察，不盲目重试。

- 用户视角：通过。先完成可用主路径，再覆盖边界；每个体验问题都有可回看的界面证据。
- 开发视角：通过。同屏静态项合并操作可控制 215 条用例成本，逐条结果仍保留追踪性。
- 商业视角：通过。先暴露 P0/P1 后继续全量，不因局部阻塞而丢失整体发布信息。
