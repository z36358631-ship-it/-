# 盖世游戏 APP 租号最终评审修订设计

## 1. 结论

本轮在现有 V6.1.1 APP 页面和 CDKEY 视觉骨架上完成租号客户端修订，并把现有 Mac 租号运营后台完整接入 APP 标注 Demo。客户端不重新发明信息架构：发现、搜索和详情负责发现与理解游戏；确认订单负责选择租期或权益方案；订单中心负责状态与操作。运营后台直接复用 Mac 后台的页面结构、字段和操作，仅增加端别数据切换。

首次体验固定为 2 小时，统一从服务端确认的“支付成功时间”开始计时。支付成功即消耗首次资格并隐藏首次体验 SKU，不以首次启动、首次分配账号或客户端本地时间作为计时起点。

本期客户端 Demo 只体现租号业务和租号状态。CDKEY 继续由其独立需求完成；订单卡不增加订单类型标签。首期可售游戏只提供标准版，确认订单不展示版本选择。

## 2. 用户问题、现状与设计基线

### 2.1 要解决的问题

- 租号价格、状态和入口散落在探索、搜索、详情和订单页，表达不一致。
- 详情页操作过多，SKU 选择与确认订单职责重复。
- 热门游戏时租与非热门游戏长期权益混在一起，用户难以理解可购买内容。
- 会员中心的购买价值、套餐和会员游戏库层级不足，横屏支付区无法在首屏完成决策。
- 订单列表与详情动作混乱，租期结束后仍出现无效的“继续畅玩”。
- Steam 租号账号可能启动非本次租用游戏，存在越权使用和履约风险。
- 多次退款用户仍可能误以为新订单继续享受平台额外“3天无理由”。
- APP 业务没有对应运营后台视图，运营无法按端管理商品、会员、账号、订单和数据。

### 2.2 用户现有方式

用户需要跨页面确认价格和权益，并通过按钮文案猜测下一步。首次体验何时开始、支付后是否还需等待分配、租期结束后能否再次购买也不清晰。运营侧只能查看 Mac 租号数据，无法在同一后台独立查看 APP 安卓端数据。

### 2.3 基线与借鉴

- APP V6.1.1：保留导航、卡片比例、媒体区、评分、PC 游戏引擎和个人中心结构。
- APP CDKEY：复用搜索结果、确认订单和支付区域的信息层级，不带入卡密、激活和发货语义。
- Mac 租号 Demo：复用租号权益、Steam 登录、后台 7 个模块、订单履约与售后规则。
- 需要规避：卡片内直接下单、详情与确认订单重复选 SKU、虚构优惠或权益、客户端计算有效期、用退款风控排除法定售后或履约失败救济。

## 3. 全局业务规则

### 3.1 页面职责

1. 探索、排行榜、玩游戏、游戏库、社区：只在原结构中增加租号价格或状态。
2. 搜索结果：游戏 Tab 使用双列竖卡，无卡内按钮，整卡进入详情。
3. 游戏详情：解释游戏与当前可执行操作，不选择租期或权益 SKU。
4. 确认订单：承载套餐、时长、权益方案、支付方式和应付金额。
5. 订单中心：展示订单状态和当前可执行操作。
6. 运营后台：在原 Mac 后台模块内按端独立管理和查看数据，不新增一套后台导航。

### 3.2 状态与价格优先级

同一游戏只展示一个最高优先级结果：

1. 存在生效中的租赁：`已租号`。
2. 当前已具备直接游玩条件：`可畅玩`。
3. 无直接权益但有符合资格的可售租号 SKU：`¥X.X 租号`。
4. 无权益且无可售内容：不展示租号补充信息。

搜索结果不显示租赁剩余时长。探索与搜索金额保留一位小数；订单结算金额按服务端订单快照展示两位小数。时长超过 24 小时使用 `X天X小时`，24 小时仍显示 `24小时`。

探索 Banner 的 `¥1.9首租` 只在用户无有效租赁和直接权益、目标游戏具备首次资格且首租 SKU 可售时显示；否则回退为当前符合资格的最低时租价。`99+ 在租` 来自有效租赁人数分档，数据不可用时隐藏，不使用虚构生产数据。

探索、搜索、确认订单读取同一商品和价格服务。2—23 小时逐小时取服务端报价，客户端不得按展示价线性推导。

### 3.3 售卖模式

- 热门游戏：运营稳定配置为 `time-rental`，只提供按小时、日租和周租。
- 非热门游戏：运营稳定配置为 `entitlement`，只提供首次体验、单游戏永久和开会员。
- 模式不随实时热度自动变化；已支付订单和已生效权益按支付快照继续履约。

### 3.4 商品、版本与时间模型

客户端统一读取 `GAME_CATALOG`，至少包含 `saleMode`、`platform`、`editionId`、SKU 报价与库存、首次体验资格、会员库归属和 `cloudSaveSupported`。本期平台为 Steam、版本固定 `editionId=standard`；确认订单只把 `标准版`作为游戏名下方灰色副标题，不渲染版本选择器。

支付成功时间以服务端支付回调落库时间 `paidAt` 为准。客户端只展示服务端返回的 `startsAt`、`expiresAt`，不得使用本机时钟计算或延长权益。

首次体验规则：

1. SKU 名称固定为 `首次体验 · 2小时`。
2. 资格按平台用户唯一标识控制：每位用户在整个游戏平台终身只能购买 1 次首次体验，不按游戏、设备、Steam 账号或重新登录重置。
3. 支付成功即设置 `startsAt=paidAt`、`expiresAt=paidAt+2小时`，并在同一事务中原子消耗平台级首次资格。
4. 支付成功后所有游戏入口立即隐藏首次体验 SKU；重复支付回调不得重复发放或移动时间。
5. 用户侧不显示“账号分配中”。每次启动时后台自动校验权益并幂等准备账号，前台无感。
6. 体验期内仍允许购买 `单游戏永久` 或开会员；新权益生效不强制中断当前游戏会话。
7. 会员只有在目标游戏属于会员库时才接管后续游玩权益。

## 4. 客户端页面设计

### 4.1 探索页

大 Banner 使用固定四角信息结构：

- 左上：`今日推荐` 与日期。
- 左下：游戏名；下一行评分与类型。
- 右下：`¥1.9首租`；下一行 `99+ 在租`。
- 首租价格字号与游戏名一致，颜色与评分一致。
- 整卡进入详情，不增加下单按钮。

小型游戏卡保留原封面与游戏名，把原 CDKEY 价格和标签原位替换为两行租号信息，例如 `¥9.9租号`、`在租99+`。生产展示仍服从 §3.2 的状态优先级。

### 4.2 搜索结果

- 保留 `全部 / 游戏 / 社区` 普通文字 Tab。
- 游戏 Tab 固定为每行两张竖卡：封面在上，游戏名在下，名称最多两行。
- 游戏名下最多保留一条 `已租号 / 可畅玩 / ¥X.X 租号`。
- 卡片无独立按钮和右箭头，点击整卡进入详情。
- 金额保留一位小数，不显示剩余时长、订单进度或权益来源。

### 4.3 游戏详情

保留原媒体、游戏名、简介、评分、类型、标签与 PC 游戏引擎。横屏主信息严格按 `游戏名 → 简介 → 标签 → 操作按钮` 排列，不重叠。

底部采用 F 方案，顺序固定为：

1. `更多`：竖向三点图标在上、文字在下，无背景和描边。
2. `秒玩`：图标在上、文字在下，始终直接可见，不折叠。
3. 动态次级交易按钮。
4. 动态主交易按钮。

动作矩阵：

| 用户/商品状态 | 次级交易 | 主交易 |
|---|---|---|
| 无权益，可买可租 | 立即购买 | 租号开玩 |
| 免费获取 | 获取游戏 | 隐藏 |
| 仅可购买 | 隐藏 | 立即购买 |
| 仅可租号 | 隐藏 | 租号开玩 |
| 有效租赁 | 隐藏 | 登录游戏 |
| 已有权益且已安装 | 隐藏 | 可畅玩 |
| 已有权益但未安装 | 隐藏 | 下载游戏 |
| 无可执行动作 | 隐藏 | 不可用说明 |

`获取游戏`与`租号开玩`互斥。无有效租赁且没有目标游戏权益时，包括租期结束或退款完成后，重新显示当前可售的 `租号开玩`，不得继续显示 `已租号` 或无效的 `继续畅玩`。

### 4.4 热门游戏确认订单

商品卡只展示封面、游戏名和下方灰色副标题 `标准版`，不展示热门标签、订单号或版本选择。

确认订单保留上一版 `租号权益` 五项保障：`100% 正版 / 一键启动 / 永不顶号 / 存档无忧 / 3天无理由`；点击 `3天无理由` 继续打开原规则弹窗。标题栏右上角增加无背景纯文字入口 `租号介绍`，不显示问号；整段文字为点击热区，点击打开 `租号功能介绍` 弹窗。弹窗以“常见问题”形式逐项一问一答，只保留三组内容：`租号有什么作用？` 说明限时使用权且不代表购买游戏或账号所有权；`如何使用租号？` 说明选择套餐、支付、系统自动准备账号和一键上号/登录信息路径；`使用时要注意什么？` 说明账号资料限制、租期边界，以及首次体验固定 2 小时、从支付成功计时、整个游戏平台终身一次。关闭后停留在当前确认订单，不改变已选套餐、金额或支付方式。租号介绍只改变说明方式，不替换或删除租号权益区。

选择区只保留一行：`租赁套餐　按小时　日租　周租`。按小时默认 2 小时，可在 2—23 小时内减号、直接输入整数或加号，并提供 6、12、23 小时快捷键。日租和周租为独立套餐。`¥1.9首租` 是符合资格用户的标准版 2 小时报价，不是第四个套餐。

删除协议、退款规则正文、支付有效期、支付二维码、租赁信息汇总卡和套餐区“当前报价”。在租号套餐与支付方式之间增加两行金额明细：`游戏原价 ¥X` 使用普通次级文字，表示游戏本体原价且不参与租号结算；`订单金额 ¥X.XX` 使用强调色，随当前所选租号套餐实时更新。支付方式标题与微信、支付宝两个等宽按钮同一行。底部左侧固定显示 `需支付 ¥X.XX`，右侧固定为 `立即购买`；订单金额、需支付金额和最终支付请求金额必须来自同一订单快照并完全一致。

竖屏内容顺序固定为 `商品 → 租号权益 → 租号套餐 → 游戏原价/订单金额 → 支付方式 → 固定底部支付栏`。横屏改为左右两栏：左侧展示商品卡和上一版五项租号权益；右侧从上到下展示租号套餐、游戏原价/订单金额、支付方式以及吸附在右栏底部的需支付与立即购买。右栏在低高度横屏下允许内部滚动，不得把支付方式或按钮裁出可操作区域。首次体验、单游戏永久和时租的差异继续通过 SKU 名称、套餐选择、支付结果和租号介绍说明，不新增替代权益卡。

### 4.5 非热门游戏确认订单

商品卡同样只展示游戏名和灰色副标题 `标准版`。`权益方案` 作为选择区独立标题，SKU 按钮另起一行展示 2—3 个，并允许紧凑换到下一行：

- `首次体验 · 2小时`
- `单游戏永久`
- `开会员`

不出现按小时、日租或周租。点击 `开会员` 进入会员中心，不创建游戏订单。首次体验从支付成功开始计时，支付成功后该 SKU 立即消失；体验期内再次进入仍可购买单游戏永久或开会员。

确认订单停留期间平台级首次资格失效时，清除当前选择并要求用户主动选择，不得自动切换到更贵的单游戏永久。若其余方案也不可售，展示空状态并允许返回详情。

非热门游戏复用同一金额明细和横竖屏分栏规则：`游戏原价`来自当前游戏标准版价格快照，`订单金额`随首次体验或单游戏永久 SKU 更新；点击开会员离开本页，不生成游戏订单或金额快照。

### 4.6 Steam 登录、第三方信息与启动拦截

竖屏 Steam 登录顺序为二维码、扫码说明、账号密码分隔、账号密码表单；横屏使用账号密码与二维码双栏。登录前不显示空令牌容器或禁用的“获取验证码”；提交账号密码且服务端返回需要 Steam Guard 后才显示令牌验证区。一键上号在本期 Demo 固定演示登录成功并返回游戏库。

部分游戏在 Steam 后还需要 Rockstar Games 等第三方登录。只有游戏、有效租赁和后台准入配置同时命中时才展示具体平台区；账号、密码默认脱敏，验证码按需获取并具备限频、倒计时、过期和清理。敏感值不得写入持久化、日志、埋点或公开截图。

当前租号 Steam 账号点击非本次租用游戏时，必须在启动前阻断：

- 弹层说明“当前租用游戏”和“目标游戏”，不允许直接启动。
- 目标游戏存在符合资格且可售 SKU 时，主操作为 `查看租号方案`。
- 无合资格 SKU 时展示 `暂不可租用`，不提供启动操作。
- 启动请求和后台账号准备均需幂等，重复点击不得创建重复会话或占用多个账号。

### 4.7 退款权益风险提醒

用户点击 `租号开玩` 时消费服务端风险结果，客户端不写死退款次数或时间窗。命中近期多次退款风险后展示 `退款权益提醒`：说明本单不适用平台额外“3天无理由”，用户可暂不购买或确认继续。确认后才进入确认订单，并将本次限制及规则版本写入订单快照。

该限制只影响平台额外承诺，不影响法定退款权利，也不影响 Steam 登录失败、启动失败、账号异常等履约售后。

### 4.8 个人中心与会员中心

会员状态与用户名同一行：未开通显示 `会员未开通 ›`，已开通显示当前套餐状态；点击进入会员中心。下一行保留 UID 与已实名，删除重复会员大卡。

用户在当前会话首次进入会员中心时，先展示 `关于会员` 弹窗；点击右上角关闭或 `我已了解` 后进入会员中心，本次会话再次进入不重复展示。正文只保留并重新编号为 4 点：

1. 开通会员可畅玩会员游戏，总价值 30w+ 的正版游戏库存；强调 `绝不顶号、挤号`。
2. 会员属于特殊虚拟商品，开通后无法退款。
3. 会员游戏库定期更新，但并非所有游戏都能第一时间加入会员游戏库。
4. 会员游戏账号池共享，非个人所有；一号一游戏，均为 Steam 正版账号；强调 `非盗版、非假入库、非离线`。

不得出现原弹窗第 3 点“工作时间联系客服申请远程协助”及同义替代文案。该弹窗不新增套餐、权益或售后承诺，只承担首次说明。

会员中心页面顺序固定为：

1. 会员价值 Hero。
2. 原四项权益：会员库内畅玩、游戏持续更新、PC 引擎与手柄适配、个人云存档同步。
3. 周卡、月卡、季卡三档套餐。
4. 会员游戏库。
5. 常见问题。
6. 固定底部支付操作。

Demo 暂用周卡 ¥39、月卡 ¥129、季卡 ¥299，季卡为推荐态；正式价格和推荐档读取服务端价格版本。会员游戏卡只在封面下方信息区显示名称、版本副标题和按配置出现的云存档支持信息，不把标识叠在封面上。

横屏首屏必须看见套餐、微信、支付宝和开通按钮，不显示二维码。周卡支持续费：未过期时从当前 `expiresAt` 顺延 7 天；已过期时从本次 `paidAt` 重新计算 7 天。支付回调服务端幂等，同一交易不得重复顺延。

### 4.9 订单中心与订单详情

订单中心只保留 `全部订单 / 待支付 / 可使用`。标题和 Tab 之间无额外空白。搜索收起态只显示无背景的放大镜，点击后以右端为锚点向左展开；三个 Tab 始终同一行、位置不变，搜索只作用于当前 Tab 的游戏名或订单号。

列表不显示 `申请售后`。列表与详情共用同一动作源，再按页面过滤，避免状态和文案漂移：

| 状态 | 列表操作 | 详情底部操作 |
|---|---|---|
| 待支付 | 取消订单、继续支付 | 取消订单、继续支付 |
| 时租账号准备中 | 刷新状态 | 刷新状态 |
| 租赁中 | 登录信息、登录游戏 | 申请售后、登录信息、登录游戏 |
| 退款中 | 退款进度 | 退款进度 |
| 已退款且无其他权益 | 租号开玩、删除订单 | 租号开玩、删除订单 |
| 已结束且无其他权益 | 租号开玩、删除订单 | 租号开玩、删除订单 |
| 已退款/已结束且有直接权益 | 可畅玩、删除订单 | 可畅玩、删除订单 |

详情顶部只展示状态和说明，按钮固定在底部。首次体验和单游戏永久不显示用户可见的账号分配状态；时租如需预分配可使用“账号准备中”，但不得复用到权益型订单。

退款中与已退款共用可关闭的退款进度弹层，展示结论、退款金额、原路退回说明和阶段进度。订单卡所有按钮必须完整位于卡片边框内。

## 5. 运营后台设计

### 5.1 接入方式

APP 标注 Demo 增加 `APP（安卓端）客户端 / 运营后台` 一级切换。运营后台直接复用现有 Mac 租号后台的布局、导航、表格、抽屉、表单和操作，不修改 Mac Demo 或 Mac PRD。

后台模块保持 7 个：

1. 租号商品管理。
2. 会员游戏库管理。
3. 会员套餐管理。
4. 账号资源管理。
5. 订单与售后。
6. 效果统计。
7. 操作记录。

### 5.2 页面端别 Tab

除“操作记录”外，前 6 个页面各自在页面内容顶部增加 `APP（安卓端） / Mac` Tab：

- 每次进入页面默认选中 `APP（安卓端）`，只展示 APP 数据。
- Tab 属于当前页面，不增加全局端别开关，也不联动修改其他页面。
- 切换到 `Mac` 后原样展示现有 Mac 后台数据与操作。
- 请求必须携带 `clientType=android|mac`；列表、汇总、筛选、编辑、导出和批量操作均按端隔离，禁止混用数据。
- 切换端别不复用另一端的勾选项、分页或未提交表单。

“操作记录”不增加端别 Tab，继续展示统一审计记录。涉及端别的写操作在记录详情和变更快照中保存 `clientType`，便于追溯，但操作记录本身不按 Tab 分裂。

### 5.3 APP 安卓端数据口径

- 租号商品管理：只展示标准版；展示热门时租/非热门权益模式、对应 SKU、价格版本、库存和上下架状态。
- 会员游戏库管理：维护 APP 会员可玩游戏、标准版、云存档支持和可用库存。
- 会员套餐管理：只展示周卡、月卡、季卡；支持价格版本、上下架和历史回滚；周卡续费按 §4.8 顺延。
- 账号资源管理：展示 APP 启动所需 Steam 及按需第三方平台资源，只展示脱敏状态和履约能力。
- 订单与售后：展示 APP 订单、权益类型、风险快照、启动结果、退款与售后；设备环境使用 APP 版本、Android 版本、机型、CPU、GPU、内存，不沿用 macOS 字段。
- 效果统计：只统计 APP 曝光、点击租号、提交订单、支付成功、一键上号成功、首次体验转长期权益、库存效率和退款数据。

## 6. 核心数据流与状态

### 6.1 支付与权益

1. 客户端用服务端草稿订单和价格版本展示金额；草稿固化 `gameOriginalAmount`、`amount` 和支付币种。
2. 支付平台回调服务端，服务端以交易号幂等确认支付并写入 `paidAt`。
3. 首次体验在同一事务中消耗平台级终身资格，写入 2 小时有效期；会员周卡根据旧有效期决定顺延或重算。
4. 客户端刷新订单和权益，不本地推算有效期。
5. 启动游戏时服务端校验当前权益、目标游戏和账号资源，幂等创建或复用启动会话。

### 6.2 到期与权益升级

- T0 到期撤销短期租赁会话和授权、释放账号，保留本地游戏文件与个人存档，同一使用单只执行一次。
- 首次体验期间购买单游戏永久或会员时，新权益生效不强退当前会话；当前会话结束后按新权益继续。
- 会员只对会员库内游戏生效；非会员库游戏仍按单游戏永久或租号规则处理。

### 6.3 售后与风险

- 售后问题固定为启动失败、Steam 登录失败、账号异常/频繁掉线、其他问题。
- `3天无理由` 是额外政策说明，不作为售后问题类型。
- 风险结果、是否适用额外无理由、规则版本和用户确认时间写入订单快照。
- 退款风险不能阻断履约失败售后；取号失败可自动进入退款中，敏感账号不得重新分配。

## 7. 横竖屏、可访问性与安全

- 客户端 18 个页面/关键状态继续覆盖横竖屏，共 36 个客户端基线状态。
- 后台为桌面布局：6 个双端页面覆盖 APP/Mac 两种数据态，操作记录覆盖统一态，共 13 个后台关键状态。
- 固定底栏预留安全区，不遮挡正文；主要触控区域不小于 44×44；状态不能只靠颜色表达。
- 横屏订单中心、会员中心、Steam 登录和详情均需满足首屏核心任务与无重叠要求。
- 账号、密码、令牌和验证码不得进入持久化、日志、埋点、导出、操作记录正文或公开截图。

## 8. 异常与边界

- 小时输入只接受 2—23 的整数；越界时阻止提交并回到最近合法值。
- 商品或资格在确认订单停留期间失效时清除选择，支付保持禁用，用户主动重新选择。
- 搜索展开后切换 Tab 时关键词保留，但只作用于新 Tab；无结果不跨 Tab 搜索。
- 无有效租赁时隐藏登录信息；进行中订单不可删除。
- 首次体验支付成功但客户端断线：平台级终身资格和有效期仍按服务端 `paidAt` 生效，重进后同步剩余时间，不补时。
- 支付回调重复、客户端重复查询或重复启动不得重复发放权益、延长有效期、创建订单或占用账号。
- 后台端别切换失败时保留当前已成功显示的数据并明确加载失败，不把另一端数据当作降级结果。

## 9. 非目标

- 不实现 CDKEY 卡密、激活、发货和 CDKEY 订单状态。
- 不新增订单类型标签、客户端导航入口或第四种会员套餐。
- 不在发现页和搜索卡片内增加按钮。
- 不修改 Mac Demo 与 Mac PRD；只把现有 Mac 后台复制进 APP 标注 Demo。
- 不修改运营后台“操作记录”为双 Tab 页面。
- 不 push、不发布，除非另行获得明确授权。

## 10. 验收标准

1. 探索 Banner 与小卡按确认位置展示租号价格、游戏信息和在租人数，且服从状态优先级。
2. 搜索游戏 Tab 为双列竖卡，无卡内按钮；名称最多两行；只显示一条状态或一位小数价格。
3. 详情使用 F 操作区，免费获取与租号互斥；租期结束且无权益时恢复 `租号开玩`。
4. 热门确认订单只有标准版和时租；按小时支持 2—23 自由输入及 6/12/23 快捷键。竖屏在商品下保留上一版 `100% 正版 / 一键启动 / 永不顶号 / 存档无忧 / 3天无理由` 五项租号权益，并在套餐与支付方式之间展示游戏原价和订单金额；横屏左侧展示商品与五项租号权益，右侧为套餐、两行金额、支付方式和支付操作；点击 `3天无理由` 打开原规则弹窗，右上角纯文字 `租号介绍` 打开的弹窗以“作用 / 使用方法 / 注意事项”三组常见问题逐项一问一答。详情入口、返回重进和标注导航直达都必须先创建或复用有效待支付草稿，正常可售场景不得展示“订单创建失败”。
5. 非热门确认订单的 `权益方案` 为独立标题，下一行只展示 `首次体验 · 2小时 / 单游戏永久 / 开会员`，并复用同一金额明细；订单金额随 SKU 变化，底部需支付与订单金额完全一致。
6. 首次体验从服务端支付成功时间计时；每位用户在整个游戏平台终身只能体验 1 次，支付成功即消耗平台级资格并让所有游戏隐藏该 SKU；无用户可见“账号分配中”。
7. 首次体验期间可购买单游戏永久或开会员，新权益不强退当前会话。
8. Steam 登录前无空令牌区；一键上号成功返回游戏库；第三方信息按配置展示且全程脱敏。
9. 点击非本次租用游戏时必定先拦截；有 SKU 才显示 `查看租号方案`，否则显示 `暂不可租用`。
10. 退款风险由服务端判定，提醒只限制平台额外“3天无理由”，不影响法定或履约售后。
11. 首次进入会员中心展示 `关于会员` 四点说明，关闭后本次会话不重复出现，且不存在远程协助条款；会员中心保留四项权益和周卡/月卡/季卡，横屏首屏可支付且无二维码，周卡续费正确顺延并幂等。
12. 订单列表不显示申请售后，详情保留；列表与详情动作由同一状态源按页面过滤。
13. 退款进度在列表和详情均可打开并展示对应状态。
14. 后台 7 个 Mac 模块已接入 APP 标注 Demo；除操作记录外，每页均有独立 `APP（安卓端）/ Mac` Tab，进入默认 APP。
15. 后台两端数据、筛选、批量操作、编辑和导出严格隔离；操作记录无端别 Tab，但写操作快照包含 `clientType`。
16. 普通 Demo、标注版、PRD、自动验证、客户端 36 个状态和后台 13 个状态口径一致。
