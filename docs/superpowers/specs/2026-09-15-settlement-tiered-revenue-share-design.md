# 发行平台阶梯分成与结算字段设计

## 1. 目标与范围

本轮调整开发者财务 Demo 与发行平台运营后台财务 Demo，统一本体、DLC、CDKEY、退款与拒付的结算口径，并支持按收入阶梯递减的平台分成配置。

本轮包含：

- 开发者端财务主体企业认证缺省态。
- 本体与 DLC 合并展示及明细下钻。
- CDKEY 渠道明细。
- 平台分成阶梯配置。
- 开发者端、运营端结算字段与金额快照同源。
- 运营端主体汇总、游戏明细、筛选和导出。

本轮不包含：

- 线上打款、打款成功或失败状态。
- 打款凭证回填。
- 发票管理。
- 合同线上签署。

## 2. 核心定义

### 2.1 结算项

| 结算项 | 展示规则 | 平台分成规则 |
|---|---|---|
| 游戏销售分成 | 合并游戏本体与 DLC，详情中分项展示 | 按阶梯规则计算 |
| CDKEY 销售分成 | 主表汇总，详情按渠道、商品类型与商品展示 | 平台分成 0% |
| 退款与拒付 | 合并展示实际退款与拒付金额 | 按实际发生金额全额冲减结算款 |

退款与拒付的“全额冲减”不是平台分成比例 100%。

### 2.2 金额口径

| 字段 | 定义 |
|---|---|
| 游戏及 DLC 销售金额 | 平台商城游戏本体与 DLC 的用户实付合计，不含 CDKEY |
| CDKEY 销售金额 | 各渠道 CDKEY 用户实付合计 |
| 用户实付 | 游戏及 DLC 销售金额 + CDKEY 销售金额 |
| 支付费 | 第三方支付商按交易实际收取的费用合计 |
| 税费 | 各国家或地区、税种对应的实际税费合计 |
| 综合税率 | 税费合计 ÷ 计税金额合计；计税金额为 0 时展示“—” |
| 退款与拒付 | 已生效退款与拒付金额合计 |
| 平台实收 | 用户实付 − 支付费 − 税费 − 退款与拒付 |
| 可分成净额 | 游戏及 DLC 销售金额扣除其对应支付费、税费、退款与拒付后的金额，不含 CDKEY |
| 平台分成 | 各阶梯内可分成净额 × 对应平台分成比例后求和 |
| 平台分成比例 | 平台分成 ÷ 可分成净额；可分成净额为 0 时展示“—” |
| 应结算金额（CNY） | 平台实收 − 平台分成 |
| 应结算金额（USD） | 应结算金额（CNY）÷ 结算月锁定汇率 |

金额统一按分存储并四舍五入，页面统一展示两位小数。负数保留负号，不显示负零。

## 3. 平台分成阶梯

### 3.1 统计范围

- 配置维度：开发者 + 游戏。
- 统计周期：单个账单月。
- 计费基础：该游戏本体与 DLC 的可分成净额。
- 计算方式：分段累进，仅超出档位的金额使用下一档比例。
- 结算月份：账单月份 N+1。

### 3.2 配置字段

- 开发者。
- 游戏。
- 规则版本。
- 生效账单月。
- 阶梯起始金额。
- 阶梯结束金额。
- 平台分成比例。
- 变更原因。
- 操作人。
- 操作时间。

### 3.3 校验

- 首档从 0 元开始。
- 末档不设上限。
- 档位必须连续，不得重叠或留空。
- 平台分成比例范围为 0%—100%。
- 后一档比例不得高于前一档。
- 生效账单月不得早于当前未锁定账单月。
- 已锁定或已确认账单不得重算。

### 3.4 示例

| 收入档位 | 平台分成比例 |
|---|---:|
| 0—1,000,000 元 | 30% |
| 超过 1,000,000—5,000,000 元部分 | 25% |
| 超过 5,000,000 元部分 | 20% |

账单锁定时保存规则版本、各档计费金额、各档比例、各档平台分成与合计金额快照，供前后台复算。

## 4. 开发者端

### 4.1 财务主体缺省态

企业认证处于申请中、驳回或未通过时，不展示财务主体编辑入口。

缺省文案：

> 开发者企业认证通过后，方可管理财务主体。

企业认证通过后，恢复财务主体查看、修改、附件预览与变更历史。

### 4.2 对账结算主表

主表保留账单月份、结算月份、游戏、结算项、用户实付、平台实收、平台分成比例、平台分成、应结算金额、状态与操作。

“游戏销售分成”与“CDKEY 销售分成”提供“查看详情”；“退款与拒付”不增加无必要的详情入口。

### 4.3 游戏销售分成详情

采用右侧半屏抽屉，不离开结算列表。字段：

- 商品类型：游戏本体或 DLC。
- 商品名称。
- 用户实付。
- 支付费。
- 税费。
- 退款与拒付。
- 平台实收。
- 适用档位。
- 平台分成比例。
- 平台分成。
- 结算金额。

抽屉顶部展示游戏、账单月、结算月及各金额合计。各明细合计必须与主表一致。

### 4.4 CDKEY 详情

字段：渠道、商品类型、商品或 DLC、用户实付、支付费、税费、退款与拒付、平台实收、平台分成、结算金额。

CDKEY 平台分成固定为 0%，支付费、税费、退款与拒付仍据实扣除。

## 5. 运营后台

### 5.1 主体汇总

按账单月份、开发者、财务主体、主体版本、账户版本汇总，数据由结算快照生成，不再读取独立旧账本。

字段顺序：

1. 账单月份。
2. 开发者。
3. 财务主体。
4. 主体版本。
5. 账户版本。
6. 游戏及 DLC 销售金额。
7. CDKEY 销售金额。
8. 用户实付。
9. 平台实收。
10. 支付费。
11. 综合税率／税费。
12. 退款与拒付。
13. 平台分成比例。
14. 平台分成。
15. 应结算金额（CNY）。
16. 应结算金额（USD）。
17. 银行账户名。
18. 银行账号。
19. 开户行。

表格使用内部横向滚动；页面本身不得横向溢出。固定首列选择框、账单月份和开发者，便于宽表核对。

### 5.2 游戏明细

在现有结算字段上补充：

- 平台实收。
- 平台分成比例。
- 平台分成。

本体与 DLC 合并为“游戏销售分成”，详情结构与开发者端一致；CDKEY 详情同步开发者端渠道与商品字段。

### 5.3 导出

- 仅导出开发者已确认的结算记录。
- 支持导出筛选结果或选中的已确认记录。
- CSV 包含结算单 ID、开发者、财务主体、主体版本、账户版本、规则版本及页面全部金额字段。
- 待确认记录不进入线下打款名单。
- 不在页面维护线上打款状态或凭证。

## 6. 数据与状态

### 6.1 快照

结算单锁定时保存：

- 财务主体版本。
- 银行账户版本。
- 分成规则版本。
- 结算项明细。
- 各档计费金额与比例。
- 支付费、税费、退款、拒付。
- 汇率版本。
- CNY 与 USD 结算金额。

### 6.2 状态

- 待确认：开发者可核对并确认，运营可查看，不得导出打款。
- 已确认：开发者不可撤销，运营可导出线下打款名单。

### 6.3 退款跨月

账单锁定后发生的退款或拒付进入后续账单月，以新结算记录冲减，不回写已确认账单。

## 7. 异常与边界

- 可分成净额为 0：平台分成比例展示“—”，平台分成为 0。
- 可分成净额为负：不计算负数平台分成，退款与拒付继续冲减应结算金额。
- 汇率缺失：USD 金额展示“—”，该记录不得进入需要 USD 打款的导出结果。
- 阶梯规则缺失或断档：账单不得锁定，运营端显示配置错误。
- 明细合计与主表不一致：阻止确认与导出。
- 企业认证未通过：财务主体页面仅展示缺省态。

## 8. 验收重点

- 本体与 DLC 主表合并、详情可拆分且金额加总一致。
- 开发者端与运营端使用同一结算快照。
- 阶梯分成按分段累进计算，跨档结果可复算。
- 修改规则不影响已锁定或已确认账单。
- 退款与拒付全额冲减，不误作平台分成 100%。
- 综合税率按金额加权，零基数展示“—”。
- 企业认证未通过时不提供财务主体管理入口。
- 主体汇总与游戏明细每页 20 条，筛选、缺省态、导出边界正确。
- 待确认记录不能导出线下打款名单。
