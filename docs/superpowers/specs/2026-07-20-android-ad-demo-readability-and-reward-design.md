# Android 广告 Demo 可读性与新增激励场景设计

> 日期：2026-07-20  
> 状态：用户已确认方案 A  
> 作用范围：`demos/Android广告接入-交互标注版.html`  
> 优先级：本文件覆盖 `2026-07-17-android-ad-demo-design.md` 中与 H1、S1、C1、Q1、L1 展示和交互冲突的旧描述。

## 1. 目标与范围

本轮解决现有 Demo 中“页面内容被裁切、难以阅读”和若干已确认交互未体现的问题，并新增“看广告获得抽奖次数”场景。仍保持单文件 Demo、用户端与运营后台双页面切换、国内与海外独立配置，不接入真实广告 SDK。

本轮改动包括：

1. H1 首页第二屏广告恢复为正常可读的内容流卡片；
2. C1 签到结果弹层删除“完成”按钮，改为右上角关闭按钮；
3. Q1 原“加速排队”按钮旁增加独立的“看广告领加速时长”入口；
4. L1 PC 启动等待广告改为 3 张静态广告图轮播；
5. S1 搜索广告使用卡片右上角的小型 `Ad` 标签；
6. 新增 R1 抽奖次数激励场景，在原任务列表中加入独立广告任务行。

搜索默认页热搜、游戏详情页和会员相关场景不在本轮增加广告。

## 2. 方案选择

### 2.1 页面可读性

采用“重构可读内容层”，不再把原始截图放大后硬裁切成第二屏内容。原截图只用于导航、色彩和页面结构参考；第二屏游戏卡片由 HTML/CSS 按设备画布重新排版。

- 竖屏：广告为一张全宽横向游戏卡，封面、标题、评分、类型和下载按钮均在一个手机画布内完整可读；
- 横屏：三列游戏卡网格，广告占一列，与自然卡等宽等高；
- 卡片内容不得超出设备边框，不得依赖横向滚动才能读完；
- 第二屏首屏至少完整露出广告卡和一张自然游戏卡的主要信息。

未选择“继续裁切截图”，原因是不同屏幕比例下仍会出现图像过大、文字不可读和交互热区错位。

### 2.2 抽奖广告入口

采用用户确认的方案 A：在“新人见面多重豪礼”的任务列表中增加独立任务行。

- 标题：`看广告得抽奖次数`；
- 副标题：`完整观看，抽奖次数 +1`；
- 按钮：`看广告`；
- 该任务不占用登录、游玩、组队等已有任务，也不伪装成已完成任务；
- 每日可领取次数、冷却时间、人群和地区由运营后台配置，Demo 不写死产品默认值。

## 3. 场景设计

### 3.1 H1 首页第二屏原生广告

**触发条件**

- 用户进入首页并滑动到第二屏；
- 命中地区、人群、实验、频控和填充规则。

**展示说明**

- 保留首页第一屏原始页面；第二屏使用重新排版的可读游戏内容流；
- 竖屏广告为全宽横向卡，横屏广告为三分之一宽游戏卡；
- 广告卡右上角使用与 S1 相同的小型深色 `Ad` 标签；
- 无填充时由同尺寸自然游戏卡补位。

**交互说明**

- 点击广告卡打开 Demo 内落地页；
- 关闭后恢复第二屏原滚动位置；
- 横竖屏切换后重新排版，但不改变本次是否命中广告。

### 3.2 S1 搜索结果原生广告

**展示说明**

- 首批位置继续固定为第 2、8、20 条，后续每 20 条随机 3 条；
- `Ad` 标签固定在广告卡右上角，采用深色半透明底、白字和细描边；
- 标签不得遮挡标题、封面或下载按钮，也不使用橙色高亮角标；
- 广告卡的字号、行高和信息密度与自然游戏结果一致。

### 3.3 C1 签到时长加倍

**触发条件**

- 用户点击原页面“签到”按钮，基础签到奖励成功到账。

**展示说明**

- 签到成功弹层右上角显示 `×`；
- 弹层保留“看广告再领 60 分钟”主按钮；
- 删除底部“完成”按钮；
- 广告奖励到账结果弹层同样只使用右上角 `×` 关闭。

**交互说明**

- 点击 `×` 只关闭结果弹层，基础奖励和已签到状态保持；
- 点击主按钮进入激励广告；完整观看后补发 60 分钟；
- 失败或提前关闭只回到签到结果，不回收基础奖励；
- 同一 `reward_id` 不重复发放。

### 3.4 Q1 排队加速激励

**触发条件**

- 用户处于免费通道排队，且命中运营配置的等待阈值和激励规则。

**展示说明**

- 保留原“加速排队”按钮及其原业务含义；
- 在其右侧增加同层级次按钮：`看广告领加速时长`；
- 两个按钮并排显示，不覆盖队列名次、预计等待时间和退出排队入口；
- 广告入口不伪装成原加速按钮，也不自动弹出。

**交互说明**

- 点击原“加速排队”只演示原业务提示，不触发广告；
- 点击“看广告领加速时长”打开权益确认层，确认后才播放广告；
- 完整观看后进入加速通道并增加 5 分钟云游时长；
- 取消、失败或提前关闭保持原排队位置且不发权益；
- 已排到或已退出时只发时长，不重新入队。

### 3.5 L1 PC 启动等待广告轮播

**触发条件**

- PC 游戏处于正常启动等待阶段；
- L1 命中投放规则，三张静态素材已完成预加载；
- 启动状态层可以正常显示。

**展示说明**

- 广告覆盖设备内容画布，但启动阶段、进度和错误状态层持续位于广告上方；
- 一个 L1 启动会话最多展示 3 张静态素材，每张 3 秒；
- 显示 `1/3`、`2/3`、`3/3` 轮播进度和当前素材剩余时间；
- 三张素材在视觉主题、标题和 CTA 上明确区分，文字必须达到可读对比度；
- 背景本身不可点击，只有 CTA 可打开落地页；保留“关闭广告”入口。

**交互与计时说明**

- 进入 L1 后立即显示第 1 张，3 秒后切第 2 张，再 3 秒切第 3 张；
- 第 3 张展示满 3 秒后自动结束广告并恢复当前启动阶段原画面，总展示最长 9 秒；
- 启动阶段从固件准备切到客户端启动时不重置轮播计时；
- 游戏提前启动完成、启动失败、用户关闭广告、无填充或状态层异常时立即停止计时并撤出广告；
- 离开 L1 页面时暂停 Demo 计时，重新进入同一未结束会话时从当前张继续，重置演示时从第 1 张重新开始。

**平台约束**

Demo 将三张图视为同一 L1 会话内已缓存的运营静态素材，不模拟每 3 秒重新请求一次穿山甲或 AdMob 广告。真实接入必须遵守 ADN 的最短展示、刷新、曝光和点击政策；不允许通过 3 秒自动请求刷新制造三次广告曝光。Demo 的收入统计按一次 L1 会话展示，素材切换只记录创意级浏览事件。

### 3.6 R1 抽奖次数激励

**触发条件**

- 用户进入“新人见面多重豪礼”任务页；
- 当前仍可获得抽奖次数；
- R1 命中地区、人群、实验、每日上限、冷却和广告填充规则。

**展示说明**

- 竖屏页面按用户提供截图重构标题栏、蓝紫任务容器、任务行和青色按钮；
- 在每日任务列表中加入独立任务行“看广告得抽奖次数”；
- 副标题显示“完整观看，抽奖次数 +1”，按钮显示“看广告”；
- 领取成功后按钮更新为“已领取”，同时显示当前抽奖次数增加结果；
- 不在首页重新增加已取消的“新人福利”入口，本场景只演示用户已经进入活动页后的广告任务。

**交互说明**

- 点击“看广告”直接进入激励广告，不再增加二次确认，因为按钮本身已明确说明广告行为和奖励；
- 完整观看并校验成功后抽奖次数 `+1`；
- 失败、无填充、提前关闭或校验失败不增加次数、不扣可领取次数；
- 重复奖励回调按 `reward_id` 幂等处理；
- 达到运营配置上限后按钮禁用并显示“今日已达上限”。

## 4. 状态与后台配置

Demo 新增或调整以下状态：

- `c1.closed`：签到结果弹层是否关闭；
- `q1.offerOpen`、`q1.awarded`：排队广告确认和权益状态；
- `l1.slideIndex`、`l1.slideElapsed`、`l1.carouselEnded`：启动广告轮播状态；
- `r1.rewarded`、`r1.drawCount`、`r1.rewardId`：抽奖激励状态。

运营后台投放配置列表新增 R1，仍在现有单页列表中完成增删查改。R1 支持地区、用户范围、投放比例、每日上限、冷却和状态配置；L1 增加“最多素材数”和“单张展示秒数”展示字段，Demo 示例固定为最多 3 张、每张 3 秒，但正式值由运营和 ADN 合规约束共同决定。

## 5. 异常与回退

- H1/S1 无填充时使用自然游戏内容补位，不留空白；
- C1 关闭弹层不重置签到，广告失败不影响基础奖励；
- Q1 广告入口不可用时隐藏新增按钮，原加速排队功能正常；
- L1 任意素材加载失败时跳过该素材；无可用素材时直接显示原启动画面；计时器在离页、重置、完成和失败时必须清理；
- R1 无填充或失败时保留原任务列表，显示轻提示，不增加抽奖次数；
- 所有激励奖励均以服务端模拟校验成功为唯一发放条件，前端按钮状态不能单独作为发奖依据。

## 6. 验收标准

1. H1 竖屏与横屏卡片均完整可读，不出现图像放大裁切导致的半张封面或文字不可见；
2. S1 第 2 条广告右上角显示小型 `Ad` 标签，且不遮挡标题和下载按钮；
3. C1 点击签到后只有右上角 `×` 和广告主按钮，不再出现“完成”；关闭后不能重复签到；
4. Q1 同时展示“加速排队”和“看广告领加速时长”两个按钮，只有后者触发广告；
5. L1 自动按 3 秒切换 3 张素材，第 9 秒后恢复启动画面，阶段切换不重置轮播；
6. L1 提前完成、失败、离页或手动关闭后不存在继续运行的轮播计时器；
7. R1 任务行完整观看后抽奖次数只增加 1 次，失败和重复回调不会增加；
8. R1 出现在国内和海外投放配置列表中，可被独立编辑、删除和纳入 A/B 测试；
9. 用户端其他场景和运营后台原有三页仍可正常切换和操作；
10. 单文件 HTML 无外部运行依赖，内嵌 JavaScript 语法检查和浏览器交互回归通过。
