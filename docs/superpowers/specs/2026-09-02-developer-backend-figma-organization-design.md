# 开发者后台一期 Figma 文件组织重整规格

## 1. 结论与目标

将现有 Figma 文件「盖世游戏｜开发者后台一期」从单根长画板，重整为人工稿「GH-竖版6.0.1&后续更新」的文件组织方式：**按业务域拆分 Figma Page、每个业务 Page 使用青绿色中文标题条、页面按用户任务横向阅读、图层使用中文业务名称**。

本次是设计文件治理，不是产品需求迭代。37 个一期页面的路由、角色、业务字段、状态、交互、尺寸与 Demo 均不得变化。

## 4. 画板与图层规范

### 4.1 业务 Page

- Page 顶部建立独立的青绿色标题条，显示「模块编号 + 中文业务域名 + 页面数」；它位于业务 Frame 之外，不改变任何 `1440 × 900` 画板尺寸。
- 同一流程的业务 Frame 沿 X 轴从左至右排布；相邻流程之间使用留白和简短流程标签区分，不增加业务文案或交互。
- Frame 名统一为 `Pxx-xx｜中文页面标题`，例如 `P03-03｜包体上传页`。内部图层使用中文业务名；稳定 ID `Pxx-xx`、路由和角色元数据必须保留。
- 每个 Frame 保留现有独立文字、矢量和组件图层；禁止以整页截图替代可编辑结构。

### 4.2 组件母版

仅整理已有、跨页面复用的组件，不为凑“组件库”虚构新组件。包含：

- 基础骨架：应用框架、顶部栏、侧边导航、上下文栏、页面标题区；
- 输入与操作：按钮、输入框、下拉选择、上传、分页、标签页；
- 数据与流程：表格、步骤条、审核面板、时间线、指标卡、图表；
- 状态：状态标签、空状态、异常状态、无权限状态。

组件与状态均使用中文名称；仍维持现有深色导航壳、浅色工作区与品牌青 `#2FD7EF` 的既有设计 Token。标题条是 Figma 文件导航元素，不进入业务产品 UI。

### 4.3 历史处理

- 原正式根 Frame `gamehub-developer-backend-phase1`（历史 Node `1:3446`）移至 `废弃／历史`，作为迁移前定位信息；它不再作为正式验收锚点。
- 四个云端诊断备份 `ceRvGbsYvEIUnwVPXuVe8z`、`27DE2A31i7Qk2wWitmFXz2`、`rcDeX7c0fvx1dXAnyRGEBi`、`onsx8OyE9f4DFpyni3J4Yc` 保持不删除。
- 本次不执行删除 Figma Page、Frame、文件或云端备份的操作。

## 5. 不变契约与验证

重整后使用下列契约验收，而非旧根 Frame 的 Node ID：

1. `frame-map.json` 中 `P01-01` 至 `P04-09` 全部存在且唯一，共 37 个；模块页数仍为 `9 / 6 / 13 / 9`。
2. 每个 Frame 名称、角色、路由、模板标识、Demo 关键内容与 `1440 × 900` 尺寸保持一致。
3. 每个业务 Page 有一条中文青绿色标题条；业务画板按编号和用户任务从左至右可读。
4. 组件母版只包含跨页复用项；无新增产品功能、字段、页面、弹窗、Toast 或流程。
5. 重建各业务 Page 的画布截图、关键页截图、文字/矢量可编辑图层证据和证据清单哈希。
6. 重新运行既有 Demo 构建、23 条自动测试、37 条路由截图、Figma SVG 结构校验和校验器测试；任何业务回归均阻断交付。

## 6. 非本次范围
