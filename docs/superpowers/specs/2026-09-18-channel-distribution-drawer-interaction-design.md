# 渠道分销抽屉交互设计

## 目标

统一渠道与批次管理的操作层级，避免创建、编辑、查看在居中弹窗和侧边抽屉之间切换。

## 交互规则

### 使用右侧抽屉

- 渠道：创建、编辑、查看。
- 批次：创建、编辑、查看。
- API 接入信息、下载记录。

抽屉从右侧进入，覆盖当前页面但保留列表上下文。桌面端使用固定宽度；手机端占满屏幕。标题和关闭按钮固定在顶部，表单或详情内容独立滚动；创建、编辑操作的取消与提交按钮固定在底部。

### 使用居中确认弹窗

- 删除渠道或批次。
- 停用渠道或批次。
- 轮换 API Secret。

确认弹窗只展示对象名称、影响说明和确认操作，不承载长表单或详情内容。

## 页面表现

- 创建与编辑抽屉沿用现有字段、校验、时间选择组件和提交逻辑，不新增步骤。
- 查看抽屉沿用现有详情字段，只调整承载容器。
- 表单抽屉宽度不超过 760px；详情抽屉可按相同宽度展示。
- 抽屉关闭方式：右上角关闭、遮罩点击、取消按钮；关闭后回到原列表位置。
- 打开抽屉时锁定页面背景滚动，抽屉内容可滚动。

## 状态与异常

- 提交校验失败时保持抽屉打开，并在原字段下展示错误。
- 创建或编辑成功后关闭抽屉并刷新当前列表。
- 删除、停用等二次确认完成后关闭确认弹窗并刷新列表。
- 手机端不显示居中表单弹窗，抽屉始终铺满可视区域。

## 验收

1. 渠道和批次的创建、编辑、查看均从右侧打开。
2. API 接入和下载记录仍从右侧打开。
3. 删除、停用、Secret 轮换仍为居中确认弹窗。
4. 抽屉标题、内容和底部操作区在长内容下均可正常使用。
5. 320px、390px、1280px、1440px 宽度下无根节点横向溢出。
6. 原增删查改、启停、下载和 API 交互回归通过。
