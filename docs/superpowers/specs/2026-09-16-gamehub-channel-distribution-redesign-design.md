# 盖世游戏渠道分销重构设计

> 状态：已确认
> 日期：2026-09-16
> 适用产物：`13-开发者平台与渠道分销demo.html`
> 替代：`2026-09-16-gamehub-channel-dual-delivery-design.md` 中“API 按批次分配和人工补量”的设计

## 1. 目标

企业开发者为第三方渠道提供盖世 Key，并按渠道和销售项查看销量、销售额和预估收益。

本轮解决：

- 渠道如何持续取 Key，不反复建批次或换凭证。
- 文件交付如何真实下载并留痕。
- 停止合作时如何处理未发、已发未兑、已售未兑、已兑、退款和拒付。
- 渠道数据和收益如何对齐现有财务口径，不把回传数据写成平台正式结算。
- 如何删除审批、固定额度、地区和重复教程。

## 2. 当前前提

- 企业认证通过后默认开放渠道分销。
- 渠道由开发者自定义命名，不是平台注册账号。
- 平台不代第三方渠道收款、开票或打款。
- 渠道销售金额来自 API 回传或开发者导入的渠道账单。
- 渠道不设地区属性，本期不按地区限制供货或统计。

## 3. 被放弃的方案

| 方案 | 问题 | 结论 |
|---|---|---|
| API 凭证绑批次 | 每批用完都需重新接入，凭证和批次数量失控 | 不用 |
| 渠道凭证不变，开发者人工补 API 库存 | 可实现，但把平台内部库存管理转给开发者 | 不用 |
| 渠道级凭证＋API 按订单自动发码＋文件按批下载 | API 不会用尽，文件仍可按量交付和审计 | 采用 |

## 4. 核心对象

| 对象 | 用途 |
|---|---|
| Channel | 系统渠道编号、自定义名称、供货方式、合作状态。改名不改历史归属。 |
| ChannelProductGrant | 渠道可销售的游戏、本体或 DLC、SKU。 |
| ChannelCredential | API 渠道凭证、版本、状态、最后使用时间。 |
| FileBatch | 文件模式的生成数量、SKU、有效期、生成和下载状态。 |
| Key | 所属 SKU、渠道或文件批次、暴露和兑换状态。界面及日志不展示明文。 |
| Delivery | 渠道订单、幂等键、Key 和发放结果的映射。 |
| SaleEvent | 销售、退款、拒付的订单、SKU、数量、金额和币种。 |
| FileExport | 文件哈希、下载账号、时间、次数和结果。 |
| AuditLog | 渠道、凭证、文件、合作状态和数据导入的操作记录。 |

## 5. 信息架构

原“渠道分销、Key 批次、渠道数据、收益与结算”四个入口合并为两个：

### 5.1 渠道与供货

包含：

- 创建渠道。
- 配置本体和 DLC 销售项。
- 选择“接口自动发码”或“下载兑换码文件”。
- 配置和轮换 API 凭证。
- 创建、下载文件批次并查看下载记录。
- 暂停供货、恢复供货、停止合作和查看清算状态。

渠道列表字段：

- 渠道名称、渠道编号。
- 销售项。
- 供货方式。
- 合作状态。
- 已发放、已售、已兑换。
- 最近供货时间。
- 管理供货、暂停或停止合作。

### 5.2 销售与收益

顶部汇总：

- 销售量。
- 退款量。
- 拒付量。
- 渠道回传销售额。
- 预估收益。

列表按“渠道＋销售项＋SKU＋币种”归类，展示：

- 渠道名称。
- 本体或 DLC。
- 商品名称和 SKU。
- 销售量、退款量和拒付量。
- 销售额、销售净额和预估收益。
- 数据状态和最近更新时间。

不同币种分行展示，不直接相加。页面复用现有财务汇总样式，但不使用“应结算”“正式账单”或“已打款”等平台结算语义。

## 6. 接口自动发码

- 不填数量，不显示固定额度、剩余额度或补量操作。
- 渠道合作中、SKU 有效且未触发风险限制时，每个已支付订单自动发一个 Key。
- 请求包含渠道订单号、SKU、幂等键、支付时间、金额和币种。
- `channel_id + channel_order_id` 唯一。同订单重试返回原 Key；同键异参返回冲突。
- 发码后响应超时时，渠道先查询原订单，不创建新订单号。
- 一次性 Secret 只在创建或轮换时显示；后续不能找回原值。
- 凭证属于渠道，不属于文件批次或单个 SKU。
- 后端可使用内部库存池、频控和风险阈值，但开发者不管理这些技术对象。

## 7. 下载兑换码文件

- 开发者填写数量和有效期，直接生成，不进入人工审批。
- 产品不固定“1,000”或其他商业额度。后端可下发当前技术上限，超限时返回当前可用上限。
- 大批量允许异步生成，只展示“生成中”、“待下载”或“生成失败”。
- Demo 点击下载后必须生成真实可下载文件，文件内为运行时随机生成的演示 Key，HTML 不固化写入 Key。
- 下载成功后记录文件名、下载账号、首次时间、最近时间和下载次数。
- 已下载 Key 计为已暴露，不得回库或重复分配。
- 已生成但未下载的文件可取消。

## 8. Key 与交易状态

Key 和交易状态分开：

- Key：未暴露 → 已发放／已导出 → 已兑换。
- 交易：已售 → 已退款或已拒付。

规则：

- 已暴露 Key 不得回库或再次销售。
- 已售未兑 Key 在原有效期内保持有效。
- 退款或拒付不改变 Key 唯一性，不能把该 Key 重新销售。
- 未兑后退款可阻止后续兑换，但 Key 进入作废而非回库。
- 已兑后退款或拒付按平台统一退款和权益政策处理，本模块只记录事实。

## 9. 停止合作和清算

渠道状态：合作中、已暂停、清算中、已停止、风险暂停。

正常停止合作：

1. 开发者二次确认后，渠道立即进入“清算中”。
2. 立即禁止 API 新发码、新文件批次和未下载文件下载。
3. API 清算期只保留原订单查询、交付确认、销售、退款和拒付回传。
4. 未下载文件批次取消；已下载批次不自动作废、不回库。
5. 已售未兑和已兑 Key 继续按原规则生效。
6. 清算期默认 30 个自然日，用于补报销售、退款和拒付。
7. 清算期结束后渠道转为“已停止”，历史数据只读保留。
8. 已锁定月份的迟到退款和拒付进入后续月份调整。

文件模式已下载但未报售的 Key 无法在系统内自动判定“未售”。停止合作只记录开发者和渠道的停售义务，不批量作废已暴露 Key。

安全事件与正常停止合作分开。平台可风险暂停凭证和发码；只对已证明涉及欺诈的未兑 Key 执行风险封禁，不允许开发者自助批量作废已暴露 Key。

## 10. 销售和收益口径

### 10.1 API 渠道

- 发码请求必须在订单支付成功后发起。
- 请求同步上报渠道订单号、SKU、销售金额、币种和支付时间。
- 退款和拒付使用原渠道订单号回传。

### 10.2 文件渠道

- 开发者导入渠道销售清单，至少包含渠道订单号、Key、SKU、金额、币种和销售时间。服务端校验 Key 归属后立即转为不可逆指纹，导入记录和页面不保存或回显明文 Key。
- 未导入销售清单时，只展示已下载和已兑换，不显示虚构的销量、销售额或收益。

### 10.3 计算

- 销售额：渠道回传的用户实付合计。
- 销售净额：销售额－退款－拒付－已明确税费。
- 预估收益：销售净额按已配置分成规则计算。
- 无分成规则时预估收益显示“—”，前端不自行假设。
- 月份锁定后发生的退款或拒付进入下个月份的历史调整。

## 11. 批次详情取舍

移除列表的通用“查看详情”。当前详情只重复列表和教程，没有新决策信息。

操作按真实目的展示：

- 待下载：下载文件。
- 已下载：查看下载记录。
- 生成失败：查看原因、重新生成。
- API：管理接入、轮换密钥、查看发码记录。
- 渠道异常：查看异常记录。

## 13. 状态

### 13.1 渠道

- 合作中。
- 已暂停，可恢复。
- 清算中。
- 已停止。
- 风险暂停，由平台处置。

### 13.2 API 接入

- 待生成凭证。
- 正常。
- 已暂停。
- 密钥待重置。
- 已停用。

### 13.3 文件批次

- 生成中。
- 待下载。
- 已下载。
- 已取消。
- 已到期。
- 生成失败。

不再出现“提交申请”、“审核中”、“已拒绝”、“授权计划”、“配额”和“剩余额度”。

## 14. 异常与恢复

- 发码超时：使用原订单号查询，不发新 Key。
- 重复订单异参：返回冲突，不改变原交付。
- 凭证泄露：暂停凭证、生成新 Secret，旧 Secret 失效。
- 文件生成失败：保留参数，允许重新生成。
- 文件下载中断：服务端未完整输出文件时不记下载成功；有效期内可重试。浏览器是否最终保存到本地无法检测，Demo 以浏览器成功发起下载并生成文件为完成标准。
- 销售未回传：标记“待补报”，不计算销售额和预估收益。
- 销售清单重复：按渠道订单号幂等导入，不重复计数。
- 停止合作与回传并发：保留停止时间前已成立的订单，终止时间后新发码失败。

## 15. 权限和审计

- 企业开发者管理员可创建渠道、下载文件、生成或轮换凭证、暂停供货和停止合作。
- 停止合作和轮换凭证须二次确认；下载明文 Key 文件校验权限并记录审计，不增加确认弹窗，也不进入人工审批。
- 平台运营可执行风险暂停，不能查看明文 Key 或 Secret。
- 审计记录至少包含操作账号、时间、IP、对象、前后值、请求号、结果和失败原因。

## 16. Demo 验收

1. 只保留“渠道与供货”“销售与收益”两个入口。
2. 可创建渠道，自定义名称，选择本体或 DLC 和一种供货方式；不显示地区、审批或额度。
3. API 渠道不填数量，可生成一次性 Secret、复制凭证、轮换密钥、暂停和恢复供货。
4. 业务页不再展示完整接口文档，“查看接入教程”打开帮助中心的 API 文章。
5. 文件渠道可填数量和有效期，生成文件并触发浏览器真实下载；成功后回显下载记录。
6. 通用“查看详情”移除，操作按状态显示真实目的。
7. 停止合作弹窗回显 API 已发未兑、文件已暴露、已售未兑、已兑、待补报和待调整数量，确认后进入清算中。
8. 销售与收益按渠道、本体／DLC、SKU 和币种展示销量、退款、拒付、销售额、净额和预估收益，不显示地区。
9. 文件渠道可导入销售清单；未导入时不显示虚构的销售额。
10. 帮助中心新增“发行与供给”目录及 8 篇可搜索文章。
11. 320px、390px、1280px 和 1440px 无根节点溢出；列表在内容区滚动。
12. 静态 HTML 不包含固定明文 Key、固定 Secret、外部脚本或 iframe。

## 17. 明确不做

- 渠道账号、渠道自助后台。
- 平台与渠道的线上签约。
- 平台代收渠道货款、正式渠道结算、开票和打款。
- 文件 Key 售出前的二次接口激活。
- 自动库存预警或开发者可见的 API 库存池。
- 地区限制、买家国家分析或跨币种汇总。
- 线上对账争议或申诉工单。

## 18. 风险边界

- 文件一旦下载，平台无法证明渠道已删除未售 Key；只能通过不回库、不复用、停售义务和异常追踪控制。
- 无渠道账号和收款关系时，渠道销售和收益只是回传口径，不是平台财务结算凭证。
- API 无开发者可见额度，但服务端仍须有频控、唯一约束、异常暂停和对账任务，防止凭证泄露后无限发码。
