# 发行人计划投稿要求与自动校验设计

## 1. 结论

任务详情和“提交投稿”页统一展示完整投稿要求，系统获取外站作品内容后执行同源校验：

- 展示发布者配置的原任务投稿要求。
- 必须带 `#{实际推广游戏名称}` 话题，不展示花括号占位符。
- 必须带 `#盖世游戏` 话题。
- 投稿发布时间不得早于任务提交时间，并展示该任务的具体提交时间。
- 缺少任一必带话题或发布时间过早时，投稿不进入待人工结算，不预留任务奖励。

## 2. 页面与数据

“提交投稿”页在投稿平台与视频链接之间新增“投稿要求”卡片；任务详情复用同一要求生成方法，避免两页口径不一致。

任务保存 `submittedAt`，外站取数保存 `publishedAt` 和标准化话题数组 `tags`。校验使用话题精确匹配和统一时间口径，不依赖用户输入的链接文本判断。

## 3. 状态与异常

| 场景 | 处理 |
|---|---|
| 内容与数据完整，两个话题齐全，发布时间合法 | 继续平台、重复、风险和预算校验；全部通过后进入待人工结算。 |
| 缺少游戏话题或 `#盖世游戏` | 提示缺失话题；不进入待人工结算，不预留预算。 |
| 发布时间早于任务提交时间 | 提示时间不符合；不进入待人工结算，不预留预算。 |
| 话题或发布时间未能完整取得 | 沿用数据缺失异常分流，不按正常投稿通过。 |

## 4. 三视角审查

- 用户视角：发布作品前即可看到完整要求和具体时间下限，避免提交后才知道不合格。
- 开发视角：任务提交时间、作品发布时间和话题数组均使用结构化字段，页面展示与服务端校验复用同一规则。
- 商业视角：两个话题保证游戏与盖世品牌曝光；时间下限阻止旧内容重复参与新任务。

## 5. 验收

1. “提交投稿”页显示原任务要求、实际游戏话题、`#盖世游戏` 和具体任务提交时间。
2. 任务详情显示相同要求。
3. 正常作品可进入待人工结算，并保存话题和发布时间。
4. 缺少话题或发布时间过早时，投稿数、预留预算和待结算记录均不增加。
