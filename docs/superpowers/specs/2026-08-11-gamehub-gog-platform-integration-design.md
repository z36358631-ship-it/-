# 盖世游戏 GOG 平台接入最终返修设计

## 1. 结论

`GUANWANGGAID-26` 最终采用“基于现有页面的完整 GOG 游戏链路”方案：保留已按真实页面还原的我的页、游戏库、搜索和游戏详情结构，在现有 Steam、EPIC 能力体系中完整加入 GOG。

最终范围包括：GOG 账号绑定与账号库；横竖搜索中的 EPIC/GOG 平台版本分条；游戏库中的 EPIC/GOG 入口、账号状态和游戏列表；详情中的平台选择、EPIC/GOG 游戏时长、云存档、启动入口；入口来源优先、无来源时 `Steam > EPIC > GOG`；以及基于中英文名称和别名的游戏归类。

我的页账号卡同时收拢操作：`更新数据 / 切换账号 / 退出账号` 统一折叠到右上角 `…` 菜单；原三按钮区域仅 EPIC 显示一个“喜加一”按钮，GOG 不显示“喜加一”与账号价值，卡片自然收缩。横竖版必须分别适配，不能通过整体缩放或旋转生成。

此前“GOG 只做平台标识、不提供详情启动链路”的收缩口径已由用户明确作废。

## 2. 用户问题与现状

### 2.1 要解决的问题

GOG 用户目前无法在盖世游戏内形成从绑定账号、浏览游戏库、搜索平台版本、查看平台数据到按来源启动的完整链路。已有页面和第一轮 Demo 已分别具备部分结构，但账号卡操作密度、横竖视觉基线、平台路由和游戏归类规则必须统一，才能供产品、设计、开发和测试评审。

### 2.2 用户现有方式

- 我的页已有 Steam、EPIC 等平台账号卡及账号管理操作。
- EPIC 账号卡存在平台专属的“喜加一”入口。
- 游戏库已有平台入口、绑定引导和账号游戏列表。
- 搜索结果可按平台版本展示，用户需要看清同一游戏的不同平台来源。
- 游戏详情已有 PC 游戏引擎、平台数据、启动入口和切换启动方式的交互基础。
- GOG 用户仍需通过 GOG Galaxy 或 GOG 网站管理资产，盖世游戏内缺少统一链路。

### 2.3 可借鉴点与规避项

本期复用 Steam、EPIC 已有的平台账号、搜索、详情和启动心智，降低 GOG 的学习成本。应规避以下问题：把 GOG 不具备的账号价值伪装为 `0`；把同名但无法确认关系的游戏错误合并；从 GOG 入口进入却静默切换成 Steam；或为 GOG 重新设计一套脱离现行产品的页面。

## 3. 设计原则

1. 先还原、后增量：现行页面结构、尺寸和交互优先，GOG 自然融入。
2. 完整链路：账号、游戏库、搜索、详情、平台切换和启动口径保持连贯。
3. 来源明确：明确入口来源优先；无来源才按 `Steam > EPIC > GOG`。
4. 归类谨慎：中英文名称与别名只用于生成候选关系，无法可靠归类时保持不同详情。
5. 平台能力不混用：只有 EPIC 显示“喜加一”；GOG 不显示账号价值和“喜加一”。
6. 低频操作折叠：更新、切换和退出进入 `…` 菜单，减少账号卡常驻按钮。
7. 横竖独立布局：竖屏 `402 × 874`，横屏 `874 × 402`，共享状态但独立排布。
8. 禁止自由发挥：不新增需求外页面、弹窗、Toast、入口和流程。

## 4. 设计依据与优先级

视觉和行为依据按以下优先级使用：

1. 用户于 2026-08-13 确认的完整 GOG 范围与账号卡调整。
2. 用户于 2026-08-11 提供的新版游戏库截图。

5. 已实现的 GOG Demo 只用于复用业务状态和交互，不覆盖更高优先级的最终口径。

## 5. 方案选择

| 方案 | 说明 | 优点 | 代价 |
|---|---|---|---|
| A. 完整 GOG 游戏链路 | 账号、游戏库、搜索分条、详情数据、平台切换和启动统一接入 | 完整覆盖最终需求，入口和结果一致 | 依赖 GOG 官方接口与启动能力验证 |
| B. 最小平台识别 | 搜索、游戏库和“获得游戏”只加 GOG 标识 | 改动小 | 无法覆盖本次明确要求的详情和启动能力 |
| C. 独立 GOG 详情 | 为 GOG 新建专属详情流程 | 平台隔离明显 | 偏离现有产品，重复页面和逻辑 |

已确认采用方案 A。方案 B 的收缩口径作废；方案 C 不符合“在现有页面基础上修改”的原则。

## 6. 三视角快速评审

- 用户视角：从哪个平台版本进入就看到并启动哪个平台，符合用户预期；同一游戏的不同平台版本在搜索中分开，不会混淆来源。
- 开发视角：统一 `gameId`、`platformAppId`、`sourcePlatform` 和 `selectedPlatform` 可支撑完整链路；游戏归类和平台不可用恢复需要严格边界，避免错误启动。
- 商业视角：完整能力可形成 GOG 使用闭环，但官方授权、库字段、云存档和启动能力必须在开发前验证，未验证字段不能当作生产承诺。

三个视角无方案级硬伤。主要风险已纳入接口前置验证、低置信度不合并、来源不可用不静默回退和启动失败恢复。

## 7. 交付架构

### 7.1 三栏标注壳

- 左侧：页面导航、方向切换和必要的状态模拟入口。
- 中间：真实 APP 页面，竖屏目标视口 `402 × 874`，横屏目标视口 `874 × 402`。
- 右侧：当前页面的交互说明、全局规则、异常与边界。
- 收起右侧面板时，中间区域可扩展，但 APP 目标视口和页面比例不变。

### 7.2 中间 APP 分层

1. `PortraitLayout`：竖屏页面结构与组件排布。
2. `LandscapeLayout`：横屏页面结构与组件排布。
3. `PlatformAccountState`：Steam、EPIC、GOG 独立账号、授权与同步状态。
4. `GamePlatformMapping`：统一游戏、平台版本、中英文名称、别名和映射置信度。
5. `SourceContext`：入口来源、当前选择平台和用户拥有的平台集合。
6. `InteractionController`：绑定、同步、账号菜单、搜索、详情、平台切换、启动、重试和返回事件。

横竖布局只负责表现，不各自复制账号、平台路由、启动和异常逻辑。

### 7.3 平台能力模型

账号卡区分平台专属能力：

```js
const PLATFORM_CAPABILITIES = {
  epic: {
    supportsAccountValue: true,
    supportsFreeGames: true
  },
  gog: {
    supportsAccountValue: false,
    supportsFreeGames: false
  }
};
```

GOG 的 `accountValue` 不进入渲染数据；任何 GOG 页面、骨架、空态和标注中都不显示“账号价值”、估值数值或对应占位空间。`supportsFreeGames: false` 时账号卡不渲染按钮容器，卡片高度随内容自然收缩。

### 7.4 游戏与平台数据模型

```js
const gamePlatformVersion = {
  gameId: 'cyberpunk-2077',
  platform: 'gog',
  platformAppId: 'gog-1423049311',
  sourcePlatform: 'gog',
  localizedNames: ['赛博朋克 2077', 'Cyberpunk 2077'],
  aliases: [],
  playtime: '74 小时',
  cloudSaveStatus: '云存档已同步',
  launchLabel: 'GOG 启动'
};
```

- `gameId` 表示盖世游戏内确认归为同一游戏的统一标识。
- `platform + platformAppId` 唯一定位一个平台版本。
- `sourcePlatform` 表示进入详情的明确平台来源。
- `selectedPlatform` 表示详情当前展示和启动的平台。
- 中英文名称和别名用于生成归类候选；低置信度候选不得自动共用 `gameId`。

## 8. 页面结构与交互

### 8.1 页面视图清单

1. 我的页：平台账号卡及 `…` 菜单。
2. GOG 官方登录/授权页。
3. 游戏库首页：竖屏。
4. 游戏库首页：横屏。
5. GOG 账号游戏库：竖屏。
6. GOG 账号游戏库：横屏。
7. 搜索结果：竖屏。
8. 搜索结果：横屏。
9. 游戏详情：竖屏。
10. 游戏详情：横屏。

未绑定、加载、空数据、失败、授权过期、取消和缓存降级作为对应页面的可切换状态，不为同一视觉页面重复建立导航项。

### 8.2 我的页账号卡

按 `30-我的.png` 还原现行页面，在既有平台区域增加 GOG，并允许在同一账号区切换 Steam、EPIC、GOG 以评审平台差异。

- 右上角使用 `…` 按钮；点击后在按钮下方展开菜单。
- 菜单从上到下为：`更新数据`、`切换账号`、`退出账号`。
- 点击菜单外部、切换平台或离开页面时关闭菜单。
- 更新进行中禁用“更新数据”，显示明确的进行中状态，避免重复点击。
- 切换账号沿用现有账号切换流程；切换失败保留旧账号与旧同步数据。
- 退出账号沿用现有二次确认；取消后保留当前账号，确认后仅清理当前平台账号。
- 保留最近同步时间或等价刷新反馈。
- EPIC 的原三按钮区域替换为一个“喜加一”按钮。
- GOG 不显示“喜加一”，也不保留空按钮栏、空白高度或占位分隔线。
- GOG 不显示账号价值；Steam、EPIC 的既有字段不因本期修改而改变。
- `…` 菜单在 `402px` 竖屏内不得被右侧或底部裁切。

### 8.3 游戏库首页

分别按用户提供的横竖首页截图重建。GOG 固定插入红框空位，顺序为：

`EPIC → GOG → 导入游戏`

- 不改变其他入口的尺寸、间距、名称和顺序。
- GOG 入口的圆角、图标尺寸、文字层级和点击区域沿用相邻 EPIC 入口。
- EPIC/GOG 未绑定时显示平台绑定引导；GOG 文案为“GOG 数据同步功能绑定账号，查看个人游戏库数据”。
- 点击 GOG 绑定按钮进入 GOG Galaxy 官方授权，不跳转 EPIC 授权页面。
- 已绑定时进入对应平台账号游戏库。

### 8.4 GOG 账号游戏库

分别参照 EPIC 账号库横竖截图还原，平台内容替换为 GOG。

- 账号区保留头像、用户名、GOG ID、游戏数、总时长和最近同步信息。
- 账号价值字段、分隔线、图标、骨架和占位全部移除，剩余内容自然重排。
- 游戏列表使用左右布局或对应方向的现有结构，显示封面、游戏名、GOG 标识和游戏时长。
- 点击游戏携带 `gameId`、`platformAppId`、`sourcePlatform=gog` 进入对应方向的现有游戏详情。
- 从 Steam、EPIC、GOG 游戏库进入时，分别携带对应 `sourcePlatform`，详情默认选择该平台。

### 8.5 搜索结果

竖屏按 `09-竖版搜索默认页.png`、横屏按 `43-掌机模式-搜索.png` 还原，新增 EPIC 和 GOG 平台版本展示。

- 同一个 PC 游戏存在多个平台时，每个平台版本展示为独立结果，不合并为一张搜索卡片。
- 每条结果显示平台标识，并携带 `gameId`、`platform`、`platformAppId`。
- 点击 EPIC 或 GOG 结果时，分别传递 `sourcePlatform=epic` 或 `sourcePlatform=gog` 进入对应方向的详情。
- EPIC 评分按现有换算规则展示；GOG 没有可用评分时显示“暂无评分”，不得复用 EPIC 评分。
- 横竖屏使用同一搜索数据、结果数量、分条规则和点击处理，只改变列表排布。

### 8.6 游戏详情

竖屏按 `10-竖版游戏详情.png`、横屏按 `44-掌机模式-游戏详情.png` 还原，在现有 PC 游戏引擎和启动方式中加入 EPIC/GOG。

- 详情卡片内显示当前启动平台 Tab 或同层级的平台入口。
- 点击当前平台 Tab 后弹出“切换启动平台”弹窗；弹窗仅展示用户拥有且具备有效平台版本的 Steam、EPIC、GOG。
- 用户选择平台后，`selectedPlatform` 更新为所选平台，弹窗关闭；取消或点击外部时保持原平台。
- 平台切换后同步更新平台标识、游戏时长、云存档状态和启动按钮/icon。
- 启动区增加 EPIC/GOG 启动 icon；点击后使用当前 `selectedPlatform` 对应的 `platformAppId` 和启动参数启动。
- 从 Steam、EPIC、GOG 游戏库或搜索结果进入时，以明确的 `sourcePlatform` 初始化 `selectedPlatform`。
- 入口没有 `sourcePlatform` 时，只在用户已拥有且账号可用的平台中按 `Steam > EPIC > GOG` 选择。
- 明确来源账号未绑定、授权失效或版本不可用时，保留该来源，提示绑定、重新登录或主动切换，不静默改用其他平台。
- 云存档字段无法获取时显示“未获取”，不得伪造“正常”；启动失败后保持当前详情和平台选择，提供现有重试或切换方式。
- “获得游戏”区域保留 Steam，并增加 EPIC/GOG 可获得平台标识；该区域的平台标识与启动平台是两个不同语义。

### 8.7 GOG 登录/授权

- 使用内置 WebView 打开 GOG 官方登录页。
- 邮箱、密码和“记住我”由 GOG 官方页面处理。
- 盖世游戏只接收授权结果，不读取或保存邮箱、密码。
- 授权成功后回到发起入口并同步 GOG 游戏库。
- 用户取消、网络失败或授权拒绝时回到原入口，不写入虚假绑定记录。

## 9. 平台路由与游戏归类

### 9.1 平台路由

1. 入口有明确 `sourcePlatform` 且该平台版本可用：`selectedPlatform` 使用来源平台。
2. 入口有明确 `sourcePlatform`，但账号未绑定、授权失效或版本不可用：保留来源平台并引导恢复或切换，不自动替换。
3. 入口没有 `sourcePlatform`：在用户已拥有且账号有效的平台中按 `Steam > EPIC > GOG` 选择。
4. 用户主动切换后，`selectedPlatform` 使用用户选择，直到离开详情或再次切换。
5. 横竖屏切换保留 `sourcePlatform`、`selectedPlatform`、当前游戏和账号状态。

### 9.2 游戏归类

1. 对英文名、中文名和维护的别名做大小写、空格、标点和版本后缀归一化，生成同一游戏候选。
2. 候选还需结合平台侧标识、发行信息或人工映射确认；名称相同不等于必然是同一游戏。
3. 确认归类后，各平台版本共用统一 `gameId`，并分别保留自己的 `platformAppId`。
4. 无法归类、存在同名歧义或置信度不足时，不合并 `gameId`，分别进入不同详情。
5. 搜索结果即使共用 `gameId`，仍按平台版本分条展示；详情基于统一 `gameId` 展示用户拥有的可切换平台。

## 10. 数据流与账号隔离

1. 用户从我的页或游戏库点击 GOG。
2. 系统检查 GOG 绑定状态；未绑定进入官方授权，已绑定展示账号或游戏库。
3. 授权成功后进行首次同步，成功后返回发起入口。
4. 同步数据按 `platform + platformAppId` 入库，并通过游戏归类规则关联统一 `gameId`。
5. 点击搜索结果或游戏库卡片时传递 `gameId`、`platformAppId` 和 `sourcePlatform`。
6. 详情根据平台路由初始化 `selectedPlatform`，读取该平台时长、云存档和启动参数。
7. 用户切换平台后只更新详情的当前平台数据；点击启动使用当前平台参数。
8. Steam、EPIC、GOG 分别维护授权令牌、账号、同步结果和缓存；任何 GOG 操作都不得改写其他平台。

## 11. 异常状态与恢复

| 场景 | 页面表现 | 恢复规则 |
|---|---|---|
| 更新进行中 | “更新数据”禁用并显示进行中状态 | 成功后更新时间；失败后恢复可点击并保留旧数据 |
| 切换账号失败 | 使用现有流程的错误状态 | 保留旧账号与旧同步数据，可再次发起切换 |
| 退出二次确认 | 使用现有确认流程 | 取消不变；确认后只清理当前平台账号与缓存 |
| 点击账号菜单外部 | 不新增提示 | 直接关闭菜单，不执行菜单项 |
| 授权失败或取消 | 返回发起入口 | 不产生虚假绑定记录，可再次绑定 |
| 同步为空或失败 | 使用现有账号库空态或失败态 | 可重新同步，其他平台数据不受影响 |
| 授权过期 | 提示重新登录当前来源平台 | 成功后回到原入口并恢复原平台上下文 |
| 来源平台不可用 | 保留来源并说明原因 | 重新绑定、重新登录或由用户主动切换 |
| 云存档字段缺失 | 显示“未获取” | 后续成功获取后更新，不伪造状态 |
| 启动失败 | 保持当前详情和平台 | 提供现有重试或平台切换，不清空详情 |
| 平台切换取消 | 关闭弹窗 | `selectedPlatform` 与详情数据保持不变 |
| 缓存降级 | 展示上次成功同步内容和时间 | 同步成功后替换缓存 |

## 12. 标注规则

- 数字：当前页面内的操作步骤。
- `G`：跨页面、跨方向共用的平台路由、游戏归类和账号隔离规则。
- `E1`、`E2`：异常与边界。
- 点击左侧页面时，中间页面和右侧说明同步切换。
- 点击标注项时高亮中间对应元素。
- 支持显示/隐藏标号、折叠/展开右侧面板。
- 所有可见按钮都有事件或明确禁用原因；平台标识与启动按钮必须具备不同的视觉和交互语义。

## 13. 视觉返修流程

### 13.1 基线保持

以已经完成的真实页面还原为基线，检查最终修改未改变页面纵向结构、导航、字体层级、卡片比例、封面、背景和滚动位置。

### 13.2 完整增量

在真实基线中增加账号卡菜单、GOG 账号库、搜索平台分条、详情平台 Tab、切换弹窗、时长、云存档和启动入口。新增内容复用相邻 EPIC 或 Steam 的视觉语言，不移动与 GOG 无关的页面区块。

### 13.3 禁止方式

- 禁止用截图作为最终页面背景。
- 禁止通过 CSS 整体旋转或缩放生成另一方向。
- 禁止为了塞入 GOG 而压缩、删除或重排无关内容。
- 禁止把“获得游戏”平台标识做成启动按钮。
- 禁止因名称相似而直接合并无法确认的游戏。
- 禁止来源不可用时静默改用其他平台启动。

## 14. 验收标准

### 14.1 视觉

- 竖屏在 `402 × 874`、横屏在 `874 × 402` 目标视口分别截图对照。
- 游戏库以用户提供的 4 张新版截图为基准；我的页、搜索和详情以列出的 V6.1.1 截图为基准。
- EPIC 账号卡只显示一个“喜加一”按钮；GOG 卡片没有按钮栏和残留空白。
- `…` 菜单位置、宽度、层级和点击区与参考图一致，竖屏不裁切。
- 搜索、游戏库和详情中的 GOG 标识与相邻平台标识同层级、同风格。
- 详情平台 Tab、切换弹窗、时长、云存档和启动 icon 在横竖版中无重叠、截断或错位。

### 14.2 产品与交互

- `更新数据 / 切换账号 / 退出账号` 只出现在账号卡 `…` 菜单中，不再常驻直出。
- 菜单支持外部点击关闭；更新中禁止重复点击；切换失败保留旧账号；退出必须二次确认。
- 只有 EPIC 显示“喜加一”，GOG 不显示账号价值和“喜加一”。
- 游戏库入口顺序为 `EPIC → GOG → 导入游戏`，GOG 未绑定与已绑定链路可操作。
- GOG 账号库横竖版显示封面、名称、GOG 标识和游戏时长。
- 横竖搜索均包含 EPIC/GOG；同一游戏的不同平台版本分条展示。
- 搜索或游戏库进入详情时，默认平台与入口 `sourcePlatform` 一致。
- 无来源时按 `Steam > EPIC > GOG` 选择可用平台。
- 切换平台后，标识、时长、云存档和启动按钮/icon 同步更新。
- 点击启动使用当前平台版本；来源不可用时不静默切换。
- 中英文名称和别名可形成同一游戏候选；无法可靠归类时进入不同详情。
- 横竖切换保留账号、搜索条件、当前游戏、来源平台和当前选择平台。

### 14.3 技术与回归

- JavaScript 语法检查通过，浏览器无 `pageerror`。
- 页面导航、标注联动、标号显隐、面板折叠、方向切换、账号菜单和状态模拟通过 Smoke Test。
- 自动化覆盖搜索分条、来源优先级、无来源平台优先级、平台切换同步、启动参数选择和低置信度不归类。
- 所有按钮均有事件映射；启动按钮不得仅为空操作。
- 现有 EPIC 原 Demo 不被覆盖或修改，SHA-256 仍为 `514577A7B777D516A683CE3610DD7C0894C5E60F9093AB780BDDE226ADC91B1C`。
- 自动截图覆盖我的页菜单、EPIC“喜加一”、GOG 自然收缩、横竖游戏库、横竖搜索、横竖详情和平台切换弹窗。

## 15. 安全、前置条件与风险

1. 正式开发前必须确认 GOG 官方授权、游戏库字段、游戏时长、云存档、令牌刷新、退出和启动能力；不得以采集用户密码替代官方授权。
2. 未经官方接口确认的字段只能作为 Demo 数据，不能被 PRD 表述为已获得生产能力。
3. 游戏错误归类可能导致错误平台数据或错误启动；低置信度必须保持不同详情。
4. 启动服务必须校验当前账号、`selectedPlatform`、`platformAppId` 和拥有关系，不能只依赖客户端传参。
5. GOG 明确没有账号价值，本期不设计估值算法、占位值或降级文案。
6. 用户提供的账号卡和游戏库截图位于临时目录，项目内已有稳定参考资产继续用于自动截图复核；最终 Demo 不以内嵌截图代替真实 DOM。

## 16. 范围外

- GOG 账号价值和 GOG“喜加一”。
- 搜索结果把同一游戏的多个平台版本合并为单张卡片。
- 无法可靠归类时强制共用同一详情。
- 来源平台不可用时自动、无提示地改用其他平台。
- 全平台管理中心、B 端配置后台或与 GOG 接入无关的页面。
- 新增未确认的购买流程、页面、弹窗和 Toast。
