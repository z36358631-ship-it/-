# 盖世游戏 GOG 平台接入第二轮返修设计

## 1. 结论

`GUANWANGGAID-26` 第二轮返修采用“现有页面上的最小平台识别”方案：保留已按真实页面还原的我的页、游戏库、搜索和游戏详情结构，只在现有位置加入必要的 GOG 账号入口与平台标识，不再设计完整的 GOG 详情启动闭环。

本轮同时收拢我的页账号卡操作：`更新数据 / 切换账号 / 退出账号` 统一折叠到右上角 `…` 菜单；原三按钮区域仅 EPIC 显示一个“喜加一”按钮，GOG 不显示该按钮且卡片自然收缩。横竖版必须分别适配，不能通过整体缩放或旋转生成。

## 2. 用户问题与现状

### 2.1 要解决的问题

第一轮返修虽然完成了真实页面还原，但将 GOG 扩展成了包含详情时长、云存档、启动按钮、平台切换和来源路由的完整能力，超过本期实际范围；我的页账号卡又把三个低频管理操作长期直出，占用主操作区域。

本期真正要解决的是：用户能在现有账号与游戏浏览路径中识别 GOG，且能以更紧凑的方式管理已绑定平台账号。

### 2.2 用户现有方式

- 我的页已有 Steam、EPIC 等平台账号卡和管理操作。
- EPIC 账号卡存在平台专属的“喜加一”入口。
- 游戏详情的“获得游戏”区域已有 Steam 平台标识。
- 搜索结果与游戏库卡片已承担平台来源识别，不需要新增一套详情启动流程。

### 2.3 可借鉴点与规避项

本期复用 EPIC 的账号绑定和平台标识视觉语言，降低新增平台的理解成本。GOG 没有账号价值，也不具备本期承诺的购买或启动能力，因此不得用 `0`、占位文案或相似按钮制造能力已存在的误解。

## 3. 设计原则

1. 先还原、后增量：现行页面结构、尺寸和交互优先，GOG 只做自然融入。
2. 最小平台识别：搜索、游戏库和详情只增加 GOG 标识，不新增启动链路。
3. 平台能力不混用：只有 EPIC 显示“喜加一”；GOG 不显示账号价值和“喜加一”。
4. 低频操作折叠：更新、切换和退出进入 `…` 菜单，减少账号卡常驻按钮。
5. 横竖独立布局：竖屏 `402 × 874`，横屏 `874 × 402`，共享状态但独立排布。
6. 禁止自由发挥：不新增需求外页面、弹窗、Toast、入口和流程。

1. 用户于 2026-08-13 确认的第二轮范围与账号卡截图。

## 5. 方案选择

| 方案 | 说明 | 优点 | 代价 |
|---|---|---|---|
| A. 最小平台识别 | 账号入口保留，搜索、游戏库和“获得游戏”只加 GOG 标识 | 最符合本期范围，改动可控，不产生能力误解 | 暂不提供 GOG 购买或启动 |
| B. 完整详情启动 | 保留时长、云存档、启动和平台切换 | 演示链路完整 | 超出确认范围，依赖未验证的 GOG 能力 |
| C. 仅静态贴标 | 只画 GOG 图标，不处理账号菜单与交互状态 | 实现最少 | 无法评审账号管理和横竖适配 |

已确认采用方案 A，并完成我的页账号菜单的必要交互，不保留方案 B 的任何展示、路由或验收项。

## 6. 三视角快速评审

- 用户视角：平台标识出现在用户已有的浏览路径中，无需学习新详情操作；账号卡主操作区也更聚焦。
- 开发视角：删除 `sourcePlatform` 驱动启动和 `selectedPlatform` 切换后，状态更简单；需防止第一轮 Demo 的旧详情字段和标注残留。
- 商业视角：先验证 GOG 平台识别与账号接入价值，不提前承诺购买、云存档或启动能力，范围与投入匹配。

三个视角无硬伤。主要风险是旧实现残留，已通过负向静态检查、交互测试和 PRD 禁用词检查纳入验收。

## 7. 交付架构

### 7.1 三栏标注壳

- 左侧：页面导航、方向切换和必要的状态模拟入口。
- 中间：真实 APP 页面，竖屏目标视口 `402 × 874`，横屏目标视口 `874 × 402`。
- 右侧：当前页面的交互说明、全局规则、异常与边界。
- 收起右侧面板时，中间区域可扩展，但 APP 目标视口和页面比例不变。

### 7.2 中间 APP 分层

1. `PortraitLayout`：竖屏页面结构与组件排布。
2. `LandscapeLayout`：横屏页面结构与组件排布。
3. `PlatformAccountState`：Steam、EPIC、GOG 独立账号与同步状态。
4. `PlatformBadgeData`：搜索结果、游戏库卡片和“获得游戏”区域使用的平台标识数据。
5. `InteractionController`：绑定、同步、菜单、搜索、详情、重试和返回事件。

横竖布局只负责表现，不各自复制账号、菜单和异常逻辑。详情页不维护 GOG 启动来源或平台切换状态。

### 7.3 平台能力模型

账号卡至少区分以下平台能力：

```js
const PLATFORM_CAPABILITIES = {
  epic: {
    supportsAccountValue: true,
    supportsFreeGames: true
  },
  gog: {
    supportsAccountValue: false,
    supportsFreeGames: false
  }
};
```

GOG 的 `accountValue` 不进入渲染数据；任何 GOG 页面、骨架、空态和标注中都不显示“账号价值”、估值数值或对应占位空间。`supportsFreeGames: false` 时账号卡不渲染按钮容器，卡片高度随内容自然收缩。

平台标识数据只表达“该内容可从哪些平台获得或来源于哪个平台”，不表达平台账号已可购买、下载或启动。

## 8. 页面结构与交互

### 8.1 页面视图清单

1. 我的页：平台账号卡及 `…` 菜单。
2. GOG 官方登录/授权页。
3. 游戏库首页：竖屏。
4. 游戏库首页：横屏。
5. GOG 账号游戏库：竖屏。
6. GOG 账号游戏库：横屏。
7. 搜索结果：竖屏。
8. 搜索结果：横屏。
9. 游戏详情：竖屏。
10. 游戏详情：横屏。

未绑定、加载、空数据、失败、授权过期、取消和缓存降级作为对应页面的可切换状态，不为同一视觉页面重复建立导航项。

### 8.2 我的页账号卡

按 `30-我的.png` 还原现行页面，在既有平台区域增加 GOG，并允许在同一账号区切换 Steam、EPIC、GOG 以评审平台差异。

- 右上角使用 `…` 按钮；点击后在按钮下方展开菜单。
- 菜单从上到下为：`更新数据`、`切换账号`、`退出账号`。
- 点击菜单外部、切换平台或离开页面时关闭菜单。
- 更新进行中禁用“更新数据”，显示明确的进行中状态，避免重复点击。
- 切换账号沿用现有账号切换流程；切换失败保留旧账号与旧同步数据。
- 退出账号沿用现有二次确认；取消后保留当前账号，确认后仅清理当前平台账号。
- 保留最近同步时间或等价刷新反馈。
- EPIC 的原三按钮区域替换为一个“喜加一”按钮。
- GOG 不显示“喜加一”，也不保留空按钮栏、空白高度或占位分隔线。
- GOG 不显示账号价值；Steam、EPIC 的既有字段不因本期修改而改变。
- `…` 菜单在 `402px` 竖屏内不得被右侧或底部裁切。

### 8.3 游戏库首页

分别按用户提供的横竖首页截图重建。GOG 固定插入红框空位，顺序为：

`EPIC → GOG → 导入游戏`

- 不改变其他入口的尺寸、间距、名称和顺序。
- GOG 入口的圆角、图标尺寸、文字层级和点击区域沿用相邻 EPIC 入口。
- 未绑定时进入 GOG 官方授权；已绑定时进入 GOG 账号游戏库。

### 8.4 GOG 账号游戏库

分别参照 EPIC 账号库横竖截图还原，平台内容替换为 GOG。

- 账号区保留头像、用户名、GOG ID、游戏数、总时长和最近同步信息。
- 账号价值字段、分隔线、图标、骨架和占位全部移除，剩余内容自然重排。
- 游戏列表沿用现有封面、标题、排序和滚动行为。
- GOG 游戏卡显示 GOG 标识；标识位置、字号和间距沿用现有平台标识。
- 点击卡片进入现有游戏详情，只传递现有详情所需的游戏标识，不触发 GOG 启动或详情平台切换。

### 8.5 搜索结果

竖屏按 `09-竖版搜索默认页.png`、横屏按 `43-掌机模式-搜索.png` 还原，在现有结果卡片中增加 GOG 标识。

- 不改变现有搜索、排序、合并或点击规则。
- GOG 标识只表示结果的平台来源。
- 点击结果进入现有游戏详情，不以 GOG 来源改变详情启动能力。
- 横竖屏使用同一搜索数据，只改变列表排布。

### 8.6 游戏详情

竖屏按 `10-竖版游戏详情.png`、横屏按 `44-掌机模式-游戏详情.png` 还原。本期只修改现有“获得游戏”区域：在 Steam 标识旁增加 GOG 标识。

- GOG 与 Steam 使用同层级的平台标识样式。
- 标识只表达可获得平台，不提供点击购买、下载或启动事件。
- 不显示 GOG 游玩时长、云存档状态、启动按钮或平台切换。
- 从搜索或游戏库进入详情时，页面仍沿用现有详情数据和启动逻辑，不由 `sourcePlatform=gog` 改写。
- 不为 GOG 新增详情 Tab、弹窗、Toast 或降级流程。

### 8.7 GOG 登录/授权

- 使用内置 WebView 打开 GOG 官方登录页。
- 邮箱、密码和“记住我”由 GOG 官方页面处理。
- 盖世游戏只接收授权结果，不读取或保存邮箱、密码。
- 授权成功后回到发起入口并同步 GOG 游戏库。
- 用户取消、网络失败或授权拒绝时回到原入口，不写入虚假绑定记录。

## 9. 数据流与账号隔离

1. 用户从我的页或游戏库点击 GOG。
2. 系统检查 GOG 绑定状态；未绑定进入官方授权，已绑定展示账号或游戏库。
3. 授权成功后进行首次同步，成功后返回发起入口。
4. 搜索结果、游戏库卡片和详情“获得游戏”区域从 `PlatformBadgeData` 渲染 GOG 标识。
5. 点击搜索结果或游戏库卡片时，只按现有 `gameId` 进入详情。
6. Steam、EPIC、GOG 分别维护授权令牌、账号、同步结果和缓存；任何 GOG 操作都不得改写其他平台。

本期不使用 `sourcePlatform=gog` 初始化详情，不维护 `selectedPlatform=gog`，也不增加任何由 GOG 来源触发的启动分支。

## 10. 异常状态与恢复

| 场景 | 页面表现 | 恢复规则 |
|---|---|---|
| 更新进行中 | “更新数据”禁用并显示进行中状态 | 成功后更新时间；失败后恢复可点击并保留旧数据 |
| 切换账号失败 | 关闭或保留现有流程的错误状态 | 保留旧账号与旧同步数据，可再次发起切换 |
| 退出二次确认 | 使用现有确认流程 | 取消不变；确认后只清理当前平台账号与缓存 |
| 点击菜单外部 | 不新增提示 | 直接关闭菜单，不执行菜单项 |
| 授权失败或取消 | 返回发起入口 | 不产生虚假绑定记录，可再次绑定 |
| 同步为空或失败 | 使用现有账号库空态或失败态 | 可重新同步，其他平台数据不受影响 |
| 授权过期 | 使用现有重新登录提示 | 成功后回到原入口并恢复同步 |
| 缓存降级 | 展示上次成功同步内容和时间 | 同步成功后替换缓存 |

## 11. 标注规则

- 数字：当前页面内的操作步骤。
- `G`：跨页面、跨方向共用的平台标识和账号隔离规则。
- `E1`、`E2`：异常与边界。
- 点击左侧页面时，中间页面和右侧说明同步切换。
- 点击标注项时高亮中间对应元素。
- 支持显示/隐藏标号、折叠/展开右侧面板。
- 所有可见按钮都有事件或明确禁用原因；纯平台标识不得伪装成可点击按钮。

## 12. 视觉返修流程

### 12.1 基线保持

以已经完成的真实页面还原为基线，检查第二轮修改未改变页面纵向结构、导航、字体层级、卡片比例、封面、背景和滚动位置。

### 12.2 最小增量

仅修改账号卡操作区、搜索与游戏库卡片标识、详情“获得游戏”区域和对应标注。新增内容复用相邻 EPIC 或 Steam 的视觉语言，不移动与 GOG 无关的页面区块。

### 12.3 禁止方式

- 禁止用截图作为最终页面背景。
- 禁止通过 CSS 整体旋转或缩放生成另一方向。
- 禁止为了塞入 GOG 而压缩、删除或重排无关内容。
- 禁止保留第一轮 GOG 详情启动、时长、云存档和平台切换控件。
- 禁止给纯标识增加未确认的点击能力。

## 13. 验收标准

### 13.1 视觉

- 竖屏在 `402 × 874`、横屏在 `874 × 402` 目标视口分别截图对照。
- 游戏库以用户提供的 4 张新版截图为基准；我的页、搜索和详情以列出的 V6.1.1 截图为基准。

## 14. 安全、前置条件与风险

1. 正式开发前仍需确认 GOG 官方授权方式、游戏库字段、令牌刷新与退出能力；不得以采集用户密码替代官方授权。
2. GOG 明确没有账号价值，本期不设计估值算法、占位值或降级文案。
3. GOG 平台标识只表示可获得平台或来源，不能被产品文案、视觉按钮或埋点命名解释为已支持购买或启动。
4. 用户提供的账号卡和游戏库截图位于临时目录，项目内已有稳定参考资产继续用于自动截图复核；最终 Demo 不以内嵌截图代替真实 DOM。
