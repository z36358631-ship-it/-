# 盖世游戏 GOG 平台接入设计说明

## 1. 结论

在盖世游戏现有 Steam/EPIC 账号与游戏平台结构中增加 GOG，不新增“全平台管理中心”或独立业务层级。

本次覆盖 C 端国内包与海外包，包含：

- 我的页：GOG 绑定、账号摘要、刷新、切换和退出。
- 游戏库：新增 GOG 游戏 Tab，以及绑定、列表、空数据、失败和恢复状态。
- 游戏详情：增加 GOG 时长、云存档状态、启动方式和平台切换。
- 搜索结果：横竖屏增加 GOG 平台标识；同一 PC 游戏存在多个平台时分条展示。
- 全局规则：明确来源平台优先；无平台来源时按 Steam > EPIC > GOG 选择用户已拥有且已绑定的平台。

## 2. 设计依据

### 2.1 现状

- 现有竖屏“我的页”使用一张平台信息卡，通过 Steam/EPIC 标志切换账号数据。
- 现有游戏库已有 PC、Steam、EPIC、复古游戏结构，包含横竖屏和绑定缺省态。
- `demos/PC与Mac端/epic接入demo.html` 已展示详情页多平台启动方式，但游戏库与个人中心尚未实现，不能直接作为完整交付。
- 盖世游戏 V6.1.1 页面素材可作为竖屏视觉基线，既有 Demo 可作为横屏结构基线。

### 2.2 要解决的问题

拥有 GOG 游戏的用户目前无法在盖世游戏内绑定 GOG、查看个人游戏库、识别 GOG 搜索结果，也无法从详情页明确选择 GOG 启动。

### 2.3 用户现有替代方式

用户只能离开盖世游戏，通过 GOG Galaxy 或 GOG 网站查看游戏、账号与启动信息；盖世游戏无法利用这部分个人游戏资产完成发现到启动的闭环。

## 3. 范围

### 3.1 本次包含

1. C 端国内包与海外包。
2. 竖屏和横屏。
3. Steam、EPIC、GOG 账号独立绑定与状态隔离。
4. GOG 官方网页登录授权。
5. GOG 游戏库列表、详情与启动上下文。
6. 搜索结果 GOG 标识和多平台分条。
7. EPIC 5 分制评分转换为 10 分制。
8. 加载、空数据、请求失败、授权失效、取消登录和恢复状态。
9. 单文件交互标注 Demo 与标准 PRD。

### 3.2 不包含

- 不新增“全平台管理中心”。
- 不改造 Steam/EPIC 既有核心流程。
- 不新增 B 端配置后台。
- 不在搜索列表中合并多平台结果。
- 不让盖世游戏保存 GOG 邮箱或密码。
- 不增加与 GOG 接入无关的弹窗、Toast、页面和流程。

## 4. 方案选择

### 4.1 备选方案

| 方案 | 说明 | 优点 | 代价 |
|---|---|---|---|
| A. 现有平台卡扩展 | 在 Steam/EPIC 旁增加 GOG，共用平台信息卡 | 与现有页面一致，改动和学习成本最低 | 后续继续增加平台时需处理 Tab 宽度 |
| B. 平台卡片平铺 | 每个平台独立一张摘要卡 | 绑定状态一眼可见，便于新增平台 | 占用首屏空间，改变既有操作习惯 |
| C. 全平台聚合中心 | 展示跨平台总资产，再进入二级管理页 | 长期扩展性最好 | 增加页面和路径，超出本次增量范围 |

### 4.2 已确认方案

采用方案 A。GOG 自然融入现有平台卡、游戏库、详情和搜索，不重构既有信息架构。

## 5. 三视角评审与修正

### 5.1 用户视角

从明确标注 GOG 的搜索结果或 GOG 游戏库进入详情后，若仍按 Steam > EPIC > GOG 启动，会造成用户困惑。

修正：明确平台入口必须携带 `sourcePlatform`，详情优先使用来源平台；来源平台不可用时提示用户切换，不静默改用其他平台。

### 5.2 开发视角

仅按中英文名归类会因别名、重名和本地化差异产生误合并或漏合并。

修正：使用统一 `gameId` 与各平台 `platformAppId` 映射。标题、中文名、英文名和别名只用于候选匹配；低置信度不合并。

### 5.3 商业视角

方案 A 的实现成本最低，但当前缺少 GOG 可覆盖用户数、有效游戏数和预期启动增量，ROI 只能定性判断。

修正：通过绑定点击率、绑定成功率、有效库覆盖率、GOG 启动成功率和灰度启动增量验证价值。保留用户已确认的完整搜索范围。

## 6. 总体架构

### 6.1 平台账号状态

Steam、EPIC、GOG 各自维护独立账号状态：

- `unbound`：未绑定。
- `authorizing`：官方登录授权中。
- `syncing`：授权成功，首次同步中。
- `bound`：已绑定且数据可用。
- `expired`：授权失效，需要重新登录。
- `error`：请求失败，可重试或使用缓存。

任一平台刷新、切换、退出或授权失效都不得改变其他平台状态。

### 6.2 游戏映射

1. 统一 `gameId` 表示盖世游戏内同一个游戏。
2. `platform + platformAppId` 唯一定位平台版本。
3. 中英文标题、别名和发行版本只做候选匹配。
4. 低置信度候选保持为不同游戏，不自动合并。
5. 人工映射或服务端确认后才能改变统一 `gameId` 归属。

### 6.3 详情来源上下文

进入详情时传递：

- `sourcePlatform`：入口明确的平台；无明确平台时为空。
- `selectedPlatform`：详情当前展示和启动的平台。
- `ownedPlatforms`：用户已拥有且已验证的平台集合。

路由规则：

1. `sourcePlatform` 已拥有且账号可用：`selectedPlatform = sourcePlatform`。
2. `sourcePlatform` 账号未绑定或授权失效：保留来源平台，启动按钮显示绑定或重新登录引导。
3. `sourcePlatform` 不可用：明确提示用户选择其他已拥有平台，不自动替换。
4. 无 `sourcePlatform`：在已拥有且账号可用的平台中按 Steam > EPIC > GOG 选择。

## 7. 页面与交互

### 7.1 我的页

平台信息卡顶部按现有结构排列 Steam、EPIC、GOG 标志。点击标志切换当前平台数据，不改变其他平台状态。

#### 未绑定

- 标题：`GOG 数据同步功能`。
- 说明：`绑定账号后可查看个人游戏库数据`。
- 按钮：`绑定 GOG 账号`。
- 点击后打开 GOG 官方登录网页。

#### 已绑定

展示用户名、账号价值、游玩时长、游戏数量、最近同步时间和“查看更多”。

账号价值由现有平台估值服务基于已映射游戏生成。暂时无法计算时显示 `--`，不得显示为 `0`。

#### 查看更多

- 更新刷新：刷新当前 GOG 账号数据；刷新中禁止重复点击，完成后更新同步时间。
- 切换账号：复用现有平台切换流程。新账号授权成功且首次同步完成后替换旧账号；取消或失败时保留旧账号。
- 退出账号：二次确认后清除 GOG 授权态和当前账号缓存，不影响 Steam/EPIC。
- GOG 不展示 EPIC“喜加一”入口。

### 7.2 GOG 登录

使用内置 WebView 打开 GOG 官方登录网页。

- 邮箱、密码和“记住我”由 GOG 官方页面处理。
- 盖世游戏只接收授权结果和后续接口所需令牌。
- 取消登录返回原入口，原状态不变。
- 登录成功进入首次同步，成功后返回原入口并展示 GOG 数据。
- 网络失败、授权拒绝和超时均停留在可恢复状态，提供重试或返回。

### 7.3 游戏库

在现有 PC、Steam、EPIC、复古游戏结构中增加 `GOG 游戏` Tab，横竖屏保持一致。

#### 未绑定

展示绑定说明和“绑定 GOG 账号”按钮，点击后进入同一官方登录流程。

#### 已绑定

- 列表项展示游戏封面、游戏名、GOG 平台标识和游玩时长。
- 点击游戏进入详情，并携带 `sourcePlatform=GOG` 与对应 `platformAppId`。
- 排序、滚动加载和缓存规则沿用现有平台游戏库，不增加独立规则。
- 游戏数为 0 时展示空数据，不使用失败文案。
- 请求失败时优先保留上次缓存并提供重试。
- 授权失效时提示重新登录，不清除其他平台数据。

### 7.4 游戏详情

PC 游戏引擎区域增加 GOG 云存档状态、GOG 游玩时长和 GOG 启动方式。

- 云存档暂时无法获取时显示 `未获取`，不得显示为“不支持”。
- 从 GOG 游戏库或 GOG 搜索结果进入时，默认展示 GOG 数据和 GOG 启动按钮。
- 通过详情卡片的平台入口打开切换平台弹窗。
- 切换弹窗只展示用户已拥有的平台，以及当前来源但尚待验证的平台。
- 选择平台后同步切换游玩时长、云存档、平台标识和启动按钮。
- 同时拥有多平台且入口无平台来源时，默认按 Steam > EPIC > GOG。

### 7.5 搜索结果

- 横屏和竖屏均增加 GOG 平台标识。
- 同一 PC 游戏存在 Steam、EPIC、GOG 多个平台时，保持多条搜索结果。
- 每条结果携带 `platform`、`platformAppId` 和 `gameId`。
- 点击 GOG 结果进入详情时传递 `sourcePlatform=GOG`。
- EPIC 评分按 `原始分数 × 2` 转换为 10 分制，沿用现有小数位规则；结果限制在 0 至 10 分。
- GOG 未定义评分换算，本次不新增 GOG 评分口径。

### 7.6 横竖屏

- 业务状态、文案、平台标识和点击规则一致。
- 竖屏沿用底部导航与顶部平台 Tab。
- 横屏沿用现有左侧或顶部导航结构，不为 GOG 新增独立导航层级。
- 横竖屏切换后保留当前平台、绑定状态和详情来源上下文。

## 8. 状态、异常与恢复

| 状态 | 页面表现 | 可执行操作 | 恢复结果 |
|---|---|---|---|
| 加载中 | 骨架或加载态 | 返回；禁止重复提交 | 成功进入内容，失败进入错误态 |
| 已绑定且空库 | 空数据说明 | 刷新 | 数据恢复后展示列表 |
| 请求失败且有缓存 | 展示缓存和更新时间 | 重试 | 成功后更新缓存 |
| 请求失败且无缓存 | 失败说明 | 重试、返回 | 成功后进入内容 |
| 授权失效 | 重新登录提示 | 重新登录、返回 | 成功后恢复原入口 |
| 取消登录 | 返回原入口 | 再次绑定 | 原账号状态保持不变 |
| 切换账号失败 | 保留旧账号 | 重试、取消 | 新账号完整同步后才替换 |
| 来源平台不可用 | 明确说明不可用 | 打开平台切换 | 用户主动选择其他平台 |

## 9. 国内与海外包

- 功能、状态与路由一致。
- 国内包使用固定中文文案。
- 海外包跟随应用语言，使用 `GameHub` 品牌名，不使用 `GaishiGame`。
- GOG 官方网页使用其可用语言与地区策略，盖世游戏不伪造本地登录表单。
- 地区网络导致页面不可达时进入可重试失败态，不回退为本地密码输入。

## 10. 安全与隐私

- 盖世游戏不得读取、保存或上报 GOG 邮箱与密码。
- 日志、埋点、本地缓存和错误上报不得包含官方登录页面输入内容。
- 授权令牌按现有第三方平台令牌规范加密保存和过期清理。
- 退出账号后清除 GOG 授权令牌与账号级缓存。
- 官方网页登录域名必须使用允许名单，页面跳转超出允许名单时中止授权并提示。
- WebView 关闭时不得把官方页面历史内容截图写入日志或埋点。

## 11. 数据与指标

| 指标 | 口径 |
|---|---|
| GOG 绑定点击率 | 点击绑定 GOG 的去重用户数 / GOG 绑定入口曝光去重用户数 |
| GOG 绑定成功率 | GOG 绑定成功次数 / GOG 授权提交次数 |
| 首次同步成功率 | 首次同步成功次数 / GOG 绑定成功次数 |
| 有效库覆盖率 | 成功映射到统一 `gameId` 的 GOG 游戏数 / GOG 返回游戏数 |
| GOG 启动成功率 | GOG 启动成功次数 / GOG 启动请求次数 |
| GOG 启动增量 | 灰度用户人均 GOG 启动次数与上线前同周期基线对比 |

事件至少区分入口页面、横竖屏、来源平台、选中平台、绑定状态、请求状态和失败类型。事件中不得包含第三方账号、邮箱、密码或令牌。

## 13. 验收

### 13.1 产品与交互

- 9 个 Demo 页面全部可切换，中间页面与右侧标注同步。
- 横竖屏平台标识、文案和来源平台规则一致。
- GOG 账号操作不改变 Steam/EPIC 状态。
- 明确来源平台优先；无来源才按 Steam > EPIC > GOG。
- 来源平台不可用时不静默改用其他平台。
- 搜索多平台分条，点击后平台上下文正确。

### 13.2 数据与边界

- 同名不同游戏不会因名称相同被自动合并。
- 已确认别名可归入同一统一 `gameId`。
- EPIC 评分换算边界覆盖 0 分、5 分和小数值。
- 账号价值、云存档暂不可用时分别显示 `--`、`未获取`。
- 加载、空数据、失败、授权失效、取消登录和切换账号失败均可恢复。

### 13.3 安全

- GOG 邮箱、密码和令牌不出现在页面业务日志、埋点和错误上报中。
- WebView 只允许受信任的 GOG 登录域名。
- 退出账号后 GOG 令牌和账号级缓存已清除。

### 13.4 Demo 质量

- JavaScript 语法检查通过。
- 页面导航、标注联动、标号显隐和面板折叠 Smoke Test 通过。
- 所有按钮均有事件映射。
- 关键竖屏、横屏和三栏布局截图检查无重叠、截断和低对比文字。

## 14. 技术前置条件与风险

1. 正式开发前，服务端必须验证可用的 GOG 官方授权方式、游戏库数据范围、令牌刷新与退出机制。官方授权不可用时，生产接入不得以采集用户密码的方式替代。
2. GOG 返回字段可能不足以直接计算账号价值、全量游玩时长或云存档状态。缺失字段按本文降级值展示，并记录字段覆盖率，不伪造数据。
3. 游戏映射错误会导致错误启动和资产展示。灰度前必须完成高频 GOG 游戏映射抽样，并保留低置信度不合并策略。
4. Tab 增加 GOG 后可能在小屏设备拥挤。实现必须沿用现有横向滚动或自适应规则，并覆盖最小支持宽度。
