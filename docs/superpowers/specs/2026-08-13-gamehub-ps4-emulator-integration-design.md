# 盖世游戏 App 主机模拟器接入设计

## 1. 结论

- 能力并入现有“游戏库”，横竖版二级 Tab 固定为“PC游戏、主机游戏、复古游戏”；不新增底部 Tab 或内容专区。
- 分类正式名称待法务确认，Demo 暂用“主机游戏”，不使用平台 Logo 或专属几何按键。
- 首版不做探索、全局搜索收录和内容型游戏详情；分类内搜索只检索本地游戏。游戏卡用独立主按钮启动，省略号承载更新/DLC、存档、设置和移除。
- 平台不提供游戏资源，只处理用户合法拥有的本地 PKG 与已解包游戏文件夹。
- PS4 引擎插件按进入分类或首次启动时检测、下载和更新，不阻塞 App 全局启动。

## 2. 用户问题

用户当前需在独立模拟器中完成文件授权、游戏导入、驱动设置、存档和按键配置，页面偏技术工具，且无法复用盖世游戏已有游戏库、手柄和虚拟按键能力。本方案把必要能力融入现有游戏库，减少重复学习和入口割裂。

## 3. 信息架构

1. 游戏库
    - PC游戏 / 主机游戏 / 复古游戏三级 Tab
    - 分类内本地搜索、排序与视图切换
    - 导入游戏
    - 游戏卡及更多菜单
2. 导入链路
    - 选择 PKG：系统文件管理器单选 → 识别 → 解压 → 安装 → 回到游戏库
    - 导入游戏文件夹：系统文件管理器选择目录 → 扫描识别 → 解压 → 已识别游戏列表 → 用户勾选 → 安装 → 回到游戏库
    - 两条链路均包含空间校验、失败重试和中断后重新安装
3. 游戏管理
    - 快捷启动
    - 安装更新包或 DLC
    - 存档管理
    - 游戏设置
    - 移除游戏
4. 运行中
    - 必要组件下载
    - 横屏游戏
    - 暂停或继续
    - 虚拟按键显示开关与布局编辑
    - 手柄映射
    - 退出游戏
5. 后台
    - PS4 引擎插件版本列表
    - 新增版本
    - 灰度、强制更新、启停和回滚
    - 操作记录

## 4. 关键规则

- 竖屏采用底部导航和单列工具区，横屏采用顶部导航、多列游戏网格与手柄焦点；两者共享数据，但不得旋转、缩放或拉伸同一套页面结构。
- 游戏库 Tab 顺序固定为“PC游戏、主机游戏、复古游戏”；切换 Tab 保留各自搜索词、排序和滚动位置。
- 选择 PKG 仅允许单文件；选择后不再出现二次文件勾选，识别成功直接进入解压和安装。
- 导入游戏文件夹允许一个目录内识别多款游戏；仅已识别游戏可勾选，至少勾选一款后才能安装。
- 安装成功后自动回到主机游戏列表，并展示新增游戏；不增加独立成功页。
- 游戏本体、更新包和 DLC 均按游戏 ID 自动关联；不让用户手动选择关联对象。
- 仅显示本地版本和 DLC 数量，不判断是否为最新版本，不展示“已更新”。
- 同一游戏的不同地区版本通过游戏 ID 区分。
- 大型文件不设置复古游戏的小文件上限；安装前校验空间，过程中空间不足时清理当前未完成内容。
- 安装中退出或杀进程不恢复进度，重新进入后从头安装。
- 移除游戏时删除本体、更新包和 DLC，保留存档；存档只能在存档管理中删除。
- 完全相同的存档重复导入不新增；内容不同则保留为新存档。
- 存档页用下拉刷新，右上角提供“导入存档”；导出后拉起保存位置，删除必须二次确认。
- 运行态复用现有 PC 模拟器侧边栏、按键布局和手柄映射。
- 游戏内“显示触控按键”为开关；按键与布局、手柄映射进入二级面板；退出游戏必须二次确认。
- Google Play 包暂不支持本地导入，其他国内及 Global 包按需申请文件访问权限。

## 5. 状态与异常

- 设备不支持：入口保留，分类内说明暂不支持，不允许导入或启动。
- 文件权限拒绝：保留当前页面，说明授权用途并允许重新授权。
- 文件无法识别、损坏或已加密：标记具体文件并允许移除后继续。
- 空间不足：安装前阻断；安装中不足则清理未完成部分并保留已完成项。
- 插件下载失败：停留在必要组件页面，支持重试和退出。
- 更新包或 DLC 找不到本体：标记未匹配，不进入安装队列。
- 文件夹扫描中未识别到游戏：保留重新选择入口，不进入空安装队列。
- 用户未勾选任何游戏：安装按钮禁用，并提示至少选择一款游戏。
- 存档下拉刷新失败：保留当前列表，在顶部显示失败状态并允许再次下拉。
- 启动闪退或卡顿：提示可能与设备、驱动、文件或兼容性有关，并提供设置入口。

## 6. 方案快速评审

- 用户视角：通过。三级 Tab 和横竖版都沿用现有游戏库心智，单文件与批量目录的流程分开，不让用户猜测下一步。
- 开发视角：通过。横竖版分壳但共享数据；PKG 单文件和文件夹批量使用独立状态机，避免把勾选逻辑错误复用到单文件链路。
- 商业视角：通过。首版聚焦本地工具能力，不触碰资源分发和内容运营，能用较小范围验证使用量。

## 7. 待确认但不阻塞 Demo

- 正式分类名称及图标由法务、设计确认。
- 驱动是只允许本地导入，还是按芯片提供平台验证版本。
- 设备支持规则及对外机型说明由研发、运营提供。
- 插件强制更新与非强制更新的最终触发策略由研发确认。

## 8. 2026-08-14 返修结论

- 来源冲突 CR-010：旧实机图为 PC/Steam/Epic/复古四 Tab，本轮用户明确要求 PC/主机/复古三 Tab；采用本轮三级 Tab，旧图仅保留页面骨架。
- 来源冲突 CR-011：旧横屏图只有单游戏与“查看详情”，本轮要求直接启动与更多管理；采用独立“启动”主按钮和省略号更多入口。
- 来源冲突 CR-012：SDK 有刷新按钮和技术提示，本轮要求存档下拉刷新、右上导入并移除提示；采用本轮交互，SDK 仅补充底层能力。
- 置信度：高。以上均为用户本轮明确要求，直接进入实施。
