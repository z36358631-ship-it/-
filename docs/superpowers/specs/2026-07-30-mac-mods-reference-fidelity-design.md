# Mac MODS 参考图 1:1 还原设计

- 日期：2026-07-30
- 状态：设计已确认，待书面规格复核
- 唯一产品文件：`demos/Mod与发行人/Mod功能Mac端demo.html`
- 视觉基准：`prd/mod功能/Mac端mod图片/` 下四张 2160×1480 截图
- 游戏：饥荒联机版（DST）
- 游戏标识：`steam:322330`

## 1. 背景

当前 Mac Demo 的信息架构、窗口外壳、游戏详情、MODS 列表和详情弹窗均未按运营提供的 Mac 参考图还原。本次纠正范围，不再继续调整 APP 主 Demo或 APP 场景联动 Demo，只重做 Mac Demo。

本次“1:1 还原”包含两层含义：

1. Mac 窗体、侧栏、主内容区、卡片、弹窗、固定操作栏和四个关键画面按参考图的坐标、比例与视觉层级重建。
2. 参考图中 MODS 的展示内容和操作语义改为最终产品定义：外部非官方来源、当前设备本地安装管理、安装、启停、更新和卸载；不沿用创意工坊的“订阅”语义。

## 2. 目标与非目标

### 2.1 目标

1. 只修改 `Mod功能Mac端demo.html`。
2. 以 2160×1480 为唯一设计基准，生成可等比缩放的 Mac Demo。
3. 还原四个参考状态：
   - 游戏详情中的 MODS 入口。
   - MODS 两列列表。
   - MOD 详情弹窗首屏。
   - MOD 详情弹窗滚动后的说明区域。
4. MODS 入口、列表、详情和底部操作栏均由同一状态模型派生。
5. 保留 MODS 状态合同、安装幂等、更新失败保留旧版和只读调试接口，不发生当前设备安装管理能力回归。
6. 单文件离线打开，封面、缩略图、图标、样式和脚本全部内嵌。

### 2.2 非目标

- 不修改 `Mod功能APP端demo.html`。
- 不修改 `Mod功能APP端-场景联动demo.html`。
- 不重做创意工坊业务。
- 不新增 APP、移动端或响应式产品方案。
- 不新增 MOD 发布、审核、点赞、收藏、排行榜和跨设备同步。
- 不展示启动检查、游戏启动结果、加载证据或异常恢复。
- 不实现真实下载、文件写入、游戏启动或日志读取。

## 3. 方案选择

采用“真实 DOM 布局 + 参考图素材裁切内嵌”的混合方案。

### 3.1 采用方案

- Mac 外壳、侧栏、列表、弹窗、按钮、文字和状态全部由 HTML/CSS/JavaScript 真实渲染。
- 参考图中的 DST MOD 封面与缩略图从用户提供的截图中机械裁切，转为内嵌 `data:` 图片。
- 默认状态严格对齐参考图；安装后的状态仍在同一卡片和底部操作栏内变化。

### 3.2 未采用方案

- 纯 CSS 重画全部封面：交互真实，但无法达到参考素材的视觉一致性。
- 整张截图作为背景：像素最接近，但无法形成真实、可验证的交互 Demo。
- 重做现有三端 Demo：超出本轮“只改 Mac”的明确范围。

## 4. 基准画布与缩放

### 4.1 固定设计坐标

产品画布固定为：

```text
width = 2160px
height = 1480px
```

所有尺寸、边距、字号和圆角均在该坐标系中定义。

### 4.2 小窗口显示

浏览器小于基准尺寸时，只对整个画布做等比缩放并居中留边：

```text
scale = min(viewportWidth / 2160, viewportHeight / 1480)
```

不允许在小窗口下重新排版、改变列数或压缩弹窗结构。本 Demo 是参考图评审画布，不对外宣称为真实响应式实现。

### 5.1 游戏详情入口

### 5.2 MODS 列表

参考：`mod列表.jpg`

还原内容：

- 左上“返回详情”按钮。
- 标题 `MODS`。
- 副标题“4 个可用 MOD，可安装到当前设备”。

- 两列卡片，卡片封面、信息区和操作区按参考图垂直分层。

- 已安装：显示启停状态，详情中提供更新和卸载。

- 来源未知：不显示可执行更新按钮。

## 6. 业务状态与数据流

### 6.1 保留合同

继续保留：

```javascript
const DEMO_MODEL_VERSION = 'dst_mods_demo_v1';
const GAME_ID = 'steam:322330';

window.__DST_MODS_DEMO__ = {
  version,
  getState,
  dispatch,
  derive,
  reset
};
```

保留现有根状态：

```text
contractVersion
game_id
device_installation_id
platform
orientation
mods
tasks
ui
metrics
```

### 6.2 单向数据流

```text
点击入口、卡片或按钮
→ dispatch(action)
→ reducer(state, action)
→ derive(state)
→ render(viewModel)
```

入口数量、列表状态、详情按钮和安装任务必须读取同一 `mods/tasks` 状态，不允许分别维护 DOM 文案。

### 6.3 幂等与正交状态

- 重复点击安装继续使用同一 `task_id`。
- 安装事实、启用值、更新事实和任务状态分别保存。
- 更新失败保留旧版、旧版指针和最近一次启用值。
- 卸载只作用于当前设备，不删除存档或用户配置。

## 7. 视觉资源

### 7.1 允许

- 从四张 Mac 参考图机械裁切 MOD 封面和缩略图。
- 将裁切结果压缩后转换为 `data:image/...;base64` 内嵌。
- 图标使用内联 SVG。

### 7.2 禁止

- 网络图片、CDN、远程字体、`fetch`、XHR 和 iframe。
- 把整张参考截图作为可点击产品页面。
- 通过隐藏截图图层伪造真实交互。

## 8. 评审控制

参考图主画布和评审控制区都不展示启动检查、游戏启动结果、加载证据或异常恢复。

评审控制区只覆盖 MODS 安装管理状态：

- 依赖阻塞。
- 来源未知。
- 更新失败保留旧版。

这些能力不得改变四张基准截图的默认视觉。

## 9. 异常与反馈

- 刷新：原位置显示短暂加载反馈，列表结构不跳动。
- 搜索无结果：两列区域显示与参考卡片等高的空状态。
- 安装失败：主按钮位置显示失败与重试，保留当前设备事实。
- 依赖阻塞：详情底部主按钮禁用并展示最短阻塞原因。
- 更新失败：显示“保留旧版”，启停控件继续可用。
- 卸载：弹出仅此设备确认，不删除存档和配置。

## 10. 验收

### 10.1 文件边界

本轮产品实现只允许修改：

```text
demos/Mod与发行人/Mod功能Mac端demo.html
```

运行截图允许写入 `.tmp/`。不得修改两个 APP Demo、PRD、参考图和其他用户文件。

### 10.2 像素基准

使用本机 Chrome 以 2160×1480 打开产品画布，分别截取：

```text
mac-reference-entry.png
mac-reference-list.png
mac-reference-detail-top.png
mac-reference-detail-scroll.png
```

逐张与四张参考图对照：

- 产品画布尺寸必须精确为 2160×1480。
- Mac 外框、侧栏、主内容左边界、双列卡片、弹窗和固定栏的边界偏差不超过 4px。
- 文字基线与图标中心偏差不超过 6px。

### 10.3 业务验收

- 入口数量随安装和卸载变化。
- 搜索与刷新可点击。
- 详情弹窗可打开、关闭和滚动。

- 安装、启停、更新失败、卸载状态正确。
- 创意工坊静态区域不受 MODS 状态影响。
- `window.__DST_MODS_DEMO__` 可读取和派发状态。

### 10.4 离线验收

- `file://` 断网打开。
- 外部请求为 0。
- 页面错误和控制台错误为 0。
