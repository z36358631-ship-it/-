# Mac 端租号 Demo 交互标注统一设计

## 1. 目标

将 Mac 端租号 Demo 的客户端、运营后台及异常边界标注统一为结构化说明。每条标注必须明确：

1. 触发条件：什么状态、操作或数据条件下出现。
2. 展示说明：界面展示哪些文案、状态、数据和控件。
3. 交互说明：用户或运营人员操作后发生什么，包括跳转、弹窗、状态变化和失败处理。

本次只调整标注说明、定位目标和校验逻辑，不改变已确认的租号业务流程。

## 2. 数据结构

现有标注使用单一 `body` 字段，调整为：

```js
{
  id: '1',
  mode: 'mac',
  page: 'explore',
  tab: 'interaction',
  title: '租号信息展示',
  trigger: '游戏商品已上架且存在可租库存。',
  display: '展示最低租号金额和当前在租数量。',
  interaction: '点击游戏内容进入游戏详情并重新校验权益。',
  target: 'explore-rent-meta',
  tag: '展示规则'
}
```

交互说明与异常边界页签均使用相同字段。异常标注的 `interaction` 描述系统拦截、提示、重试、回滚或转人工结果。

## 3. 面板展示

每张标注卡保留编号、标题和标签，在正文中固定展示三个字段：

- `触发条件`
- `展示说明`
- `交互说明`

字段标题使用弱强调标签，正文保持当前字号和可读行高。卡片宽度、点击定位和闪烁反馈保持不变；内容较长时由右侧面板纵向滚动，不压缩 Demo 画布。

## 4. 补齐范围

### 4.1 客户端

- 探索、编辑推荐、找游戏、搜索结果中的租号金额、在租数、筛选和卡片入口。
- 游戏库的安装分组、Steam 租赁/个人会话、同步、筛选和详情入口。
- 游戏详情在租赁目标、租赁非目标、个人已拥有、个人未拥有等状态下的按钮展示与点击结果。
- 非目标游戏获取、下载、启动拦截及去租号流程。
- 套餐、时长、版本、首单优惠、订单金额、支付方式和启动保障险。
- 订单中心筛选、状态操作、待支付倒计时、卡片详情入口、取消/删除确认及再来一单预填。
- 订单详情状态区、订单号复制、游戏详情入口、状态流转和申请售后。
- 售后申请的问题类型、问题描述、游戏摘要、提交校验和退款进度。

### 4.2 运营后台

- 商品摘要、新建商品、版本套餐、复制、批量改价和上下架。
- 账号库存、新建库存、同步、检测、释放、批量处理和凭据隐藏。
- 订单与售后的两个页签、组合筛选、启动结果、用户问题描述和处置入口。
- 售后抽屉的审核、退款、会话撤销、账号释放及异常结果。
- 效果统计的周期筛选、业务指标、库存效率、转化漏斗和明细排序。
- 操作记录的触发范围和展示内容。

### 4.3 异常边界

现有异常标注全部转换为三段式，并覆盖库存/价格失效、支付超时、重复支付、续租冲突、批量部分失败、同步延迟、无库存换号、重复退款、统计分母为零、非目标白名单和资源释放失败。

## 5. 定位策略

- 复用已有 `data-anno-target` 时不新增包装层。
- 对游戏库等无标注目标的新增区域添加稳定的 `data-anno-target`。
- 弹窗类功能优先定位到触发入口，并在交互说明中写明弹窗内容；需要直接查看弹窗时，由标注点击逻辑打开对应演示弹窗。
- 每个标注 ID 唯一，每个目标必须能在对应页面渲染结果中找到。

## 6. 校验与验收

1. 所有标注均包含非空的 `trigger`、`display`、`interaction`。
2. 标注面板不再读取旧 `body` 字段。
3. 客户端和后台每个新增功能至少有一条交互标注或异常标注。
4. 所有标注点击后能定位到页面目标；弹窗类标注能打开或定位到触发入口。
5. 标注 ID 无重复，目标无缺失。
6. Demo 既有冒烟测试全部通过，并新增结构完整性、三段标题渲染和新增页面标注覆盖测试。
7. 1076×734 客户端画布与 1800×1300 后台画布不因标注面板调整发生遮挡或错位。

## 7. 非目标

- 不调整租号价格、订单状态机、退款规则和后台业务数据。
- 不重新设计 Demo 主界面。
- 不改动 PRD 截图和在线 CDN 资源。
