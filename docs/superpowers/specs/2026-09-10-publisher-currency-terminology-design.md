# 发行人计划货币与任务中心积分区分设计

## 1. 结论

发行人计划名称保持不变，发行任务的预算与奖励单位继续使用“盖世币”；任务中心的普通任务奖励单位统一称为“盖世积分”。两类资产分别记账，不互相合并或换算。

“盖世币”仍按取得来源控制京东卡兑换资格：

- 用户付费充值获得的盖世币，只能用于创建或追加发行任务预算，不可兑换京东卡。
- 用户参与发行任务并完成结算获得的盖世币，计入可兑换盖世币，可兑换京东电子卡。
- 发行任务取消、审核驳回或结算后退回的未消耗盖世币继承原来源；充值来源退回后仍不可兑换。
- 任务中心获得的盖世积分不计入盖世币总余额，也不进入京东卡兑换链路。

## 2. 要解决的问题

“盖世币”容易同时被理解为任务中心奖励、充值资产和发行任务奖励，用户无法仅凭名称判断资产用途。本轮用“盖世积分／盖世币”区分两套资产，再在盖世币账内按来源控制兑换资格，避免形成“充值盖世币→京东卡”的近现金通道。

## 3. 术语与资产模型

| 名称 | 获得方式 | 主要用途 | 是否可兑换京东卡 |
|---|---|---|---|
| 盖世积分 | 完成任务中心的普通任务 | 沿用任务中心既有用途 | 否 |
| 充值盖世币 | 用户付费充值；充值预算冻结后按原来源退回 | 创建或追加发行任务预算 | 否 |
| 发行任务奖励盖世币 | 用户参与发行任务并结算获得 | 发行人计划内展示、消费或兑换 | 是 |

“可兑换盖世币”不是第三种货币，只是发行任务奖励来源中当前未消耗、符合兑换条件的盖世币余额。

## 4. C 端表现

1. 项目、入口和页面标题继续使用“发行人计划”，不改成“创作者计划”。
2. 发行任务卡、详情、创建任务、钱包、充值、兑换商城和兑换记录继续使用“盖世币”单位。
3. 玩法说明与兑换规则明确：“任务中心获得的是盖世积分，与盖世币分开计算；只有参与发行任务并结算获得的盖世币可兑换京东电子卡。”
4. 钱包继续展示盖世币总余额，不增加盖世积分卡片；任务中心积分不属于本页范围。
5. 兑换商城继续只展示“可兑换盖世币”，不展示充值来源余额或盖世积分。
6. 不新增页面、弹窗、Toast、入口或兑换步骤。

## 5. B 端表现

1. 任务预算、结算奖励、京东卡价格和兑换订单继续使用“盖世币”。
2. 兑换订单说明明确：只扣减参与发行任务并结算获得的盖世币；充值盖世币和盖世积分均不得进入兑换流程。
3. 不新增盖世积分配置、积分换币、资产合并或独立告警能力。

## 6. 数据与校验

1. 盖世积分账与盖世币账分别维护余额和流水，不共享可用余额。
2. 盖世币流水至少可区分充值来源与发行任务奖励来源；预算冻结、退回和兑换保留原流水关联。
3. 京东卡兑换校验以服务端可兑换盖世币为准，只允许扣减发行任务奖励来源。
4. 客户端展示值、缓存或同名盖世币总余额不能替代服务端来源校验。
5. 既有三账一致性继续成立：盖世币扣减、卡密状态与兑换订单按订单号对应。

## 7. 快速角色评审

- 用户：用“盖世积分／盖世币”区分任务中心和发行人计划，名称与获得场景一致；兑换页只出现可兑换盖世币，避免误以为积分或充值余额可兑卡。
- 开发：需要两套独立资产账；盖世币账内继续保留来源属性。只改显示文案而不分账会导致兑换越权，因此不可采用。
- 商业与合规：充值盖世币不能兑换京东卡，保留发行任务奖励兑换路径；规则说明不得把充值、积分与可兑换奖励混为一类。

## 8. 验收标准

1. 全部产物仍称“发行人计划”，不存在“发行积分”“发行币”“共创币”或“创作者计划”替换。
2. 任务中心奖励单位在术语和规则中明确为“盖世积分”。
3. 充值获得的盖世币不可兑换京东卡。
4. 只有参与发行任务并结算获得的盖世币可兑换京东电子卡。
5. 盖世积分、充值盖世币和发行任务奖励盖世币的余额归属与兑换资格前后一致。
6. C/B Demo、PRD、截图、规则和自动化校验使用同一口径。

## 9. 明确不做

- 不修改任务中心页面结构或恢复当前工作区中已删除的历史任务中心 Demo。
- 不设计盖世积分的商城、消耗规则或换币规则。
- 不修改京东卡面额、价格、限兑、库存告警和卡密履约规则。
- 不执行 Git 推送、线上发布、真实飞书请求或真实支付。
