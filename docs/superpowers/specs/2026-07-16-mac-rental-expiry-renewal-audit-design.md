# Mac 端租号到期续租、启动拦截与运营审计设计

## 1. 目标与范围

补齐 Mac 端游戏租号从临近到期到订单结束后的完整生命周期，并同步优化确认订单页的价格展示和租号运营中心的审计能力。

本次范围包括：

1. 租期到期前 15 分钟、5 分钟的顶部居中提醒。
2. 到期前续租、到期立即结束及账号回收。
3. 到期后本地已有安装包的启动拦截与重新租用。
4. 确认订单页的游戏原价、首单优惠标签和订单划线价调整。
5. 租号运营中心新增操作记录及组合筛选。
6. 效果统计页移除“环比对比”按钮。

本次不改变“3 天无理由退款”及高频退款风控规则，不新增 1 分钟到期提醒，不删除用户本地安装包、配置或存档。

## 2. 当前缺口

现有 Demo 和 PRD 已有订单有效期、剩余时长、续租入口、到期撤销授权及账号后续预约冲突规则，但缺少：

- 游戏中和游戏外的临期提醒。
- 到期时结束游戏、撤销会话和回收账号的端到端处理。
- 本地仍有安装包时的过期启动拦截。
- 续租支付、账号预约冲突和到期任务之间的一致性规则。
- 后台跨模块操作审计。
- 首单折扣价格的清晰展示层级。

## 3. 时间口径与订单状态

### 3.1 唯一时间口径

- 服务端 `expire_at` 是租期到期的唯一判断依据。
- 客户端不得使用本机时间决定订单是否有效，只根据服务端返回的 `server_time` 与 `expire_at` 计算展示倒计时。
- 客户端时间被修改、设备休眠、应用最小化或前后台切换均不得延长租期。

### 3.2 新增状态字段

订单或租赁会话至少保存：

| 字段 | 说明 |
|---|---|
| `expire_at` | 当前租赁服务到期时间 |
| `expiry_15m_reminded_at` | 15 分钟提醒实际展示时间；未展示为空 |
| `expiry_5m_reminded_at` | 5 分钟提醒实际展示时间；未展示为空 |
| `renewal_status` | 无续租、待支付、成功、失败或关闭 |
| `renewal_order_id` | 关联的续租支付单 ID |
| `force_exit_at` | 到期强制结束游戏的时间 |
| `session_revoked_at` | 租赁会话撤销时间 |
| `account_released_at` | 账号资源释放时间 |
| `expiry_end_result` | 到期结束执行结果及失败原因 |

提醒展示需按订单和提醒档位幂等，同一订单的同一档提醒最多展示一次。

## 4. 临期提醒

### 4.1 提醒档位

| 触发点 | 提示文案 | 操作 |
|---|---|---|
| 到期前 15 分钟 | 租期将在 15 分钟后到期，是否续租？ | 暂不续租、立即续租 |
| 到期前 5 分钟 | 租期仅剩 5 分钟，未续租将在到期后结束游戏 | 知道了、立即续租 |

不增加到期前 1 分钟提醒。

### 4.2 展示规则

- 两次提醒均在屏幕顶部居中展示，不暂停游戏。
- 游戏全屏或客户端最小化时，由常驻进程展示系统级置顶浮层。
- 客户端及常驻进程均未运行时，以 macOS 系统通知兜底；用户点击通知后打开原订单续租页。
- 设备从休眠恢复时，如果已经错过提醒时间但订单仍有效，只补发一次当前剩余时间提醒，不连续补发 15 分钟和 5 分钟两条历史提醒。
- 用户点击“立即续租”后进入原订单续租流程；点击关闭或“暂不续租”不改变订单状态。
- 续租失败必须立即说明失败原因和剩余时长，不得让用户误以为续租已经成功。

## 5. 到期前续租

### 5.1 续租页面

续租页面展示：

- 游戏、版本和当前租赁账号状态。
- 原到期时间。
- 可选续租套餐和价格。
- 续租后的新到期时间。
- 原账号后续可用时长限制。

### 5.2 续租计算与支付

- 续租时长从原 `expire_at` 顺延，不从点击时间或支付时间重新起算。
- 续租生成独立支付交易和续租记录，但继续延长原租赁服务订单的 `expire_at`，便于支付对账且不打断当前游戏会话。
- 支付成功前不延长租期。
- 支付成功后服务端更新 `expire_at`，返回新的到期时间；客户端刷新倒计时并重新生成 15 分钟、5 分钟提醒任务。
- 续租成功后不退出游戏、不重新上号、不重新下载。

### 5.3 账号预约冲突

- 续租提交和账号后续预约校验必须在同一事务或等价的原子并发控制中完成。
- 原账号后续已有预约时，只展示当前最多可续时长，用户需缩短续租时长后重新提交。
- 原账号完全无法继续占用时，提示“当前账号后续时段已被预约，暂时无法续租”；当前订单仍按原到期时间结束，到期后用户可重新租用。
- 第一期不在有效订单中途自动换号，避免重登、存档同步及游戏中断风险。

### 5.4 跨到期支付

- 续租支付必须在原订单到期前成功。
- 到期前仍未支付成功时，原订单正常结束，续租支付单自动关闭。
- 已关闭续租单收到迟到支付回调时，不得重新占用已释放账号或延长已结束订单，应按幂等规则发起原路退款并记录异常日志。

## 6. 到期处理

### 6.1 游戏进行中

到达 `expire_at` 且续租未成功时：

1. 服务端原子地将订单置为已完成并撤销租赁权限。
2. 客户端触发一次可保存进度的正常退出流程。
3. 立即结束订单目标游戏。
4. 清理租赁 Steam 会话及本地租赁凭证。
5. 释放账号资源，供后续订单使用。
6. 提示“租期已结束，游戏已退出”，提供“重新租用”和“返回首页”。

到期不提供额外宽限时间。

### 6.2 游戏未运行

- 到期后直接撤销租赁会话、清理租赁凭证并释放账号。
- 订单状态更新为已完成。
- 不删除游戏安装包、本地配置或个人存档。

### 6.3 异常兜底

- 客户端关闭、休眠或断网不得阻止服务端按时撤销权限和回收账号。
- 客户端恢复后应立即同步服务端状态，并清理仍残留的过期租赁会话。
- 强制结束、会话撤销或账号释放失败需重试并告警；后台订单详情展示具体失败步骤。

## 7. 到期后的安装包启动拦截

### 7.1 启动校验

每次启动本地游戏前，校验：

1. 当前登录主体是否使用自己的 Steam 账号。
2. 用户自己的 Steam 账号是否拥有目标游戏。
3. 是否存在与目标游戏和版本匹配的有效租赁订单。
4. 租赁凭证是否有效且未超过 `expire_at`。

### 7.2 处理分支

| 场景 | 处理 |
|---|---|
| 个人 Steam 账号拥有该游戏 | 按个人游戏正常启动，不触发租号拦截 |
| 有有效租赁订单 | 正常建立租赁会话并启动 |
| 租期已结束且本地有安装包 | 拦截启动，提示“该游戏租期已结束，重新租用后可继续游戏” |
| 无网络或状态校验失败 | 不放行租赁游戏，提示“租赁状态验证失败，请检查网络后重试” |

过期拦截弹窗操作为“取消”和“重新租用”。重新租用成功后，如果本地安装包版本可用则直接上号启动；版本不一致时才提示更新，不重复完整下载。

## 8. 确认订单页价格展示

### 8.1 游戏原价

- 游戏卡片上的“首单 5 折”标签移除。
- “游戏原价”继续表示游戏本体售价，例如 `¥198`。
- 游戏原价使用红色强调，但不使用删除线。

### 8.2 订单金额

- “首单 5 折”标签移动到“订单金额”附近。
- 首单用户同时展示当前版本、租期及小时数计算出的标准租赁价和优惠实付价。
- 标准租赁价使用删除线，例如 `¥6.8`；优惠实付价使用红色放大展示，例如 `¥3.4`。
- 首单优惠价按标准租赁价乘以 50% 计算，并沿用现有金额精度和舍入规则。
- 非首单用户不展示“首单 5 折”标签和删除线价，仅展示正常订单金额。
- 游戏本体原价不得作为订单金额的删除线价。

## 9. 租号运营中心操作记录

### 9.1 导航与覆盖模块

租号运营中心左侧导航新增“操作记录”，统一审计：

- 租号商品管理。
- 账号资源管理。
- 订单与售后。
- 效果统计。
- 系统设置。

### 9.2 记录范围

记录：

- 新建、编辑、复制、上下架、批量操作等商品变更。
- 账号新增、检测、释放、换号、上下架等资源操作。
- 订单补偿、退款审核、售后处理、强制结束等订单操作。
- 退款风控及其他系统规则配置。
- 账号详情、订单设备信息等敏感详情查看。
- 报表及数据导出。

不记录普通页面浏览、Tab 切换、搜索和筛选操作。

### 9.3 日志字段

| 字段 | 说明 |
|---|---|
| 操作时间 | 服务端接收并执行操作的时间 |
| 操作人 | 姓名、账号 ID；离职或停用后仍保留历史快照 |
| 所属模块 | 商品、账号、订单售后、效果统计或系统设置 |
| 操作动作 | 标准化动作名称及动作编码 |
| 操作对象 | 对象名称、类型和对象 ID |
| 修改前/修改后 | 仅保存发生变化的字段差异 |
| 操作结果 | 成功或失败 |
| 失败原因 | 错误码和可读原因；成功时为空 |
| 操作备注 | 审核、补偿、强制操作等场景的业务说明 |
| 请求 ID | 关联服务端请求、审计日志和问题排查 |

敏感凭据、支付密钥、完整设备指纹及其他禁止展示的信息不得写入日志正文。敏感业务字段按后台权限脱敏展示。

### 9.4 查询与导出

支持：

- 时间范围筛选。
- 操作人筛选。
- 所属模块筛选。
- 动作类型筛选。
- 成功/失败结果筛选。
- 对象 ID 精确筛选。
- 对象名称、动作和备注关键词搜索。
- 条件重置、分页、日志详情和按当前条件导出。

筛选条件可组合使用。导出需要独立权限，导出动作自身也写入操作日志。

### 9.5 审计规则

- 日志由服务端业务接口或统一审计中间件生成，不依赖前端上报。
- 操作失败也必须记录。
- 批量操作生成一条主日志并关联子结果，详情展示成功数、失败数和失败对象。
- 操作日志不允许运营人员编辑或删除。
- 日志默认保留 180 天。

## 10. 效果统计页调整

- 移除页面右上角“环比对比”按钮及相关交互状态。
- 保留“导出”按钮。
- 指标卡片中已有的涨跌比例继续展示，不因移除按钮而删除。

## 11. 数据埋点与指标

### 11.1 事件

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| `rental_expiry_reminder_show` | 15 分钟或 5 分钟提醒成功展示 | `order_id`, `reminder_stage`, `remaining_seconds`, `scene` |
| `rental_expiry_reminder_action` | 用户关闭提醒或点击续租 | `order_id`, `reminder_stage`, `action` |
| `rental_renewal_submit` | 提交续租 | `order_id`, `renewal_order_id`, `package_code`, `new_expire_at` |
| `rental_renewal_result` | 续租成功、失败或关闭 | `order_id`, `renewal_order_id`, `result`, `reason` |
| `rental_expiry_force_exit` | 到期结束目标游戏 | `order_id`, `exit_result`, `session_revoke_result`, `account_release_result` |
| `rental_expired_launch_block` | 过期安装包启动被拦截 | `order_id`, `game_id`, `block_reason` |
| `rental_rerent_result` | 从拦截页重新租用完成 | `source_order_id`, `new_order_id`, `result` |
| `rental_audit_log_export` | 导出操作记录 | `operator_id`, `filter_summary`, `export_task_id` |

### 11.2 核心指标

- 15 分钟和 5 分钟提醒到达率。
- 提醒到续租点击率。
- 续租支付转化率。
- 续租账号预约冲突率。
- 到期强制退出发生率及失败率。
- 过期安装包拦截到重新租用转化率。
- 到期相关投诉率和退款率。
- 操作日志生成成功率及导出使用率。

## 12. 验收标准

1. 每个有效订单在到期前 15 分钟和 5 分钟最多各出现一次顶部居中提醒，不出现 1 分钟提醒。
2. 游戏全屏、客户端前台、最小化及休眠恢复场景均按规则展示或补发提醒。
3. 续租时长从原到期时间顺延；续租成功不退出游戏、不重新上号。
4. 原账号后续有预约时只允许选择可续时长，完全冲突时不能支付续租。
5. 到期前未支付成功的续租单自动关闭，迟到支付回调不延长订单并进入原路退款。
6. 到期未续租时立即结束目标游戏、撤销租赁会话、释放账号并更新订单状态。
7. 到期后本地安装包仍存在时，租赁启动被拦截；重新租用成功且版本一致时无需重新下载。
8. 用户自己的 Steam 账号拥有游戏时不触发租号拦截。
9. 确认订单页的游戏原价标红且不划线；首单标签位于订单金额附近，标准租赁价划线，实付价标红放大。
10. 非首单用户不展示首单标签和划线订单价。
11. 操作记录覆盖五个后台模块的修改、敏感查看和导出，普通浏览与筛选不生成日志。
12. 操作记录支持时间、操作人、模块、动作、结果、对象 ID 和关键词组合筛选，详情可查看修改差异。
13. 操作失败、批量操作和日志导出均产生可追踪的审计记录，运营人员不能编辑或删除日志。
14. 效果统计页不再出现“环比对比”按钮，导出按钮和指标卡涨跌比例保持不变。

## 13. 实施边界

后续实施需同步更新：

- `Mac端demo/mac端租号功能/Mac端租号功能-标注版.html`
- `prd/【盖世游戏Mac】游戏租号需求/【Prd】《盖世游戏Mac》游戏租号需求.md`
- 对应结构化交互标注、Smoke 测试、截图脚本和 PRD 截图。

实施不得覆盖工作区内与 Mac 租号无关的现有修改；Git 操作必须使用完整远端引用 `refs/remotes/origin/master`，避免与本地同名分支混淆。
