# Mac 原生游戏版本切换弹窗与安装入口细化设计

## 1. 结论

“切换版本”只负责改变详情页当前选择的游戏版本，不承担下载或安装操作。

弹窗展示该产品支持的全部版本，但每行只显示版本 Icon、版本名称和切换操作，不显示是否安装、文件大小或其他说明。用户选择未安装版本后，详情页主按钮变为该版本的下载按钮；用户再次点击详情主按钮时，才进入现有“安装路径”弹窗。

本设计覆盖 `2026-08-06-mac-native-game-screenshot-replica-design.md` 中与版本切换弹窗、未安装版本选择和安装入口相关的旧规则，其他页面范围与视觉基准保持不变。

## 2. 解决的问题

- 当前 Demo 将版本切换和安装动作合并，点击未安装版本会直接进入安装弹窗，偏离真实产品入口。
- 当前版本弹窗使用自创的版本管理卡片，展示安装状态、文件大小和说明文案，视觉密度与原 Mac 客户端不一致。
- 当前按钮热区、整行是否可点击和关闭区域缺少明确约束，容易产生误触或实现分歧。

## 3. 视觉设计

### 3.1 弹窗外框

- 复用原“安装路径”弹窗的视觉语言：居中遮罩、背景模糊、深色背景、细描边、圆角和阴影。
- 逻辑画布继续使用 `1076×734px`。
- 弹窗宽度使用 `548px`，与现有安装弹窗保持一致。
- 标题“切换版本”居中；关闭图标位于右上角。
- 不增加副标题、说明文案、Toast 或底部确认区。

### 3.2 版本列表

每行仅包含：

- 版本 Icon。
- 版本名称，例如“Steam”“Mac 原生版”。
- 当前选择态或“切换”按钮。

明确禁止展示：

- 已安装、未安装或下载中等状态文案。
- 文件大小。
- “下载并切换”“安装”等按钮文案。
- 卡片式大图标、版本说明或额外标签。

当前选择版本使用轻微行背景高亮和右侧对勾表达，不显示“当前使用”按钮。其他版本右侧显示“切换”按钮。

### 3.3 点击区域

- 版本整行不可点击，鼠标样式保持默认。
- 只有右侧“切换”按钮触发版本选择，按钮命中区为 `88×44px`。
- 关闭按钮命中区为 `44×44px`，视觉图标保持原尺寸。
- 详情主按钮的整个胶囊区域可点击。
- “…”仅圆形按钮区域可点击，不扩大到主按钮或周边留白。

## 4. 交互流程

### 4.1 打开弹窗

1. 用户进入游戏详情。
2. 点击详情主按钮右侧的“…”按钮。
3. 在紧凑菜单中点击“切换版本”。
4. 当前详情页打开版本切换弹窗。

### 4.2 切换至已安装版本

1. 用户点击目标版本右侧“切换”。
2. 更新详情页当前选择版本和默认启动版本。
3. 关闭版本切换弹窗。
4. 详情主按钮显示目标版本 Icon＋“开始游戏”。
5. 原已安装版本继续保留。

### 4.3 切换至未安装版本

1. 用户点击目标版本右侧“切换”。
2. 只更新详情页当前选择版本，不改变实际默认启动版本。
3. 关闭版本切换弹窗，不自动打开安装弹窗。
4. 详情主按钮显示目标版本 Icon＋`下载 XXX.X MB`。
5. 用户点击详情主按钮。
6. 打开原图中的“安装路径”弹窗，在其中选择安装位置和游戏版本。
7. 安装成功后，目标版本成为默认启动版本，详情主按钮变为“开始游戏”。

### 4.4 关闭和取消

- 未执行“切换”时关闭弹窗，不改变当前选择版本和默认启动版本。
- 选择未安装版本后取消安装、下载失败、路径失效或空间不足时，默认启动版本保持不变。
- 失败或取消后，详情页仍保留用户选择的目标版本，主按钮继续显示下载入口，允许再次点击重试。
- 不自动删除任何已安装版本。

## 5. 状态模型

|状态|作用|更新时机|
|---|---|---|
|`selectedVersion`|驱动版本弹窗的对勾、详情页平台 Icon、大小和主按钮文案|用户点击“切换”后更新|
|`activeVersion`|实际默认启动的已安装版本|切换到已安装版本或新版本安装成功后更新|
|`installedVersions`|记录已安装版本集合|安装成功后新增，切换版本不删除|

规则：

- 版本弹窗的当前选择态以 `selectedVersion` 为准，不以安装状态为准。
- `selectedVersion` 已安装时，详情主按钮显示“开始游戏”。
- `selectedVersion` 未安装时，详情主按钮显示“下载大小”。
- 安装取消或失败不得修改 `activeVersion` 和 `installedVersions`。

## 6. 安装路径弹窗

安装路径弹窗继续按原截图复刻，不改变既有结构：

- 游戏摘要中展示封面、名称、所需空间和平台信息。
- 安装位置区域支持选择路径。
- 游戏版本区域支持展开和选择版本。
- 底部保留“已入库”和“安装游戏”按钮。
- 安装状态、文件大小和路径信息只在详情主按钮与安装弹窗中出现，不回流到版本切换弹窗。

## 7. 异常与边界

- 当前产品只有一个版本时，不展示“切换版本”菜单项。
- 重复点击当前选择版本不产生操作；当前行没有“切换”按钮。
- 快速连续点击“切换”只处理第一次有效点击，弹窗关闭后忽略后续事件。
- 安装弹窗关闭后返回详情，不重新打开版本切换弹窗。
- 页面刷新后 Demo 恢复初始评审状态，不要求持久化。

## 8. 验收标准

- 版本切换弹窗与原安装弹窗的背景、宽度、圆角、标题、关闭按钮和遮罩风格一致。
- 弹窗内不出现“已安装”“未安装”“当前使用”、文件大小或安装说明。
- 所有支持版本均可见；当前选择行以高亮和对勾表达，其他行只有“切换”按钮。
- 版本整行不可点击；“切换”和关闭按钮的命中区分别达到 `88×44px` 和 `44×44px`。
- 选择未安装版本后不会自动打开安装弹窗，详情主按钮会更新为对应版本的下载入口。
- 只有点击详情主按钮才打开安装路径弹窗。
- 切换已安装版本、选择未安装版本、取消安装、安装失败和安装成功五条链路状态正确。
- 视觉、交互和状态变化均不新增 Toast、二次确认或独立设置页面。

## 9. 方案快速评审

- 用户视角：选择与安装分开后路径清晰；详情主按钮变为“下载”能够提供明确反馈。
- 开发视角：`selectedVersion` 与 `activeVersion` 分离，能避免未安装版本选择、取消或失败污染实际启动版本。
- 商业视角：方案只修改现有弹窗和详情按钮状态，不增加页面与运营能力，范围最小。
