# 开发者平台与财务结算整合设计

> 状态：已确认方案 A。用于生成新的开发者平台整合 Demo，不覆盖既有开发者平台、财务结算或运营后台 Demo。

## 1. 目标

将既有开发者平台与开发者财务结算能力合为一个离线单文件 Demo，使开发者完成登录、入驻、企业认证、游戏管理、经营数据、厂商设置和财务结算时始终处于同一平台、同一地址和同一视觉体系。

本次解决三个问题：

1. 财务结算仍使用独立地址，开发者需要离开平台。
2. 现有财务 Demo 与开发者平台的顶栏、颜色、导航和场景入口不一致。
3. 企业认证、厂商设置和财务主体存在结算资料重复入口。

## 2. 输入与输出

### 2.1 输入

- demos/开发者后台一期/开发者平台demo.html：统一开发者平台基线。
- demos/开发者后台一期/15-开发者财务结算demo.html：财务业务、状态和交互基线。
- demos/开发者后台一期/src/：开发者平台构建、样式和运行时源文件。
- tests/developer-backend/developer-finance-settlement.browser.test.mjs：财务专项回归基线。
- tests/developer-backend/developer-portal-*.browser.test.mjs：开发者平台回归基线。

### 2.2 输出

- 新文件：demos/开发者后台一期/开发者平台财务整合demo.html。
- 原 开发者平台demo.html、15-开发者财务结算demo.html 和兼容别名保持不变。
- 新 Demo 为单文件 HTML，不加载外部脚本、样式、图片、接口或 iframe。

## 3. 范围

### 3.1 包含

- 原开发者平台全部开发者端页面和交互。
- 财务主体。
- 对账结算。
- 对账流水次级页面。
- 结算详情、账单确认、差异、发票、付款状态和付款凭证。
- 中英文、资格门禁、场景切换、刷新恢复、浏览器前进后退和响应式。
- 经营数据、厂商设置与财务模块的站内联动。

### 3.2 不包含

- 发行平台运营后台。
- 平台财务审核后台。
- 支付商工作台。
- 自动出款、真实文件上传、真实验证码、真实通知和服务端持久化。
- 对旧 Demo 的结构或视觉整改。

## 4. 信息架构

认证通过后的厂商级侧栏为：

    游戏
    └─ 游戏管理

    财务
    ├─ 财务主体
    └─ 对账结算

    厂商管理
    └─ 厂商设置

- 财务属于厂商级，不进入单游戏侧栏。
- 对账流水不是一级入口，从“对账结算—查询流水”进入。
- 进入单游戏详情后继续使用原单游戏侧栏；返回全部游戏后恢复厂商级导航。
- 旧“付款记录”不恢复为一级入口，付款并入结算记录和详情。

## 5. 路由

新 Demo 在原开发者路由之外增加三个只供整合版使用的路由：

| 路由 | 页面 | 规则 |
|---|---|---|
| #/P15-01 | 财务主体 | 厂商级一级页面。 |
| #/P15-02 | 对账结算 | 厂商级一级页面，侧栏高亮“对账结算”。 |
| #/P15-03 | 对账流水 | 次级页面，侧栏仍高亮“对账结算”。 |

路由规则：

1. 未登录直达财务路由时进入登录，登录后恢复目标路由。
2. 未完成开发者注册时进入注册选择，完成后恢复目标路由。
3. 企业认证未通过时进入企业认证状态页，并以一行说明提示财务能力需认证通过后使用。
4. 已认证账号刷新财务路由时直接恢复当前页面和当前语言。
5. 浏览器前进、后退切换页面时关闭旧页面抽屉和确认框，不残留遮罩或焦点。
6. P15-03 的面包屑为“开发者平台／财务／对账结算／对账流水”，返回后恢复 P15-02 的筛选、页码和滚动位置。

## 6. 页面框架与视觉

### 6.1 统一框架

- 复用开发者平台的深蓝顶栏、白色侧栏、青色品牌色、内容背景、卡片、表格、按钮、表单、抽屉和确认框。
- 不保留财务 Demo 的黄色 Logo、黄色按钮或第二套顶栏。
- 复用原账号区、帮助中心入口、中英文切换和全局场景悬浮球。
- 每页只显示一个主标题；面包屑单独显示，不增加蓝色眉题或重复副标题。

### 6.2 财务页面

- 财务主体保留申请状态、生效版本、付款状态、主体资料、收款资料、税务资料和历史版本。
- 对账结算保留指标摘要、六项筛选、每页 20 条、查询流水和导出。
- 结算详情继续使用单层右侧抽屉；顶部和底部固定，正文独立滚动。
- 对账流水保留三本账、关联结算单、每页 20 条和安全导出。
- 1440px 与 1280px 使用桌面表格；390px 不产生根节点横向溢出，表格仅在内容区滚动。

## 7. 重复入口收口

### 7.1 企业认证

- 企业认证继续保存提交时的主体和银行证明快照，用于认证审核及历史回溯。
- 认证通过后，企业认证页不再作为结算资料编辑入口。
- 后续收款账户、税务资料和财务联系人以“财务主体”的生效版本为唯一结算来源。

### 7.2 厂商设置

- “财务信息”改为只读摘要，展示财务主体状态、结算币种和脱敏收款账户。
- 只提供“前往财务主体”，不在厂商设置保存另一份收款或税务资料。
- 财务主体尚未配置时，摘要展示未配置并进入 P15-01。

### 7.3 经营数据

- 经营数据中的结算内容只作只读摘要。
- “查看正式对账”在同一 HTML 内进入 P15-02，不再跳转 15-开发者财务结算demo.html。
- 如果摘要带有账期或业务来源，进入对账结算后自动应用筛选；返回经营数据时保留原查询条件。

## 8. 状态与门禁

| 场景 | 入口 | 页面权限 |
|---|---|---|
| 未登录 | 财务深链可访问 | 登录后恢复目标路由。 |
| 未注册开发者 | 不进入财务内容 | 完成注册后恢复目标路由。 |
| 企业认证未通过 | 财务入口可识别 | 进入认证状态页，不能编辑或对账。 |
| 财务主体未配置 | 财务主体显示配置入口 | 可查看预估或草稿账单，不能确认正式账单或提交差异。 |
| 财务主体审核中 | 当前申请只读 | 首次申请未生效时继续限制正式财务操作。 |
| 财务主体已生效 | 全部入口可用 | 按账单状态确认、提出差异或提交发票。 |
| 敏感变更审核中 | 旧版本继续生效 | 仅暂停付款；历史核账和差异仍可操作。 |
| 企业资格暂停或停用 | 页面保留历史查看 | 禁止新增主体申请和新的财务写操作。 |

## 9. 场景与语言

### 9.1 场景入口

- 全站只保留一个右下角场景悬浮球。
- 在财务页面打开时提供“穷举态／缺省态”；默认穷举态。
- 在原开发者页面打开时继续使用原页面场景，不生成第二个悬浮球。
- 切换场景只替换演示数据，不写公共存储；保留当前一级页面并回到第 1 页。

### 9.2 中英文

- 顶栏语言切换对财务标题、导航、筛选、状态、表单、按钮、抽屉、确认框、缺省和错误文案同时生效。
- 金额、币种、编号和日期值不翻译；状态展示翻译但状态码不变。
- 切换语言不重置筛选、页码、表单草稿或抽屉上下文。

## 10. 交互保留

从财务专项 Demo 保留：

- 财务主体首次配置、变更、字段联动、附件状态、撤销审核二次确认和历史版本。
- 银行地区、账号或 SWIFT／BIC 变化后要求重新上传账户证明。
- 结算单筛选、分页、确认账单、四类差异、发票提交和导出。
- 付款失败、退回、部分付款、合并付款、多次付款尝试和凭证门禁。
- 详情抽屉默认展开当前待办区块，底部操作固定。
- 抽屉和确认框的焦点锁定、Esc 关闭和焦点恢复。

合并时不增加：

- 第二层抽屉。
- 页面间成功弹窗。
- 不必要的 Toast、说明卡或状态提示。
- 开发者主动打款、标记到账或修改平台账单。

## 11. 技术结构

### 11.1 构建

- 在现有构建流程增加整合版构建目标，默认构建结果和原兼容别名不变。
- 整合版使用开发者平台模块配置、页面数据和运行时，再追加财务路由、财务样式和财务运行时。
- 财务路由只存在于整合版的内嵌路由清单，不增加运营后台路由，也不改变既有 PRD 路由契约。

### 11.2 模块边界

新增文件固定为：

- src/styles/publisher-finance.css：只负责统一壳下的财务布局和组件变体，所有选择器以财务根节点为范围。
- src/runtime/publisher-finance.js：负责财务数据、渲染、筛选、表单、抽屉、导出和场景状态。
- tests/developer-backend/developer-platform-finance-integration.browser.test.mjs：负责整合路由、跨模块联动、视觉和原文件不回归。

财务运行时通过明确接口接入平台：

- renderFinancePage(routeId, context)：返回当前财务页面内容。
- handleFinanceAction(event, context)：处理财务范围内动作。
- getFinanceNavigation(routeId, language)：返回侧栏和面包屑状态。
- setFinanceScenario(scenario)：切换穷举态或缺省态。

不得把 15-开发者财务结算demo.html 整页字符串、第二套应用壳或 iframe 注入新文件。

## 12. 数据与状态

- 原开发者平台登录、注册、认证、游戏和厂商状态继续由现有会话内存管理。
- 财务状态挂到同一内存对象的独立 finance 域，不使用另一套全局状态。
- 财务主体快照、结算单、流水、差异、发票和付款尝试保持原数据结构及整数金额口径。
- 路由切换清理临时覆盖层，但不清空已应用筛选、分页、表单草稿或当前语言。
- 刷新恢复初始演示数据；不使用远程持久化或跨 Demo LocalStorage。

## 13. 异常处理

- 财务数据加载失败时保留统一页面框架、筛选和重试入口。
- 业务写操作失败时保留原状态和输入，按钮恢复可用。
- 状态冲突时展示服务端最新状态的模拟结果，不覆盖已有记录。
- 导出失败不生成空文件；付款无真实回执时不显示下载入口。
- 切换路由、语言或场景时关闭已失效的抽屉和确认框，避免遮罩残留。

## 14. 验证范围

### 14.1 功能

1. 原登录、注册、认证、游戏管理、游戏详情、数据总览、厂商设置和帮助中心可用。
2. 三个财务深链可直达、刷新恢复并支持浏览器前进后退。
3. 对账流水返回后保留对账结算的筛选、页码和滚动位置。
4. 数据总览和厂商设置跳转财务时留在同一 HTML。
5. 财务主体门禁、账单确认、差异、发票和付款追踪与财务专项 Demo 一致。
6. 全站只有一套顶栏、侧栏、帮助中心和场景悬浮球。

### 14.2 回归

- 原开发者平台专项测试继续通过。
- 财务专项测试迁移到整合版后继续通过。
- 默认构建输出及原两个 HTML 的内容不因整合版构建改变。
- 新文件无外部依赖、无 iframe、无重复 ID、无运行时错误。

### 14.3 视觉

- 检查 1440×900、1280×800 和 390×844。
- 财务页面使用开发者平台的深蓝、青色、字体、圆角、间距和表格规范。
- 标题、面包屑、筛选、固定操作区、分页和悬浮球无遮挡。
- 中英文均无截断、错位或中文残留。

## 15. 三视角审查

- 用户视角：通过。财务保持厂商级，两入口路径清晰；需确保旧财务外链改为站内跳转并消除三处可编辑财务资料。
- 开发视角：有条件通过。须使用统一壳、单一状态和整合版专用路由，不能复制第二套应用或破坏既有构建契约。
- 商业视角：通过。只整合开发者端财务闭环，不引入平台财务或支付商后台；经营数据继续只作摘要。
