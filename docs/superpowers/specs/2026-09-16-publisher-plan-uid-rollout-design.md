# 发行人计划 UID 灰度设计

> 日期：2026-09-16｜状态：已确认

## 1. 目标

发行人计划只能使用现有账号灰度能力。未登录用户没有 UID，因此不展示发行人计划；登录后按 UID 稳定分桶，逐步从 20% 扩至 50% 和 100%。灰度只限制新入口和新业务关系，不中断已产生的任务、投稿、结算、奖励和兑换权益。

## 2. 采用方案

### 2.1 身份规则

- 未登录：不展示发行人计划入口；通过功能链接直达时先完成登录，再按 UID 判断。
- 已登录且 UID 命中：展示入口，可浏览并发起新操作；发布、投稿和兑换仍执行实名、认证、余额、任务状态等业务校验。
- 已登录且 UID 未命中、无存量：不展示入口，不允许建立新任务或投稿关系。
- 已登录且 UID 未命中、有存量：保留本人任务、投稿、钱包、奖励和订单的必要入口，只允许继续处理存量，不允许新增。
- 同一设备切换账号：清除上一账号的私有缓存，按新 UID 重新判断；功能可能出现或消失。
- 同一 UID 更换设备、重启 App 或重新登录：灰度结果不变。

### 2.2 UID 选择规则

服务端对每个有效 UID 计算稳定桶值：

```text
bucket = stable_hash(feature_key + rollout_round + uid) % 10000
```

- 20%：`bucket` 为 0～1999。
- 50%：`bucket` 为 0～4999。
- 100%：`bucket` 为 0～9999。
- 同一灰度轮次固定 `feature_key`、`rollout_round` 和分桶算法，只调整比例；因此原 20% 用户一定包含在 50% 中。
- 不按注册时间、活跃度、消费、等级、粉丝量或 UID 尾号选人。
- 内部测试账号使用独立白名单，不计入正式灰度比例和正式数据。
- 实名、创作者认证、余额、次数、风控等属于业务校验，不参与 UID 分桶。

### 2.3 存量关系

以下服务端记录属于存量：

- 已生成任务记录或已冻结／待退回预算。
- 已建立任务参与关系或已生成投稿记录。
- 已确认待发奖励或已有可兑换余额。
- 已生成兑换订单。

仅浏览、收藏、分享、打开创建页或保存在本地但尚未成功提交的表单不属于存量。

灰度缩量、关闭或配置异常后，存量用户仍可查看和处理本人记录。已获得的可兑换奖励继续允许兑换；兑换仍检查登录、实名认证、余额、库存和订单状态，但不再检查当前灰度资格。机器审核、取数、结算、退款、发奖及回调按已有业务记录继续推进，不重新检查灰度。

### 2.4 服务端边界

- 客户端只负责展示，所有新增操作由服务端按最新配置和 UID 最终判断。
- 旧客户端或缓存残留按钮不能绕过服务端；被拒绝时不得创建记录、冻结预算、扣币或预占卡密。
- 同一幂等请求已成功时，灰度随后关闭也返回原结果，不重复创建或改成失败。
- 灰度配置读取失败时停止新入口和新关系，存量处理继续。
- 同一轮灰度不得更换分桶规则；需要重新抽样时创建新的灰度轮次，不能静默洗牌。

## 3. 页面结果

| 用户状态 | 入口与页面 | 新操作 | 存量处理 |
|---|---|---|---|
| 未登录 | 不展示入口；功能直达先登录 | 不允许 | 无账号数据 |
| UID 命中 | 展示完整入口和页面 | 允许，继续业务校验 | 允许 |
| UID 未命中且无存量 | 不展示入口 | 不允许 | 无 |
| UID 未命中但有存量 | 只保留本人记录与资产入口 | 不允许新增 | 允许 |
| 总开关关闭或配置异常 | 停止新入口 | 不允许新增 | 允许 |

## 4. 后台配置

- 总开关：开启／关闭。
- 灰度比例：20%、50%、100%，不支持任意比例。
- 灰度轮次与分桶依据：服务端维护，后台只读。
- 配置版本：每次保存递增，旧版本提交不得覆盖新版本。
- 操作记录：保存修改人、时间、修改前后值、结果和失败原因。
- 内部白名单：与正式灰度分开管理、分开统计。

## 5. 数据口径

- 灰度主体统一为 UID，不再统计安装设备主体。
- 分别记录 `gray_hit` 与 `business_allowed`，避免把未实名、未认证或余额不足统计成灰度故障。
- 入口曝光、点击和页面成功率均按 UID、灰度比例、配置版本和 App 版本统计。
- 同一 UID 分桶稳定率必须为 100%；20% 扩至 50% 时原 20% UID 保留率必须为 100%。
- 内部白名单账号从正式比例、正式转化和放量判断中排除。

## 6. 放量与止损

| 阶段 | 最短观察 | 最低技术样本建议 |
|---|---:|---:|
| 20% | 24 小时 | 核心读取不少于 1,000 次；每个关键写操作不少于 50 次 |
| 50% | 48 小时 | 核心读取不少于 5,000 次；每个关键写操作不少于 200 次 |
| 100% | 重点观察 72 小时 | 持续监控，不作为扩量门槛 |

时间和样本同时满足后才能扩量。正式数值需在上线前按真实流量校准；业务点击率、投稿量只观察，不作为技术扩量硬门槛。

任一资金、奖励、卡密、错账、越权、数据丢失、灰度绕过或重大合规问题立即关闭新增能力；关闭不撤销存量记录和权益。

## 7. 必测场景

- 未登录、UID 命中、UID 未命中无存量、UID 未命中有存量。
- 同一 UID 多设备、同一设备切换多个账号、退出登录、Token 过期。
- 20% 边界 1999／2000，50% 边界 4999／5000，20%→50%、50%→20%、关闭和恢复。
- 入口、功能直达、旧通知、旧客户端残留按钮和接口直调。
- 已有任务、参与关系、投稿、奖励余额和兑换订单在缩量或关闭后的访问与处理。
- 配置读取失败、非法比例、并发保存、版本冲突和灰度关闭瞬间提交。
- 客户端伪造 UID、桶值、比例或允许结果；重复提交和超时重试不得产生重复业务结果。

## 8. 明确不做

- 不使用设备 ID、安装 ID 或未登录会话进行灰度。
- 不增加任意百分比、人群标签组合或运营手工圈选。
- 不把实名认证、创作者认证或风控结果混入 UID 分桶。
- 不新增未确认的页面、弹窗、Toast 或复杂审批流。
