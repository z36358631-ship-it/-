# 开发者平台渠道分销整合设计

> 状态：已确认
> 日期：2026-09-14
> 修订：V2，从结果看板补齐为开发者端到端流程
> 依据：PRD-13「盖世 Key 与渠道分销」、原开发者平台 Demo、2026-09-14 已确认拆解

## 1. 目标与用户问题

将渠道分销放入开发者的单游戏控制台，让已签约企业开发者在一个地方完成授权查看、批次申请、处理结果、交付跟踪、渠道数据和收益结算查看。

当前 Demo 只展示合作生效后的聚合数据，开发者无法创建 Key 批次，也看不到审核、生成、交付和异常闭环。没有平台时，这些信息需要通过邮件、即时沟通和表格反复确认。

## 2. 角色边界

- 开发者：查看本厂商、本游戏的授权计划；在计划额度内创建批次申请；查看脱敏交付、销售、兑换、异常及自身收益。
- 平台运营：配置渠道、合同快照、授权计划、额度和风险规则；审批高风险批次；必要时暂停计划。
- 外部渠道：通过专用 API 取得 Key，确认接收并回传销售、退款和拒付事实。
- 财务：处理平台与渠道、平台与开发者的正式对账和付款。

开发者页不展示 Key 明文、渠道 Secret、玩家身份、平台与渠道的内部合同单价或「待渠道确认」操作。批量文件交付仅由经授权的平台人员执行。

## 3. 入口和主流程

入口保持：

`开发者平台首页 → 登录／认证 → 游戏管理 → 选择游戏 → 单游戏控制台 → 发行与供给`

开发者主流程：

`查看分销状态 → 查看授权计划 → 创建 Key 批次 → 额度／风险校验 → 自动生成或人工审核 → 查看结果 → 跟踪交付 → 查看销售／退款／拒付／兑换 → 查看异常 → 查看月度收益与结算`

开通或合作流程允许在包体或游戏资质未完成时继续，不在入口阻断。正式生成可售 Key 或开放渠道销售前，再校验 SKU 是否满足发行条件。

## 4. 信息架构

不新增一级导航，单游戏下保留四项。

### 4.1 渠道分销

- 显示未开通、待生效、合作中、暂停、终止。
- 显示当前授权计划、剩余额度、有效期、交付方式和待办事项。
- 计划详情显示渠道、APPID、Product／SKU、地区、用途、总额度、日额度、单次上限和有效期。
- 未开通时说明「邀请制渠道合作」，不新增线上渠道入驻申请。

### 4.2 Key 批次

- 提供「创建 Key 批次」，只允许在生效计划内提交。
- 表单包含授权计划、数量、用途、交付方式和有效期，实时显示剩余额度。
- 额度内普通 API 批次自动生成；新渠道、超单次上限、批量文件、免费推广、测试、补偿、敏感地区或风险异常进入人工审核。
- 结果覆盖生成中、审核中、已拒绝、生成失败、可用；拒绝可修改重提，生成失败可重试。
- 详情显示总量、可用、分配待确认、已暴露未兑换、已兑换、过期和作废。

### 4.3 渠道数据

- 按渠道、SKU、地区和月份筛选。
- 用「交付记录」「销售与兑换」「异常记录」区分分配、接收、销售、退款、拒付和兑换事实。
- 异常覆盖接收确认超时、已兑换但销售未回传、退款异常和计划暂停；开发者只查看原因、影响和平台处理进度。
- 页面和导出只使用 Key 掩码或不可逆指纹。

### 4.4 收益与结算

- 按自然月显示渠道售出、退款、拒付、历史调整和预估渠道销售净额。
- 开发者页不暴露平台与渠道的内部结算单价和渠道确认操作。
- 开发者正式应收、开票和付款继续由「财务与结算」模块处理；本页保留口径说明和入口。
- 锁单后的迟到退款或拒付进入下期调整，不改旧账单。

## 5. Demo 状态与交互

- 复用既有「Demo 状态」悬浮工具，渠道页显示「未开通／合作中／暂停」和「自动生成／审核中／已拒绝／生成失败」，不把演示控件放进正式业务区。
- 计划详情、创建批次、批次详情、异常详情和月度结算详情使用现有弹窗规格。
- 开发者可以从拒绝态修改重提，从生成失败态重试，但不能直接通过高风险申请。
- 英文跟随开发者平台语言；业务 ID、SKU、币种和 API 事件保持原文。
- 手机端保留四个横向功能入口，卡片单列，表格在内容区滚动，根节点不横向溢出。

## 6. 业务口径

- 仅处理盖世 Key 出站渠道分销，不包含 Steam、Epic 等外部 Key 入站。
- `sale_confirmed` 是渠道销售净额的唯一正向事件；分配、接收和兑换不单独计收入。
- `refund_confirmed` 和 `chargeback_lost` 负向冲减，同一销售不得重复冲减。
- 已暴露 Key 不得回库；确认超时只告警，不自动回库。
- 开发者只能查看本厂商、本游戏脱敏数据。

## 7. 验收

1. 同一 HTML 可完成首页、登录、进入游戏和渠道分销主流程。
2. 四个功能入口不变，内部可完成计划查看、批次创建、处理结果、交付、异常和月结查看。
3. 渠道状态覆盖未开通、合作中和暂停；批次结果覆盖自动生成、审核中、已拒绝和生成失败。
4. 未开通和暂停状态不能创建批次；已拒绝可重提，生成失败可重试。
5. 开发者页和导出不得出现 Key 明文、Secret、玩家身份或平台与渠道的内部结算操作。
6. 桌面和 320／390px 手机端无根节点溢出、浮层裁切或核心操作遮挡。
7. 页面为离线单文件，不依赖远程脚本、样式、图片、接口或 iframe。

## 8. 明确不做

- 不新增公开渠道入驻、开发者自选渠道、在线合同或自动打款。
- 不向开发者提供渠道凭据、Key 明文或平台与渠道的对账确认操作。
- 不把运营后台、渠道 API 联调或玩家兑换页合入开发者 HTML。
- 不新建工单中心、消息中心或独立审核中心；状态使用页内提示和邮件通知。
- 不修改旧 `02-CDKEY商品与供给demo.html`。
