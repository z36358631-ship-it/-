# 运营后台财务结算 Demo 设计

> 状态：已确认。先交付 Demo，PRD 在 Demo 确认后整理。

## 1. 目标

平台按月生成游戏结算记录，运营核对并导出给财务，由财务在线下完成对账和打款。后台不承担付款审批、执行或结果回填。

## 2. 页面结构

- 新建 `发行平台运营后台财务整合demo.html`，保留原运营后台 Demo。
- 左侧新增一级入口“财务结算”。
- 页面只有一个主标题和一张游戏结算表，不设置 Tab、详情抽屉或付款状态页面。
- 沿用运营后台的顶部、左侧导航、筛选、表格和分页样式。

## 3. 数据口径

- 一款游戏在一个结算月和币种下生成一条结算记录。
- 记录包含结算月、游戏、开发者、财务主体、销售额、退款、平台分成、调整额、应付金额和收款账户。
- 页面展示脱敏账户；导出文件包含完整银行、账号和 SWIFT/BIC 信息。
- 应付金额＝销售额－退款－平台分成＋调整额。

## 4. 操作

- 默认展示最近已完成结算的月份。
- 支持按结算月、游戏/开发者/财务主体和币种筛选。
- 支持勾选记录后导出；没有选择时导出全部筛选结果。
- 导出后只回写最近导出时间和导出人，不记录线下付款结果。
- 列表每页 20 条。

## 5. Demo 状态

- 默认穷举态，包含多游戏、开发者、财务主体、币种、正负调整和导出记录。
- 右下角状态球切换穷举态和缺省态。

## 6. 边界

不包含打款批次、付款条件、发票审核、付款成功或失败、付款凭证、付款尝试、线上审批、支付商 API、网银直连和自动打款。

## 7. 验收

- 原运营后台文件不变，新整合版可独立打开。
- 页面为单页单表，没有线上付款相关页面和状态。
- 筛选、分页、选择、导出和缺省态均可操作。
- 导出金额为可计算数值，包含完整收款字段。
- 1280×800 和 390×844 无页面级横向溢出。
