# Android 广告时长激励弹窗融合与全屏广告承载设计

日期：2026-07-28
关联 Demo：`demos/Android广告接入-交互标注版.html`
关联 PRD：`prd/ai生成/【Prd】《盖世游戏》Android广告接入需求-V2.0.md`

## 1. 背景与问题

当前 Demo 将 G1“秒玩时长不足”、激励视频播放页和广告落地页都实现成居中小弹窗，形成“业务弹窗上再叠广告弹窗”的效果，与盖世游戏原有提示样式及真实广告 SDK 的全屏链路不一致。

本次调整解决两个问题：

1. 时长不足提示与盖世游戏已有“提示”弹窗融合，不再单独使用粉紫色广告弹窗。
2. 用户主动选择看广告后，激励视频和广告落地页覆盖整个 App 页面，不再使用通用小弹窗。

## 2. 方案比较与结论

### 方案 A：原生业务弹窗 + SDK 全屏覆盖层（采用）

- 时长不足、签到结果、排队权益确认继续使用盖世游戏原生业务弹窗。
- 点击观看广告后关闭业务弹窗，打开覆盖整个 App 页面的激励视频层。
- 点击广告 CTA 后打开全屏广告落地页；关闭后恢复广告页或原业务页。
- Demo 模拟 SDK 页面；正式版本的倒计时、声音、反馈、关闭、落地页和外跳由广告 SDK 控制。

优点：符合真实 SDK 行为，层级清晰，业务与广告职责分离；用户返回时可恢复原页面状态。
代价：需要统一管理广告覆盖层、来源场景和奖励回调。

### 方案 B：把广告实现成 App 内普通路由页

优点：页面结构和返回栈完全由客户端控制。
缺点：容易误导研发把 SDK 广告页当成自研页面；真实广告落地页不一定能由 App 接管。

### 方案 C：继续使用居中弹窗

优点：Demo 实现简单。
缺点：广告素材无法完整展示，弹窗叠弹窗，和真实激励视频差异明显，因此废弃。

## 3. 方案快速评审

- 用户视角：全屏广告符合用户对激励视频的既有认知；业务提示和广告播放不再争抢视觉层级。
- 开发视角：业务弹窗只负责询问，SDK 只负责广告展示；奖励通过统一回调处理，边界更清晰。
- 商业视角：完整素材、卖点和 CTA 可见，曝光与点击价值优于小弹窗；仍保留用户主动触发和提前退出权。
- 风险处理：广告落地页可能由 SDK 打开内置页、应用商店或外部页面，PRD 不限定为盖世游戏详情页，仅要求返回时恢复业务状态。

## 4. 页面层级

从低到高的层级为：

1. 盖世游戏原业务页面。
2. 盖世游戏原生业务弹窗。
3. 广告 SDK 全屏激励视频页。
4. 广告 SDK 全屏落地页或系统应用商店。

同一时刻只允许展示一层业务弹窗或广告层。进入激励视频前必须先关闭原业务弹窗，不能出现两个居中卡片叠加。

Demo 中“全屏”指覆盖模拟设备的完整可视区域，不覆盖左侧导航、顶部 Demo 工具栏和右侧标注面板。正式 App 中覆盖整个 App 界面，系统状态栏和导航栏的显示方式遵循广告 SDK。

## 5. G1 时长不足提示融合

### 5.1 统一样式

- 复用盖世游戏现有深灰色“提示”弹窗。
- 标题固定为“提示”，右上角保留关闭按钮。
- 不使用原 Demo 的粉紫色“秒玩时长不足”广告卡。
- 底部保留两个明确操作：
  - 主按钮：`看广告得 5 分钟`
  - 次按钮：`前往充值`
- 右上角关闭按钮承担“暂不处理”。

### 5.2 两种业务状态

**低时长状态（剩余 1—14 分钟）**

- 正文：`游戏剩余时长不足 15 分钟，为保障您的进度，避免存档丢失或重置，请及时补充时长。`
- 补充：`完整观看约 15 秒广告，可获得 5 分钟云游戏时长。`
- 关闭弹窗后继续当前游戏流程。

**零时长状态（剩余 0 分钟）**

- 正文：`当前云游戏时长不足，暂时无法启动游戏。`
- 补充：`完整观看约 15 秒广告，可获得 5 分钟云游戏时长。`
- 关闭弹窗后返回原页面，不创建启动请求。

## 6. 全屏激励视频页

参考用户提供的激励视频截图，大致还原常见穿山甲激励视频结构，不复刻具体游戏和广告素材。

### 6.1 页面结构

- 顶部工具区：
  - 左侧：声音开关、反馈。
  - 右侧：剩余倒计时，如 `29s`。
- 主素材区：
  - 展示占据主要面积的视频/试玩素材。
  - 素材保持完整比例，允许裁切背景但不得裁掉标题、主要画面和 CTA。
- 卖点区：
  - 展示游戏名称、核心卖点和广告文案。
  - 持续显示 `Ad` 或 SDK 广告标识。
- 底部转化区：
  - 应用图标、应用名、评分或类型。
  - 主 CTA：`点击试玩`或 SDK 返回的原始文案。
  - 点击 CTA 进入全屏广告落地页。

横屏场景采用左右分栏：左侧主要视频画面，右侧展示卖点、应用信息和 CTA；竖屏场景采用从上到下排列。两种方向都必须覆盖完整设备画布。

### 6.2 Demo 控制

- 广告页内部不出现“完整观看”“提前关闭 / 播放失败”等研发模拟按钮。
- Demo 使用缩短的自动倒计时演示完整播放。
- “模拟播放完成”“模拟失败”放在 Demo 外部工具区或标注面板，不能混入用户真实界面。
- 倒计时未结束时允许按 SDK 规则提前关闭；提前关闭不发奖励。

## 7. 全屏广告落地页

- 点击激励视频 CTA 后，落地页覆盖整个设备画布。
- 顶部提供 SDK 返回/关闭控件。
- 页面展示广告主视觉、应用信息、卖点、截图/试玩区域和安装或试玩 CTA。
- 关闭落地页后：
  - 视频尚未完成：返回全屏视频页，保留原播放状态。
  - SDK 已返回完成回调：关闭广告链路并回到来源业务页。
- Demo 仅模拟一种 SDK 内置落地页；正式产品必须兼容 SDK 内置页、系统应用商店和外部浏览器三种结果。
- 不将广告落地页伪装成盖世游戏详情页。

## 8. 统一奖励链路

适用 C1 签到加倍、G1 零时长补充、Q1 排队加速和 R1 抽奖次数。

1. 用户在业务页主动点击广告权益入口。
2. 业务层保存来源场景、页面状态、滚动位置和待发权益。
3. 打开全屏激励视频。
4. 用户可点击 CTA 进入全屏落地页，再返回广告链路。
5. SDK 返回完整观看回调。
6. 服务端按 `reward_id` 校验并幂等发放。
7. 关闭广告层，恢复原业务页并更新权益结果。

提前关闭、无填充、播放失败、校验失败均不发放激励权益；原有基础权益和排队位置不受影响。

## 9. 场景差异

|场景|广告前业务层|完整观看后的结果|提前关闭后的结果|
|---|---|---|---|
|C1 签到加倍|签到结果弹窗，基础时长已到账|补发同等签到时长|保留基础时长|
|G1 零时长|原生“提示”弹窗|增加 5 分钟并继续创建启动请求|返回原页，不创建启动请求|
|Q1 排队加速|排队权益确认弹窗|进入加速通道并增加 5 分钟|保持原排队位置|
|R1 抽奖次数|活动任务入口|抽奖次数 +1|次数不变|

## 10. 状态与异常

- 广告展示期间来源页面业务状态继续保持，但不能重复发起第二个广告请求。
- App 切后台再回来时，由 SDK 恢复广告；SDK 无法恢复则按播放失败处理。
- 广告落地页外跳应用商店后，返回 App 时恢复 SDK 或来源业务页。
- 只有 SDK 完整观看回调和服务端校验均成功才展示“奖励到账”。
- 重复回调不得重复发放。
- 无填充时直接关闭广告加载状态并恢复业务弹窗或原页面，不留下黑屏。

## 11. Demo 与 PRD 验收

1. G1 使用盖世游戏原有深灰色提示弹窗，不再使用粉紫广告弹窗。
2. C1、G1、Q1、R1 进入广告后均覆盖完整设备画布。
3. 激励视频具备声音、反馈、倒计时、主素材、卖点、应用信息和 CTA。
4. 广告页内不存在“完整观看”等模拟按钮。
5. 点击 CTA 打开完整设备画布尺寸的落地页。
6. 关闭落地页能恢复视频或来源页面，不丢失页面和业务状态。
7. 完整观看、提前关闭、无填充、失败和重复回调均有可验证结果。
8. 横屏和竖屏均无素材裁断、按钮错位、文字重叠或双层弹窗。

## 12. O1 开屏广告视觉补充

用户提供的竖屏开屏广告截图作为 O1 广告阶段的结构参考，不复刻广告品牌和具体素材。

### 12.1 实现方式

采用“按参考图重建可交互结构”，不直接把竖屏截图拉伸成横屏素材：

- 方案 A（采用）：用 HTML/CSS 重建广告标识、跳过倒计时、中央主视觉、标题、动态上滑引导和“查看详情”入口；横竖屏分别排版。
- 方案 B：直接嵌入整张截图。还原快，但按钮无法适配，横屏会产生拉伸或大面积留白。
- 方案 C：继续使用当前抽象渐变广告。实现简单，但与真实开屏广告差距过大。

快速评审结论：

- 用户视角：参考真实开屏结构后，更容易理解广告在 Logo 与首页之间的完整流程。
- 开发视角：结构重建可保持跳过和查看详情可点击，也能适配横竖屏。
- 商业视角：中央主卖点和底部转化入口都可见，比只有一段广告文案更接近真实转化链路。

### 12.2 竖屏结构

- 白色全屏广告背景。
- 左上持续显示 `Ad` 和广告网络标识。
- 右上显示圆形跳过倒计时，如 `跳过 3s`。
- 中央使用绿色盾牌/锁形主视觉和大标题，模拟用户参考图的强中心构图。
- 标题下展示向上滑动的连续箭头动画。
- 底部同时提供明确的“查看详情”入口，避免只靠手势造成可发现性不足。
- 点击“查看详情”、点击主素材或完成上滑手势，均打开全屏 SDK 落地页。

### 12.3 横屏结构

- 不拉伸竖屏排版。
- 左侧展示盾牌/锁形主视觉，右侧展示标题、卖点、上滑/点击引导和“查看详情”。
- 广告标识固定左上，跳过倒计时固定右上。

### 12.4 启动流程

1. 真正冷启动显示盖世游戏 Logo 动画。
2. Logo 动画结束且广告已预加载时，显示 O1 全屏开屏广告。
3. 点击“查看详情”进入全屏 SDK 落地页；关闭后进入当前方向的目标页。
4. 点击跳过或倒计时结束，竖屏进入首页、横屏进入游戏库。
5. 无填充、预加载失败或超时时，Logo 后直接进入目标页，不额外等待。

Demo 的“下一阶段”按钮只保留在设备外部工具区，用于产品评审快速切换；设备内部只展示真实用户可见的跳过、查看详情和手势引导。

## 13. S1/S2/S3 搜索广告落地样式补充

用户提供的搜索广告点击结果截图作为 S1 搜索结果、S2 热游推荐和 S3 热门搜索三类原生广告的落地样式参考。

### 13.1 方案结论

采用“全屏 SDK 遮罩 + 居中竖向广告承载卡”：

- 遮罩覆盖完整设备画布，底层搜索页不可点击。
- 广告内容保持竖向圆角卡比例，不在横屏设备中强行横向拉伸。
- 卡片内部按参考图展示手势提示、关闭按钮、视频/试玩素材、卖点、应用信息和下载 CTA。

不采用以下两种方式：

- 不把广告落地页伪装成盖世游戏详情页，避免用户误判内容归属。
- 不把竖向广告卡铺满横屏后裁切，避免广告标题、主素材和转化按钮显示不全。

快速评审结论：

- 用户视角：全屏遮罩明确表示已进入广告链路，关闭后仍能回到原搜索位置。
- 开发视角：Demo 模拟 SDK 返回的广告容器；正式形态和外跳结果继续由 SDK 控制。
- 商业视角：保留视频素材、应用信息和“立即下载”按钮，广告转化信息完整。

### 13.2 卡片结构

- 顶部引导区：
  - 左侧展示手机摇动或点击图标。
  - 文案：`摇一摇或点击图标，跳转到详情页或第三方应用`。
  - 右上角展示关闭按钮。
- 中部素材区：
  - 展示横向游戏视频或试玩画面。
  - 视频不得被按钮、关闭控件或底部应用栏遮挡。
- 卖点区：
  - 展示一行广告卖点和省略后的补充内容。
  - 持续显示 `Ad` 或广告网络提供的广告标识。
- 底部转化区：
  - 展示应用图标、应用名和主按钮 `立即下载`。
  - 点击应用图标、素材或按钮时，按 SDK 结果进入详情页、应用商店或第三方应用。

### 13.3 交互与恢复

1. 用户点击 S1、S2 或 S3 的原生广告条目。
2. 保存搜索关键词、当前 Tab、已加载批次、随机广告位置和滚动位置。
3. 显示完整设备画布尺寸的 SDK 遮罩和竖向广告卡。
4. 点击关闭按钮，移除 SDK 遮罩并恢复原搜索状态。
5. 点击“立即下载”或完成摇一摇动作，模拟打开系统应用商店或第三方应用。
6. 从外部页面返回盖世游戏时，仍恢复原搜索状态，不重新随机广告位置。

### 13.4 横竖屏

- 竖屏：广告卡宽度接近设备可视宽度，四周保留安全边距。
- 横屏：广告卡保持竖向比例并居中，左右使用不可点击的暗色遮罩，不将卡片横向拉伸。
- 小屏无法完整容纳时，优先缩放整个卡片；不能单独压缩视频或底部 CTA。

## 14. 激励广告失败反馈补充

### 14.1 方案结论

采用“关闭广告层、恢复来源状态、展示轻量 Toast”的失败闭环：

- Demo 外部点击“模拟失败”后，立即结束当前广告链路。
- 设备内恢复用户触发广告前的业务页面或业务弹窗。
- 在设备内展示 Toast：`广告播放失败，请稍后重试`。
- 失败不发放广告奖励、不扣减领取资格，也不改变原业务权益。

不采用以下方式：

- 不静默关闭，否则用户无法判断广告是否完成、奖励是否到账。
- 不追加失败弹窗，否则会在广告结束后再次打断用户，且容易形成连续弹窗。
- 不展示奖励成功层，避免失败状态与到账状态混淆。

快速评审结论：

- 用户视角：Toast 能解释失败，又不会阻塞继续操作。
- 开发视角：四个激励资源位可以复用统一失败回调，只需要按来源恢复状态。
- 商业视角：失败后仍保留重新观看入口和领取资格，不会因一次技术失败损失后续转化。

### 14.2 场景恢复规则

|场景|失败后恢复位置|权益结果|
|---|---|---|
|C1 签到加倍|返回“签到成功”结果层，继续显示“看广告再领”入口|保留基础签到奖励，不发双倍奖励，不扣广告领取资格|
|G1 零时长|重新显示原深灰色“提示”弹窗|不增加时长，不创建启动请求，不扣广告领取资格|
|Q1 排队加速|返回排队页并保留原排队位置|不进入加速通道、不增加时长、不扣广告领取资格|
|R1 抽奖次数|返回活动任务页|不增加抽奖次数、不扣广告领取资格|

“模拟失败”只模拟广告加载或播放失败。用户主动提前关闭广告时，继续按 SDK 提前关闭规则处理，不复用技术失败 Toast。

## 15. 信息流广告菜单范围补充

M1 社区主信息流广告和 T1 游戏详情社区广告的更多菜单本期只提供一个业务操作：

- `对此广告不感兴趣`

交互规则：

1. 点击广告更多按钮打开轻量菜单。
2. 点击“对此广告不感兴趣”后，隐藏当前页面中的该条广告；本次页面不再原位补充另一条广告。
3. 点击菜单外遮罩或关闭入口只关闭菜单，不改变广告展示状态。
4. 本期移除“举报广告”，也不把“取消”展示为第二个业务选项。
5. 重新进入页面后是否再次展示，由后台投放、频控和广告平台返回结果共同决定；“不感兴趣”不等同于永久屏蔽该广告主。
