# Demo 02 创建游戏与版本发布资料设计

## 1. 目标与范围

本轮只修改 `demos/开发者后台一期/02-CDKEY商品与供给demo.html` 对应的源文件与定向构建结果，统一创建游戏和创建后的资料补充路径。

目标开发者是已完成厂商认证、准备创建 PC 游戏并继续补充发行资料的国内厂商。创建阶段只采集建立游戏项目和确定后续资料路径所需的信息；完整商店资料、素材、权属和地区资质在创建后补充。

本轮不修改 Demo 01、Demo 06 和 PRD；不实现包体上传、构建版本、定价、正式上线或下架能力。

## 2. 信息架构

单游戏控制台新增一级导航“版本发布”，与“概览、商店、游戏运营、游戏服务、数据分析”并列。

创建游戏成功后默认进入：

`游戏管理 / 当前游戏 / 版本发布 / 游戏资料`

“版本发布”在本轮是后续完整发布流程的容器，只开放“游戏资料”。游戏资料使用一张长页面，左侧资料导航负责定位页面内分区，不把同一份资料拆成多张相互割裂的页面。

左侧资料导航依次为：

1. 游戏类型与分发
2. 基础信息
3. 开发者信息
4. 游戏素材
5. 其他设置
6. 资质认证

点击导航滚动到对应分区并更新选中态；页面标题只显示“游戏资料”，不重复显示英文眉题或解释性副标题。

## 3. 创建游戏表单

### 3.1 字段

| 字段 | 控件 | 是否必填 | 规则 |
|---|---|---:|---|
| 游戏名称（英文） | 单行输入框 | 是 | 最多 100 个字符 |
| 游戏类型 | 多选下拉 | 是 | 从既有类型字典中选择，可同时选择多个；收起后显示已选标签 |
| 当前主体与该游戏的关系 | 单选下拉 | 是 | 开发商、发行商、开发商和发行商 |
| 开发商名称 | 单行输入框 | 否 | 仅关系为“发行商”时显示；创建阶段选填，进入资质提交时必须补齐 |
| 发布平台 | 多选复选框 | 是 | Windows、macOS、Linux，默认选择 Windows |
| 当前发布计划 | 卡片单选 | 是 | 开放预约、先锋测试、准备上线三选一 |

### 3.2 联动规则

- 选择“发行商”时显示“开发商名称”。
- 从“发行商”切换为其他关系时隐藏并清空“开发商名称”，避免保存不适用数据。
- 选择“开发商和发行商”时，当前主体同时承担两个角色，不重复填写开发商名称。
- 游戏类型至少选择一项；再次点击已选类型可取消，最后一项取消后提交时显示必填错误。
- 创建按钮保持“创建游戏”，提交成功生成唯一 Game ID 和 APPID。

## 4. 创建后的游戏资料页

创建表单数据写入新游戏项目，并在游戏资料页对应分区回显。新项目状态保持“草稿”。

### 4.1 游戏类型与分发

回显并允许编辑游戏类型、当前主体与游戏的关系、开发商名称、发布平台和当前发布计划。

### 4.2 基础信息

包含游戏图标、游戏名称（英文）、游戏名称（中文，选填）、一句话介绍和完整介绍。创建阶段不要求游戏图标和介绍，避免阻断建项；提交游戏资料审核前再校验完整性。

### 4.3 开发者信息

展示当前认证主体；关系为发行商时展示开发商名称。当前认证主体只读，避免与厂商认证数据形成第二份可编辑数据。

### 4.4 游戏素材

包含横版封面、竖版封面、商店截图和宣传视频入口。使用真实上传控件状态，不增加与本轮无关的素材裁剪弹窗。

### 4.5 其他设置

包含支持语言和 PC 系统要求。iOS 配置不属于 PC 发行平台，不展示。

### 4.6 资质认证

根据主体关系展示对应入口：

- 开发商：自研权属证明；软件著作权作为可选证明，不作为海外发行统一必填项。
- 发行商：开发商／原始权利方、授权链文件、授权地区与期限；开发商名称在提交资质前必须补齐。
- 中国大陆发行：仅当发行范围包含中国大陆时要求补充版号及相关审批信息；不阻断其他合规海外地区的资料准备。

本轮只展示资料项、状态和编辑入口，不实现正式审核提交。

## 5. 数据与跳转

创建提交数据结构：

```js
{
  gameNameEn: string,
  genres: string[],
  relationship: 'developer' | 'publisher' | 'developer_publisher',
  developerName: string,
  platforms: Array<'Windows' | 'macOS' | 'Linux'>,
  releasePlan: 'reservation' | 'test' | 'launch'
}
```

创建成功后的工作台状态：

```js
{
  workspaceView: 'game',
  selectedGame: gameKey,
  gameTab: 'release',
  gameSection: 'game-profile',
  profileAnchor: 'classification'
}
```

创建失败时保留表单内容并展示当前已有的表单级错误，不增加 Toast。返回游戏管理时不新增确认弹窗。

## 6. 验收条件

1. 游戏类型可多选、取消和回显；未选择时阻止创建。
2. 字段标题为“当前主体与该游戏的关系”。
3. 选择“发行商”显示选填的开发商名称，切换其他关系后隐藏并清空。
4. 创建成功生成 Game ID、APPID，并进入“版本发布 / 游戏资料”。
5. 游戏资料页包含六个约定分区，左侧点击可定位且选中态正确。
6. 创建时填写的名称、类型、关系、开发商、平台和计划在资料页正确回显。
7. 不出现移动端、iOS、包体上传、定价、上线或下架操作。
8. 现有概览、商店、CDKEY、运营、服务和数据分析入口仍可正常切换。
9. Demo 02 可以离线打开，定向构建不改写其他 Demo。

## 7. 快速评审结论

- 用户视角：通过。创建字段足够精简，创建后立即进入可继续补资料的落点；开发商名称的后置必填不会阻断建项。
- 开发视角：通过但需守边界。“版本发布”只作为一级容器，游戏主数据仍归游戏资料；本轮不复制包体与版本状态。
- 商业视角：通过但需守门禁。发行商可暂不填写开发商名称，但资质提交前必须补齐授权主体和授权链。

## 8. 自检结果

- 无待定项、占位字段或未定义状态。
- 创建字段、数据结构、显示规则和验收条件一致。
- “版本发布”与同事负责的包体、定价和上线流程边界已明确，不在本轮重复实现。
