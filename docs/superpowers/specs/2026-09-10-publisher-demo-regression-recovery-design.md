# 开发者后台 01／02 Demo 功能回退恢复设计

## 背景与目标

01／02 Demo 合并后，前台仍以 02 为主体、运营后台仍以 01 为主体，但重新构建覆盖了曾只写入生成 HTML 的分区定价；同时多语言能力虽仍在源码中，当前入口与测试状态没有稳定证明其完整联动；前后台切换入口又被放入正式顶部导航，容易被误认为正式产品能力。

本次只恢复和校正以下三项：

1. 全球服收费 SKU 的“USD 基准价＋地区例外价”。
2. 游戏资料中的基础信息、游戏素材共用同一多语言集合，默认仅英语。
3. 前后台切换改为独立的悬浮 Demo 工具。

不调整创建游戏流程，不把多语言放进创建游戏，不扩展 C 端、CDKEY、财务、投放或社区功能。

## 设计决策

### 1. 分区定价

收费的基础游戏与每个 DLC 都是独立 SKU。全球服下，每个收费 SKU 可选：

- 统一价：沿用单一 USD 售价、可选折扣价及折扣期限。
- 分区定价：先填写统一 USD 基准价，再为当前已选发行地区中的少数国家／地区配置当地币种例外价。

分区定价默认只展示一行基准价。未配置例外价的发行地区继承基准价；平台换算规则只作文字说明，Demo 不模拟实时汇率。例外地区通过搜索和多选添加，每个地区显示当地币种、售价、折扣价和移除操作。

规则沿用既有设计 `2026-09-09-demo2-default-and-override-pricing-design.md`：

- 例外地区只能来自当前发行范围，不能重复。
- 移除发行地区后，例外价保留在草稿中但停止生效；重新加入后恢复。
- 提审快照只带当前发行范围内的有效例外价。
- 统一价与免费 SKU 不携带隐藏例外价；免费时清空全部收费配置。
- 中国大陆固定使用 CNY 统一价，不展示分区定价。
- 例外折扣价必须低于例外售价，并与 SKU 共用有效折扣期限。
- 审核中锁定定价；撤销审核后恢复编辑；再次提审生成新快照，不覆盖历史版本。

数据继续使用 SKU 级字段：

```js
{
  pricingModel: 'paid',
  pricingStrategy: 'regional',
  listPrice: '19.99',
  discountPrice: '14.99',
  regionalPrices: {
    JP: { listPrice: '2200', discountPrice: '1650' }
  },
  discountStartAt: '2026-09-20T10:00',
  discountEndAt: '2026-09-27T10:00'
}
```

地区与币种映射由发行地区模块统一提供，前台填写、提审校验和运营后台快照共用同一来源。历史逐币种草稿仅迁移为对应发行地区的例外价，不推断跨币种基准价。

### 2. 多语言联动

创建游戏仍只填写创建所需字段，不处理多语言。创建后的游戏资料以 `nameLanguages` 为唯一语种集合：

- 全球服新游戏默认只有英语。
- 在基础信息或游戏素材点击“管理多语言”新增语种后，两处同步出现该语种。
- 游戏名称、短介绍、完整介绍、开发者寄语与该语种素材共用同一语种集合，但各自保存内容。
- 删除语种后，当前提审快照不包含该语种；已有草稿内容保留，重新添加时恢复。
- 旧草稿按已保存语种恢复，不强制重置为英语。
- 选择中国大陆发行时，自动补充中文并切换到中文界面；全球服仍以英语为默认语种。

持久化继续以 `storeLocales.enabled/default/current` 为规范结构，同时兼容历史 `nameLanguages`、`assetLanguageSettings`、`localizedContent` 和 `localizedAssets` 字段。

### 3. 悬浮 Demo 切换入口

从正式顶部导航移除“切换运营后台／切换开发者前台”。在页面右侧中下部增加固定悬浮胶囊，显示：

- 开发者前台：`Demo · 切换运营后台`
- 运营后台：`Demo · 切换开发者前台`

悬浮入口复用现有 `switch-portal-side` 行为：从开发者端切换前先保存工作区状态，进入运营审核页面；从运营端返回开发者端时回到既定落点。悬浮入口不出现在登录、无账号和脱敏页面。

桌面端固定在右侧中下部；窄屏移动到右下角并适配安全区。层级高于业务内容、低于弹窗，不遮挡底部保存、提审、返回顶部等业务操作。保留键盘焦点、悬停反馈和明确的目标端文案。

## 源码与构建边界

分区定价必须迁入源码，禁止再次只修改生成 HTML：

- `src/runtime/publisher-release-regions.js`：地区与币种映射。
- `src/runtime/publisher-game-profile.js`：SKU 定价模型、地区联动、校验和快照裁剪。
- `src/styles/publisher-game-profile.css`：基准价与例外价布局。
- `src/runtime/publisher-game-review-store.js`：审核数据归一化、校验和摘要。
- `src/runtime/publisher-game-review.js`：运营后台及版本快照展示。
- `src/styles/publisher-game-review.css`：审核定价展示样式。
- `src/runtime/publisher-game-names.js`、`publisher-storage-schema.js`：保持并验证统一语种源与持久化兼容。
- `src/runtime/shell.js`、`src/styles/shell.css`：悬浮 Demo 切换入口。

完成后由 `build.mjs` 统一重建 01、正式 02 和兼容入口，使三个入口使用同一源码能力。

## 异常与边界

- 缺少基准售价、例外售价无效、折扣价不低于售价或折扣期限无效时，提审定位到首个错误控件。
- 发行范围变化后，界面统计、有效价格和审核快照必须使用同一地区集合。
- 免费／收费、统一／分区、全球／中国大陆切换时，隐藏字段不能污染当前快照。
- 多语言切换后，当前编辑内容先同步到草稿，再切换语种，避免内容串写。
- 悬浮入口在 320px、390px 窄屏下不得造成横向滚动或覆盖主操作。

## 验收与验证

1. 全球服基础游戏与 DLC 均可配置统一价或“USD 基准价＋少量当地币种例外价”。
2. 新增、移除、恢复发行地区时，例外价继承、生效和草稿恢复符合规则。
3. 中国大陆仅显示 CNY 统一价；免费 SKU 不携带收费字段。
4. 审核中锁定，撤销后可编辑；提审快照及版本记录准确展示基准价、继承地区数和例外价。
5. 新游戏默认仅英语；新增日语后，基础信息与游戏素材同步出现日语，保存重开后仍保留。
6. 顶部导航不再出现前后台切换；符合显示条件的业务页显示右侧悬浮 Demo 入口，并可双向切换且不丢草稿。
7. 01、正式 02、兼容入口与运营审核页使用同一行为。
8. 1440px、390px 和 320px 视口无横向裁切或主要操作遮挡。
9. 运行分区定价、多语言、发行审核和既有 01／02 聚焦回归测试；测试应显式建立账号状态，避免依赖残留浏览器存储。

## 快速评审结论

- 用户视角：分区定价只展开少量例外地区，多语言在资料与素材间同步，悬浮入口明确属于 Demo，主流程不会被干扰。
- 开发视角：把历史生成物逻辑迁回源码，并统一地区、语种和构建来源，可以避免再次被构建覆盖；测试需消除本地存储前置不稳定。
- 商业视角：恢复已确认能力，不新增正式产品范围，能直接支撑开发者填写与运营审核演示。
