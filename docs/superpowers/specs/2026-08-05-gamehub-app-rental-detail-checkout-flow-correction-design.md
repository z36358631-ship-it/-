# 盖世游戏 APP 租号详情与确认订单链路修正设计

## 1. 结论

采用方案 A：游戏详情只承载游戏信息与“租号开玩”入口，版本、SKU、租期、金额和支付全部进入独立确认订单页选择。横屏复用 Mac 租号与 CDKey 确认订单的双栏骨架，竖屏复用同一组件和内容顺序纵向排列。

## 2. 问题与依据

当前 APP 租号 Demo 在游戏详情直接展示“首次体验、单游戏永久、会员”和更多租期，详情页同时承担内容浏览、权益判断和交易配置，存在三个问题：

1. 与现有 APP、Mac 和 CDKey 的详情页操作结构不一致。
2. 用户尚未进入交易流程就需要理解多个 SKU 和租期，详情主任务被打断。
3. 版本、SKU、租期、库存、价格属于同一报价上下文，分散在详情和订单页容易产生状态不一致。

本次对照以下既有实现：

- `demos/充值与商城/cdkey售卖（游戏详情）demo.html`：详情只提供购买入口，确认订单集中选择商品类型并支付。
- `Mac端demo/mac端租号功能/Mac端租号功能-标注版.html`：详情操作区展示“秒玩、获取/下载/启动、租号开玩”，确认订单集中选择版本和获取方式。
- `Mac端demo/mac端租号功能/租号中心-订单确认.html`：确认订单使用左侧游戏与权益、右侧选择与支付的双栏结构。

## 3. 范围

### 3.1 本次修改

- APP 横屏、竖屏游戏详情页。
- APP 横屏、竖屏确认订单页。
- 从详情进入确认订单、切换版本/SKU/租期、刷新报价、创建订单及返回详情的状态连续性。
- 普通版 Demo、标注版 Demo、自动验证、PRD 图示及 PRD 说明。

### 3.2 不修改

- 租号曝光入口、个人中心、会员中心、会员游戏库、订单列表、订单详情、Steam 登录、临期、到期和售后主流程。
- 已确认的 SKU 业务范围、价格规则、会员游戏库规则和外放规则。
- 后台商品、库存、会员库及灰度配置结构。

## 4. 交互设计

### 4.1 游戏详情

详情页移除“游戏权益”中的 SKU 卡片、租期选择和价格摘要，不在详情页创建订单或锁定价格。

操作区按用户当前权益显示：

| 用户状态 | 原游戏操作 | 租号增量操作 |
|---|---|---|
| 已拥有且已安装、已导入或已有单游戏永久权益 | 启动游戏 | 不展示“租号开玩” |
| 已拥有但未安装 | 下载游戏 | 不展示“租号开玩” |
| 存在进行中租号订单 | 继续游戏 | 提供订单入口，不重复展示“租号开玩” |
| 有效会员且当前版本在会员游戏库 | 会员畅玩 | 不重复展示普通租号入口 |
| 未拥有且当前地区、灰度、商品和库存可用 | 保留原“秒玩/获取/下载”能力 | 在相邻位置展示“租号开玩” |
| 未命中外放、商品下架或无可售版本 | 保留原游戏操作 | 隐藏“租号开玩” |

点击“租号开玩”后进入独立确认订单页，并携带当前游戏、来源页面和已匹配的默认版本；不得在详情页提前选择 SKU 或租期。

### 4.2 确认订单

确认订单页集中展示以下内容，顺序固定：

1. 游戏信息：封面、游戏名、平台和当前版本。
2. 版本选择：展示后台当前可售版本，例如标准版、增强版、豪华版。
3. SKU 选择：按会员游戏库状态展示当前可售 SKU。
4. 租期选择：仅普通时租 SKU 显示，支持 2—23 小时；日租和周租作为独立 SKU，不重复展示小时数。
5. 会员入口：作为独立权益入口，不并入单游戏订单 SKU。
6. 费用明细：游戏原价、当前订单金额和价格有效期。
7. 支付方式：支付宝、微信、二维码、协议和确认支付。
8. 服务保障：100% 正版、一键启动、永不顶号、存档无忧、3天无理由。

### 4.3 SKU 联动规则

| 商品状态 | SKU 选择 | 租期选择 | 会员入口 |
|---|---|---|---|
| 未加入会员游戏库 | 时租、日租、周租 | 选择时租后显示 2—23 小时；日租和周租不显示小时选择 | 不展示该游戏会员畅玩引导 |
| 已加入会员游戏库且首次资格可用 | 首次体验、单游戏永久畅玩 | 不显示 | 展示“开通会员/查看会员权益” |
| 已加入会员游戏库且首次资格已使用 | 单游戏永久畅玩 | 不显示 | 展示“开通会员/查看会员权益” |
| 有效会员且版本在会员游戏库 | 不创建单游戏租号订单 | 不显示 | 主操作为“会员畅玩”并返回详情启动 |
| 已有单游戏永久权益 | 不创建重复订单 | 不显示 | 按当前会员状态展示，但不影响已有权益 |

加入会员游戏库后，后台原时租、日租、周租配置保留但对新订单失效；移出会员游戏库并通过价格、库存校验后恢复。

### 4.4 版本、报价与订单

1. 进入确认订单时请求默认版本的可售 SKU、库存和报价，只生成页面报价，不创建支付订单。
2. 切换版本后重新获取该版本的 SKU、库存和报价，并把不再适用的 SKU 重置为当前首个可售项。
3. 切换 SKU 或租期后同步刷新订单金额、价格版本和预计到期时间。
4. 用户点击“确认支付”时再次校验版本、SKU、租期、库存、首次资格和价格版本；通过后创建订单并锁价30分钟。
5. 价格变化时展示新价格并要求再次确认，不静默加价；无库存的版本或 SKU 置灰且不可支付。
6. 返回详情不保留未支付订单，只保留当前游戏和来源页面；已创建待支付订单返回时保留订单号和锁价倒计时。

### 4.5 横竖屏布局

| 方向 | 详情页 | 确认订单页 |
|---|---|---|
| 竖屏 | 内容纵向滚动，底部固定操作区展示原游戏操作与“租号开玩” | 游戏信息、版本、SKU、租期、金额、支付和保障按同一顺序纵向排列；底部固定应付金额和确认支付 |
| 横屏 | 继承 Mac 详情骨架，游戏主视觉下方同排展示“秒玩、获取/下载/启动、租号开玩” | 继承 CDKey/Mac 双栏骨架；左侧游戏信息与服务保障，右侧版本、SKU、租期、金额和支付 |

详情、确认订单均为独立任务页，不显示 APP 全局导航；返回时按任务栈回到来源详情或核心页。

## 5. 异常与边界

- 某版本无库存：版本置灰并显示“暂无库存”，自动选择首个可售版本；全部版本无库存时禁用确认支付。
- SKU 下架或资格变化：刷新当前 SKU 列表，已选项失效时选择首个可售 SKU并提示规则已更新。
- 价格变化：更新费用明细，要求用户重新确认，不沿用旧金额。
- 弱网或报价失败：保留当前选择，显示重新查询；不得创建订单或使用旧报价支付。
- 重复点击确认支付：按客户端请求号和订单号幂等，不重复创单或扣款。
- 横竖屏切换：保留游戏、版本、SKU、租期、支付方式、报价版本和待支付订单，不重新选默认值。
- 跨游戏返回：游戏名、封面、版本、SKU和订单草稿必须属于同一游戏，不复用上一游戏状态。

## 6. 验证范围

### 6.1 自动验证

- 详情页不存在 SKU 卡片和租期选择。
- 横竖屏详情均存在“租号开玩”，且与原游戏操作相邻。
- 点击“租号开玩”进入确认订单。
- 横竖屏确认订单均包含版本、SKU和租期选择。
- 切换版本、SKU、租期后金额与订单快照一致。
- 会员游戏库与非会员游戏库的 SKU 互斥规则正确。
- 进入确认订单不创建支付订单；确认支付时才锁定最终选择。
- 旋转、返回、弱网、无库存、价格变化和重复点击不破坏状态。

### 6.2 视觉验证

- 对照 CDKey Demo 检查选择行、按钮层级和支付区结构。
- 对照 Mac 租号 Demo 检查横屏详情操作区和确认订单双栏结构。
- 截取横竖屏详情、确认订单和关键切换状态，检查文字不裁切、按钮不溢出、操作区不遮挡正文。

## 7. 三视角评审

| 角色 | 结论 | 评审意见 |
|---|---|---|
| 用户代言人 | 通过 | 详情只负责发现和进入交易，选择集中在确认订单，用户不需要在两个页面反复核对。 |
| 开发挑战者 | 通过 | 可复用现有 CDKey 选择行、Mac 详情操作区及 APP 订单状态；需要把报价和支付订单拆开，避免进入页面即锁定错误 SKU。 |
| 商业审视者 | 通过 | 保留“租号开玩”曝光和会员入口，同时减少详情页信息负担，不增加新的交易步骤。 |
