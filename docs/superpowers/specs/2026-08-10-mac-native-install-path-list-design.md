# Mac 原生游戏安装路径平铺与最大空间默认选择设计

## 1. 结论

在现有“安装路径”弹窗内，将单个安装位置字段改为单列单选列表。列表直接平铺全部候选安装路径，完整展示绝对路径和可用空间；合格路径按可用空间从大到小排列，并默认选中可用空间最大的路径。

本设计是 `2026-08-07-mac-native-version-switch-refinement-design.md` 的增量补充，只调整安装位置区域和对应状态逻辑，不改变版本选择、下载、安装完成或默认启动版本规则。

## 2. 解决的问题

现有 Demo 一次只显示一个安装路径，用户必须点击字段循环切换，无法同时比较多个位置，也无法快速判断哪个路径空间最大。路径失效时，弹窗还会把不可用位置作为当前选择，增加安装失败和反复尝试的成本。

改动后的核心目标是：用户进入弹窗后，无需额外展开或切换即可看全路径，并可直接使用系统推荐的最大合格空间完成安装。

## 3. 范围

### 3.1 本次包含

- 安装路径由单字段改为平铺单选列表。
- 每项展示完整绝对路径和可用空间。
- 合格路径按可用空间降序排列，默认选中第一项。
- 空间不足和路径不可用的候选项禁用并标明原因。
- 无合格路径、切换游戏版本、下载锁定和安装前路径状态变化的处理。
- 同步更新 Demo、PRD、静态测试、真实浏览器测试和验收截图。

### 3.2 本次不包含

- 不新增目录浏览器、自定义路径创建或磁盘空间管理。
- 不新增路径删除、重命名、格式化、清理或一键扩容。
- 不新增弹窗、Toast、二次确认或独立设置页。
- 不改变现有版本切换、下载取消、双版本保留和默认启动版本规则。

## 4. 界面设计

### 4.1 安装位置区域

- 字段标题保留“安装位置”，删除标题后括号中的单个当前路径，避免与下方列表重复。
- 标题下直接展示 `.install-path-list` 单列列表，不再使用下拉、循环切换或右侧箭头。
- 每个 `.install-path-option` 左侧为文件夹图标，中间为路径信息，右侧为单选状态。
- 第一行展示完整绝对路径，不使用省略号；超长路径在行内自然换行。
- 第二行展示“可用空间 XXX GB/MB”；禁用项改为“空间不足”或“路径不可用”。
- 可选行整行可点击，选中行使用现有弹窗的浅色高亮描边和单选选中态。
- 禁用行降低文字对比度、取消点击能力，并保留清晰的失败原因。
- 行高使用自适应 `min-height`，保证路径换行后不截断；列表超过弹窗安全高度时只让路径列表内部滚动。

### 4.2 Demo 示例数据

Demo 至少展示以下四类候选项，便于验证完整状态：

1. `/Volumes/external_disk/Gamehub/`：可用空间最大，默认选中。
2. `/Applications/GameHub/`：空间足够，可手动选择。
3. `/Volumes/SmallDisk/Gamehub/`：空间不足，禁用。
4. `/Volumes/OfflineDisk/Gamehub/`：路径不可用，禁用并置底。

实际展示容量以 Demo 数据为准，但必须保证前两项空间足够且数值不同，第一项可用空间最大。

## 5. 数据与选择规则

### 5.1 状态模型

安装位置从单一字符串状态调整为：

```js
installPaths: [
  {
    id: 'external',
    path: '/Volumes/external_disk/Gamehub/',
    availableBytes: 512000000000,
    status: 'available',
    order: 0
  }
],
selectedPathId: 'external'
```

版本数据新增数值型 `requiredBytes`，展示文案继续使用既有 `size`。容量统一使用 macOS/Finder 的十进制口径：`1 MB = 1,000,000 bytes`，`1 GB = 1,000,000,000 bytes`。

### 5.2 合格条件

候选路径同时满足以下条件时才可选择：

1. `status === 'available'`，即路径存在且可写。
2. `availableBytes >= selectedVersion.requiredBytes`。

空间不足和路径不可用都属于禁用项，不允许用户选中后再到安装提交阶段才发现失败。

### 5.3 排序规则

1. 合格路径在前，按 `availableBytes` 从大到小排列。
2. 空间不足路径随后，按 `availableBytes` 从大到小排列。
3. 路径不可用项置底。
4. 容量相同时按稳定的 `order` 升序排列，避免界面顺序抖动。

### 5.4 默认选择

- 首次打开安装弹窗时，默认选中排序后的第一个合格路径。
- 切换游戏版本后，若当前选择仍然合格则保留用户选择；若不再合格，则自动选择新版本下空间最大的合格路径。
- 没有合格路径时，`selectedPathId = null`，不回退选择空间不足或不可用项。

## 6. 交互与异常处理

- 点击合格路径的任意可见区域即可选中；键盘可使用 Tab 聚焦并通过 Space/Enter 选择。
- 下载开始后，路径列表和游戏版本入口一起锁定，当前选择不允许变化。
- 下载取消后恢复路径选择能力，但保持取消前的合格选择；若路径状态已变化，则按默认选择规则重新计算。
- 点击“安装游戏”前按 `selectedPathId` 重新读取候选项，复验路径可用性和剩余空间。
- 若提交前路径失效或空间不足，停止安装、清空失效选择并在弹窗内显示原因；有其他合格路径时由用户重新选择，不自动提交。
- 无合格路径时禁用“安装游戏”，安装位置区域显示“没有可用且空间足够的安装位置”。

## 7. 验收标准

1. 安装位置区域同时显示全部候选路径，绝对路径无省略号和截断。
2. 合格路径按可用空间降序排列，默认选中空间最大的路径。
3. 用户可以选择其他空间足够的路径，选中态唯一且清晰。
4. 空间不足和路径不可用的路径不可点击，并分别显示准确原因。
5. 没有合格路径时无默认选择，“安装游戏”不可点击且原因可见。
6. 切换游戏版本后按新版本所需空间复验当前选择，不合格时改选最大合格路径。
7. 下载中路径列表和版本入口均锁定；取消后恢复，不改变实际默认启动版本。
8. 安装提交前路径状态变化会阻止安装，不会写入已安装版本或切换默认启动版本。
9. 弹窗在 `1440×900` 和 `1280×800` 视口下无内容溢出、遮挡或不可操作项。

## 8. 测试方案

- 静态测试：检查平铺列表结构、完整路径文案、数值容量字段和单一路径状态已移除。
- 逻辑测试：覆盖排序、稳定并列顺序、默认最大项、手动选择、无合格路径和版本所需空间变化。
- 浏览器测试：覆盖可点击区域、禁用项、下载锁定、取消恢复、安装前路径突变和安装成功。
- 视觉测试：分别截取默认最大路径、异常路径禁用、下载锁定三个状态，并检查弹窗高度和路径换行。
- 回归测试：确认版本切换弹窗、详情主按钮、下载取消、双版本安装和默认启动版本逻辑保持不变。

## 9. 方案快速评审

- 用户视角：平铺列表消除逐项切换成本；提前禁用空间不足和不可用路径，可避免安装提交时才发现失败。
- 开发视角：`installPaths[] + selectedPathId + requiredBytes` 能统一排序、默认选择和提交前复验；无合格路径有明确空状态。
- 商业视角：只调整现有弹窗和状态数据，不扩展空间管理或新增流程，投入范围与用户收益匹配。
