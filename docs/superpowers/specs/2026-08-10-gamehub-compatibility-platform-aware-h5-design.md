# 盖世游戏跨平台兼容性 H5 多参数查询与移动端密度优化设计规格

**日期：** 2026-08-10（2026-08-12 修订）

**任务：** GUANWANGGAID-4

**状态：** 移动端密度优化方案已确认，待书面规格审阅

**参考结构：** [GameNative Compatibility](https://gamenative.app/compatibility/)

**目标形态：** 单一 H5 自动识别 Android / Mac，复刻竞品的多参数即时查询与多记录结果体验

## 1. 结论

页面继续使用多参数兼容性查询结构，但修正手机端筛选区占据近半屏、详细卡片坪效过低的问题。手机顶部改为“兼容性查询”紧凑标题、同排三个快捷筛选按钮和结果工具栏；任一条件变化后即时执行 AND 过滤，并展示多条兼容运行记录。

Android 使用“游戏 / 设备或 GPU / 最低评分（≥）”，Mac 使用“游戏 / Mac 机型或 Apple 芯片 / 最低评分（≥）”。结果仅提供一个“列表 / 平铺”开关：列表代表简约高密度呈现，平铺代表完整详细呈现，不再增加独立的“简约 / 详细”开关。手机默认列表模式，390×844 常规数据目标为一屏展示 4～6 条主要信息；平铺在 390px 为单列，600px 及以上为双列。桌面列表继续使用高密度表格，平铺使用 2～3 列详细卡片。

初始无筛选时不再显示空提示，而是展示当前平台 4～6 款不同热门游戏的代表性兼容记录；任何筛选变化都会立即更新结果，清空筛选恢复热门记录。兼容记录不进入独立详情页；列表记录可原位展开完整字段，只有“启动配置详情”继续独立承载，桌面使用居中弹窗，手机使用全屏浮层。

平台识别、Android/Mac 数据隔离、配置查看与 Web/App 下载能力继续保留。

## 2. 用户、问题与竞品依据

### 2.1 目标用户

- Android 用户：希望按游戏、手机型号或 GPU 查询实际运行记录。
- Mac 用户：希望按游戏、Mac 机型或 Apple 芯片查询实际运行记录。
- 网页访客：尚未进入 App，希望先判断兼容表现并下载适用配置。

### 2.2 用户问题

- 用户不一定先知道要查哪个游戏，也可能先按本机硬件查“能玩什么”。
- 同一游戏在不同设备、系统、盖世版本或运行环境下会产生多条结论，单游戏单结果会掩盖真实差异。
- 配置详情直接塞在结果卡内会拉长列表，破坏连续比较多条记录的效率。
- Android 与 Mac 的硬件和系统口径不同，不能共用一套候选和字段。
- 手机端将三个桌面筛选器纵向堆叠，会让筛选区接近半屏；详细卡片再使用四个大色块承载短字段，导致首屏通常只能看到一条记录。

### 2.3 用户现有解决方式

用户通常在社区、群聊、视频和零散测试记录中搜索游戏或设备关键词，再人工比对游戏版本、硬件、系统、兼容层、驱动和验证时间。该方式信息分散，难以筛选，也容易把其他环境的成功结论误认为本机结论。

### 2.4 竞品事实

GameNative Compatibility 当前使用“Search by Game / GPU / Rating”三个顶部选择器，任一条件生效后直接展示兼容记录，而不是进入单游戏详情。历史竞品规格还记录了结果字段：游戏、设备、GPU、Android、App 版本、评分、平均 FPS、标签、备注、配置和创建时间。

本次借鉴：

- 三个顶部快捷筛选框。
- 下拉选择与输入搜索合并。
- 条件变化后即时刷新，无“查询”按钮。
- 输出多条兼容运行记录。
- 桌面高密度表格。
- 无筛选时展示可直接浏览的热门兼容记录。

本次不复制：

- GameNative 的品牌、Logo、配色和文案。
- 不适合手机竖屏的横向宽表格。
- 只适用于 Android 的字段结构。

## 3. 已确认方案与范围

### 3.1 本次完成

- 单一响应式 H5 与 Android / Mac 自动识别。
- 三个顶部快捷下拉筛选框，全部支持输入搜索和单项清除。
- Android：“游戏 / 设备或 GPU / 最低评分（≥）”。
- Mac：“游戏 / Mac 机型或 Apple 芯片 / 最低评分（≥）”。
- 任一条件独立生效，多条件执行 AND 过滤。
- 同一游戏可展示多条独立兼容运行记录。
- 无筛选时展示当前平台 4～6 款不同热门游戏的代表记录。
- 一个“列表 / 平铺”开关同时控制布局和信息密度：列表为简约，平铺为详细。
- 手机默认高密度列表，可原位展开单条记录；平铺在窄屏单列、600px 及以上双列。
- 桌面列表为高密度表格，平铺为 2～3 列详细卡片。
- 两种视图共用同一筛选、排序、结果和配置数据。
- 启动配置详情：桌面居中弹窗、手机全屏浮层。
- 浏览器 Blob 下载与 App Bridge 下载。
- 加载、空数据、无候选、无结果、下载失败、超时和重试状态。

### 3.2 明确不做

- 单游戏兼容详情页。
- 兼容记录详情页。
- Android / Mac 两套独立 H5。
- 正式页面手动切换平台。
- 一键应用配置、下载并应用或自动启动游戏。
- 独立的“简约 / 详细”开关，以及与“列表 / 平铺”交叉形成的四种组合。
- 手机筛选详情页、底部筛选抽屉或需要“查询 / 确定”的二次提交流程。
- 全量后台、登录、会员、付费、收藏、分享、评论和配置上传。
- 与本任务无关的页面、弹窗或流程。

### 3.3 未采用方案

- 统一搜索框加高级筛选：无法清楚表达用户当前在搜游戏还是硬件，也偏离竞品结构。
- 搜索页与结果页分离：增加提交和返回步骤，不符合即时查询。
- 继续使用单游戏详情：无法表达同一游戏在不同环境下的多条记录。
- “简约 / 详细”与“列表 / 平铺”两个独立开关：会产生无价值的四种组合，其中详细平铺在手机上仍然低效。
- 手机筛选底部抽屉：仍然增加一层承载，与用户确认的三按钮同排即时筛选不一致。

## 4. 平台识别与隔离

平台来源优先级固定为：

```text
App Bridge 注入 > URL query 参数 > Demo 默认 Android
```

规则：

- App WebView 通过 `setContext({ platform })` 注入 `android` 或 `mac`。
- 浏览器可通过 `?platform=android` 或 `?platform=mac` 指定平台。
- 未提供有效平台时，Demo 默认 Android，并显示当前平台。
- App Bridge 与 query 冲突时以 Bridge 为准。
- 游戏、硬件候选、运行记录和配置必须同时通过 `platform` 过滤。
- 切换平台时清空筛选、下拉搜索词、排序、已展开记录、配置详情和下载状态；保留用户当前选择的列表或平铺视图。
- Demo 平台切换工具置于正式页面容器之外。

Mac 页面不得出现手机型号、Android 或移动 GPU 字段；Android 页面不得出现 Apple 芯片或 macOS 字段。

## 5. 页面结构

页面从上到下包含：

1. 返回入口、标题“兼容性查询”和当前平台标识，同处一行。
2. 游戏、硬件和最低评分三个快捷筛选按钮，同处一行。
3. 结果数量、清空筛选和“列表 / 平铺”开关，同处一行。
4. 热门或筛选后的兼容运行记录。
5. 启动配置弹窗或全屏浮层。
6. Demo 环境专用的平台和尺寸预览工具栏。

手机端隐藏占空间的标题说明文案。无筛选条件时展示热门兼容记录；任意筛选发生变化后，立即用全部运行记录重新执行 AND 过滤；清空筛选恢复热门记录。

## 6. 顶部快捷筛选

### 6.1 通用交互

- 点击筛选框打开下拉面板。
- 下拉面板顶部提供输入框，输入后即时过滤当前字段的候选。
- 选择候选后关闭下拉并立即刷新结果。
- 三个筛选按钮在 320～430px 宽度始终同排，不换行、不进入详情页；按钮长值单行省略。
- 手机候选面板在按钮行下方全宽浮出，覆盖结果而不推高页面，最大高度约 45vh；桌面仍可使用对应按钮下方的下拉面板。
- 已选按钮使用短值，例如“艾尔登法环”“红魔 10 Pro”“≥4”；完整值在候选面板中可见。
- 候选面板提供“清除当前项”，结果工具栏提供“清空筛选”，避免在窄按钮内塞入独立小叉号。
- 三项都可单独使用；两项或三项同时选择时按 AND 过滤。
- 不增加“查询”“确定”或第二层筛选页。
- 点击外部或按 Esc 关闭面板；下拉支持键盘焦点、方向键选择和 Enter 确认。

### 6.2 游戏筛选

- 支持中文名、英文名和别名搜索。
- 候选同时展示本地封面、中文名、英文名和当前平台标签。
- 同一游戏在 Android 与 Mac 可拥有不同的可用记录数量。

### 6.3 硬件筛选

Android：

- 支持手机型号、SoC、GPU 名称和别名搜索。
- 候选主标题优先显示设备型号；缺少具体设备时显示 GPU。
- 副信息显示 SoC / GPU，避免只显示用户不理解的内部 ID。

Mac：

- 支持 Mac 机型、Apple 芯片和别名搜索。
- 候选主标题显示 Mac 机型或 Apple 芯片。
- 副信息显示芯片与可用 macOS 范围。

### 6.4 最低评分筛选

字段名称固定为“最低评分（≥）”，不得只写“评分”。

候选为：

- 全部。
- 5 分及以上。
- 4 分及以上。
- 3 分及以上。
- 2 分及以上。
- 1 分及以上。

下拉输入支持搜索数字或“及以上”。选择“4 分及以上”时必须保留 4 分和 5 分记录。

## 7. 多条兼容运行记录

### 7.1 初始热门记录

无筛选时，从当前平台目录生成热门代表记录：

1. 仅选择标记为当前平台热门的游戏。
2. 同一游戏只保留一条代表记录，避免首屏被同一游戏重复占据。
3. 同一游戏先选评分最高的记录；评分相同时选验证时间最新的记录。
4. 最多展示 6 款、目标至少展示 4 款；数据不足时按实际数量展示，不复制或伪造记录。

热门记录只作用于无筛选初始状态。用户选择任意条件后，结果切换为所有符合条件的运行记录，同一游戏可以出现多条；清空全部条件后恢复热门代表记录。

### 7.2 结果口径

一条结果代表一条 `CompatibilityRecord`，不是一个游戏聚合卡。只要设备、GPU/芯片、游戏版本、系统、盖世版本或运行环境不同，就可以展示为独立记录。

结果默认排序：

1. 评分从高到低。
2. 评分相同时，验证时间从新到旧。

桌面允许点击“评分”和“验证时间”表头切换排序；手机沿用同一排序结果，不增加独立排序控件。热门代表记录也按同一默认顺序展示。

### 7.3 列表与平铺

仅保留一个 `viewMode`：

- `list`：简约高密度。手机渲染紧凑记录行；桌面渲染完整表格。
- `grid`：详细平铺。390px 手机为单列详细卡片；600px 及以上为双列；桌面根据容器宽度使用 2～3 列。

默认进入 `list`。切换视图只替换结果渲染器，不重新查询、不改变结果数量、顺序、筛选和排序；视图选择在当前 H5 会话内保留，切换 Android / Mac 时也不重置。

手机紧凑记录行高度目标为 108～120px，默认显示：

- 40×56 游戏封面、中文名。
- 设备 / GPU 或 Mac 机型 / Apple 芯片。
- 评分、平均 FPS。
- 系统与运行环境摘要。
- 最多两个关键标签。
- 配置状态或查看入口。

游戏名、硬件摘要、环境摘要和标签在收起态都限制为单行；超长内容省略，不得为了展示完整文案突破默认行高。完整字段仅在展开态或详细平铺中展示。

点击或用 Enter / Space 操作记录主体时原位展开完整字段；再次操作收起，同时最多展开一条。点击“查看配置”只打开配置浮层，不触发记录展开。无配置时以弱化文字显示“暂无配置”，不占用主要操作空间。

详细平铺卡片展示桌面结果字段的完整信息，但不再把四个短字段拆成四块大色块；使用紧凑的两列文字信息区，减少重复容器和无效留白。

### 7.4 Android 结果字段

- 游戏封面、中文名和英文名。
- 设备型号、SoC / GPU。
- 游戏版本。
- Android 版本。
- 盖世游戏版本与运行环境。
- 驱动或兼容层。
- 评分、平均 FPS 和稳定性结论。
- 问题标签和简短备注。
- 配置数量与查看入口。
- 验证时间。

### 7.5 Mac 结果字段

- 游戏封面、中文名和英文名。
- Mac 机型或 Apple 芯片。
- 游戏版本。
- macOS 版本。
- 盖世游戏版本与兼容层。
- 分辨率或显示模式。
- 评分、平均 FPS 和稳定性结论。
- 问题标签和简短备注。
- 配置数量与查看入口。
- 验证时间。

### 7.6 配置入口

- 有配置：显示“查看配置（N）”。
- 无配置：显示“暂无配置”，不可点击。
- 点击只打开启动配置详情，不进入兼容记录或游戏详情页。

## 8. 启动配置详情

### 8.1 承载方式

- 桌面端：居中弹窗，背景遮罩，内容区可独立滚动。
- 手机端：全屏浮层，顶部固定返回/关闭，底部操作区不遮挡内容。
- 两种尺寸使用同一份 DOM、状态和数据，只通过响应式样式改变形态。
- 关闭后恢复原筛选、排序和滚动位置。

### 8.2 多配置处理

同一运行记录存在多份配置时，在同一弹窗/浮层内先显示配置列表。选择配置后在该容器内展示对应详情，不再创建第三层页面或第二个弹窗。

### 8.3 配置内容

1. 适用范围：平台、游戏版本、设备/GPU 或 Apple 芯片、系统范围。
2. 启动参数：兼容层、驱动、分辨率、画质和启动参数。
3. 文件信息：配置版本、文件大小、更新时间和下载次数。

底部显示“下载配置”，不增加“一键应用”。

## 9. 视觉与响应式

### 9.1 视觉方向

- 使用盖世游戏黑、深灰、白和品牌金的克制视觉体系。
- 不复制 GameNative 或 Stitch 的 Logo、品牌配色和文案。
- 下拉、表格、卡片和弹窗使用统一圆角、描边、阴影和状态标签。
- 图片、脚本和样式本地化，不使用 iframe、CDN 或运行时外链。

### 9.2 桌面网页

- 三个筛选框顶部横向等分排列。
- 列表模式使用紧凑表格，内容容器约 1150～1280px；平铺模式使用 2～3 列详细卡片。
- 游戏封面保持可识别但不挤压环境字段。
- 配置详情弹窗宽度随内容受控，最大高度不超过视口安全区。

### 9.3 390×844 手机竖屏

- 标题固定为“兼容性查询”，与返回入口、平台标识同排；隐藏说明文案。
- 三个筛选按钮同排等宽，单个按钮高度不小于 44px，整行不换行、不出现横向滚动。
- 按钮下方候选面板使用浮层定位，不推高结果区。
- 筛选按钮的可见短值允许省略，但无障碍名称必须保留完整字段名和已选值。
- 结果工具栏显示结果数量、清空筛选和“列表 / 平铺”开关。
- 标题、筛选和结果工具区的可见纵向占用目标约 125px，不得再接近半屏。
- 默认列表模式使用 108～120px 紧凑记录行，常规数据下 390×844 首屏目标看到 4～6 条记录的主要信息。
- 平铺模式在 390px 使用单列详细卡片；600px 及以上变为双列。
- 详细卡片使用紧凑文字信息区，不再使用四个大色块承载短字段。
- 配置详情使用全屏浮层。
- 主要点击区域不小于 44×44px，核心正文不小于 12px。

### 9.4 响应式断点

- 320、390、430px：筛选三按钮同排；列表为紧凑记录行；平铺为单列。
- 600px 及以上：平铺变为双列。
- 桌面容器：列表为表格，平铺为 2～3 列。
- 所有宽度不得分别实现筛选或结果数据逻辑，只允许更换布局样式与渲染器。

## 10. 组件、状态与数据流

### 10.1 组件边界

- `PlatformContext`：解析 Bridge、query 和 Demo 默认值。
- `CatalogAdapter`：校验并隔离平台目录。
- `FilterBar`：管理三个顶部筛选框和清空入口。
- `SearchableSelect`：统一处理下拉、输入搜索、候选选择和清除。
- `ResultToolbar`：显示热门 / 筛选结果数量、清空筛选和视图切换。
- `ViewModeSwitch`：只更新 `viewMode`，不修改结果集合。
- `RecordResults`：提供统一结果数据，并按视图与断点渲染桌面表格、紧凑列表或详细平铺。
- `ConfigViewer`：渲染桌面弹窗或手机全屏浮层。
- `DownloadController`：互斥处理 Web Blob 与 App Bridge 下载。
- `StatePanel`：加载、空数据、无候选、无结果和恢复状态。

### 10.2 统一状态

### 10.3 数据流

```text
Bridge / query / Demo 默认
  → PlatformContext 确定平台
  → CatalogAdapter 校验并隔离当前平台目录
  → 三个 SearchableSelect 分别搜索候选
  → 无筛选时生成不同游戏的热门代表记录
  → 有筛选时对全部记录执行 AND 过滤
  → 生成多条 CompatibilityRecord
  → 统一排序
  → ViewModeSwitch 选择列表或平铺渲染器
  → 列表记录可原位展开完整字段
  → ConfigViewer 查看配置
  → Web Blob 或 App Bridge 下载
```

桌面与手机、列表与平铺不得分别实现筛选、排序、数据转换或下载逻辑。

## 11. 数据口径与安全边界

最小目录对象：

```js
{
  games: [{ id, platform, name, englishName, aliases, coverKey }],
  hardware: [{ id, platform, type, displayName, aliases, deviceModel, soc, gpu, chip }],
  records: [{
    id, platform, gameId, hardwareIds, gameVersion, osVersion,
    appVersion, runtime, driver, resolution, rating, avgFps,
    stability, tags, notes, verifiedAt, configIds
  }],
  configs: [{
    id, platform, gameId, recordId, applicableGameVersion,
    applicableHardware, applicableOs, runtime, driver, resolution,
    quality, launchArgs, version, fileSize, downloadCount, updatedAt
  }]
}
```

规则：

- `rating` 只接受 1～5。
- `avgFps` 只接受 0～240；缺失时显示“—”。
- `hardwareIds` 同时关联具体设备/机型和 GPU/芯片，使任一硬件候选都能命中同一运行记录。
- 运行记录必须关联至少一个当前平台的有效硬件。
- 配置必须同时匹配当前平台、游戏和运行记录，否则拒绝查看和下载。
- 封面只接受受控本地资源键，失败时使用本地占位图。
- 名称、标签、备注和启动参数在渲染前转义并限制长度。
- 缺少环境字段时显示“未记录”，不推测兼容结论。

## 12. 下载策略

- 浏览器环境只允许把受控目录中的配置内容生成 Blob 下载，不接受任意外部 URL。
- App 环境只调用 `GameHubBridge.downloadConfig`，不得同时触发浏览器下载。
- 每次下载生成唯一 `requestId`，只接受当前请求回调。
- 下载进行中禁用重复点击；成功、失败或超时后恢复按钮。
- 迟到或重复回调不得覆盖当前下载状态。
- Demo 下载内容明确标记为模拟配置，不宣称可直接用于正式客户端。

## 13. 状态、异常与恢复

| 场景 | 处理 |
|---|---|
| 未选择任何条件 | 展示当前平台 4～6 款不同热门游戏的代表记录；不足时按实际数量展示 |
| 下拉搜索无候选 | 保留关键词，显示“暂无匹配选项” |
| 组合筛选无结果 | 保留全部条件，提供单项清除和“清空筛选” |
| 当前平台目录为空 | 显示平台专属空状态和“重新加载” |
| 目录加载失败 | 显示重新加载，不展示旧平台数据 |
| 平台值缺失或无效 | Demo 默认 Android，并显示当前平台 |
| Bridge 与 query 冲突 | 以 Bridge 为准 |
| 清空全部筛选 | 恢复当前平台热门代表记录 |
| 切换平台 | 清空筛选、排序、展开记录、详情和下载状态；保留 `viewMode` |
| 切换列表 / 平铺 | 保留筛选、排序、结果顺序和配置上下文，只替换结果呈现 |
| FPS、备注或标签缺失 | 显示“—”或隐藏空标签 |
| 记录没有配置 | 显示“暂无配置”，不提供查看入口 |
| 配置与当前上下文不一致 | 拒绝查看和下载 |
| 浏览器下载被拦截 | 详情内原位提示并允许重试 |
| App Bridge 不存在或抛错 | 详情内提示“App 连接不可用”，不伪造成功 |
| App 下载超时 | 恢复按钮并允许重试 |
| 迟到或重复回调 | 通过 `requestId` 忽略 |

## 14. 验收标准

- 同一 H5 能通过 Bridge、query 和 Demo 默认值正确识别平台。
- Android/Mac 的筛选候选、运行记录、字段和配置严格隔离。
- 顶部同时存在游戏、硬件和最低评分三个快捷下拉筛选框。
- 手机三个筛选按钮在 320～430px 始终同排，候选浮层不推高结果区。
- 三个下拉均支持输入搜索、候选选择和单项清除。
- 游戏候选展示本地封面、中文名、英文名和当前平台。
- 最低评分明确使用“X 分及以上”，不会误删更高评分记录。
- 任一条件可独立查询，多条件按 AND 过滤。
- 无筛选时按热门代表算法展示 4～6 款不同游戏；清空筛选恢复热门结果。
- 结果按运行记录展示，同一游戏允许出现多条记录。
- 默认排序为评分降序、验证时间降序。
- 只存在“列表 / 平铺”一个视图开关：列表为简约高密度，平铺为完整详细。
- 手机默认列表模式，390×844 常规数据首屏展示 4～6 条主要信息；点击记录最多原位展开一条。
- 390px 平铺为单列，600px 及以上为双列；桌面平铺为 2～3 列。
- 列表 / 平铺的结果数量和排序一致，切换时不丢筛选或改变顺序。
- 兼容记录不进入单游戏详情页。
- 配置详情在桌面为居中弹窗、手机为全屏浮层。
- 关闭配置详情后保留筛选、排序和滚动位置。
- Web/App 下载互斥，并覆盖成功、失败、超时、重复点击和迟到回调。
- 320、390、430、600px 与桌面宽度均无横向溢出。
- HTML、脚本、样式和图片可离线运行，无外部请求和未处理异常。
