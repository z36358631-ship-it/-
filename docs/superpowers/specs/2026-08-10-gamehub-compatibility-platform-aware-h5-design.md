# 盖世游戏跨平台兼容性 H5 高保真改版设计规格

**日期：** 2026-08-10

**任务：** GUANWANGGAID-4

**状态：** 方案已确认，待书面规格确认

**参考结构：** GameNative Compatibility

**目标形态：** 单一 H5 自动识别 Android / Mac 平台

## 1. 结论

在现有兼容性查询 Demo 上重构一套单一、响应式、可在浏览器和盖世游戏 App WebView 中运行的高保真 H5。页面自动识别当前平台，Android 与 Mac 共用页面框架、搜索交互和视觉规范，但严格使用各自的数据、字段和启动配置。

核心链路收敛为：图文搜索游戏 → 查看当前平台的兼容表现 → 查看启动配置详情 → 下载配置。正式环境不要求用户选择平台；仅在 Demo 验收工具栏提供 Android / Mac 预览切换。

## 2. 用户、问题与现状

### 2.1 目标用户

- Android 用户：准备通过盖世游戏运行 PC 游戏，需要确认自己的手机、GPU 和 Android 环境能否运行目标游戏。
- Mac 用户：准备通过盖世游戏在 Apple 芯片 Mac 上运行目标游戏，需要确认芯片、macOS 和兼容层要求。
- 网页访客：尚未进入 App，希望先查询兼容记录并下载可用启动配置。

### 2.2 需要解决的问题

- 现有页面虽然能查询兼容记录，但视觉基础、信息表达不够精致，未达到高保真验收标准。
- 当前页面没有体现 Android 与 Mac 的真实差异，容易让用户看到不适用于本机的环境字段和结论。
- 游戏搜索候选缺少足够鲜明的图文识别，竖屏操作缺乏内容吸引力。
- 最新需求要求启动配置可查看和下载，而当前规格与验证脚本明确禁止配置查看、下载，必须整体返工。

### 2.3 用户现有解决方式

用户通常在社区、视频、群聊或零散测试记录中搜索同机型经验，再自行比对游戏版本、设备、系统、兼容层和驱动。即使找到别人分享的配置，也难以判断是否适用于自己的平台和环境。

### 2.4 参考页面可借鉴与应规避

可借鉴 GameNative Compatibility 的同页搜索、即时结果和低操作成本；游戏一旦选中，结果应原位出现，不增加确认步骤。

应规避：直接复制参考站品牌、用宽表格压缩移动端、要求普通用户理解全部硬件术语、把 Android 与 Mac 数据混在一个结果集合、增加不必要的筛选层级。

## 3. 方案选择

### 3.1 已确认方案：单一 H5 自动识别平台

一个 H5 维护统一页面壳、视觉令牌、交互状态和组件，通过平台适配层选择 Android 或 Mac 目录。优势是体验一致、维护成本低，并能同时服务浏览器和 App WebView。

### 3.2 未采用方案

- Android / Mac 两套 H5：平台边界清楚，但页面、交互和测试重复，后续容易出现版本不一致。
- 正式页面手动选择平台：实现简单，但增加用户操作并可能让用户主动切到错误平台。

## 4. 范围

### 4.1 本次完成

- 单一响应式 H5 与 Android / Mac 自动识别。
- 带本地封面、游戏名、别名和平台可用性的图文搜索。
- Android / Mac 各自的热门游戏、搜索结果、兼容字段和配置数据。
- 游戏兼容结果、启动配置原位展开详情和下载闭环。
- 浏览器下载、App Bridge 下载及其加载、成功、失败、超时、重试状态。
- 390×844 竖屏优先设计，并兼容桌面网页宽度。
- 可操作 Demo、自动验证和 Android / Mac 高保真验收截图。

### 4.2 明确不做

- 全量游戏与配置后台。
- 登录、会员、付费、收藏、分享、评论和配置上传。
- 一键应用配置、下载并应用、自动启动游戏。
- Android / Mac 以外的平台。
- 正式环境的平台手动切换入口。
- 与本任务无关的页面或数据改造。

## 5. 页面结构与核心流程

页面保持单一 H5，通过内部视图状态完成以下结构：

1. 顶部返回入口、当前平台标识和页面标题。
2. 图文游戏搜索框。
3. 当前平台的热门游戏网格。
4. 搜索候选或兼容结果。
5. 启动配置列表与原位展开详情。
6. Demo 环境专用的尺寸与平台预览工具栏。

### 5.1 首次进入

1. H5 按固定优先级识别平台。
2. 页面显示“Android”或“Mac”平台标识。
3. 搜索框下展示当前平台的热门游戏，不渲染另一平台内容。

### 5.2 图文搜索

1. 用户输入中文名、英文名或别名。
2. 候选项同时展示本地封面、游戏名、别名和当前平台可用状态。
3. 点击候选项后原位展示兼容结果，不设置额外查询按钮。
4. 清除搜索后恢复当前平台热门游戏。

### 5.3 查看兼容结果与配置

1. 结果首屏展示游戏封面、名称、当前平台结论、运行表现和验证时间。
2. 下方展示适用于当前平台的启动配置卡。
3. 点击配置卡后在当前结果中展开配置详情，不新增弹窗或独立页面。
4. 用户确认版本、适用环境、推荐参数和文件信息后点击“下载配置”。

## 6. 平台识别与隔离

平台来源优先级固定为：

```text
App Bridge 注入 > URL query 参数 > Demo 默认 Android
```

规则如下：

- App WebView 通过 `setContext({ platform })` 注入 `android` 或 `mac`。
- 浏览器可通过 `?platform=android` 或 `?platform=mac` 指定平台。
- 未提供有效平台时，Demo 默认 Android，并明确显示平台标识。
- App Bridge 与 query 冲突时以 Bridge 为准。
- 平台变化后清空已选游戏、展开配置和下载状态，再按新平台重新渲染。
- 热门游戏、搜索候选、兼容记录和配置必须同时通过 `platform` 过滤。
- Demo 平台切换控件置于页面容器之外，正式 H5 内容中不渲染该控件。

## 7. Android 与 Mac 内容差异

### 7.1 Android

兼容结果展示：

- 手机型号、SoC / GPU。
- Android 版本。
- 盖世游戏版本与运行环境。
- 驱动或兼容层信息。
- 平均 FPS、稳定性结论、问题标签和验证时间。

配置详情展示：

- 适用游戏版本、设备 / GPU 和 Android 范围。
- 分辨率、画质、驱动或运行环境等推荐参数。
- 配置版本、文件大小、下载次数和更新时间。

### 7.2 Mac

兼容结果展示：

- Mac 机型或 Apple 芯片。
- macOS 版本。
- 盖世游戏版本与兼容层。
- 分辨率或显示模式。
- 平均 FPS、稳定性结论、问题标签和验证时间。

配置详情展示：

- 适用游戏版本、Apple 芯片和 macOS 范围。
- 兼容层、分辨率、画质与启动参数等推荐配置。
- 配置版本、文件大小、下载次数和更新时间。

Mac 页面不得出现手机型号、Android 或移动 GPU 字段；Android 页面不得出现 Apple 芯片或 macOS 字段。

## 8. 视觉与响应式设计

### 8.1 视觉方向

- 使用盖世游戏黑、深灰、白和品牌金的克制视觉体系。
- 页面首屏以大尺寸图文搜索和真实本地游戏封面形成视觉重点。
- 卡片采用统一圆角、描边、层级阴影和高对比状态标签。
- 不复制 Stitch 或 GameNative 的 Logo、品牌配色和文案。
- 不使用运行时外链、iframe 或 CDN；图片和脚本可离线加载。

### 8.2 390×844 竖屏

- 首屏优先露出标题、平台、完整搜索框和至少一行热门游戏。
- 搜索结果使用单列图文卡，不出现横向滚动。
- 主要点击区域不小于 44×44px，核心正文不小于 12px。
- 配置详情在卡片内分组展示，下载按钮保持清晰但不遮挡内容。

### 8.3 桌面网页

- 使用居中内容容器，搜索和结果维持相同业务结构。
- 热门游戏使用多列网格，兼容信息可使用双列分组卡片。
- 不为桌面端新增另一套筛选或数据逻辑。

## 9. 组件与数据流

### 9.1 组件边界

- `PlatformContext`：解析 Bridge、query 和 Demo 默认值。
- `SearchPanel`：输入、候选、清除和键盘操作。
- `PopularGames`：渲染当前平台热门游戏。
- `CompatibilityResult`：展示当前平台兼容结果。
- `ConfigList`：展示可用配置和展开状态。
- `ConfigDetail`：展示配置字段和下载操作。
- `DownloadController`：在 Web 与 App 下载路径间互斥路由。
- `StatePanel`：加载、空数据、失败、超时和重试。

### 9.2 统一状态

```js
{
  platform: "android",
  platformSource: "demo",
  gameQuery: "",
  selectedGameId: null,
  expandedConfigId: null,
  catalogStatus: "ready",
  download: {
    requestId: null,
    configId: null,
    status: "idle",
    message: ""
  }
}
```

### 9.3 数据流

```text
Bridge / query / Demo 默认
  → PlatformContext 确定平台
  → Adapter 校验并按平台隔离目录
  → 搜索与选择游戏
  → 兼容结果与配置列表
  → Web 下载或 App Bridge 下载
  → 下载状态原位反馈
```

## 10. 下载策略与安全边界

- 浏览器环境只允许下载目录中受控配置生成的本地 Blob，不接受目录数据直接提供任意外部 URL。
- App 环境只调用 `GameHubBridge.downloadConfig`，不同时触发浏览器下载。
- 每次下载生成唯一 `requestId`，只接受当前请求的回调，防止超时和迟到回调重复更新状态。
- 下载进行中禁用重复点击；成功、失败或超时后恢复按钮。
- Demo 的下载产物为明确标注的模拟配置，不宣称可直接用于真实客户端。
- 配置详情中的平台、游戏、版本必须与当前上下文一致；不一致时拒绝下载并提示重新选择。

## 11. 异常与边界

| 场景 | 处理 |
|---|---|
| 平台值缺失或无效 | 默认 Android，并显示当前平台 |
| Bridge 与 query 冲突 | 以 Bridge 为准 |
| 切换平台后原游戏不存在 | 清空游戏与配置，恢复该平台首页 |
| 搜索无结果 | 保留关键词，显示清除入口 |
| 当前游戏没有兼容记录 | 显示“暂无验证记录”，不推测结论 |
| 当前游戏没有配置 | 显示“暂无可下载配置”，不展示下载按钮 |
| 目录字段异常 | Adapter 丢弃无效项，页面继续运行 |
| 浏览器下载被拦截 | 原位提示并允许重试 |
| App Bridge 不存在或抛错 | 原位提示“App 连接不可用”，不伪造成功 |
| App 下载超时 | 按钮恢复并允许重新下载 |
| 迟到或重复回调 | 通过 `requestId` 忽略 |
| 封面加载失败 | 使用盖世游戏风格本地占位封面 |

## 12. 验收标准

- 同一 H5 能通过 Bridge、query 和 Demo 默认值正确识别平台。
- 正式 H5 内不出现用户平台切换控件；Demo 可预览 Android 和 Mac。
- Android / Mac 的热门游戏、搜索候选、兼容字段和配置严格隔离。
- 搜索候选同时展示本地封面和文字，支持中文名、英文名和别名。
- 选择游戏后无需确认按钮即可展示兼容结果。
- 配置可原位展开查看，并能在浏览器和 App 模拟环境分别下载。
- 下载加载、成功、失败、超时、重试和重复回调状态正确。
- 390×844 竖屏首屏信息完整、点击热区合格且无横向溢出。
- 桌面网页布局完整，不维护第二套业务逻辑。
- HTML、脚本和图片可离线运行，无外部请求、控制台错误或未处理异常。

- 响应式验证：390×844 与桌面宽度下无横向溢出。
