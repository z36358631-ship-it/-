# 盖世游戏跨平台兼容性 H5 多参数查询改版设计规格

**日期：** 2026-08-10

**任务：** GUANWANGGAID-4

**状态：** 返工方案已确认，待书面规格审阅

**参考结构：** [GameNative Compatibility](https://gamenative.app/compatibility/)

**目标形态：** 单一 H5 自动识别 Android / Mac，复刻竞品的多参数即时查询与多记录结果体验

## 1. 结论

现有版本把兼容性数据库收窄成了“搜索一个游戏并查看单个详情”，与 GameNative Compatibility 的真实结构不一致。本次返工恢复为一个多参数兼容性查询页：顶部提供三个快捷下拉筛选框，每个下拉框均支持输入搜索；任一条件变化后即时执行 AND 过滤，并展示多条兼容运行记录。

Android 使用“游戏 / 设备或 GPU / 最低评分（≥）”，Mac 使用“游戏 / Mac 机型或 Apple 芯片 / 最低评分（≥）”。桌面端以高密度表格呈现结果，手机端以字段一致的单列卡片呈现。兼容记录不进入单游戏详情页；只有“启动配置详情”独立承载，桌面使用居中弹窗，手机使用全屏浮层。

平台识别、Android/Mac 数据隔离、配置查看与 Web/App 下载能力继续保留。

## 2. 用户、问题与竞品依据

### 2.1 目标用户

- Android 用户：希望按游戏、手机型号或 GPU 查询实际运行记录。
- Mac 用户：希望按游戏、Mac 机型或 Apple 芯片查询实际运行记录。
- 网页访客：尚未进入 App，希望先判断兼容表现并下载适用配置。

### 2.2 用户问题

- 用户不一定先知道要查哪个游戏，也可能先按本机硬件查“能玩什么”。
- 同一游戏在不同设备、系统、盖世版本或运行环境下会产生多条结论，单游戏单结果会掩盖真实差异。
- 配置详情直接塞在结果卡内会拉长列表，破坏连续比较多条记录的效率。
- Android 与 Mac 的硬件和系统口径不同，不能共用一套候选和字段。

### 2.3 用户现有解决方式

用户通常在社区、群聊、视频和零散测试记录中搜索游戏或设备关键词，再人工比对游戏版本、硬件、系统、兼容层、驱动和验证时间。该方式信息分散，难以筛选，也容易把其他环境的成功结论误认为本机结论。

### 2.4 竞品事实

GameNative Compatibility 当前使用“Search by Game / GPU / Rating”三个顶部选择器，任一条件生效后直接展示兼容记录，而不是进入单游戏详情。历史竞品规格还记录了结果字段：游戏、设备、GPU、Android、App 版本、评分、平均 FPS、标签、备注、配置和创建时间。

本次借鉴：

- 三个顶部快捷筛选框。
- 下拉选择与输入搜索合并。
- 条件变化后即时刷新，无“查询”按钮。
- 输出多条兼容运行记录。
- 桌面高密度表格。

本次不复制：

- GameNative 的品牌、Logo、配色和文案。
- 不适合手机竖屏的横向宽表格。
- 只适用于 Android 的字段结构。

## 3. 已确认方案与范围

### 3.1 本次完成

- 单一响应式 H5 与 Android / Mac 自动识别。
- 三个顶部快捷下拉筛选框，全部支持输入搜索和单项清除。
- Android：“游戏 / 设备或 GPU / 最低评分（≥）”。
- Mac：“游戏 / Mac 机型或 Apple 芯片 / 最低评分（≥）”。
- 任一条件独立生效，多条件执行 AND 过滤。
- 同一游戏可展示多条独立兼容运行记录。
- 桌面表格与手机卡片共用同一筛选、排序和数据源。
- 启动配置详情：桌面居中弹窗、手机全屏浮层。
- 浏览器 Blob 下载与 App Bridge 下载。
- 加载、空数据、无候选、无结果、下载失败、超时和重试状态。

### 3.2 明确不做

- 单游戏兼容详情页。
- 兼容记录详情页。
- Android / Mac 两套独立 H5。
- 正式页面手动切换平台。
- 一键应用配置、下载并应用或自动启动游戏。
- 全量后台、登录、会员、付费、收藏、分享、评论和配置上传。
- 与本任务无关的页面、弹窗或流程。

### 3.3 未采用方案

- 统一搜索框加高级筛选：无法清楚表达用户当前在搜游戏还是硬件，也偏离竞品结构。
- 搜索页与结果页分离：增加提交和返回步骤，不符合即时查询。
- 继续使用单游戏详情：无法表达同一游戏在不同环境下的多条记录。

## 4. 平台识别与隔离

平台来源优先级固定为：

```text
App Bridge 注入 > URL query 参数 > Demo 默认 Android
```

规则：

- App WebView 通过 `setContext({ platform })` 注入 `android` 或 `mac`。
- 浏览器可通过 `?platform=android` 或 `?platform=mac` 指定平台。
- 未提供有效平台时，Demo 默认 Android，并显示当前平台。
- App Bridge 与 query 冲突时以 Bridge 为准。
- 游戏、硬件候选、运行记录和配置必须同时通过 `platform` 过滤。
- 切换平台时清空筛选、下拉搜索词、排序、配置详情和下载状态。
- Demo 平台切换工具置于正式页面容器之外。

Mac 页面不得出现手机型号、Android 或移动 GPU 字段；Android 页面不得出现 Apple 芯片或 macOS 字段。

## 5. 页面结构

页面从上到下包含：

1. 返回入口、当前平台标识、标题和一句说明。
2. 三个顶部快捷下拉筛选框。
3. 已选条件、结果数量和清空筛选入口。
4. 多条兼容运行记录。
5. 启动配置弹窗或全屏浮层。
6. Demo 环境专用的平台和尺寸预览工具栏。

未选择任何条件时不渲染任意单游戏结果，显示“添加筛选条件开始查询”。游戏仍通过带封面和文字的下拉候选以及结果列表完成图文展示。

## 6. 顶部快捷筛选

### 6.1 通用交互

- 点击筛选框打开下拉面板。
- 下拉面板顶部提供输入框，输入后即时过滤当前字段的候选。
- 选择候选后关闭下拉并立即刷新结果。
- 每项已选条件可单独清除；页面提供“清空筛选”。
- 三项都可单独使用；两项或三项同时选择时按 AND 过滤。
- 不增加“查询”“确定”或第二层筛选页。
- 下拉支持键盘焦点、方向键选择、Enter 确认和 Esc 关闭。

### 6.2 游戏筛选

- 支持中文名、英文名和别名搜索。
- 候选同时展示本地封面、中文名、英文名和当前平台标签。
- 同一游戏在 Android 与 Mac 可拥有不同的可用记录数量。

### 6.3 硬件筛选

Android：

- 支持手机型号、SoC、GPU 名称和别名搜索。
- 候选主标题优先显示设备型号；缺少具体设备时显示 GPU。
- 副信息显示 SoC / GPU，避免只显示用户不理解的内部 ID。

Mac：

- 支持 Mac 机型、Apple 芯片和别名搜索。
- 候选主标题显示 Mac 机型或 Apple 芯片。
- 副信息显示芯片与可用 macOS 范围。

### 6.4 最低评分筛选

字段名称固定为“最低评分（≥）”，不得只写“评分”。

候选为：

- 全部。
- 5 分。
- 4 分及以上。
- 3 分及以上。
- 2 分及以上。
- 1 分及以上。

下拉输入支持搜索数字或“及以上”。选择“4 分及以上”时必须保留 4 分和 5 分记录。

## 7. 多条兼容运行记录

### 7.1 结果口径

一条结果代表一条 `CompatibilityRecord`，不是一个游戏聚合卡。只要设备、GPU/芯片、游戏版本、系统、盖世版本或运行环境不同，就可以展示为独立记录。

结果默认排序：

1. 评分从高到低。
2. 评分相同时，验证时间从新到旧。

桌面允许点击“评分”和“验证时间”表头切换排序；手机沿用同一排序结果，不增加独立排序控件。

### 7.2 Android 结果字段

- 游戏封面、中文名和英文名。
- 设备型号、SoC / GPU。
- 游戏版本。
- Android 版本。
- 盖世游戏版本与运行环境。
- 驱动或兼容层。
- 评分、平均 FPS 和稳定性结论。
- 问题标签和简短备注。
- 配置数量与查看入口。
- 验证时间。

### 7.3 Mac 结果字段

- 游戏封面、中文名和英文名。
- Mac 机型或 Apple 芯片。
- 游戏版本。
- macOS 版本。
- 盖世游戏版本与兼容层。
- 分辨率或显示模式。
- 评分、平均 FPS 和稳定性结论。
- 问题标签和简短备注。
- 配置数量与查看入口。
- 验证时间。

### 7.4 配置入口

- 有配置：显示“查看配置（N）”。
- 无配置：显示“暂无配置”，不可点击。
- 点击只打开启动配置详情，不进入兼容记录或游戏详情页。

## 8. 启动配置详情

### 8.1 承载方式

- 桌面端：居中弹窗，背景遮罩，内容区可独立滚动。
- 手机端：全屏浮层，顶部固定返回/关闭，底部操作区不遮挡内容。
- 两种尺寸使用同一份 DOM、状态和数据，只通过响应式样式改变形态。
- 关闭后恢复原筛选、排序和滚动位置。

### 8.2 多配置处理

同一运行记录存在多份配置时，在同一弹窗/浮层内先显示配置列表。选择配置后在该容器内展示对应详情，不再创建第三层页面或第二个弹窗。

### 8.3 配置内容

1. 适用范围：平台、游戏版本、设备/GPU 或 Apple 芯片、系统范围。
2. 启动参数：兼容层、驱动、分辨率、画质和启动参数。
3. 文件信息：配置版本、文件大小、更新时间和下载次数。

底部显示“下载配置”，不增加“一键应用”。

## 9. 视觉与响应式

### 9.1 视觉方向

- 使用盖世游戏黑、深灰、白和品牌金的克制视觉体系。
- 不复制 GameNative 或 Stitch 的 Logo、品牌配色和文案。
- 下拉、表格、卡片和弹窗使用统一圆角、描边、阴影和状态标签。
- 图片、脚本和样式本地化，不使用 iframe、CDN 或运行时外链。

### 9.2 桌面网页

- 三个筛选框顶部横向等分排列。
- 结果使用紧凑表格，内容容器约 1150～1280px。
- 游戏封面保持可识别但不挤压环境字段。
- 配置详情弹窗宽度随内容受控，最大高度不超过视口安全区。

### 9.3 390×844 手机竖屏

- 三个筛选框纵向排列或按可读宽度换行，不出现横向滚动。
- 结果使用单列卡片，字段与桌面表格一致。
- 卡片首屏优先显示游戏、硬件、评分和 FPS；环境、标签、备注、配置和时间继续在同一卡内展示。
- 配置详情使用全屏浮层。
- 主要点击区域不小于 44×44px，核心正文不小于 12px。

## 10. 组件、状态与数据流

### 10.1 组件边界

- `PlatformContext`：解析 Bridge、query 和 Demo 默认值。
- `CatalogAdapter`：校验并隔离平台目录。
- `FilterBar`：管理三个顶部筛选框和清空入口。
- `SearchableSelect`：统一处理下拉、输入搜索、候选选择和清除。
- `RecordResults`：提供统一结果数据，并渲染桌面表格或手机卡片。
- `ConfigViewer`：渲染桌面弹窗或手机全屏浮层。
- `DownloadController`：互斥处理 Web Blob 与 App Bridge 下载。
- `StatePanel`：加载、空数据、无候选、无结果和恢复状态。

### 10.2 统一状态

```js
{
  platform: "android",
  platformSource: "demo",
  filters: {
    gameId: null,
    hardwareId: null,
    ratingMin: null
  },
  queries: {
    game: "",
    hardware: "",
    rating: ""
  },
  sort: {
    field: "rating",
    direction: "desc"
  },
  viewer: {
    recordId: null,
    configId: null
  },
  catalogStatus: "ready",
  download: {
    requestId: null,
    configId: null,
    status: "idle",
    message: ""
  }
}
```

### 10.3 数据流

```text
Bridge / query / Demo 默认
  → PlatformContext 确定平台
  → CatalogAdapter 校验并隔离当前平台目录
  → 三个 SearchableSelect 分别搜索候选
  → 已选条件执行 AND 过滤
  → 生成多条 CompatibilityRecord
  → 统一排序
  → 桌面表格或手机卡片
  → ConfigViewer 查看配置
  → Web Blob 或 App Bridge 下载
```

桌面与手机不得分别实现筛选、排序、数据转换或下载逻辑。

## 11. 数据口径与安全边界

最小目录对象：

```js
{
  games: [{ id, platform, name, englishName, aliases, coverKey }],
  hardware: [{ id, platform, type, displayName, aliases, deviceModel, soc, gpu, chip }],
  records: [{
    id, platform, gameId, hardwareIds, gameVersion, osVersion,
    appVersion, runtime, driver, resolution, rating, avgFps,
    stability, tags, notes, verifiedAt, configIds
  }],
  configs: [{
    id, platform, gameId, recordId, applicableGameVersion,
    applicableHardware, applicableOs, runtime, driver, resolution,
    quality, launchArgs, version, fileSize, downloadCount, updatedAt
  }]
}
```

规则：

- `rating` 只接受 1～5。
- `avgFps` 只接受 0～240；缺失时显示“—”。
- `hardwareIds` 同时关联具体设备/机型和 GPU/芯片，使任一硬件候选都能命中同一运行记录。
- 运行记录必须关联至少一个当前平台的有效硬件。
- 配置必须同时匹配当前平台、游戏和运行记录，否则拒绝查看和下载。
- 封面只接受受控本地资源键，失败时使用本地占位图。
- 名称、标签、备注和启动参数在渲染前转义并限制长度。
- 缺少环境字段时显示“未记录”，不推测兼容结论。

## 12. 下载策略

- 浏览器环境只允许把受控目录中的配置内容生成 Blob 下载，不接受任意外部 URL。
- App 环境只调用 `GameHubBridge.downloadConfig`，不得同时触发浏览器下载。
- 每次下载生成唯一 `requestId`，只接受当前请求回调。
- 下载进行中禁用重复点击；成功、失败或超时后恢复按钮。
- 迟到或重复回调不得覆盖当前下载状态。
- Demo 下载内容明确标记为模拟配置，不宣称可直接用于正式客户端。

## 13. 状态、异常与恢复

| 场景 | 处理 |
|---|---|
| 未选择任何条件 | 显示“添加筛选条件开始查询”，不默认展示单游戏结果 |
| 下拉搜索无候选 | 保留关键词，显示“暂无匹配选项” |
| 组合筛选无结果 | 保留全部条件，提供单项清除和“清空筛选” |
| 当前平台目录为空 | 显示平台专属空状态和“重新加载” |
| 目录加载失败 | 显示重新加载，不展示旧平台数据 |
| 平台值缺失或无效 | Demo 默认 Android，并显示当前平台 |
| Bridge 与 query 冲突 | 以 Bridge 为准 |
| 切换平台 | 清空筛选、排序、详情和下载状态 |
| FPS、备注或标签缺失 | 显示“—”或隐藏空标签 |
| 记录没有配置 | 显示“暂无配置”，不提供查看入口 |
| 配置与当前上下文不一致 | 拒绝查看和下载 |
| 浏览器下载被拦截 | 详情内原位提示并允许重试 |
| App Bridge 不存在或抛错 | 详情内提示“App 连接不可用”，不伪造成功 |
| App 下载超时 | 恢复按钮并允许重试 |
| 迟到或重复回调 | 通过 `requestId` 忽略 |

## 14. 验收标准

- 同一 H5 能通过 Bridge、query 和 Demo 默认值正确识别平台。
- Android/Mac 的筛选候选、运行记录、字段和配置严格隔离。
- 顶部同时存在游戏、硬件和最低评分三个快捷下拉筛选框。
- 三个下拉均支持输入搜索、候选选择和单项清除。
- 游戏候选展示本地封面、中文名、英文名和当前平台。
- 最低评分明确使用“X 分及以上”，不会误删更高评分记录。
- 任一条件可独立查询，多条件按 AND 过滤。
- 结果按运行记录展示，同一游戏允许出现多条记录。
- 默认排序为评分降序、验证时间降序。
- 桌面表格与手机卡片的结果数量、字段和排序一致。
- 兼容记录不进入单游戏详情页。
- 配置详情在桌面为居中弹窗、手机为全屏浮层。
- 关闭配置详情后保留筛选、排序和滚动位置。
- Web/App 下载互斥，并覆盖成功、失败、超时、重复点击和迟到回调。
- 390×844 与桌面宽度均无横向溢出。
- HTML、脚本、样式和图片可离线运行，无外部请求和未处理异常。

## 15. 验证与交付证据

### 15.1 自动验证

- 静态契约：三个筛选框、平台字段映射、结果结构、配置浮层与下载接口。
- 筛选验证：游戏单筛、硬件单筛、评分单筛、两两组合、三项组合和清空恢复。
- 多记录验证：同一游戏的不同设备、版本或环境不会被合并。
- 平台验证：Android/Mac 候选、记录、配置和异常状态不串线。
- 响应式验证：桌面表格、390×844 卡片、弹窗/全屏浮层和无横向溢出。
- 下载验证：Web Blob、App Bridge、失败、超时、重试、重复点击和迟到回调。

### 15.2 验收产物

- 可操作 H5 Demo。
- 本设计规格与实施计划。
