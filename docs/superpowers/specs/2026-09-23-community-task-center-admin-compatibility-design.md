# 社区任务中心后台 Demo 兼容改造设计

## 1. 目标

修改 `demos/后台管理/任务中心后台demo.html` 的“任务配置”页，使其兼容已确定的每日任务与成长任务清单，并补齐任务条件、按钮、跳转页面和目标值配置。Demo 必须能展示、创建、编辑和回显完整配置，用于运营确认及客户端、服务端联调说明。

本次只修改任务配置页。奖品配置、兑换与发货、C 端任务中心不调整。

## 2. 用户与问题

主要用户是配置社区任务的运营人员，以及依据配置联调的客户端和服务端研发。

当前 Demo 只有任务名称、任务类型、奖励、频率上限、指定话题和指定专区，存在四个问题：

1. 缺少“任务条件”，无法表达最终任务清单中的 API 活跃、APP 功能活跃、APP 社区活跃等分类与具体目的。
2. “指定话题、指定专区”对所有任务始终可见，非发帖任务也可误配。
3. 缺少按钮、跳转页面和目标值，客户端无法获得完整落地参数，服务端也无法用同一目标值判断指定对象。
4. 弹窗确认后没有把编辑值写回 Mock 数据，新增和编辑无法形成可验收闭环。

## 3. 设计原则

- 保留现有后台的页面骨架、Ant Design 风格、弹窗交互和单文件 HTML 形式。
- 将“任务完成条件”和“客户端跳转参数”分开表达，避免同为话题名称时发生歧义。
- 只在字段适用时显示；切换到不适用的配置时同步清空旧值。
- 最终任务清单作为 Mock 数据来源，不额外增加截图之外的任务。

## 4. 任务列表

任务列表调整为以下列：

| 列 | 含义 |
| --- | --- |
| 任务 ID | Mock 任务唯一标识 |
| 任务类型 | 每日任务 / 成长任务 |
| 任务条件 | 如 APP 活跃、APP 社区活跃、社区引导 |
| 目的 | 如每日签到、社区帖子发布、首次加入社区分区 |
| 积分 | 单次完成奖励 |
| 每日上限 | 对应最终任务表中的上限值；无上限显示 `-` |
| 按钮 | 客户端按钮文案；无按钮显示 `-` |
| 跳转页面 | 固定页面或指定对象页面；无跳转显示 `-` |
| 目标值 | 指定帖子时显示帖子 ID，指定话题时显示话题名称，其余显示 `-` |
| 状态 | 生效中 / 已停用 |
| 操作 | 编辑配置、启用/停用 |

表格放在可横向滚动容器内，避免新增列后压缩文字或导致操作列越界。

## 5. 弹窗结构

新增和编辑共用同一弹窗，按三个区域组织。

### 5.1 基本配置

- 任务类型：必填，单选 `每日任务` 或 `成长任务`。
- 任务条件：必填，按任务类型展示对应分组与选项。
- 任务目的：必填，使用最终任务清单中的具体任务名称。
- 连续签到天数：仅任务目的为“连续签到”时显示，必填，平铺单选 `3天`、`7天`、`15天`、`30天`、`自定义`；选择自定义后输入 `1-99` 的整数，每条任务只配置一个连续天数。
- 奖励积分：必填，正整数。
- 每日上限：使用最终任务表数值；允许填写正整数或 `-`。

切换任务类型时，只保留该类型下可用的任务条件；当前条件不再适用时，自动选择该类型的首个条件，并同步更新目的默认值。

### 5.2 完成条件

只有任务目的为 `社区帖子发布` 或 `首次发布社区帖子` 时显示该区域：

- 指定话题：可选；默认“不限”，可选择预设话题或填写自定义话题。
- 指定专区：可选；默认“全部专区”，可选择预设专区。

切换到其他任务目的时隐藏该区域，并将 `topic`、`zone` 清空，避免不可见旧值继续生效。

连续签到天数是任务完成条件的一部分，与奖励积分一一对应；它不使用“目标值”字段。切换到其他任务目的时清空 `streakDays`。

“指定话题”表示完成任务时帖子必须归属的话题，是服务端完成条件；它不等于跳转配置中的“目标值”。

### 5.3 跳转配置

- 按钮文案：对应最终任务表中的按钮；无按钮可填写 `-`。
- 跳转页面：支持最终任务清单中的无跳转、游戏库、社区、打开发帖、打开广告，并补充指定帖子、指定话题两类可带参数的落地方式。
- 目标值：只在跳转页面为“指定帖子”或“指定话题”时显示。

目标值联动规则：

| 跳转页面 | 目标值显示 | 目标值规则 |
| --- | --- | --- |
| 指定帖子 | 显示且必填 | 帖子 ID，去除首尾空格后不能为空 |
| 指定话题 | 显示且必填 | 话题名称，去除首尾空格后不能为空 |
| 其他页面或无跳转 | 隐藏 | 切换时清空 `targetValue` |

目标值同时用于客户端拼装跳转参数和服务端判断指定对象。

## 6. 数据模型

每条 Mock 任务使用以下字段：

```js
{
  id: 'T_001',
  type: 'daily',
  conditionGroup: 'app_active',
  purpose: '每日签到',
  streakDays: '',
  reward: 2,
  dailyLimit: '2',
  buttonText: '签到',
  landingPage: 'none',
  targetValue: '',
  topic: '',
  zone: '',
  status: 1
}
```

`conditionGroup` 使用稳定英文枚举，界面通过映射显示中文。`landingPage` 也使用枚举，至少包含 `none`、`game_library`、`community`、`create_post`、`open_ad`、`specific_post`、`specific_topic`。

## 7. 保存与编辑

- 新增：校验通过后生成新的任务 ID，将表单值写入 `mockTasks`，关闭弹窗并刷新列表。
- 编辑：根据任务 ID 覆盖对应对象，保留原 ID 和状态，关闭弹窗并刷新列表。
- 回显：再次打开编辑弹窗时，任务类型、任务条件、目的、积分、上限、按钮、跳转页面、目标值、指定话题和指定专区均按保存值回显。
- 回显：连续签到任务还需要回显“连续签到天数”。
- 切换清空：离开发帖类任务时清空 `topic/zone`；离开连续签到任务时清空 `streakDays`；离开指定帖子或指定话题跳转时清空 `targetValue`。

## 8. 校验与反馈

- 任务类型、任务条件、任务目的、奖励积分为空时阻止保存。
- 奖励积分必须为大于 0 的整数。
- 任务目的为连续签到时，连续签到天数必须选择固定天数或输入 `1-99` 的自定义整数；超过 99 天阻止保存。
- 跳转页面为指定帖子或指定话题时，目标值为空则阻止保存，并在目标值输入框下显示对应提示。
- 帖子 ID 和话题名称本期只校验非空，不虚构线上 ID 格式或字数限制。
- 保存成功沿用现有 Toast；字段错误优先在字段下方显示，不增加新弹窗。

## 9. 验收标准

1. 列表展示最终任务清单的每日任务和成长任务，并包含跳转页面、目标值列。
2. 新增与编辑弹窗按三个区域展示，样式与现有后台一致。
3. 选择 `社区帖子发布` 或 `首次发布社区帖子` 时显示指定话题和指定专区；切换到其他目的时隐藏并清空。
4. 选择 `连续签到` 时平铺显示 3、7、15、30 天和自定义；选择自定义后可输入 1-99 的整数，其他目的隐藏并清空。
5. 选择指定帖子时显示“目标值”，提示输入帖子 ID；选择指定话题时提示输入话题名称。
6. 切换到普通固定页面后目标值隐藏并清空。
7. 指定帖子或指定话题缺少目标值时无法保存，并显示明确错误。
8. 新增任务保存后出现在列表，编辑保存后列表更新，再次编辑可完整回显。
9. 新增列在常用桌面宽度下可横向滚动，表格、弹窗和按钮无重叠或截断。
10. 奖品配置与兑换发货页面行为无回归。

## 10. 不在本期范围

- 不接入真实接口、真实帖子或话题查询。
- 不修改奖品、兑换、发货或 C 端页面。
- 不新增批量导入、排序、复制任务、审核流或权限控制。
- 不定义后端协议以外的线上帖子 ID 格式。
