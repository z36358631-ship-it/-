# 买断游戏与永久 DLC：直接购买／CDKEY 双履约设计

> 本文记录 2026-09-09 的最新业务确认，并覆盖同日旧设计中“CDKEY 仅作页面参考、不进入履约”的结论。旧文档仍保留为方案演进记录；本次实现、PRD 和验收以本文为准。

## 1. 目标与用户问题

玩家购买买断游戏本体或永久 DLC 时，可能有两种获取需求：直接把内容加入当前盖世账号，或者购买一枚可查看、复制并支持一键激活的 CDKEY。现有直购 Demo 只能直接发放账号权益，旧 CDKEY Demo 又把两类购买和后续激活动作混在一起，容易让玩家误以为“一键激活”是第三种购买方式。

本次目标是把两种履约方式放进同一条下单链路：

1. 下单时只选择“直接购买”或“购买 CDKEY”。
2. 支付前明确展示各自的价格、到账结果、适用范围和退款规则。
3. 支付后按订单锁定的履约类型进入账号权益发放或 CDKEY 分配。
4. CDKEY 到货后再提供查看、复制和一键激活；一键激活不再次收费，也不是第三种购买方式。
5. 订单中心完整展示支付、履约、激活、退款、拒付和用户删除状态。

## 2. 已确认范围

- 商品仅包括买断游戏本体与永久 DLC，Android 与 Mac 均可下单和查询。
- 同一商品允许配置“直接购买”和“购买 CDKEY”两种可售 Offer；价格、库存和适用平台／地区可以分别配置。
- 订单创建时把 `fulfillment_type` 固定为 `account_entitlement` 或 `cdkey`，支付开始后不可原单切换。
- 直接购买成功后向当前盖世账号发放永久权益，并在 Android 与 Mac 同步。
- CDKEY 分配成功后允许查看、复制和一键激活；激活始终使用原订单分配的同一枚 Key。
- Google Play 安装包继续使用 Google Play Billing；官网 APK 与 Mac 使用供应商待定的统一第三方支付适配层。
- 免费 Offer 仍生成 0 元订单；是否提供免费直购或免费 CDKEY 由生效 Offer 决定。
- 直接购买继续适用“支付成功后不超过 5×24 小时，且 Android 与 Mac 累计有效游玩严格小于 120 分钟”的无理由退款规则。
- CDKEY 未展示且可安全撤回／回库时允许退款；首次查看、复制或发起一键激活后不再支持无理由退款，但保留无效、重复、平台／地区与描述不符等质量售后及适用法律规定的权利。
- “删除订单”只改变玩家侧列表可见性，不删除支付、权益、Key、退款、拒付、结算或审计事实。
- 本轮不修改“02 游戏创建”、发行资料、包体、价格和折扣后台。

## 3. 核心产品决策

### 3.1 购买方式与使用动作分层

确认订单页的“购买方式”只有两个选项：

| 购买方式 | 履约类型 | 支付后结果 | 后续动作 |
|---|---|---|---|
| 直接购买 | `account_entitlement` | 游戏／DLC 加入当前盖世账号 | 查看游戏库、安装或启动、申请退款 |
| 购买 CDKEY | `cdkey` | 原订单分配一枚适用平台和地区明确的 CDKEY | 查看、复制、一键激活、质量售后 |

“一键激活”只在 CDKEY 已分配后出现。下单页不得把“直接购买／购买 CDKEY／一键激活”展示成三个平级选项。

### 3.2 选择与锁定

- 同时可售时默认选择“直接购买”，并排在第一位；“购买 CDKEY”排第二位。
- 每个选项独立展示售价、适用平台、适用地区、到账说明和退款摘要。
- 切换选项立即刷新金额、支付渠道、库存提示和规则，不沿用另一种方式的价格或承诺。
- 某一方式不可售时保留其位置并禁用，显示“当前地区不可用”“暂无可分配 CDKEY”等真实原因。
- 创建订单后锁定履约方式。若用户想更换，必须先取消未支付订单，再按当前生效价格重新下单。
- 支付确认中、已支付或履约已开始时禁止切换，也不能把缺货 CDKEY 静默改发为账号权益。

### 3.3 CDKEY 查看、复制与一键激活

- CDKEY 明文首次展示前必须确认：“查看后通常不再支持无理由退款；CDKEY 无效、重复或与描述不符仍可申请售后。”
- 确认后记录 `key_revealed_at`，再展示完整 Key；复制只记录 `key_copied_at`，不重复确认。
- “已查看”“已复制”是审计标签，不等于已激活。
- 一键激活前展示目标平台和接收账号；未绑定账号时先完成账号选择或绑定。
- 激活请求使用唯一 `activation_attempt_id`，重复点击复用原 Key，不重新配码。
- 只有外部平台可信接口返回成功，才能标记“已激活”。超时或结果未知停留“激活中／等待确认”，不得自行判定成功。
- 激活失败仍保留已分配 Key，允许再次激活、复制或查看指引；不能把 Key 状态回退为未分配。
- 一键激活区域明确展示“无需再次付费”。

## 4. 数据与状态域

订单展示状态只能由下列事实派生，不能用一个字段覆盖全部流程：

| 状态域 | 关键值 | 作用 |
|---|---|---|
| `fulfillment_type` | `account_entitlement`、`cdkey` | 锁定购买方式 |
| `payment_status` | `pending`、`confirming`、`paid`、`failed`、`cancelled`、`not_required` | 记录支付渠道事实 |
| `fulfillment_status` | `not_started`、`processing`、`blocked`、`succeeded`、`failed` | 表达通用履约进度 |
| `entitlement_status` | `granting`、`active`、`frozen`、`revoked` | 直接购买的账号权益事实 |
| `key_status` | `unallocated`、`allocating`、`delivered`、`reclaimed`、`failed` | CDKEY 的分配与回收事实 |
| `activation_status` | `not_started`、`processing`、`succeeded`、`failed`、`unknown` | CDKEY 一键激活事实 |
| `refund_status` | `none`、`review`、`refunding`、`partial`、`refunded`、`failed`、`rejected` | 退款事实 |
| `chargeback_status` | `none`、`open`、`won`、`lost` | 渠道拒付事实 |
| `visibility_status` | `visible`、`hidden_by_user` | 仅控制玩家列表可见性 |

CDKEY 记录还需保存 `key_revealed_at`、`key_copied_at`、`key_reclaimable`、Key 批次和不可逆指纹。Key 明文不得进入埋点、普通日志、开发者报表或客服导出。

## 5. 用户可见状态与动作矩阵

双履约订单中心共覆盖 24 个 `display_state`。每种状态必须提供一条评审样例；列表主操作与详情操作必须一致。

| # | 适用分支 | `display_state` | 用户文案 | 主要操作 | 可删除 |
|---:|---|---|---|---|---|
| 1 | 共用 | `pending` | 待支付 | 继续支付、取消订单 | 否 |
| 2 | 共用 | `confirming` | 支付确认中 | 查看进度 | 否 |
| 3 | 共用 | `payment_failed` | 支付失败 | 重新支付、取消订单 | 否 |
| 4 | 共用 | `cancelled` | 已取消 | 再次购买、删除订单 | 是 |
| 5 | 直接购买 | `fulfilling` | 正在添加到账号 | 查看进度 | 否 |
| 6 | 直接购买 | `fulfillment_blocked` | 等待本体权益 | 查看原因 | 否 |
| 7 | 直接购买 | `fulfillment_failed` | 添加到账号失败 | 重试添加 | 否 |
| 8 | 直接购买 | `completed` | 已添加到账号 | 查看游戏库、删除订单 | 是 |
| 9 | CDKEY | `key_allocating` | CDKEY 分配中 | 查看进度 | 否 |
| 10 | CDKEY | `key_blocked` | CDKEY 待补充 | 查看进度 | 否 |
| 11 | CDKEY | `key_failed` | CDKEY 发放失败 | 重试发放／联系客服 | 否 |
| 12 | CDKEY | `key_delivered` | CDKEY 已发放 | 查看、复制、一键激活、删除订单 | 是 |
| 13 | CDKEY | `key_activating` | 激活中 | 查看进度 | 否 |
| 14 | CDKEY | `key_activation_failed` | 激活失败 | 重试激活、复制 CDKEY | 否 |
| 15 | CDKEY | `key_activated` | 已激活 | 查看详情、删除订单 | 是 |
| 16 | 共用 | `refund_review` | 退款审核中 | 查看进度 | 否 |
| 17 | 共用 | `refunding` | 渠道退款中 | 查看进度 | 否 |
| 18 | 共用 | `refund_partial` | 部分处理中 | 查看明细 | 否 |
| 19 | 共用 | `refunded` | 已退款 | 查看详情、删除订单 | 是 |
| 20 | 共用 | `refund_failed` | 退款失败 | 查看原因、删除订单 | 是 |
| 21 | 共用 | `refund_rejected` | 退款未通过 | 查看原因、删除订单 | 是 |

| 24 | 共用 | `chargeback_lost` | 拒付败诉 | 查看结果、删除订单 | 是 |

`key_delivered` 表示平台已经完成交付，不要求用户必须一键激活后才能结束交易。用户复制后在外部平台自行兑换时，平台没有可信回执就继续展示“CDKEY 已发放＋已复制”，不能伪造“已激活”。

## 6. 退款与质量售后

### 6.1 直接购买

- 实付订单同时满足支付成功后不超过 5×24 小时、跨端累计有效游玩严格小于 120 分钟时，可申请无理由退款。
- 受理后冻结账号权益；成功后撤销，退款失败或审核未通过时只恢复本次冻结前有效的权益。
- 本体退款继续关联处理永久 DLC，并保留跨渠道部分处理中状态。
- 0 元订单不出现现金退款入口。

### 6.2 CDKEY

- Key 尚未展示，且供应商确认可撤回／回库：允许取消或退款，成功后 Key 必须失效或安全回库。
- 首次查看、复制或发起激活后：不再支持无理由退款，但仍可针对无效、重复、平台／地区不符、商品描述不符等问题申请质量售后。
- 已激活 Key：依据外部平台能否撤销和销售地区规则进入人工审核，不承诺自动退款。
- 无效或重复 Key 可先校验并补发；补发始终保留原 Key、新 Key、原因与操作人的关联审计。无法按承诺履约时再退款。
- 拒付打开后如 Key 可撤回应立即回收；已被外部激活或不可撤回时保留真实风险和损失，不显示为“已回收”。

## 7. 删除订单

“删除订单”不是第 25 个交易状态。产品界面保留用户熟悉的按钮文案，底层执行软隐藏：

1. 点击后确认：“删除后将移至已删除订单，不影响已购内容、CDKEY、退款、客服和平台交易记录。”
2. 成功后 `visibility_status=hidden_by_user`，从默认列表移入“已删除订单”。
3. 已删除列表同时展示原交易状态和“已删除”标签，并提供“恢复订单”。
4. 可删除状态仅限上表标记“是”且没有进行中的退款、拒付、激活或客服工单。
5. 待支付必须先取消；支付失败仍可重试时必须先取消；全部处理中状态不得删除。
6. 隐藏后收到迟到支付、履约、激活、退款、拒付或客服事件时自动恢复可见，并记录审计事件。
7. 玩家删除不影响开发者、运营、客服、财务和审计查询，也不能级联删除 Key 或权益。

Demo 至少预置一条已删除样例，并完整演示删除、二次确认、从默认列表消失、进入已删除列表和恢复显示。

## 8. 页面流程

### 8.1 Android

`首页商品卡 → 游戏详情 → 确认订单选择购买方式 → 支付／免费确认 → 分支履约结果 → 游戏库或 CDKEY 订单详情 → 订单中心／售后`

- 继续使用 GameHub V6.1.1 核心 App Shell。
- 确认订单页用两张卡片展示购买方式，直接购买默认在前。
- 直接购买结果使用“正在添加到账号／已添加到账号”，面向玩家不使用“发权”。
- CDKEY 结果展示分配状态；完整 Key 只有完成首次查看确认后才显示。
- 订单卡展示“直接购买”或“CDKEY”标签，并根据分支显示合法主操作。
- “已删除订单”从订单中心右上角管理入口进入，避免与大量交易状态并列成横向 Tab。

### 8.2 Mac

- 保留原生窗口、侧栏、工具栏和桌面双栏结构。
- 与 Android 共享购买方式、订单快照、24 状态、退款资格和删除规则。
- CDKEY 详情可以在右侧信息区查看、复制和一键激活，不移植 Android 底部导航。

## 9. 服务端与幂等约束

- 建单：`client_request_id` 保证重复点击返回原订单。
- 履约：`(order_item_id, fulfillment_type)` 唯一；直接购买使用 `source_order_item_id` 保证权益只发一次。
- CDKEY 分配：库存行锁加 `allocated_order_item_id` 唯一约束，一笔订单只能持有一枚当前有效 Key。
- 激活：`activation_attempt_id` 幂等；并发请求只允许一个处理中，重试不得更换 Key。
- 支付、退款和拒付：渠道 `event_id + transaction_id` 去重，客户端回跳不代表成功。
- 删除／恢复：使用 `row_version` 条件更新；资格校验与写入在同一事务完成。
- 所有外部回调忽略玩家隐藏状态并照常处理，业务状态变化优先于隐藏操作。

## 10. 开发者、运营与对账影响

- 开发者数据按 `fulfillment_type` 拆分直接购买销量、CDKEY 销量、免费领取、退款、拒付、预估收入和待结算。
- CDKEY 在支付确认且 Key 成功交付后计入交付销量；退款、拒付和质量售后按原订单形成调整项。
- 开发者仅看到脱敏对账流水号、游戏／SKU、履约类型、地区、平台、金额、状态和结算期，不看到玩家身份、Key 明文、支付凭证或风控证据。
- 运营后台按原订单查看支付、账号权益或 Key 分配、激活可信结果、退款、拒付和审计时间线。
- 用户删除对开发者报表、运营查询、财务账单和结算结果没有影响。

## 11. 验收要求

1. 下单页只出现“直接购买／购买 CDKEY”两个购买选项，一键激活只在 CDKEY 到货后出现。
2. 两种方式分别展示价格、到账结果和退款规则；默认选中直接购买。
3. 直接购买全链路不展示 Key；CDKEY 链路不自动生成盖世账号永久权益。
4. CDKEY 首次查看确认、复制、一键激活、失败重试和可信成功均可操作，重试不换 Key。
5. 24 个状态在 Android 与 Mac 均有样例，状态标签、主操作和详情事实一致。
6. 删除能力覆盖所有允许的终态，处理中不出现删除；已删除样例支持恢复。
7. 退款规则能区分直接购买与 CDKEY 展示前后，不允许已展示 Key 继续走 5 天／2 小时自动退款。
8. 开发者与运营数据能按履约类型区分，任何页面和导出均不泄露 Key 明文。
9. Android 320／390 宽度与 Mac 1280×800／1440×900 无横向溢出、按钮裁切或不可达操作。
10. 02 游戏创建保持不变。

## 12. 多角色评审结论

- 用户视角：路径成立。必须持续区分“购买方式”和“购买后的使用动作”，并前置解释直接购买不提供 CDKEY、一键激活不再次收费，以及查看 Key 对退款资格的影响。
- 开发视角：方案可实现。`fulfillment_type`、Key 分配和激活状态必须独立；配码与激活都需要幂等，删除只能控制可见性。
- 商业视角：有条件通过。直接购买与 CDKEY 不得共用无理由退款判断；Key 展示后进入质量售后，开发者结算与对账按履约类型拆分。
