# 盖世游戏 Google Play 竖屏文件管理 MVP 设计

## 1. 文档信息

- 关联任务：`GUANWANGGAID-21 谷歌版提审`
- 设计日期：2026-08-27
- 状态：新增范围书面规格已更新，待用户复核
- 目标产物：现有离线单文件 HTML Demo 的下一版实现基线
- 取代关系：本规格取代 `2026-08-27-google-play-consistent-file-library-design.md` 中与文件页布局、权限、存储位置、文件操作和横屏行为相关的旧定义；审核前后一致原则继续有效。
- 当前实施计划：`2026-08-27-google-play-file-library-portrait-mvp.md` 只覆盖上一版 Demo；完成本规格复核后更新实施计划，再进入新增范围实现。

## 2. 要解决的问题

在不改变盖世游戏主要游戏能力和现有五栏框架的前提下，提供一个最小但真实可用的竖屏文件管理入口，用于浏览内部存储、进入文件夹、排序、查看常见文件、解压 ZIP 和处理单个文件，并通过 Android“所有文件访问权限”完成授权。

本轮重点不是扩展完整文件管理器，而是把权限、目录浏览、常见文件查看、当前目录解压和单文件操作形成闭环，同时保留 PC游戏、复古游戏的现有页面和视觉骨架。

## 3. 来源与采用顺序

1. 用户本轮明确确认：最高优先级。
2. 用户提供的 PC游戏布局调整截图：PC游戏页当前布局基线。
3. 用户提供的内部存储容量截图：容量卡结构基线。
4. 用户提供的“修改信息”截图：重命名弹窗的外框、输入、关闭和双按钮结构基线。
5. 用户提供的“复制布局”截图：复制弹窗的说明、命名输入、计数和双按钮结构基线。
6. V6.1.1 `screen-18`：竖屏游戏库内容密度与五栏 Shell。
7. V6.1.1 `screen-27`：危险操作二次确认结构。
8. 用户提供的竞品 HTML 查看截图：全屏查看器、左侧关闭、居中文件名和正文阅读结构基线；截图中的分享入口不采用。
9. 当前 `google-play-file-home-ab-demo.html`：只复用现有离线素材、首页和已实现状态机，不覆盖本轮新决策。

采用组件：`C-SHELL-P`、`C-NAV-P`、`C-TOPBAR`、`C-TAB`、`C-INPUT-SEARCH`、`C-SHEET`、`C-DIALOG`、`C-FEEDBACK`、`C-BUTTON-GLOW`、`C-BUTTON-SECONDARY`。

## 4. 总体方案

继续使用一个完全离线的单文件 HTML Demo，并保留一个文件 Manager 实例。Manager 统一管理权限、目录栈、搜索、筛选、排序、文件查看、解压、单文件操作和方向状态，避免多实例之间出现文件列表或授权状态不一致。

候选方案结论：

| 方案 | 特点 | 结论 |
|---|---|---|
| A. 单 Manager + 统一全屏查看器 | 在现有 Demo 内完成排序、查看、解压和文件操作，改动集中 | 采用 |
| B. 每种文件独立详情页 | 类型还原度高，但页面和状态明显增多 | 不采用 |
| C. 调用系统应用查看 | 正式 Android 可扩展，但离线 Demo 无法稳定验证 | 不采用 |

## 5. 竖屏信息架构

### 5.1 底部导航

底部固定为：

`首页｜玩游戏｜排行榜｜文件库｜我的`

“文件库”继续作为正式一级入口，审核员和正式用户体验一致，不设置审核专版、远程隐藏或通过后切换。

### 5.2 文件库顶部

顶部直接展示：

`文件｜PC游戏｜复古游戏`

规则：

- 移除当前 Demo 的 `GAMEHUB LOCAL`、文件库大标题和顶部权限 Chip。
- 竖屏冷启动默认进入“文件”。
- PC游戏、复古游戏复用现有正式布局；文件功能不得重做或污染这两个页面。
- PC游戏页采用用户提供的布局调整版：顶部平台入口卡、导入游戏、我的游戏区和现有游戏卡继续保留。

## 6. 文件页已授权状态

从上到下展示：

1. “文件｜PC游戏｜复古游戏”顶部 Tab。
2. 一张内部存储容量卡。
3. 文件与文件夹搜索。
4. 单选排序按钮：名称、修改日期、类型、大小。
5. 当前目录路径和文件列表。

### 6.1 内部存储容量卡

- 只保留内部存储；彻底移除 SD 卡和 USB 卡、数据及切换逻辑。
- 复用用户提供截图的圆环结构：左侧圆环显示可用容量，右侧显示已用和可用明细。
- Demo 使用来源截图的示例值 `已用 20.4 GB / 可用 26.3 GB`；正式 App 读取设备真实值。
- 卡片缩为适配竖屏文件页内容密度的紧凑尺寸，不照搬原截图的横向画布宽度。

### 6.2 数量文案

- 删除路径栏右侧的“6项”及所有动态“x项”数量文案。
- 目录、搜索或删除后都不重新显示数量。

### 6.3 排序

- 排序区固定显示“名称”“修改日期”“类型”“大小”四项；四项为单选，同一时刻只能有一个选中态。
- 默认选择“名称”，按中文名称升序排列，按钮显示“名称↑”。
- 点击未选中的排序项时切换排序字段：“名称”“类型”默认升序，“修改日期”“大小”默认降序。
- 再次点击当前排序项时切换升降序；当前项显示方向箭头，降序 `↓`、升序 `↑`，未选中项不显示箭头。
- 移除“全部”“压缩包”“文件夹”独立按钮；文件夹、压缩包、图片、视频、文本、HTML、PDF、游戏及其他文件都作为“类型”排序的数据，不再同时命中第二个筛选状态。
- 类型升序使用稳定分组：文件夹 → 图片 → 视频 → 文本 → HTML → PDF → 压缩包 → 游戏 → 其他；类型相同按名称升序，类型降序反转分组顺序，同组仍按名称升序。
- 处理顺序固定为：读取当前目录 → 搜索 → 排序 → 渲染。
- 文件夹参与全部四种排序；大小排序使用演示数据中的汇总大小，不把未知大小伪造为 `0`。

## 7. 权限状态与系统跳转

### 7.1 权限类型

采用 Android“所有文件访问权限”，不使用 SAF 文件夹选择器。

正式 Android 实现：

- 使用 `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` 打开当前应用的系统设置页。
- 回到 App 的 `onResume` 后使用 `Environment.isExternalStorageManager()` 重新检查权限。

Demo 只模拟系统设置交互，必须明确标记“Android 系统设置模拟”，不得宣称真实系统授权已经发生。

### 7.2 首次进入

- 竖屏首次进入“文件”时，自动打开 Android 所有文件访问设置的模拟页。
- 用户选择允许后返回文件页，展示内部存储容量、搜索、筛选和文件列表。
- 用户拒绝或返回后，进入未授权缺省态。

### 7.3 未授权缺省态

- 顶部三个业务 Tab 保持可见，允许切换至 PC游戏或复古游戏。
- 文件内容区只显示 `C-FEEDBACK`：标题“未获得文件访问权限”，说明“允许访问设备文件后，才能浏览和管理内部存储中的文件”，主按钮“去授权”。
- 不展示容量卡、搜索、筛选、路径或伪造文件列表。
- 点击“去授权”再次打开 Android 系统设置模拟页。

已知风险：首次直接进入系统设置缺少前置用途说明，可能增加审核和用户理解成本。本轮按用户明确确认的首次自动跳转流程实现；拒绝返回后的页内缺省态承担用途解释和再次授权入口。

## 8. 目录浏览

- 仅支持内部存储目录树。
- 点击文件夹进入下一层，不进入多选状态。
- 二级及更深目录顶部显示返回按钮和当前路径。
- 点击返回回到上一层；回到根目录后不再显示目录返回按钮。
- 同一前台会话内保留目录栈；冷启动或重新授权成功后回到内部存储根目录。
- 点击图片、TXT、HTML、PDF 或视频文件进入统一全屏查看器。
- 点击 ZIP 压缩包不进入查看器，直接打开“是否解压到当前文件夹”的二次确认。

Demo 根目录至少提供以下结构，确保目录进入、返回、排序、查看和解压均可操作验证：

```text
内部存储
├─ Download
├─ 示例文件
│  ├─ 示例图片.jpg
│  ├─ 示例文本.txt
│  ├─ 示例网页.html
│  ├─ 示例文档.pdf
│  ├─ 示例视频.mp4
│  └─ 示例压缩包.zip
├─ Games
└─ Documents
```

“示例文件”与 `Download` 平级；六个示例文件直接放在“示例文件”目录内，不再增加第三层示例目录。

## 9. 文件操作

### 9.1 更多菜单

- 文件和文件夹行的 `…` 菜单标题固定为“更多菜单”，不得动态替换为项目名称。
- “更多菜单”标题在弹层横向空间内严格居中；右侧 `X` 不得把标题挤向左侧。
- 右上角显示 `X` 关闭按钮；点击后关闭菜单并清空本次操作目标。
- 菜单固定保留“复制、重命名、删除”三个纯文字操作，顺序不变，三项前方均不显示图标。
- “更多菜单”和第一项“复制”之间不显示分割线；复制、重命名、删除三项之间继续保留分割线。
- 打开菜单后不自动聚焦第一项，避免底部 Sheet 动画期间发生标题或内容抖动。
- 删除使用危险色；复制和重命名使用普通操作样式。
- 移除当前菜单中的移动和添加到游戏库。
- 移除文件页多选和多选操作栏；三个操作均以单个文件或文件夹为目标。

### 9.2 复制

- 点击“复制”后打开 `C-DIALOG` 命名弹窗，视觉结构复用用户提供的“复制布局”截图。
- 标题根据目标显示“复制文件”或“复制文件夹”。
- 说明为“副本将保存到当前目录，是否使用以下命名”。
- 输入框默认名称：文件保留扩展名，在主文件名后增加 `_副本`；文件夹在完整名称后增加 `_副本`。
- 输入框右侧显示字符计数；Demo 最大 50 个字符，正式 Android 同时遵守系统文件名长度限制。
- 弹窗提供右上角关闭、取消和确认；关闭或取消均不改变当前目录。
- 名称为空、超过长度、包含 `/\\:*?\"<>|` 或与当前目录已有项目重名时，显示输入框内联错误并禁用确认。
- 点击确认后在当前目录创建同类型副本，保留原项目，关闭弹窗并立即刷新列表。
- 复制文件夹时，Demo 复制该文件夹及其演示子项；不新增进度页或 Toast。

### 9.3 重命名

- 点击“重命名”后打开 `C-DIALOG`，复用用户提供“修改信息”截图的弹窗外框、关闭按钮、输入框和双按钮，不显示游戏封面或其他文件无关字段。
- 输入框默认填入当前完整名称；用户可清空并重新输入。
- 弹窗提供右上角关闭、取消和确认；关闭或取消均保留原名称。
- 使用与复制相同的空值、长度、非法字符和重名校验。
- 点击确认后立即更新当前目录中的名称，关闭弹窗并刷新列表；文件类型和目录内容保持不变。
- 不新增成功 Toast。

### 9.4 删除与二次确认

- 点击“删除”后打开 `C-DIALOG` 危险确认。
- 标题“提示”，正文 `是否删除“{名称}”？`，操作为“取消”和“删除”。
- 取消：关闭弹窗并回到原目录，数据不变。
- 删除：立即从当前目录数据中移除目标并关闭弹窗；删除文件夹时同时移除其演示子项。
- 不增加 Toast、结果页或第三次确认。

### 9.5 文件查看器

- 图片、TXT、HTML、PDF 和视频共用一个竖屏全屏查看器，不为每种类型创建独立详情页面。
- 顶部采用 `C-TOPBAR`：左侧关闭按钮、居中显示完整文件名；不显示分享、复制、重命名、删除或其他操作。
- 详情页只负责查看；复制、重命名和删除始终回到文件列表的 `…` 菜单处理。
- 图片：按可用区域完整适配显示，不拉伸变形。
- TXT：保留换行并支持纵向滚动阅读。
- HTML：渲染演示 HTML 的正文效果，不显示 HTML 源代码，不使用远程资源或 `iframe`。
- PDF：使用离线 DOM 页面预览，支持纵向滚动查看演示页；不得依赖浏览器外部 PDF 插件或联网资源。
- 视频：使用内嵌离线演示视频和原生控件，支持播放、暂停、进度、音量和全屏。
- 点击关闭回到原目录，保留进入查看器前的搜索、筛选、排序、路径和滚动上下文。

### 9.6 ZIP 解压

- 点击 ZIP 文件行后直接打开二次确认，不进入文件查看器。
- 弹窗标题“解压文件”，正文“是否解压到当前文件夹？”，操作为“取消”和“解压”。
- “解压文件”标题在弹窗内严格居中；正文和按钮布局保持现有结构。
- 取消：关闭弹窗并返回当前目录，目录数据不变。
- 解压：在当前目录创建与压缩包主文件名相同的文件夹，例如 `示例压缩包.zip` 生成 `示例压缩包`；原 ZIP 文件保留。
- 当前目录已存在同名文件夹时直接覆盖原文件夹及其演示子项，不再增加第三次确认，也不执行合并。
- 确认后关闭弹窗、刷新当前目录，并将新文件夹标记为最近修改；不增加 Toast 或结果页。
- ZIP 的 `…` 菜单仍提供复制、重命名和删除，解压不进入更多菜单。

## 10. 横屏行为

- 文件管理器只支持竖屏，不制作文件页横屏布局。
- 横屏时直接隐藏“文件”Tab和文件 Panel；PC游戏、复古游戏继续使用原有横屏能力。
- 如果设备旋转到横屏时正停留在“文件”，自动切换至“PC游戏”，不得显示空白页或“不支持横屏”占位。
- 如果 App 在横屏冷启动，默认进入 PC游戏。
- 从横屏返回竖屏时重新显示“文件”Tab，但保留当前 PC游戏或复古游戏，不强制跳回文件。

Demo 使用方向媒体查询和方向状态监听验证上述规则；不把竖屏 DOM 拉伸、旋转或整体缩放成横屏文件页。

## 11. 状态模型

Manager 最小状态：

```text
permission: unknown | denied | granted
libraryTab: files | pc | retro
orientation: portrait | landscape
pathStack: string[]
query: string
sortBy: name | modified | type | size
sortOrder: asc | desc
viewingFile: null | item
pendingAction: null | copy | rename | delete | extract
actionTarget: null | item
draftName: string
firstPermissionPrompted: boolean
```

核心状态转换：

1. 竖屏冷启动 → `permission:unknown` → 自动打开系统设置模拟。
2. 允许 → `permission:granted` → 根目录已授权态。
3. 拒绝/返回 → `permission:denied` → 未授权缺省态。
4. 去授权 → 再次打开系统设置模拟。
5. 点击文件夹 → `pathStack` 入栈 → 渲染子目录。
6. 点击返回 → `pathStack` 出栈 → 渲染上级目录。
7. 默认 `sortBy:name + sortOrder:asc`；切换排序字段时同一时刻只保留一个选中态，再次点击当前字段切换升降序。
8. 点击图片、TXT、HTML、PDF 或视频 → 写入 `viewingFile` → 打开对应内容渲染器；关闭后清空 `viewingFile` 并恢复原目录上下文。
9. 点击 ZIP → 写入 `pendingAction:extract` 和 `actionTarget` → 二次确认 → 创建或覆盖同名文件夹并保留 ZIP。
10. 点击复制 → 写入 `actionTarget` 和默认 `draftName` → 校验 → 确认后在当前目录创建副本。
11. 点击重命名 → 写入 `actionTarget` 和当前名称 → 校验 → 确认后更新名称。
12. 点击删除 → 写入 `actionTarget` → 二次确认 → 确认后移除当前目录目标。
13. 关闭或取消任一文件操作 → 清空 `pendingAction`、`actionTarget` 和 `draftName`，数据不变。
14. 切横屏且当前为文件 → 隐藏文件并切 PC游戏；若查看器或解压确认处于打开状态则一并关闭并清理临时状态。

## 12. 冲突裁决

### CR-GP-PMVP-001

- 冲突项：此前要求“不支持 SAF”，本轮口述“手机自带授权文件夹”。
- 采用项：Android 所有文件访问权限系统设置。
- 废弃项：SAF 文件夹选择器。
- 理由：用户明确选择方案 1，且与既有技术约束一致。
- 置信度：高。

### CR-GP-PMVP-002

- 冲突项：旧 Demo 展示内部存储、SD 卡和 USB；本轮只允许内部存储。
- 采用项：单内部存储容量卡。
- 废弃项：SD/USB DOM、数据和交互。
- 理由：用户明确要求，并提供容量卡参考。
- 置信度：高。

### CR-GP-PMVP-003

- 冲突项：上一版书面规格将 `…` 收敛为仅删除；用户复核时要求保留复制、重命名、删除并提供完整交互。
- 采用项：取消多选；单项目菜单保留复制、重命名、删除，分别完成命名校验、即时数据更新和删除二次确认。
- 废弃项：仅删除方案，以及移动和添加到游戏库。
- 理由：用户本轮明确修订，并提供复制、重命名弹窗结构参考。
- 置信度：高。

### CR-GP-PMVP-004

- 冲突项：文件库作为一级入口长期存在，但文件管理不支持横屏。
- 采用项：横屏只隐藏文件 Tab和文件 Panel，自动进入 PC游戏；竖屏继续长期显示文件。
- 废弃项：横屏文件占位页或把竖屏文件页机械缩放。
- 理由：用户明确要求横屏直接隐藏，同时不影响 PC游戏、复古游戏原横屏能力。
- 置信度：高。

### CR-GP-PMVP-005

- 冲突项：已实现菜单动态显示项目名并在打开后自动聚焦第一项，用户反馈标题会抖动。
- 采用项：标题固定为“更多菜单”，右上角提供 `X`，三项操作使用纯文字，标题与第一项之间无线，取消打开后的自动聚焦。
- 废弃项：动态项目名标题、操作图标和首次自动聚焦。
- 理由：用户明确修订；固定头部可以消除动画期间的布局与焦点扰动。
- 置信度：高。

### CR-GP-PMVP-006

- 冲突项：旧规格明确不支持文件详情、文件打开和压缩解压；用户新增常见文件查看和当前目录 ZIP 解压要求。
- 采用项：支持图片、TXT、HTML、PDF、视频的只读全屏查看，以及 ZIP 当前目录解压和同名文件夹覆盖。
- 废弃项：普通文件点击无行为，以及完全不支持解压的旧范围。
- 理由：用户明确要求，并将查看与列表操作边界定义为“详情只查看，操作回列表”。
- 置信度：高。

### CR-GP-PMVP-007

- 冲突项：竞品 HTML 查看器截图右上角提供分享，但用户要求详情只查看且明确不做分享。
- 采用项：查看器只保留关闭、居中文件名和正文内容。
- 废弃项：分享入口及详情内复制、重命名、删除。
- 理由：用户明确确认；减少能力扩张并保持操作入口唯一。
- 置信度：高。

### CR-GP-PMVP-008

- 冲突项：旧方案允许“全部 + 最近修改”或“压缩包 + 大小”同时选中；用户指出同一排条件应只能命中一项，并明确改为名称、修改日期、类型、大小四项。
- 采用项：四项统一为单选排序字段，默认名称升序；类型负责文件夹、压缩包等类型分组排序。
- 废弃项：独立“全部”“压缩包”“文件夹”按钮，以及筛选和排序同时高亮的双状态。
- 理由：用户明确修订；单一排序状态更符合当前紧凑快捷栏的视觉与操作心智。
- 置信度：高。

## 13. 明确不做

- 不支持 SAF、SD 卡、USB、云盘、局域网、FTP、分享和回收站。
- 不支持文件移动、多选、编辑或调用系统外部应用打开；复制、重命名和删除仅支持列表中的单项目操作。
- 文件查看只覆盖图片、TXT、HTML、PDF 和视频；不新增通用未知格式查看器，也不在详情页增加文件操作。
- 解压只覆盖当前目录 ZIP 演示，不支持选择目标目录、进度页、加密压缩包、其他压缩格式、压缩文件创建或合并覆盖。
- 不新增授权教程页、审核说明 Banner、运营卡片、Toast或删除结果页。
- 不修改首页、玩游戏、排行榜、我的及 PC游戏、复古游戏的业务属性。
- 本轮 Demo 阶段不修改 Android 代码、Manifest，不生成 AAB，不提交 Google Play。
