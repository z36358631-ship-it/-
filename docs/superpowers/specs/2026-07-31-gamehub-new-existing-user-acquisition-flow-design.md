# 盖世游戏新用户与非新用户来源采集整合设计

## 1. 背景与目标

当前主 Demo `demos/新手引导完整链路demo.html` 只呈现新用户链路，非新用户的“个性化选游戏 → 来源采集”仍位于独立 Demo `demos/用户与设置/个性化推荐采集demo.html`。评审时需要在两个文件之间切换，无法连续验证不同人群、缺失步骤和中断恢复。

本次目标：

- 将新用户和非新用户的当前有效链路整合进同一个主 Demo。
- 保留新用户国内、海外新手第三页的三段全亮进度条。
- 保留非新用户“个性化选游戏 → 来源采集”的完整流程及缺失步骤恢复能力。
- 将本次专项 PRD 更新为两类人群的当前交付规则，不恢复历史版本、废弃实验或旧后台需求。

## 2. 方案选择

|方案|处理方式|结论|
|---|---|---|
|A. 主 Demo 完整整合|在主 Demo 增加非新用户场景和页面，统一演示两类人群链路|采用；评审链路完整，状态切换集中|
|B. 两个 Demo 相互跳转|保留独立 Demo，只在主 Demo 增加跳转入口|不采用；评审割裂，无法在同一状态控制区验证|
|C. 主 Demo 增加静态示意页|只展示非新用户页面外观，不实现状态和恢复|不采用；无法作为开发和测试依据|

独立的 `个性化推荐采集demo.html` 暂不删除，可作为历史对照；后续以主 Demo 为本需求的评审入口。

## 3. 人群与流程

### 3.1 新用户

国内：

`用户类型选择 → 来源采集 → 秒玩游戏列表`

海外：

`User type → Acquisition source → Operation guide`

规则：

- 来源单选、必答、不可跳过。
- 国内、海外新手第三页显示三段全亮进度条。
- “有游戏想玩”分支继续进入导入／Steam 绑定流程，不增加第三页进度条。
- 新用户来源标记使用 `new_user_onboarding`。

### 3.2 非新用户

完整链路：

`个性化选游戏 → 来源采集 → 完成`

选游戏规则：

- 可选择3～9款游戏。
- 少于3款时不能提交。
- 可点击“暂不选择”，并将该步骤写为已跳过终态。

来源规则：

- 单选、必答、默认不选中。
- 提供“其他／不记得”，不提供跳过。
- 来源标记使用 `existing_user_recall`，只用于存量用户回忆来源分析，不覆盖客观安装归因。

### 3.3 非新用户缺失步骤

|状态|进入页面|完成后的去向|
|---|---|---|
|游戏、来源均缺失|个性化选游戏|来源采集 → 完成|
|仅游戏缺失|个性化选游戏|完成|
|仅来源缺失|来源采集|完成|
|均已完成|不展示问卷|实际产品直接放行；Demo 只显示“无需展示”说明供评审|

游戏步骤和来源步骤分别保存终态。完成其中一步后，即使下一步中断，也不得回退已完成步骤。

## 4. 主 Demo 整合设计

### 4.1 场景控制

主 Demo 的场景控制区增加以下入口：

- 新用户 · 国内
- 新用户 · 海外
- 非新用户 · 游戏与来源均待答
- 非新用户 · 仅游戏待答
- 非新用户 · 仅来源待答
- 非新用户 · 均已完成

切换场景时重置当前演示态，但不改变其他场景的预设规则。国内／海外只影响文案、来源选项和新用户第三页，不改变非新用户步骤终态规则。

### 4.2 页面组件

主 Demo 增加并复用以下组件：

- 非新用户个性化选游戏页。
- 非新用户来源采集页。
- 非新用户流程完成页。
- 场景状态说明与当前步骤标识。

页面视觉、按钮、卡片、进度表达和横竖屏适配沿用现有盖世游戏风格。非新用户页面不强行使用新手三段进度条，避免让用户误以为这是首次启动流程。

### 4.3 状态模型

主 Demo 使用以下独立状态：

- `game_step_terminal`：`pending / submitted / skipped`
- `source_step_terminal`：`pending / completed`
- `selected_games`：已选择游戏集合
- `source_code`：来源选项
- `entry_group`：`new_user_onboarding / existing_user_recall`
- `market`：`domestic / overseas`

页面进入时根据两个步骤终态计算下一步，不根据固定页码跳转。这样可覆盖“完整链路”“只缺一步”和“中断恢复”。

## 5. 数据与异常处理

- 游戏步骤提交或主动跳过后立即写入独立终态。
- 来源在本地可靠保存后允许放行；接口失败时进入待补报队列，联网后使用同一响应标识幂等补报。
- 本地保存失败时停留当前页并提示重试，不写完成终态。
- 游戏候选加载失败时支持重试或用户主动“暂不选择”；技术失败不能自动写成跳过。
- 横竖屏切换保留当前场景、步骤、选择结果和滚动位置，不重复曝光或提交。
- 总开关或步骤开关关闭时只临时绕过，不清除草稿或终态；重开后从缺失步骤继续。

## 6. PRD 更新范围

专项 PRD 更新为“新用户与非新用户来源采集需求”，只保留本次需要开发、测试的当前规则：

- 新用户国内链路及第三页进度条。
- 新用户海外链路及第三页进度条。
- 非新用户个性化选游戏。
- 非新用户来源采集。
- 缺失步骤、中断恢复、异常处理、埋点和验收标准。

图示统一放在需求表格的“图示”列，计划使用4张真实 Demo 截图：

1. 国内新用户第三页。
2. 海外新用户第三页。
3. 非新用户个性化选游戏。
4. 非新用户来源采集。

图片使用固定 Git 提交 SHA 的公开 HTTPS 地址并逐张验证可访问。PRD 不加入历史版本记录、废弃 A/B 方案、旧后台配置说明或与本次交付无关的历史页面。

## 7. 验收与测试

### 7.1 主要链路

1. 国内新用户完成用户类型和来源后进入国内第三页，三段进度条全亮。
2. 海外新用户完成用户类型和来源后进入海外第三页，三段进度条全亮。
3. 非新用户完成选游戏后进入来源页，提交来源后结束流程。
4. 非新用户选择“暂不选择”后进入来源页，不重复展示选游戏。

### 7.2 缺失步骤

1. 仅缺游戏时只展示选游戏，完成或跳过后结束。
2. 仅缺来源时直接展示来源，提交后结束。
3. 两步均完成时不展示问卷。
4. 任一步骤中断后从未完成步骤恢复，已完成步骤不回退。

### 7.3 边界与兼容

1. 少于3款游戏不可提交，最多选择9款。
2. 来源未选择不可提交，且没有跳过入口。
3. 国内、海外来源选项和文案正确。
4. 横竖屏切换后状态不丢失。
5. 离线来源可本地完成并待补报，重复补报不产生重复数据。
6. Demo 静态检查、主链路自动化测试和关键页面截图比对通过。

## 8. 非目标

- 不修改推荐算法，不使用来源答案生成兴趣推荐。
- 不新增后台配置页面。
- 不重新设计新手引导已有页面。
- 不删除独立个性化采集 Demo。
- 不恢复已废弃的历史实验组或24小时后再次弹窗方案。

## 9. 三视角快速评审

- 用户视角：两类用户只回答自己缺失的步骤，避免重复打扰；新用户和非新用户的流程语义清楚。
- 开发视角：复用现有非新用户状态机，以步骤终态计算路由，避免整合后重复触发；主要回归点是场景切换和中断恢复。
- 商业视角：同时获得新用户首次来源和存量用户回忆来源，并保持口径隔离；不扩大弹窗频次和页面范围。

评审结论：方案可实施，风险已通过独立步骤终态、来源口径隔离和专项 PRD 范围控制处理。
