# 盖世游戏新手四页引导、非新用户来源采集与来源分析设计

## 1. 背景与目标

当前新手引导进入后立即要求用户选择类型，缺少品牌欢迎和平台价值说明；“跳过”又作为页面右上角的脱离操作，用户无法清楚理解跳过后会发生什么。非新用户的“个性化选游戏 → 来源采集”仍位于独立 Demo `demos/用户与设置/个性化推荐采集demo.html`，后台也没有集中查看来源分布的位置。

本次目标：

- 将新用户调整为“欢迎封面＋来源采集＋准备方式＋分支落地”的四页结构。
- 欢迎页不计入进度；后续三页使用三段式进度条。
- 将右上角“跳过”改为准备方式中的普通选项“以后再说”。
- 将新用户和非新用户的当前有效链路整合进同一个主 Demo。
- 保留非新用户“个性化选游戏 → 来源采集”的完整流程及缺失步骤恢复能力。
- 在运营数据看板增加来源分析，分别查看国内／海外、新用户／非新用户的来源分布。
- 将本次专项 PRD 更新为上述当前交付规则，不恢复历史版本、废弃实验或无关后台需求。

## 2. 方案选择

|方案|处理方式|结论|
|---|---|---|
|A. 主 Demo 完整整合|在主 Demo 增加非新用户场景和页面，统一演示两类人群链路|采用；评审链路完整，状态切换集中|
|B. 两个 Demo 相互跳转|保留独立 Demo，只在主 Demo 增加跳转入口|不采用；评审割裂，无法在同一状态控制区验证|
|C. 主 Demo 增加静态示意页|只展示非新用户页面外观，不实现状态和恢复|不采用；无法作为开发和测试依据|

独立的 `个性化推荐采集demo.html` 暂不删除，可作为历史对照；后续以主 Demo 为本需求的评审入口。

## 3. 人群与流程

### 3.1 新用户

页面结构：

`欢迎页 → 来源采集 → 准备方式 → 分支落地`

规则：

- 欢迎页是独立封面，不显示进度条。
- 来源采集页显示三段进度的第1段。
- 准备方式页显示三段进度的前2段。
- 分支落地页显示三段进度全部点亮。
- 来源单选、必答、不可跳过。
- 准备方式提供“我有游戏想玩”“我是新手，想先看看”“以后再说”三个平级选项。
- 选择“我有游戏想玩”进入导入游戏／绑定 Steam 选择页。
- 选择“我是新手，想先看看”时，国内进入秒玩游戏列表，海外进入操作引导。
- 选择“以后再说”立即结束引导并进入首页，不再增加确认页。
- 新用户来源标记使用 `new_user_onboarding`。

“四页”指完整分支的页面结构；选择“以后再说”属于第3页提前结束，不强制展示没有业务内容的第4页。

导航规则：

- 欢迎页没有返回入口。
- 来源页返回欢迎页，未提交选择仅作为草稿保留。
- 准备方式页返回来源页时回显已提交答案；用户修改后以最新一次有效答案为准。
- 分支落地页沿用各原页面的返回和完成规则，不新增统一完成弹窗。

### 3.2 非新用户

完整链路：

`个性化选游戏 → 来源采集 → 完成`

选游戏规则：

- 可选择3～9款游戏。
- 少于3款时不能提交。
- 可点击“暂不选择”，并将该步骤写为已跳过终态。

来源规则：

- 单选、必答、默认不选中。
- 提供“其他／不记得”，不提供跳过。
- 来源标记使用 `existing_user_recall`，只用于存量用户回忆来源分析，不覆盖客观安装归因。

### 3.3 非新用户缺失步骤

|状态|进入页面|完成后的去向|
|---|---|---|
|游戏、来源均缺失|个性化选游戏|来源采集 → 完成|
|仅游戏缺失|个性化选游戏|完成|
|仅来源缺失|来源采集|完成|
|均已完成|不展示问卷|实际产品直接放行；Demo 只显示“无需展示”说明供评审|

游戏步骤和来源步骤分别保存终态。完成其中一步后，即使下一步中断，也不得回退已完成步骤。

## 4. 主 Demo 整合设计

### 4.1 场景控制

主 Demo 增加“用户端／运营后台”视图切换。用户端场景控制区提供：

- 新用户 · 国内
- 新用户 · 海外
- 非新用户 · 游戏与来源均待答
- 非新用户 · 仅游戏待答
- 非新用户 · 仅来源待答
- 非新用户 · 均已完成

运营后台提供“来源分析”入口。切换场景时重置当前演示态，但不改变其他场景的预设规则。国内／海外影响文案、来源选项和新用户分支落地页，不改变非新用户步骤终态规则。

### 4.2 页面组件

主 Demo 增加并复用以下组件：

- 新用户欢迎页。
- 新用户来源采集页。
- 新用户准备方式页。
- 新用户分支落地页。
- 非新用户个性化选游戏页。
- 非新用户来源采集页。
- 非新用户流程完成页。
- 场景状态说明与当前步骤标识。
- 运营后台来源分析页。

欢迎页参考用户提供的示例，采用大面积留白、品牌开场、平台价值介绍和底部主按钮结构，但使用盖世游戏暗色视觉，不照搬参考品牌。页面展示：

- “欢迎来到盖世游戏”。
- “欢迎新朋友，开启你的 PC 游戏之旅”。
- “手机上的 PC 游戏平台”。
- Steam 与 Epic 游戏数据互通、云游戏无需下载一键秒玩、AI 超级插帧与虚拟按键方案三项平台特色。
- 底部“开始”按钮。

页面视觉、按钮、卡片、进度表达和横竖屏适配沿用现有盖世游戏风格。非新用户页面不使用新手三段进度条，避免让用户误以为这是首次启动流程。

### 4.3 状态模型

主 Demo 使用以下独立状态：

- `new_user_stage`：`welcome / source / start_method / destination / completed`
- `start_method`：`has_game / explore_first / later`
- `game_step_terminal`：`pending / submitted / skipped`
- `source_step_terminal`：`pending / completed`
- `selected_games`：已选择游戏集合
- `source_code`：来源选项
- `entry_group`：`new_user_onboarding / existing_user_recall`
- `market`：`domestic / overseas`

新用户根据 `new_user_stage` 和 `start_method` 进入对应页面；“以后再说”写入引导完成状态并进入首页。非新用户根据两个步骤终态计算下一步，不根据固定页码跳转，以覆盖“完整链路”“只缺一步”和“中断恢复”。

### 4.4 运营后台来源分析

来源分析位于运营数据看板的用户分析范围内，沿用现有后台导航、筛选区、指标卡、图表和明细表样式。

筛选项：

- 日期范围。
- 国内／海外。
- 新用户／非新用户。
- 安装或分发渠道。
- App 版本。

展示内容：

- 来源提交人数。
- 来源填写完成率：来源提交去重人数 ÷ 来源页曝光去重人数。
- “其他／不记得”占比。
- 各来源人数与占比的分布图。
- 来源明细表：来源名称、人数、占比、较上一等长周期变化。

新用户 `new_user_onboarding` 与非新用户 `existing_user_recall` 默认分开统计。后台不得把非新用户回忆来源写回或展示为客观安装归因；数据刷新频率复用现有运营数据看板口径。

## 5. 数据与异常处理

- 欢迎页“开始”、来源提交、准备方式选择和分支落地分别记录曝光与点击／提交事件。
- 新用户选择“以后再说”只结束本次引导，不删除已提交的来源答案。
- 游戏步骤提交或主动跳过后立即写入独立终态。
- 来源在本地可靠保存后允许放行；接口失败时进入待补报队列，联网后使用同一响应标识幂等补报。
- 本地保存失败时停留当前页并提示重试，不写完成终态。
- 游戏候选加载失败时支持重试或用户主动“暂不选择”；技术失败不能自动写成跳过。
- 横竖屏切换保留当前场景、步骤、选择结果和滚动位置，不重复曝光或提交。
- 总开关或步骤开关关闭时只临时绕过，不清除草稿或终态；重开后从缺失步骤继续。
- 来源分析按统一来源编码聚合；登录用户按用户账号去重，游客按 `install_id` 去重，游客转登录后幂等合并。同一去重主体多次有效提交时按查询周期内最后一次答案归类；未选择来源的曝光只进入完成率分母，不进入来源分布。

## 7. 验收与测试

### 7.1 主要链路

1. 新用户首次进入先看到欢迎页，页面无进度条；点击“开始”后进入来源采集。
2. 来源页、准备方式页和分支落地页分别显示三段进度的第1、前2和全部3段。
3. 选择“我有游戏想玩”后进入导入游戏／绑定 Steam 选择页。
4. 选择“我是新手，想先看看”后，国内进入秒玩游戏列表，海外进入操作引导。
5. 选择“以后再说”后直接进入首页，不展示额外确认页，来源答案保持有效。
6. 非新用户完成选游戏后进入来源页，提交来源后结束流程。
7. 非新用户选择“暂不选择”后进入来源页，不重复展示选游戏。

### 7.2 缺失步骤

1. 仅缺游戏时只展示选游戏，完成或跳过后结束。
2. 仅缺来源时直接展示来源，提交后结束。
3. 两步均完成时不展示问卷。
4. 任一步骤中断后从未完成步骤恢复，已完成步骤不回退。

### 7.3 边界与兼容

1. 少于3款游戏不可提交，最多选择9款。
2. 来源未选择不可提交，且没有跳过入口。
3. 准备方式页不显示右上角“跳过”，“以后再说”为三个平级选项之一。
4. 国内、海外来源选项、文案和分支页面正确。
5. 横竖屏切换后状态不丢失。
6. 离线来源可本地完成并待补报，重复补报不产生重复数据。
7. 来源分析的筛选、指标、分布图和明细表联动正确；新用户与非新用户默认分开统计。
8. Demo 静态检查、主链路自动化测试和关键页面截图比对通过。

## 8. 非目标

- 不修改推荐算法，不使用来源答案生成兴趣推荐。
- 不新增后台配置页面。
- 不增加来源归因修改能力，后台只做分析展示。
- 不删除独立个性化采集 Demo。
- 不恢复已废弃的历史实验组或24小时后再次弹窗方案。

## 9. 三视角快速评审

- 用户视角：欢迎页先解释价值，降低进入即被提问的压迫感；“以后再说”作为明确选项，比悬浮跳过更容易理解。
- 开发视角：新用户使用阶段状态、非新用户使用步骤终态，避免固定页码导致分支和恢复错误；主要回归点是“以后再说”、市场切换和中断恢复。
- 商业视角：来源前置使选择“以后再说”的新用户也能进入来源统计；后台按人群和市场拆分，避免把旧用户回忆当作新增获客渠道。

评审结论：方案可实施，风险已通过欢迎封面不计步、独立步骤终态、来源口径隔离和专项 PRD 范围控制处理。
