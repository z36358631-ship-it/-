# 版本发布 Build 与商品联动设计

## 1. 目标与范围

本次只修改开发者后台单游戏控制台的“版本发布”页面。页面负责选择本次发布使用的 PC 游戏包，并回显与已选游戏包关联的商品、SKU 和 DLC 商品资料；不在本页创建或编辑 Build、Package、SKU、DLC。

本期同时增加“支持的控制器”和“系统需求”填写区域。右下角 Demo 状态只提供“穷举态”和“缺省态”。

## 2. 页面结构

沿用现有后台顶部导航、左侧单游戏菜单、居中内容区、版本发布页内定位、白底卡片、保存草稿和提交审核结构。页面内容顺序为：

1. 游戏资料
2. PC 游戏包
3. 商品与 SKU
4. DLC 商品资料
5. 支持的控制器
6. 系统需求
7. 发行设置
8. 资质认证

“PC 包体”统一改名为“PC 游戏包”。不新增页面、弹窗、Toast 或额外流程。

## 3. PC 游戏包

### 3.1 数据来源

直接读取当前游戏“构建管理”的 Build 列表。本页移除“从包体库选择”“从本地上传”和其他创建、上传、编辑、删除入口。

列表展示：选择框、目标 App、游戏包类型（本体/DLC）、版本号、Build ID、平台、Build 状态、QA 状态、提包审核状态。

### 3.2 选择规则

- 固定使用复选框，支持多选，不提供单选/多选模式切换。
- 同一个 App 最多选择一个 Build；选择同 App 的另一 Build 时替换原选择，避免一个 App 同时发布两个版本。
- 已冻结、QA 已通过且提包审核已通过的 Build 可选。
- 其他状态仍在穷举态展示，但禁用选择并就地说明原因。
- 已选数量在卡片标题区回显。

### 3.3 缺省态

构建管理没有记录时显示：

- 标题：暂无可用 PC 游戏包
- 说明：请先在构建管理中创建并完成构建。
- 按钮：前往构建管理
- 目标：当前游戏的“构建管理”页面

## 4. 商品与 SKU 联动

### 4.1 联动链路

PC 游戏包是唯一选择入口。每次选择变化后按以下关系自动计算：

`Build.appId -> Base App / DLC App -> 同 appId 的 Package/SKU`

商品与 SKU 区域只回显计算结果，不提供选择框、创建、删除、名称编辑、价格编辑或折扣编辑。

### 4.2 展示内容

回显商品名称、Package/SKU ID、用途、本体或 DLC、关联 App、收费方式、基础价格、区域价格、审核状态和销售状态。标题区显示“已根据 N 个游戏包匹配 M 个商品”。

取消某个 Build 后，对应商品和 SKU 同步移除。若多个已选 Build 关联同一 Package，只展示一次，并保留来源 Build 关系。

### 4.3 配置缺失

- 已选 Build 找不到 App：显示“关联 App 不存在”，阻断提交。
- 找不到 Package/SKU：显示“所选游戏包尚未配置商品”，提供“前往付费下载设置”，阻断提交。
- DLC App 存在但默认 Package 未配置或无有效价格：保留 DLC 资料卡，标记“待配置”，提供“前往付费下载设置”，阻断该 DLC 提交。
- 没有选择 PC 游戏包时，商品区显示轻量提示“选择 PC 游戏包后自动回显对应商品与 SKU”。

## 5. DLC 商品资料

当联动结果包含 DLC SKU 时，从“DLC 商品设置”按 DLC AppID 读取并回显：商品图、DLC 名称、DLC AppID、卖点、完整介绍、默认 Package ID、资料审核状态和上架状态。价格及销售状态来自默认 Package。

DLC 不设置第二套选择控件；其是否进入本次发布完全跟随已选 DLC Build。找不到 DLC 商品资料时显示“DLC 商品资料缺失”，提供“前往 DLC 商品设置”，并阻断对应 DLC 提交。没有选中 DLC Build 时不阻断本体发布。

## 6. 支持的控制器

只填写支持的手柄类型，不再增加“不支持、部分支持、完全支持”等支持程度字段。

采用复选项：Xbox 手柄、PlayStation 手柄、Switch 手柄、通用手柄。允许不选、单选或多选；保存后再次进入继续回显。玩家端按选中的手柄类型展示。

## 7. 系统需求

页面样式以用户提供的后台截图为准：顶部为“预设配置”，提供“独立、跨端、3A、自定义”；下方为“最低配置”和“推荐配置”双列，窄屏时上下排列。

两列字段均为：

- 操作系统：Windows 7 / 8 / 10 / 11（64 位）
- 处理器
- 内存：数值 + KB / MB / GB / TB 单位
- 显卡
- 存储空间：数值 + KB / MB / GB / TB 单位
- DirectX 版本
- 声卡
- 备注（最多 80 字）

玩家端展示以最新深色截图为准：最低配置与推荐配置并列，处理器和显卡可使用“Intel / AMD”形式；网络文案“宽带互联网连接”属于客户端固定展示，不在后台新增网络输入字段。

预设仅用于填充建议值，用户仍可修改。最低配置和推荐配置独立保存，不得串写；推荐内存和存储空间不得低于最低配置，其他文本字段只做必填与长度校验，不做型号性能比较。

## 8. 右下角 Demo 状态

版本发布页复用现有右下角浮动按钮和状态面板，只保留两个页面级状态：

- 穷举态：展示多条本体与 DLC Build、可用和禁用状态、多选及同 App 替换、自动匹配的商品/SKU、DLC 完整介绍、控制器多选、完整系统需求。
- 缺省态：构建、商品和 DLC 来源均为空，分别展示跳转引导；控制器为空，系统需求为空。

状态切换只改变 Demo 数据，不写入真实业务数据；刷新页面恢复默认穷举态。发布记录页原有审核状态演示不属于本次范围。

## 9. 保存、提交与再次发布

草稿保存所选 Build ID、由其计算出的商品引用快照、控制器类型和系统需求。提交时再次校验 Build、App、Package/SKU、DLC 和价格关系，生成不可变版本快照。

再次发布继承上一版的游戏资料、发行设置、资质认证、控制器和系统需求；PC 游戏包选择清空，商品与 SKU 随本次新选 Build 重新计算，不继承旧选择。

## 10. 验收重点

- 版本发布页不存在上传包体、从包体库选择、创建 DLC、编辑价格和折扣的入口。
- PC 游戏包支持多选，同 App 始终最多一个 Build。
- 商品/SKU 与 DLC 随 Build 选择实时增删，数据来源和关联 ID 一致。
- 缺失 App、Package、价格或 DLC 资料时就地说明、正确跳转并阻断对应提交。
- 控制器只出现手柄类型多选。
- 系统需求字段、双列布局、单位选项和 80 字备注符合参考图。
- 右下 Demo 状态只有“穷举态”和“缺省态”，两种状态可稳定复现。

## 11. 明确不做

- 不修改构建管理、付费下载设置和 DLC 商品设置的业务流程。
- 不把促销、捆绑组合或 CDKEY 纳入商品联动。
- 不增加网络输入、控制器支持程度、包体单选模式或独立 DLC 选择。
- 不重做现有后台导航和页面视觉体系。
