# 盖世游戏 APP 租号 V6.1.1 基线与统一订单中心设计

## 1. 目标

整体返工现有《盖世游戏 APP 游戏租号需求》及配套 Demo。核心目标不是重新设计 APP，而是先按最新版 APP 页面 1:1 还原现有结构、视觉和交互，再把 Mac 端已确认的租号能力自然接入，并解决租号与既有 CDKEY 售卖同时存在时的入口、价格和订单中心兼容问题。

本次交付包含租号 PRD、普通 Demo、交互标注版、PRD 截图和验证结果。CDKEY 的完整购买、激活和订单状态继续以既有 CDKEY 需求为准，不在本期租号 Demo 中重复制作。

## 2. 已确认决策

1. 现有租号 PRD 与 Demo 整体返工，不只修正首页、搜索和详情三张图。
2. APP 核心页面先按 V6.1.1 原页面还原，再增加租号内容；禁止自由改版。
3. APP 没有的租号交易页面继承 Mac 端已确认的信息结构，再适配 APP 横竖屏视觉。
4. 个人中心只保留一个“订单中心”入口，不新增“租号订单”入口。
5. 订单中心顶部只保留“全部订单 / 待支付 / 可使用”，不增加订单类型筛选。
6. CDKEY 与租号在产品中共用订单中心和卡片外壳；卡片不增加“游戏购买/租号畅玩”等订单类型标签。
7. 本期租号 Demo 的订单中心只展示租号订单及租号状态，不构造 CDKEY 示例订单。
8. “可使用”右侧提供订单搜索，只搜索当前 Tab 内的订单。
9. 租号与 CDKEY 不是同类 SKU，外部价格不得直接跨类型取绝对最低价。

## 3. 设计基线与来源优先级

发生视觉或交互冲突时按以下顺序处理：

1. 用户本次提供的个人中心与订单中心截图，作为这两个页面的最高优先级基线。
2. `C:\Users\z3635\官网改动-app-mods\盖世游戏V6.1.1使用说明手册\图片和附件` 中的最新版 APP 页面，作为首页、搜索、详情、玩游戏、排行榜、游戏库、我的及横屏页面基线。
3. `C:\Users\z3635\官网改动\Mac端demo\mac端租号功能` 中已确认的交易、订单详情、登录、到期和售后页面，作为 APP 新增任务页的信息结构基线。
4. 现有租号 PRD 与 Demo 只用于复用已经确认的业务规则，不作为核心页面视觉基线。

“1:1 还原”指页面结构、导航、色彩、背景、卡片比例、字号层级、间距、主要素材位置和既有按钮关系一致；只允许在必要位置增加租号价格、权益、入口和状态。

## 4. 页面结构

### 4.1 核心页面

首页、玩游戏、排行榜、游戏库、我的和搜索继续使用 APP 原有全局导航与页面结构。租号只作为现有游戏卡、游戏详情和个人中心服务入口的增量，不修改核心信息架构，不新增导航项。

社区不增加直接交易卡片；从社区内容进入游戏详情后，再按统一权益规则决定是否展示租号能力。

### 4.2 任务页面

游戏详情、确认订单、会员中心、会员游戏库、订单中心、订单详情、Steam 登录、售后、临期和到期为独立任务页。任务页不显示 APP 全局导航，返回时恢复来源页面、搜索条件和滚动位置。

横屏任务页继承 Mac 已确认的信息骨架；竖屏使用同一组件和业务状态纵向排列，不另做一套业务逻辑。

## 5. 首页、搜索与详情价格规则

### 5.1 权益优先级

所有入口先判断用户已有权益，再决定是否展示价格：

1. 已拥有且可启动：显示“启动游戏”或原有“秒玩”。
2. 已拥有但未安装：显示“下载游戏”。
3. 有效租赁：显示“继续游戏”或“租用中”。
4. 单游戏永久权益：显示启动或下载。
5. 有效会员且游戏在会员库：显示“会员畅玩”。
6. 无现有权益：才展示租号、CDKEY、单游戏永久或会员入口。

价格不得覆盖用户已有的启动、下载、会员或租赁状态。

### 5.2 同类最低价

- 租号：只在当前地区、游戏版本、库存和用户资格内计算最低可售租号 SKU，展示“租 2小时 ¥X起”；确认具有首次资格时可展示“首次租 ¥1.99”。
- CDKEY：沿用既有 CDKEY 需求，在同类可售 SKU 中展示“购 ¥Y起”。
- 单游戏永久和会员价格分别按自身权益类型展示，不与租号或 CDKEY 混算。

### 5.3 同时可租、可购

空间足够时展示“租 2小时 ¥X起｜购 ¥Y起”；空间不足时展示“租/购可选”，进入详情后再呈现完整权益与价格。禁止只展示跨类型的最低数字，也禁止让租金看起来像永久购买价。

本期租号 Demo 可以演示租号外显及与购买能力共存的布局，但不需要实现 CDKEY 下单、激活或 CDKEY 订单状态。

## 6. 统一订单中心

### 6.1 入口与顶部区域

个人中心沿用用户提供截图中的“订单中心”卡片。点击进入统一订单中心。

订单中心顶部固定为：

- 全部订单
- 待支付
- 可使用
- 当前 Tab 订单搜索

搜索位于“可使用”右侧并右对齐。竖屏默认显示搜索图标，点击后本行进入搜索输入状态；关闭或清空后恢复 Tab。横屏可直接显示紧凑搜索框。

页面默认进入“全部订单”，按最近更新时间倒序排列。不得因为存在待支付订单而自动切换到“待支付”。

### 6.2 Tab 口径

| Tab | 本期租号 Demo 数据 |
|---|---|
| 全部订单 | 待支付、分配中、租用中、退款中、已退款、已结束 |
| 待支付 | 尚未完成支付且仍在支付有效期内的租号订单 |
| 可使用 | 已完成账号分配、租期有效且当前允许一键上号、继续游戏或查看登录信息的租号订单 |

分配中尚未获得可用账号，不进入“可使用”；已结束、退款中和已退款只进入“全部订单”。

未来 CDKEY 订单继续按既有 CDKEY 需求进入同一个订单中心，但不由本期 Demo 构造或演示。

### 6.3 订单卡片

所有卡片沿用用户提供截图的统一视觉外壳，不增加订单类型标签。租号卡片显示：

- 订单编号与精确租号状态。
- 游戏封面、游戏名称和历史实付金额。
- 必要时显示租期或剩余时间。
- 根据状态显示操作，不使用类型标签解释业务。

| 租号状态 | 主要信息 | 可用操作 |
|---|---|---|
| 待支付 | 支付剩余时间 | 取消订单、继续支付 |
| 分配中 | 正在分配账号 | 查看详情、刷新状态 |
| 租用中 | 剩余租期 | 一键上号、继续游戏或登录信息 |
| 退款中 | 退款进度 | 查看详情 |
| 已退款 | 退款结果 | 查看详情 |
| 已结束 | 实际结束时间 | 再次租用、查看详情 |

列表不展示账号、密码、Guard 或其他敏感凭据。敏感信息只在有效租用订单详情中通过短时授权读取。

### 6.4 当前页面搜索

搜索只作用于当前选中的 Tab，不跨 Tab、不进入 APP 全局搜索。匹配字段为游戏名称和订单编号。

- 输入后即时过滤当前已加载订单。
- 清空后恢复当前 Tab 全部订单。
- 切换 Tab 时保留关键词并在新 Tab 重新过滤。
- 无匹配时显示“未找到相关订单”，并提供清空搜索操作。
- 网络分页存在时，搜索由订单接口按当前 Tab 口径执行，客户端不得只过滤首屏数据。

### 6.5 列表与详情边界

订单列表只承载筛选、搜索、摘要和主要快捷操作。点击卡片进入独立订单详情；横竖屏均不把列表与详情强塞在同一屏。

从详情返回时恢复原 Tab、搜索词、列表滚动位置和订单排序。订单状态更新后重新判断所属 Tab；若订单不再属于当前 Tab，则从当前列表移除并保持其余位置稳定。

## 7. 租号状态与数据边界

租号订单不能使用单一展示状态代替支付、履约和退款状态。最小状态至少包括：

- `paymentStatus`：待支付、已支付、已关闭。
- `allocationStatus`：未分配、分配中、已分配、分配失败。
- `rentalStatus`：未开始、租用中、已结束。
- `refundStatus`：无退款、退款中、已退款、退款失败。
- `expireAt`：服务端租期结束时间。

列表状态由上述字段计算，但历史订单金额、游戏、版本、套餐、租期和退款规则必须使用订单快照，后台调价或商品下架不能改写历史订单。

## 8. 异常与恢复

1. 支付超时：从“待支付”移除，进入“全部订单”并显示已关闭。
2. 支付成功但取号失败：进入退款中，不得显示登录信息。
3. 租期到期：立即从“可使用”移除，进入“全部订单”的已结束状态。
4. 网络异常：保留当前 Tab、搜索词和订单号，恢复后幂等查询，不重复支付或取号。
5. 价格变化：进入确认订单前重新校验，不能静默加价。
6. 搜索请求失败：保留关键词并提供重试，不清空当前订单列表状态。
7. 订单深链无权限或不存在：不返回敏感数据，回到订单中心兜底页。

## 9. 组件边界

| 组件 | 职责 |
|---|---|
| `CoreAppShell` | 1:1 承载 APP 核心页与原全局导航 |
| `TaskPageShell` | 租号任务页标题、返回与安全区 |
| `EntitlementResolver` | 统一计算启动、下载、租号、购买、永久和会员入口 |
| `PricePresentation` | 按权益类型分别计算并展示价格 |
| `OrderCenterPage` | 三个 Tab、当前页搜索、排序和列表状态 |
| `RentalOrderCard` | 统一卡片外壳中的租号摘要与快捷操作 |
| `RentalOrderDetail` | 单笔租号订单状态、进度、登录与售后 |
| `RentalCredentialPanel` | 有效租用订单的短时凭据与 Guard |

本期不创建 CDKEY 订单组件；CDKEY 订单继续由既有需求实现，并复用订单中心约定的页面入口和基础外壳。

## 10. 验证方案

### 10.1 视觉验收

- 首页、搜索、详情、个人中心逐页与 V6.1.1 或用户提供截图对比。
- 核心结构、导航、卡片比例、主要素材、字号、间距和背景达到可直接辨认的同源程度。
- 租号增量不得导致原页面大面积改版或重新编排。
- 横竖屏原尺寸截图可直接阅读，不使用根容器整体缩放。

### 10.2 订单中心验收

- 顶部只有“全部订单 / 待支付 / 可使用”和当前页搜索。
- 订单卡片没有订单类型标签。
- Demo 只有租号订单状态，没有 CDKEY 示例订单。
- 三个 Tab 的订单归属符合 6.2 口径。
- 搜索只匹配当前 Tab 的游戏名称和订单编号。
- 切换 Tab、搜索、进入详情、返回和状态刷新后上下文连续。

### 10.3 业务验收

- 用户已有权益优先于商业价格。
- 租号与 CDKEY 价格不跨类型取绝对最低价。
- 同类多 SKU 最低价带“起”，首次价只对确认有资格的用户展示。
- 支付、取号、登录、临期、到期、退款和售后状态闭环不回退。

## 11. 不做事项

- 不重做 APP 核心信息架构或新增全局导航。
- 不增加订单类型筛选或订单类型标签。
- 不在本期租号 Demo 中复制 CDKEY 订单、激活和退款流程。
- 不新增营销活动、支付渠道、会员套餐或后台配置。
- 不修改 Mac Demo 与 Mac PRD 已确认的业务规则。
- 不物理删除订单、财务、退款、供应商对账或售后记录。

## 12. 三视角评审结论

- 用户视角：统一订单中心可降低入口认知成本；在不使用类型标签的前提下，必须依靠精确状态、租期和业务动作自然区分。
- 开发视角：统一页面外壳可行，但租号与 CDKEY 状态机、详情和敏感数据必须保持独立；本期 Demo 只实现租号状态可避免重复和状态污染。
- 商业视角：租购价格按权益类型拆分能够减少低价误导、无效点击和退款客诉，同时保留低门槛租号与永久购买的选择。

上述方案已经按用户最新决策移除订单类型筛选、订单类型标签和 CDKEY Demo 示例，无未处理的范围分歧。
