# APP 会员游戏快捷入口设计

**日期：**2026-09-18
**范围：**盖世游戏 APP 游戏库、排行榜、内容列表、会员中心、玩游戏·PC游戏、统一游戏详情及 Demo 内容图片
**状态：**用户已确认方案，待实施计划

## 1. 问题与目标

已开通会员的用户当前需要从个人中心进入会员中心，再通过“查看更多”进入会员游戏库。路径深，且高频游玩任务被套餐、支付和权益说明干扰。

本次目标是把会员游戏放入用户日常使用的游戏库主路径，让会员快速完成“找游戏—看详情—登录／下载／启动”，同时复用现有会员库、详情和账号履约能力。

## 2. 设计结论

游戏库顶层固定为：

```text
会员游戏｜PC游戏｜复古游戏
```

1. “会员游戏”固定第一位，作为会员权益的正式使用入口。
2. Steam、Epic、导入游戏继续放在“PC游戏”内部，不再占用顶层 Tab。
3. 会员中心负责购买、续费和权益说明，不再维护一套独立的会员游戏库页面。
4. 会员开通成功、会员中心“查看更多”、玩游戏·PC游戏快捷入口均跳转到“游戏库／会员游戏”。
5. 会员游戏卡片点击后进入统一游戏详情，不在列表直接登录、分配账号或启动。

## 3. 信息架构

### 3.1 顶层 Tab

| Tab | 承载内容 | 默认状态 |
|---|---|---|
| 会员游戏 | 会员游戏库、库内搜索、游戏卡片 | 有效会员首次进入游戏库时默认选中；会员相关入口固定选中 |
| PC游戏 | Steam、Epic、导入游戏及用户已有 PC 游戏 | 从未开通过会员的用户直接进入游戏库时默认选中 |
| 复古游戏 | 现有复古游戏内容 | 保持现状 |

用户主动切换后记忆上次 Tab。返回游戏库时恢复 Tab、搜索词和滚动位置，不因会员身份刷新强制切换。

### 3.2 PC 游戏内部

PC 游戏保持当前结构：顶部展示 Steam、Epic、导入游戏入口，下方展示“我的游戏”、搜索、排序和筛选。除顶层 Tab 收敛外，不改变现有内容和操作。

### 3.3 会员游戏内容

1. 顶部只提供“搜索会员游戏”，首期不增加排序和筛选。
2. 游戏采用一排2个卡片；卡片仅显示封面、游戏名称和灰色版本信息。
3. 不显示库存、云存档、会员、可畅玩、账号状态或直接启动按钮。
4. 搜索查询完整会员库，不得只过滤客户端已加载的数据。
5. 空库、无结果和请求失败分别展示对应空态或重试操作。

### 3.4 游戏库权益卡片

本节用于解释用户已经取得目标游戏权益后，游戏库卡片如何展示；不适用于排行榜和玩游戏等发现列表。

1. 卡片信息从上到下为：线框封面、游戏名称、版本／权益、剩余有效期。
2. 首次体验或其他有时效权益：第二行显示`标准版 · 已租号`，第三行显示剩余有效期；不超过24小时显示`剩余X小时X分`，超过24小时显示`剩余X天X小时`。
3. 单游戏永久：第二行显示`标准版 · 单游戏永久`，不展示剩余有效期或倒计时。
4. 会员游戏 Tab 的游戏卡仍只显示游戏名称和灰色版本；会员有效期在会员状态区域统一展示，不在每张会员游戏卡重复。
5. 卡片不提供登录、下载或启动按钮；点击整卡进入统一详情，再由详情提供操作。
6. 客户端不展示`正在分配账号`、`正在获取登录凭据`、`正在自动登录`等后台过程，也不使用“内部账号准备状态”作为 PRD 或 C 端术语。

## 4. 入口与主流程

### 4.1 会员开通成功

会员支付成功后，会员中心成功提示中提供主操作“去选游戏”。点击后进入“游戏库／会员游戏”，从支付成功时间开始计算会员有效期。

### 4.2 会员中心

会员中心的会员游戏预览继续保留；点击“查看更多”进入“游戏库／会员游戏”，不再打开独立会员游戏库页面。

### 4.3 玩游戏·PC游戏

有效会员进入“玩游戏／PC游戏”时，现有会员提示改为可点击的紧凑入口“会员游戏库已同步，去看看 ›”。点击进入“游戏库／会员游戏”，不在玩游戏页复制会员游戏列表。

### 4.4 日常游玩

```text
游戏库 → 会员游戏 → 游戏详情 → 现有登录／下载／启动流程
```

会员游戏卡片点击后进入统一详情。返回时恢复会员 Tab、搜索词和滚动位置。

## 5. 权益与详情规则

1. 详情继续使用服务端统一权益优先级：有效租赁 → 单游戏永久 → 有效会员且游戏在会员库 → 无权益。
2. 命中会员权益后不再展示首次体验、单游戏永久或租号购买入口，按当前登录、安装和运行状态提供对应操作。
3. 登录成功后返回游戏详情；账号只在启动时无感准备或复用，不展示“账号分配中”。
4. 会员过期后保留会员 Tab 和浏览记录；详情引导续费，不把游戏表现为用户永久拥有。
5. 游戏移出会员库后不允许新建使用单；进行中的使用单按订单或使用快照继续履约。
6. 账号资源繁忙时保留会员权益并提示稍后重试，不自动退款或延长会员。
7. 已有其他游戏正在运行时，阻止新游戏启动并提示先退出当前游戏；退出后再释放旧账号并准备新账号。

## 6. 状态与数据流

1. 游戏库读取会员状态、会员库配置、地区和客户端可用性。
2. 会员列表请求至少包含客户端、地区、关键词和分页参数。
3. 点击游戏进入详情时只传递游戏 ID 与来源；会员资格、在库状态和安装状态由详情实时复核。
4. 启动请求使用用户、游戏和请求 ID 保证幂等，重复点击不得重复创建使用单或重复分配账号。
5. 会员状态、列表请求或详情权益查询失败时不得把未知状态当作无权益；保留当前页面并提供重试。

## 7. 横竖屏要求

1. 竖屏顶层3个 Tab 一行完整展示，不换行、不横向滚动。
2. 横屏沿用现有游戏库框架，Tab 顺序与竖屏一致。
3. 会员游戏卡片按内容宽度排列，不为凑满一行强制拉伸；不得与搜索、底部导航或系统状态栏重叠。
4. 横竖屏切换后保留当前 Tab、关键词和滚动位置。

## 8. 明确不做

1. 不新增会员启动中心。
2. 不在玩游戏页复制一套会员游戏列表或推荐算法。
3. 不把会员游戏混入 PC 游戏“我的游戏”。
4. 不在会员卡片上增加直接登录、下载或启动按钮。
5. 不新增会员游戏排序、分类、筛选和个性化推荐。
6. 不修改 Mac 端本轮信息架构。

## 9. 排行榜与发现列表规则

### 9.1 适用页面

本规则适用于排行榜游戏项、玩游戏·PC游戏的推荐和游戏列表，以及其他以游戏封面为主体的发现列表。搜索结果继续使用已确认的个性化“已租号／可畅玩／¥X.X租号”规则，不在本次覆盖范围内。

### 9.2 展示

1. 列表保留页面原有的排名、游戏名称、线框封面和必要基础信息；租号信息区根据当前用户权益显示以下三种之一，不使用通用营销展示。
2. 从未购买首次体验且无目标游戏权益：第一行显示`¥X.X 首租`，第二行显示`99+ 在租`；`¥X.X`读取该游戏首次体验配置价并保留1位小数，Demo 使用`¥1.9 首租`。
3. 首次体验已支付且2小时有效期内：第一行显示`已租号`，第二行显示`99+ 在租`；不显示剩余时长和到期时间。
4. 首次体验已结束且用户已购买单游戏永久：第一行显示`可畅玩`，第二行显示`99+ 在租`；不在列表重复显示“单游戏永久”。
5. 列表不展示“登录游戏”“下载游戏”“启动游戏”“租号开玩”“立即购买”等操作按钮。
6. 整个游戏卡片为唯一点击区域，点击后进入统一游戏详情，由详情实时判断用户状态和可执行操作。

### 9.3 异常

1. 租号价格或在租人数获取失败时，只隐藏租号信息区，保留游戏基础内容和详情入口。
2. 游戏不支持本期租号、已下架或地区不可售时，不展示首租和在租信息。
3. 同一列表重复点击只允许打开一个详情任务，不在列表创建订单、下载任务、使用单或账号分配请求。

## 10. 列表状态穷举

列表只实现本轮确认的三个代表场景；其他交易和异常状态沿用主 PRD，在进入详情后处理。三种场景都不提供列表按钮。

| 场景 | 列表第一行 | 列表第二行 | 点击结果 |
|---|---|---|---|
| 没有进行首租 | `¥1.9 首租` | `99+ 在租` | 进入详情，详情可继续选择首次体验、单游戏永久或会员 |
| 已进行首租且首次体验仍生效 | `已租号` | `99+ 在租` | 进入详情，详情按当前登录、安装和运行状态处理 |
| 首租结束后已购买单游戏永久 | `可畅玩` | `99+ 在租` | 进入详情，详情按单游戏永久权益处理 |

首次体验从支付成功开始计时；列表不显示剩余时长、到期时间或“单游戏永久”来源，避免卡片信息过载。

## 11. Demo 图片线框化

1. APP 租号 Demo 中的游戏封面、Banner、头像、宣传图和其他位图内容统一替换为本地线框占位，不再读取或裁剪真实图片。
2. 线框占位保留原图片容器的尺寸、比例、圆角、排版位置和可点击区域，不改变页面信息层级。
3. 每个占位使用统一的深色底、低对比描边、简化线框图形和必要的内容名称，保证能识别其业务角色，但不模拟真实美术素材。
4. 页面功能图标、按钮图标、状态图标和平台文字标识继续使用现有 SVG 或文本，不因图片线框化丢失操作含义。
5. 竖屏、横屏、普通 Demo 和标注版必须使用同一套线框渲染逻辑；后续 PRD 截图从线框版 Demo 重新生成。
6. 线框图必须随单文件 Demo 离线可用，不增加外部图片、字体或网络依赖。

## 12. 验收口径

1. 游戏库顶层严格按“会员游戏、PC游戏、复古游戏”排序。
2. PC 游戏内部仍可使用 Steam、Epic、导入游戏、搜索、排序和筛选。
3. 有效会员首次进入默认会员游戏；从未开通过会员的用户直接进入默认 PC 游戏；主动选择后记忆上次 Tab。
4. 开通成功、会员中心“查看更多”和玩游戏快捷入口均进入同一会员 Tab。
5. 会员库搜索覆盖完整数据；清空、无结果、失败和重试状态正确。
6. 卡片只显示封面、名称和版本；点击进入统一详情，返回状态不丢失。
7. 登录成功返回详情；启动时无感准备账号，不出现“账号分配中”。
8. 会员过期、游戏下架、无库存、并发启动和网络失败均符合本设计的边界规则。
9. Demo 中不再出现真实游戏封面、截图、头像或宣传位图；所有原图片区域均以统一线框占位呈现，容器尺寸和交互热区不变。
10. 断网打开普通 Demo 与标注版时，线框图、页面文字和全部核心交互仍可正常展示。
11. 排行榜、玩游戏·PC游戏及其他发现列表按三种用户状态分别显示“¥X.X 首租”“已租号”或“可畅玩”，第二行统一显示“99+ 在租”；不出现登录、下载、启动或购买按钮。
12. 点击发现列表卡片只进入详情，不创建订单、下载任务、使用单或账号分配请求。
13. 没有进行首租、首次体验生效中、首租结束后已购买单游戏永久三个列表状态均可独立验证，且只允许整卡进入详情。
14. 游戏库有时效权益卡片在名称下方依次展示版本／权益和剩余有效期；永久权益不展示倒计时，会员游戏卡不重复展示会员有效期。
15. Demo、标注和 PRD 中不得再出现“内部账号准备状态”，后台分配、取凭据和自动登录过程均不作为用户可见状态。

## 13. 验证指标

首期记录会员游戏 Tab 曝光、入口来源、库内搜索、详情进入、登录、下载、启动结果和启动耗时。以灰度基线比较会员开通后7日游戏启动率、从游戏库进入到成功启动的中位步骤数与耗时，并监控 PC 游戏原有启动率不得明显下降。
