# 盖世游戏 APP 租号功能 Mac 衍生式横竖屏重构设计

## 1. 文档信息

- 日期：2026-08-03
- 状态：已确认设计，待实施
- 目标端：盖世游戏 APP 横屏、竖屏
- 横屏视觉与交互基线：`Mac端demo/mac端租号功能/Mac端租号功能-标注版.html`
- 当前待重构 Demo：`demos/APP租号功能/盖世游戏APP租号功能demo.html`
- 与原设计关系：保留原业务规则、权益状态机、订单状态机和横竖屏连续性；替换原“所有页面统一保留 APP 顶部导航、横屏重新设计”的页面与布局方案

## 2. 问题与结论

### 2.1 当前问题

现有 APP Demo 的横屏确认订单、会员中心、订单、Steam 登录、售后等页面被压缩成两张或多张小卡片，并保留了不属于任务场景的 APP 顶部导航，导致：

1. Mac 端已经确认的信息结构没有被复用，横屏重新创造了一套低密度页面。
2. `874×402` 内大量正文降至8—10px，关键信息、按钮和说明难以阅读。
3. 详情、交易、登录、售后等独立任务页仍展示全局导航，既挤占高度，也弱化当前任务。
4. 竖屏只是另一套独立布局，未体现与 Mac 横屏相同的模块层级和操作顺序。

### 2.2 最终结论

采用“核心页面保留 APP 外壳，独立任务页继承 Mac 骨架”的方案：

- 主页、游戏库、社区、排行榜、我的保留 APP 全局导航，只自然增加租号、会员和订单入口。
- 游戏详情及进入租号后的交易、会员、订单、Steam 登录、售后和到期处理均为独立任务页，不显示 APP 全局顶部或底部导航。
- 横屏直接继承 Mac 端对应页面的信息架构、模块关系、视觉层级和交互方式，不做整体缩放。
- 竖屏复用同一套页面组件、业务状态和文案顺序，按移动端优先级纵向重排。

## 3. 设计原则

1. **先还原，再适配**：横屏先对齐 Mac 已确认页面，竖屏再基于同一页面结构适配。
2. **任务优先**：独立任务页只保留返回/关闭、任务上下文和当前主操作，不展示全局导航。
3. **一个页面、一套逻辑**：横竖屏共用组件树、事件、接口和状态，只通过方向布局容器改变排列。
4. **不整体缩放**：禁止使用 `transform: scale()` 或统一缩小字号把 Mac 页面塞进 APP 横屏。
5. **关键内容先出现**：游戏、权益、价格、租期、订单状态、账号操作、风险和主按钮优先于说明与 FAQ。
6. **来源可返回**：每个任务页持有 `sourceRoute/returnTo`；完成、取消或返回时恢复来源页面和滚动位置。
7. **不扩展范围**：不重做社区、排行榜等现有页面，只增加已确认入口；不新增无必要页面、弹窗或 Toast。

## 4. 页面壳层划分

### 4.1 保留 APP 全局导航的核心页面

| 页面 | 导航要求 | 本期改动 |
|---|---|---|
| 主页 | 保留现有 APP 全局导航 | 在现有游戏卡和内容区增加首次体验、可租号、会员畅玩状态及详情入口 |
| 游戏库 | 保留现有 APP 全局导航 | 增加可租状态、会员状态、Steam 登录和租号订单相关入口，已有游戏仍优先启动或下载 |
| 社区 | 保留现有 APP 全局导航 | 不重做；如现有游戏卡命中租号展示规则，仅沿用统一状态组件 |
| 排行榜 | 保留现有 APP 全局导航 | 不重做；如榜单游戏可租，只增加统一状态与详情入口 |
| 我的 | 保留现有 APP 全局导航 | 在头像附近增加会员状态，并提供会员中心和租号订单入口 |
| 搜索 | 沿用当前 APP 搜索层和来源页面外壳 | 搜索结果复用统一租号状态组件；进入详情后切换为独立任务页 |

| 页面 | 顶部区域 | 返回规则 | 横屏基线 |

| 游戏详情 | 返回、游戏名称或必要操作 | 返回来源核心页并恢复位置 | Mac 游戏详情页 |
| 确认订单 | 返回、标题“确认订单” | 返回游戏详情，保留版本与套餐 | Mac 确认订单页 |
| 会员中心 | 返回、用户身份与会员状态 | 返回来源详情或我的 | Mac 会员中心页 |
| 会员游戏库 | 返回、标题与当前会员状态 | 返回会员中心 | Mac 会员中心内游戏库模块扩展为独立页 |
| 支付结果/账号分配 | 关闭或返回订单 | 返回订单详情或来源详情 | Mac 支付与履约状态 |

## 5. 横屏布局设计

横屏参考尺寸为 `874×402`。页面继承 Mac 信息骨架，但按有效高度重排，不压缩到不可读尺寸。

### 5.1 游戏详情

- 左侧为游戏主视觉、名称、平台和当前状态；右侧为版本、权益/SKU、价格和主操作。
- 与 Mac 一致，已有游戏主操作优先；租号或会员作为条件性操作出现。
- 详情长说明、兼容性和次要信息进入页面内部纵向滚动，不占用首屏主操作区。
- 页面不显示 APP 全局导航，仅保留左上返回。

### 5.2 确认订单

- 继承 Mac 确认订单的左右结构：左侧为游戏与服务保障，右侧为版本、SKU、价格、支付方式和二维码。
- 右侧支付区域固定显示订单金额和主按钮；左侧内容超过高度时仅左侧内部滚动。
- 游戏原价、订单金额、套餐和版本必须在首屏可见；主按钮不得被滚动内容推离视口。
- 单游戏订单不出现会员购买 Tab，“开通会员”进入独立会员中心。

### 5.3 会员中心

- 继承 Mac 页面：顶部用户信息与会员说明，中部月度/年度/永久三张套餐卡，右侧支付区，下方会员游戏库。
- `874×402` 下首屏保留用户信息、三张套餐卡和支付区；会员游戏库与 FAQ 在页面下方滚动区域。
- 套餐卡整卡切换，不能压缩为三张过小的摘要卡。
- 不显示 APP 全局导航。

### 5.4 租号订单与订单详情

- 继承 Mac 左列表、右详情结构，左侧约35%，右侧约65%。
- 左侧订单列表独立滚动；右侧显示游戏、状态进度、金额和当前可操作按钮。
- 按钮根据状态收敛，进行中订单显示继续游戏、登录信息、继续畅玩和申请售后。
- 列表与详情都不得通过缩小字号强行塞满。

### 5.5 Steam 登录与登录信息

- Steam 登录基本1:1继承 Mac 双栏结构：左侧账号密码，右侧二维码。
- “租号登录信息”位于关闭按钮左侧，点击后只覆盖二维码区域，不遮挡左侧输入表单。
- 独立订单登录信息继续使用 Mac 居中凭据弹窗，只保留右上角 X。
- Guard 按需获取，账号、密码、Guard 共用同一使用单和短时授权。

### 5.6 售后、临期与到期

- 售后横屏采用左侧订单摘要、右侧售后表单；退款进度和换号结果在右侧内容区延续展示。
- 15分钟提醒使用顶部居中提示条，但在独立任务页相对页面顶部定位，不为不存在的 APP 导航预留空间。
- 到期和安装包启动拦截复用 Mac 游戏卡与权益选择结构，按钮保持“立即结束、继续畅玩”。

## 6. 竖屏适配设计

竖屏参考尺寸为 `390×844`。竖屏不是重新设计业务，而是同一页面的移动端排列。

### 6.1 通用结构

- 顶部使用独立任务页标题栏：返回、标题、必要的关闭或帮助入口。
- 内容顺序统一为：任务上下文 → 当前选择/状态 → 价格或关键操作 → 风险与说明。
- 交易页主按钮固定在底部安全区；正文可滚动，底部留出主按钮高度。
- 价格、租期、账号状态和异常提示不得折叠；服务保障、FAQ和次要说明可下移或折叠。

### 6.2 页面适配

| 页面 | 竖屏排列 |
|---|---|
| 游戏详情 | 游戏主视觉与名称 → 当前权益/版本 → SKU与价格 → 固定主按钮 → 次要详情 |
| 确认订单 | 游戏摘要 → 版本与套餐 → 游戏原价/订单金额 → 支付方式与二维码 → 固定支付按钮 → 服务保障 |
| 会员中心 | 用户与会员状态 → 三张纵向套餐卡 → 支付方式与二维码 → 固定支付按钮 → 会员游戏库 → FAQ |
| 租号订单 | 状态 Tab → 订单列表；点击订单进入独立订单详情，不在同屏强塞列表和详情 |
| Steam 登录 | 账号密码表单 → 登录按钮 → 按需 Guard → 二维码；登录信息使用底部面板或轻浮层 |
| 售后 | 订单摘要 → 五类问题 → 必填描述 → 固定提交按钮 → 提交后的退款/换号进度 |
| 到期 | 游戏卡 → 到期原因 → 当前可用权益说明 → 立即结束/继续畅玩 |

## 7. 字号、密度与可读性

| 元素 | 最小标准 |
|---|---|
| 页面标题 | 20px；重要独立页可使用24px |
| 模块标题 | 18px |
| 正文与表单值 | 14px |
| 价格、关键状态 | 18—28px，按层级使用 |
| 辅助说明 | 12px，仅用于非关键补充 |
| 标签 | 11—12px，不承载关键规则 |
| 按钮 | 高度≥44px，主按钮文字≥14px |
| 输入框 | 高度≥44px，输入文字≥14px |

禁止：

- 使用8—10px正文或关键状态文字。
- 为容纳内容而整体缩放页面。
- 同一首屏同时出现多个等权主按钮。
- 通过去掉必要文案解决高度问题。

## 8. 路由与状态

### 8.1 路由分层

- `core-shell`：主页、游戏库、社区、排行榜、我的、搜索层；渲染 APP 全局导航。
- `task-shell`：详情、交易、会员、订单、登录、售后、到期；不渲染 APP 全局导航。
- 从核心页进入任务页时写入 `sourceRoute`、`sourceScrollTop` 和必要的 `sourceParams`。
- 返回优先恢复来源页面；来源失效或深链冷启动时，详情兜底返回主页，订单兜底返回我的。

### 8.2 横竖屏连续性

以下状态必须放在路由级共享状态/ViewModel，不属于方向组件：

- 当前游戏、版本、SKU、时长和价格快照。
- 订单号、支付状态、账号分配状态和倒计时。
- 登录方式、Steam 输入、凭据授权和 Guard 倒计时。
- 订单筛选、售后草稿、退款进度和换号状态。
- 15分钟提醒是否已展示/关闭、到期处理状态。
- 来源路由、来源滚动位置和任务页内部滚动位置。

旋转只切换布局类和容器排列，禁止重复请求、重复创单、重复支付、重复取号或重复获取 Guard。

| `PaymentPanel` | 支付方式、二维码和主按钮 | 横屏右栏，竖屏纵向区＋底部主按钮 |

## 10. 异常处理

1. 返回来源不可用：详情返回主页；订单/会员返回我的，并提示不新增额外弹窗。
2. 横屏高度不足：使用页面或单栏内部滚动，不降低正文和按钮字号。
3. 键盘弹出：竖屏表单自动滚动到当前输入框，底部主按钮可随键盘收起或上移，不遮挡输入。
4. 旋转过程中有支付/登录请求：保持请求实例与幂等键，旋转后继续展示相同状态。
5. 临期提示与独立任务页标题冲突：提示条占据标题下方安全区，正文同步下移；关闭后恢复。
6. 深链直接进入 Steam 登录或售后但订单无效：不展示敏感信息，返回订单兜底页。

## 12. 验证方案

### 12.1 视觉验收

- 横屏逐页与 Mac 对应页面并排检查信息结构、模块顺序、主次、字号和交互位置。
- 竖屏逐页检查首屏是否包含任务上下文、价格/状态和主操作。
- 所有关键页面在 `874×402` 与 `390×844` 原尺寸截图下可直接阅读，不依赖放大。
- 独立任务页不得出现 APP 全局导航；核心页面必须保留现有 APP 导航。

### 12.2 交互验收

- 从主页、游戏库、搜索和我的进入任务页，完成或返回后恢复正确来源和滚动位置。
- 确认订单、会员、Steam 登录、订单详情和售后过程中旋转，状态与输入不丢失。
- 一键与手动登录、订单登录信息、Guard、15分钟提醒、T0和售后仍满足原业务规则。

### 12.3 自动检查

- 增加核心页/任务页导航壳层断言。
- 增加关键文字最小字号、按钮/输入框最小高度断言。
- 增加禁止整体 `transform: scale()` 的页面检查。
- 保留权益、SKU、交易、登录、安全、连续性、到期和售后原有自动用例。
- 重新生成横竖屏 PRD 截图，逐张原尺寸复核后更新 PRD 固定 Git SHA。

## 13. 三视角评审结论

- 用户视角：方案成立；必须提供清晰返回、来源兜底和持续任务上下文，竖屏不能机械纵排。
- 开发视角：方案成立；必须使用同一组件树和共享状态，任务路由与核心路由分层，旋转不得重建业务。
- 产品视角：方案成立；现有核心页面只增加入口，重做范围集中在租号独立链路，避免再次扩大到社区和排行榜改版。

上述风险均已写入路由、布局、组件、异常和验证章节，无未处理硬伤。
