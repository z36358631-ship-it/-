# 盖世游戏 APP 租号功能全量继承式重构设计

## 1. 文档信息

- 日期：2026-08-04
- 状态：已确认，待按实施计划重构
- 目标端：盖世游戏 APP 横屏、竖屏
- 核心页面基线：现有盖世游戏 APP 对应页面与已提供的原页面素材
- 横屏任务页基线：`Mac端demo/mac端租号功能/Mac端租号功能-标注版.html`
- 当前待重构 Demo：`demos/APP租号功能/盖世游戏APP租号功能demo.template.html`
- 构建产物：`demos/APP租号功能/盖世游戏APP租号功能demo.html`
- 标注版：`demos/APP租号功能/盖世游戏APP租号功能-标注版.html`

## 2. 问题与最终决策

### 2.1 当前问题

当前 APP Demo 同时存在页面继承和业务闭环两类问题：

1. 首页、玩游戏、排行榜等核心页面被重新组织或合成，偏离“在现有 APP 上增量接入租号”的范围。
2. 社区、搜索仍是不可达或占位页面，游戏库缺少统一租号状态与详情入口。
3. 横屏任务页只借用了 Mac 的视觉印象，没有完整继承 Mac 的模块、顺序、文案、状态与操作。
4. 横屏订单列表和订单详情被合并为 35%/65% 主从页，与竖屏独立页面和最终产品路由不一致。
5. 支付停在“取号中”、会员停在“待支付”、启动和会员畅玩只播放反馈动画，用户无法完成闭环。
6. 凭据没有真正绑定订单、账号和使用单；到期后的详情仍可能显示过期前状态；退款和换号不改变订单与账号绑定。
7. 横竖屏分别拼装页面，容易出现模块顺序、文案、状态和事件不一致。

### 2.2 最终决策

采用“全量继承式重构”，不在当前合成页面上继续修补：

- **核心页继承 APP**：主页、玩游戏、社区、排行榜、游戏库、我的和搜索，逐页 1:1 继承现有 APP。只允许增加已确认的租号状态、会员状态、订单入口和详情入口。
- **横屏任务页继承 Mac**：详情、交易、会员、订单、登录、凭据、临期、到期和售后，逐页 1:1 继承 Mac 的信息架构、模块顺序、业务文案、状态和操作。
- **竖屏同组件同顺序**：横竖屏使用同一组件树、同一状态、同一事件和同一文案顺序；竖屏只通过 CSS 布局和滚动策略重排，不另写一套页面。
- **订单拆页**：无论横屏还是竖屏，`orders` 只显示订单列表，`order-detail` 只显示单笔订单详情；点击订单进入独立详情页，禁止 35%/65% 主从布局。
- **业务必须闭环**：页面不能停在展示状态。支付、取号、会员开通、登录、临期、到期、退款和换号都必须产生可验证的后续状态。

## 3. 设计原则

1. **继承优先于创新**：有 APP 或 Mac 基线的页面，不重新发明结构、内容或交互。
2. **先还原原页，再加租号**：核心页未达到 1:1 前，不加入新的租号卡片、弹窗或流程。
3. **任务页逐页映射**：每个 APP 任务页必须能指出唯一 Mac 参考页或参考状态。
4. **一页一棵组件树**：同一页面不得维护互相独立的横屏与竖屏业务模板。
5. **一个用户动作一个可验证结果**：支付、续费、登录、换号等操作必须改变订单、权益、账号或使用单状态。
6. **实时状态而非场景标签**：CTA 必须由当前游戏、订单、会员、账号和使用单计算，不能由静态演示 `scenario` 决定。
7. **敏感信息最小暴露**：账号、密码和 Guard 只能在有效使用单授权内查看，默认掩码，结束后立即撤销。
8. **旋转不重建业务**：旋转只能改变布局，不重复创单、支付、取号、授权、Guard、退款或换号。
9. **禁止范围漂移**：不新增未确认功能、页面、弹窗、Toast、后台能力或营销内容。

## 4. 页面壳层与继承关系

### 4.1 核心页：1:1 继承现有 APP

| 页面 | 必须继承 | 唯一允许的增量 |
|---|---|---|
| 主页 `home` | 原搜索、推荐、资讯、卡片、导航和视觉层级 | 命中游戏增加首次体验/可租号/会员畅玩/进行中状态及详情入口 |
| 玩游戏 `play` | 原 Tab、最近游玩、游戏列表、账号区和导航 | 原游戏卡增加统一租号状态；进入详情或进行中订单 |
| 社区 `community` | 原信息流、帖子、游戏卡和导航 | 命中游戏卡复用统一租号状态，不改变社区内容结构 |
| 排行榜 `ranking` | 原榜单、排序、筛选、卡片和导航 | 可租游戏增加统一状态与详情入口 |
| 游戏库 `library` | 原平台 Tab、搜索、筛选、游戏卡、启动/下载优先级和导航 | 增加租号/会员状态、Steam 登录和订单入口 |
| 我的 `profile` | 原头像、Steam 信息、活动、设备、服务入口和导航 | 增加会员状态、会员中心和租号订单入口 |
| 搜索 `search` | 原搜索层、输入、历史/建议、结果和来源页外壳 | 结果卡复用统一租号状态；详情返回时恢复查询和滚动位置 |

核心页验收采用基线截图叠图和结构清单。禁止删除、改名、换位或新增原页面模块；租号增量必须能单独关闭，关闭后页面恢复原样。

### 4.2 任务页：横屏 1:1 继承 Mac

| APP 页面/状态 | Mac 基线 | APP 路由与返回 |
|---|---|---|
| 游戏详情 | Mac 游戏详情 | `detail`；返回来源核心页并恢复位置 |
| 确认订单 | Mac 确认订单 | `checkout`；返回详情并保留选择 |
| 支付与账号分配 | Mac 支付确认、取号结果 | 保持在交易任务栈；成功进入订单详情，失败进入退款/恢复状态 |
| 会员中心 | Mac 会员中心 | `membership`；返回详情或我的 |
| 会员游戏库 | Mac 会员库模块 | `member-library`；返回会员中心 |
| 订单列表 | Mac 租号中心列表 | `orders`；返回我的 |
| 订单详情 | Mac 单笔订单详情 | `order-detail`；返回订单列表 |
| 登录方式 | Mac 登录方式轻弹窗 | 覆盖订单详情；X/外点/Esc 关闭 |
| Steam 登录 | Mac Steam 双栏登录 | `steam-login`；关闭回原订单详情 |
| 登录信息 | Mac 独立凭据弹窗 | 覆盖订单详情，不拉起 Steam |
| 15分钟提醒 | Mac 顶部临期提醒 | 覆盖当前页面；关闭留在原页，继续进入详情 |
| 到期结束/启动拦截 | Mac 到期结束与启动 Guard | 覆盖当前任务；结束回来源，继续进入实时权益详情 |
| 售后申请与结果 | Mac 售后表单、退款详情和换号结果 | `after-sales`；返回订单详情并保留进度 |

“1:1 继承”包含：模块名称、模块顺序、字段、业务文案、状态、CTA、弹层关系和异常反馈。允许因 `874×402` 视口使用内部滚动或紧凑间距，但不得删减关键模块、降低字号、合并页面或改造为另一种信息结构。

### 4.3 核心壳层与任务壳层

- `core-shell`：保留对应现有 APP 的全局导航、主题和页面容器。
- `task-shell`：只保留任务标题、返回/关闭、任务上下文和当前操作，不显示 APP 全局导航。
- 从核心页进入任务页时记录 `sourceRoute`、`sourceParams`、`sourceScrollTop`。
- 任务完成、取消或返回时优先恢复来源；深链无来源时，详情回主页，会员/订单回我的。

## 5. 横竖屏统一组件规则

### 5.1 同组件同顺序

每个任务页只允许一个页面渲染器。横竖屏共享以下内容：

- 组件实例和 DOM 顺序。
- 游戏、版本、SKU、价格和订单快照。
- 文案、按钮名称和可用条件。
- 表单输入、草稿、错误、倒计时和异步请求。
- 弹层、凭据授权、Guard、退款和换号状态。

方向差异只由容器类和 CSS Grid/Flex 规则表达。禁止用 `renderPortraitXxx()` 与 `renderLandscapeXxx()` 分别维护两份页面业务；若保留方向包装函数，包装函数只能添加布局类，不能改变模块、数据和事件。

### 5.2 横屏

- 参考尺寸：`874×402`。
- 任务页按 Mac 原页面的左右栏、上下区、弹层和固定操作继承。
- 订单列表和订单详情例外地保持两个独立页面：订单列表全宽展示列表，订单详情全宽展示单笔详情。
- 页面高度不足时使用页面或指定模块内部滚动，不通过整体缩放解决。

### 5.3 竖屏

- 参考尺寸：`390×844`。
- 使用横屏同一组件顺序，由多列自然折为单列。
- 交易主按钮固定在底部安全区，正文为同一组件树的可滚动内容。
- Steam 登录从双栏折为“账号密码→登录→Guard→二维码”，模块不可换序。
- 订单列表与订单详情仍为两个独立页面。

### 5.4 可读性底线

| 元素 | 最小标准 |
|---|---|
| 页面标题 | 20px |
| 模块标题 | 18px |
| 正文、表单值、按钮 | 14px |
| 辅助说明 | 12px |
| 价格和关键状态 | 18—28px |
| 可点击区域、按钮、输入框 | 高度至少44px |

禁止根容器 `transform: scale()`、8—10px 关键文案、多个等权主按钮和依靠删文案解决空间不足。

## 6. 统一游戏与权益决策

所有入口、详情和订单必须读取同一 `GameContext`：

- `gameId`、名称、封面、版本必须来自同一记录，禁止文字与素材错配。
- 游戏卡进入详情时传递明确 `gameId`，不得依赖默认游戏。
- CTA 根据实时状态按以下优先级计算：个人已拥有且已安装→启动；个人已拥有未安装→下载；有效租赁→继续游戏/登录信息；单游戏永久→启动；有效会员且在会员库→会员畅玩；首次体验资格→首次体验；其他→普通租用/永久/会员入口。
- 到期、退款、换号和会员变化后必须重新计算 CTA，不保留旧 `scenario`。
- 首页、玩游戏、社区、排行榜、游戏库和搜索共用同一状态组件和同一详情入口。

## 7. 支付与账号分配闭环

### 7.1 单游戏订单

1. 用户在详情选择版本和唯一 SKU。
2. 进入确认订单后生成待支付订单，保存游戏、版本、SKU、时长、价格版本、退款规则和支付截止时间快照。
3. 支付成功后订单从 `pending` 进入 `allocating`，同一订单只允许一次取号。
4. 取号成功进入 `active`，创建使用单并绑定唯一账号；页面跳转该订单详情。
5. 取号失败进入 `refunding`，显示自动退款进度；不得继续展示可登录凭据。
6. 支付超时进入 `cancelled`；价格变化要求重新确认，但不得静默改价。
7. 网络异常保留订单号和服务端状态，提供重新查询，不重复创单或支付。

### 7.2 幂等与旋转

- 创单、支付、取号分别使用订单级幂等键。
- 旋转、返回前台、重复点击和重新渲染不得重复执行。
- 支付按钮后必须存在成功、失败、超时或网络恢复结果，禁止永久停在“支付处理中”。

## 8. 会员与会员游戏库闭环

### 8.1 会员购买状态

- 未开通：可购买月度、年度或永久会员。
- 月度/年度有效：同套餐续费和跨套餐续费均从当前到期时间顺延；购买永久为升级。
- 已过期：重新开通从支付成功时间计算。
- 永久会员：所有购买入口禁用，显示“永久会员无需重复购买”和“查看权益”。
- 每笔购买保存套餐名称、配置版本、价格、有效期和购买前会员状态快照。

### 8.2 会员畅玩

- 会员游戏卡必须显示正确游戏素材、会员状态和可用条件。
- 点击会员畅玩后创建 `member-use` 使用单并绑定可用账号，不得只播放按钮动画。
- 同一会员同时只保留一个活动会员使用单；切换游戏前先撤销旧会话、回收旧凭据和释放旧账号，再创建新使用单。
- 会员到期立即结束会员使用单，并进入会员到期恢复流程。

## 9. 订单、登录与凭据安全

### 9.1 订单列表与详情拆页

- `orders` 只包含筛选、搜索和订单列表，不渲染详情栏。
- `order-detail` 只显示所选订单的游戏、状态进度、金额、时间、账号服务和状态操作。
- 横竖屏均点击订单进入 `order-detail`；返回恢复订单筛选和列表滚动位置。
- 待支付提供去支付/取消；取号中提供状态查询；进行中提供继续游戏、登录信息、继续畅玩、申请售后；退款中提供退款进度；已结束提供查看详情/再次购买。

### 9.2 登录方式与 Steam 登录

- 一键上号和手动登录使用同一订单、账号和使用单。
- 一键上号必须有成功与失败分支；失败可重试或切换手动登录。
- Steam 登录只接受当前活动使用单授权的账号；任意非空输入不能直接通过。
- 租号账号默认不勾选“记住我”。
- Steam 页中的“租号登录信息”只覆盖二维码区域，关闭后不影响左侧输入。

### 9.3 凭据与 Guard

- 账号和密码按 `orderId + accountId + usageId` 绑定，默认掩码。
- 订单登录信息使用居中轻弹窗，只保留右上角 X；外点、Esc 和退后台关闭并清除明文展示。
- Guard 按需获取，绑定同一使用单和短时授权；未过期重复打开复用，刷新或过期后必须生成新值。
- 订单结束、T0、退款提交、换号、账号解绑和授权失效时，立即撤销会话并清除账号、密码、Guard 与剪贴板提示状态。

## 10. 15分钟提醒与到期闭环

### 10.1 15分钟提醒

- 以服务端时间为准，首次从 `>15分钟` 跨入 `≤15分钟且>0` 时触发一次，不依赖恰好等于15分钟。
- 同一使用单只提醒一次；关闭、旋转和退后台后不重复。
- 不设置5分钟或1分钟二次提醒。
- “继续畅玩”进入实时权益详情，租期不得自动延长；详情必须提供当前可购买或可接管权益。

### 10.2 T0 与启动拦截

- T0 必须幂等地结束原使用单、撤销游戏会话和短授权、释放账号、清除凭据并关闭敏感弹层。
- 若存在个人拥有、单游戏永久、有效会员或支付后新活动订单，使用对应权益接管；详情 CTA 同步更新。
- 无新权益时显示到期启动 Guard：“立即结束”返回来源，“继续畅玩”进入可购买详情。
- 离线或校验失败时保持拦截，不得沿用过期账号启动。
- 本地安装包、配置和个人存档保留，但过期租赁授权不可继续使用。

## 11. 售后、退款与换号闭环

### 11.1 售后资格

- “3天无理由”以支付成功后72小时、累计成功游玩不超过30分钟和订单退款规则版本快照共同判断。
- 不合资格时选项禁用并显示具体原因。
- 启动失败、Steam 登录失败、账号异常/频繁掉线和其他履约问题不受无理由资格影响。
- 描述必填；重复提交返回原售后单，不生成重复记录。

### 11.2 退款

- 提交退款后订单进入 `after-sales/refunding`，登录和凭据入口立即失效。
- 退款进度由售后状态驱动，依次呈现申请中、审核、原路退款和完成，不使用静态装饰数组冒充处理结果。
- 退款完成后订单进入终态，原账号完成会话撤销和凭据回收。

### 11.3 换号

- 仅分配同游戏、同版本且具备完整凭据能力的新账号。
- 有库存：先回收旧账号和旧凭据，再绑定新账号并在同一订单下创建新使用单；订单详情更新账号服务状态。
- 无库存：保留原绑定和售后进度，提供重试与客服入口，不得先释放原账号。
- 旧账号回收失败时不得重新进入库存，必须进入异常状态。

## 12. 路由与共享状态

### 12.1 路由

- 核心页：`home/play/community/ranking/library/profile/search`。
- 任务页：`detail/checkout/membership/member-library/orders/order-detail/steam-login/after-sales`。
- 弹层状态：登录方式、登录信息、15分钟提醒、到期 Guard、支付确认、异常恢复。
- `orders → order-detail` 始终是路由跳转，不因方向切换为同屏主从。

### 12.2 共享状态

以下状态必须属于统一 ViewModel，不属于方向布局：

- 游戏、版本、SKU、价格和来源上下文。
- 订单、支付、取号、账号、使用单和退款规则快照。
- 会员状态、购买快照和活动会员使用单。
- 登录方式、Steam 表单、凭据授权、Guard 和敏感信息可见性。
- 订单筛选、列表滚动、售后草稿、退款和换号进度。

## 14. 异常与恢复

1. 无库存：禁止支付或取号，保留选择，支持重试或返回详情。
2. 价格变化：显示前后价格，用户确认后创建新价格快照。
3. 支付超时：关闭待支付订单，重新支付必须创建新订单。
4. 取号失败：进入自动退款，不暴露凭据。
5. 网络异常：保留订单号和服务端状态，重新查询不重复请求。
6. 深链订单无效：回订单列表，不显示任何敏感信息。
7. 键盘弹出：输入框保持可见，竖屏底部操作不遮挡表单。
8. 横屏高度不足：使用内部滚动，不降低可读性或改变模块顺序。
9. 旋转中存在请求：复用原请求与幂等键，展示同一状态。
