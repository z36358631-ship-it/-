# 微信 H5 精品游戏无障碍、音频与发布门禁加固设计

## 1. 状态与目标

- 设计状态：已批准，待实施。
- 批准方案：平衡方案 A。
- 影响范围：试玩大厅、《五秒之后》《世界缝补师》《裂隙猎人》及对应自动验收工具。
- 目标：关闭已经由浏览器证据确认的焦点穿透、短横屏入口裁切、减少动态效果不一致、无效声音开关和测试参数未隔离问题，同时不在本轮高风险改写三款 Canvas 的缩放与触控坐标主链。

本轮完成后仍只能声明“浏览器评审包 READY”。微信开发者工具、正式 AppID、业务域名、iOS/Android 真机、CDN、灰度、监控和回滚未取得证据前，不得声明微信生产 GO。

## 3. 方案选择

### 3.1 已选：平衡方案 A

修复明确阻断用户完成任务且不要求重写 Canvas 坐标系统的问题；对 200% CSS `zoom` 保留透明的失败证据和风险说明。

### 3.2 未选方案

- 全量缩放重构：允许 200% 页面缩放，并重写 CSS 尺寸、Canvas backing store、DPR 与 Pointer 坐标换算。优点是覆盖更高无障碍目标，缺点是会同时影响三款核心输入与性能，需要独立真机专项。
- 只记录不修：不改游戏，只在发布清单登记问题。该方案会保留键盘、眩晕敏感用户和误横屏用户的直接障碍，不符合精品评审包标准。

## 4. 交互与页面设计

### 4.1 开场焦点隔离

每款游戏在开场、暂停和结算层激活时，只允许焦点进入当前顶层对话区域。

- 顶层区域使用 `role="dialog"`、`aria-modal="true"`、可编程聚焦标题或容器。
- 非当前层和游戏 HUD 使用 `inert` 隔离；不支持 `inert` 的浏览器使用统一 Tab 循环作为降级。
- 开场出现时焦点落在主操作按钮；按 Tab 只能在该层可操作控件间循环。
- 开始游戏后移除隔离，焦点返回游戏容器。
- 暂停、恢复、结算和重玩沿用同一焦点管理器，不分别复制逻辑。
- `Escape` 不绕过开始页或结算层；暂停层是否响应 `Escape` 保持现有产品规则。

焦点管理器只负责可聚焦元素、`inert` 和焦点恢复，不读取或修改游戏规则状态。

### 4.2 竖屏阻断

《五秒之后》和《世界缝补师》补充与《裂隙猎人》一致的竖屏阻断层。

- 触发条件：`orientation: landscape` 且视口高度不超过 600px。
- 阻断层覆盖游戏壳，显示“请旋转至竖屏”和一条与游戏主题一致的解释。
- 阻断层不是失败结算，不推进游戏、不发 `run_end`，也不修改本局 `runId`。
- 页面在进行中转为短横屏时，先暂停游戏；恢复竖屏后仍需玩家主动继续。
- 超宽短屏使用同一规则，不另外压缩竖屏游戏到不可操作宽度。
- 阻断层本身可被读屏识别，但不抢占结算层等更高优先级对话状态。

### 4.3 减少动态效果

- 大厅在 `prefers-reduced-motion: reduce` 下移除试玩按钮、卡片和装饰元素的非必要 transition/animation。
- 《五秒之后》首次初始化时使用“系统偏好或用户已保存偏好”的并集；系统要求简动时不得被错误类型或旧缓存关闭。
- 用户在游戏内切换简动设置后继续持久化；系统偏好变化只在不违背用户主动开启简动的方向上生效。
- 减少动态只降低粒子、抖动、脉冲和过渡，不改变计时、碰撞、敌人或胜负规则。
- 《世界缝补师》《裂隙猎人》现有通过行为保持不变。

## 5. 《世界缝补师》轻量音频

### 5.1 SoundBus

在单文件内部增加一个无外部资源的 `SoundBus`：

- 首次明确用户手势后惰性创建或恢复 `AudioContext`。
- 同一页面只保留一个音频上下文，不在重玩时重复创建。
- 静音、页面隐藏、暂停和浏览器不支持 Web Audio 时直接无声降级。
- 每个声音节点都设置短包络并按时断开，避免长期驻留。
- 默认增益保持低音量；不播放循环背景音乐。

### 5.2 四类反馈

| 反馈 | 触发 | 声音方向 |
|---|---|---|
| 有效缝合 | 合法锚点连接成功并扣除线长 | 短促上行双音 |
| 无效缝合 | 非法配对、线长不足或错误终点 | 低音量短促下行音 |
| 生命获救 | 单个生命首次安全抵达花园 | 柔和高音，设置最小间隔防止同帧叠响 |
| 结算 | 胜利或失败结果首次出现 | 胜利短和弦；失败低沉但不刺耳的双音 |

声音只辅助操作因果；颜色、文字、形状和状态播报仍是完整信息来源。

### 5.3 音频错误处理

- `AudioContext` 构造、`resume`、节点连接或播放失败均捕获，不显示阻断弹窗。
- 音频失败不改变缝线、资源、生命、计时和结算。
- 强制静音查询参数仅在测试模式中生效；普通生产入口不接受查询参数改变声音持久化状态。
- 页面隐藏立即挂起声音；恢复可见后不自动发声，只在玩家主动继续并再次发生游戏事件时播放。

## 6. 测试能力与发布门禁

### 6.1 查询参数

- `speed`、`seed`、`mute` 仅在 `test=1` 时读取并生效。
- 未带 `test=1` 的入口无论附加什么 `speed` 值，公开状态必须始终显示 `timeScale=1`，自然速度规则不变。
- 小程序壳路由继续拒绝外部 query、hash、URL 凭证和未知游戏参数。

### 6.2 测试接口

- `window.__GAME_TEST__` 仅在 `test=1` 时挂载。
- 普通入口不得暴露 `advance`、`finish`、`setElapsed`、`grantXp`、`grantLoot`、`forceDeath` 等状态注入能力。
- 验收脚本访问游戏时显式添加 `test=1`，不依赖普通入口暴露调试接口。
- `file://` 普通双击试玩仍可运行，只是不提供自动测试接口。

### 6.3 报告可追溯性

四类 JSON 报告统一增加以下元数据：

```json
{
  "schemaVersion": 1,
  "generatedAt": "ISO-8601",
  "gitCommit": "40 位提交 SHA 或明确的 unavailable",
  "command": "实际执行命令",
  "environment": {
    "nodeVersion": "vX",
    "browserVersion": "X"
  },
  "summary": {}
}
```

- 主验收报告从顶层数组升级为包含 `results` 的对象。
- 验收脚本内部读取新旧两种结构的地方同步更新。
- 小程序壳验收新增 `test-results/wechat-h5-premium-games/miniprogram-shell-verification.json`。
- 脚本开始时不删除旧报告；只有整套运行结束后才以临时文件原子替换正式报告。
- 失败时输出完整结果、退出码和失败摘要；旧成功报告不得被误认为本次成功。

最终交付阶段另生成 `DELIVERY-MANIFEST.json` 和 `SHA256SUMS.txt`，报告元数据不替代逐文件哈希。

## 7. 验收设计

### 7.1 自动验收

1. 主验收保持当前 16 个大厅/游戏/视口场景全部通过。
2. 小程序壳静态验收退出码为 0，并生成机读报告。
3. 无障碍验收预期从 16/28 提升到至少 25/28：
   - 三款键盘焦点通过。
   - 大厅和《五秒之后》减少动态通过。
   - 《五秒之后》《世界缝补师》横屏与超宽短屏通过。
   - 仅三款 `zoom-200` 允许保留失败。
4. 普通入口断言：
   - `window.__GAME_TEST__ === undefined`。
   - `?speed=40` 不改变自然速度。
5. 测试入口断言：
   - `?test=1&speed=20&mute=1` 仍能完成确定性胜负路径。
6. 音频断言只验证：
   - 首次手势前未创建/播放。
   - 静音状态不创建声音节点。
   - 不支持 Web Audio 时核心流程不报错。
   - 浏览器自动化不把“听到好听”作为机器结论。

### 7.2 人工浏览器检查

- 逐一检查三款开场 Tab 顺序、焦点框和开始后焦点恢复。
- 旋转到 844×390 和 1200×390，确认阻断层可读且不会推进局时。
- 开启系统减少动态效果，确认大厅过渡和《五秒之后》脉冲/抖动降低。
- 《世界缝补师》依次触发四类音效，确认音量、区分度、静音和重玩无叠音。

### 7.3 仍需微信真机执行

- iOS/Android 首次手势音频解锁、硬件静音和输出设备切换。
- 前后台、锁屏、电话打断与音频挂起恢复。
- 横竖屏、系统字号、安全区和外接键盘。
- 低端 Android 的帧率、内存和音频节点回收。

## 8. 风险与回退

- 焦点隔离若导致按钮不可操作：回退到统一 Tab 循环，但不得恢复背景焦点穿透。
- 横屏阻断若错误覆盖竖屏：以 `matchMedia` 和实际视口高度双条件复核，不修改游戏壳基础比例。
- 音频在某端不可用：无声降级，不回退游戏规则。
- 报告格式升级破坏既有读取器：验收工具在迁移期兼容旧数组，交付文档只认新对象格式。
- 200% CSS `zoom` 继续在报告中标记失败，不把工具期望改成 PASS；若公司要求 WCAG 200% 页面缩放，则单独启动 Canvas 缩放重构并将其提升为发布阻断。

## 9. 三角色评审结论

- 用户视角：平衡方案能优先消除焦点穿透、眩晕敏感和误横屏的直接障碍；短促、低音量的四类声音能强化缝合因果。
- 开发视角：方案不触碰 Canvas 坐标主链；音频首次手势解锁、单上下文和无声降级符合微信 WebView 风险控制。
- 商业视角：优先关闭影响可完成性的 P1，同时把 200% 缩放透明列为 P2；全量缩放重构应作为独立专项。

三个视角均通过，无硬伤分歧。

## 10. 完成定义

满足以下全部条件后，本专项才可关闭：

1. 代码、文档和自动验收均按本设计实现。
2. 主验收、小程序壳、短时性能和长时性能没有新增失败。
3. 无障碍达到 25/28，唯一允许失败为三款 200% CSS `zoom`。
4. 普通入口不能通过测试参数或测试接口改变规则。
5. 《世界缝补师》声音开关与真实声音能力一致。
6. 报告能追溯到固定 Git commit，最终交付清单含逐文件 SHA-256。
7. QA、README 与发布清单明确区分浏览器评审包和微信生产状态。
