# 开发者数据看板双页签改版设计

## 目标

将单游戏“数据看板”收敛为开发者可直接判断商店曝光转化和真实玩家质量的分析页面，降低页签和口径入口数量，并让时间区间与每项指标定义在当前上下文内可见。

## 信息架构

- 页面标题仍为“数据看板”，右侧只显示“数据更新至 2026-09-10 23:59”。
- 删除“数据口径”和“只读经营数据”。
- 页签只保留“曝光转化”“用户数据”，默认进入“曝光转化”。
- 原“订单明细”“收入与结算”不再作为看板页签展示；其底层样例与公共 API 暂时保留，供独立交易和财务模块继续使用。
- 历史持久化状态为 `overview`、`orders` 或 `revenue` 时统一迁移为 `conversion`，保证始终有一个页签激活。

## 筛选与时间控件

- 筛选栏维持在页签下方的原位置，桌面端保持单行，窄屏仅筛选栏内部横向滚动。
- “曝光转化”展示时间、商品类型、来源位置、地区；“用户数据”只展示时间、地区。平台固定显示“Mac”，右侧保留“重置”。
- 时间由快捷周期按钮和日期区间按钮组成。快捷项为昨日、今日、近 7 天、近 30 天、上月、本月、自定义。
- 点击任一时间按钮打开同一个浮层：左侧为快捷周期，右侧为连续两个月日历。月份支持前后切换；超过数据截止日的日期禁用。
- 昨日、今日、近 7 天、近 30 天、上月、本月按数据截止日计算并立即生效；起止日都计入。
- 自定义第一次点击确定开始日，第二次点击确定结束日；若第二次早于开始日，则以该日期重新开始选择。点击“应用”后生效，取消、点击遮罩或 Esc 不改变已生效区间。
- 自定义时间最长 180 个自然日，结束日不得晚于数据截止日；非法区间显示错误并禁用“应用”。
- 切换页签后保留已生效的时间和地区；商品、来源状态可保留，但在用户数据中隐藏且不参与计算。

## 曝光转化

- 保留从有效曝光、游戏卡点击、详情页访问、购买／领取点击、创建订单、成功获取到履约成功的七步漏斗。
- 保留曝光到成功获取总转化率、站内转化趋势和站内位置与访问来源。
- 移除原页面的销量、退款、拒付、预估收入和待结算卡片，避免与交易及财务模块重复。
- 时间、商品、来源、地区共同刷新漏斗、趋势和来源表，使用同一数据截止时间。

## 用户数据

- 指标为活跃玩家数、新增玩家数、次日留存、3 日留存、7 日留存、平均游戏时长。
- 活跃玩家按统计期内成功启动游戏的去重账号计；新增玩家按统计期内首次成功启动游戏的去重账号计；平均游戏时长按有效游戏会话总时长除以有效会话数计算。
- 留存按新增玩家 cohort 计算：分母为首日新增玩家，分子为对应自然日再次成功启动的玩家。尚未观察满 1／3／7 日的 cohort 显示“—”，不按 0 计算。
- 趋势支持活跃玩家和新增玩家切换，日期和地区变化时同步刷新；平台固定 Mac。

## 指标定义

- 每个可见指标名称旁显示问号按钮，不再提供整页口径弹窗。
- 定义内容至少包括指标定义、计算或分子分母、去重维度、统计时点；留存额外说明 cohort 和数据成熟条件。
- 鼠标悬浮、键盘聚焦或点击问号均可查看；点击后固定显示，再次点击、点击其他问号、点击外部或按 Esc 关闭。
- 问号按钮使用 `aria-describedby` 关联 `role="tooltip"`，不依赖浏览器 `title`。

## 响应式与异常

- 1440px 下筛选项单行展示；390px 下页面根节点不横向溢出，筛选栏可横向滚动，Mac 与重置始终可见。
- 查询无数据时保留当前筛选并显示空态；查询失败时保留旧数据和上下文。
- 双日历在窄屏中改为单月纵向浏览，但快捷项、起止日和操作按钮完整可用。

## 验证

- 自动化验证只存在两个页签、旧状态迁移、页头精简、筛选作用域、全部时间快捷项和双日历选择。
- 覆盖取消、Esc、未来日期、超过 180 天、跨月选择、页签切换保持条件。
- 遍历曝光与用户指标，验证均有可访问的问号定义。
- 验证用户指标随时间和地区变化，留存始终为 0%—100% 或“—”。
- 验证 1440px 和 390px 布局及页面根节点无横向溢出。
