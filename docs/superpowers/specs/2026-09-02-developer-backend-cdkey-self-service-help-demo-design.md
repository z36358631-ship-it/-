# 开发者后台 CDKEY 自助发行、首次介绍与帮助中心设计规格

## 1. 目标与结论

在现有开发者后台一期 37 个业务路由内补齐发行方自助 CDKEY 能力、第三方渠道 API 说明、首次入驻介绍和帮助中心，同时修复顶栏文字对比度、左侧导航选中态与页面 Tab 不清晰的问题。

本次采用用户确认的方案 A：**不新增业务路由或页面编号**。新增能力分别并入 `P01-01 受邀账号登录页`、`P02-01 游戏商品与供给状态页`和全局后台壳；现有 PRD、Figma 与 Demo 必须同步，不能继续使用旧口径交付。

## 2. 用户、问题与现有方式

- 目标用户：已签约并获得游戏发行授权的受邀发行方，以及盖世游戏平台内部发行运营。
- 当前问题：发行方只能查看供应状态，不能为自身已授权游戏自助创建 Key 批次或渠道 API 凭据；第三方渠道缺少可执行的接口说明；首次进入后台时不清楚完整发行流程；遇到额度、渠道或凭据问题时没有统一帮助入口。
- 现有方式：通过平台运营线下开通、供应商 API 或受控直接供给处理；介绍和问题排查依赖人工沟通。
- 目标方式：平台运营预授权并配置风控边界，发行方在授权范围内自助操作；超范围事项仍联系平台运营处理。

## 3. 来源与冲突裁决

| 来源 | 采用内容 | 不采用内容 |
|---|---|---|
| 用户本轮确认 | 发行方自助生成 Key、创建第三方渠道 API、提供接口说明；介绍并入入驻第一步；帮助中心包含 FAQ 和联系我们 | 不新增独立介绍 Tab 或业务路由 |
| 用户提供的 Steam Direct 截图 | “先介绍流程与准备事项，再开始入驻”的信息顺序 | Steamworks 的收费、税务、银行、SDA 和公众注册流程 |
| 最新开发者后台 Figma | 现有深色导航、浅色工作区、页面字段和 37 页骨架 | 截图中低对比度文字、缺少导航选中态和不明显的 Tab |
| 当前 HTML Demo | 现有角色、路由、五种通用状态和内存交互机制 | 旧的只读 CDKEY 供给范围 |
| 当前 CDKEY PRD | 商品、SKU、供应来源、异常和审计基础 | “只能供应商 API、发行方不能自助生成”的旧边界 |

### 3.1 Key 类型边界

“平台生成 Key”仅指由盖世兑换服务校验并授予已配置权益的盖世平台授权码。Steam、Epic、GOG 等外部平台 Key 不能由盖世自行生成，继续使用外部平台申请、供应商 API 或受控导入；页面必须明确区分来源，避免把平台兑换码误认为 Steam Key。

## 4. 页面与导航设计

### 4.1 `P01-01`：首次入驻第一步

介绍内容放在受邀开发者首次进入的第一屏，不单独创建 Tab 或页面。页面顺序为：

1. 盖世发行合作说明：平台解决什么问题、谁可以使用、一期只面向受邀合作方。
2. 四步流程：完成厂商与游戏资料 → 配置商品及 CDKEY → 上传包体并通过测试发布 → 提交精准投放并查看发行数据。
3. 准备事项：受邀账号、公司与授权资料、首款签约游戏资料、拟合作渠道和技术联系人。
4. 点击“开始入驻”后进入现有受邀账号登录/激活区域；不新增公众注册入口。

### 4.2 `P02-01`：四个任务 Tab

`P02-01` 保持同一路由，在页面标题下增加按钮式 Tab：

| Tab | 主要内容 | 关键动作 |
|---|---|---|
| 商品与供给 | 复用现有商品、SKU、供应来源和异常摘要 | 查看详情、进入已有异常处理 |
| Key 批次 | 批次列表、剩余配额、已用数量、状态、来源和审计摘要 | 创建批次、一次性下载、暂停或作废未发放库存 |
| 渠道 API | 渠道白名单、凭据末四位、授权游戏、有效期和状态 | 创建、轮换、暂停、撤销凭据 |
| 接口说明 | 接入步骤、鉴权、接口目录、字段、示例、错误码与联调说明 | 复制示例、定位章节、查看 FAQ |

四个 Tab 上方固定展示当前游戏的授权状态、剩余 Key 配额、可用渠道和发行暂停原因。任一限制导致动作不可用时，页面必须直接显示不可操作原因和“查看帮助”入口。

### 4.3 全局帮助中心

顶栏增加“帮助中心”入口，进入后台壳内的帮助内容状态；不计入 37 个业务路由。返回后恢复原路由、Tab 和滚动位置。

- FAQ：如何创建 Key 批次、额度不足、渠道未开通、Secret 丢失、重复请求、凭据暂停、Key 作废、外部平台 Key 与盖世平台 Key 的区别。
- 联系我们：展示后台配置的发行支持名称、服务时间和联系渠道；未配置时显示“请联系对接的盖世发行运营”，不得虚构邮箱、电话或工单能力。
- Demo 只展示和切换内容，不向真实人员发送消息或创建工单。

## 5. CDKEY 自助发行规则

### 5.1 权限模型

- 发行方：只能操作自己所属签约主体下已授权且状态正常的游戏、SKU 和渠道；可以创建 Key 批次及渠道凭据，不能调整自己的授权范围、配额或渠道白名单。
- 平台发行运营：配置游戏发行权限、Key 配额、有效期上限、渠道白名单和暂停状态；可以暂停、撤销和审计，但不需要代替发行方逐批手工发码。
- 第三方渠道：只能通过已分配凭据调用明确授权的游戏和 SKU，不能进入开发者后台或读取其他渠道数据。

每次服务端请求均按“签约发行方 × 已授权游戏 × SKU × 渠道白名单 × 剩余配额 × 有效期 × 启停状态”重新校验；前端禁用状态不能替代服务端权限判断。

### 5.2 Key 批次

创建字段为批次名称、游戏、SKU、Key 来源、用途、渠道、数量和有效期。Key 来源只有：

- `gamehub_generated`：盖世平台兑换码，由盖世兑换服务校验并授予配置权益。
- `external_imported`：外部平台或供应商提供的 Key，只允许受控导入或 API 同步，不由盖世生成。

批次状态为生成中、可用、已暂停、已耗尽、已过期、已作废和生成失败。生成成功后的明文只允许一次性下载；关闭或离开后仅展示批次号、数量、已分配数、未分配数、来源、渠道、状态和审计记录。作废只作用于尚未分配的 Key，已分配记录保持可追溯。

### 5.3 渠道 API 凭据

创建凭据必须选择白名单渠道、授权游戏/SKU、配额和有效期。`client_secret` 只在创建或轮换成功时明文显示一次；以后只显示凭据名称、`client_id`、Secret 末四位、授权范围、创建时间、最近调用时间和状态。支持轮换、暂停与撤销，所有动作写入审计日志。

## 6. CDKEY 接口说明草案

Demo 中展示产品级接口草案，不连接真实服务：

| 接口 | 方法与路径 | 用途 |
|---|---|---|
| 申请一个 Key | `POST /openapi/v1/cdkeys/allocate` | 按渠道订单为已授权游戏/SKU 分配一个 Key |
| 查询分配结果 | `GET /openapi/v1/cdkeys/allocations/{request_id}` | 查询处理状态、渠道订单和掩码后的 Key 信息 |
| 确认已交付 | `POST /openapi/v1/cdkeys/allocations/{request_id}/confirm` | 渠道确认已向用户交付，形成审计闭环 |

鉴权采用 `client_id + HMAC-SHA256`，请求头包含时间戳、随机数和签名，Secret 不进入 URL。申请接口必填 `request_id`、`channel_order_id`、`game_id`、`sku_id`；同一 `request_id` 必须幂等返回同一分配结果，禁止重复扣减库存。错误码至少包括无权限、签名失败、时间戳过期、渠道暂停、游戏未授权、配额不足、无可用 Key、重复订单冲突和服务异常。

生产路径、签名串拼接方式、时间窗口和是否需要联调环境仍需研发/安全评审，Demo 不把草案冒充已上线接口。

## 7. Demo 交互与状态

沿用 `default`、`loading`、`empty`、`error`、`permission` 五种通用状态，并增加页面内存中的业务状态：

- 首次入驻介绍：未开始、已阅读、已进入登录；刷新恢复演示初始值。
- Key 批次：可创建、额度不足、渠道未授权、发行暂停、生成中、成功、失败、已暂停、已作废。
- 渠道 API：未创建、创建成功且 Secret 首次显示、再次进入掩码、已轮换、已暂停、已撤销。
- 接口说明：目录切换、复制示例、错误码筛选；复制仅写入当前浏览器剪贴板。
- 帮助中心：FAQ 展开/收起、返回原页面；联系区域不产生外部副作用。

Demo 不读取真实文件、不生成可用 Key、不创建真实凭据、不访问远程接口；所有示例值必须显式标注为演示数据。

## 8. 视觉修复

- 顶栏浅色区域使用深色主文字和足够对比度的次级文字；“正式环境”标签不得使用接近背景的浅色描边/文字。
- 左侧导航当前项增加品牌色竖线、清晰选中底色和高对比度文字，并设置 `aria-current="page"`；悬停、键盘焦点和禁用态分开表现。
- 页面 Tab 使用至少 36px 高的按钮式导航；当前项有明确底色、边框和文字差异，不只依赖细下划线。
- 保持现有深色侧栏、浅色工作区和品牌青色体系；不重做与本次无关的卡片、表格和流程。

## 9. 异常与边界

- 未授权或越权访问不返回游戏、渠道、额度或凭据是否存在。
- 配额并发消耗以服务端原子校验为准；失败不生成半批次或重复分配。
- 凭据暂停/撤销后，新请求立即拒绝；历史审计和已交付记录不删除。
- 下载失败可在一次性有效窗口内重试；窗口结束后不能再次查看明文，需按运营规则作废未发放库存后重建。
- 合作终止、退款、结算、渠道违规归责和已发 Key 的跨系统撤销只写入帮助说明与待确认边界，不在本轮 Demo 模拟真实处理。

需要同步：

2. `prd/发行平台专项/开发者后台PRD/02-游戏商品与CDKEY供给管理PRD.md`

验收条件：

- 37 个原业务路由仍唯一且可访问，模块数量保持 `9／6／13／9`。
- P01-01 首屏包含入驻介绍且没有公众注册入口；P02-01 四个 Tab 均可切换并保持清晰选中态。
- Key 生成、额度不足、渠道未授权、发行暂停、Secret 一次展示、掩码、轮换、暂停和撤销均可演示。

- 帮助中心可达、可返回并覆盖约定 FAQ；不会发送真实消息。
- `1440×900` 与 `1280×800` 下无裁切、遮挡和横向溢出；截图指出的顶栏、侧栏和 Tab 可读性问题消失。
- Demo 无外部脚本、字体、图片、接口或 iframe；控制台无错误。

## 11. 明确不做

- 不新增业务路由、页面编号、公众注册、组织成员、复杂权限、自动结算或真实渠道联调。
- 不允许盖世生成 Steam、Epic、GOG 等外部平台 Key。
- 不让平台运营承担每次手工生成或发放 Key。
- 不在普通列表、日志、埋点或再次进入页面时展示完整 Key 或 Secret。
