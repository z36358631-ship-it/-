# Mac 租号分档定价同步设计

## 1. 目标与范围

本次只调整现有 Mac 租号业务的定价与相关展示，不重做页面结构。范围包含：

- C 端租号发现、游戏详情、确认订单、续租和重新租用。
- B 端租号商品、版本、成本与价格配置。
- 服务端价格同步、订单锁价、永久资格成本封顶。
- PRD 版本信息、套餐规则、异常处理、埋点和运营准备。

一期仅上线 Mac，国内与海外共用交互；货币、Steam 原价和永久售价按用户所在地区返回。客户端不展示供应商取号成本或成本档。

## 2. 套餐结构

前台套餐统一为：

1. 时租：用户可选择 2～24 小时，24 小时仍按时租处理。
2. 周租：固定 7 天。
3. 永久：正式上线，表示长期使用共享账号池的资格，不表示永久独占账号。

日租从新订单中移除。历史日租订单继续按原快照履约、展示和售后。

## 3. 时租与周租价格

供应商成本分为低、标准、高三档，C 端只展示最终售价。

| 时长 | 低成本档 | 标准成本档 | 高成本档 |
|---:|---:|---:|---:|
| 2小时 | ¥4 | ¥6 | ¥9 |
| 6小时 | ¥7 | ¥9 | ¥12 |
| 12小时 | ¥10 | ¥12 | ¥15 |
| 18小时 | ¥12 | ¥14 | ¥17 |
| 24小时 | ¥14 | ¥16 | ¥19 |
| 周租 | ¥18 | ¥20 | ¥23 |

2～24 小时的每个整数小时都由后台保存最终价格。首次建档时根据相邻锚点线性生成中间价，四舍五入至 0.1 元，运营可逐小时调整；客户端只读取对应小时的最终价，不自行推导。

所有游戏的时租和周租支持首单 5 折，永久不参与。续租、重新租用和普通非首单均按下单时标准价结算。

## 4. 永久价格

永久售价按用户所在地区的 Steam 非促销原价计算：

```text
永久售价 = Steam 非促销原价 × 20%～30%
默认系数 = 25%
```

永久售价不得低于周租售价。永久订单使用供应商账号时，累计取号成本不超过该订单实付金额的 60%；下一次取号将超过上限时切换自建账号池。

## 5. 成本同步与锁价

- 低成本档：取号成本不高于 ¥3。
- 标准成本档：取号成本高于 ¥3 且不高于 ¥5。
- 高成本档：取号成本高于 ¥5 且不高于 ¥8。
- 取号成本高于 ¥8：停止自动更新售价，优先切换自建账号；无可用自建账号时进入人工评估并暂停该 SKU 新订单。
- 供应商成本每日最多同步一次，同步后生成新的价格版本。
- 用户进入确认订单时获取最新售价；提交订单时再次校验。
- 订单创建成功后保存标准价、优惠、实付价、价格版本、成本档和锁价时间，租期内不跟随成本变化。
- 续租和重新租用按提交时最新价格重新计价，并生成新的价格快照。

## 6. Demo 表现

- 至少用低、标准、高成本档各一款游戏展示不同最低时租价。
- 确认订单只显示时租、周租、永久三个套餐。
- 首单选择时租或周租时，订单金额旁显示“首单5折”和划线标准价。
- 选择永久时不显示首单标签或划线价。
- B 端版本价格展开区展示内部成本档、当日取号成本、成本同步时间、价格版本、时租锚点、周租价和永久价。
- 新建商品支持填写成本、五个时租锚点、周租价、Steam 非促销原价与永久系数。

## 7. 异常与兼容

- 价格版本变化：刷新订单金额并要求用户再次确认。
- 成本同步失败：沿用上一有效价格版本并告警，不向客户端下发半成品价格。
- 成本高于 ¥8：SKU 暂停自动定价；无自建库存时停止新订单，历史订单不受影响。
- 永久售价低于周租：禁止发布。
- 历史日租订单：保留原套餐文案、金额和到期时间，不允许新建同类订单。
- 弱网或价格接口失败：禁止提交订单，提示重试。

## 8. 方案快速评审

- 用户视角：通过。成本档只用于后台，用户只需要比较当前游戏的时租、周租和永久价格。
- 开发视角：通过。客户端读取逐小时价格表，避免不同端重复实现插值并产生金额误差。
- 商业视角：通过。引流套餐和盈利套餐分工清楚，成本异常及永久60%封顶能够限制敞口。

- 订单锁价、续租重定价和历史订单兼容规则无冲突。
