# 盖世游戏「适合本机」WebView 页面设计规格

**日期：** 2026-08-05  
**状态：** 待书面确认  
**交付形态：** App 内嵌单页 WebView，横竖屏自适应

## 1. 产品结论

页面不做兼容性数据库，也不区分普通用户和高级用户。所有信息对所有用户可见，通过信息层级控制阅读顺序：先给结论和行动，再展示证据、评价与完整配置。

页面同时解决两件事：

1. 用户不知道玩什么时，直接找到当前设备可以玩的游戏。
2. 用户已有目标游戏时，搜索后得到能否运行、预计表现和可执行方案。

页面一句话定义：

> 打开就能看到这台设备能玩的游戏；搜索任意游戏，就能知道是否可玩以及应该使用什么方案。

## 2. 用户与问题

**目标用户：** 不理解 GPU、驱动、Wine、DXVK 等术语，只想尽快玩到游戏的盖世游戏用户。

**当前问题：**

- 用户不知道当前设备可以稳定运行哪些 PC 游戏。
- 用户搜索到想玩的游戏后，不知道能否运行、表现如何。
- 游戏需要调整时，原始配置无法转化为用户能照做的步骤。
- 原始评价、FPS 和配置缺少综合结论，用户仍需自行判断。

## 3. 范围

### 3.1 本期包含

- WebView 自动接收当前设备、GPU、Android 版本和盖世版本。
- 默认展示当前设备已验证可玩的游戏。
- 搜索全部游戏并查看当前设备兼容结论。
- 四种用户结论：可直接玩、调整后可玩、暂不建议、数据不足。
- 游戏详情展示预计表现、推荐方案、执行步骤、真实运行数据、玩家评价、完整配置。
- 横屏和竖屏自适应。
- 模拟数据与真实数据共用同一标准数据结构。
- 对外暴露设备注入、数据注入、直接打开游戏详情和使用方案的接口。

### 3.2 本期不包含

- 登录、会员或付费限制。
- 用户分级或“高级模式”。
- 评价提交、点赞、举报和后台治理。
- 驱动下载及安装。
- 自动修复启动失败。
- 云游戏兜底；国内和海外均按本地运行能力给结论。
- 在页面内编辑底层配置。
- 复制 GameNative 的品牌、文案、视觉资产或源代码。

## 4. 设计原则

1. **结论优先：** 先回答能不能玩，再解释原因。
2. **行动优先：** “调整后可玩”必须给出按顺序执行的 1～3 步。
3. **当前设备优先：** 同设备证据优先，同 GPU 次之，其他设备只作补充。
4. **全部可见：** 评价、证据和完整配置均可展开，无权限差异。
5. **人话表达：** 默认不要求用户理解 GPU、驱动和模拟器术语。
6. **不错误承诺：** 设备上下文未就绪时不输出兼容性结论。
7. **单一数据模型：** 默认列表、搜索结果和详情页读取同一份标准模型。

## 5. 页面结构

页面只有一个路由和两种视图，不设置“找游戏／查游戏”Tab。

### 5.1 默认发现视图

从“适合本机”入口进入，页面依次展示：

1. 顶部返回、标题“适合本机”。
2. 搜索框“搜索想玩的游戏”。
3. 当前设备信息：“一加 13 · Android 15”，次级信息显示芯片和盖世版本。
4. 标题“这台设备可以玩的游戏”及游戏数量。
5. 游戏卡片列表。

游戏卡片字段：

- 游戏封面、名称、来源平台。
- 可直接玩或调整后可玩标签。
- 预计 FPS 区间及流畅度描述。
- 当前设备或同 GPU 的成功运行次数。
- 点击整张卡片进入详情。

默认列表不展示“暂不建议”和“数据不足”的游戏，避免把发现页变成不可玩清单；用户主动搜索时仍可看到这两类结果。

### 5.2 搜索状态

- 输入关键词后在当前页面实时更新结果。
- 支持中文名、英文名和常见别名。
- 结果按当前设备匹配程度排序：可直接玩、调整后可玩、暂不建议、数据不足。
- 搜索结果不隐藏任何状态。
- 无结果显示“没有找到这款游戏”，提供清除搜索操作。
- 清空关键词恢复默认可玩列表。

### 5.3 游戏详情视图

点击卡片，或通过 `game_id` 从游戏详情页进入时，展示：

1. 游戏封面、名称、来源平台。
2. 当前设备兼容结论和一句话原因。
3. 预计 FPS、流畅度和数据更新时间。
4. 推荐运行方案。
5. 按顺序执行的 1～3 步。
6. “使用推荐方案”主操作。
7. 当前设备真实运行数据。
8. 常见问题及影响。
9. 玩家评价。
10. 可展开的完整配置。

所有模块对所有用户开放。完整配置默认收起，仅为保证先读结论，不代表用户权限差异。

## 6. 四种结论

### 6.1 可直接玩

**含义：** 当前设备存在稳定运行证据，默认或推荐方案不需要用户额外处理。  
**展示：** 绿色标签，文案“当前设备已验证，可直接运行”。  
**行动：** 使用推荐方案。

### 6.2 调整后可玩

**含义：** 游戏可以运行，但需要使用指定方案，或存在可规避的问题。  
**展示：** 金色标签，并直接列出执行步骤。  
**行动：** 使用推荐方案；页面不得只展示完整配置。

### 6.3 暂不建议

**含义：** 当前设备存在稳定性或性能硬伤，不建议下载后反复试错。  
**展示：** 红色标签，必须同时说明具体原因，例如“当前设备多次启动失败”或“实测帧率低于 20 FPS”。  
**行动：** 返回可玩游戏列表，不提供云游戏承诺。

### 6.4 数据不足

**含义：** 暂无足够的当前设备或同 GPU 有效样本，不能等同于不兼容。  
**展示：** 灰色标签，文案“暂时无法判断，不代表不能运行”。  
**行动：** 可以查看已有少量记录和完整配置，但不输出确定承诺。

## 7. 结论计算口径

本规格先固定可执行的 V1 口径，真实服务端可使用相同输出状态：

- **有效运行：** 会话时长不少于 10 分钟，且有正常 FPS 数据或明确启动成功结果。
- **可直接玩：** 官方验证通过；或同设备有效运行不少于 5 次、FPS 中位数不低于 30、重大问题比例低于 20%。
- **调整后可玩：** 存在已验证推荐方案，同设备或同 GPU 有效运行不少于 3 次，使用该方案后 FPS 中位数不低于 24，且无高比例启动失败。
- **暂不建议：** 同设备重大启动失败比例达到 50%，或 FPS 中位数低于 20，或已有明确官方不兼容结论。
- **数据不足：** 不满足以上任一结论，且没有官方结论。

评分、超短会话和异常 FPS 不可单独决定兼容性；同一用户的重复短会话需在服务端去重或降权。

## 8. 信息翻译

| 原始字段 | 默认展示 |
|---|---|
| GPU exact match | 与你的设备匹配 |
| GPU family match | 同类设备已验证 |
| Avg FPS 37 | 预计 30～40 FPS，基本流畅 |
| 128 successful runs | 当前设备已有 128 次成功运行 |
| Config | 推荐运行方案 |
| No result | 暂无足够数据 |
| no_graphics | 部分用户遇到有声音无画面 |

完整配置展开后可以显示原始参数名，但必须隐藏本地文件路径、账号信息和其他无助于复现的字段。

## 9. 设备上下文

设备上下文有三种状态：

- `loading`：等待 App 注入，显示骨架或“正在识别当前设备”，不展示兼容结论。
- `ready`：展示当前设备和兼容数据。
- `unavailable`：显示“暂时无法识别设备”，仅提供重试；不使用默认设备伪造结果。

用户可以点击设备信息查看已识别的型号、GPU、Android版本和盖世版本，用于确认推荐环境。V1 不提供手动切换设备，避免引入设备库和错误选择。

## 10. 使用推荐方案

- 页面点击“使用推荐方案”时，优先调用 App 注入的 `applyPlan` 接口。
- 没有 App 接口的本地 Demo 环境中，复制一份人类可读的方案摘要并显示按钮状态变化。
- 页面不直接修改设备文件，不静默安装驱动。
- 方案应用失败时保留页面内容并显示“方案未应用，请重试”。

## 11. 横竖屏

### 11.1 竖屏

- 单列页面内容。
- 游戏列表为两列卡片。
- 详情内容纵向排列。
- 主操作固定在详情内容中，不遮挡系统返回手势区域。

### 11.2 横屏

- 游戏列表增加至四列或更多，保持卡片最小可读宽度。
- 详情页左侧为封面和结论，右侧为推荐方案与证据。
- 所有模块仍按同一阅读顺序，不生成另一套详情数据和交互状态。

## 13. 页面接口

页面暴露统一入口，后续部署只替换数据适配层：

```js
window.GameHubCompatibility.setContext(context);
window.GameHubCompatibility.setGames(games);
window.GameHubCompatibility.openGame(gameId);
window.GameHubCompatibility.setContextUnavailable();
```

页面使用推荐方案时调用：

```js
window.GameHubBridge?.applyPlan(JSON.stringify({ gameId, planId, settings }));
```

从游戏详情页进入时支持 URL 参数：

```text
?game_id=steam_1245620
```

## 14. 异常状态

| 场景 | 处理 |
|---|---|
| 等待设备信息 | 显示识别中，不输出结论 |
| 设备识别失败 | 显示失败原因和重试 |
| 游戏列表加载失败 | 保留设备信息，显示重新加载 |
| 搜索无结果 | 显示没有找到并支持清空搜索 |
| 详情数据缺失 | 展示数据不足，不推断不兼容 |
| 推荐方案应用失败 | 显示重试，不改变原始配置 |
| 封面加载失败 | 使用内置渐变封面 |
| 横竖屏切换 | 保留搜索词、当前游戏和展开状态 |

## 15. 模拟内容

Demo 至少覆盖以下状态：

- 可直接玩：黑神话：悟空、哈迪斯、只狼。
- 调整后可玩：艾尔登法环、赛博朋克2077、极限竞速：地平线5。
- 暂不建议：荒野大镖客：救赎2。
- 数据不足：星空。
- 搜索无结果、设备识别中、设备识别失败。

## 16. 指标

主指标不是查询次数，而是用户看到结果后是否更快进入有效游戏体验：

- 默认列表游戏点击率。
- 搜索后进入游戏详情率。
- 推荐方案使用率。
- 使用方案后的启动成功率。
- 使用方案后的有效运行率（会话不少于 10 分钟）。
- 错误结论率和用户负面反馈率。

## 17. 验收标准

- 无设备上下文时不出现任何确定兼容结论。
- 默认页面能在 3 秒内让用户理解“这些游戏适合当前设备”。
- 搜索任意模拟游戏后能看到四种结论之一。
- “调整后可玩”必须展示 1～3 个顺序步骤和主操作。
- “暂不建议”必须给具体原因，不使用含糊文案。
- “数据不足”不得显示为“不兼容”。
- 所有用户均可展开评价、证据和完整配置。
- 竖屏 390×844 与横屏 874×402 下无横向溢出，核心操作可见。
- 横竖屏切换不丢失搜索词、当前详情和展开状态。
- HTML 无外部 CDN 依赖，模拟数据可离线演示。
- 模拟数据与后续真实数据均通过标准适配层进入 UI。

## 18. 三视角快速审查及处理

- **用户视角：** “调整后可玩”不能只给参数；规格已增加 1～3 步和明确主操作。“暂不建议”必须说明原因。设备识别失败时不输出错误推荐。
- **开发视角：** 已增加设备上下文 `loading / ready / unavailable` 三态；列表、搜索与详情共用标准模型；横竖屏只重排，不复制状态。
- **商业视角：** 两条用户路径共用同一列表和详情，不拆成两套系统；本期不做反馈、治理和驱动下载。主指标绑定方案使用后的启动成功与有效运行，而非查询流量。
