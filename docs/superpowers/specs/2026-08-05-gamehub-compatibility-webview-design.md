# 盖世游戏「游戏兼容库」WebView 设计规格

**日期：** 2026-08-05

**更新：** 2026-08-06

**状态：** 已确认

**交付：** App 内嵌单页 WebView，支持横竖屏

## 1. 产品定义

产品是公开的“游戏 × GPU × 运行配置”兼容库，不是“适合本机”的重复版本。

用户可以：

1. 搜索游戏，查看哪些 GPU 可以运行、表现如何、有哪些配置。
2. 搜索 GPU，查看该 GPU 已验证可玩的游戏。
3. 在配置列表下载配置；配置与当前设备匹配时下载后直接应用。配置详情仅查看内容，不执行下载或应用。

当前设备只用于“只看本机”和应用前校验，不限制用户浏览其他 GPU、游戏和配置。

## 2. 核心关系

```text
游戏版本 × 来源平台 × GPU × 设备 × Android版本
× 盖世版本 × 内核版本 × 配置版本 → 实际运行结果
```

领域对象拆为四类：

- `Game`：游戏、版本、来源平台。
- `GPU`：GPU 名称、厂商、架构和代表设备。
- `CompatibilityRecord`：某游戏在某 GPU 和软件环境下的运行结论与证据。
- `ConfigPackage`：可查看、下载和应用的版本化运行配置。

## 3. 本期范围

### 3.1 包含

- “按游戏查”和“按 GPU 查”双入口。
- 游戏名、英文名、别名和 GPU 名称搜索。
- 游戏详情的推荐 GPU、最低已验证 GPU、全部 GPU 运行记录。
- GPU 详情的已验证游戏列表。
- 首页分级筛选：横屏常驻目录、竖屏全屏双栏面板。
- 四种运行结论和四级证据等级。
- 配置列表、配置详情、配置下载和匹配设备后的直接应用。
- “只看本机”快捷筛选。
- App 自动注入当前设备环境。
- 数据加载、空数据、失效数据和 Bridge 失败恢复。
- 横竖屏适配与状态保留。

### 3.2 不包含

- 云游戏兜底。
- 登录、会员或付费墙。
- 用户评价提交、点赞、举报及后台治理。
- 驱动下载、设备跑分和硬件购买推荐。
- 手动编辑配置文件。
- 将其他 GPU 的配置强制应用到当前设备。

## 4. 页面结构

WebView 内包含四种视图，共用同一数据状态：

1. 游戏兼容库首页。
2. 游戏详情。
3. GPU 详情。
4. 配置详情。

### 4.1 游戏兼容库首页

顶部展示：

- 返回。
- 标题“游戏兼容库”。
- 主 Tab：“按游戏查”“按 GPU 查”。
- 搜索框，根据 Tab 显示“搜索游戏”或“搜索 GPU”。
- 筛选入口、已选数量和清空入口。

“按游戏查”展示：

- “只看本机”开关，默认关闭。
- 筛选目录：“GPU 型号”“运行表现”“游戏平台”“配置状态”。
- 游戏列表，显示封面、来源平台、已验证 GPU 数量和配置数量。
- 开启“只看本机”后，仅展示当前 GPU 有运行记录的游戏，并显示本机结论。
- “运行表现”必须基于已选 GPU 判断；未选择 GPU 时不可选，并提示先选择 GPU，避免把其他 GPU 的结论误解为本机结论。

“按 GPU 查”展示：

- 筛选目录：“GPU 厂商”“GPU 系列”“性能档位”“验证状态”。
- GPU 列表，显示名称、厂商、已验证游戏数、可直接玩数量和配置数量。
- 当前 GPU 显示“本机”标识，但不固定在首屏、不限制其他 GPU 浏览。

筛选交互：

- 横屏：左侧常驻筛选目录；点击目录后，二级多选面板覆盖在结果区左侧，页面结构参照用户提供的桌面筛选样式。
- 竖屏：结果页只保留“筛选”入口；点击后打开全屏双栏面板，左侧为短分类，右侧为选项，底部固定“清空”和“查看 X 项”。
- 横竖屏共用同一份筛选状态和过滤逻辑，不维护两套数据。
- “按游戏查”和“按 GPU 查”的筛选条件相互独立；切换 Tab 后恢复各自已选项。
- 选项支持多选，选择后即时计算结果数量；重复点击不重复计数。
- 关闭面板或旋转屏幕后保留搜索词、筛选条件和当前 Tab。
- 无结果时保留当前条件，显示“暂无符合条件的结果”，支持清空全部筛选。

### 4.2 游戏详情

依次展示：

1. 游戏封面、名称、来源平台和版本。
2. 推荐 GPU：有高质量运行证据且综合表现最佳的 GPU。
3. 最低已验证 GPU：已有有效运行证据的最低档 GPU，不写成理论最低支持。
4. GPU 类型筛选。
5. 全部 GPU 运行记录。
6. 当前选中 GPU 的可用配置。

GPU 运行记录展示：

- GPU 名称。
- 运行结论。
- 预计 FPS。
- 证据等级。
- 有效样本。
- 配置数量。

点击记录后在当前详情中切换对应配置列表，不增加中间页。

### 4.3 GPU 详情

依次展示：

1. GPU 名称、厂商、架构和代表设备。
2. 已验证游戏数、可直接玩数量和配置数量。
3. 已验证游戏列表。

游戏记录展示游戏名、来源平台、运行结论、预计 FPS、证据等级和配置数量。点击后进入游戏详情并默认选中当前 GPU。

### 4.4 配置列表

每条配置展示：

- 配置名称和版本。
- 适用游戏版本、GPU、Android、盖世版本和内核版本。
- 预计 FPS、验证人数、更新时间、文件大小和下载量。
- “查看配置”。
- 下载操作。

操作规则：

| 配置与当前设备关系 | 操作 |
|---|---|
| GPU 和关键环境匹配 | 下载并应用 |
| GPU 不匹配 | 下载配置；保存到盖世配置库，不允许应用 |
| 数据或文件失效 | 暂不可用，可重新加载 |

### 4.5 配置详情

配置详情直接展示，不把关键内容全部折叠：

- 适用环境。
- 预计表现和证据等级。
- 推荐设置。
- 1～3 个使用步骤。
- 已知问题和解决方法。
- 完整配置参数。
- 配置版本、验证人数、更新时间、文件大小和下载量。

配置详情为纯查看页面：

- 不展示“下载并应用”“下载配置”或其他执行按钮。
- 不调用下载、应用及其结果回调。
- 下载和应用只允许从上一层配置列表发起。
- 返回后保留原游戏、GPU 和配置列表状态。

## 5. 运行结论与证据

### 5.1 运行结论

| 结论 | 含义 |
|---|---|
| 可直接玩 | 当前环境已有稳定运行证据 |
| 调整后可玩 | 使用指定配置后可稳定运行 |
| 暂不建议 | 当前环境存在明确启动或性能问题 |
| 暂无结论 | 样本不足或关键环境不匹配 |

### 5.2 证据等级

| 等级 | 含义 |
|---|---|
| 当前设备已验证 | 当前设备和关键软件环境匹配 |
| 同 GPU 已验证 | GPU 与关键软件环境匹配 |
| 同类 GPU 参考 | 仅 GPU 系列或架构接近 |
| 样本较少 | 样本不足或关键字段缺失 |

结论和证据分开显示，例如：`调整后可玩｜同 GPU 已验证`。

## 6. 推荐 GPU 口径

- 推荐 GPU 必须存在有效配置和稳定运行证据。
- 按结论、FPS、有效玩家数和更新时间综合排序。
- 最低已验证 GPU 只代表存在有效记录，不承诺更低型号无法运行。
- 无足够证据时显示“暂无推荐 GPU”，不根据型号大小猜测。

## 7. 配置下载与应用

配置不导出为普通系统文件，统一进入盖世配置库。

### 7.1 匹配当前设备

1. 用户点击“下载并应用”。
2. WebView 调用 App Bridge 下载配置。
3. App 校验 GPU、游戏版本、Android 版本、盖世版本和内核版本。
4. 校验通过后应用配置。
5. App 回传成功或失败结果。

### 7.2 不匹配当前设备

1. 用户可查看和下载配置。
2. 配置保存到盖世配置库。
3. 页面明确提示适用 GPU 与当前 GPU 不同。
4. 不调用应用接口。

### 7.3 状态

- `idle`：显示“下载并应用”或“下载配置”。
- `loading`：显示“正在下载配置”。
- `success`：显示“配置已应用”或“已保存到配置库”。
- `error`：显示失败原因和“点击重试”。
- 8 秒未收到 App 回调：按失败态显示“操作超时，点击重试”。

## 9. WebView 接口

```js
window.GameHubCompatibility.setContext(context);
window.GameHubCompatibility.setCatalog({ games, gpus, records, configs });
window.GameHubCompatibility.setCatalogLoading();
window.GameHubCompatibility.setCatalogError();
window.GameHubCompatibility.openGame(gameId, gpuId);
window.GameHubCompatibility.openGpu(gpuId);
window.GameHubCompatibility.openConfig(configId);
window.GameHubCompatibility.setActionResult({ requestId, configId, status, message });
```

App Bridge：

```js
window.GameHubBridge?.downloadAndApplyConfig({ requestId, configId, gameId, gpuId });
window.GameHubBridge?.downloadConfig({ requestId, configId, gameId, gpuId });
window.GameHubBridge?.reloadCompatibilityCatalog();
```

每次配置操作生成唯一 `requestId`。结果 `status` 只接受 `success` 或 `error`；WebView 只接收当前 `requestId + configId` 对应的结果。页面切换、环境变化、重试或新请求产生后，旧回调直接忽略。

## 10. 异常处理

| 场景 | 处理 |
|---|---|
| 设备未识别 | 仍可浏览全库；隐藏“只看本机”，配置不能直接应用 |
| 目录加载失败 | 保留搜索框，显示重新加载 |
| 搜索无结果 | 区分游戏和 GPU，支持清空搜索 |
| 游戏或 GPU 失效 | 返回兼容库重新查找 |
| 配置失效 | 显示暂不可用，不调用下载 |
| 配置与本机不匹配 | 允许查看和下载，不允许应用 |
| Bridge 失败 | 原位显示原因和重试 |
| Bridge 无回调 | 8 秒后进入超时状态 |
| 旧请求延迟回调 | 校验 `requestId + configId`，不覆盖当前操作状态 |

## 11. 横竖屏

- 竖屏：单列主内容；游戏和 GPU 列表使用两列卡片或单列记录；筛选使用全屏双栏面板。
- 横屏：首页左侧常驻筛选目录，右侧展示至少三列结果；二级筛选面板从目录右侧展开。详情左侧为对象摘要，右侧为记录或配置。
- 切换方向保留当前 Tab、搜索词、筛选条件、游戏、GPU、配置和操作状态。

## 12. 指标

- 游戏搜索后进入详情率。
- GPU 搜索后进入详情率。
- GPU 记录到配置详情的转化率。
- 配置下载率。
- 匹配设备配置的应用成功率。
- 应用配置后的启动成功率和有效运行率。
- 配置不匹配拦截次数。
- 错误兼容结论率。

## 13. 验收标准

- 首页默认可浏览全部游戏和全部 GPU，不依赖当前设备。
- 可分别搜索游戏和 GPU。
- 游戏和 GPU 筛选状态相互独立，支持多选、清空和无结果恢复。
- 竖屏筛选为全屏双栏面板，横屏筛选为左侧目录和二级选项面板。
- “运行表现”未选择 GPU 时不可选，不产生跨 GPU 的模糊结论。
- 游戏详情能查看至少三种 GPU 记录及对应配置。
- GPU 详情能查看已验证游戏。
- 推荐 GPU 和最低已验证 GPU 有数据依据。
- 每条配置均可进入配置详情。
- 配置列表中，匹配本机时可下载并直接应用；不匹配时只能下载，不能应用。
- 配置详情完整展示设置、步骤、问题和参数，不展示下载或应用按钮。
- 四种运行结论和四级证据均可演示。
- 设备未识别时仍可浏览兼容库。
- 390×844 和 874×402 下无横向溢出。
- HTML 无外部 CDN，可离线演示。
- 异常数据、加载失败和 Bridge 失败不会导致页面失效。
