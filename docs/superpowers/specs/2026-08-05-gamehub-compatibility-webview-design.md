# 盖世游戏「适合本机」WebView 设计规格

**日期：** 2026-08-05

**状态：** 已确认

**交付：** App 内嵌单页 WebView，支持横竖屏

## 1. 产品定义

这不是兼容性参数库，而是“当前设备的游戏发现与成功运行方案中心”。

目标用户是不理解 GPU、驱动、Wine、DXVK 等术语，只想尽快玩到 PC 游戏的普通用户。统一任务是：

> 帮用户用当前设备，以最低试错成本成功运行一款游戏。

页面覆盖三类连续场景：

1. 不知道玩什么：当前设备能玩什么？
2. 已有目标游戏：这款游戏能玩吗？
3. 已运行失败：怎么才能玩起来？

所有内容对所有用户开放，不设置高级用户、会员或付费门槛。完整配置默认收起仅用于控制阅读层级。

## 2. 竞品判断

GameNative 的核心价值不是查询表格，而是“真实运行数据、玩家评价、配置复用”的兼容性闭环。可借鉴其数据来源和方案复用，不照搬以下问题：

- 表格字段过多，移动端难阅读。
- 不直接回答“当前设备能不能玩”。
- 超短会话、0 FPS 与五星评价可能互相矛盾。
- 设备、GPU、系统和版本字段缺失时仍容易形成确定结论。
- 完整配置暴露本地路径和无关底层参数。
- 驱动名称与下载文件存在错配风险。

盖世的差异是 App 能提供当前设备上下文、游戏拥有和安装状态，并能把方案直接用于下载或启动。

## 3. 本期范围

### 3.1 包含

- App 自动注入设备、GPU、Android 版本、盖世版本、游戏拥有和安装状态。
- 默认展示适合当前设备的游戏。
- 按中文名、英文名、别名搜索全量游戏。
- 展示运行结论、证据等级、预计表现和更新时间。
- 展示并应用推荐运行方案。
- 根据拥有、安装和兼容状态给出下一步操作。
- 在游戏详情内提供启动失败排查。
- 展示真实运行数据、玩家评价和完整配置。
- 横竖屏适配，切换方向不丢失当前状态。
- 模拟数据与真实数据共用同一 Adapter 和页面模型。

### 3.2 不包含

- 评价提交、点赞、举报及后台治理。
- 登录、会员、付费墙或内容分级。
- 驱动下载、排行榜和复杂筛选。
- 自动修复、独立故障中心和手动编辑底层配置。
- 云游戏兜底；国内、海外均按本地运行能力给结论。
- GameNative 的品牌、文案、视觉资产或源码复制。

## 4. 核心数据关系

兼容性不是游戏的静态属性。每条结论必须绑定以下关系：

```text
游戏版本 × 来源平台 × 设备 × GPU × Android版本 × 盖世版本
× 内核版本 × 运行方案版本 → 实际运行结果
```

任何一个关键条件变化，旧结论只能作为参考，不能直接继承为“已验证”。每条结论至少包含：

- 游戏、游戏版本和来源平台。
- 设备、GPU 和 Android 版本。
- 盖世版本、内核版本和方案版本。
- 数据更新时间、有效样本数和结论依据。

## 5. 结论与证据

### 5.1 运行结论

| 结论 | 含义 | 展示要求 |
|---|---|---|
| 可直接玩 | 当前环境存在稳定运行证据 | 显示预计表现，可直接进入下一步 |
| 调整后可玩 | 使用指定方案后可稳定运行 | 必须展示推荐方案及 1～3 个步骤 |
| 暂不建议 | 当前环境存在明确的启动或性能硬伤 | 必须说明原因，不承诺可运行 |
| 暂无结论 | 样本不足或关键环境不匹配 | 明确“不代表不能运行” |

### 5.2 证据等级

| 等级 | 判定依据 |
|---|---|
| 当前设备已验证 | 设备、GPU、系统、盖世、内核和方案版本均匹配 |
| 同 GPU 设备已验证 | GPU 与核心软件环境匹配，设备型号不同 |
| 同类设备参考 | 仅芯片或 GPU 系列接近 |
| 样本较少 | 有效样本不足，或关键字段缺失 |

结论与证据分开显示，例如：`调整后可玩｜当前设备已验证`。不能把“同类设备参考”包装为当前设备的确定结论。

### 5.3 有效运行口径

- 会话不少于 10 分钟。
- 有正常 FPS 数据或明确的启动成功事件。
- 同一用户的重复短会话去重或降权。
- 0 FPS、超短会话和单条主观评分不能单独决定兼容结论。
- 缺少设备、GPU、内核或方案版本的记录不得进入最高证据等级。

## 6. 推荐方案

“运行方案”是独立、可版本化的数据对象，至少包含：

- 适用环境。
- 预计结果。
- 推荐设置。
- 1～3 个顺序步骤。
- 已知问题及解决方法。
- 方案版本、验证时间和有效验证人数。
- 可展开的完整配置。

方案版本变化后重新统计有效运行结果，不把旧方案数据混入新方案结论。

## 7. 页面结构

页面只有一个入口、一个搜索框和一套游戏详情，不增加“找游戏/查游戏”Tab。

### 7.1 默认发现视图

从“适合本机”进入，依次展示：

1. 返回与标题“适合本机”。
2. 搜索框“搜索想玩的游戏”。
3. 当前设备信息。
4. “这台设备可以玩的游戏”及数量。
5. 按当前设备成功运行概率排序的游戏列表。

默认列表面向整个内容库，不限于用户已拥有或已安装的游戏。卡片展示：

- 封面、游戏名和来源平台。
- 运行结论和证据等级。
- 预计 FPS 区间与简短流畅度描述。
- 有效运行人数或次数。

默认发现列表只展示“可直接玩”和“调整后可玩”。“暂不建议”和“暂无结论”仍可通过搜索找到。

### 7.2 搜索状态

- 支持中文名、英文名和常见别名。
- 同名游戏按 Steam、Epic 等来源区分。
- 搜索结果不隐藏任何运行结论。
- 默认按当前设备匹配程度排序，再按有效样本量和更新时间排序。
- 无结果时显示“没有找到这款游戏”，可清空搜索恢复默认列表。

### 7.3 游戏详情

详情按以下顺序回答问题：

1. 游戏名、封面和来源平台。
2. 能不能玩：运行结论和一句话原因。
3. 预计表现：FPS、流畅度、证据等级和更新时间。
4. 推荐方案：适用环境、预计结果和已验证人数。
5. 1～3 个执行步骤。
6. 与当前状态对应的主操作。
7. 真实运行数据。
8. 启动失败排查。
9. 玩家评价。
10. 默认收起的完整配置。

所有模块对所有用户开放。

## 8. 主操作

App 注入 `owned` 和 `installed` 后，页面只显示当前状态对应的一个主操作：

| 状态 | 主操作 |
|---|---|
| 已安装 | 使用方案并启动 |
| 已拥有、未安装 | 使用方案并下载 |
| 尚未拥有 | 查看游戏详情 |
| 暂不建议 | 查看其他可玩游戏 |
| 暂无结论 | 查看已有记录 |

“暂不建议”和“暂无结论”不显示“使用方案并启动”，避免错误承诺。

## 9. 启动失败排查

不新增独立故障中心。详情内提供以下问题入口：

- 无法启动。
- 黑屏。
- 闪退。
- 手柄异常。
- 声音或画面问题。

选择问题后在当前模块内展示 1～3 个按顺序执行的处理步骤。步骤必须绑定当前方案和环境；无匹配方案时只展示通用检查，并标明“暂无针对当前设备的验证结果”。

## 10. 冷启动与逐级匹配

数据不足时不隐藏入口，按以下顺序降级：

1. 当前设备已验证。
2. 同 GPU 设备已验证。
3. 同类设备参考。
4. 样本较少。

页面始终明确证据等级。完全没有数据时显示“暂无结论”，不显示“不兼容”。

## 11. 设备状态

| 状态 | 页面处理 |
|---|---|
| `loading` | 显示“正在识别当前设备”，不输出兼容结论 |
| `ready` | 展示当前设备和匹配数据 |
| `unavailable` | 显示“暂时无法识别设备”及重试，不使用默认设备伪造结果 |

设备信息可展开查看型号、GPU、Android、盖世和内核版本。V1 不提供手动切换设备。

## 12. 横竖屏

### 12.1 竖屏

- 单列页面，游戏卡片两列。
- 详情纵向排列，主操作不遮挡系统手势区。

### 12.2 横屏

- 游戏卡片至少四列，保证标题和状态可读。
- 详情左侧为游戏与结论，右侧为方案与证据。
- 横竖屏切换保留搜索词、当前游戏、滚动位置和展开状态。

## 14. WebView 接口

页面暴露统一注入接口：

```js
window.GameHubCompatibility.setContext(context);
window.GameHubCompatibility.setGames(games);
window.GameHubCompatibility.setGamesLoading();
window.GameHubCompatibility.setGamesError();
window.GameHubCompatibility.openGame(gameId);
window.GameHubCompatibility.setContextUnavailable();
window.GameHubCompatibility.setActionResult({ status, message });
```

主操作调用 App Bridge：

```js
window.GameHubBridge?.applyPlanAndLaunch({ gameId, planId });
window.GameHubBridge?.applyPlanAndDownload({ gameId, planId });
window.GameHubBridge?.openGameDetail({ gameId, store });
window.GameHubBridge?.reloadCompatibility();
```

从其他页面直达详情时支持：

```text
?game_id=steam_1245620
```

本地 Demo 没有 Bridge 时只模拟按钮状态，不修改设备文件、不安装驱动。

## 15. 异常处理

| 场景 | 处理 |
|---|---|
| 设备识别失败 | 说明失败并支持重试，不输出结论 |
| 列表加载失败 | 保留设备信息，支持重新加载 |
| 搜索无结果 | 显示无结果并支持清空搜索 |
| 详情关键数据缺失 | 降级为“暂无结论” |
| 方案应用失败 | 保留原配置并支持重试 |
| 封面失败 | 使用内置占位封面 |
| 横竖屏切换 | 保留搜索、详情和展开状态 |

## 16. 指标

主指标不是查询量，而是方案使用后能否进入有效游戏：

- 默认列表游戏点击率。
- 搜索后进入详情率。
- 推荐方案使用率。
- 使用方案后的启动成功率。
- 有效运行率：会话不少于 10 分钟。
- 错误结论率。

## 17. 验收标准

- 无设备上下文时不显示确定兼容结论。
- 首屏 3 秒内能理解“这些游戏适合当前设备”。
- 默认列表可发现当前设备可玩的游戏，搜索可找到四种结论的游戏。
- 结论和证据等级分开显示。
- “调整后可玩”必须有推荐方案、1～3 步和主操作。
- 主操作随拥有、安装和运行结论变化。
- 详情能查看五类启动问题及对应步骤。
- “暂无结论”不得写成“不兼容”。
- 玩家评价、真实数据和完整配置对所有用户开放。
- 390×844 竖屏和 874×402 横屏无横向溢出。
- 横竖屏切换不丢失当前操作状态。
- HTML 无外部 CDN 依赖，模拟数据可离线演示。
- 模拟数据和真实数据通过同一 Adapter 进入 UI。

## 18. 决策结论

- 不做传统兼容性表格，优先给出“能否运行、怎么运行、失败怎么办”。
- 不拆“找游戏”和“查游戏”，共用一个搜索框和一套详情。
- 不用云游戏兜底，保证国内与海外结论口径一致。
- 不因冷启动隐藏功能，用证据等级表达数据强弱。
- 不把完整参数当主要答案，参数只用于验证和复现。
- 页面免费开放，作为盖世的转化与留存基础能力。
