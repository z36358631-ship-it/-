# Mac 原生标识与安装交互修正设计

## 目标

在现有 Mac 原生版本管理 Demo 与 PRD 上做三项增量修正：统一平台标识形态、记忆用户上次安装路径、让安装弹窗只负责提交安装任务。

## 已确认口径

1. 游戏库卡片中的 Mac 原生标识仅显示苹果图标，不显示“Mac 原生”文字；悬停说明继续区分“当前使用 Mac 原生版”。
2. 安装位置优先选中用户上一次成功安装时选择的路径；该路径不存在、不可写或空间不足时，回退到可用空间最大的路径。
3. 安装弹窗不显示下载进度，也不提供“取消下载”；点击“安装游戏”并通过路径复验后立即关闭弹窗，下载任务转入后台。
4. 后台下载期间，详情主按钮显示下载状态并禁止重复提交；下载完成后更新安装版本、当前启动版本和游戏库标识。

## 状态与数据

- `lastUsedInstallPathId`：保存最近一次成功提交安装任务时使用的路径标识，并写入本地配置。
- `selectedPathId`：本次安装弹窗的当前选择；打开弹窗时优先从 `lastUsedInstallPathId` 恢复。
- `downloadState`：保留 `idle`、`downloading`、`success`，但进度不在安装弹窗内展示。
- 最近路径只在安装提交校验通过后更新，取消弹窗或校验失败不更新。

## 路径回退

1. 最近路径合格：选中最近路径，即使它不是可用空间最大的路径。
2. 最近路径不合格：选中可用空间最大的合格路径。
3. 没有合格路径：不选中路径，安装按钮不可点击，并保留现有异常提示。
4. 用户手动改选路径并成功提交安装后，新路径成为后续默认路径。

## 下载交互

1. 用户点击“安装游戏”。
2. 客户端再次校验路径存在、可写且空间足够。
3. 校验失败：弹窗保持打开，清空失效选择并提示重新选择。
4. 校验成功：创建后台下载任务、记录最近路径、关闭安装弹窗。
5. 详情主按钮显示后台下载进度；下载完成后切换为目标版本，原版本继续保留。

## 方案快速评审

- 用户视角：通过。平台标识更统一，常用安装位置无需重复选择，安装提交后可立即返回详情。
- 开发视角：通过。最近路径使用单值持久化；下载仍沿用现有状态模型，只调整展示位置。
- 商业视角：通过。不新增页面、弹窗或能力，仅减少操作成本并修正流程表现。

## 验证

- 所有游戏卡片的 Mac 原生角标仅包含苹果图标。
- 首次打开安装弹窗默认选中预置的最近路径；完成一次不同路径安装后，再次安装默认选中新路径。
- 最近路径不可用时回退到最大空间合格路径。
- 安装弹窗不包含进度条和取消下载按钮。
- 点击安装后弹窗立即关闭，详情显示下载状态，任务完成后版本状态正确更新。
- PRD 的规则、验收和埋点口径与 Demo 一致。
