# Mac MODS 列表、排序与启用开关增量设计

## 目标

在不扩大本期 Mac MODS 范围的前提下，降低列表和详情的信息密度，让用户更快完成发现、安装与本机启停。

## 已确认范围

- 浏览排序仅保留“热门趋势、下载量、最新发布”，默认“热门趋势”。
- “热门趋势”按近 24 小时下载激增百分比降序；提示语为“按近 24 小时下载增幅排序”。
- “热门推荐”改为“热门组件”。
- 删除浏览页汇总文案“共 128 个，当前加载 8 个 · 下载量来自外部同步”。
- 删除游戏详情 MODS 标题旁的“非官方”徽标；“仅此设备”等设备边界语义保留。
- 浏览列表中的已安装卡片、已安装 Tab 卡片、MOD 详情三处增加同一设备级启用开关。
- 详情标题下只显示一行“作者、下载量、文件大小”，参数间保留明确间距；不展示兼容性、最新版本和原指标宫格。

## 交互设计

### 浏览排序

三项排序直接平铺，不使用下拉菜单。默认选中“热门趋势”：

1. 热门趋势：`trend_growth_24h DESC NULLS LAST → download_count DESC → published_at DESC → mod_id ASC`
2. 下载量：`download_count DESC → published_at DESC → mod_id ASC`
3. 最新发布：`published_at DESC → download_count DESC → mod_id ASC`

缺失趋势和下载量按 `0` 处理，缺失发布时间按最旧处理。正式服务端分页需固定同一查询快照，并把完整排序元组写入分页游标，防止趋势值更新导致重复或漏项。

### 卡片

- 卡片整张保持可点击进入详情。
- 未安装卡片右下角显示“安装”。
- 已安装卡片右下角显示“已安装”与“已启用/未启用”开关。
- 开关是独立点击和键盘聚焦区域，位于整卡点击层之上；操作开关不得打开详情。
- 已安装 Tab 继续展示更新状态。启用值、安装事实和更新事实是正交状态，开关不能替代“可更新、已是最新、更新失败”等状态文案。

### 详情

- 标题下单行显示：`作者 {author}`、`{download_count} 次下载`、`{file_size}`。
- 移除原五格数据摘要，不展示最近更新、最新版本和兼容性。
- 已安装 MOD 在底部状态区显示“已启用/未启用”开关；更新、检查更新、卸载仍是独立操作。
- 更新失败时继续展示“保留旧版”和“重试更新”，启用开关仍可操作旧版。

## 状态与失败处理

三处开关读取同一个 `enabled_value`。发起写入后锁定该 MOD 的全部可见开关，避免连续点击产生乱序响应；成功后统一刷新，失败时恢复操作前状态并提示“启用状态修改失败，请重试”。请求超时后先重新读取设备状态，再决定展示值。

Demo 使用同步设备状态模拟成功路径，并保留 `ENABLE_CHANGE_FAILED` 回滚事件供自动验证。正式客户端接入设备状态服务时复用相同渲染规则。

## 验证

- DOM 断言排序严格为三项且默认热门趋势。
- 数据断言三种排序使用确认后的字段与稳定次级键。
- DOM 断言“热门组件”存在，汇总文案、非官方徽标、兼容性与最新版本展示不存在。
- 交互断言浏览已安装卡、已安装 Tab、详情三处开关状态同步，且开关点击不打开详情。
- 失败断言回滚到操作前值并显示错误提示。
- 截图检查列表信息层级、开关位置、详情标题元信息行和弹窗滚动。

## 范围边界

本轮只更新 Mac Demo 与对应 PRD 页面规则，不新增创意工坊需求，不改变 APP 横竖屏范围，不改变 MOD 外部来源安全口径，也不改变“安装与启用状态跟设备走”的规则。
