# Mac 原生游戏版本管理截图复刻设计

> 版本切换弹窗、未安装版本选择和安装入口的最新规则，以 `2026-08-07-mac-native-version-switch-refinement-design.md` 为准；本文其他视觉基准与页面范围继续有效。

## 1. 目标

以用户提供的四张 Mac 客户端真实截图为唯一视觉基准，先还原现有页面，再增加 Mac 原生游戏版本管理。

本次不是重新设计 Mac 客户端，不改变现有导航、页面结构、卡片密度、详情布局和安装流程。

## 2. 画布与复刻原则

- Demo逻辑画布固定为 `1076×734px`，按现有 Mac 标注版等比缩放。
- 截图原始比例与逻辑画布存在差异时，保持页面元素的相对位置和视觉比例，不横向或纵向拉伸。
- 现有页面优先级高于通用 UI 规范；截图已经出现的颜色、间距、圆角、字体层级和组件结构按截图还原。
- 不使用上一版的自创布局、GH 标识、异常演示工具栏、重新设计的详情卡片或其他截图中不存在的组件。
- 普通版本不展示“Windows”“转译”“普通版本”等新增标识，只保留 Steam、Epic、GOG 等现有平台信息。
- 仅 Mac 原生版增加 Mac 原生 Icon。

## 3. 页面复刻范围

### 3.1 我的游戏

按截图还原：

- 左侧竖向导航及当前“我的游戏”选中状态。
- 页面标题、筛选按钮、添加游戏和搜索框。
- 已安装、未安装分组与游戏卡片排列。
- 右侧 Steam、Epic Games、GOG 账号卡片。
- Steam 在线状态、头像、好友数量和游戏统计。

新增内容：

- “已安装 / 未安装”只由分组标题表达，游戏封面不重复增加安装状态角标。
- 游戏封面右下角的 Icon 只表达当前使用版本或准备下载版本的平台与版本类型。
- Steam、Epic、GOG 版本只展示对应平台 Icon，不增加“Windows”“转译”“普通版本”等标识。
- 当前使用或准备下载 Mac 原生版时，展示来源平台 Icon＋Mac 原生 Icon。
- 游戏支持 Mac 原生版但当前未选择时，不展示 Mac 原生 Icon。
- 已安装分组补齐 Steam、Epic、GOG、Steam＋Mac 原生、Epic＋Mac 原生等示例；多版本均已安装但当前使用平台版时，只展示当前平台 Icon。
- 未安装分组补齐 Steam、Epic、GOG、来源平台＋Mac 原生等准备下载版本示例，不增加“未安装”角标。

### 3.2 游戏详情

按截图还原：

- 顶部游戏名称。
- 左侧媒体预览区、纵向缩略图和主视觉。
- 右侧评价、标签、开发商、发行商、发行日期、下载大小和支持平台。
- 左侧主视觉底部居中的下载或开始游戏按钮。
- 首屏下方兼容性评价和成就模块的可见区域。

新增内容：

- 当前选择 Steam 或 Epic 等平台版时，主按钮展示：`平台 Icon＋下载 XXX.X MB`。
- 当前选择 Mac 原生版时，主按钮展示：`Mac 原生 Icon＋下载 XXX.X MB`。
- 当前版本已安装时，主按钮切换为对应版本的“开始游戏”。
- “开始游戏”或“下载”主按钮右侧增加独立的“…”更多操作按钮。
- 点击“…”后展示紧凑菜单，菜单提供“切换版本”；点击后在当前详情页打开版本切换弹窗。
- 移除详情标题右侧的齿轮入口，版本切换不跳转独立设置页面。
- 详情页不增加独立的“下载其他版本”按钮。
- 详情页不合并 Steam、Epic、GOG 等现有独立产品。

### 3.3 版本切换弹窗

- 弹窗在当前游戏详情页居中显示，背景使用现有遮罩与模糊效果。
- 弹窗展示当前产品可用的所有版本，每行包含版本 Icon、版本名称、下载大小和状态操作。
- 状态只包含：当前使用、已安装、未安装。
- 当前使用版本不可重复选择。
- 选择其他已安装版本后立即更新默认启动版本并关闭弹窗，原版本继续保留。
- 选择未安装版本后关闭版本切换弹窗，并在当前详情页打开现有安装路径弹窗；安装弹窗默认选中目标版本。
- 关闭版本切换弹窗不改变当前启动版本或目标下载版本。

### 3.4 安装路径弹窗

按截图还原：

- 背景详情页的遮罩和模糊效果。
- 弹窗标题、关闭按钮、游戏信息卡片、安装位置、游戏版本、创建桌面快捷方式和底部按钮。
- 游戏信息卡片中的封面、名称、所需空间和平台信息。
- 底部“已入库”和“安装游戏”按钮状态。

新增内容：

- “游戏版本”支持展开和切换。
- 每个版本展示版本 Icon、版本名称和下载大小。
- Steam、Epic 等平台版只展示原平台 Icon和平台名称。
- Mac 原生版展示 Mac 原生 Icon及“Mac 原生版”。
- 切换版本后，弹窗中的版本 Icon、所需空间和下载大小同步更新。

### 3.5 搜索

按截图还原：

- 原页面作为模糊背景。
- 居中的搜索弹窗、输入框、Games分组和搜索结果行。
- 游戏封面、名称、平台 Icon和跳转箭头。

新增内容：

- 搜索结果不区分已安装、未安装或当前使用状态，只展示产品支持的平台与版本。
- 结果行补齐 Steam、Epic、GOG、Steam＋Mac 原生、Epic＋Mac 原生等 Icon 组合示例。
- 产品支持 Mac 原生版时，在来源平台 Icon 旁增加 Mac 原生 Icon；不支持时只展示来源平台 Icon。
- 点击搜索结果进入当前发行平台对应的独立产品详情。

## 4. 核心交互流程

### 4.1 首次安装

1. 用户进入独立产品详情。
2. 主按钮显示当前选择版本的 Icon及下载大小。
3. 用户点击主按钮。
4. 打开现有安装路径弹窗。
5. 用户可在“游戏版本”中切换目标版本。
6. 用户确认安装。
7. 安装成功后，目标版本成为默认启动版本。

### 4.2 当前详情页切换至已安装版本

1. 用户点击详情主按钮右侧的“…”并选择“切换版本”。
2. 当前详情页打开版本切换弹窗。
3. 用户选择另一个已安装版本。
4. 系统更新默认启动版本并关闭弹窗。
5. 游戏库和详情页同步更新当前版本 Icon和启动行为，原版本继续保留。

### 4.3 当前详情页切换至未安装版本

1. 用户点击详情主按钮右侧的“…”并选择“切换版本”。
2. 当前详情页打开版本切换弹窗。
3. 用户选择未安装版本。
4. 系统关闭版本切换弹窗，并在当前详情页打开现有安装路径弹窗。
5. 安装弹窗默认选中目标版本，用户确认后开始下载。
6. 安装成功后切换为目标版本，原版本保留。

### 4.4 失败与取消

- 下载失败、空间不足、路径失效或用户取消时，不改变当前默认启动版本。
- 失败后返回详情，主按钮仍展示目标未安装版本的下载状态；用户可以重新下载或在设置中改回其他版本。
- 不自动删除任何已安装版本。

## 6. 实现边界

- 单文件 HTML，CSS和JavaScript全部内嵌。
- 使用行内 SVG，不使用 emoji、水印、CDN或 iframe。
- 页面元素按截图结构拆分，不能用整张截图作为不可编辑背景。
- 使用真实游戏名称和与截图一致的可见文案。
- 页面切换、版本选择、安装弹窗和状态变化必须可操作。
- 本次只修改 Demo，不追加 PRD 范围、不增加后台、埋点、灰度或运营功能。

## 7. 验收标准

- 在不展示新增 Mac 原生内容时，四个页面的整体结构、比例和视觉气质与截图一致。
- 删除新增内容后，页面仍可作为现有 Mac 客户端截图复刻版使用。
- 普通版本不出现任何“Windows转译”新增标识。
- Mac 原生 Icon只在已确认的状态和位置出现。
- 游戏库以分组标题表达安装状态，封面不出现重复安装状态角标。
- 游戏库已安装和未安装分组均补齐 Steam、Epic、GOG、来源平台＋Mac 原生等 Icon 示例。
- 搜索结果补齐平台与 Mac 原生 Icon 组合，但不出现安装状态。
- 详情页无齿轮入口；主按钮右侧存在“…”按钮，菜单可打开、可关闭并可在当前详情页打开版本切换弹窗。
- 选择未安装版本后，在当前详情页打开与截图一致的安装路径弹窗，弹窗默认选中目标版本。
- 取消弹窗后，详情主按钮正确显示目标版本 Icon和下载大小，可再次进入安装路径弹窗。
- 下载失败或取消不改变当前启动版本。
- `1076×734px` 逻辑画布下无滚动错位、内容遮挡或组件溢出。

## 8. 快速评审结论

- 用户视角：版本选择在当前详情页完成，不产生设置页跳转；安装状态由游戏库分组标题统一表达，封面 Icon 只承担平台与版本识别。
- 开发视角：版本切换弹窗复用现有版本状态数据；未安装版本继续承接现有安装弹窗，避免产生第二套下载逻辑。
- 商业视角：通过现有卡片和搜索结果补齐 Icon 示例即可覆盖评审场景，不增加说明工具栏或额外页面，范围可控。
