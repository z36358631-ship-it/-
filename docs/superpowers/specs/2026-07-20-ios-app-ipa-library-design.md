# 盖世游戏 Mac 端 iOS 应用与 IPA 资源库设计方案

> 文档状态：已确认方案，待实现计划
> 日期：2026-07-20
> 适用端：盖世游戏 Mac 端
> 参考能力：PlayCover 的 App 管理与 IPA 来源能力、现有 Mac 端游戏库 Demo

## 1. 背景与目标

盖世游戏 Mac 端需要补充一套独立的 iOS 应用管理能力，让用户能够选择本机 App 库目录、导入已有 iOS App、添加第三方 IPA 来源，并完成下载、校验、安装、启动、手动更新和卸载。

本功能不并入现有 PC/Mac 游戏库。原因是两类内容的安装包、运行环境、兼容性判断和资源来源均不同，强行混合会增加用户理解和后续功能扩展成本。

首期目标是形成以下完整闭环：

```text
选择 App 库目录
→ 导入已有 App 或添加 IPA 来源
→ 查找并下载 IPA
→ 确认安装
→ 启动、更新或卸载 App
```

## 2. 产品原则

1. 按用户任务分层，不按文件格式堆叠入口：已拥有内容进入“我的 App”，待获取内容进入“IPA 资源”。
2. App 是用户最终使用对象，IPA 只是获取和安装载体。
3. 只访问用户明确授权的目录，不主动扫描整台 Mac，也不申请完整磁盘权限。
4. 第三方来源不自动上传云端，不自动覆盖更新，优先保障可控性与数据安全。
5. 首期只完成最小闭环，不加入高级运行参数和复杂资源运营能力。

## 3. 信息架构

左侧导航新增独立一级入口“iOS 应用”，不改变现有“游戏库”。

```text
左侧导航
├─ 探索
├─ 找游戏
├─ 游戏库
└─ iOS 应用
   ├─ 我的 App
   └─ IPA 资源
```

进入“iOS 应用”后默认打开“我的 App”。安装完成后停留在安装结果页，避免批量失败项和重试入口被自动跳转打断；用户主动点击“前往我的 App”后，再定位并高亮刚完成安装的 App。

## 4. 功能范围

### 4.1 首期包含

- 选择唯一 App 库目录。
- 扫描并导入所选目录内可识别的 iOS App。
- 更改 App 库目录，但不迁移原目录内容。
- 浏览、搜索和筛选已导入 App。
- 添加、校验、刷新、停用和删除第三方 IPA 来源。
- 合并多个来源并对相同 App 去重。
- 单个或批量下载 IPA。
- 下载完成后的安装确认。
- 文件、版本、兼容性和可用空间校验。
- 安装、启动、手动更新和卸载 App。
- 刷新失败时展示上一次成功缓存。

### 4.2 首期不包含

- 多个 App 库目录。
- 更改目录时自动迁移 App。
- IPA 来源云端同步。
- 盖世官方 IPA 资源。
- 任意网页抓取和非标准来源解析。
- 历史版本选择和降级安装。
- 自动更新。
- 分辨率、设备型号、键鼠映射等高级运行设置。
- 依赖或唤起 PlayCover；安装和运行能力由盖世自研实现。

## 5. “我的 App”设计

### 5.1 首次进入空状态

页面主体展示空状态，核心文案和动作如下：

```text
设置 App 库位置
选择一个文件夹，用于保存、导入和管理 iOS App。
已有 App 不会被移动或删除。

[选择文件夹]

已有 iOS App？选择原 App 所在文件夹即可识别。
```

点击后拉起 macOS 原生文件夹选择器：

- 文件选择器标题为“选择 App 库文件夹”。
- 只允许选择可读写文件夹，不允许选择单个文件。
- 单次只允许选择一个目录。
- 用户取消选择后留在空状态，不展示错误提示。
- 授权成功后在本机保存目录访问凭据，以便后续刷新和安装。

### 5.2 目录扫描与导入确认

选择目录后立即扫描可识别 App，并展示导入确认弹层。视觉结构复用现有游戏库导入弹层：

```text
App 库                                  [取消全选]
/Users/xxx/iOSAppLibrary

□ App 图标  App 名称       版本/大小        状态
□ App 图标  App 名称       版本/大小        已导入

已选 3 / 5                         [取消] [导入]
```

交互规则：

- 默认勾选全部可导入 App。
- 已导入、结构损坏或当前版本无法识别的 App 置灰。
- 置灰项必须展示明确原因，不能只禁用复选框。
- 支持全选和取消全选；无可选项时“导入”按钮置灰。
- 空目录只要可读写且空间可用，仍然保存为有效 App 库。页面展示“App 库已设置，当前文件夹中还没有 App”，并提供“浏览 IPA 资源”和“更改文件夹”。
- 扫描到 App 时，确认层明确提示“导入后可在盖世中启动和管理这些 App，不会移动或删除原文件”。
- 计数统一使用“已选 N 项 · 可导入 N 项 · 共识别 N 项”，避免把置灰项算入可操作数量。
- 标题和底部操作区固定，中间列表独立滚动。
- 导入只建立盖世管理关系，不在导入阶段迁移或删除文件。

### 5.3 唯一 App 库路径

用户选择的目录同时承担两种职责：

1. 识别和管理该目录中已有的 iOS App。
2. 作为以后从 IPA 资源下载安装 App 的统一目标目录。

设置入口展示当前路径，并提供“在访达中显示”和“更改路径”。

### 5.4 更改路径

更改路径时不迁移、不复制、不删除原路径内容。

确认弹窗文案：

```text
更改 App 库路径？
切换后将扫描新目录，原目录中的 App 不会迁移或删除。
重新切回原路径后，可以再次识别其中的 App。

[取消] [选择新路径]
```

限制规则：

- 存在下载、校验、安装或卸载任务时禁止更改路径。
- 新路径授权或扫描失败时继续使用原路径。
- 本地保留曾使用路径的管理元数据；切回旧路径后，已管理 App 自动恢复，新发现 App 进入导入确认。这不代表同时管理多个活动路径。
- 切换成功后清空当前展示索引并扫描新路径，不影响原目录文件。

### 5.5 App 列表

页面布局和卡片视觉可复用现有游戏库 Demo，但字段和状态改为 iOS App：

- App 图标与名称。
- 当前版本。
- 文件大小。
- 安装或导入来源。
- 正常、可更新、无法启动、路径失效等状态。路径失效时保留上次扫描缓存，卡片进入只读异常状态并提供“重新授权原路径”。
- 主操作：打开、更新、重新授权或查看原因。

顶部能力：

- 搜索 App 名称。
- 默认按最近使用排序，并支持名称、最近使用、安装时间排序。
- 按全部、可更新、异常状态筛选。
- 在访达中显示 App 库。
- 更改 App 库路径。

### 5.6 App 操作

- **打开**：从盖世自研运行能力启动 App；启动失败需展示可定位的失败原因。
- **更新**：仅在 IPA 资源中存在更高兼容版本时出现，由用户主动触发。
- **卸载**：二次确认后只移除 App 包，首期默认保留用户数据；确认弹窗明确展示“App 将被移除，用户数据会保留”。
- **路径失效**：当目录被移动、删除或权限失效时，卡片不可启动，并引导用户重新选择或授权目录。

## 6. “IPA 资源”设计

### 6.1 无来源空状态

首次进入且没有来源时展示：

```text
还没有 IPA 来源
添加符合盖世格式规范的来源地址后，即可浏览和下载 IPA。

[添加来源]
```

页面需明确标注：资源来自用户添加的第三方来源，盖世不提供或审核来源中的内容。

### 6.2 添加来源

点击“添加来源”后打开弹窗：

```text
添加 IPA 来源

来源地址
[ https://example.com/source.json           ]
输入后自动验证来源是否有效

校验反馈区域

[取消] [导入]
```

输入和按钮规则：

- 仅支持无需账号、Cookie、自定义请求头或令牌的公开 HTTPS 标准来源。
- 用户停止输入 500ms 后自动发起校验，校验期间显示“正在验证来源…”。
- URL 被修改后立即清除旧成功状态并禁用“导入”；旧请求结果不得覆盖最新输入结果。
- 校验反馈固定显示在输入框下方，提前预留高度，避免弹窗因文案出现而抖动。
- 只有校验通过时“导入”按钮可用。
- URL 为空、格式错误、请求失败或内容无效时按钮置灰。
- 用户修改已通过校验的 URL 后，立即恢复为待校验状态并禁用按钮。

来源有效必须同时满足：

1. URL 可以访问。
2. 返回盖世约定的标准结构，而不是普通网页。
3. 来源基本信息和资源必要字段完整。
4. 至少包含一个有效且可识别的 IPA 资源。

失败反馈需区分：

- URL 格式不正确。
- 网络连接失败或请求超时。
- 来源拒绝访问。
- 返回内容不是有效来源格式。
- 必填字段缺失。
- 来源中暂无有效资源。
- 该来源已经添加。

### 6.3 来源字段建议

来源级字段：

- 来源 ID、来源名称、来源版本。
- 更新时间。
- 资源列表。

资源级必要字段：

- App 名称。
- Bundle ID。
- 版本号。
- IPA 下载地址。
- 图标地址。
- 安装包大小。
- 支持的架构或兼容信息。
- 更新时间。
- 文件校验信息。缺少来源哈希时仍可进入下载，但不能标记为“来源校验通过”，安装确认中不默认勾选并要求用户额外确认。

具体接口格式在技术方案中定义，本设计只约束产品校验结果和用户反馈。

### 6.4 来源管理

来源 URL 只保存在当前 Mac，不跟随盖世账号同步。

来源管理列表展示：

- 来源名称和域名。
- 最近成功刷新时间。
- 正常、刷新失败、格式失效、已停用状态。
- 单独刷新、停用/启用、删除操作。

删除来源时：

- 不卸载已经安装的 App。
- 从聚合资源列表中移除该来源独有内容。
- 如果某个 App 同时存在于其他来源，继续保留该 App。

### 6.5 资源聚合与去重

- 默认合并全部已启用来源。
- 支持按来源筛选和进入来源管理。
- 按 Bundle ID 合并相同 App。
- 版本比较使用“版本号 + Build 号”，只展示各来源中版本最高且兼容当前设备的构建。
- 首期不向用户展示历史版本或来源选择。
- 同版本存在多个来源时，使用校验通过且当前可用的来源；下载失败可尝试其他同版本来源。
- 下载后必须核对 IPA 内部 Bundle ID 与来源元数据一致；覆盖更新时若 Team ID、签名主体或关键身份信息变化，不允许静默覆盖，必须明确警告或阻止安装。

每张资源卡展示：

- App 图标和名称。
- 最新兼容版本。
- 安装包大小。
- 来源名称。
- 未安装、已安装、可更新、不兼容等状态。
- 下载或更新操作。

顶部支持 App 名称搜索、来源筛选和更新状态筛选。

### 6.6 刷新与缓存

- 每次进入“IPA 资源”时自动刷新一次全部启用来源。
- 页面保留“刷新”按钮，支持用户主动刷新。
- 同一次进入页面不重复自动刷新。
- 单个来源失败不影响其他来源结果。
- 刷新失败时继续展示上次成功缓存，并标注失败状态和上次更新时间。
- 首次刷新失败且没有缓存时，展示失败空状态和重试入口。

## 7. 下载与安装流程

### 7.1 前置拦截

如果用户尚未选择 App 库路径，在 IPA 资源中点击下载时先引导设置路径；设置完成后返回原资源并继续操作。

如果目录权限失效，则先要求重新授权，不能下载完成后才提示无法安装。

### 7.2 单个与批量下载

资源列表支持：

- 单张卡片直接下载。
- 进入批量选择状态后勾选多个资源。
- 底部展示已选数量和预计总下载大小。

下载状态依次为：

```text
等待下载 → 下载中 → 校验中 → 等待确认安装
```

下载失败项可单独重试，不要求重新下载已成功项目。

批量任务中所有项目达到终态后进入安装确认。终态包括“校验通过、下载失败、校验失败”；失败项不得阻塞通过项进入安装确认。

### 7.3 校验规则

安装确认前至少完成：

- IPA 包结构完整性校验。
- 来源提供哈希时校验文件哈希一致性；无哈希时标记为风险项，不表述为“已验证安全”。
- Bundle ID 和版本信息校验。
- 当前 Mac 与运行环境兼容性校验。
- 可用存储空间校验。
- 已安装版本冲突校验。

校验失败项保留在列表中但置灰，并展示失败原因。

### 7.4 安装确认

下载和校验完成后统一进入安装确认弹层，结构复用 App 导入确认列表：

```text
确认安装                              [取消全选]

□ App 图标  App 名称   新版本   大小   来源   兼容状态
□ App 图标  App 名称   新版本   大小   来源   不可安装原因

已选 2 / 3                         [取消] [确认安装]
```

列表必须展示：

- App 图标、名称和版本。
- 文件大小。
- 来源名称和域名。
- 当前已安装版本。
- 兼容状态。
- 覆盖更新或风险提示。

默认勾选全部通过完整校验的 App；不可安装项置灰；无来源哈希等风险项不默认勾选，用户勾选时需额外确认。“确认安装”仅对已勾选项目生效。

用户取消安装确认后保留已下载文件，资源卡状态改为“已下载，待安装”，主按钮改为“继续安装”，并提供“删除安装包”；再次安装不重复下载。

### 7.5 安装完成

- 安装到用户选择的唯一 App 库路径。
- 单个安装完成后停留在结果页，提供“打开”和“前往我的 App”。
- 批量安装完成后停留在结果页，展示成功、失败数量并支持仅重试失败项。
- 用户主动返回“我的 App”时定位并短暂高亮新安装内容。
- 安装失败不能破坏原有已安装版本；覆盖更新失败时保留旧版本可用。

## 8. 更新规则

- App 库中的 Bundle ID 与聚合资源匹配，且资源版本更高时显示“可更新”。
- 首期不自动下载、不自动安装更新。
- 用户点击更新后沿用“下载 → 校验 → 确认安装 → 覆盖更新”流程。
- 相同版本不显示更新操作。
- 新版本不兼容当前环境时不展示为可更新，可在状态说明中提示“存在新版本但暂不兼容”。

## 9. 关键状态与异常反馈

| 场景 | 产品处理 |
|---|---|
| 用户取消目录选择 | 保持原页面，不提示错误 |
| 目录内没有 App | 目录仍设置成功，提供浏览 IPA 资源和更改路径 |
| 目录权限失效 | 保留上次扫描缓存，禁止安装和启动，引导重新授权原路径 |
| 更改路径时存在任务 | 禁止更改并提示先完成或取消任务 |
| 来源验证失败 | 输入框下方显示具体原因，导入按钮置灰 |
| 来源刷新失败 | 展示缓存和上次更新时间，支持重试 |
| 下载中断 | 保留已完成任务，失败项单独重试 |
| 存储空间不足 | 下载或安装前拦截并显示所需空间 |
| IPA 损坏 | 禁止安装，支持重新下载 |
| IPA 无来源哈希 | 标记为风险项，不默认勾选，安装前额外确认 |
| App 不兼容 | 置灰并说明架构或系统原因 |
| 覆盖更新失败 | 保留旧版本并提示更新失败 |

## 10. 安全与责任边界

- 所有来源均由用户主动添加，盖世首期不预置官方 IPA 内容。
- 添加来源和安装确认时展示来源名称及域名，避免把第三方内容误认为盖世官方内容。
- 来源 URL 和缓存只保存在当前 Mac。
- 不自动执行来源中的脚本或非 IPA 内容。
- 安装前必须完成文件结构和兼容性校验；存在风险时不得静默安装。
- 无来源哈希的 IPA 不得显示为“已验证安全”，批量安装中不得默认选中。
- 对来源失效、内容侵权或文件安全问题提供来源删除和问题定位能力。

## 11. 数据与验收指标

建议观察：

- App 库路径选择完成率。
- 目录扫描成功率与平均耗时。
- 来源 URL 校验通过率及失败原因分布。
- 资源刷新成功率。
- IPA 下载成功率。
- IPA 校验通过率。
- 安装成功率和失败原因分布。
- 从进入 iOS 应用到首次成功启动 App 的耗时。
- 可更新提示到更新完成的转化率。

## 12. 首期验收标准

1. “iOS 应用”作为独立一级入口，内部包含“我的 App”和“IPA 资源”两个 Tab。
2. 未设置目录时可以通过 macOS 文件夹选择器选择唯一 App 库路径。
3. 选择路径后能够扫描、勾选并导入可识别 App，异常项有明确原因。
4. 更改路径不会迁移或删除原目录内容，失败时仍保留原路径。
