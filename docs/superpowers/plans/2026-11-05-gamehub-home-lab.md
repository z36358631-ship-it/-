# 盖世首页三个内容方向 Implementation Plan

> **For agentic workers:** 按本计划直接在当前会话执行。UI 实现由快速原型工程师负责，主管负责素材、验证、走查、调优与交付；不覆盖其他任务的改动。

**Goal:** 将付费价值、可玩发现、玩家内容三个首页方向制作成同一入口可切换的 Demo，以模拟用户场景走查后调优。

**Architecture:** 复用现有 PC 主机体验 Demo 的暗色、导航与真实局部媒体，三个首页分别使用独立内容函数，共用详情与返回栈。新用户阶段、游戏来源和设备能力独立建模；云游戏是可由不同来源进入的游玩路径。

**Tech Stack:** 原生 HTML/CSS/JavaScript、Python 标准库打包、Playwright 浏览器验证。

## 范围与事实

- 仅首页方向实验；7.0 内核、原正式 PRD 与原线上 Demo 的业务决定不变。
- 导入约六至七成、Steam 约两至三成、秒玩约一成仅作约数；不据此推断云游戏占比。
- 商业化仅以已有云时长入口为原型依据；套餐/价格未核实，不启用支付，不造会员权益。
- 兼容记录、资源就绪与云游戏供给是评审场景样例，外部控制区统一说明。
- 玩家内容为编辑样例；AI 用户走查不等于真实招募测试。

## 验收边界

所有交互为浏览器演示，不运行 PC 游戏、不登录真实账号、不发通知、不扣费。新内容方向没有像素一致的实机原稿，不声明达到原页面 95% 复刻门槛；验证来源、Shell 分工、几何、响应式和真实 DOM。真实用户反馈与真机兼容验证仍待招募/设备执行。
