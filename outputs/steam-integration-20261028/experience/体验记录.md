# APK 体验记录

日期：2026-10-28。执行者：Codex 主代理。环境：本机 MuMu，ADB 127.0.0.1:16384，Android 12，ABI 列表 x86_64/arm64-v8a/x86/armeabi-v7a/armeabi。

## 实际操作与结果

1. 查询当前设备；当时无 USB 真机连接。启动本机已有 MuMu 实例，不修改模拟器配置。
2. 检查 com.steamdroid.client 未安装；用用户提供的 steamsir.apk 安装，ADB 返回 Success。
3. 启动 com.steamdroid.client/.SteamActivity，截图 01-first-launch.png：可见 Window mode、Big Picture（带选中描边）、Continue。未见“记住我的选择”。此截图不能证明后续行为。
4. 随后抓取 UI XML 已为 Steam failed to start，错误为 java.io.IOException: lib/arm64/libtier0_s.so: dlopen failed: failed to link libtier0_s.so。
5. 02-window-selected.png 文件名是取证时预定名，实际画面为启动失败，不是“窗口模式选择成功”证据；不能据此判断已选中窗口。
6. force-stop 目标应用并重新启动，04-relaunch-result.png 和 XML 再次出现同样失败。没有清除应用数据、没有卸载旧应用、没有修改用户账号。

## 可判断与不能判断

- 可判断：安装成功；有大屏/窗口选择首屏；在此模拟器环境运行时初始化失败；重启应用未恢复。
- 不可判断：失败是否只发生于模拟器、ARM64 真机是否成功、是否会自动进入、长期模式记忆是否有效。
- 未体验：Steam 登录、桌面/大屏完整库、好友聊天、工坊、游戏下载安装/启动、手柄输入和账号迁移。
- 没有输入账号密码、读取凭据、发送消息、购买或订阅内容。
- 静态核查另见 ../apk-analysis/静态核查.md；不要混同静态能力与运行结果。

## 接入启示

下载完成后必须独立显示“准备/启动”阶段和失败返回路径。本次真实失败可以作为异常设计依据，但不能推断为盖世生产包也存在同一缺陷。

恢复完整体验条件：提供可连接且已授权调试的 ARM64 Android 10+ 测试设备，或提供能在当前环境运行的兼容测试包。涉及实际 Steam 登录时由用户完成账号验证。
