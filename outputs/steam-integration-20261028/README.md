# 盖世游戏 Steam 接入评审包

打开 `Steam接入Demo.html` 即可离线使用。右下角“演示”展开悬浮面板，可直接切换55个状态；面板可收起。

## 当前流程

游戏库 Steam → 模式选择并勾选协议 → 组件准备弹窗 → 扫码或账号密码登录 → Steam。

- 新用户与旧版已登录用户首次进入新方案，都必须选择模式并主动勾选；继续才保存。旧登录状态不能绕过接入确认。
- 确认后保留有效Steam登录态；旧用户按本次选择启动新界面。后续可恢复本方案有效会话或使用已记忆模式。
- 准备弹窗仅显示状态、进度及操作，收起后继续下载、校验与准备，完成后留在当前盖世页面。
- 竖屏上扫码、下账号密码；横屏左右排列。二维码仅为演示，不可真实登录。
- 悬浮球最小化只缩成图标，不关闭Steam；无关闭和设置开关。

- 启动后进入可选主页、社区、游戏库、Steam；未设置（含旧版缺字段）竖屏主页、横屏游戏库，保存后下次冷启动生效。用演示面板“模拟重新打开 App”验证。
- 已接入PC及已导入游戏通过Steam模式承接原目标；实际回执前不算运行成功。
- Steam成功登录后卡片显示昵称头像；首次Steam库轻提示可直达启动页设置。

## 重建与检查

在本目录执行 `npm install`、`npm run build`、`npm test`。需要Node.js和已有Chrome；可用 `CHROME_PATH` 指定浏览器路径。`npm run capture` 重新截图。

所有构建输入位于本目录。Demo不调用真实登录、下载、消息或游戏服务；输入仅内存保存。真实APK在当前MuMu环境启动受阻，原生运行、迁移、输入和法务文本仍需核对。

悬浮菜单右上“−”直接最小化为小图标，底部不再重复提供最小化项；支持当前大屏／窗口即时切换及100%—150%缩放。账号管理、导入账号已按样图呈现，认证与导入为内存模拟；开发者选项仍作占位，具体以接入 Steam Demo 为准。

浏览器每次打开或刷新均重置Demo，直接展示首次模式与协议选择（默认窗口、未勾选）。验证设置记忆请使用演示面板“模拟重新打开 App”；真实产品的持久化规则不变。

用户流程图.html 已更新为实际 Demo 页面串联，采用参考评审长页，含首次进入、悬浮球、账号管理、设置、后台准备五类流程，实际截图可点击放大。build-page-flow.mjs为生成源，随npm run build一起生成。

账号界面源：account-view.mjs；GitHub Pages产物由build-public.mjs生成。发布仅更新public/steam-integration三文件，不合并整个开发分支。
