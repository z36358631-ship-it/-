## 一、文档概述

### 1.1 背景概述

- **需求背景：** GameFusion 一期向全球用户提供 PC 游戏发行服务。2026-10-12 评审要求收口客户端结构、商城与原生能力边界，并承接硬件分发 CDK 和 Gamesir Connect 入口。
- **当前方式：** 用户在共享商城发现、购买游戏，再由客户端管理本机内容和启动。V1.0 原型含左侧导航、独立安装按钮和模拟支付；同一游戏的详情、游戏库、最近游戏曾出现不同状态。
- **问题：** 客户端页面结构与评审结论不一致；下载与安装被拆成两个用户动作；硬件入口、锁区和兑换范围缺少明确承接。
- **证据：** V1.0 PRD、合并上传版 HTML、2026-10-12 产品文档修改清单及2026-10-13手柄入口位置与Steam激活／下载样式反馈。底部下载栏借鉴 Steam 的集中任务入口；本平台注册 IP 锁区是自身规则。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | GameFusion 自有 Windows、macOS 桌面客户端；商城为内嵌网页，游戏详情、游戏库、任务、启动与设置采用客户端原生界面。增加 Gamesir Connect 顶部右侧手柄入口和同窗口承接区域。本文件不设计开发者后台页面。 |
| 业务边界 | 登录、账号与地区展示、发现、购买或领取、CDK 兑换、权益入库、下载即安装、DLC、更新、修复、卸载与授权启动。商城售卖本体、DLC、捆绑包；平台不售卖 CDK。不新增购物车、社区、好友、聊天、论坛、秒玩、手游库、第三方游戏管理、P2P 或云游戏。 |
| 运营边界 | 消费已审核、符合地区、语言、时间及平台条件的商品与素材；运营提供推荐兜底方案、官方群二维码。硬件侧提供 CDK 分发规则和 Gamesir Connect 具体需求，不在本文件建立新的配置后台。 |
| 人力边界 | 客户端负责容器、原生页面、本机任务、授权和系统适配；服务端负责商城网页、账号、订单、权益、内容和支付；UI 负责独立发行平台视觉；硬件产品负责 Connect 业务与迁移方案；运营负责兜底推荐与二维码；测试、数据、安全分别核对状态、事件和授权。Windows 签名申请由陈韬跟进。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| UID | User ID | C 端和开发者端共用的账号唯一标识。同一 UID 可登录两端，开发者业务权限另行校验。 |
| 地区 | 无 | 注册时由 IP 确定并锁定的账号地区；个人页只读，不按每次访问 IP 改写。 |
| 本体／DLC／捆绑包 | Downloadable Content（DLC） | 本体是游戏主商品；DLC 为独立附加内容权益；捆绑包发放约定本体和 DLC，拥有本体不代表拥有全部 DLC。 |
| CDK | 无 | 外部分发的兑换码，用于兑换约定权益；本平台提供兑换入口，不售卖兑换码。奖励、格式、有效期和地区细则需硬件与权益侧确认。 |
| READY | 无 | 本机内容、校验及安装全部完成，可进入启动预检；已下载字节数达到预期不能单独认定 READY。 |
| Build／Manifest | 无 | 目标平台游戏版本及其内容清单，用于选择内容、校验和启动。 |
| Launch Plan | 无 | 本次启动冻结的账号、游戏、版本、内容、主程序、依赖与有效 DLC 快照。 |
| Ticket／Guard | 无 | Ticket 为绑定本次启动的短时一次性授权；Guard 为游戏侧启动校验。两者不能被按钮状态或本机已购缓存替代。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 用共享商城承接发现与交易，用客户端原生能力承接权益、本机内容和授权启动，并预留硬件结合入口。 |
| 目标用户 | 购买或领取平台 PC 游戏的全球用户，以及通过硬件渠道获得 CDK、使用 Gamesir Connect 的用户。 |
| 核心目标 | 同一账号、同一游戏在不同页面得出一致可用操作；下载完成即可启动预检；兑换与支付只有真实权益确认后才入库。 |
| 使用场景 | 在客户端浏览商品、完成交易或兑换、管理本机游戏、启动游戏，以及访问硬件软件承接区域。 |
| 功能概述 | 顶部商城／游戏库两个主导航，右侧工具区手柄图标承接 Gamesir Connect，中间页面内容，底部集中下载入口；详情、任务、DLC、更新与启动使用同一账号和本机状态。 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 改造并复用 V1.0 关键链路事件；新增 CDK 兑换与硬件承接事件。原最近游戏、下载前确认和内容任务事件继续记录，事件名为兼容历史采集保留，`install_*` 表示一体内容任务而非独立安装入口。Demo 与真实业务数据分开。

#### 4.1.1 指标口径

| 指标名称 | 口径（含分子和分母） | 去重与时间窗口 | 数据源与决策用途 |
|---|---|---|---|
| 下载创建成功率 | 成功创建的一体内容任务数 ÷ 已提交任务创建请求数；拒绝与失败计入分母，重复请求不重复计 | 按 task_id／请求 trace_id 去重；按自然日与版本观察 | install_task_create；检查目录、权益和平台预检阻断 |
| 内容完成率 | 进入 READY 的 task_id 数 ÷ 成功创建的 task_id 数；取消和失败不能算完成 | 按创建日任务 cohort，观察至所选查询截止；明确未终态任务仍未完成 | install_task_create、download_task_stage；核对下载即安装终态 |
| 启动成功率 | 进入 RUNNING 的 launch_id 数 ÷ 已执行预检的 launch_id 数 | launch_id 去重；按发起自然日及版本观察 | game_launch_result；不能按点击或获 Ticket 认定成功 |
| CDK 兑换成功率 | 正式服务确认发放的兑换请求数 ÷ 正式提交请求数 | trace_id 去重；按自然日观察；模拟数据剔除 | cdk_redeem_result；未知结果不计成功，不能用模拟奖励分析业务 |
| 硬件入口使用率 | 进入承接区域的 UID 数 ÷ 有效展示顶部导航及右侧手柄入口的登录 UID 数 | UID＋自然日去重，按客户端平台／版本拆分 | client_nav_view、gamesir_connect_view；只衡量入口使用，不代表调参或升级成功 |

自然日按数据平台已批准统计时区计算；统计时区未提供前需在报表标明所用时区，不能与客户端显示时间混算。

### 4.2 启动授权与客户端安全

| 需求项 | 具体要求 |
|---|---|
| 可信来源 | 权益来自账号／权益服务；商品、订单、媒体和地区来自共享服务；Build／Manifest／Chunk来自内容服务；安装、任务、文件及进程来自原生客户端。页面传入的 owned=true 或本机已购缓存不能成为授权依据。 |
| 启动顺序 | 当前账号与本体／所选DLC权益 → 目标平台／架构、READY、Manifest、主程序、依赖及关键文件 → 冻结Launch Plan → 获取短时一次性Ticket → Guard校验 → 创建进程 → RUNNING。任一阶段失败停止后续动作。 |
| Plan与幂等 | Plan冻结账号、游戏、Build／Manifest、主程序、参数、依赖、有效DLC；同一请求使用幂等键。单游戏只允许一个启动中或运行实例，发行配置明确允许多实例时例外；重复点击不得申请多张并行Ticket。 |
| Ticket绑定与敏感信息 | Ticket至少绑定用户、设备、游戏、Build，并有签发／失效时间、唯一ID或随机数和一次使用约束。具体时长、标识、传递与接口由技术／安全评审确定。界面不得显示原文，日志不得输出Ticket、刷新凭据或完整Plan敏感字段。 |
| 状态与恢复 | PREPARING→AUTHENTICATING→CHECKING_CONTENT→ACQUIRING_TICKET→GUARD_CHECKING→LAUNCHING→RUNNING→EXITED；可执行阶段可进入FAILED。显示准备启动、验证账号与权益、检查游戏文件、获取启动授权、启动游戏、运行中；失败记录阶段、脱敏错误码、时间和恢复动作，区分正常／异常退出。 |
| 进程与断连 | 只有进程进入真实运行态才显示运行中；退出释放临时授权和进程锁。窗口重开或服务重连查询真实进程与启动任务快照，不能按页面状态猜测。 |
| 命令与记录 | 界面和原生任务服务使用版本化命令／事件；每次启动至少记录launch_id、game_id、account_id、platform、build_id、phase、result、脱敏error_code、trace_id和幂等键。按launch_id查询或订阅，断连后可恢复；拒绝未知命令、过期及跨账号事件。 |
| 双端业务与系统适配 | 同账号、商品、订单、权益、任务与主操作在两端一致；本机任务、目录及安装记录按设备／平台独立。macOS处理目录权限、架构、签名／公证；Windows处理盘符／目录、运行依赖与签名。平台无兼容Build必须阻断，不执行错误平台程序。 |
| 程序分发 | 一期Windows客户端需要签名，不上微软商店；Windows SDK优先。macOS SDK及兼容层方案待评估，macOS原型和共用业务规则继续保留，不将未评估SDK宣称已支持。 |
| 账号撤权 | 账号切换、会话过期、退款／撤权后刷新操作并停止新下载授权与新Ticket。已安装文件清理、已运行游戏强制退出由批准安全策略决定，不由前端删记录替代。 |

|---|---|---|---|
| 登录失效 | 停止Ticket申请、清除当前敏感上下文 | 重新登录并再次启动 | 新会话重新读取权益 |
