远程电脑入口位置评审

本轮推荐：游戏库增加独立「远程电脑」卡作为主入口；「我的 → 我的设备」增加电脑入口作为辅助。首页恢复原推荐结构，不常驻远程卡。Mac 使用左侧电脑列表＋右侧选中电脑详情。

这是按俞军“新体验－旧体验－替换成本”的框架，对既有盖世页面作场景走查；不是本人意见，也不是招募用户后的统计结论。Demo 保留三种入口预览供评审，默认采用推荐方案。

1. 四个位置的比较

位置 使用收益 主要成本 建议
游戏库，与 Steam 卡同区域的独立卡 来找游戏、选择游玩方式的既有玩家容易发现；沿用底栏习惯 纯办公用户不一定去游戏库找电脑；卡片宽度要适配四入口 主入口。卡名「远程电脑」，不塞进 Steam 内，不要求绑定 Steam
我的 → 我的设备 → 远程电脑 自己的电脑归属明确，适合设备管理、办公和回访 现有设备区在账号内容之后；当前手柄语义需要区分 辅助入口。原手柄保留，电脑明确单列；共享同一设备数据
推荐旁边增加远程频道 第一屏可发现，不依赖游戏库概念 原栏已有多种游戏频道；加入工具混合内容与操作，进一步拥挤 只保留备选预览，本期不推荐
推荐上方独立卡 曝光强 每个无远程需求的用户都付出首屏空间、注意力成本；不像原有页面 移除旧卡

2. 用户、体验与业务判断

用户处境 推荐路径 解决的问题
已有盖世玩家想串流 游戏库 → 远程电脑 → 设备 去原来找游戏的位置选电脑，不再切换 APP
临时办公或取文件 我的 → 我的设备 → 远程电脑 用“自己的电脑”理解功能，不先选择游戏或工作模式
已使用过的回访用户 游戏库或我的设备 → 同一设备列表 两个入口是同一功能，设备、设置、引导已读一致，返回回到来路
第一次使用 入口 → 首次引导 → 电脑安装与同账号登录 说明在哪台电脑安装；关闭引导不能假装添加成功

产品侧：两个已有位置承接不同任务，不新增底栏和第二套远程产品。设计侧：游戏库沿用平台入口卡样式，但远程是连接能力，不假扮游戏平台；我的设备保留手柄并区分电脑。研发侧：两个入口共用同一设备页与数据，只保留返回来源。业务侧：优先承接已有盖世用户；不能把这个入口决定当成纯办公用户拉新的解决方案。后续若办公成为独立主业务，再重审一级导航。

已核对页面：gh-105 游戏库现有 Steam／Epic／导入游戏；gh-11 与 gh-78 我的设备现有手柄入口；gh-17 首页现有游戏频道。依据这些事实，首页曝光更强不等于整体用户价值更高。没有点击或留存实验数据，因此不编造成功概率。

Mac 直接展示选中电脑

盖世主侧栏保留；进入远程后，左列列出电脑及在线／被控状态，右侧直接显示选中电脑的名称、进入桌面、文件传输、观看模式、终端、更多与快速启动。第一次默认选中一台示例电脑但不连接；点击其他电脑只换右侧详情。全部设备作为次入口保留；设置在左列“我的设备”右上角。空／加载／失败仍显示对应状态，不能凭空选出电脑。

旋转屏幕后收起当前操作／设置／键盘面板，保留连接、设备对象、文档及设置；用户需要时从工具条重新展开。

3. 我的设备与设置

「我的设备」是远程工作区内的标题，只展示远程相关设备，不直接覆盖盖世个人中心中原有的手柄设备管理。设备系统是列表属性，不作平台切换 Tab。

右上齿轮进入远程设置；返回设备列表；从设备列表返回时回到进入远程的游戏库或我的页面。删除远程协助入口、协助编号、收藏协助设备及 UU 式独立「我的」页。会话内的画质、输入和声音仍在操作面板中，不要求退出会话到齿轮设置。

4. 两种引导放在同一张图里

弹窗内用两张流程卡展示完整路径，不采用 Tab、轮播或「下一页」。竖屏上下排列，横屏与 Mac 并排；两种方式和主按钮都应可见。示意图必须标明「控制端 → 被控电脑」，避免看不清究竟要在哪台设备安装。

展示端 第一条路径 第二条路径
手机 APP，标题「添加你的电脑」 这台手机 → 你的电脑。先在要连接的电脑安装盖世电脑端并登录同一盖世账号，按电脑端提示开启被控权限；然后回到本机「我的设备」选择电脑 其他电脑 → 你的电脑。同一台被控电脑也可由另一台电脑连接；在另一台电脑安装并登录同一盖世账号，再从「我的设备」选择它。这是第二种使用方式，不是手机连接的前置步骤
Mac，标题「添加你的设备」 手机 → 这台 Mac。手机安装盖世 APP 并登录同一盖世账号；本机按提示完成被控权限，随后在手机设备列表选择本机 其他电脑 → 这台 Mac。其他电脑安装盖世电脑端并登录同一盖世账号；本机完成被控权限，随后在其他电脑的设备列表选择本机

手机端已经安装 APP，不再让用户扫本机二维码下载手机 APP；只给出电脑端获取方式。Mac 端可在手机路径中提供 APP 下载二维码，在其他电脑路径中提供电脑端下载网址。下载地址和二维码必须指向实际有效的官方分发页，不能用装饰二维码冒充可用入口。

Mac 引导中的「本机」指当前 Mac，不能写成手机控制手机。两条路径依赖对应主控端和被控端能力；Demo 表达的是目标设计，不能据此认定 Mac 被控服务已实现。若发布版本不支持 Mac 被控，该引导不能随功能直接上线，应按实际支持组合调整。

5. 首次与再次查看

  1. 用户首次进入「远程电脑」时展示，不在打开盖世首页时弹出。未登录时先沿用已有盖世登录，再进入设备页和引导；不新建另一套远程账号。
  2. 底部主按钮为「知道了」。点按钮或关闭后进入设备列表；这只表示看过引导，不表示安装、授权或添加设备成功，也不自动生成在线设备。
  3. 同一账号在同一客户端只自动展示一次；再次进入不重复打断。设置中的「添加设备引导」可随时重看，两种路径始终同时展示。
  4. 没有设备时展示空态及「添加设备」操作，打开同一份引导。已有设备时直接显示真实列表；设备何时出现、能否控制，以实际登录、权限与在线状态为准。

6. 采用的证据与冲突处理

  • 首页结构采用 盖世 6.3.0 首页实机图 及 盖世 APP 与 Mac 基线。这张首页图能证明原有导航和内容位置，不能证明本次新增入口已存在。
  • 调研/截图/G02-盖世首页.png 实际画面是「绑定手机号」，不用于首页布局判断。以实际画面为准，不按文件名作结论。
  • 用户本轮两张 UU 图分别展示手机、其他电脑控制本机的引导；采用其安装与同账号登录的语义。用户明确要求合并展示，因此不复制原图的两个 Tab；图中的 UU 账号、二维码和域名不进入盖世界面。
  • 此结论替代旧文档中「Demo 直接打开孤立远程工作区」的安排。新版 Demo 应从盖世 APP 外壳进入新增入口，远程功能本身无需重做另一套业务流程。
