# 远程电脑入口与首次引导

**推荐在盖世 APP 首页频道栏下、今日推荐上，增加一条「远程电脑」入口。进入后展示「我的设备」，相关设置收在该页右上角。保留盖世原有五个底栏，不保留 UU 的「远程协助」与独立「我的」导航。首次进入时，用同一个弹窗完整展示手机和其他电脑两种连接方式。**

这是在盖世内增加远程能力的设计方案，功能链路继续采用本轮已确认的设备列表、设备详情、桌面控制与文件传输。入口、引导和导航整合是本轮新增设计，不代表已上线。

## 1. 入口放在哪里

实际首页已有搜索、消息、设备形状图标、推荐／云游戏／PC 游戏等频道，以及推荐内容；底部是主页、社区、排行榜、游戏库、我的。本轮保留这些结构，在频道栏与「今日推荐」之间增加一条紧凑入口。

入口展示电脑图标、**远程电脑**、说明「连接自己的电脑，继续游戏和工作」及向右箭头。点击直接进入「我的设备」，不先选游戏／办公，也不选择 Windows／Mac。返回时回到原来的盖世首页。横屏保持同一位置关系，不把整套 APP 变成远程专用客户端。

| 备选位置 | 对用户的影响 | 取舍 |
|---|---|---|
| 首页频道栏下、今日推荐上 | 打开盖世即可看到；游戏和工作都能理解；会占用一条推荐内容空间 | 本轮采用紧凑入口，不使用大宣传卡 |
| 游戏库内的 PC 远程 | 对已有串流玩家容易理解，但工作用户可能不会去游戏库找电脑 | 不作为本轮主入口，也不额外增加一条重复路径 |
| 首页右上现有设备图标 | 改动看似最小，但现有点击落点没有可靠证据；图标也不能说明它是手柄还是远程电脑 | 保留原入口，不擅自更换含义 |
| 底栏或「我的」 | 新增底栏挤占现有导航；藏入「我的」会增加每次连接的路径 | 不新增底栏，不把主入口藏入设置 |

Mac 继续使用既有盖世主侧栏，增加「远程电脑」项；工作区同样显示「我的设备」和右上设置。既有全局账号与客户端设置保持原职责，这里的设置只管理远程相关项，不再复制一套账号中心。

## 2. 为什么值得这样放

按俞军的用户价值框架，这里的判断重点是用户是否能以更低成本完成原来的任务，而不是首页多了一个模块。这是依据其方法论作出的产品推断，不是本人意见或真实用户实验结论。

- **已有盖世用户：** 手机上玩电脑游戏时，可以从已有 APP 连接自己的电脑，减少切换应用和重新寻找入口的成本。前提仍是连接和控制可用，入口本身不等于体验更好。
- **临时工作用户：** 想回到电脑改文件、处理工作或继续 AI 会话时，「远程电脑」直接说明操作对象；不要求先理解 PC 游戏、模拟器、云游戏的区别。
- **已有 UU 用户：** 保留熟悉的设备列表→详情→桌面链路，减少重新学习。盖世中的价值是已有账号与使用路径的整合，不能仅凭一套相似页面宣称足以替代 UU。

本轮用一条可见入口解决发现问题，用原有五个底栏保留老用户习惯。是否值得占据更大的首页位置，后续看进入后实际完成连接和持续使用的情况；目前没有数据支持增加一个一级业务 Tab。

## 3. 我的设备与设置

「我的设备」是远程工作区内的标题，只展示远程相关设备，不直接覆盖盖世个人中心中原有的手柄设备管理。设备系统是列表属性，不作平台切换 Tab。

右上齿轮进入远程设置；返回恢复设备列表及滚动位置。删除远程协助入口、协助编号、收藏协助设备及 UU 式独立「我的」页。会话内的画质、输入和声音仍在操作面板中，不要求退出会话到齿轮设置。

## 4. 两种引导放在同一张图里

弹窗内用两张流程卡展示完整路径，不采用 Tab、轮播或「下一页」。竖屏上下排列，横屏与 Mac 并排；两种方式和主按钮都应可见。示意图必须标明「控制端 → 被控电脑」，避免看不清究竟要在哪台设备安装。

| 展示端 | 第一条路径 | 第二条路径 |
|---|---|---|
| 手机 APP，标题「添加你的电脑」 | **这台手机 → 你的电脑**。先在要连接的电脑安装盖世电脑端并登录同一盖世账号，按电脑端提示开启被控权限；然后回到本机「我的设备」选择电脑 | **其他电脑 → 你的电脑**。同一台被控电脑也可由另一台电脑连接；在另一台电脑安装并登录同一盖世账号，再从「我的设备」选择它。这是第二种使用方式，不是手机连接的前置步骤 |
| Mac，标题「添加你的设备」 | **手机 → 这台 Mac**。手机安装盖世 APP 并登录同一盖世账号；本机按提示完成被控权限，随后在手机设备列表选择本机 | **其他电脑 → 这台 Mac**。其他电脑安装盖世电脑端并登录同一盖世账号；本机完成被控权限，随后在其他电脑的设备列表选择本机 |

手机端已经安装 APP，不再让用户扫本机二维码下载手机 APP；只给出电脑端获取方式。Mac 端可在手机路径中提供 APP 下载二维码，在其他电脑路径中提供电脑端下载网址。下载地址和二维码必须指向实际有效的官方分发页，不能用装饰二维码冒充可用入口。

Mac 引导中的「本机」指当前 Mac，不能写成手机控制手机。两条路径依赖对应主控端和被控端能力；Demo 表达的是目标设计，不能据此认定 Mac 被控服务已实现。若发布版本不支持 Mac 被控，该引导不能随功能直接上线，应按实际支持组合调整。

## 5. 首次与再次查看

1. 用户首次进入「远程电脑」时展示，不在打开盖世首页时弹出。未登录时先沿用已有盖世登录，再进入设备页和引导；不新建另一套远程账号。
2. 底部主按钮为「知道了」。点按钮或关闭后进入设备列表；这只表示看过引导，不表示安装、授权或添加设备成功，也不自动生成在线设备。
3. 同一账号在同一客户端只自动展示一次；再次进入不重复打断。设置中的「添加设备引导」可随时重看，两种路径始终同时展示。
4. 没有设备时展示空态及「添加设备」操作，打开同一份引导。已有设备时直接显示真实列表；设备何时出现、能否控制，以实际登录、权限与在线状态为准。

## 6. 采用的证据与冲突处理

- 首页结构采用 [盖世 6.3.0 首页实机图](../../竞品分析/GUANWANGGAID-48/evidence/mumu/gh-17-630-start.png) 及 [盖世 APP 与 Mac 基线](../调研/盖世APP与Mac基线.md)。这张首页图能证明原有导航和内容位置，不能证明本次新增入口已存在。
- `调研/截图/G02-盖世首页.png` 实际画面是「绑定手机号」，不用于首页布局判断。以实际画面为准，不按文件名作结论。
- 用户本轮两张 UU 图分别展示手机、其他电脑控制本机的引导；采用其安装与同账号登录的语义。用户明确要求合并展示，因此不复制原图的两个 Tab；图中的 UU 账号、二维码和域名不进入盖世界面。
- 此结论替代旧文档中「Demo 直接打开孤立远程工作区」的安排。新版 Demo 应从盖世 APP 外壳进入新增入口，远程功能本身无需重做另一套业务流程。


仅 Mac 显示手机 APP 下载二维码；APP 引导只提示电脑端下载、安装和同账号登录。
