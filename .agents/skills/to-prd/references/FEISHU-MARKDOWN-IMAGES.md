# 飞书 Markdown 配图规范

## 目标

在 PRD 中输出飞书可识别的标准 Markdown 图片，并为飞书无法抓取外链的情况保留可执行兜底。语法正确、链接公网可访问和飞书成功转存是三个独立条件，不得混为一谈。

## 标准写法

表格外的图片独占一行，图片行前后各留一个空行；表格单元格内的图片使用 `<br>` 与前后内容分隔，并保证每张图只对应一个短标题：

```markdown
![探索场景的租号发现与曝光](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@2efa2b11d4f60f7d9e1aa775d31fc1be69d5b1c6/public/prd/mac-rental/c01-rental-discovery-explore.png)

*图 4.2.1-1：探索内容中的租号金额、在租热度和编辑推荐。*

> **界面文字与布局：** 左侧为导航，右侧为内容区；卡片展示封面、游戏名、红色“¥X 租号”和灰色“XX 在租”。
```

必须满足：

- 只用 `![图标题](图片直链)`，不使用 HTML `<img>`、引用式图片、相对路径、`file://`、Base64 或占位域名。
- 方括号内只写简短、可辨识的界面名称，例如“租号订单中心”或“售后申请弹窗”。不要写图号、章节号、中文冒号或一整句界面描述。
- 图片标题最多 16 个字符；禁止中文或英文冒号，禁止以“图 1”“3.1.2”等图号、章节号开头。
- 将稳定图号和完整说明放在下一行独立图注中，例如 `*图 4.2.1-1：探索内容中的租号金额、在租热度和编辑推荐。*`。
- 图片直链使用 HTTPS，最终响应为 `200`，`Content-Type` 为 `image/png`、`image/jpeg`、`image/webp` 或 `image/gif`。
- 链接不得依赖登录、Cookie、Referer、防盗链白名单、临时签名或即将过期的查询参数。
- 仓库图片链接必须固定到不可变提交版本，不使用会漂移的分支名；优先使用已验证可被飞书抓取的对象存储或图床。
- GitHub Raw、jsDelivr 等链接能在浏览器打开，只能证明公网可访问，不能单独证明飞书导入一定成功。

## PRD 批量处理流程

1. 盘点目标 Markdown 中全部 `^!\[` 图片引用，记录图片数量、图号、标题、原图文件和所在章节。
2. 若用户说“全部图片”，处理文档中的全部图片，不只处理当前章节或示例图。
3. 将每处图片统一为标准单行语法，方括号内使用短标题，并保持图片、独立图号图注、界面描述连续出现。
4. 每张图补一段“界面文字与布局”，至少写清页面区域、核心 UI 文案、关键控件、状态或颜色；即使图片抓取失败，读者仍能理解需求。
5. 对全部链接执行下载校验，检查最终状态码、MIME 类型、文件大小大于 0，并确认无占位域名。
6. 能访问飞书时，先用 1 张图做真实导入冒烟测试，再批量处理；“真实导入”必须看到飞书完成转存后的实际图片，不得用浏览器打开链接或脚本返回 200 代替。
7. 不能访问飞书时，明确说明“仅完成公网验证，飞书转存未验证”，保留标准 Markdown 和原图目录／原图包；只有用户明确要求或同意备选格式时才生成图片已内嵌的 DOCX。
8. 保留原尺寸图片文件及“图号—文件名—章节”映射，便于失败后上传替换。

## 已验证的飞书兼容性规则

- 在同一批 25 张图片、同一组 HTTPS 链接不变的情况下，将图片标题从“图号 + 中文冒号 + 长界面名”恢复为短界面名后，飞书可正常加载。
- 因此默认使用 `![短界面名](图片直链)`，图号与详细描述必须放在图片下方，不得放入方括号。
- 遇到图片全部加载失败时，先恢复短标题做最小化验证，再检查链接提交号、响应状态和飞书抓取能力。

## 飞书使用与失败兜底

直接粘贴时，复制包含图片语法的 Markdown 正文到飞书文档，等待图片加载完成后再关闭页面。若飞书显示“无法导入该图片”，该外链方案立即判定为飞书导入失败，不再用重复公网校验代替修复：

1. 先与已成功导入的 Markdown 对比图片语法、标题、格式、固定提交和链接结构，不直接改文档格式。
2. 固定地址曾失败但原图有效时，获得 Git 发布授权后可改用包含同一原图的新固定 SHA，避开飞书旧缓存。
3. 先用 1 张图做真实飞书导入冒烟；成功后再批量替换。只完成公网校验时不得声称已修复。
4. 冒烟仍失败时，交付标准 Markdown 和原图目录／原图包；用户同意后再改用图片内嵌 DOCX或在飞书中手动上传原图。
5. 保留原图号、图注和“界面文字与布局”，不要用截图二次压缩后替换原图。

没有飞书图片 token、开放平台上传能力或已验证的飞书可抓取图床时，外链图片无法保证自动转存成功。默认交付标准 Markdown 和原图目录／原图包；DOCX 需用户明确要求或同意，不得伪造“不会报错”的保证。
