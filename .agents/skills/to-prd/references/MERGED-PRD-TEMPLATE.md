## 成稿硬规则

1. 不生成目录，使用飞书自动目录。
2. 不写功能优先级、详细开发计划链接、研发评估状态、执行准备度、目标上线时间、独立验收章和独立数据校验表。
3. C/B 分端，按页面拆分；一页一张六要素表，不使用功能汇总大表或公共规则编号。
4. 删除无决策价值、重复和 AI 腔内容。能短则短，但不得让研发、测试、设计、运营或数据人员猜规则。
5. 第四章保留“数据结论”，无埋点写“不涉及”；第五章保留“待确认项”，无内容写“无”。
6. 轻量需求删除不需要的 2.2、端、小节、非功能表和附录。

## 模板生成约定（不写入 PRD 成稿）

### 页面拆分

- 一页一张六要素表；同页的模块、元素、按钮、文案、状态、校验和异常写在同表，不继续拆页。
- 页面内独立子功能用一张四列汇总表，一项一行，并放在页面最末。
- 复杂风险表放在页面主表之后、子功能表之前。

### 页面图示

- 每页 1—3 张，顺序为前置→当前→后续；当前页面必填。
- 产品流程图另行合成一张横向图，不占单页图示的三张上限。
- 图示不能替代全部元素、具体文案、展示和交互说明。

### C/B 端

- C 端写清用户所见、操作、数据来源及后台配置对本端的影响。
- B 端写清权限、字段、校验、生效／失效及 C 端最终表现。
- 不使用 `R-01` 等公共规则编号，不写“详见 B 端”或“同 C 端”。两端必要重述由生成和校验过程核对一致性。

### 描述

优先用：

> [对象]在[前置条件]下执行[动作]；系统[处理方式]；成功后[结果]；失败时[反馈与恢复]。

- 禁用“旨在、赋能、助力、沉浸式”等 AI 腔。
- 删除无用小节、模板提示、重复原文和不影响决策的内容。
- 能用短词不用长词，能用一句不用两句；但不能省掉实现和测试所需信息。
- 禁止只写“支持、优化、兼容、同上、按配置展示”。
- 普通规则用编号和加粗关键词；仅对易漏且会造成明显返工的内容使用 `> **重点：**`。
