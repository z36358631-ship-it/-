# 基础规范

## 三层令牌

使用 `Primitive → Semantic → Component` 三层。实现时引用 `assets/gamehub-app-tokens.css`，不要在页面配方里重复硬编码。

### Primitive

- 中性色：`#09090B` 基底、`#111113` 页面、`#1A1A1D` 卡片、`#252529` 抬升、`#34343A` 交互表面。
- 文字：`#F5F5F7` 主文字、`#A4A4AC` 次文字、`#6D6D75` 禁用。
- 品牌与业务：`#FFC928` 黄色主操作、`#12A8E8` 青蓝、`#8B68FF` 紫、`#FF8A24` 评分橙、`#00C777` 成功绿。
- 空间：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40。
- 圆角：8 / 12 / 16 / 20 / 28 / pill。

### Semantic

- 背景区分 `base`、`environment`、`media-overlay`，环境色不能成为全局固定背景。
- 表面区分 `default`、`elevated`、`selected`。
- 操作区分品牌主操作、业务青蓝操作、次操作与危险操作。
- 边框以 8%–14% 白色透明度建立层级，不依赖浓重阴影。

### Component

组件令牌覆盖按钮高度、导航高度、卡片圆角、Chip、输入、弹层、封面比例与手柄焦点环。

## 排版

- 系统无衬线字体栈，不依赖在线字体。
- 辅助文字 12–13；正文 14–16；卡片标题 16–18；区块标题 20；页面标题 24–28；展示标题 32–40。
- 游戏名最多两行；横屏密集卡默认一行省略。
- 数字与单位保持同一基线；评分缺失显示“暂无评分”，不要显示 `0`。

## 竖屏 Shell

- 设计容器 `402×874`；内容左右边距 20–24。
- 顶部包含状态安全区与页面工具栏；底部导航固定，正文为独立滚动容器。
- 首页与频道使用单列纵向流，卡片内部可横向轨道；搜索结果每排 2 个游戏封面。
- 触控目标不小于 44×44。

## 掌机横屏 Shell

- 设计容器 `874×402`；顶部导航和状态区固定。
- 采用横向轨道、多列网格、左右双面板或首屏沉浸 Hero。
- 为可聚焦元素提供明显焦点环和 LB/RB、A/B 等手柄提示。
- 不复用竖屏底部导航，不整体缩放竖屏 DOM。

## 图形与资源

- 使用项目内图片或内联 SVG；不要用 Emoji 充当图标。
- 无真实封面时使用克制的结构化占位，不伪装为真实游戏资产。
- 媒体背景需有深色遮罩以保证文字对比度。

## 动效与无障碍

- 常规反馈 140–180ms；弹层 220–260ms；尊重 `prefers-reduced-motion`。
- 文字与背景保持足够对比度；焦点可见；按钮有可读名称。
- 模态弹层打开后锁定背景交互，关闭后返回原焦点。
