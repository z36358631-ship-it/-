## 二、背景与目标

背景：盖世用户通过模拟器玩PC游戏，存档管理面临三个痛点：

1）从零开始肝太耗时间；

2）Wine Prefix崩溃/换手机导致存档丢失；

3）想体验全收集但不想自己打。

现有方案采用单个云存档 ¥6 永久购买。为降低用户连续体验多个存档的决策成本，本期在保留单买的基础上，新增“云存档月度套餐”试运营方案。

目标：在APP内建立“单个存档永久购买 + 30天套餐”双权益体系，验证用户对全部存档短周期畅用的需求，同时控制玩家寄售奖励与退款风险。

核心挑战：Wine Prefix路径自动识别与导入、永久权益与套餐权益鉴权、套餐周期顺延、首次成功使用与奖励去重、使用与退款并发一致性。

本期已确认口径：

- 云存档月度套餐试运营优惠 ¥18/30天，不展示划线原价。
- 支付成功后立即生效，非自动续费；提前续费创建独立未来周期。
- 套餐有效期内可不限次使用全部官方存档和玩家寄售存档；原 ¥6 单买永久权益继续保留。
- 套餐周期一旦产生成功使用记录即不可退款；未成功使用的当前周期及尚未开始的未来周期可联系客服申请后台人工退款。

待验证项：用户购买意愿、续费意愿、对 ¥6 单买的影响、奖励实际兑换成本及客服压力，均以试运营数据为准。

## 三、故事介绍

### 3\.1 用户与运营场景

❗用户与运营场景：

- **C端买方（张三）**：张三想玩GTA5线上模式但不想肝几百小时。他在游戏详情页点击"存档"tab，看到一个"500万CR\+440辆车全收集"的存档，标价¥6\.00，877人已购买。他点击购买，微信支付¥6后，存档出现在"我的存档"中。他点击"使用"，系统自动将存档放入Wine Prefix正确路径并重启。启动游戏后直接从满级状态开始玩。

- **C端卖方（李四）**：李四通关了艾尔登法环全Boss，他在"我的存档"中点击"上传"，选择存档文件，填写标题"全Boss击杀\+全武器收集"，定价¥6\.00，提交上架。

- **C端月包用户（王五）**：王五想在一个月内体验多款游戏存档。他在存档广场开通“云存档月度套餐”，支付试运营优惠 ¥18 后立即获得30天权益。套餐有效期内，他可不限次使用官方和玩家寄售存档；需要长期保留某个存档权益时，仍可 ¥6 永久购买。

- **运营人员**：运营人员在后台配置套餐售卖时间与奖励规则，查看套餐订单、独立周期、成功使用流水和奖励状态；对未成功使用的当前周期或尚未开始的未来周期进行人工退款。

### 3\.2 价值分析

❗价值分析：

- **直接变现**：存档单价¥6，平台100%收入，寄售人成交获赠30分钟云时长

- **扩展变现**：新增试运营优惠 ¥18/30天套餐，以短周期畅用降低多存档体验门槛；是否提升总收入需结合单买变化、退款与奖励成本评估

- **提升留存**：买了存档的用户有更强的游戏动力，游戏时长和回访率提升

- **供给飞轮**：玩家上传存档获得云游戏时长奖励→更多人上传→存档覆盖面更广→更多人购买或使用

- **差异化壁垒**：一键导入到Wine Prefix是盖世独有能力，竞品做不到

### 3\.3 核心体验路径

❗核心链路：

- **买方核心链路**：
游戏详情页"存档"tab → 浏览存档列表 → 查看详情 → 支付购买 → 我的存档 → 一键导入 → 启动游戏

- **月包开通链路**：
存档广场套餐卡/存档详情 → 查看权益、到期时间、非自动续费与退款条件 → 支付 ¥18 → 当前30天周期立即生效 → 使用存档 → 成功加载并启动游戏

- **月包提前续费链路**：
套餐状态卡/存档详情 → 点击“续费30天” → 查看续费后到期时间 → 支付 ¥18 → 创建独立未来周期 → 当前周期结束后未来周期生效并重置奖励名额

- **月包到期链路**：
再次下载、加载或切换套餐存档 → 到期拦截 → 选择 ¥18 续费30天或 ¥6 永久购买当前存档；已加载形成的本地游戏进度不删除、不回滚，用户仍可启动游戏

- **卖方核心链路**：
我的页 → 我的存档 → 上传存档 → 选择游戏\+文件  → 上架 → 成交后30分钟云时长（有效期7天）收益到账

- **运营核心链路**：
后台存档管理 → 新建官方存档 → 上传文件\+配置 → 发布 → 订单退款

- **月包运营链路**：
后台月度套餐配置 → 套餐订单与周期 → 查看成功使用/奖励流水 → 判断退款资格 → 人工退款或记录不可退款原因 → 统计收入、续费、奖励与资源成本

### 3\.4 产品指标预测

❗产品指标预测：

1. 存档浏览→购买转化率：首月预测 3\-5%

2. 一键导入成功率：目标 \> 95%

3. 首批覆盖：Top 20游戏，每游戏2\-3个官方存档

4. 玩家上传：首月预测50\+个玩家存档通过审核

5. **月度套餐试运营指标（建议口径，目标值待基线确认）**：

    - 套餐卡曝光→支付成功转化率
    - 套餐首购人数、提前续费人数、到期续费率
    - 套餐用户成功使用率、人均成功使用次数、人均不同存档数
    - 套餐退款申请率、退款成功率、相关客服率
    - 套餐上线前后 ¥6 单买订单量与单买收入变化
    - 奖励待发/实发/实际兑换分钟、异常奖励率及真实资源成本
    - 试运营护栏：连续3日“奖励实际资源成本/套餐净收入”超过35%时暂停奖励发放并排查；暂停期间已命中奖励保留为“暂停发放”，恢复后继续风险审核

### 3\.5 路径规划

❗路径规划：

- **V1\.0（已规划）**：跑通官方存档上架\+用户购买\+一键导入闭环；开放玩家上传\+审核\+定价

- **V1\.1（本期）**：保留 ¥6 单买，新增试运营优惠 ¥18/30天月度套餐、套餐周期、使用奖励、到期拦截、人工退款与运营后台

- **后续候选（未排期）**：试玩功能（加载存档体验5分钟再决定买不买）。自动续费、季度/年度套餐、优惠券、套餐赠送、复杂收入分成池与独立会员中心不在本期范围内

## 四、概要设计

### 4\.1 模块设计

- C端：存档广场套餐卡、存档详情双权益、开通/续费确认、我的存档套餐状态与月包存档分区、到期拦截、游戏中侧边栏复用。
- B端：月度套餐配置、套餐订单与周期、成功使用流水、作者奖励流水、人工退款与套餐数据统计。
- 服务端规则：永久权益优先、套餐周期鉴权、支付幂等、使用/奖励/退款一致性、存档去重与风控。
- 上线范围：本期仅国服包开放月度套餐及云游戏时长奖励；海外 Global、GooglePlay 包不展示套餐入口、不执行云游戏时长奖励。原 ¥6 单买是否在海外展示沿用现有线上规则。

#### 4\.2\.1 双权益与套餐周期规则

|规则项|处理方式|
|---|---|
|正式名称|云存档月度套餐|
|价格与周期|试运营优惠 ¥18/30天，不展示划线原价；每笔支付订单生成一个独立30天套餐周期|
|生效与续费|首次支付成功后立即生效；非自动续费。提前续费时，未来周期开始时间等于当前周期结束时间，结束时间为开始时间后30天|
|权益范围|有效周期内不限次使用全部官方存档和玩家寄售存档；原 ¥6 单个存档永久购买并存|
|权益优先级|永久单买权益 > 有效月包 > 无权益。客户端只展示服务端返回的永久权益、当前周期与未来周期，不以本地缓存作为最终鉴权|
|周期切换|提前续费仅创建未来周期，不改变当前周期起止时间、使用记录和奖励名额；未来周期正式开始后成为当前周期，并重新获得3个奖励名额|
|到期处理|源存档再次下载、加载或切换时拦截；已加载形成的本地游戏进度不删除、不回滚、不限制启动游戏|
|试运营提前续费上限|固定最多提前续费1期，即同时最多保留当前周期与下一个周期；试运营期间后台不可修改|

#### 4\.2\.3 套餐成功使用与作者奖励

1. “成功使用”仅指存档成功加载并成功启动游戏；仅点击、仅下载、用户取消、加载失败或启动失败均不计入。
2. 每个30天套餐周期独立拥有3个奖励名额。按成功使用时间，前3个不同的玩家寄售存档首次成功使用后，各奖励作者30分钟云游戏时长，奖励有效期7天。
3. 官方存档不奖励、不占名额；同一周期重复使用同一存档不奖励、不占名额，但两者均属于成功使用，周期因此不再满足退款条件。
4. 不同存档按内容指纹或规范化存档ID去重，重复上传同一文件不得重复获奖。同一作者的不同有效存档可以分别获得奖励；异常集中获奖进入风控审核。
5. 奖励先记录为“待发放”，风险检查通过后T+1发放。业务唯一键为“套餐周期 + 规范化存档”；套餐周期已唯一绑定买家，服务重试不得重复发放。
6. 当前周期已占用名额不因提前续费重置；未来周期正式开始后重新获得3个名额。单周期奖励成本上限为90分钟。
7. ¥6单买寄售奖励沿用原规则，和月包“成功使用奖励”分开记录、分开统计，不能因同一业务事件重复发放。

#### 4\.2\.4 退款规则

|场景|是否可退|处理方式|
|---|---|---|
|当前套餐周期无任何成功使用记录|可申请|用户联系客服，由后台人工校验并退款；C端不提供自助退款入口|
|当前套餐周期已有任意成功使用记录|不可退|后台显示“已使用，不可退款”；官方存档使用和重复使用也计入成功使用|
|尚未开始的未来续费周期|可申请|单独退款并移除对应未来周期，不影响当前周期或其他有效权益|
|退款与首次使用并发|以服务端结果为准|使用写入与退款资格校验必须基于同一周期数据并加并发控制，只允许一个操作成功|
|支付成功但客户端未收到结果|不重复支付|按支付流水查询订单与周期；每个支付订单只创建一次套餐周期|
|¥6永久单买|沿用原规则|不提供用户自助退款；内容不匹配、描述不符等质量争议按原人工核实流程处理|

#### 4\.3\.1 边界条件\-内容侧

|场景|处理方式|
|---|---|
|存档文件含恶意程序|上传后服务端安全扫描，未通过拒绝上架|
|存档与标注游戏不匹配|用户投诉→人工核实→下架\+退款|
|存档截图与实际不符|用户举报"描述不符"→人工核实→属实则下架\+退款|
|存档文件过大（\>500MB）|拦截上传，提示"文件过大"|
|玩家重复上传同一存档|按内容指纹或规范化存档ID归一；同一内容在同一套餐周期只按首次成功使用判断奖励|
|内容指纹计算失败|不占用奖励名额、不生成待发奖励；记录异常供运营复核，不影响用户在有效权益下继续使用|

#### 4\.3\.2 边界条件\-用户侧

|场景|处理方式|
|---|---|
|购买后卸载APP重装|购买记录绑定账号，重装登录后仍可下载导入|
|卖家自买自卖|禁止购买自己上传的存档，按钮显示"这是你的存档"|
|买家二次售卖|**买家仅使用云存档，无法生成存档进行二次售卖**|
|玩家下架存档|已购买用户不受影响，仍可下载导入|
|单日上传限制|单游戏上限不限制|
|单游戏寄售过多|单游戏上限寄售4个，超出toast提示“已达到寄售上限，请删除寄售存档后重试”|
|套餐到期后用户正在游戏|不强制退出，不删除或回滚已加载的本地进度；再次下载、加载或切换套餐存档时才拦截|
|套餐到期时间跨时区|客户端统一展示服务端返回时间，并明确时区；鉴权以服务端时间为准|
|首次使用与退款同时发起|服务端以同一套餐周期加并发控制；成功使用已写入则拒绝退款，退款先成功则拒绝该周期继续使用|
|支付回调重复|按支付流水和订单幂等处理；同一支付订单只能创建一个套餐周期|
|提前续费支付成功但页面未刷新|重新查询服务端当前/未来周期并恢复展示，不根据本地点击次数补建周期|
|月包第4个不同玩家寄售存档|允许正常使用，不占奖励名额、不发奖励；周期成功使用次数正常累计|
|奖励发放失败|保留“待发放/发放失败”记录，由后台重试；业务唯一键不变，不重复发放|
|奖励暂停开关开启|不影响用户套餐权益与成功使用；新命中奖励记为“暂停发放”并占用名额，恢复后转为“待发放”继续审核与T+1发放|

#### 4\.3\.3 套餐后台状态与操作

|对象|状态|可执行操作|状态说明|
|---|---|---|---|
|套餐商品|未开始|编辑、启售前校验|活动开始时间未到，不允许新购|

|套餐周期|当前有效且已使用|查看|不可退款；仍可在到期前继续使用|
|套餐周期|未来待生效|查看、人工退款|退款仅移除该未来周期|
|套餐周期|已到期|查看|不再提供套餐源存档鉴权，保留流水|
|套餐周期|已退款|查看退款记录|不可再次退款或恢复|
|作者奖励|待发放|查看、风控审核|风险检查通过后T+1发放|
|作者奖励|已发放|查看流水|奖励有效期7天|
|作者奖励|发放失败/暂停|查看、按唯一键重试|重试不得重复发放|

## 七、运营需求

1. **官方存档内容（P0，上线前必须）**

- **Top 20热门游戏清单**：确定首批覆盖哪20款游戏

- **每款游戏2\-3个官方存档文件**：通关存档 / BOSS存档 / 全收集存档等（小黑盒有存档广场）

- **每个存档的配套素材**：

    - 标题文案（如"500万CR\+440辆车全收集"）

    - 内容描述文案

    - 封面图 \+ 多张截图（用于轮播展示）

    - 存档类型标签（通关存档/BOSS存档）

2. **文案配置（P0）**

- **存档使用说明弹窗文案**：点击"❓说明"后展示的内容（后台配置）

- **退款提示文案**：区分两类权益。¥6永久单买不提供用户自助退款；月度套餐在首次成功使用前可联系客服申请人工退款，成功使用后不可退款；未来周期可单独人工退款

3. **运营规则确认（P0）**

- **玩家寄售审核标准**：什么样的存档通过/驳回，需要出一份审核SOP

- **用户投诉处理流程**：PRD写了48小时内下架，运营侧需要有对应的响应机制

- **"存档与游戏不匹配"投诉处理流程**：人工核实→下架\+退款的操作规范

4. **定价与分成策略确认**

- **官方存档定价表**：每个存档目前定的¥6，看是否需要外放时以试运营口径，方便后续调价以及定价确认

- **卖家分成：**每笔成交获赠30分钟时长卡，有效期7天，方案确认

- **月包使用奖励**：每个30天周期前3个不同玩家寄售存档首次成功使用后，各奖励作者30分钟云游戏时长，有效期7天；官方和重复存档不占名额，新周期开始后重置

- **试运营售价**：云存档月度套餐“试运营优惠 ¥18/30天”，不展示划线原价，非自动续费

5. **上线后运营计划**

- **首批存档上架排期**：什么时候完成Top 20游戏的存档上传

- **玩家上传引导策略**：如何激励玩家上传存档（"每成交1次赠送30分钟云游时长"的宣传物料）

- **玩家使用引导文章：**告知用户如何购买并使用存档

- **数据监控关注指标**：浏览→购买转化率（目标3\-5%）、导入成功率（目标\>95%）

6. **月度套餐试运营准备（P0）**

- 配置套餐活动起止时间、售卖状态、奖励暂停开关与试运营总预算；最大提前续费期数固定为1
- 客服培训：识别当前周期/未来周期，核验成功使用记录，执行人工退款并记录原因
- 风控准备：内容指纹去重、异常集中获奖审核、奖励T+1发放与失败重试
- 报表准备：套餐首购/续费/退款、成功使用、单买变化、奖励发放与实际兑换、真实资源成本
- 试运营护栏：奖励实际资源成本连续3日超过套餐净收入35%时暂停奖励并排查；实际资源成本按“实际兑换分钟 × 云游戏每分钟边际成本”计算
- 评估公式：套餐收入 + 单买收入 - 奖励及支付成本；不能只用套餐订单量判断试运营成功

7. **运营执行口径**

- 最多提前续费1期，同时最多保留当前周期和下一个周期
- 奖励暂停期间新命中奖励进入“暂停发放”，占用本周期奖励名额；恢复后继续审核与发放
- 试运营总预算由商业化运营在后台配置，未配置预算不得开启售卖；数据看板由商业化运营维护
- 当前周期剩余时间≤3天时仅在页面内显示“即将到期”，本期不增加Push触达
- 当前未使用周期退款时，已有未来周期仍按原计划时间生效，不提前起算；用户如需退款，允许分别处理当前周期与未来周期
