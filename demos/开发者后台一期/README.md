# 盖世游戏开发者后台一期 Demo

本目录是受邀开发者、平台发行运营和平台测试人员使用的离线评审 Demo。它用统一后台壳串联单一签约厂商、单款 Windows 游戏从资料、CDKEY 供给、包体测试发布到规则式精准投放与发行数据查看的 MVP；所有操作仅改变当前页面内存中的演示状态。

## Figma 终稿基线

- 当前视觉基线：[盖世游戏｜开发者后台一期](https://www.figma.com/design/arz12KT0WQ7UsHHglFtReN/)。
- Figma 的 6 个正式 Page 包含 1 个全局流程索引、4 个业务模块和 1 个组件母版；Demo 对应 4 个业务模块的 37 个页面，数量保持 `9／6／13／9`。
- `build.mjs` 会在生成 HTML 前核对 `figma-page-map.json`、`frame-map.json` 与交付证据中的 5 份正式 SVG SHA-256，确保 Frame ID、模块、标题、角色、模板、`1440×900` 尺寸和已确认设计源与 Demo 一致；不一致时停止构建。
- Figma 与 Demo 共用当前业务 Fixture、路由和交互规则。Figma 决定页面骨架与视觉，Demo 提供可操作状态；两者均不连接真实账号、接口、Key、Secret、发布或投放服务。

## 五个入口

| 入口文件 | 用途 | 默认路由 |
|---|---|---|
| 开发者后台一期总览demo.html | 评审入口；选择模块、角色、Frame ID 和通用状态 | 四模块索引 |
| 01-开发者平台与资料demo.html | 受邀登录、厂商与游戏资料、资料审核 | P01-01 |
| 02-CDKEY商品与供给demo.html | 商品、SKU、供应来源、库存与供给异常 | P02-01 |
| 03-包体测试与发布demo.html | Windows 包体、测试、版本审核与发布处置 | P03-01 |
| 04-精准投放与数据demo.html | 投放需求、运营配置、排期、监控与 T+1 数据 | P04-01 |

总览中的角色切换、模块选择和全页面索引只用于评审，不属于正式后台，也不进入 Figma 的 37 个业务 Frame。

## P01-01 与 P02-01 本轮交互

- P01-01 首次进入先展示合作说明、四步流程与准备事项；“开始入驻”后在同一路由展示受邀账号登录。
- P02-01 在同一路由内提供“商品与供给、Key 批次、渠道 API、接口说明”四个任务 Tab。
- 顶栏帮助中心属于全局后台壳，不计入 37 个业务路由；返回后恢复原路由、Tab 与滚动位置。
- 盖世只生成由自身兑换服务校验的盖世平台 Key；外部平台 Key 仅能受控导入或通过供应商 API 同步。
- Key 明文仅在一次性下载动作中出现，Secret 仅在创建或轮换结果中出现；刷新后只能查看掩码。
- 所有 Key、凭据、URL、订单和审计内容均为演示数据，不连接真实服务。

## Hash 路由

业务入口统一使用以下格式：

    #/Pxx-xx?role=<role>&state=<state>

示例：

    01-开发者平台与资料demo.html#/P01-03?role=developer&state=default
    03-包体测试与发布demo.html#/P03-07?role=tester&state=default
    04-精准投放与数据demo.html#/P04-08?role=operations&state=error

未知 Frame ID 回退到当前模块默认路由；非法角色或状态使用安全默认值。角色无权直接访问某个路由时展示无权限状态，不返回目标对象是否存在，也不展示厂商、游戏、版本或投放对象名称。

## 三个角色

| 参数 | 角色 | 本期权限边界 |
|---|---|---|
| developer | 受邀开发者 | 维护自身厂商和首款签约游戏资料；在平台预授权范围内创建盖世平台 Key 批次和渠道 API 凭据；提交包体测试和投放需求；只读查看审核、发布、投放回执和发行数据；不能扩权、直接发布版本或启动投放 |
| operations | 平台发行运营 | 配置合作方账号；审核资料、商品、供给、版本和素材；控制立即／定时发布、下架、停售、规则圈选、资源位与排期 |
| tester | 平台测试人员 | 仅查看并处理分配给本人的待测任务，提交不可覆盖的测试结果；不能审核、发布或配置投放 |

## 五种通用状态

| 参数 | 表现 |
|---|---|
| default | 默认业务内容和可用动作 |
| loading | 保留页面骨架的加载状态 |
| empty | 保留标题和允许动作的空状态 |
| error | 页面内展示失败原因和重试入口 |
| permission | 不泄露对象存在性的无权限结果 |

表单采用显式“保存草稿”，不自动保存。审核、上传、测试、发布和投放交互只写入当前页面 JavaScript 内存；刷新页面后恢复初始 Fixture。列表返回应保留当前会话内的筛选、页码和滚动位置。

## 桌面与离线要求

- 设计基准为 1440×900，最小支持 1280×800；本期不提供手机端或平板端布局。
- 五个 HTML 均为可双击打开的离线单文件，不加载外部脚本、样式、字体、图片、接口或 iframe。
- 演示数据来自 src/fixtures.json；不读取或提交真实账号、密码、合同、CDKEY、包体、用户或投放数据。
- 不使用 localStorage、IndexedDB、Cookie 或远程存储保留演示操作。

## 非本期范围

- 公众注册、组织成员与复杂权限、在线合同、税务、银行账户、提款、自动结算或自动分账。
- 真实认证、真实上传、真实测试执行、真实发布、真实下架／停售、真实投放与真实数据接口。
- Mac／Linux 包体、多正式分支、开发者自助回滚、自动保存、云存档。
- CDKEY 购买、支付、订单、激活与退款的新后台页面；渠道 API 只接入既有 CDKEY 订单履约链路，不新增用户侧流程。
- 广告竞价、预算自动消耗、推荐算法、开发者自助启动投放和单用户数据。

## 待业务冻结

## 本地验收

在仓库根目录执行：

    node demos/开发者后台一期/build.mjs
    node --test tests/developer-backend/*.test.mjs

浏览器验收使用 playwright-core 驱动本机 Chrome 或 Edge，覆盖 37 个路由、两种桌面尺寸、五态、权限隔离、关键交互、控制台错误和水平溢出。
