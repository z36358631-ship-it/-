## 第一份 Demo 的关键交互

- 首页点击“登录”直接打开双栏弹窗，不跳转独立登录页。中文使用 11 位手机号＋6 位验证码，英文使用邮箱＋6 位验证码；两种语言都支持盖世游戏 App 扫码，未注册账号登录时自动注册。
- 登录后选择“注册平台开发者”可直接进入控制台；选择“认证企业开发者”进入认证介绍。企业认证预计 5 个工作日内完成。
- 控制台使用顶部横向 Tab：游戏管理、数据总览、财务与管理，默认进入游戏管理。游戏管理常驻企业认证状态，审核中可查看详情，重复申请会提示已有申请；可创建基础游戏项目。数据总览展示五项游戏数据与日期明细结构，财务与管理仅占位，具体口径和业务能力由后续 PRD 定义。
- 企业认证不保存草稿，先阅读介绍，再在一个页面填写企业工商、银行结算、厂商联系人和授权签署信息；支持清空重填、附件参考示例、协议全文和正式提交。
- 工商执照、银行账户证明为必传图片；运营端只读查看提交快照，通过受控预览打开附件，银行账号仅显示后四位。
- 运营审核支持关键词、状态和日期组合筛选；待审核申请可通过／拒绝，已通过申请可下架。所有处理均包含成功、失败和幂等反馈。
- 帮助中心采用左侧目录＋右侧文章正文，支持搜索、结果跳转和关键词高亮；“控制台”入口仅在帮助中心显示。对外合作邮箱统一为 `dev@xiaoji.com`。
- 企业认证内容配置用文章列表管理认证介绍、保密协议和合作协议，支持搜索、新建、编辑、删除、唯一编号和中文／English 富文本，不提供排序。新建或修改后为草稿，运营在列表逐条发布。
- 帮助中心为运营后台独立入口，含“导航目录／目录子文档”两个 Tab；两类对象支持增删查改，导航与同导航子文档支持上移、下移。新建、编辑或排序后为草稿，运营逐条发布；子文档只能发布到已发布导航下。

## 响应式与演示边界

- 第一份 HTML 为可双击打开的离线单文件，不加载外部脚本、样式、字体、图片、接口或 iframe。
- 统一 02 开发者前台新增“数据看板”，覆盖买断游戏与永久 DLC 的经营概览、脱敏订单明细、预估收入和待结算摘要；正式对账、差异、发票与付款继续进入第十五份 Demo。
- 页面适配宽屏、1280px 桌面和 320／390px 手机视口；手机端不产生根节点横向溢出。
- 所有操作只保留在当前浏览器会话；刷新后恢复初始数据，不使用远程持久化。
- 实际验证码、扫码授权、文件上传、附件鉴权、审核通知和内容发布由正式服务端处理。
- 游戏详情、游戏上架、SDK 服务、开发者服务、CDKEY、包体发布和精准化投放只在本期相关位置说明或占位，由后续 PRD 定义完整业务规则。

## 第十五份 Demo 的关键交互

- 财务模块只有“财务主体”和“对账结算”两个一级页面，不设置页内业务 Tab。
- 对账结算按结算单聚合对账、发票、付款状态，并直接展示当前待办。
- 结算详情使用单层右侧抽屉，按账单、来源、流水、差异、发票、付款纵向展示。
- 全局流水查询使用次级页面，保留三本账筛选、每页 20 条和安全导出。
- 默认穷举态覆盖主要状态，右下角“场景”可切换无假数据的缺省态。
- 平台直销、外部 Key 采购和盖世 Key 渠道使用独立账本；页面和导出保留来源字段。
- 开发者确认账单后进入已确认，平台锁单与付款不属于开发者操作。
