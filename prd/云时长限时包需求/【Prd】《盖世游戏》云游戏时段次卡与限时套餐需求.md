# 【Prd】《盖世游戏》云游戏时段次卡与限时套餐需求

## 一、版本信息

| 时间 | 版本 | 变更人 | 变更内容 |
|---|---|---|---|
| 2026.08.06 | V1.0 | 郑群超 | 新增时段次卡、节点限时包预热、套餐排队特权、限时时长查询与扣除；补充竖版及掌机模式 |

## 二、背景与目标

现有商品无法按“多次购买、指定时段激活”销售闲时资源；节点限时包不能提前预热；付费用户永久享有排队特权，权益成本不可控；后台也不能按记录处理限时时长。

本期目标：上线时段次卡和节点限时包预热能力，排队特权改为按套餐订单计算，并补齐限时时长的查询、消耗和人工扣除。

| 范围 | 说明 |
|---|---|
| C端 | 充值中心、时段次卡购买与激活、节点限时包预热、时长明细、到期提醒、竖版与掌机模式 |
| B端 | 商品管理、次卡与节点限时包配置、普通时长包排队特权、旧权益切换、限时时长查询与扣除 |
| 不做 | 零时长用户引导、现有包天卡/包夜卡改造、跨日次卡时段、通用促销引擎、人工发放限时时长 |

## 三、用户路径

1. 时段次卡：充值中心购买 → 次数到账 → 指定时段点击秒玩 → 确认扣1次 → 本时段任意云游戏免扣 → 到期切换其他时长或进入现有无时长流程。
2. 节点限时包：预热期查看 → 开售后购买 → 限时时长到账 → 使用窗口内消耗 → 耗尽或到期。
3. 后台扣除：用户详情 → 选择一条限时时长 → 填写扣除量与原因 → 二次确认 → 更新余额并记录日志。

## 五、通用规则

| 类型 | 规则 |
|---|---|
| 时间 | 所有窗口、倒计时和有效期使用服务端北京时间，时间窗口按左闭右开处理。 |
| 并发 | 支付发放、次卡激活、时长消耗、人工扣除、退款和迁移必须幂等；余额不得为负。 |
| 协议 | 仅对后台配置的国内云游戏APP协议生效；服务端同时校验包体与协议，海外包不可查询、购买、激活或使用。 |
| 权限与日志 | 商品修改、人工扣除和旧权益迁移按角色授权，完整记录操作日志。 |
| 失败处理 | 网络异常按服务端结果恢复，不重复发放或扣减；配置异常商品不展示。 |

## 七、运营准备

1. 上线前配置首期午间/深夜次卡的价格、次数、有效天数、星期、时段和限购规则。
2. 为全部在售普通时长SKU配置排队特权天数；未配置按0天处理。
3. 确定旧权益切换时间T，切换前冻结套餐配置并核对最后一笔订单迁移预览。
4. 节点活动按场配置预热、售卖、使用窗口及素材，不把活动参数写死在客户端。

## 八、上线后关注

关注时段次卡曝光、支付、激活、到期未使用率，节点限时包支付与到期损耗，普通用户排队时长、启动成功率、退款率及权益账实差异；按活动记录结果，不在本期增加新后台页面。
