一、文档概述

1.1 背景概述

  • 用户场景： 盖世游戏承载选游戏、阅读游戏信息与社区内容、管理下载、调整设置等使用行为。用户会在白天、夜间及不同光照环境下使用，也有各自固定的阅读和配色习惯：部分用户偏好深色界面，部分用户习惯浅底深字，还有用户希望应用随手机系统自动切换。单一配色难以同时满足这些使用需求。
  • 现有不足： 当前设置未提供独立的深浅主题选择，偏好浅色的用户只能接受现有深色外观；希望跟随系统的用户，也缺少对应设置。调整屏幕亮度只能改变显示亮度，无法切换文字与背景的配色，不能替代主题选择。外观选择受限会持续影响用户在游戏之外浏览内容和操作功能时的体验。
  • 竞品与行业参考： 游戏设备已提供外观选择能力：Nintendo Switch 支持白色与黑色主题，Xbox 主机支持深浅主题，并可结合夜间模式定时切换；移动端的 YouTube 支持浅色、深色和使用设备主题。这些做法为盖世提供了两项明确参照：让用户保留自己的配色偏好，以及让应用外观与系统设置保持一致。
  • 本期价值： 在保留现有深色体验的基础上，补齐浅色显示和跟随系统能力，让用户能选择适合自己的阅读与操作界面；选择跟随系统后，减少手动切换的负担。通过一个设置项覆盖固定深色、固定浅色和自动切换三类需求，同时保留老用户当前外观，补齐平台的基础体验与个性化能力。上线后统计两种模式的实际使用人数和主动选择情况，为后续界面适配提供依据。

1.2 需求边界

边界类型 范围说明
产品边界 盖世游戏 App“我的—设置”的深色模式入口与三项选择，主题作用于 App 自有界面；横竖屏使用同一偏好。Demo 覆盖设置、选择态、深浅结果和横屏；不把这些示例视为全 App 换肤验收。
业务边界 深色为黑底白字，非深色为白底黑字；保持卡片层级、品牌强调色和可读性。游戏画面、封面、头像、视频不反色；第三方网页和系统授权界面遵循其自身能力，不强行反色。
运营边界 无新增后台配置、活动、营销提示或主题商品。
人力边界 产品确定规则；设计补齐全 App 自有组件的深浅主题；客户端落实保存、系统跟随与切换；自有 H5 由服务端页面负责人适配、客户端传递有效主题；数据与测试核验统计和异常。

1.3 术语定义

术语 定义与判断口径
深色模式设置 用户选择的偏好，三值为跟随系统、开启、关闭。
用户模式 事件发生时实际显示的主题，两值为深色、非深色，不包含“跟随系统”。
新用户／老用户 此处按安装与升级场景识别，不按账号注册时间：全新安装且无历史配置为新安装；已有安装升级为老安装。重新登录或更换账号不触发初始化。

二、产品说明

2.1 产品／方案简介

项目 说明
目标用户 需要浅色显示、固定深色显示或随系统自动切换外观的 App 用户，包括游客。
方案 在现有设置列表“模式切换”下新增“深色模式”，沿用设置选择交互，提供“跟随系统、开启、关闭”；选择立即应用并保存本设备偏好。
默认策略 [已确认] 新用户默认跟随系统；老用户保留升级前外观，当前深色则迁移为开启。已有明确主题偏好优先保留。

详细说明：
展示说明：
1. 保留原图的返回与“设置”标题；主组依次为账号管理、模式切换、深色模式（新增）、兑换中心、通知、按键音、隐私设置、存储管理、下载任务；第二组为反馈&建议、关于；底部为退出登录。原图没有帮助中心，本期不追加该项。

3. 点击新增行显示标题“深色模式”和依次排列的“跟随系统、开启、关闭”，使用互斥单选和当前选中标记；选择容器沿用现有 App 单选样式。
4. 深色使用深底浅字，非深色使用浅底深字；文字、卡片、箭头、分割线、选择态和可控系统栏同步适配。图片内容及品牌强调色保持原意，不对整页做简单反色。
交互说明：
1. 点击“深色模式”打开选择，当前偏好已选中；点击任一选项立即保存并应用，返回设置后行右侧显示所选值，不需要额外提交或重启，不新增成功 Toast。
2. 选择“开启”固定深色；选择“关闭”固定非深色；选择“跟随系统”立即采用当前系统主题，此后响应系统变化。
3. 关闭选择容器、返回或点击容器外部（若现有容器支持）且未选新值，保持原偏好和外观；再次选择当前项不构成一次配置变化。
4. 点击设置页返回，回到“我的”，新主题继续生效；原有其他设置入口与退出登录行为不变，Demo 不模拟这些无关业务操作。
输出／后置条件 偏好保存到本设备，当前与后续 App 自有页面使用有效主题；重开 App 保留偏好；切换账号或退出登录不重置。公共参数在下一事件前更新为有效主题。
补充说明 1. [推导] 本地保存失败时不把配置变更记为成功；保持上次已保存的选中项与外观，使用现有错误反馈能力，允许重试，不新造弹窗或错误文案。
2. [推导] 网络断开不影响选择和保存；埋点沿用现有离线队列，补报保留发生时主题而非补报时主题。
3. [推导] 连续选择以最后一次成功保存为准；手动开启／关闭优先于系统通知，避免延迟通知覆盖用户选择。
4. [推导] 系统主题在后台改变时，回前台先重新解析有效主题再展示页面；切换不得清空表单、播放状态、导航栈或当前滚动位置。

场景 初始偏好 有效主题 恢复与冲突
已有合法偏好 保留原值 按原偏好解析 优先于新装默认与迁移，不因版本更新反复覆盖。
新安装且无历史偏好 跟随系统 与系统一致 后续以用户成功保存的偏好为准。
老安装且原为深色、无偏好 开启 深色 仅首次迁移写入，保留熟悉外观。
老安装且原为非深色、无偏好 关闭 非深色 仅首次迁移写入。
无法读取系统主题 跟随系统保持不变 [建议方案] 有最近有效主题则延用，否则深色 系统能力恢复后重新跟随；不能在右侧把跟随系统改为开启。
本地值损坏／迁移状态无法识别 [建议方案] 优先恢复最近有效偏好；否则按老安装恢复深色开启 恢复偏好后按主题解析表计算；无可恢复偏好时为深色 不伪造旧外观已被保留；记录为恢复路径，数据中不归为用户主动选择。

4.1.1 指标口径

指标名称 口径（含分子和分母） 去重与时间窗口 数据源与用途
深色／非深色使用用户数 统计周期内有相应主题展示事件或有效前台业务事件的用户数；分别筛选 user_mode=dark／light。不设分母。 按现有统一分析用户标识去重；日及版本周期。建议日界使用北京时间，与现有数据平台日界不一致时统一沿用现有日界。 theme_view 与携带 user_mode 的有效前台业务事件取并集；回答实际使用人数。
两种模式使用覆盖率 对应模式使用 UV ÷ 本期支持主题参数且实际前台展示的用户 UV；分母为两类用户并集。 与使用人数相同窗口和身份规则。 相同的前台事件集合；同一用户可同时计入两类，因此覆盖率之和可能超过100%，不得标成互斥分布。
主动选择用户数 按 theme_preference 分组统计成功更改偏好的用户数；自动初始化、升级迁移、系统自动变化不计入。 统一分析用户标识去重；日及版本周期，同人可选过多项。 theme_preference_change；区分主动选择与实际使用。

登录用户沿用现有统一用户标识；游客沿用现有匿名标识。登录前后按数据平台已有身份合并规则去重；若尚无合并能力，登录用户与匿名用户分开报告，不能直接相加并称为全量唯一自然人数。旧版本缺失 user_mode 的事件单列未覆盖，不默认归深色；参数覆盖率和支持版本过滤作为报表条件。

4.1.2 埋点事件

事件 页面／类型 触发与成功 参数
客户端现有业务事件（保留原事件名） App 自有界面／改造公共字段 在事件发生时附上已生效主题；不改变原事件成功条件和频次。切换时未完成渲染的事件仍记录当时实际主题。 user_mode
theme_view App 自有界面／新增 启动或回前台后第一屏实际可见时上报一次；前台期间有效主题真正变化且渲染成功后再上报一次。重复系统通知、重新进入设置但主题未变不重复上报；后台系统变化不单独上报。若身份变化后没有可归因的前台业务事件，首次界面可见时补报一次。 user_mode、theme_preference、trigger_source、event_id
theme_preference_change 设置／深色模式／新增 用户选择不同偏好且本地保存成功、界面已按其规则应用后上报一次；即使新旧实际主题相同，偏好真实变化也上报。取消、重复选中、保存失败和自动迁移不报成功。 user_mode、theme_preference、previous_preference、event_id

两个新增事件沿用现有公共身份、版本、时间和设备字段，不新增第二套身份体系。自动变化只通过 theme_view 的触发原因识别，不算主动选择。数据入库按 event_id 去重；离线重传使用原 event_id 和原发生时间，防止重传重复计次。使用人数取主题展示事件与有效前台业务事件的并集，剔除纯后台任务、补报接收时间及系统通知。跨日持续前台使用，以新统计日第一次有效业务事件归入新日；静置跨零点不新增使用。登录、退出或切换账号后的首个有效业务事件使用变更后的分析身份和当前主题；若现有 SDK 不提供该事件，需补报一次当前主题展示，避免同一前台会话身份变化后漏计。

4.1.3 参数说明

参数 类型／必填 说明 枚举／示例
user_mode string／是（支持本功能的客户端事件） 新增公共字段“用户模式”，记录事件时实际生效主题。 dark＝深色；light＝非深色。禁止写 system 或把缺失值补成 dark。
theme_preference string／是（两个新增事件） 当前已保存的主题偏好，区别于实际外观。 system＝跟随系统；on＝开启深色；off＝关闭深色。
previous_preference string／是（theme_preference_change） 变更前已保存偏好。 system＝跟随系统；on＝开启深色；off＝关闭深色。
trigger_source string／是（theme_view） 此次实际主题展示的触发原因。 foreground＝启动或回前台首屏；user_selection＝前台用户选择导致主题变化；system_change＝前台跟随系统导致主题变化；identity_change＝身份变化后补充主题展示。
event_id string／是（两个新增事件） 沿用 SDK 事件唯一标识；每个逻辑事件只生成一次，重传保持不变。 示例：theme-view-20260928-0001（示意，实际格式沿用 SDK）。

4.2 技术需求

需求项 具体要求
主题完整性 App 自有页面、选择容器、加载与错误状态一起适配，不出现深底黑字或浅底白字；非深色不是仅更改设置页背景。保留内容媒体原色与语义颜色。
切换与恢复 不依赖网络，不要求用户重启；恢复前台和打开新页前解析有效主题。避免首屏先闪现另一主题，切换不得丢失原业务状态。
系统兼容 使用平台已有主题能力；系统不支持时按已定义降级规则处理。系统授权界面不承诺可由 App 强制换肤。
本地存储 设置按设备安装实例保存，登录／退出不清除；清除 App 数据或全新安装按新安装处理。已保存合法偏好优先，不主动新增账号同步。
