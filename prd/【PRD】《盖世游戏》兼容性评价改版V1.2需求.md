## 一、文档概述

### 1.1 背景概述

- **需求背景：** 手机运行 PC 游戏时，不同游戏与 GPU 组合的运行结果差异较大。用户需要在启动前参考其他玩家的真实运行反馈，并在正常退出后低成本补充自己的体验。
- **当前方式：** 用户主要依据评价星级、设备、文字和图片判断兼容性；即使看到他人评价，也无法确认该玩家当次使用的完整配置和实际游玩时长，更无法直接复用。
- **问题：** 评价缺少可查看、可应用的当次配置，参考价值有限；评价绑定不可变快照的旧命名又容易与可持续维护的个人“启动方案”实体混淆。
- **本期方向：** 在原游戏详情、评价列表、启动方案详情、正常退出邀评和评价后台中补齐闭环；评价绑定快照统一显示“本次启动配置”，内部字段和正式“启动方案”实体不改。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 国内 APP C 端竖屏游戏详情、玩家兼容性评价、本次启动配置详情、兼容性评价弹窗、我的评价，以及横屏游戏运行与退出；B 端玩家兼容性评价管理和快照追溯。启动失败、闪退和异常退出流程不改。 |
| 业务边界 | 覆盖评价查看、同配置筛选、配置查看与应用、正常退出邀评、评价提交、评价绑定的单次配置快照、评价与快照生命周期、后台筛选／预览／删除／导出。不自动创建个人云分享方案，不跨评价复用或去重配置，不累计多人验证、成功率或最近验证。 |
| 运营边界 | 沿用玩家兼容性评价管理；邀评间隔与次数由服务端配置中心维护。本期不新增后台配置页、灰度、标签配置或运营活动。 |
| 人力边界 | 客户端负责 C 端页面、横竖屏切换、会话采集和动作反馈；服务端负责 30 分钟资格、邀评冷却、评价、快照、导出和生命周期；设计负责在原组件体系内更新页面与文案；测试覆盖 C/B 端主链路、状态、异常和历史数据展示。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 兼容性评价 | Compatibility Review | 用户针对某个游戏在当前设备上的实际运行体验提交的 1～5 星评价，可含类型、文字和图片。评价资格沿用全平台累计游戏时长达到 30 分钟的门槛。 |
| 本次启动配置 | Launch Configuration Snapshot | 评价绑定的单次成功运行配置在 C/B 端的固定展示名；它是不可编辑、不可变的一次性快照，不等同于个人“启动方案”。 |
| 评价快照 | Review Snapshot | 用户显式勾选分享后，为当前评价在云端独立创建的完整白名单配置与当次游玩时长；`review_id` 与 `review_snapshot_id` 一对一。 |
| 同配置 | Same Configuration | 沿用原定义：同一游戏且 GPU 相同；不按手机型号、APP 版本或快照内容重新定义。 |
| 邀评冷却 | Review Invitation Cooldown | 正常退出后判断是否主动拉起评价弹窗的服务端规则；用户全局默认 7 天最多曝光一次，并叠加当前游戏＋GPU的间隔和次数配置。 |
| 启动方案 | Launch Solution | 可在“启动方案”页管理、应用或复制的正式方案实体；本期名称和既有能力不变。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 将兼容性评价与评价人当次实际运行配置连接起来，让其他玩家在启动前查看并复用有效配置，让已完成游玩的用户在退出后提交可信评价。 |
| 目标用户 | 使用手机运行 PC 游戏、希望判断游戏能否运行或复用他人配置的玩家；负责评价治理和问题追溯的后台管理人员。 |
| 核心目标 | 形成“查看评价与配置—应用配置—启动并退出—提交评价与当次配置—后台追溯”的闭环，同时避免把单次快照误解为个人云方案。 |
| 使用场景 | 玩家启动游戏前查看同游戏评价并应用有效配置；正常退出后收到低频邀评；管理员筛选、查看、隐藏、恢复、删除或导出评价及其关联快照。 |
| 功能概述 | C 端提供兼容性入口、评价筛选、有效快照详情、应用／复制、正常退出邀评、共用评价弹窗和我的评价；B 端提供关联快照筛选、只读预览、生命周期管理和 CSV 导出。 |

| 输出／后置条件 | 用户进入某条有效配置详情，打开手动评价弹窗，或停留在已选择的评价筛选结果。 |

| 输出／后置条件 | 应用成功后返回游戏详情并更新当前方案；复制成功后生成个人副本并进入“启动方案”页；返回时恢复评价列表上下文。 |
| 补充说明 | 1. “本次启动配置”只是一对一评价快照的展示名；`solutionName`、`reviewSnapshotId` 等内部字段名不改。<br>2. 硬条件不兼容时禁用应用并展示既有明确原因；复制是否可用由服务端动作状态独立决定。<br>3. 列表不展示不可用快照入口；详情异常态只处理旧链接、状态变化或加载过程中的降级。 |

#### 3.1.4 横屏游戏运行与退出

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 手机横屏游戏运行、退出确认和正常退出后的主动邀评判断。 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 一致性与并发 | 1. `review_id` 全局唯一；评价先持久化，再创建或删除快照，评价保存失败不得产生孤儿快照。<br>2. 同一评价并发创建以首个成功快照为准；后续不同 `play_session_id` 请求返回已有快照，不覆盖正文。<br>3. 删除关联后再次分享必须使用新的成功会话创建当前快照；允许复用确定性快照 ID，但正文和时长必须来自新会话。<br>4. 删除需校验快照归属，重复请求返回同一终态。 |
| 快照存储 | 1. 每条已分享评价独立保存一份不可变云端快照，同一评价最多一份，相同配置也不跨评价复用、去重或聚合。<br>2. 8KB 上限按归一化白名单 JSON 的 UTF-8 字节数计算；超过上限则只保留评价，不绑定快照。 |
| 白名单结构 | 1. `general` 组仅允许 `env`、`args`、`exe_path`。<br>2. `compatibility` 组仅允许 `wine_ver`、`dinput`、`skip_video`、`surface`、`audio_drv`、`dxvk`、`vkd3d`、`cpu_trans`、`cpu_core`、`vram`。<br>3. `dependencies` 组仅允许 `cjkfonts`；`steam` 组仅允许 `steam_input_exp`。<br>4. `valueType` 仅允许 `text`、`boolean`、`number`。 |
| 字段与安全 | 1. 组名、项名、描述、展示值长度上限依次为 32、48、160、512 个字符。<br>2. 拒绝未知组项、重复组项、账号、令牌、用户 ID、存档、文件、设备唯一标识、本地绝对路径和原始文件。<br>3. 字段类型、长度或安全校验失败时评价仍可成功，但不绑定快照。 |
| 状态与生命周期 | 快照状态为 `available`、`deprecated` 或 `invalid`；状态变化不覆盖历史正文。降为 1～2 星、取消分享或删除评价时删除关联及正文；隐藏评价只影响 C 端可见性，B 端保留追溯。 |
| 展示兼容 | C/B 端对评价快照固定显示“本次启动配置”，不读取历史 `solutionName` 决定标题；不迁移旧快照、内部字段或引用关系。正式“启动方案”页、“应用方案”和“复制方案”语义保持不变。 |
| 失败恢复 | 快照上传失败不回滚评价，不转为个人云方案；详情加载失败、正文缺失、字段版本异常或 ID／归属不一致时禁止应用和复制，不用假参数补齐。 |
