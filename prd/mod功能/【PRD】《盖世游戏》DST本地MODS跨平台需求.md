## 2. 背景与问题

Mac 端已有一版 MODS 功能，可从 DST 游戏详情查看列表、详情并安装。现有实现尚未形成跨端产品合同，主要问题如下：

- Mac、APP 竖屏和 APP 横屏缺少统一入口、页面字段、术语和状态。
- 下载完成、安装成功、用户启用、本次启动计划加载和游戏实际加载是不同阶段，现有描述容易混淆。
- 硬依赖、软依赖、冲突、兼容性未知、安装失败、更新回退和异常退出缺少处理规则。
- APP 旋转或进入后台可能重建页面，不能因此重复创建接口请求、下载或安装任务。
- “文件已复制”不能证明 MOD 已被游戏加载，必须保留游戏或引擎日志证据。

本需求定义外部非官方 MOD 的发现、本地安装、设备级管理、启动检查和恢复闭环。创意工坊属于官方渠道业务，本期不改造。

## 3. 目标与成功标准

### 3.1 产品目标

让 Mac 和 APP 用户从 DST 游戏详情发现非官方 MOD，一次点击完成当前设备的下载、校验、安装和默认启用；启动前知道本次生效、跳过和风险项；安装或更新失败后仍能使用旧版或无 MOD 启动基础游戏。

### 3.2 成功标准

- 用户可从游戏详情进入 MODS，完成浏览、搜索、查看详情、安装、启停、更新和卸载。
- 安装、启用、文件和任务状态按设备独立管理，不制造跨设备同步预期。
- APP 横竖屏切换保留页面与任务状态，不重复请求详情、下载或安装。
- 每次携带 MOD 启动前生成 `resolved_launch_manifest`。
- 进入游戏后可从游戏或引擎日志核对实际加载的 MOD ID 和本地版本。
- 安装、更新或启用集合变化后异常退出，下一次启动提供三种明确恢复选项。
- 更新失败保留当前可用版本，不阻断基础游戏启动。

### 3.3 指标门槛

- 一键安装成功率不低于 95%。
- 已启用 MOD 进入实际加载清单的比例不低于 90%。
- 携带 MOD 的游戏启动成功率不低于 90%。
- 无 MOD 降级启动成功率不低于 99%。
- 异常退出后恢复成功率不低于 90%。
- 安装用户 7 日内再次使用 MODS 的比例不低于 20%。
- 横竖屏切换造成的重复下载或重复安装任务为 0。
- 游戏存档或用户 MOD 配置丢失事件为 0。

## 4. 范围与非目标

### 4.1 本期范围

- DST 游戏详情中的 MODS 入口。
- 可用 MOD 列表、已安装列表、MOD 详情。
- 当前设备的一键安装、依赖安装、启用、停用、更新和卸载。
- Mac、APP 竖屏、APP 横屏及 APP 运行中旋转。
- 安装前检查、文件完整性校验、原子安装、更新失败回退。
- 启动前检查、`resolved_launch_manifest`、游戏或引擎日志核对。
- 异常退出后的恢复建议和无 MOD 启动。
- 页面与核心动作埋点、灰度指标和技术 Go/No-Go 前置。

### 4.2 非目标

- 不改造创意工坊入口、页面、订阅、取消订阅和官方渠道同步。
- 不提供 MOD 上传、发布、审核、创作者后台和用户投稿。
- 不提供点赞、评论、收藏、关注和社区关系。
- 不提供多套 MOD 组合方案。
- 不自动调整加载顺序，不自动解决 MOD 冲突。
- 不跨设备同步安装、启用、更新、卸载和下载任务。
- 不后台静默自动更新。
- 不提供病毒扫描和内容安全审核；文件完整性校验必须保留。
- 不删除游戏存档和用户 MOD 配置。

### 4.3 登录与内容展示边界

- MODS 不依赖云游戏、实名认证或国内登录方式。未登录用户可进入 MODS、安装和管理当前设备文件，不弹登录或实名引导；登录过期不取消设备任务。
- 国内包与海外包均提供首期完整能力。国内包页面使用中文；海外包页面使用 GameHub 现有多语言能力，并跟随海外包语言设置。
- 设备状态由当前设备安装标识区分，不以账号状态替代。
- 账号在 Mac 安装后，同账号 APP 不显示已安装，也不自动下载；反向同理。
- 本期无用户发布和文本输入，不新增敏感词提交、图片上传或人工审核流程。
- 来源名称、作者、简介、更新说明和安装说明按服务端同步内容展示；客户端将其作为不可执行文本处理。
- 来源文本没有当前语言译文时展示来源原文，不由客户端生成或猜测译文。
- 卡片长标题和短简介截断展示，详情页展示完整内容；预览图加载失败显示占位图，不阻断安装。

## 5. 用户角色与核心场景

### 5.1 用户角色

|角色|目标|主要风险|
|---|---|---|
|首次安装用户|确认当前设备兼容后一次完成安装|不理解依赖、误以为会跨设备同步|
|已安装用户|启停、更新或卸载当前设备的 MOD|更新覆盖旧版、卸载误删存档|
|携带 MOD 启动用户|知道本次实际计划加载哪些 MOD|把安装成功误判为游戏生效|
|异常退出用户|快速恢复到可启动状态|系统擅自停用或删除用户内容|

### 5.2 核心场景

1. 用户进入 DST 游戏详情 → 打开 MODS → 搜索或浏览 → 查看详情 → 点击安装 → 自动安装必要依赖和主 MOD → 默认启用 → 显示“已安装 · 已启用 · 仅此设备”。
2. 用户点击启动 DST → 系统检查当前设备已启用 MOD → 生成 `resolved_launch_manifest` → 用户确认跳过或风险项 → 启动游戏 → 游戏日志确认实际加载。
3. 用户更新 MOD → 新版本在临时目录完成校验 → 原子切换版本；若失败则保留旧版并允许继续启动。
4. MOD 集合变化后游戏异常退出 → 用户下次启动看到变化项和恢复建议 → 主动选择停用变化项、无 MOD 启动或保持当前设置。

## 6. 业务规则

### 6.1 MODS 与创意工坊隔离

|维度|本期 MODS|创意工坊|
|---|---|---|
|来源|外部非官方来源|官方接入渠道|
|用户动作|下载、校验、安装、启停、更新、卸载|订阅、取消订阅|
|本期处理|完整设计并落地|不改造，仅参考信息布局|
|数据与文件|独立数据表、接口命名和本地目录|不与 MODS 复用|

- 两套业务不得合并入口、数据表、文件目录或操作术语。
- MODS 页面不得把“订阅”“取消订阅”“我的订阅”作为用户动作。
- 创意工坊故障或状态变化不得改变 MODS 的本地记录，反向同理。

### 6.2 设备级安装边界

- Mac 与每台 APP 设备分别保存安装版本、启用值、文件清单和任务状态。
- 游戏详情入口、列表、详情、已安装页和启动检查读取同一个设备级状态源。
- 所有已安装状态持续显示以下文案：

```text
已安装 · 已启用 · 仅此设备
已安装 · 未启用 · 仅此设备
```

- 卸载确认必须显示：

```text
只卸载当前设备中的 MOD 文件，不影响其他设备。
```

- 换设备后用户需在新设备重新安装；账号登录、退出或切换不得把另一设备状态覆盖到本机。
- 启动只读取当前设备已安装且已启用的 MOD。

### 6.3 一键安装与依赖

1. 用户点击一次“安装”后，系统自动完成空间与网络检查、下载、`package_hash` 校验、目录检查、原子安装和默认启用。
2. 硬依赖可用且兼容时，按钮显示“安装（含 N 个必要依赖）”，同一根任务安装完整依赖闭包，不要求用户逐个点击。
3. 硬依赖缺失、来源失效或本端不兼容时，主 MOD 为 `dependency_blocked`，按钮不可执行，页面显示最短阻塞原因链。
4. 软依赖、软冲突或兼容性未知时允许安装；点击后先展示风险和受影响项，用户确认后开始安装，取消则不创建任务。
5. 一个设备上的同一 MOD 同时只允许一个下载、校验、安装或更新任务。连续点击、页面重建和旋转复用同一任务。
6. 依赖安装顺序为硬依赖从底层到上层，主 MOD 最后安装。任一必要项失败时主 MOD不切换为可加载版本。
7. 取消下载清理本任务临时文件，不影响已安装版本；进入校验或原子切换阶段后不可取消。

安装时序：

```text
检查依赖、网络和空间
→ 创建或复用设备级任务
→ 下载到 staging 临时目录
→ 校验 package_hash
→ 解包并检查目录结构
→ 写入新的版本目录
→ 原子切换当前版本指针
→ 更新本地文件清单
→ 默认启用
```

失败时不得留下可被游戏加载的半成品。

### 6.4 更新、回退与卸载

更新规则：

- 不静默自动更新；只有用户点击“更新”才开始。
- 页面同时展示已安装版本、最新版本和更新时间。
- 新版本下载、校验和目录检查全部通过前，当前版本指针不变。
- 新版本成功后原子切换版本指针，并保留最近一个成功可用版本供失败回退。
- 更新失败继续使用旧版，不改变更新前的启用值，不影响启动。
- 同版本但 `package_hash` 变化时按新包执行完整更新，不原地覆盖。
- 用户选择“使用旧版”时不创建更新任务，本次仍使用当前版本。

卸载规则：

- 点击卸载后展示 MOD 名称、“仅此设备”和依赖它的已启用 MOD 列表。
- 用户确认后先停用目标 MOD，再删除当前设备的受控 MOD 程序文件和本地文件清单。
- 不删除游戏存档和用户 MOD 配置。
- 被依赖项卸载后，依赖它的 MOD 不自动卸载、不自动停用；在下一次启动检查中标记为跳过并显示缺失依赖。
- 卸载失败时保留可判断的本地记录；重新扫描文件后显示实际状态和重试入口。

### 6.5 启动前检查与实际加载证据

启动检查只处理当前设备已安装且已启用的 MOD，顺序如下：

```text
读取设备级已启用集合
→ 校验本地文件清单和 package_hash
→ 计算完整硬依赖闭包
→ 检查平台、引擎版本和已知冲突
→ 生成 resolved_launch_manifest
→ 展示本次生效、跳过和风险项
→ 用户确认
→ 启动游戏
→ 读取游戏或引擎日志核对实际加载
```

|检查结果|判定|页面动作|
|---|---|---|
|本次生效|文件完整、硬依赖闭包完整、当前设备兼容|计入启动清单，可启动|
|本次跳过|文件损坏、硬依赖不完整或当前设备不兼容|列出原因；启动时跳过|
|风险项|存在软冲突或兼容性未知|用户确认后可继续|

按钮规则：

- 全部正常：显示“启动游戏”。
- 有跳过项：显示“启动游戏，跳过 N 个 MOD”。
- 有风险项：显示“仍要启动”。
- 用户取消：返回游戏详情，不改变安装或启用状态。
- 没有已启用 MOD：直接启动，不增加确认页；清单项目为空。

`resolved_launch_manifest` 至少记录 MOD ID、本地版本、`package_hash`、加载顺序、当前设备 ID 和本次检查结果。文件复制完成、安装状态或预检查通过都不是实际生效证据。进入游戏后必须从游戏或引擎日志核对实际加载的 MOD ID 和本地版本；日志无法读取或无法匹配时记录为“无法确认实际加载”，不得计入实际生效。

### 6.6 异常退出与恢复建议

- 系统保存最近一次正常进入游戏的实际加载清单。
- 本次清单相对最近成功清单发生新安装、重新启用、版本或依赖变化，且游戏异常退出时，下次启动进入恢复建议。
- 页面展示本次变化项、最近成功清单时间和异常退出证据，不把无清单变化的崩溃归因给 MOD。
- 只提供以下选项：

|选项|执行结果|状态影响|
|---|---|---|
|停用本次变化后重试|用户确认后停用本次变化涉及的 MOD，再重新检查并启动|只在用户确认后修改对应启用值|
|无 MOD 启动|本次使用空清单启动|不改变安装及启用状态|
|保持当前设置继续尝试|按当前集合重新检查并启动|不改变安装及启用状态|

- 系统不自动修改用户状态，不自动卸载，不删除游戏存档或 MOD 配置。
- 用户关闭恢复页或取消操作时返回游戏详情，不执行任何恢复动作。

## 7. Mac 页面与交互

### 7.1 DST 游戏详情入口

|项目|要求|
|---|---|
|入口|保留独立 MODS 卡片，不与创意工坊合并|
|字段|当前设备已安装数量、当前设备已启用数量、最多 3 个已安装 MOD 缩略图|
|空状态|“发现并安装适合当前游戏的 MOD”|
|动作|点击卡片或“查看全部”进入 DST MODS 列表|
|加载态|数量读取中显示加载态；加载失败显示“状态读取失败，点击重试”，不展示另一设备缓存|
|异常|本地状态损坏时先扫描受控目录；扫描完成前数量显示“--”，不自动启用任何 MOD|

### 7.2 MODS 列表

|区域|字段与动作|状态与异常|
|---|---|---|
|顶部|返回游戏详情、标题、可用 MOD / 已安装页签、搜索、热门 / 最新 / 最近更新排序|切换页签或排序回到列表顶部；返回详情后再次进入保留上次页签，不保留已失效任务弹层|
|搜索|按 MOD 名称和作者模糊匹配；提交空词恢复全量；清空立即恢复|无搜索建议、历史或热门词；无结果显示“未找到相关 MOD”，可清空搜索|
|可用 MOD 卡片|封面、名称、短简介、版本、大小、当前设备兼容性、依赖摘要、安装按钮|名称和短简介超出卡片范围截断，详情展示全文；封面失败显示占位图；阻塞时按钮不可用并显示原因|
|已安装卡片|名称、已安装版本、最新版本、启停开关、更新和卸载入口、“仅此设备”|操作成功后原卡片刷新；失败保留原状态并显示原因和重试|
|任务进度|等待下载、下载百分比、正在校验、正在安装直接显示在原卡片|页面刷新或重进后绑定已有任务；同一 MOD 不新增第二条任务|

列表采用两列卡片。首次请求加载失败显示重试；追加加载失败保留已加载内容并提供“重新加载”。列表采用滚动追加，以服务端分页令牌请求下一批；同一分页令牌只允许一个进行中的请求，返回空令牌后显示“没有更多了”，页面不显示总页数。每次返回列表恢复滚动位置。

默认按热门排序；同一排序值下按更新时间倒序，再按 MOD ID 稳定排序。最新按版本发布时间倒序，最近更新按更新时间倒序。每次切换排序后重新请求第一页。

### 7.3 MOD 详情

详情使用居中弹窗，关闭后恢复原列表位置。

|区域|字段与动作|状态与异常|
|---|---|---|
|顶部|名称、来源、作者、版本、关闭|来源缺失显示“来源未提供”；关闭不取消已有任务|
|预览|主预览图、缩略图切换|图片失败显示占位图；其他图仍可查看|
|正文|完整简介、安装说明、依赖、冲突、更新记录、文件大小、更新时间、当前设备兼容性|来源未提供兼容、依赖或冲突信息时显示“来源未提供”，不包装成平台检测|
|操作栏|安装、安装（含 N 个必要依赖）、更新、使用旧版、启用、停用、卸载或状态进度|按钮随设备状态变化；重复点击不创建新任务|

长内容在弹窗内部滚动。详情加载失败保留弹窗并显示重试；来源已失效时已安装用户仍能查看本地版本，未安装用户不能安装。

### 7.4 已安装页

- 默认按最近状态变化时间倒序；相同时按 MOD 名称排序。
- 支持名称和作者搜索，支持“全部、已启用、未启用、有更新、异常”筛选；多个条件为“且”关系。
- 空状态显示“当前设备尚未安装 MOD”，并提供“浏览可用 MOD”。
- 搜索或筛选无结果显示“没有符合条件的已安装 MOD”，保留清空条件入口。
- 启停操作立即写入设备级状态；写入成功后反馈，失败恢复开关原值。
- 卸载必须二次确认；有依赖影响时在确认页列出受影响 MOD。

### 7.5 启动检查页

- 按“本次生效、跳过、风险项”分组展示数量和 MOD 列表。
- 每项展示名称、本地版本、检查结果和具体原因；硬依赖原因展示最短依赖链。
- 检查中禁止重复点击启动；检查失败显示失败阶段和重试，允许返回游戏详情。
- 用户确认启动后保存本次 `resolved_launch_manifest`，并记录启动结果。
- 游戏返回后日志解析失败时标记“无法确认实际加载”，不把该项记为实际生效。

### 7.6 恢复建议页

- 展示异常退出时间、本次变化摘要、最近成功清单时间和三个恢复选项。
- “停用本次变化后重试”需二次确认，并列出将停用的 MOD。
- “无 MOD 启动”直接生成空清单，不改变设备级启用值。
- “保持当前设置继续尝试”重新运行启动检查。
- 任何操作失败均保留当前设置和页面证据，可重试或返回游戏详情。

## 8. APP 竖屏页面与交互

### 8.1 入口

- 入口保留在 DST 游戏详情“更多菜单”中，不新增一级导航。
- 菜单项显示“MODS”；点击进入独立全屏 `DST MODS` 页面。
- 入口读取当前 APP 设备状态，不读取 Mac 或其他 APP 设备状态。
- 入口加载失败不阻断游戏详情，点击后进入 MODS 错误页并提供重试。

### 8.2 MODS 列表

|区域|字段与动作|状态与异常|
|---|---|---|
|顶部|返回、`DST MODS`|返回游戏详情；下载任务继续由设备级任务管理器持有|
|页签|可用 MOD / 已安装|切换后保留各自搜索、排序和列表位置|
|搜索|独占一行；按名称和作者模糊匹配|清空恢复列表；无结果与初始空状态分开|
|排序|热门、最新、最近更新横向排列|选中一项；切换后回到列表顶部|
|卡片|单列展示封面、名称、短简介、版本、大小、兼容性、依赖摘要和主操作|任务进度显示在原卡片；封面失败使用占位图|

首次加载、追加加载、空状态、搜索无结果、排序和稳定次序与 Mac 一致。下拉刷新只刷新目录和更新信息，不取消、重建或重复当前任务。

### 8.3 MOD 详情

- 使用全屏结构，顶部返回，底部固定主操作按钮。
- 依次展示预览图、名称、来源、作者、版本、大小、更新时间、兼容性、简介、安装说明、依赖、冲突和更新记录。
- 点击主操作按 6.3、6.4 规则执行；风险确认使用当前页面弹层，取消不创建任务。
- 返回列表后恢复原页签、搜索、排序和列表位置。
- 长内容滚动时记录当前阅读章节，旋转后恢复到同一章节。
- 详情加载失败显示重试；来源失效、图片失败和字段缺失处理与 Mac 一致。

### 8.4 已安装页

- 使用单列卡片，字段、排序、搜索、筛选、启停、更新和卸载规则与 Mac 一致。
- 每张卡片持续展示“仅此设备”。
- APP 进入后台后任务继续或由系统暂停；回前台恢复同一任务和进度。
- 操作系统终止页面后，重新进入页面从设备级任务管理器恢复任务，不凭页面缓存创建新任务。

### 8.5 启动检查与恢复建议

- 启动检查为全屏页，分组、字段、按钮和异常规则与 Mac 一致。
- 没有已启用 MOD 时不显示检查页，直接启动。
- 恢复建议为全屏页，显示变化项、最近成功清单和三个恢复选项。
- 页面进入后台或旋转不自动选择恢复动作，不改变用户状态。

## 9. APP 横屏页面与交互

### 9.1 入口与列表

- 仍从游戏详情“更多菜单”进入，不新增横屏专用一级入口。
- 顶部工具栏集中展示返回、可用 MOD / 已安装、搜索、热门 / 最新 / 最近更新。
- 列表使用两列卡片；卡片字段、状态、操作、加载、空状态和异常与竖屏一致。
- 从竖屏旋转进入横屏时复用现有列表数据和任务，不重新请求第一页。

### 9.2 MOD 详情

|区域|字段与动作|状态与异常|
|---|---|---|
|左侧|主预览图和缩略图|图片失败显示占位图；缩略图切换不改变当前 MOD|
|右侧|名称、来源、作者、版本、大小、更新时间、兼容性、简介、安装说明、依赖、冲突和更新记录|字段缺失显示“来源未提供”；长内容在右侧滚动|
|操作|固定在详情底部或右下区域|与竖屏使用同一设备状态和任务；旋转不重复执行|

### 9.3 已安装、启动检查与恢复建议

- 已安装页使用两列布局，字段、筛选、启停、更新和卸载规则与竖屏一致。

- 恢复建议同时展示变化摘要与三个恢复选项；选择前不修改任何状态。
- 横屏返回竖屏后恢复同一 MOD、详情章节、列表位置和任务进度。

## 10. 横竖屏切换规则

旋转时必须保留：

- 当前页签。
- 搜索词与排序方式。
- 当前筛选条件。
- 当前打开的 MOD。
- 详情阅读章节。
- 列表浏览位置。
- 下载、校验和安装进度。
- 启动检查结果和尚未提交的恢复选择。

|场景|旋转后的要求|
|---|---|
|可用 MOD 列表|单列与两列重排；数据集合、排序和滚动锚点不变|
|已安装页|布局重排；启停值、筛选和已有任务不变|
|MOD 详情|全屏结构与左右分栏互换；MOD ID、预览图和阅读章节不变|
|下载中|任务 ID、已下载字节和进度连续；不重发下载|
|校验或安装中|继续同一任务；不重新校验已完成阶段，不创建第二个安装|
|风险确认|保留弹层内容与当前选择，不视为用户确认|
|启动检查|保留已完成结果；未完成检查继续同一轮，不重复生成清单|
|恢复建议|保留异常证据和变化项，不自动执行任何选项|

页面旋转只改变布局，不重新发起目录接口、详情接口、下载或安装。任务由设备级任务管理器持有，以当前设备、DST 和 MOD ID 共同保证一个活动任务。

## 11. 状态与异常

### 11.1 状态定义

|系统状态|用户文案|允许操作|进入条件|退出条件|
|---|---|---|---|---|
|`available`|安装|安装、查看详情|本机无可用安装版本|创建安装任务或发现阻塞|
|`dependency_blocked`|缺少必要依赖|查看原因|硬依赖缺失、失效或本端不兼容|依赖信息恢复后回到 `available`|
|`queued`|等待下载|取消|安装任务已创建|开始下载或用户取消|
|`downloading`|下载中 N%|取消|开始接收主包或依赖包|下载完成、取消或失败|
|`verifying`|正在校验|等待|下载完成|校验通过或失败|
|`installing`|正在安装|等待|校验与目录检查通过|原子切换成功或失败|
|`enabled`|已安装 · 已启用 · 仅此设备|停用、更新、卸载|首次安装成功默认启用，或用户启用|用户停用、发现更新或卸载|
|`disabled`|已安装 · 未启用 · 仅此设备|启用、更新、卸载|用户停用|用户启用、发现更新或卸载|
|`update_available`|有新版本|更新、使用旧版、启停、卸载|本地版本存在且来源提供新包|更新成功、来源撤回新包或卸载|
|`failed`|安装失败|重试、查看原因|下载、校验、安装或更新失败|重试进入 `queued`，或清理未安装任务回到 `available`|
|`incompatible`|当前设备不兼容|查看原因|来源明确不支持当前平台或引擎|兼容信息变化后回到 `available`|

`update_available` 保留更新前的启用值。更新成功或失败后恢复该启用值；用户在等待更新时仍可启停旧版。

### 11.2 合法流转

```text
available
→ dependency_blocked / incompatible / queued
queued
→ downloading / available
downloading
→ verifying / failed / available
verifying
→ installing / failed
installing
→ enabled / failed
enabled
↔ disabled
enabled / disabled
→ update_available
update_available
→ enabled / disabled / failed
enabled / disabled / update_available / failed
→ available（卸载或清理未完成安装）
dependency_blocked / incompatible
→ available（阻塞条件解除）
failed
→ queued（重试）
```

页面不得自行推断状态。列表、详情、游戏详情入口、启动检查和恢复页均以设备级状态源为准。

### 11.3 操作反馈与防重

- 创建任务成功后按钮立即进入 `queued`，并禁用重复提交。
- 启用、停用、更新和卸载成功后刷新所有可见入口；失败时恢复操作前状态并显示原因。
- 同一 MOD 已有活动任务时，任何页面只绑定已有任务，不创建新任务。
- 危险操作仅包括卸载、停用变化项后重试；均需二次确认。
- 网络或目录刷新失败不覆盖本地已安装状态。

### 11.4 异常处理

|错误标识|场景|用户提示|处理与恢复|
|---|---|---|---|
|`NETWORK_UNAVAILABLE`|目录、详情或下载时无网络|“网络不可用，请检查后重试”|目录和详情可重试；已安装页仍读取本地状态|
|`DOWNLOAD_INTERRUPTED`|下载中断|“下载已暂停，可继续”|恢复同一任务；不重复已完成字节；取消则清理 staging|
|`STORAGE_INSUFFICIENT`|空间不足|“存储空间不足，清理后重试”|下载前终止；不创建可加载半成品|
|`PACKAGE_HASH_MISMATCH`|`package_hash` 不一致|“文件校验失败，请重试”|删除本次临时包；旧版和启用值不变|
|`PACKAGE_STRUCTURE_INVALID`|解包目录不符合 DST 规则|“安装包结构异常，暂时无法安装”|不切换版本指针；保留旧版|
|`DEPENDENCY_UNRESOLVED`|硬依赖闭包不完整|“缺少必要依赖：{最短原因链}”|禁止安装主 MOD或启动时跳过|
|`PLATFORM_INCOMPATIBLE`|当前平台或引擎不兼容|“当前设备不兼容”|禁止新安装；已安装项在启动检查中跳过|
|`SOURCE_UNAVAILABLE`|来源或下载地址失效|“来源已失效，暂时无法重新安装或更新”|从可用列表下架；已安装版本仍可使用|
|`TASK_CONFLICT`|同一 MOD 已有活动任务|“任务已在进行中”|绑定已有任务，不新增任务|
|`ATOMIC_SWITCH_FAILED`|版本指针切换失败|“安装未完成，已保留原版本”|恢复旧指针；新目录不可被加载|
|`LOCAL_FILE_MISSING`|已安装文件缺失|“本地文件不完整，本次将跳过”|启动清单标记跳过；提供重新安装|
|`LOG_EVIDENCE_MISSING`|游戏日志无法确认加载|“无法确认 MOD 是否实际加载”|不计入实际生效；保留原始日志和解析结果|
|`UNINSTALL_PARTIAL`|卸载未完整结束|“卸载未完成，请重试”|扫描受控目录后显示真实状态；不删除存档或配置|

### 11.5 外部来源边界

- MOD 改名时通过来源 ID 保持安装关系，不生成重复条目。
- MOD 被删除后从可用列表下架，已安装文件仍可在本地使用。
- 下载源失效时禁止重新安装和更新，不远程删除已安装版本。
- MOD 转移到其他游戏或 DLC 后停止向 DST 新用户展示；已安装用户看到兼容性提示。
- 缺少兼容、依赖或冲突信息时显示“来源未提供”；兼容性未知按风险项处理。

### 11.6 时间与极端数据

- 页面更新时间按设备当前时区显示为 `YYYY-MM-DD HH:mm`；来源只提供日期时显示 `YYYY-MM-DD`。
- 任务、启动清单和日志证据保存 ISO 8601 时间及时区，跨端排查不得只保存本地时分。
- 安装数和启用数为 0 时显示 `0`；无已启用 MOD 时生成项目为空的清单并直接启动。
- 只有 1 个 MOD 时仍使用标准卡片和清单结构，不使用特殊页面。
- 超长名称、作者和短简介在卡片截断，详情展示完整文本；特殊字符和 emoji 作为普通文本展示。
- 依赖项多于当前屏幕可展示数量时列表滚动，不截断依赖闭包；阻塞原因仍优先展示最短原因链。
- 同一分页返回重复 MOD ID 时按 MOD ID 去重，设备级安装记录优先于目录卡片缓存。

|AC-ROTATE-01|下载中旋转|APP 限速下载中|竖转横再转竖|任务不变、进度连续、下载和安装任务各只有一个；任务日志可核对|
|AC-ROTATE-02|详情旋转|详情已滚动到更新记录|旋转并旋回|当前 MOD、预览项和阅读章节保留；不重发详情请求|
|AC-ROTATE-03|列表旋转|已设置页签、搜索、排序、筛选并滚动|旋转|条件和列表位置保留；只重排布局|
|AC-BACKGROUND-01|APP 前后台|下载任务进行中|进入后台再返回前台|任务继续或显示系统暂停；恢复同一任务，不重复下载或安装|

|AC-UNINSTALL-01|卸载依赖项|MOD B 硬依赖已启用 MOD A|卸载 A 并确认|确认页列出 B；只卸载本机 A；B 下次启动检查被跳过；存档与配置未变化|
|AC-PREFLIGHT-01|全部正常|2 个完整且兼容的已启用 MOD|点击启动|两项均为本次生效；生成含版本和哈希的 `resolved_launch_manifest`|
|AC-PREFLIGHT-02|存在损坏项|1 个完整 MOD、1 个损坏 MOD 均已启用|点击启动并继续|损坏项跳过且显示原因；完整项生效；游戏可启动|
|AC-PREFLIGHT-03|存在风险项|1 个软冲突或兼容未知 MOD 已启用|点击启动并确认风险|风险项可在用户确认后继续；取消不改变安装或启用状态|
|AC-BASELINE-01|没有已启用 MOD|当前设备无已启用 MOD|点击启动|无额外确认页；清单项目为空；基础游戏可启动|
|AC-LOG-01|实际加载证据|清单至少有 1 个本次生效项|启动并解析游戏或引擎日志|日志可核对 MOD ID 和本地版本；文件复制不作为生效证据|
|AC-LOG-02|证据缺失|日志不可读或缺少对应项|完成启动结果核对|显示无法确认；该 MOD 不计入实际生效；保存原始日志与解析结果|
|AC-RECOVERY-01|变化后异常退出|已有最近成功清单，本次集合变化后异常退出|再次启动|只展示停用变化项后重试、无 MOD 启动、保持当前设置；默认不执行|
|AC-RECOVERY-02|无 MOD 恢复|进入恢复建议|选择无 MOD 启动|本次使用空清单；设备级安装和启用值不变|
|AC-SAFETY-01|文件安全边界|准备可校验的 DST 存档和 MOD 用户配置|执行更新失败、卸载和恢复|存档和用户配置哈希不变；只变化受控 MOD 程序文件|
|AC-SOURCE-01|来源下架或失效|MOD 已安装，来源随后失效|刷新列表并查看已安装页|可用列表不再展示；已安装版仍可启动；不能重新安装或更新|
|AC-NETWORK-01|弱网和断网|已有安装任务或本地已安装项|断网后查看页面和任务|目录显示重试；已安装状态可读；任务暂停或失败可恢复，不生成重复任务|

所有验收必须保留页面录屏或截图、设备级状态记录、任务状态时间线、本地文件清单、`resolved_launch_manifest`、原始游戏日志和解析结果中与用例相关的证据。缺少游戏侧日志时不得判定“实际加载”通过。

## 13. 数据与灰度

### 13.1 核心漏斗

```text
进入 MODS
→ 查看详情
→ 点击安装
→ 下载成功
→ 安装成功
→ 保持启用
→ 进入启动检查
→ MOD 进入 resolved_launch_manifest
→ 游戏日志确认实际加载
→ 游戏成功启动
```

### 13.2 事件

- `mods_entry_view`
- `mods_detail_view`
- `mods_install_click`
- `mods_download_result`
- `mods_install_result`
- `mods_enable_change`
- `mods_update_result`
- `mods_uninstall_result`
- `mods_preflight_result`
- `mods_launch_result`
- `mods_recovery_action`

安装与启动相关事件至少携带游戏 ID、MOD ID、本地目标版本、当前设备安装标识、设备平台、屏幕方向、任务 ID、`package_hash`、结果和失败原因。Mac 的屏幕方向记为不适用。事件字段和去重口径在埋点与指标字典中固化。

### 13.3 核心指标

- 一键安装成功率。
- 下载、校验和安装失败原因分布。
- 已启用 MOD 实际生效率。
- 携带 MOD 的游戏启动成功率。
- MOD 变化后的异常退出率。
- 异常退出后的恢复成功率。
- 安装完成后 7 日内再次使用率。
- 重复下载或重复安装任务数。
- 游戏存档或用户配置丢失事件数。

### 13.4 灰度

- 首批接入 20–50 个经过双端包、依赖、哈希和日志验证的 DST MOD。
- 邀请 20–50 名包含 Mac 和 APP 用户的灰度用户。
- 完成技术 Go/No-Go 后再开始用户灰度，不自动全量。
- 指标达到 3.3 门槛且无存档或配置丢失，才可提交扩大灰度评审。
- 发生存档或配置丢失、更新失败后旧版不可启动、旋转产生重复任务或无法获取实际加载证据时停止新增曝光和新安装。
- 停止灰度后保留用户已安装可用版本，提供无 MOD 启动和恢复建议，不远程自动卸载或修改启用状态。

### 13.5 隐私与权限

- 仅收集当前设备安装标识、设备平台、屏幕方向、MOD ID、任务结果、启动结果和失败原因，用于任务幂等、质量分析和故障定位。
- 设备安装标识不得替代账号，不用于还原用户真实身份，不在页面对其他用户展示。
- 不采集账号凭证、游戏存档内容或用户 MOD 配置内容；安全验收只比较文件哈希是否变化。
- MODS 不新增相机、位置、通讯录、麦克风等系统权限。
- 发布前将新增采集项纳入现有隐私清单和埋点评审；未通过评审不得开始用户灰度。

## 14. 依赖、风险与发布前置

### 14.1 外部数据依赖

每个来源 MOD 至少提供：

- 来源 ID、来源 MOD ID 和 DST 统一游戏 ID。
- 名称、作者、简介和预览图。
- 当前版本、更新时间和文件大小。
- 按 Mac、APP 区分的下载地址。
- `package_hash`。
- 支持平台和引擎版本。
- 硬依赖、软依赖和已知冲突。
- 更新说明和安装说明。

缺少兼容、依赖或冲突信息时必须按 11.5 处理，不得伪装成平台已检测。

### 14.2 客户端与运行依赖

- Mac 与 APP 各自具备受控下载、staging、哈希校验、解包、版本目录和原子指针能力。
- APP 具备独立于页面生命周期的设备级任务管理器。
- Mac 与 APP 均能把 `resolved_launch_manifest` 交给 DST 启动链路。
- 游戏或引擎日志能提供实际加载 MOD ID 和版本证据。
- 本地状态源能被入口、列表、详情、已安装页、启动检查和恢复页共同读取。
- 服务端目录能按 DST 和平台返回来源、版本、包、依赖、兼容和冲突信息。

### 14.3 技术 Go/No-Go

完整页面开发前必须使用以下最小样本验证：

1. 一个 DST 精确游戏 ID：`steam:322330`。
2. 一个 Mac 目标设备和一个 APP 目标设备。
3. 一个在两端分别有可用包的 MOD。
4. 两端分别完成下载、`package_hash` 校验、安装、启用和启动。
5. 两端均从游戏或引擎日志确认实际加载。
6. 至少完成一次更新失败后的旧版回退。

任一端无法确认实际加载，结论为 No-Go：停止完整页面开发，先解决运行链路。

### 14.4 风险与控制

|风险|影响|控制|
|---|---|---|
|Mac 与 APP 实际加载路径不同|安装成功但游戏未生效|技术 Go/No-Go 必须读取两端游戏侧日志|
|外部依赖数据不完整|主 MOD 安装后无法使用|安装前计算硬依赖闭包；不可满足时禁止安装|
|更新覆盖可用旧版|游戏无法恢复|staging、哈希校验、原子切换和旧版保留|
|横竖屏重建任务|重复下载、安装或状态错乱|任务脱离页面生命周期，并按设备与 MOD 保证幂等|
|异常退出误归因|错误停用用户 MOD|只在清单变化时提示，且只提供建议，不自动修改|
|用户误认为跨端同步|另一设备未安装被视为故障|入口、已安装和卸载持续标注“仅此设备”|
|外部来源删除或失效|已安装用户无法恢复|保留本地可用版本，禁止新安装和更新，不远程删除|
|日志不可用|无法证明实际生效|不计入实际生效，停止扩大灰度并补齐日志链路|

### 14.5 发布前置

- 技术 Go/No-Go 结果为 Go，且保存两端安装、启动和日志证据。
- 端到端合同明确状态、任务、错误和外部字段。
- 埋点与指标字典明确事件、字段、去重键和指标公式。
- Mac、APP 竖屏、APP 横屏、旋转、后台、更新失败、日志和恢复用例全部通过。
- 灰度开关、停止线、无 MOD 启动和已安装版本保留策略可执行。
- 产品、客户端、服务端、测试和数据负责人确认同一术语与状态口径。
