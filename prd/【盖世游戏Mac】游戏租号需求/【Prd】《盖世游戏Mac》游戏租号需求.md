## 二、背景与目标

### 2.1 需求背景

高价单机游戏的购买门槛较高，传统租号又需要用户自行处理账号、密码和验证码。盖世游戏需要在 Mac 内完成选购、支付、登录、启动、到期和售后闭环，同时控制账号越权、资源并发和凭据泄露风险。

### 2.2 产品目标

1. 用户在盖世游戏内完成“发现 → 选权益 → 支付 → 登录 → 下载/启动 → 续租、到期或售后”。
2. 支付成功后即可使用，不向客户端展示账号或资源分配过程。
3. 订单清楚展示版本、租期、有效期、金额和当前可执行操作。
4. 后台统一管理商品、会员游戏库、账号库存、订单、售后和统计，并区分 APP 与 Mac 配置。

### 2.3 核心挑战

1. 支付、权益生效和账号资源的一致性。
2. Steam 及第三方登录信息的短时授权与回收。
3. 首次体验、时租、永久和会员权益的互斥与优先级。
4. 到期强退、续租、退款和资源释放的并发处理。
5. 历史订单按快照履约，不受后续调价或下架影响。

### 2.4 本期范围

- 租号曝光、搜索、游戏详情和确认订单。
- 热门游戏时租；非热门游戏首次体验、单游戏永久和会员。
- 会员中心、会员游戏库、订单中心、订单详情和退款进度。
- Steam 一键上号、手动登录、第三方登录信息和目标游戏限制。
- 15分钟临期提醒、续租、到期回收、售后申请与撤销。
- 商品、会员、账号、订单、售后、统计、灰度和操作记录后台。

### 2.5 本期不包含

- 用户自主出租账号。
- 新支付渠道和永久会员。
- 标准版以外的新订单版本选择。
- 客户端“账号分配中”“资源分配中”等内部状态。
- CDKEY 卡密、激活和发货流程。

## 三、故事介绍

### 3.1 用户与运营场景

1. **热门游戏时租**：用户选择2—23小时、日租或周租，支付后登录并进入游戏详情，自行下载和启动。
2. **非热门游戏**：新用户可选首次体验2小时、单游戏永久或开会员；首次体验使用后默认单游戏永久。
3. **账号无感分配**：用户每次启动时由系统自动准备可用账号，不看到中间分配状态。
4. **售后处理**：用户提交问题后返回订单详情；点击“售后详情”弹出三阶段售后进度，处理中可撤销，退款完成后立即回收会话和凭据。
5. **运营配置**：运营分别维护 APP、Mac 商品和会员配置，历史订单继续按支付时快照履约。

### 3.2 价值分析

- 用户用更低成本体验游戏，减少登录操作，遇到问题有明确售后入口。
- 平台新增租号、单游戏永久和会员收入，并提升账号库存利用率。
- 运营可在同一后台管理商品、资源、订单、退款和业务效果。

### 3.3 核心体验路径

**主链路：** 发现可租游戏 → 游戏详情 → 租号开玩 → 确认订单 → 支付 → 登录 → 游戏详情 → 下载/启动。

**订单链路：** 订单中心 → 订单详情 → 登录游戏、续租、查看登录信息或申请售后。

**到期链路：** 剩余15分钟提醒 → 续租则顺延 → 未续租则到期结束、撤销会话、轮换凭据并释放账号。

### 3.4 产品指标

1. 租号曝光到详情点击率。
2. 详情到支付成功转化率。
3. 支付成功到登录、启动成功率。
4. 会员开通率、续费率和会员游戏启动率。
5. 账号使用率、复用率、售后率和退款率。

### 3.5 路径规划

- **本期**：完成标准版租号、单游戏永久、会员、登录、订单、售后和后台闭环。
- **后续**：根据数据评估更多游戏平台、游戏版本和用户出租能力，不在本期预先上线。

### 4.4 服务端公共规则与状态

#### 4.4.1 可租判定

1. 新订单可租需同时满足：功能开放、地区可用、商品上架、权益方案有效、价格有效、用户资格通过且资源可履约。
2. 发现页可短时缓存摘要；进入确认订单、创单、支付和启动时必须重新校验。
3. 已支付永久或会员权益不因商品下架失效；目标游戏暂时无资源时保留权益并告警。

#### 4.4.2 权益判定、资格核销与订单锁价

1. 权益判定顺序为：有效租赁 → 单游戏永久 → 有效会员且游戏在会员库 → 无权益。客户端只展示服务端判定结果。
2. 首次体验资格按盖世游戏账号全平台唯一；支付成功时核销，重复支付回调不得重复核销。
3. 待支付订单锁定SKU、租期、游戏原价、订单金额、币种、价格版本和资格快照30分钟。
4. 锁价期内后台调价不改原订单；资格失效、商品下架或地区关闭时禁止继续支付，并关闭原订单。
5. 单游戏永久和会员支付成功后立即生效；已有首次体验订单不延长、不重置，也不阻止新权益生效。

#### 4.4.3 订单状态

| 客户端状态 | 允许流转 | 可执行操作 |
|---|---|---|
| 待支付 | 租赁中、已结束 | 取消、继续支付 |
| 租赁中 | 退款中、已结束 | 登录、续租、售后 |
| 退款中 | 已退款 | 查看进度 |
| 已退款 | 终态 | 查看进度、重新租用 |
| 已结束 | 终态 | 重新租用 |

售后状态：`未申请 → 已提交/审核中 → 已撤销 | 已拒绝 | 退款中 → 已退款`。非法流转拒绝并告警。

#### 4.4.4 幂等与一致性

1. 创单、支付回调、首次体验资格消耗、会员续费、时租续租、售后提交/撤销、退款、换号和释放均使用业务幂等键。
2. 超时或结果未知时先查询原请求，仅在确认未受理后重试。
3. 支付成功、权益生效和首次体验资格消耗在同一业务事务内完成。
4. 退款成功但回收失败不回滚退款；通过异常库存和补偿任务继续处理。

#### 4.4.5 关键返回字段

| 业务对象 | 客户端所需信息 |
|---|---|
| 租号摘要 | 展示状态、最低金额、在租数、是否可进入确认订单 |
| 计价结果 | 游戏、标准版、权益方案、租期、原价、订单金额、币种、价格版本、失效时间 |
| 订单 | 订单号、状态、版本、租期、支付截止、有效期、金额、支付方式、允许操作 |
| 会员 | 开通状态、套餐、开始时间、有效期、允许续费状态 |
| 售后 | 问题类型、描述、提交时间、状态、是否可撤销、退款进度 |

敏感凭据通过独立短时授权接口返回，不进入订单和通用详情响应。

#### 4.4.6 首次体验到期与权益切换一致性

1. 服务端时间为租期唯一口径；客户端本地倒计时只用于展示。
2. 首次体验到期前购买单游戏永久或会员，新权益支付成功后立即接管后续使用；首次体验订单仍按原有效期结束。
3. 首次体验到期且无新权益时，结束目标游戏并执行资源回收；再次启动按当前权益重新判断。
4. 时租续租成功后原订单有效期精确增加所选时长，订单、账号、游戏和版本不变。
5. 原订单已到期、已退款或资源存在不可续冲突时阻止续租，不改变原绑定。
6. 到期回收不删除安装包、设置和个人存档。

#### 4.4.7 登录信息短时授权与凭据回收

1. “登录游戏”负责执行一键或手动登录；订单“登录信息”只展示凭据，两者共用当前使用单，但查看凭据不判定登录成功。
2. 每次打开、查看、复制或获取验证码前校验用户、设备、订单归属、状态、有效期、目标游戏和账号绑定。
3. 授权绑定当前用户、设备、订单、游戏和会话，最长5分钟且不超过订单有效期；接口按操作返回最少字段。
4. 账号和密码默认遮罩；验证码按第三方生命周期返回并限频。弱网、超时和错误提示不得回显敏感值。
5. 复制敏感值60秒后仅在剪贴板仍等于该值时清除；用户已复制其他内容时不得覆盖。
6. 退后台、退出账号、到期、退款、换号或结束租期时，客户端清理敏感视图，服务端撤销授权。
7. 资源回收顺序为撤销会话、轮换凭据、释放账号；任一步失败时账号转异常库存并告警，旧授权不得继续使用。

### 4.5 边界条件与异常处理

| 场景 | 处理 | 用户结果 |
|---|---|---|
| 价格变化 | 阻止旧价支付并重新计价 | 价格已更新 |
| 待支付超时 | 关闭订单并释放锁定资源 | 订单已取消 |
| 支付结果未知 | 查询原订单 | 正在确认支付结果 |
| 时租支付成功但无资源 | 进入退款处理 | 可查看退款进度 |
| 永久/会员启动无资源 | 保留权益并告警 | 当前资源繁忙，请稍后重试 |
| 登录授权失效 | 关闭敏感内容 | 登录信息授权已失效 |
| 非目标游戏 | 阻止获取、下载和启动 | 返回目标游戏、切换账号或去租号 |
| 售后重复提交/撤销 | 返回原结果 | 不创建重复申请 |
| 退款成功但释放失败 | 保持已退款，账号转异常 | 退款结果不受影响 |
| 会员库搜索无结果 | 保留关键词 | 未找到相关会员游戏 |

### 4.6 非功能需求
