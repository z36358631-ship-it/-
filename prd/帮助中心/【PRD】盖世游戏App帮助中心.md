## 一、文档概述

### 1.1 背景概述

- **需求背景：** [已确认] 在 App 设置中加入帮助中心，复用发行平台的帮助内容管理逻辑，目录与文章可编辑，图文正文新增插入视频。
- **当前方式：** 原 App 设置提供“反馈&建议”，其内含“提交反馈”“反馈历史”“官方网站”；当前截图没有独立帮助中心入口。发行平台已有“导航目录＋目录子文档”管理及富文本图文编辑。
- **问题：** 玩家缺少设置内集中查阅操作说明的入口；运营复用现有内容结构即可维护教程，无须逐篇开发页面。
- **证据：** 需求评论、两张 App 原页面截图、发行平台 Demo，以及2026/9/24《632需求评审.txt》00:05–07:59的帮助中心结论；07:59后其他需求不纳入本次范围。本轮用户截图进一步确认APP协议八项及列表多语言操作位置，最新参考图明确编辑页语言页签，以及只配置启用语言和默认语言的“多语言设置”弹窗。尚无访问量、咨询量或阅读完成率基线。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | App 设置入口、帮助目录与文章阅读、后台目录与文章管理；国内包／海外包独立配置，展示竖屏及推导的掌机横屏。原“反馈&建议”入口及其三个功能不迁移、不合并。 |
| 业务边界 | 面向玩家的独立帮助内容；复用发行平台的数据层级和编辑行为，不复制开发者认证等文章。APP协议仅用于帮助文章的适用范围，不另增独立渠道字段，不扩大为全 App 协议配置；[已确认] 版本控制属于灰度，不纳入帮助中心；本模块不配置或筛选App版本。无 C 端搜索、客服、评价、推荐及新增登录流程。 |
| 运营边界 | 运营在同一对象内集中维护多语言目录、文章及媒体，逐条发布；首批教程正文由运营校对。Demo 示例内容只用于评审，不代表正式支持说明。 |
| 人力边界 | 产品确认内容结构与范围；设计确认 App 页面；客户端负责入口、返回及视频生命周期；服务端负责内容管理、发布与媒体服务；运营提供多语言素材；测试检查阅读与发布边界。 |

### 1.3 术语定义

| 术语 | 定义与判断口径 |
|---|---|
| 导航目录 | 帮助内容的分组，一个目录可包含多篇文章；App 列表中显示为组标题。 |
| 目录子文档 | 归属一个目录的帮助文章，含多语言标题和富文本正文。 |
| 草稿／已发布快照 | 草稿用于编辑；已发布快照是 App 可读内容。修改草稿不覆盖快照，发布成功才替换相应对象。 |
| 内容对象 | 目录或文章是一个对象，各语言内容共用编号、包与公共配置；enabledLanguages记录启用语言，defaultLanguage记录对象默认语言，均与内容一起作为草稿发布，不按语言复制对象。 |
| APP协议 | 文章共用的适用协议多选集合；至少一项，协议内为“或”，与包条件为“且”。所有语言共用集合，不按协议复制文章。 |

### 3.2 B 端功能需求

[已确认] 国内包／海外包配置相互独立；一个目录或文章对象在编辑页按语言页签维护名称或标题正文；列表“多语言”和编辑页“管理多语言”打开同一设置弹窗。设置只调整启用语种和默认语言，不编辑正文、不新建对象，不提供自动翻译或独立语言发布。<br>[建议方案] 正式后台沿用现有内容管理授权，不另建角色系统。服务端校验权限及 App 内容范围，越权不写入。发布、删除及排序沿用操作日志；多人修改拒绝静默覆盖。Demo 仅模拟运营视角，无真实鉴权、日志、并发控制或网络写入。
