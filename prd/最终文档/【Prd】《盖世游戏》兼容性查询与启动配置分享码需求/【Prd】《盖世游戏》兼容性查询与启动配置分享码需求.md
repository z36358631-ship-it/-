## 一、文档概述

### 1.1 背景概述

- **需求背景：** 盖世游戏需要提供类似 GameNative Compatibility 的游戏兼容性查询能力，并衔接盖世游戏现有启动配置导入能力。
- **当前解决方式：** 用户自行查找兼容信息、比对硬件参数，再手动调整启动配置。
- **存在问题：** 查询门槛高，兼容结论与启动配置分离；用户知道游戏能否运行后，仍需自行寻找和调整配置。
- **问题证据：** 现有高保真 Demo、设计规格及 2026/8/25—2026/8/26 评审结论已确认本期方案。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 新增 App 内嵌响应式 H5，覆盖兼容性查询页和兼容性评价页；支持 Android、Mac 数据及竖屏、横屏、桌面宽度；不区分地区。 |
| 业务边界 | 展示平台用户评价数据和实际运行数据；支持筛选、查看兼容结论和复制启动配置分享码。不做用户提交评价、举报治理、配置文件下载、一键应用、分享落地页、登录或会员限制。 |
| 运营边界 | 无。 |
| 人力边界 | 产品负责规则与验收口径；UI 负责 H5 页面；服务端负责 H5、兼容数据和启动配置数据；客户端提供 H5 容器、平台信息和剪贴板 Bridge；测试覆盖 Android、Mac、横竖屏、桌面宽度及复制降级。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 兼容记录 | Compatibility Record | 一次真实运行结果，不是游戏汇总。同一游戏因机型、系统或运行环境不同可有多条记录。 |
| 机型 | Device Model | Android 为手机型号；Mac 为带芯片版本的 Mac 机型。不包含独立 CPU、处理器、GPU 或芯片候选。 |
| 评级 | Rating | 1—5 分。筛选项“X 分及以上”包含 X 分及所有更高分记录。 |
| 兼容状态 | Compatibility Status | 严格四选一：不可玩、基本可玩、完美兼容、有部分问题。每条记录只显示一个状态。 |
| 有效启动配置 | 无 | 与当前平台、游戏和兼容记录一致，且配置与记录可双向关联的启动配置。 |
| 分享码 | Share Code | 可由盖世游戏现有导入能力识别的文本，格式为：`复制打开盖世游戏导入PC引擎设置方案：[游戏名称][系统智能设置方案][GPU:原有GPU字段]SCFG##现有编码`。 |
| App Bridge | 无 | App 向 H5 提供平台信息和剪贴板等原生能力的调用通道。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向普通玩家的游戏兼容性查询 H5，提供真实运行记录、兼容结论及对应启动配置分享码。 |
| 目标用户 | 不知道目标游戏能否在自己设备运行，希望直接复用可用配置的玩家。 |
| 核心目标 | 降低兼容信息查询和启动配置使用门槛，减少用户自行比对硬件、反复试错的成本。 |
| 使用场景 | 用户准备在 Android 或 Mac 上运行目标游戏，需要先确认可玩性或寻找可复用配置。 |
| 功能概述 | H5 识别当前平台；用户按游戏、机型和评级筛选兼容记录；点击记录查看兼容性评价；在记录或详情复制同一份分享码。 |

### 2.2 产品流程

**核心流程：** 用户进入兼容性查询 H5 → 系统识别 Android 或 Mac → 用户查看热门记录或筛选结果 → 点击记录查看兼容性评价 → 在记录或详情复制分享码 → 前往盖世游戏使用已有导入能力。

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 不涉及。

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容性要求 | 同一 H5 支持 Android、Mac、手机竖屏、手机／掌机横屏和桌面宽度；页面不得横向溢出。 |
| 平台隔离要求 | Android 与 Mac 的游戏、机型、兼容记录和启动配置必须按当前平台读取；任何加载或校验失败均不得回退展示另一平台数据。 |
| 原生能力降级 | 复制依次使用 App Bridge、Clipboard API、`execCommand`；任一方式失败后继续尝试下一方式，全部失败才显示失败状态。 |
| 数据完整性要求 | 正式兼容记录必须关联真实有效启动配置；H5 不生成或补齐虚假正式配置。分享码编码沿用现有逻辑，本期不重新定义。 |
