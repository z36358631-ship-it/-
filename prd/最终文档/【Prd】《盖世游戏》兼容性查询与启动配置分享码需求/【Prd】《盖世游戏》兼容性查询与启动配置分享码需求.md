## 一、文档概述

### 1.1 背景概述

- **需求背景：** 玩家判断目标游戏能否在某款手机上运行时，需要分散查资料、手动试配。
- **当前方式：** 按游戏和硬件参数查经验，再自行调整启动配置。
- **主要问题：** 兼容结论口径不一，运行记录与可复用配置未形成完整链路。
- **新增场景：** 进阶用户希望替换内置兼容层或 GPU 驱动；新手希望直接复用已配置方案，无需填写技术参数。仅能本地导入、其他设备无法取得依赖时，分享无法成立。
- **分享场景：** 用户查到可用的兼容结论后，希望把“查兼容性”直接发给尚未安装盖世游戏的人。现有分享只有 SCFG 分享码，必须在 App 内粘贴才能看结果，站外无法查询；本轮在查询页右上角增加分享入口，拉起 App 通用分享，分享固定站外查询页链接。
- **依据：** 2026/9/30 玩家聊天及六张现有方案页面截图；“同芯片运行成功次数”来自玩家补充，不等于成功率。入口依据为 2026/8/21—9/17 的 28 天数据：游戏详情页活跃用户 2,016,043，平均互动 6 分 02 秒；“玩游戏”页活跃用户 1,700,035。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | Android App 原生页面及内嵌 H5，覆盖手机竖屏、掌机横屏；国内、海外采用同一业务规则。本轮新增站外只读查询页：浏览器可直接打开，无 App Bridge、无登录态。不涉及 Mac 原生页面。 |
| 业务边界 | H5：首页 PC 游戏频道和游戏详情双入口、兼容记录、评价详情、复制分享码，不增加直接下载或应用按钮。查询页右上角增加分享入口，点击直接拉起 App 通用分享（微信、朋友圈、QQ、微博、复制链接），分享内容为固定站外查询页链接；站外只读页只做查询与结果浏览，不复制分享码、不应用配置，仅引导打开或下载盖世游戏。原生：在现有启动方案列表、编辑与详情内增加受支持组件导入、依赖可获取检查、分享及应用。首期仅开放兼容层、GPU 驱动自定义导入；其余组件保留内置选择。不新建插件商店、评价提交、举报、分享管理或后台页面。 |
| 运营边界 | 不增加运营配置页面；组件是否允许分发、来源失效及公开方案不可用状态由现有平台能力支撑，未具备时不开放相关分享。分享链接固定，不新增渠道位、分享素材或分享模板配置，渠道能力沿用现有通用分享。 |
| 数据边界 | H5 每条记录须关联能生成现有有效分享码的配置；原生方案保存完整配置和实际启用依赖。同芯片统计只采用可验证运行记录，不将用户选择比例改称成功率。站外只读页与 App 内查询使用同一数据源、同一分类与排序口径，但不携带筛选参数、不识别当前机型。 |
| 人力边界 | 客户端负责原生入口、文件选择、组件校验与准备、配置切换、恢复、WebView 能力及通用分享拉起；服务端负责 H5、站外只读页及固定链接、记录及方案数据、公共组件获取与运行数据归集；设计、测试分别核对横竖屏和主流程、失败恢复，并覆盖站外页无 Bridge 的降级表现。 |

### 1.3 术语定义

| 术语 | 定义与判断口径 |
|---|---|
| 兼容记录 | 一次实际运行结果。同一游戏因机型、系统或配置不同，可有多条记录。 |
| 机型 | Android 手机型号，不提供独立处理器、CPU 或 GPU 筛选。 |
| 兼容性筛选 | 选项为全部、完美兼容、基本可玩、部分兼容、不可玩；单选并按类别精确匹配，不含“及以上”。 |
| 兼容状态 | 完美兼容、基本可玩、部分兼容、不可玩，四选一；无法确定时显示“暂无兼容数据”，不归入四类。 |
| 有效启动配置 | 与当前游戏和兼容记录匹配，并可生成现有格式分享码的配置。 |
| 分享码 | `复制打开盖世游戏导入PC引擎设置方案：[游戏名称][系统智能设置方案][GPU:记录中的GPU]SCFG##现有编码` |
| 通用分享 | App 现有的分享面板，本轮包含微信、朋友圈、QQ、微博与复制链接；不新增渠道，也不自建分享页或分享管理页。 |
| 固定分享链接 | 由服务端下发的站外查询页地址，不带游戏、机型、兼容性等筛选参数；任何人打开拿到的是同一份查询工具。 |
| 站外只读查询页 | 浏览器可直接打开的只读查询页（正文简称站外页），无 App Bridge、不识别当前机型；只提供查询与结果浏览，不复制分享码、不应用配置，仅引导打开或下载盖世游戏。 |
| `game_id` | 游戏详情入口传给 H5 的游戏标识，用于预选当前游戏。 |
| 当前机型 | App 识别的本机型号；进入 H5 时默认选中，识别失败则不预选。 |
| 启动方案 | 与确定游戏关联、可保存、分享或应用的原生配置对象；不等同于单条兼容评价。 |
| 方案版本 | 保存或分享时固定的配置内容及依赖版本。修改后产生新版本，不改写已分享版本或历史运行记录。 |
| 自定义组件 | 在受支持类型中导入的兼容层或 GPU 驱动包；不是通用脚本或任意插件。 |
| 有效依赖 | 当前配置实际启用的组件及其关联依赖；固定精确内容和版本，未启用组件不强制下载。 |
| 复制方案 | 原生详情的“复制”：生成个人本地副本，不写入剪贴板、不应用、不自动云分享。H5 的“复制分享码”仍只写入剪贴板。 |
| 应用成功 | 所需依赖已准备，当前游戏完整切换到目标方案；不代表游戏已启动或运行成功。 |
| 同芯片运行成功 | 相同游戏、游戏构建、方案版本、芯片、引擎及组件内容下，取得可验证进入可游玩状态的运行结果；不能仅凭进程启动或存活时长认定。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品定位 | 查询兼容记录，并通过原生启动方案复用确定配置及所需组件。 |
| 目标用户 | 判断游戏能否运行的新手；需要自定义组件并分享方案的进阶用户。 |
| 核心目标 | 让查询结果有可复用配置，分享方案在其他符合条件的设备上可获取完整依赖。 |
| 使用场景 | 启动前查记录；进阶用户调整并分享方案；新手查看适用条件后应用。 |
| 功能概述 | H5 按游戏、机型、兼容性查询并复制分享码，查询页可分享固定站外链接；原生方案沿用现有列表与分组，作者按需导入组件，接收者查看详情后自动准备依赖并应用。各路径不新增互相跳转。 |

| 兼容状态迁移 | 有效新类别优先旧数字评分；旧名称“有部分问题”归一为“部分兼容”。仅缺少有效类别且旧 rating 为 1—5 的有效数字时迁移：4≤rating≤5 为完美兼容，3≤rating＜4 为基本可玩，2≤rating＜3 为部分兼容，1≤rating＜2 为不可玩。缺失、空值、非数字及越界值不补默认分，也不裁剪为有效值，统一为未知并显示“暂无兼容数据”；不命中四类筛选。旧分与截图中的折算分仅作历史数据迁移或统计，不在前台展示，不作数值筛选或数字排序，也不并入同芯片成功统计。 |
| 复制能力 | 优先调用 App 剪贴板能力；不可用时依次尝试 Clipboard API、`execCommand`。 |
| 访问权限 | H5 查询和复制分享码无需登录或会员；原生公开分享需现有账号权限，不新增会员门槛。站外只读页在浏览器直接可查，不要求登录、不要求安装 App。 |
| 分享能力 | 复用 App 现有通用分享（微信、朋友圈、QQ、微博、复制链接），本轮不新增渠道、不新增分享管理后台。渠道结果以现有回执为准，不可判定时不显示“分享成功”，只有复制链接给出本机可验证结果。 |
| 分享链接 | 固定路径、不带游戏／机型／兼容性参数，由服务端下发，前端不硬编码域名；同一链接在任意设备打开都是同一份查询工具。域名、协议及是否带渠道标识待确认，见第五章。 |
| 站外页数据 | 站外只读页与 App 内共享同一数据源、同一分类与排序口径；不依赖 App Bridge、不接收也不推断当前机型，URL 中不出现设备或用户标识。 |
| 入口参数 | 客户端传当前机型；游戏详情入口另传 `game_id`。参数缺失或无效时按页面规则降级，不阻断 H5。 |
| 原生配置来源 | 方案绑定确定游戏、版本和完整有效值；同名同版本但包内容不同视为不同制品。已分享版本不可原地改写，更新产生新版本，旧使用者不静默升级。 |
| 原生依赖获取 | 分享与应用检查所有实际启用依赖及其关联依赖，固定内容、版本和可获取来源；未启用项不强制下载。作者本机路径不能成为他人下载地址；内容校验一致不等于组件安全或游戏一定可运行。 |
| 新旧能力兼容 | 现有分享码能否表示自定义组件和完整依赖尚未确认。H5 继续只展示能生成现有有效码的记录，不承诺新增方案均能由 H5 完整复用；不修改编码算法。 |

### 4.2 埋点与指标

**数据结论：** 新增同芯片运行记录归集与展示；事件名称为建议命名，实际对接需保持下述含义。未取得可靠可游玩状态信号时，不开启成功数字展示，不使用模拟数据补齐。V1.9 另增查询页分享与站外页浏览、转化事件，只用于评估分享链路，不并入同芯片统计，也不代表安装或激活成功。

#### 4.2.1 指标口径

| 指标 | 计算与排除项 | 去重及时间窗口 | 展示与用途 |
|---|---|---|---|
| 同芯片成功次数 | 相同游戏、游戏构建、方案及版本、芯片、引擎与有效组件内容组内，取得经验证可游玩结果的运行次数 | 同一次启动以唯一运行标识去重；重试为新运行。评审稿采用最近 30×24 小时，以该次启动时间落在窗口内归集 | 显示“成功 X 次”，不写“X 人成功”或成功率；应用、复制、导入成功不计入 |
| 成功设备数 | 上述成功记录中匿名设备标识的去重数量 | 与成功次数使用同一组和窗口；同设备多次只算一台 | 与成功次数同时展示，不能以次数代替设备规模 |
| 失败与未知 | 可识别失败信号记为失败；尚无可靠成功或失败结论时，主动退出、缺报或只观察到进程存活记为未知。已验证成功不因之后正常退出降级 | 与成功记录按同一运行去重；仅以更可靠证据修正原结果，不追加一条新运行 | 未知不强算失败；本期不计算成功率 |
| 无记录、未就绪与失败 | 有检测能力且无合格组显示“暂无同芯片运行记录”；无可靠检测显示“暂无可验证运行记录”；统计请求失败显示“运行记录加载失败” | 进入原生列表／详情读取当前可用统计，不自动轮询；重新进入可重试 | 数字未返回时不显示 0；统计失败不阻断方案详情和应用前置检查 |
| 分享链路 | 分享面板拉起次数、各渠道点击次数、站外页访问次数、站外页打开／下载点击次数分段统计，不合并成“分享成功” | 同一面板一次拉起算一次；站外页访问按会话去重，不做跨端合并；窗口按自然日 | 仅评估分享入口是否有效，不对外展示，也不与同芯片成功次数混算 |

**归集边界：** 不混合不同游戏构建、方案版本、引擎或组件内容。游戏构建未知不能混入已知构建组；用户主动反馈与自动验证记录区分，不合并计数。无稳定匿名设备标识时不展示设备数及整组统计，不用账号人数替代。原“用户选择比例”的口径不在本次改造范围，继续使用已有数据，不另造公式。

#### 4.2.2 运行、分享与站外页事件

| 事件 | 页面／类型 | 触发与成功 | 参数 |
|---|---|---|---|
| scheme_run_result | 原生游戏运行链路；新增／有同义事件时复用 | 为本次启动取得可验证结果或确定无法判定时记录。必须是方案真正用于该次运行的版本；同一运行只保留一份有效结果。上报重试沿用原运行标识，迟到更正替换原结果；缺报不自行补成功 | run_id, game_id, game_build, scheme_id, scheme_revision, soc_id, engine_version, component_set_id, device_anon_id, started_at, result, evidence_type |
| compat_share_open | 兼容性查询页；新增 | 点击右上角分享按钮并成功拉起面板时记录一次；同一面板内重复点击不重复计数，拉起失败单独记 failure | page=compatibility_query, source（home／game_detail）, platform（android）, result（success／failure） |
| compat_share_action | 通用分享面板；新增 | 点击渠道或复制链接并取得可判定结果时记录；渠道结果不可判定记 unknown，不补 success | channel（wechat／moments／qq／weibo／link）, result（success／failure／unknown）, url_type=fixed, page=compatibility_query |
| outside_query_view | 站外只读查询页；新增 | 页面加载完成时记录一次；不采集设备型号、不推断机型、不写用户标识 | platform=web, entry（share_link／direct）, has_filter=false |
| outside_query_action | 站外只读查询页；新增 | 点击“打开盖世游戏应用配置”或“下载盖世游戏”，或完成一次筛选时记录 | action（open_app／download／filter）, result（success／failure／unknown）, platform=web |

#### 4.2.3 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| run_id | string／是 | 一次真实启动尝试的唯一标识 | 示例：run-a001；上报重试不生成新值 |

| soc_id | string／是 | 规范芯片标识，不能用 GPU 显示名称代替 | 示例：soc-001；无法识别则不进入同芯片统计 |

| component_set_id | string／是 | 能唯一对应完整有效依赖内容与版本的集合标识 | 示例：set-001；包内容改变则值改变 |

| result | enum／是 | 对本次运行的判定；更正只能依据更可靠证据，已验证成功不因后续正常退出降级 | success＝经验证已进入可游玩状态；failure＝收到可识别失败；unknown＝尚无可靠结论，包括此时主动退出或仅有进程存活证据 |

### 4.3 组件与应用约束

| 项目 | 要求 |
|---|---|
| 可复现 | 完整配置与实际启用依赖分开定义；分享时全部有效依赖可取回同一内容，接收端不自动升级成最新版。 |
| 本地保护 | 应用准备必须隔离，不得提前改写当前游戏容器。全部成功才切换；任何失败或取消保持原配置和容器可用；不覆盖启动文件、存档、账号或其他游戏。 |
| 分享内容 | 不公开本机路径、环境变量及启动参数中的敏感值；运行所必需的引用无法转换时阻止分享，不能删除必需字段后伪装成可复用方案。 |
| 数据使用 | 运行信号和匿名设备统计沿用已有数据用途与授权机制；未具备适用授权或检测能力时不采集并展示该项，不假定已获新权限。 |
| 发布前置 | 组件格式、大小和适配矩阵、可分发来源、隔离准备与可靠恢复，均须验证后才能开放相应能力；本稿不表示已实现。 |

## 五、待确认项

| 待确认问题 | 推荐或条件式处理 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 兼容层／GPU 驱动具体支持哪些格式、大小、架构、引擎和设备；包元数据如何可信读取；底部“添加组件”原有类型是什么 | 工程给出明确支持矩阵及失败原因；不支持的包拒绝导入。文件大小和解压空间按实际能力确定，不编造统一阈值 | 原生导入、校验与空间验收 | 阻塞对应类型导入开放，不阻塞既有 H5 |
| 公共托管、可分发检查、完整有效依赖获取及失效维护是否具备 | 全部依赖能获取同一内容后才分享；未具备时本地保存，不能公开为可应用方案 | 自定义组件云分享，以及其他设备应用 | 阻塞自定义包公开分享 |

| 站外页是否需要 App 下载归因与安装统计 | 本轮只做只读查询与跳转，不做归因；如需归因另行确认设备标识与隐私口径 | 安装归因与投放评估 | 不阻塞 |
