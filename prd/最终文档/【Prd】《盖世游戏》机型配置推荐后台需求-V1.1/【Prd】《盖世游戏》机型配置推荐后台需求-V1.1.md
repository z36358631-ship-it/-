## 二、背景与目标

运营、客户端和内核团队目前缺少统一的数据面板，无法快速判断“哪个 GPU、哪款设备、哪款游戏、哪套配置”更容易成功运行，也无法直接圈选对应用户做内容触达或问题用户回流。

当前处理方式：运营向数据团队临时提取启动、机型和游戏数据，再在 Excel 中手工关联配置；客户端和内核主要依赖用户群反馈确定优化名单。该方式等待时间长、口径易不一致，也无法稳定复用到人群圈选。

本期目标：

1. 提供 GPU、设备型号、运行内存、游戏和配置方案维度的运行数据查询及导出能力。
2. 区分“能否成功运行”和“实际运行质量”，避免用单一时长阈值替代可玩判断。
3. 让运营按设备 GPU、设备厂商和近 30 天游戏偏好圈选人群，复用现有人群包进行后续触达。

本期不直接向 C 端推荐配置，不验证具体游戏是否流畅，也不新增日志采集后台。

### 2.1 成功指标与数据验证

- 运营可在后台独立完成“查询 → Tab 切换 → 查看配置 → 导出”，无需数据团队临时拉表。
- 上线验收抽样中，GPU、游戏、配置 MD5 和人群圈选结果与源数据逐项一致，不出现口径差异。
- 三类结果、平均帧率和平均单次时长均可追溯到明确的数据定义，报表不再通过差值推算失败数。

## 三、用户与核心路径

### 3.1 目标用户

- 运营：查询高成功率配置、圈选目标人群、导出人群包。
- 客户端/内核：定位失败率较高的 GPU、设备型号和游戏组合，制定兼容性优化顺序。

### 3.2 核心路径

```text
数据报表
├─ GPU运行数据 → 筛选/排序 → GPU / 设备类型 Tab → 导出
└─ 游戏运行数据 → 筛选/排序 → 游戏 / GPU / 配置方案 Tab → 配置详情 → 导出

会员管理
└─ 人群圈选与导出 → 设备GPU/设备厂商/最近下载游戏 → 查询人数 → 导出现有人群包
```

## 四、范围说明

### 4.1 本期范围

- GPU 运行数据报表，以及 GPU、设备类型两个页内 Tab。
- 游戏运行数据报表、GPU 分布、配置 MD5 分布和配置详情。
- 配置来源识别：云分享、系统配置、系统兜底、用户本地。
- 人群圈选新增设备 GPU、设备厂商、最近下载游戏条件。
- 报表按日/按月汇总、排序、分页和 CSV 导出。

### 4.2 本期不做

- CPU/SoC 统计维度。
- 失败日志自动采集与上传。
- 按“游戏 + 机型”配置日志采集开关及采集数量上限。
- H5 机型/游戏兼容性落地页。
- 资讯、社区内容中的配置一键应用。
- 本地导入游戏识别准确率优化。
- 用户分享激励、排行榜和奖励发放。

## 五、核心概念与统计口径

### 5.1 通用口径

| 指标/概念 | 最终定义 | 展示规则 |
|---|---|---|
| 统计日期 | 数据仓库聚合日期；默认按日，支持切换按月 | 按日展示 `YYYY-MM-DD`；按月展示 `YYYY-MM` |
| 启动设备数 | 统计周期内发起目标游戏启动行为的去重设备数 | 按设备 ID 去重 |
| 成功运行设备数 | 首帧已渲染，且帧率持续波动至少 5 秒的去重设备数 | 仅代表游戏已进入可运行状态，不代表高画质或高帧率 |
| 上报失败设备数 | 客户端明确上报启动失败结果的去重设备数 | 只统计明确失败上报，不得用启动设备数减成功运行设备数反推 |
| 未判定设备数 | 已发起启动，但未采集到成功或失败结果的去重设备数 | 用于识别崩溃、断网、进程退出、数据缺失等无法归因的情况 |
| 成功运行率 | 成功运行设备数 ÷ 启动设备数 | 百分比，保留 1 位小数；分母为 0 时显示 `—` |
| 平均帧率 | 成功运行会话的单场平均帧率再求算术平均 | 保留 1 位小数，单位 FPS；失败和未判定会话不参与 |
| 平均单次时长 | 成功运行会话从首帧渲染到退出的单场时长平均值 | 显示为 `X分X秒`；失败和未判定会话不参与 |
| GPU | 客户端上报的 GPU 标准名称 | 一级报表按 GPU 聚合；CPU/SoC 不参与本期统计 |
| 设备型号 | 客户端上报的厂商原始型号，通过兼容性评价设备字典映射为可读机型 | 未映射时展示原始型号并标记“未映射” |
| 运行内存 | 客户端上报的设备物理运行内存规格 | 同一设备型号按运行内存拆行统计 |

说明：启动、成功、失败数据来自不同事件链路，受延迟上报、跨日和数据缺失影响，原始指标可能不闭合；“未判定设备数”必须独立展示，失败数不得通过差值推算。

### 5.2 配置 MD5 口径

| 项目 | 规则 |
|---|---|
| 聚合标识 | 对实际运行配置 JSON 内容生成 32 位小写 MD5 |
| 参与字段 | DXVK 版本、VKD3D 版本、GPU 驱动、兼容层版本、CPU 转译器、转译参数模式及后续纳入运行配置的参数 |
| 不参与字段 | 方案名称、作者昵称、分享 ID、创建时间、更新时间、用户/设备标识等非运行参数 |
| 规范化 | 服务端按固定字段顺序、固定数据类型和 UTF-8 编码序列化；缺省值与空值按统一规则处理后再计算 |
| 变更规则 | 任一实际运行参数变化即生成新的 MD5；只改方案名称不生成新 MD5 |
| 历史兼容 | 新增运行参数后，包含新参数的配置按新内容生成新 MD5；历史配置保留原 MD5，不回写覆盖 |

### 5.3 配置来源

| 来源 | 定义 | 作者展示 |
|---|---|---|
| 云分享 | 用户通过云分享生成并被其他用户使用的配置 | 展示分享作者；详情至少可关联作者 UID 和昵称 |
| 系统配置 | 后台或系统为指定游戏/GPU 下发的正式配置 | 作者显示“系统” |
| 系统兜底 | 未命中指定配置时返回的全局默认配置 | 作者显示“系统” |
| 用户本地 | 用户在本地创建或修改、未形成云分享的配置 | 作者显示 `—` |

同一 MD5 若同时命中多个来源，按本次启动实际使用配置的来源统计，不合并来源字段。

### 5.4 最小数据契约

以下为报表聚合层的逻辑字段，物理字段名可复用现有数仓规范，但类型、空值和枚举必须满足下表：

| 逻辑字段 | 建议字段名 | 类型/格式 | 必填 | 说明 |
|---|---|---|---|---|
| 统计日期 | `stat_date` | Date，UTC+8 | 是 | 按日统计日期；按月时取自然月 |
| 汇总粒度 | `summary_granularity` | Enum：day/month | 是 | 页面按日/按月切换 |
| GPU | `gpu_name` | String(100) | 是 | 缺失时写入“未知 GPU” |
| 设备型号 | `device_model` | String(100) | 设备类型 Tab 是 | 映射后名称；映射失败保留原始型号 |
| 运行内存 | `ram_gb` | Decimal(6,2) | 设备类型 Tab 是 | 单位 GB |
| 游戏编号 | `game_id` | String(64) | 游戏报表是 | 标准游戏产品编号 |
| 启动设备数 | `start_device_count` | Int64 ≥ 0 | 是 | 去重设备数 |
| 成功运行设备数 | `success_device_count` | Int64 ≥ 0 | 是 | 满足首帧 + 帧率波动 5 秒 |
| 上报失败设备数 | `failure_report_device_count` | Int64 ≥ 0 | 是 | 仅明确失败上报 |
| 未判定设备数 | `undetermined_device_count` | Int64 ≥ 0 | 是 | 未采集到成功或失败结果 |
| 平均帧率 | `avg_fps` | Decimal(8,1)，可空 | 否 | 仅成功运行会话 |
| 平均单次时长 | `avg_session_seconds` | Int64 ≥ 0，可空 | 否 | 仅成功运行会话，单位秒 |
| 配置 MD5 | `config_md5` | Char(32)，小写十六进制 | 配置报表是 | 规范化配置 JSON 的 MD5 |
| 配置来源 | `config_source` | Enum：cloud/system/fallback/local | 配置报表是 | 对应四类来源 |
| 分享作者 | `share_author_uid` | String(64)，可空 | 否 | 仅云分享必填；展示时关联昵称 |

比率和占比由服务端按本章口径计算，前端不得使用页面可见数据自行反推。

按月查询时必须在自然月范围重新聚合：数量按月内去重设备计算；成功运行率使用“月成功运行设备数 ÷ 月启动设备数”；平均帧率和平均单次时长基于月内成功运行会话重新计算，不得沿用日结果、直接相加日均值或仅修改日期文案。

## 七、列表、状态与异常规则

| 场景 | 处理规则 |
|---|---|
| 首次进入 | 默认查询昨日、按日数据；GPU 报表默认 GPU Tab，游戏报表默认游戏 Tab；列表首列排序状态明确展示 |
| 加载中 | 表格保留表头，内容区显示加载状态；查询、导出按钮防重复点击 |
| 无数据 | 显示“暂无符合条件的数据”，不展示示例行；导出按钮置灰 |
| 查询失败 | 显示失败原因和“重新加载”；保留用户筛选条件 |
| 日期非法 | 开始日期晚于结束日期时不发起查询，并在日期区提示；按日查询最多 31 天，按月查询最多 12 个自然月 |
| 汇总维度切换 | 改变按日/按月选项时只更新待查询条件，点击“查询”后才刷新当前报表组的全部 Tab |
| Tab 筛选切换 | Tab 始终位于标题下方、筛选区上方；GPU/游戏主 Tab 使用模糊搜索输入框，设备类型及游戏 GPU/配置方案 Tab 使用顶部可搜索多选下拉；多选变化在点击查询后生效 |
| 按月汇总 | 以自然月聚合；跨月查询每月一行，不按滚动 30 天处理；月内数量重新去重，成功率以月成功数/月启动数计算，帧率和时长基于月成功会话重新计算 |
| GPU/设备型号缺失 | GPU 为空时归入“未知 GPU”；设备型号无法映射时展示原始型号并标记“未映射” |
| 游戏未关联 | 不进入按标准游戏产品聚合的游戏报表；保留在数据质量监控中，本期不新增识别优化能力 |
| 指标分母为 0 | 比率显示 `—`，排序时置于有值数据之后 |
| MD5 碰撞或数据异常 | 服务端同时保存规范化配置摘要；若相同 MD5 对应不同配置内容，记录数据告警并分开处理，不合并展示 |
| 表格过宽 | 表格区域支持横向滚动，固定操作列；页面导航不随表格横向滚动 |
| 权限不足 | 不展示无权访问的菜单；直接访问时返回无权限页面，不返回报表或作者数据 |
| 导出量过大 | 10 万行以内同步导出；超过 10 万行复用后台异步导出能力，生成成功后由现有下载中心获取 |

## 八、数据、权限与非功能需求

### 8.1 数据依赖

上线前必须确认以下字段可稳定入仓：

- 设备 ID、设备厂商、厂商原始型号、设备字典映射结果、GPU、运行内存。
- 游戏产品 ID/编号、游戏名称、启动时间、首帧状态、帧率波动结果、明确失败结果、退出时间。
- 单场平均帧率、单场运行时长。
- 实际运行配置 JSON、配置来源、云分享 ID、分享作者关联信息。
- 用户近 30 天下载记录、本地导入后与游戏产品的成功关联记录。

若已有埋点无法提供某字段，应在开发排期内补齐数据链路；本需求不新增失败日志文件上传。

### 8.2 数据时效与性能

| 项目 | 要求 |
|---|---|
| 数据时效 | T+1 更新，不要求实时；每日聚合完成后可查询前一自然日数据 |
| 统计时区 | 统一使用 Asia/Shanghai（UTC+8），跨日和自然月均以该时区为准 |
| 默认分页 | 20 条/页 |
| 报表首屏 | 常规筛选条件下 3 秒内返回 |
| 30 天查询 | 5 秒内返回首屏 |
| 导出 | CSV、UTF-8 BOM、包含列头；默认导出当前筛选和排序结果 |
| 浏览器 | Chrome 90+、Edge 90+ |

### 8.3 权限与审计

| 能力 | 权限 | 审计记录 |
|---|---|---|
| 报表查看 | 运营角色及以上 | 操作人、时间、筛选条件、查询维度 |
| 报表导出 | 复用现有报表导出权限 | 操作人、时间、筛选条件、排序、导出行数 |
| 配置详情 | 与报表查看权限一致 | 操作人、时间、游戏编号、配置 MD5 |
| 人群查询 | 复用现有人群圈选权限 | 操作人、时间、圈选条件、预估人数 |
| 人群导出 | 运营主管及以上，复用现有规则 | 操作人、时间、圈选条件、实际导出人数 |

分享作者信息仅用于内部运营和问题定位，不随报表或人群包默认导出。

### 8.4 发布与回滚

- 发布：完成数据抽样核对后，仅向具备报表权限的内部角色开放菜单；本期无 C 端灰度。
- 回滚：出现统计口径或权限异常时先关闭对应菜单入口和导出权限，保留已聚合数据供排查，不回写或删除原始上报数据。
- 兼容：历史数据字段缺失时按“未知/未判定/—”规则展示，不阻断新数据查询。

## 九、验收标准

| 编号 | 验收场景 | 验收标准 |
|---|---|---|
| AC-01 | GPU 聚合 | 列表按 GPU 聚合，不出现 CPU/SoC 维度；默认昨日、按日、启动设备数降序 |
| AC-02 | 按月汇总 | 选择按月并点击查询后，GPU、设备类型、游戏、游戏 GPU、配置方案五类表均显示自然月和重新计算的月数量、成功率、帧率、时长；重置恢复按日和默认 Tab |
| AC-03 | GPU 报表 Tab | GPU 与设备类型 Tab 位于标题下、筛选区上；GPU 列表无“查看详情”；切换设备类型后顶部 GPU 筛选变为可搜索多选下拉，并按 GPU + 设备型号 + 运行内存拆分，未映射型号保留原始值和“未映射”标记 |
| AC-04 | 成功口径 | 首帧渲染且帧率持续波动至少 5 秒才计入成功运行设备数 |
| AC-05 | 三类结果 | 成功、明确失败、未判定均独立展示；失败数不通过差值计算 |
| AC-06 | 质量指标 | 平均帧率、平均单次时长仅使用成功运行会话，分母为 0 时显示 `—` |
| AC-07 | 游戏报表 Tab | 游戏、GPU、配置方案 Tab 位于标题下、筛选区上；游戏列表无“查看详情”；GPU/配置方案 Tab 顶部游戏筛选为可搜索多选下拉并共用选择结果，支持排序与分页 |
| AC-08 | 配置聚合 | 相同规范化配置 JSON 生成相同 MD5；任一运行参数变化生成新 MD5；名称变化不影响 MD5 |
| AC-09 | 配置来源 | 四类来源均可区分；云分享配置能关联作者，其他无作者场景显示 `—` |
| AC-10 | 圈选 GPU | “设备芯片”已统一为“设备 GPU”；包含/不包含、多选和搜索有效 |
| AC-11 | 近 30 天游戏 | 下载记录或本地导入后成功关联产品均命中；未关联的本地游戏名不命中 |
| AC-12 | 条件组合 | 同条件多值 OR、跨条件 AND；重置后条件和预估人数全部清空 |
| AC-13 | 导出 | 报表导出字段、筛选和排序与当前页面一致；人群包复用现有格式与权限 |
| AC-14 | 异常状态 | 空数据、加载失败、非法日期、未知 GPU、未映射机型均按第七章处理 |
| AC-15 | 范围门禁 | 本期不出现日志采集配置、H5 落地页、资讯/社区一键应用或导入识别优化入口 |
| AC-16 | 权限与回滚 | 无权限用户无法看到或直接访问数据；关闭菜单与导出权限后不影响原始数据留存 |

## 十、上线前检查

1. 数据团队抽样核对 GPU、设备型号、运行内存、成功/失败/未判定和质量指标。
2. 客户端确认首帧、帧率持续波动 5 秒、单场帧率和时长字段的上报版本覆盖范围。
3. 后端确认配置 JSON 规范化及 MD5 生成规则，并准备参数新增时的版本兼容策略。
4. 运营使用 1 个 GPU、1 款游戏和 1 套云分享配置完成日/月查询、Tab 切换、导出和作者关联验收。
5. 权限管理员确认报表查看、报表导出、配置详情和人群导出权限。
