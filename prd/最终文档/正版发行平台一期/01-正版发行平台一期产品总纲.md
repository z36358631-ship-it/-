## 一、文档概述

### 1.1 背景概述

- **需求背景：** 一期需为首批已签约正版产品提供可交付的发行能力，同时覆盖既有 CDKEY 分销与一款 Windows 游戏的盖世包体发行。
- **当前方式：** 平台已有 CDKEY 用户购买、订单和 Key 交付方案；厂商资料、CDKEY 供给关联、包体测试发布、盖世权益、下载启动、规则式精准投放及数据查看尚未形成同一发行闭环。
- **问题：** 合作方无法在统一入口跟踪游戏从资料提交到用户交付的状态；平台发行运营和测试人员缺少贯通的任务视图；用户难以稳定识别“第三方平台激活”与“盖世直接下载”的差异。
- **证据：** 2026-08-31 会议在 `00:40:28`、`00:45:51`、`01:25:19` 和 `02:00:16` 明确一期包含开发者能力、CDKEY 分销、包体发行、测试审核、发布及推广闭环；已批准产品规格确认规则式精准投放采用平台运营圈选方案。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 包含受邀开发者平台、固定模板厂商主页、游戏项目、CDKEY 供给状态、单款 Windows 游戏包体版本、测试审核、发布、用户权益、游戏下载启动更新、规则式精准投放及基础发行数据。C 端复用游戏详情和 PC 游戏库现状外壳；B 端新增开发者、发行运营和测试入口。CDKEY 用户购买、支付、订单、Key 交付、激活指引和退款沿用既有 PRD。 |
| 业务边界 | [已确认] 服务 1 个已签约厂商、1 款 Windows 游戏、单一正式发布分支；支持首个正式版本及后续更新。CDKEY 分销与盖世包体发行并存，同一可售游戏在一次用户交付链路中只呈现一种交付方式。不包含开放开发者注册、多游戏规模化接入、多正式分支、抢先体验、预载、复杂灰度和开发者自助回滚。 |
| 运营边界 | [已确认] 平台发行运营审核厂商、游戏、商品、供给和素材，组织测试，控制发布、停售、下架及异常处理；精准投放仅使用现有资源位和规则圈选，由平台运营配置时间、频次和优先顺序。不建设推荐算法、广告竞价、预算计费或开发者自助启动投放。 |
| 人力边界 | 已签约厂商负责资料、包体、素材和目标人群建议；平台发行运营负责审核、发布和投放；测试人员负责指定包体测试；产品、设计、服务端、客户端、测试和数据人员完成对应页面与链路。开发者平台及运营后台的 Web 页面由服务端提供业务能力，客户端负责 C 端容器、下载、安装、启动和更新能力。不开展程序预研。 |

#### 一期明确不包含

1. 开放开发者注册、在线合同、复杂组织与成员权限。
2. Mac、Linux、移动端或主机包体同步发行。
3. 多游戏并行规模化接入、多正式分支、抢先体验和测试分支自助管理。
4. 自动结算、税务、发票、复杂分账和开发者提款。
5. 推荐算法、广告竞价、预算计费和开发者自助启动投放。
6. Steam 游戏库导入、首次游戏偏好问卷和第三方用户画像抓取。
7. 社区、私域运营、测试玩家招募、成就、云存档、Overlay 和创意工坊。
8. 高级 DRM、反作弊、强加壳、离线设备管理和盗版监控。
9. 预载、P2P、复杂增量更新、智能 CDN 调度和开发者自助版本回滚。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 厂商 | Publisher | 与平台完成签约并获得受邀账号的合作主体；一期账号只访问本厂商对象和数据。 |
| 游戏项目 | Game Project | 厂商在开发者平台创建的一款待发行游戏及其资料、商品、版本、投放和数据关系集合。 |
| 商品 | Product | 面向用户售卖或零价领取的游戏交易对象，关联游戏项目和一种交付方式。 |
| SKU | Stock Keeping Unit | 商品在激活平台、销售地区、价格或领取条件等维度形成的可交易单元；具体字段由商品与供给 PRD定义。 |
| CDKEY 供给 | CDKEY Supply | CDKEY 商品与供应来源、激活平台、销售地区及可售状态的关联；一期默认沿用供应商 API，不在开发者平台新增批量明文上传 Key。 |
| 包体版本 | Package Build | 厂商提交测试并由平台发布的 Windows 游戏文件及版本说明；同一游戏同时只有一个正式线上版本。 |
| 用户权益 | Entitlement | 用户购买或领取盖世包体游戏后获得的下载、安装、启动和更新资格；CDKEY 订单不生成盖世直接下载权益。 |
| 投放计划 | Campaign | 开发者提交素材、推广目标和期望人群后，由平台运营以现有资源位和规则人群配置并执行的推广对象。 |
| 第三方平台激活 | Third-party Activation | 用户在盖世完成购买并获得 CDKEY，随后前往指定第三方平台激活、下载和游玩。 |
| 盖世直接下载 | GameHub Direct Download | 用户在盖世购买或领取并获得权益后，直接在盖世下载、安装、启动和更新。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向首批已签约厂商的混合发行 MVP，贯通游戏资料、CDKEY 供给或 Windows 包体、审核发布、规则式精准投放、用户交付及发行效果查看。 |
| 目标用户 | 已签约游戏厂商、平台发行运营、测试人员和盖世用户。 |
| 核心目标 | 首批游戏可以完成 CDKEY 分销或盖世包体发行闭环；用户在详情、结算、订单和游戏库始终识别同一种交付方式；开发者能查看自身游戏和投放结果。 |
| 使用场景 | 厂商提交首款正版游戏，平台完成审核、供给或测试发布并配置精准投放，用户购买或领取后进入第三方激活或盖世直接下载路径。 |
| 功能概述 | 开发者平台承接资料、供给／版本、投放需求和数据入口；平台发行运营承接审核、发布、异常和规则投放；测试入口承接包体测试；C 端详情和游戏库承接用户分流与交付。 |

#### 共享业务对象与数据归属

| 业务对象 | 归属与可见范围 | 一期关系 | 交付结果 |
|---|---|---|---|
| 厂商与游戏项目 | 厂商仅见自身；发行运营见签约范围；测试人员仅见分配任务关联信息 | 一个厂商关联一期首款游戏项目；项目连接商品、供给、版本、投放和发行数据 | 资料审核通过后方可进入商品或包体发布准备 |
| 商品、SKU 与 CDKEY 供给 | 厂商只读查看自身关联与状态；发行运营配置和处置 | 商品关联一种交付方式；CDKEY SKU 关联激活平台、地区、供应来源和可售状态 | 用户获得 Key，游戏库进入第三方激活入口 |
| 包体版本与用户权益 | 厂商查看自身版本；测试人员处理分配版本；发行运营控制发布；用户只见本人权益 | 测试通过的单一正式版本发布后，购买或领取生成盖世权益 | 用户进入下载、安装、启动和更新入口 |
| 投放计划与发行数据 | 厂商提交需求并只读查看自身数据；发行运营配置全平台计划；测试人员不见商业数据 | 计划关联厂商、游戏、素材、资源位和规则人群；一期按 `campaign_id + game_id` 归集，默认 T+1 更新 | 曝光、点击及最终可观测交付行为回流到开发者数据入口 |

#### 两种交付方式统一表现

| 触点 | 第三方平台激活 | 盖世直接下载 | 统一约束 |
|---|---|---|---|
| 游戏详情 | 展示激活平台、地区限制、退款边界和购买入口 | 展示 Windows 支持、下载大小、更新要求和购买／领取入口 | 必须展示唯一交付方式标签；精准投放不得隐藏或弱化限制 |
| 结算确认 | 确认购买后交付 CDKEY 及第三方激活限制 | 确认购买或零价领取后生成盖世权益 | 进入提交动作前再次展示与详情一致的交付方式 |
| 订单／领取结果 | 展示 Key 或取 Key 状态及激活指引 | 展示权益处理中、成功或失败状态 | 结果页不得提供另一种交付方式的行动入口 |
| 游戏库 | 展示“第三方平台激活”及激活入口／指引，不显示盖世下载按钮 | 展示“盖世直接下载”及下载、启动或更新入口 | 同一游戏不得同时出现互相冲突的 CDKEY 与包体入口 |

### 3.2 B 端功能需求

#### 3.2.1 开发者工作台首页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 受邀厂商查看本厂商发行对象、共享状态和后续业务入口。 |

### 3.4 共享异常与恢复原则

| 场景 | 平台处理 | 角色可见结果 | 恢复原则 |
|---|---|---|---|

| 包体上传中断 | 不生成可测试版本 | 开发者看到上传中断和已保留草稿 | 继续或重新上传，保留已填写信息 |

| 投放目标人群为空 | 禁止计划进入已排期 | 运营看到空人群原因；开发者看到平台处理中或驳回结果 | 调整合法圈选条件后重新预估 |
| 游戏下架或落地页失效 | 停止新售、新领取和关联投放曝光 | 开发者、运营和用户在权限范围内看到下架结果 | 重新满足合同、资料、商品及版本条件后由运营发布 |
| 数据延迟或缺失 | 不以 0 覆盖未知值 | 开发者和运营看到数据更新时间与异常状态 | 数据补齐后按原计划和游戏重新归集，不修改历史业务状态 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 不涉及。总纲不定义页面埋点事件；CDKEY 供给、包体交付、下载启动和精准投放的数据采集及指标口径由对应详细 PRD就地定义，总纲只约束对象归属、角色可见范围和成功形态。

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容 | 盖世包体发行只覆盖一款 Windows 游戏和单一正式版本；CDKEY 交付继续使用既有客户端链路。其他操作系统、移动端、主机、多分支、预载和复杂增量更新不在一期范围。 |
| 安全 | 受邀合作方账号只能访问绑定厂商数据；测试人员只能获取分配任务；用户只能查看本人订单与权益。开发者平台不展示或批量导出明文 Key；审核、发布、停售、下架、权益处置和投放操作需留痕。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 平台发行运营负责厂商与游戏审核、商品及供给关联、版本发布、异常处置、现有资源位和规则人群配置；关闭、下架或失效后同步影响 C 端入口和开发者状态。 |
| 内容／素材 | 厂商提交固定模板厂商资料、游戏资料、包体或 CDKEY 供给关系、投放素材、推广目标和期望人群；运营审核并修正正式发布或投放内容。 |
| 上线协同／推广 | 测试人员完成指定 Windows 包体测试；运营在游戏已发布、素材合规和人群非空后启动投放，并在异常时暂停或结束。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 游戏发布前明确合同约定的价格或零价领取条件、分成及结算责任；一期不建设自动结算、税务、发票、复杂分账和开发者提款。 |
| 法务 | 厂商须完成签约，平台在授权期限、发行地区和约定范围内发布；合同或授权失效时停止新售、新领取和关联投放。 |
| 版权 | 厂商对游戏包体、Logo、封面、宣传素材、文案和投放素材拥有合法授权；审核不通过的素材不得发布或投放。 |
| 其他合规 | 投放只使用平台已有或本期主流程自然产生的合法用户数据；不导入 Steam 游戏库、不抓取第三方画像。地区、语言、系统要求和未成年人等限制按现有合规规则执行。 |

## 五、待确认项

| 待确认问题 | 默认建议 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 首款包体游戏及其付费／免费类型 | 选择已签约、Windows 单机、无复杂反作弊的游戏；按合同采用购买或零价领取 | 影响商品、权益、退款和详情文案 | 阻塞包体相关详细 PRD定稿，不阻塞总纲结构 |
| 当前 CDKEY 实际供给方式 | 复用现有供应商 API；开发者平台只做厂商、游戏、SKU 关联与状态展示 | 影响供应来源关联页及异常处理 | 阻塞 CDKEY 供给详细 PRD定稿，不阻塞总纲结构 |
| 可复用的现有资源位 | 优先评估首页及现有游戏推荐位，不新增客户端入口 | 影响曝光单元、资源位排期页面和曝光口径 | 阻塞精准投放详细 PRD图示与字段定稿，不阻塞总纲结构 |
| 可直接使用的用户标签 | 仅使用地区、语言、设备／系统和本平台内游戏行为；无数据标签不出现在圈选器 | 影响人群规则配置和命中预估 | 阻塞精准投放详细 PRD字段定稿，不阻塞总纲结构 |
