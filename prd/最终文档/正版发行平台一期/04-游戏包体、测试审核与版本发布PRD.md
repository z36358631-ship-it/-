## 一、文档概述

### 1.1 背景概述

- **需求背景：** 正版发行平台一期需让首个受邀签约厂商完成一款 Windows 游戏从包体提交、测试驳回修订、测试通过到正式发布及后续更新的闭环。
- **当前方式：** 会议确认平台已有“包体管理流”，但未提供入口、页面、字段、上传规则及测试／发布覆盖范围；开发者传包、测试取包、审核、待上线和发布尚未形成可由多角色共同执行的书面规则。
- **问题：** 开发者、测试人员和平台发行运营无法基于同一套版本对象、测试轮次和发布状态协作；上传中断、重复版本、测试重提、发布失败和线上重大问题缺少统一恢复方式。
- **证据：** 已批准一期规格确认单款 Windows 游戏、单一正式分支、一个当前线上版本，以及“草稿→上传中→待提交→测试中→测试不通过／测试通过→待发布→已发布→已撤回”的状态链路；会议 `02:00:16` 明确测试取包、后台测试列表、过审、待上线和按时发布。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 本文不新增 C 端页面；只定义开发者、测试人员和平台发行运营的 B 端页面，以及版本发布结果对后续用户权益、下载、启动和更新链路的输入。开发者侧包含版本列表、创建／编辑版本、包体上传、提交测试确认、测试驳回详情；测试侧包含待测任务列表、测试任务详情、测试结果提交；运营侧包含版本审核列表、版本审核详情、待发布列表、发布配置、线上版本处置。 |
| 业务边界 | [已确认] 仅覆盖 1 个受邀签约厂商、1 款 Windows 游戏、单一正式发布分支、首个正式版本和后续正式更新；同一游戏同时只有一个当前线上版本。用户购买／领取、权益生成、游戏下载、安装、启动和更新页面由后续 PRD 定义，本文只输出版本及运营开关状态。 |
| 运营边界 | 开发者提交版本与包体但无发布权限；测试人员只处理分配任务；平台发行运营分配测试、校验签约及发布门禁、确认待发布、立即／定时发布、撤回未发布版本、下架游戏、暂停下载或启动并执行恢复。 |
| 人力边界 | 已签约厂商维护版本资料和包体；测试人员执行测试并提交结果；发行运营控制审核、排期、发布和线上处置；商务／法务确认授权范围；产品、设计、服务端、客户端、测试和数据人员完成对应规则、页面及状态消费。不开展程序预研。 |

#### 一期明确不包含

1. Mac、Linux、移动端或主机包体发行。
2. 多游戏规模化接入、多正式分支、测试分支、抢先体验和开发者自助灰度。
3. 预载、P2P、复杂增量更新、智能 CDN 调度和包体差分策略配置。
4. 开发者自助正式发布、下架、暂停、恢复或版本回滚。
5. 多个线上正式版本并存或由用户选择正式版本。
6. 用户购买、权益、下载、安装、启动、修复、卸载和更新页面的详细交互。
7. 高级 DRM、反作弊、强加壳、离线设备管理和盗版监控。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 包体版本 | Build Version | 关联已审核游戏项目的一次正式发布候选，包含版本号、更新说明、Windows 包体、启动信息、测试轮次和发布记录。 |
| 版本号 | Version Number | 面向开发者、测试及用户识别的版本标识；同一游戏不能创建两个独立版本记录使用相同版本号。 |
| 包体修订 | Build Revision | 同一包体版本在发布前因重传或测试不通过而形成的文件修订序号；每次成功替换包体后递增，旧修订只读留存。 |
| 测试轮次 | Test Round | 某个包体修订提交测试后形成的一次独立测试过程；测试不通过后重新提交必须创建新轮次，旧轮次结果不可覆盖。 |
| 当前线上版本 | Current Live Version | 平台当前向新用户和需更新用户提供的唯一正式版本；新版本发布成功后替代上一线上版本。 |
| 发布门禁 | Release Gate | 版本进入待发布及正式发布前必须满足的资料、授权、测试、包体、启动信息、商品／权益准备和运营状态条件。 |
| 运行开关 | Runtime Switch | 平台运营针对已发布游戏控制新下载、启动或游戏整体获取的状态；开关变化不删除版本、订单、权益或用户本地文件。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向首个受邀厂商的一条 Windows 正式版本交付链路，由开发者提交、测试人员验证、平台运营控制发布和线上处置。 |
| 目标用户 | 已签约厂商的开发者账号、平台测试人员、平台发行运营。 |
| 核心目标 | 首版和后续正式更新可重复完成上传、测试、发布；失败不破坏当前线上版本或用户当前可运行版本；所有关键动作可追溯。 |
| 使用场景 | 开发者为资料已通过的盖世直接下载游戏创建版本并上传包体，测试人员按轮次验证，运营在门禁满足后发布；重大问题时暂停下载或启动。 |
| 功能概述 | 版本资料、断点恢复、包体修订、测试任务、驳回重提、发布门禁、立即／定时发布、线上开关、状态机、日志和数据采集组成完整闭环。 |

#### 对象关系与唯一性

| 对象 | 归属与关系 | 唯一性与版本规则 | 结果去向 |
|---|---|---|---|
| 游戏项目 | 归属一个受邀签约厂商，发行方式为“盖世直接下载” | 一期只处理一款 Windows 游戏；游戏资料通过后才可创建包体版本 | 连接版本、商品／领取条件、权益和发行数据 |
| 包体版本 | 归属一个游戏项目，可包含多个发布前包体修订和测试轮次 | 同一游戏版本号唯一；已发布版本号永久占用，不可创建同号独立版本 | 测试通过并满足门禁后成为待发布候选 |
| 包体修订 | 归属一个版本；上传成功或重传成功后形成新修订 | 一个测试轮次只绑定一个不可变修订；测试中不得替换文件 | 供分配测试人员获取并产生测试结果 |
| 测试任务／轮次 | 归属一个版本和包体修订，由运营分配给一个测试人员 | 重新提交产生新轮次；同一轮次因任务终止接续可留存多个 `task_id`，但待分配、待测试或测试中的有效任务最多一条 | 通过后等待运营确认待发布，不通过则退回开发者；任务终止不结束轮次或改变版本测试中状态 |
| 发布记录 | 归属一个待发布版本，由平台运营或定时任务执行 | 同一时刻只有一个当前线上版本；发布尝试使用唯一动作标识防重复 | 成功后切换线上版本，失败保持原线上版本 |

#### 版本号、修订与重复规则

| 场景 | 判断规则 | 页面结果 | 历史处理 |
|---|---|---|---|
| 创建重复版本号 | 同一游戏已存在相同版本号的草稿、测试、待发布、已发布或已撤回记录 | 禁止创建第二条记录，定位已有版本及状态 | 不删除或复用原版本 ID |
| 测试不通过后修订 | 开发者在原版本记录修改资料或替换包体 | 保持版本号或改为未占用版本号；包体替换成功后修订号递增 | 旧包体修订及测试轮次只读留存 |
| 上传同一文件 | 文件校验结果与当前修订一致 | 不创建重复修订，提示沿用当前已上传结果 | 留存原上传动作日志，不重复提交测试 |
| 已发布后续更新 | 新建不同版本号的正式候选 | 新版本重新执行上传、测试和发布全流程 | 发布成功后上一线上版本主状态进入已撤回，细分为历史线上版 |
| 已撤回后再次发行 | 未发布撤回或历史线上替代的原版本均不得恢复 | 必须新建未占用的不同版本号，并重走上传、测试、门禁和发布 | 原版本、修订、测试、发布及撤回字段只读留存 |
| 并发编辑或提交 | 页面版本与服务端最新版本不一致 | 不覆盖先完成结果，刷新后继续 | 两次请求均记录成功或冲突结果 |

#### 已撤回细分与字段

主状态仍为“已撤回”，通过 `withdrawal_kind` 区分业务含义；不得新增平级主状态。

| `withdrawal_kind` | 触发与列表展示 | 必记字段 | 再次发行 |
|---|---|---|---|
| `cancelled_before_publish` | 待发布候选被运营撤回；显示“已撤回（未发布）” | `withdrawn_at`＝撤回成功时间；`withdrawal_reason`＝运营必填原因；`withdrawal_from_state=pending_release`（待发布）；`first_published_at` 为空；`superseded_by_version_id` 为空 | 原版本不可恢复；新建不同版本号并重走测试和发布 |
| `superseded_after_publish` | 历史线上版本被新版本成功替代；显示“已撤回（历史线上版）” | `withdrawn_at`＝新版本发布成功时间；`withdrawal_reason`＝新版本发布替代；`withdrawal_from_state=published`（已发布）；`first_published_at` 维持首次发布时间；`superseded_by_version_id`＝新线上版本 ID | 原版本不可恢复；需再次发行时新建不同版本号并重走测试和发布 |

#### 发布门禁

| 门禁组 | 进入待发布条件 | 正式发布前复核 | 失败与恢复 |
|---|---|---|---|
| 项目与授权 | 厂商及游戏属于有效签约范围，游戏资料已通过且发行方式为盖世直接下载 | 授权期限、地区和合同合作范围仍有效 | 不改写资料审核结果；版本保持测试通过或待发布，补齐后重检 |
| 版本与包体 | 版本号唯一，最新包体修订上传完整且基础校验通过，更新说明和启动信息完整 | 待发布版本仍指向同一已测试修订 | 文件或启动信息变化后测试结果失效，必须新建测试轮次 |
| 测试 | 最新测试轮次结果为测试通过，且无更新的包体修订 | 测试结果、轮次与候选修订一致 | 测试不通过不可进入待发布；重复提交不覆盖终态 |
| 商品与权益准备 | 价格或领取条件、分成和结算责任已明确，商品／权益生成链路具备发布条件 | 用户获取条件和交付方式仍与游戏资料一致 | 未齐时阻塞发布，不在本文修改交易或权益规则 |
| 线上状态 | 游戏未下架且候选版本有效；下载暂停或启动暂停不阻塞已测试通过且其他门禁齐全的修复版进入待发布 | 定时执行时再次校验游戏未下架、候选仍有效，并读取当前线上版本及下载／启动开关 | 游戏已下架或候选失效时发布失败，候选保持待发布且原线上版本继续有效；处于暂停状态时允许发布修复版，成功后新线上版本继承原下载／启动暂停开关，由运营验证后分别恢复 |

| 补充说明 | 1. 新版本发布成功只提供版本状态，不在本文定义客户端下载安装和更新页面。<br>2. 更新失败时客户端必须保留用户当前可运行版本和重试入口，具体规则由下载更新 PRD 承接。<br>3. 一期不提供开发者自助回滚；重大问题由平台运营使用线上版本处置页。 |

### 3.3 包体版本状态机

| 状态 | 进入／退出 | 可见内容与操作 | 失败、恢复和历史 |
|---|---|---|---|
| 草稿 | 创建版本、取消上传或保存未提交资料后进入；开始上传后退出 | 开发者可编辑、保存和上传 | 保存失败不清空输入；版本号占用规则保持 |
| 上传中 | 开始上传后进入；校验通过、取消或版本失效后退出 | 查看进度、继续、重传或取消 | 中断不生成可测试修订；取消返回草稿且版本资料不变 |
| 待提交 | 上传完成且基础校验通过后进入；提交测试或替换包体后退出 | 核对资料并提交测试 | 提交失败保持待提交；重复请求不产生多轮 |
| 测试中 | 提交测试后进入；本轮提交终态后退出 | 开发者只读；运营分配；测试人员处理本人任务 | 包体获取失败可重试；测试中不可替换快照 |
| 测试不通过 | 测试提交不通过后进入；开发者修订并重新提交后退出 | 展示原因，允许编辑和重传 | 新提交产生新包体修订或测试轮次，旧轮次只读 |
| 测试通过 | 测试提交通过后进入；运营确认门禁后进入待发布 | 运营核对发布门禁；开发者只读 | 门禁不齐保持本状态，不改写测试结果 |
| 待发布 | 运营确认发布条件后进入；发布成功或撤回后退出 | 运营配置立即／定时发布、撤回和失败重试 | 发布失败保持待发布，原线上版本继续有效 |
| 已发布 | 发布成功后进入并首次写入 `first_published_at`；被新版本替代后进入已撤回 | 当前版本可供下游下载更新链路读取；平台可处置运行开关 | 已发布版本不可删除；游戏下架不删除版本历史；重复发布不改首次发布时间 |
| 已撤回 | 待发布候选被撤回，或旧线上版本被新版本替代后进入；本主状态不再退出 | 按 `withdrawal_kind` 显示“已撤回（未发布）”或“已撤回（历史线上版）”，只读查看 `withdrawn_at`、原因、原状态、`first_published_at`、替代版本及完整历史 | 原版本不向新用户下发且不可恢复；再次发行必须新建不同版本号并重走上传、测试、门禁和发布 |

### 3.4 统一操作日志规则

版本、上传、测试、发布和线上处置的每次操作尝试均记录成功与失败。固定字段为 `log_id`、`action_id`、动作、`vendor_id`、`game_id`、`version_id`、版本资料版本、`build_revision`、`test_round_id`、`task_id`、变更前状态、变更后状态、原因、操作人、操作角色、操作来源、结果、失败类型和发生时间；任务终止接续另记 `replacement_task_id`，发布执行另记 `publish_started_at`，版本撤回另记 `withdrawal_kind`、`withdrawn_at`、`withdrawal_reason`、`withdrawal_from_state`、`first_published_at` 和 `superseded_by_version_id`。对象尚未成功创建时允许对应 ID 为空，但父对象和 `action_id` 必填。系统定时发布或自动状态动作的操作人固定为 `system`。

| 动作范围 | 对象与版本 | 必记变更与原因 | 主体、来源与失败 |
|---|---|---|---|
| 创建／编辑版本、保存草稿 | 游戏、版本、资料版本 | 版本号、更新说明、启动信息的前后值；编辑原因 | 开发者／版本编辑页；校验失败和并发冲突也记录 |
| 开始／继续／重传／取消上传 | 版本、上传任务、包体修订 | 上传前后状态、恢复位置、取消或重传原因 | 开发者／包体上传页；失败记录类型和时间 |
| 提交／重新提交测试 | 版本、包体修订、测试轮次 | 待提交到测试中的状态及重提原因 | 开发者／提交确认页；重复请求记录幂等结果 |
| 分配／改派／终止测试任务 | 版本、测试轮次、原任务及接续任务 | 原／新测试人员、旧 `task_id` 失效、新 `replacement_task_id` 待分配、版本保持测试中及终止原因 | 运营／版本审核列表；任一步失败均不改旧有效任务，成功后同轮最多一条有效任务 |
| 获取包体、提交通过／不通过 | 任务、修订、测试轮次 | 获取结果或测试结果、问题说明摘要 | 测试人员／任务页面；不记录长期包体地址 |
| 确认待发布 | 版本、修订、测试轮次、门禁快照 | 测试通过到待发布的状态及阻塞原因 | 运营／审核详情；失败保持测试通过 |
| 立即发布／定时发布／重试发布 | 候选版本、发布动作、当前线上版本 | 首次进入发布中的 `publish_started_at`、结束结果、方式和计划时间；成功时记候选首次发布时间及旧线上版本撤回字段，失败时记原因 | 人工记运营来源；定时执行记 `system` 来源；未结束动作只由超时监控识别，不伪造结果日志或撤回字段 |
| 撤回未发布版本 | 版本、发布计划 | `cancelled_before_publish`、撤回时间、运营原因、原状态；首次发布时间和替代版本为空 | 运营／待发布列表；失败时原计划和撤回字段不变 |
| 暂停／恢复下载或启动、下架游戏 | 游戏、线上版本、运行开关版本 | 开关前后值、影响范围和处置原因 | 运营／线上处置页；系统联动另记系统来源 |

日志不得写入上传凭据、可长期访问的包体地址、完整启动敏感参数、合同金额或用户个人数据。

### 4.1 埋点与数据需求

| `build_publish_result` | B 端发布配置页／新增 | 立即、定时或重试发布执行结束后上报一次；成功切换当前线上版本记为成功，未结束或监控超时不伪造结果事件 | `action_id, publish_action_id, vendor_id, game_id, version_id, build_revision, publish_mode, result, failure_type, operator_role` |
| `build_withdraw_result` | B 端待发布列表页／发布配置页／新增 | 未发布候选撤回结束后上报成功或失败；新版本成功替代旧线上版本时，为旧版本上报成功，全部撤回字段成功写入才记成功 | `action_id, vendor_id, game_id, version_id, withdrawal_kind, withdrawn_at, withdrawal_reason, withdrawal_from_state, first_published_at, superseded_by_version_id, result, failure_type, operator_role` |
| `build_live_disposal_result` | B 端线上版本处置页／新增 | 暂停、恢复或下架动作完成后上报；目标运行开关首次成功写入记为成功 | `action_id, disposal_action_id, vendor_id, game_id, version_id, disposal_action, result, failure_type, operator_role` |

#### 4.1.3 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| `action_id` | string／是 | 一次业务提交的幂等和去重标识 | `act_20260901_10001` |
| `upload_action_id` | string／是 | 一次上传任务标识；继续上传沿用，重传生成新值 | `upload_20001` |
| `publish_action_id` | string／是 | 一次实际发布执行标识；进入发布中时生成并关联 `publish_started_at`，仅保存排期不生成执行标识 | `publish_30001` |
| `disposal_action_id` | string／是 | 一次线上处置标识，用于关联暂停与恢复 | `dispose_40001` |
| `vendor_id` | string／是 | 厂商唯一标识 | `vendor_10001` |
| `game_id` | string／是 | 游戏项目唯一标识 | `game_40001` |
| `version_id` | string／条件必填 | 包体版本唯一标识；仅首次创建失败且对象未生成时可空，其余事件必填 | `version_50001` |
| `version_no` | string／是 | 开发者填写的版本号 | `1.0.0` |
| `build_revision` | int／是 | 包体修订序号；尚未上传成功时传 0 | `2` |
| `test_round_id` | string／条件必填 | 测试轮次标识；测试提交成功及后续测试／发布门禁事件必填，提交失败且轮次未生成时可空 | `round_60001` |
| `task_id` | string／条件必填 | 测试任务标识；分配成功和测试任务结果必填，分配失败且任务未生成时可空 | `task_70001` |
| `replacement_task_id` | string／条件必填 | 终止有效测试任务成功时创建的同轮接续任务标识；其他分配动作和终止失败时为空 | `task_70002` |
| `withdrawal_kind` | enum／是 | 已撤回主状态的业务细分 | `cancelled_before_publish`＝未发布候选被撤回；`superseded_after_publish`＝历史线上版本被新版本替代 |
| `withdrawn_at` | string／条件必填 | 撤回状态成功写入时间；撤回失败时为空 | `2026-09-01T18:30:00+08:00` |
| `withdrawal_reason` | string／是 | 未发布撤回时为运营必填原因；历史线上替代时固定为“新版本发布替代” | `新版本发布替代` |
| `withdrawal_from_state` | enum／是 | 进入已撤回前的主状态 | `pending_release`＝待发布；`published`＝已发布 |
| `first_published_at` | string／条件必填 | 版本首次发布成功时间；历史线上替代必填且保持原值，未发布撤回为空 | `2026-08-20T10:00:00+08:00` |
| `superseded_by_version_id` | string／条件必填 | 替代该历史线上版本的新版本 ID；未发布撤回或撤回失败时为空 | `version_50002` |
| `save_action` | enum／是 | 版本资料动作 | `create`＝创建版本；`save_draft`＝保存草稿；`edit_after_reject`＝驳回后编辑 |
| `upload_action` | enum／是 | 上传动作 | `start`＝开始；`continue`＝继续；`reupload`＝重新上传；`cancel`＝取消；`complete`＝完成并通过基础校验 |
| `submit_type` | enum／是 | 测试提交类型 | `first_submit`＝首次提交；`resubmit`＝测试不通过后重新提交 |
| `assignment_action` | enum／是 | 测试任务分配动作 | `assign`＝首次分配；`reassign`＝开始前改派；`terminate`＝终止任务 |
| `test_result` | enum／是 | 测试终态；非测试结果事件不使用 | `passed`＝测试通过；`failed`＝测试不通过 |
| `publish_mode` | enum／是 | 发布执行方式 | `immediate`＝立即发布；`scheduled`＝定时任务执行；`retry`＝失败后重试 |
| `disposal_action` | enum／是 | 线上版本处置动作 | `pause_download`＝暂停下载；`resume_download`＝恢复下载；`pause_launch`＝暂停启动；`resume_launch`＝恢复启动；`take_down_game`＝下架游戏 |
| `result` | enum／是 | 业务处理结果 | `success`＝目标状态写入成功；`failure`＝未写入目标结果 |
| `failure_type` | enum／是 | 失败分类；成功传 `none` | `none`＝无失败；`permission_denied`＝无权限；`validation_failed`＝字段或文件校验失败；`duplicate_version`＝版本号重复；`state_conflict`＝状态或并发冲突；<br>`upload_interrupted`＝上传中断；`test_gate_blocked`＝测试前置未满足；`release_gate_blocked`＝发布门禁未通过；`publish_failed`＝发布执行失败；`service_error`＝平台服务失败 |
| `operator_role` | enum／是 | 操作角色 | `developer`＝受邀开发者；`tester`＝测试人员；`platform_ops`＝发行运营；`system`＝定时发布或系统任务 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容 | 包体只支持 Windows 正式版本；页面支持公司指定桌面浏览器。客户端只消费已发布版本和下载／启动开关，不在本文定义安装更新实现。 |
| 安全 | 开发者只访问绑定厂商版本，测试人员只获取分配任务，运营只处理签约范围；包体获取凭据、上传地址和敏感启动参数不进入公开链接、埋点或普通日志。 |
| 数据存储 | 版本资料、包体修订、上传任务、测试轮次、全部历史任务、发布尝试、撤回子类型及字段、运行开关均留存；撤回、下架、任务终止或版本替代不删除记录。 |
| 一致性 | 1. 测试轮次锁定包体修订；同轮最多一条有效任务，终止时旧任务失效、新任务待分配和版本保持测试中须原子写入。<br>2. 发布成功同时且仅同时切换一个当前线上版本，并完整写入候选首次发布时间及旧线上版本撤回字段。<br>3. 任一步失败不得产生候选已发布、旧版已撤回或同轮多条有效任务的部分状态。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 运营分配测试任务、确认发布门禁、配置立即／定时发布、撤回候选并处置下载／启动／下架状态；所有动作逐版本执行并留痕。 |
| 内容／资料 | 开发者提供版本号、更新说明、Windows 包体、启动文件、启动参数和运行说明；测试人员提供结论及问题说明；运营不替开发者修改包体。 |
| 上线协同／推广 | 版本发布成功且游戏未下架、下载／启动开关有效时，后续权益与下载更新链路读取当前线上版本；游戏下架时关联投放停止曝光。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 正式发布前价格或领取条件、分成和结算责任须明确；本文不建设商品定价、自动结算或提款。 |
| 法务 | 厂商签约和发行授权须覆盖游戏、Windows 包体、发行地区及有效期；授权失效时阻塞发布或下架游戏。 |
| 版权 | 厂商须拥有包体、第三方组件、启动内容和更新说明的发行权；测试通过不替代版权责任。 |
| 其他合规 | 包体、测试附件和运行信息按最小权限处理；重大合规问题可暂停下载／启动或下架，处置原因需可追溯。 |

## 五、待确认项

| 待确认问题 | 默认建议 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 现有包体管理流包含哪些入口、页面、字段、上传限制和状态 | 复用现有版本列表、版本编辑及上传能力，只补版本唯一性、测试轮次、发布门禁和异常恢复；不脱离现状重做 | 影响版本列表、创建／编辑版本、包体上传的新建／改造边界，及文件形态、大小、会话有效期和恢复粒度 | 阻塞前三个页面及对应图片定稿，不阻塞跨角色核心流程评审 |
| 首款包体游戏及其付费／免费类型是什么 | 选择已签约、Windows 单机、无复杂反作弊的游戏；按合同采用购买或零价领取 | 影响发布门禁中的商品／领取条件、权益准备和用户侧文案 | 阻塞正式发布配置定稿，不阻塞版本上传和测试规则 |
