## 一、文档概述

### 1.1 背景概述

- **需求背景：** 正版发行平台一期同时支持既有 CDKEY 分销和一款 Windows 游戏的盖世包体发行，用户需在详情、确认、结果和游戏库中始终识别同一种交付方式。
- **当前方式：** 平台已有 CDKEY 浏览、购买、支付、订单、Key 交付、直接激活／后续一键激活及退款链路；当前 PC 游戏库已有列表和游戏详情外壳。盖世包体游戏尚缺购买或零价领取后生成权益、进入游戏库及异常恢复的统一规则。
- **问题：** 若两种交付方式的文案、状态和操作未统一，用户可能把 CDKEY 游戏误认为可在盖世下载，或在已付款／领取后因权益未生成而重复操作；运营也无法定位包体权益异常并向用户解释下架、退款、合同或违规撤销结果。
- **证据：** 已批准的一期规格明确 `第三方平台激活` 与 `盖世直接下载` 两种交付方式，以及“包体购买或领取→生成盖世权益→进入游戏库”的闭环；页面证据基线仅确认既有游戏详情和 PC 游戏库外壳，确认／结果、权益异常及运营页面均不能冒充现状页面。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] C 端覆盖游戏详情、购买／领取确认、订单／领取结果、游戏库列表、游戏库游戏详情和权益异常状态；B 端覆盖用户权益查询与权益异常处理。详情与游戏库复用当前页面外壳，仅改交付信息和动作区；确认、结果和后台页面按已批准规格形成产品低保真结构。本文不新增独立购买入口、弹窗或支付能力。 |
| 业务边界 | [已确认] CDKEY 分支完整复用既有购买、支付、订单、Key 交付、直接激活／后续一键激活和退款规则，本文只补四个触点的交付方式一致性及游戏库互斥表现。盖世包体分支覆盖购买或零价领取、权益生成、游戏库入库、异常展示和运营处置；下载、安装、启动与更新的任务规则不在本文定义。 |
| 运营边界 | 平台发行运营可查询授权范围内的用户交付记录，并对盖世权益执行生成重试、补发或按退款／合同／违规原因撤销；CDKEY 记录只读展示并继续在既有订单模块处置。商品下架停止新购／新领取，不自动删除已获得的有效权益。 |
| 人力边界 | 平台发行运营负责权益异常和撤销原因；客服按既有流程承接用户咨询；商务／法务提供合同或违规处置依据；服务端负责订单／领取记录、权益和状态同步，客户端负责四触点展示与游戏库入口，数据人员负责事件贯通。沿用既有支付和 CDKEY 履约能力，不开展程序预研。 |

#### 一期明确不包含

1. 重做 CDKEY 的 SKU 选择、登录／实名／未成年人校验、支付方式、订单状态机、Key 展示、一键激活或退款规则。
2. 新增首页、搜索、活动页或其他购买入口；新增购买弹窗、支付渠道、钱包或余额能力。
3. CDKEY 游戏在盖世下载、安装、启动或更新；盖世包体游戏展示 Key、第三方激活或 Steam 收货账号。
4. 下载任务、安装位置、启动校验、更新、修复和卸载的详细交互。
5. 礼物、代购、家庭共享、订阅、租赁、会员赠送、组合包和跨账号转移权益。
6. 多设备授权数量、高级 DRM、离线设备管理或用户自助申诉系统。
7. 开发者查看、补发、撤销或导出用户级权益数据。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 交付方式 | Delivery Type | 商品及用户获取记录的交付类型，仅有 `第三方平台激活` 和 `盖世直接下载`；四个用户触点必须使用这两段完整文案。 |
| 获取方式 | Acquisition Type | 盖世包体商品的用户获取条件：付费购买或零价领取；同一个生效 SKU 同时只使用一种方式。CDKEY 继续使用既有付费购买规则。 |
| 来源记录 | Source Record | 产生用户交付结果的交易证据。付费购买对应订单，零价领取对应领取记录；记录成功后才可触发盖世权益生成。 |
| 盖世权益 | GameHub Entitlement | 用户购买或领取交付方式为“盖世直接下载”的游戏后获得的下载、安装、启动和更新资格；CDKEY 订单不生成此权益。 |
| 权益状态 | Entitlement Status | 盖世权益链路的归一结果：权益对象尚未创建、生成中、有效、生成失败、退款撤销、合同撤销或违规撤销；其中“权益对象尚未创建”仅表示盖世包体来源记录已成功但尚无权益对象，状态变化保留来源、原因、操作人和时间。 |
| 交付快照 | Delivery Snapshot | 下单或领取成功时保存的 `game_id`、`product_id`、`sku_id`、交付方式、获取方式及限制；商品后续下架或字段变化不反向改写历史来源记录。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 在既有 CDKEY 交易链路之外补齐盖世包体权益，使用户在同一套详情、确认、结果和游戏库触点中按唯一交付方式完成获取。 |
| 目标用户 | 购买或领取正版游戏的盖世用户，以及查询、补发和撤销盖世权益的平台发行运营。 |
| 核心目标 | CDKEY 继续按既有规则完成 Key 履约；包体购买或领取成功后生成有效权益并进入游戏库；异常不重复扣款，商品下架不自动删除历史有效权益。 |
| 使用场景 | 用户从已发布游戏详情进入购买或领取，确认唯一交付方式后完成交易／领取，再到结果页和游戏库执行第三方激活或盖世下载；运营在异常时查找来源并处理权益。 |
| 功能概述 | 统一交付文案、购买／领取确认、结果状态、盖世权益状态、游戏库互斥动作、异常说明、运营查询处置及数据贯通组成用户交付闭环。 |

#### 交付对象与唯一性

| 对象 | 数据来源与关系 | 生效规则 | 冲突与历史处理 |
|---|---|---|---|
| CDKEY 用户交付 | 既有 CDKEY 订单及履约状态；关联用户、游戏、商品、SKU 和订单交付快照 | 按既有支付、取码、直接激活／后续一键激活和退款状态生效 | 不生成盖世权益，不提供盖世下载；本文不修改订单状态进入、退出和退款条件 |
| 盖世包体来源记录 | 付费订单或零价领取记录；关联用户、游戏、商品、SKU 和交付快照 | 付费订单支付成功或零价领取记录创建成功后触发权益生成；成功来源尚无权益对象时归一为“权益对象尚未创建” | 同一用户与游戏已有成功来源且权益对象尚未创建，或已有生成中／有效权益时，不重复创建来源记录或重复扣款；失败请求按动作标识幂等处理 |
| 盖世权益 | 关联一个用户、一个游戏及一个成功来源记录 | 同一用户与游戏同时最多一个生成中或有效权益；有效后进入游戏库并开放盖世下载入口 | 商品下架不改变有效权益；三种撤销均为不可被生成回调覆盖的终态并保留记录和原因；满足对应解除条件后的新购／领取创建新来源和新权益，不改写原撤销终态 |
| 游戏库条目 | 聚合用户对游戏的当前可解释交付结果 | 每个用户与游戏只展示一个游戏卡片和一种主交付方式 | 同时发现可操作 CDKEY 记录与盖世权益时，不同时展示两组动作，条目进入权益异常状态等待平台处置 |

#### 四触点统一表现

| 触点 | 第三方平台激活 | 盖世直接下载 | 统一约束 |
|---|---|---|---|
| 游戏详情 | 展示激活平台、适用地区、退款边界和既有购买动作 | 展示 Windows 支持、下载大小、更新要求及购买或领取动作 | 交付方式标签使用完整文案；复用既有底部主动作区，不增加第二购买入口 |
| 购买／领取确认 | 继续展示既有 SKU、发货方式、账号与支付限制，并增加“第三方平台激活” | 展示价格或零价领取条件、系统与交付限制，并显示“盖世直接下载” | 用户提交前再次看到与详情一致的交付方式；两种方式不在本页互相切换 |
| 订单／领取结果 | 按既有订单和 Key 状态展示取 Key、复制、激活、退款结果 | 展示权益生成中、成功或失败 | 失败不提供重复支付；结果页不出现另一交付方式的操作 |
| 游戏库 | 展示“第三方平台激活”及既有激活入口／指引 | 展示“盖世直接下载”及下载、启动或更新入口状态 | 一个游戏卡片只展示一种主交付方式和一组下一步动作 |

## 三、功能需求

### 3.1 C 端功能需求

#### 3.1.1 游戏详情页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 展示正版游戏资料、唯一交付方式、获取条件和进入购买／领取前必须知晓的限制。 |
| 场景描述 | 用户从既有推荐、搜索、游戏库或其他既有入口进入已发布游戏详情，判断该游戏是在第三方平台激活还是在盖世直接下载。 |
| 输入／前置条件 | 游戏资料已发布；至少一个面向当前地区和账号条件的商品／SKU 可见，或页面可读取暂不可获取原因。未登录用户可浏览，触发购买／领取时沿用既有登录流程并返回本页。 |

| 输出／后置条件 | 用户进入与当前交付方式一致的确认页，或进入已有游戏库条目／权益状态；页面保留本次 `game_id`、`product_id`、`sku_id`、`delivery_type` 及有效投放归因上下文。 |
| 补充说明 | 1. 商品下架或无可售 SKU 只停止新购／新领取，不改变用户已有订单和有效权益。<br>2. 成功来源尚无权益对象、权益生成中或有效时均拦截重复购买／领取；三种撤销只有满足本页对应解除条件后才允许新建来源，禁止用新订单立即绕过合同或违规限制。<br>3. CDKEY 的游客转正、实名／未成年人、收货账号、重复购买、支付前校验继续使用既有规则，本文不改条件和提示。<br>4. [待确认] 首款包体游戏是付费购买还是零价领取；未确认前页面结构可共用，但主动作、价格、支付和退款文案不能最终冻结。 |

#### 3.1.2 购买／领取确认页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 在提交支付或零价领取前确认游戏、SKU、交付方式、金额／领取条件和必要限制。 |

| 补充说明 | 1. 商品普通下架不构成撤销理由；有效权益保持不变，只停止新购／新领取。<br>2. 退款撤销以退款成功为前置，退款申请中或退款失败不得提前撤销权益。<br>3. 三种撤销均不允许从“权益对象尚未创建”或任一撤销终态进入；合同／违规限制的解除只恢复重新获取资格，不反向恢复原权益。<br>4. 操作日志至少记录 `action_id`、用户／游戏／来源／权益对象、前后状态、动作类型、原因、依据编号、操作人／系统、角色、结果、失败类型和时间；合同与违规动作的原因、依据和上报分别保存。 |

##### 处置动作与用户结果

| 动作 | 允许条件 | 成功结果与用户表现 | 失败与冲突 |
|---|---|---|---|
| 重试生成 | 来源记录成功，`from_status=generation_failed` 且原 `entitlement_id` 存在 | 复用原 `entitlement_id` 进入生成中；成功后有效并显示“盖世直接下载” | 与补发互斥；来源无效、权益 ID 缺失、已有有效权益或状态变化时不执行，返回当前结果 |
| 补发权益 | 来源记录成功、从未创建权益对象、`entitlement_id` 为空，且同一用户与游戏不存在生成中／有效权益 | 创建新 `entitlement_id` 并进入有效，结果页和游戏库同步成功 | 与重试互斥；不允许无来源或已有权益对象时补发，重复动作返回已有结果 |
| 退款撤销 | 退款已成功，且 `from_status` 仅允许 `generating`、`valid`、`generation_failed` | 权益进入退款撤销终态，用户看到“已退款，权益不可用” | 退款未完成、无权益对象或已是撤销终态时拒绝；迟到生成成功回调只记幂等结果 |
| 合同撤销 | 有授权的合同／发行处置依据，且 `from_status` 仅允许 `generating`、`valid`、`generation_failed` | 权益进入合同撤销终态，用户看到发行授权变化说明 | 普通商品下架、无依据、无权益对象或已是撤销终态时拒绝；迟到生成成功回调只记幂等结果 |
| 违规撤销 | 有授权的账号／订单违规依据，且 `from_status` 仅允许 `generating`、`valid`、`generation_failed` | 权益进入违规撤销终态，用户看到账号或订单违规说明 | 无依据、越权、无权益对象或已是撤销终态时拒绝；迟到生成成功回调只记幂等结果 |

### 3.3 统一状态、下架与历史规则

| 场景 | 判断与优先关系 | C 端结果 | B 端与历史处理 |
|---|---|---|---|
| CDKEY 订单与盖世权益 | `delivery_type=third_party_activation` 只读取既有订单／履约；`delivery_type=gamehub_direct_download` 只读取来源记录和盖世权益 | 四触点只显示对应完整文案和动作，不混用 | CDKEY 在既有订单模块处置；盖世权益在本文后台处置 |
| 已支付／领取但权益未生成 | 成功来源记录优先于用户重复提交；尚无权益对象归一为 `not_created`，已有权益对象处理失败才使用 `generation_failed` | `not_created`／生成中显示处理中，生成失败显示失败；均禁止重复支付，只有 `generation_failed` 可基于原 `entitlement_id` 重试 | `not_created` 仅允许运营补发，`generation_failed` 仅允许复用原权益重试；两动作互斥，重复回调和动作幂等 |
| 重复购买／领取 | 盖世包体已有成功来源且权益对象尚未创建，或已有生成中／有效权益时拦截新来源记录；CDKEY 重复购买继续既有规则 | 包体显示处理中或去游戏库；CDKEY 继续原确认提示与结果 | 不合并或覆盖不同 CDKEY 订单；包体不生成第二条有效权益 |
| 商品停售／游戏下架 | 停止新购／新领取和关联投放，不自动撤销用户有效权益 | 历史有效权益和游戏库条目保留；运行开关暂停时只显示动作不可用 | 保留商品、来源、权益和下架历史；重新发布不重建有效权益 |
| 退款成功 | `from_status` 为生成中／有效／生成失败时进入退款撤销终态；终态优先于迟到生成回调 | 显示“已退款，权益不可用”；当前商品、SKU 和账号资格通过时可“重新获取” | 不删除或恢复原记录；新购／领取创建新来源和新权益，重复退款及迟到生成回调只记幂等结果 |
| 合同撤销 | `from_status` 为生成中／有效／生成失败且具备合同／发行处置依据时进入终态；普通下架不触发 | 发行授权恢复且运营解除合同限制前显示“暂不可获取”；解除后按最新商品和资格显示“重新获取” | 留存合同原因和依据；新获取不改原终态，迟到生成回调只记幂等结果 |
| 违规撤销 | `from_status` 为生成中／有效／生成失败且具备账号／订单违规依据时进入终态 | 违规限制解除前显示“暂不可获取”；解除后按最新商品和资格显示“重新获取” | 留存违规原因和依据；新获取不改原终态，迟到生成回调只记幂等结果 |
| 两种交付记录冲突 | 同一用户与游戏同时存在可操作 CDKEY 记录及成功但尚无权益对象的盖世来源、生成中或有效盖世权益 | 只显示“权益状态异常”，不展示两组动作 | 运营核对来源；不得用当前商品字段覆盖历史快照或直接删除任一记录 |

| `entitlement_status` | enum／条件必填 | 当前盖世权益链路状态；`not_created` 仅用于盖世包体来源成功但权益记录创建前，以及补发动作完成后仍无权益对象的结果；CDKEY 使用 `not_applicable`。盖世包体购买／领取在来源尚未成功且无权益上下文的失败结果中为空，权益、游戏库和 B 端事件均必填 | `not_applicable`＝第三方平台激活不生成盖世权益；`not_created`＝权益对象尚未创建；`generating`＝生成中；`valid`＝有效；`generation_failed`＝生成失败；`revoked_refund`＝退款撤销；`revoked_contract`＝合同撤销；`revoked_violation`＝违规撤销 |
| `library_action` | enum／条件必填 | 游戏库当前被点击的下一步动作；游戏库动作事件必填 | `view_order`＝查看订单；`view_key`＝查看 Key；`activate`＝激活；`download`＝下载；`view_progress`＝查看处理进度；`view_error`＝查看异常；`open_detail`＝打开游戏库详情 |
| `handle_action` | enum／条件必填 | 运营权益处置动作；B 端处置事件必填。合同撤销、违规撤销是两个独立入口，只提交各自原因与依据并分别上报 `contract_revoke`、`violation_revoke` | `retry_generation`＝重试生成；`grant_entitlement`＝补发权益；`refund_revoke`＝退款撤销；`contract_revoke`＝合同撤销；`violation_revoke`＝违规撤销 |
| `operator_role` | enum／条件必填 | B 端处置操作主体；B 端事件必填 | `platform_ops`＝平台发行运营；`system`＝系统任务 |

#### 4.1.4 数据贯通规则

| 场景 | 贯通字段 | 成功判定 | 边界与去重 |
|---|---|---|---|
| 投放到购买／领取 | `campaign_id + game_id + delivery_type` 从详情上下文写入订单／领取来源快照 | 付费支付成功或零价领取记录创建成功 | 无有效投放上下文时 `campaign_id` 为空；具体归因窗口由精准投放 PRD 定义 |
| 购买／领取到盖世权益 | `source_record_id + uid + game_id + delivery_type` | 权益最终为 `valid` | 来源成功但无权益对象时为 `not_created`，仅可补发；已有 `generation_failed` 权益仅可复用原 `entitlement_id` 重试。两动作均使用 `action_id` 幂等，每个成功来源只产生一次有效结果 |
| CDKEY 购买到 Key 交付 | `source_record_id + game_id + delivery_type` 连接既有订单状态 | 既有订单履约达到 Key 成功交付终态 | 不把站外第三方激活当作默认可观测成功；无数据来源时不进入激活漏斗 |
| 游戏库下一步 | `uid + game_id + delivery_type + entitlement_status` | 点击当前有效主动作 | 一个页面会话每游戏只记一次曝光；动作按 `event_id` 去重 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 一致性 | 付费订单支付成功或零价领取记录成功后才可生成盖世权益；订单／领取、权益、游戏库和运营页读取同一 `game_id`、交付快照及状态版本。重试只复用已有 `generation_failed` 权益，补发只创建从未存在的权益对象；重复回调、重复提交和并发处置不得产生第二次扣款、第二条有效权益或状态回退。退款、合同和违规撤销为终态，迟到生成成功回调只记幂等结果，不得覆盖。 |
| 兼容 | 详情和游戏库沿用当前 PC 客户端外壳；无法识别新增交付或权益状态的客户端不得错误展示盖世下载／CDKEY 动作，应显示不可操作状态并引导更新既有客户端。 |
| 安全 | B 端按授权发行范围和角色校验；用户 ID 脱敏，Key、Steam 账号、支付凭据、实名信息、合同全文和违规证据原文不进入权益页面或操作日志。 |
| 数据存储 | 订单／领取来源、交付快照、权益状态版本、撤销原因、依据编号和操作日志保留关系；商品下架、退款和撤销不硬删除历史记录。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 商品／SKU 必须明确唯一交付方式和付费购买／零价领取条件；未确认获取方式、商品不可售、游戏下架或发布门禁未齐时不得开放新购／新领取。 |
| 用户文案 | 游戏详情、确认、结果和游戏库只使用 `第三方平台激活` 与 `盖世直接下载`。退款／合同／违规撤销使用本文确定的可理解文案，不向用户展示内部错误、合同或违规证据。 |
| 异常协同 | 运营建立权益对象未创建、生成失败、重复回调、交付冲突和撤销任务的处理责任；CDKEY 异常回到既有订单模块，盖世权益异常在本文后台处理。合同撤销须在发行授权恢复后由运营解除合同限制；违规撤销须在违规限制解除后恢复重新获取资格，两者均不恢复原权益。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 盖世包体付费购买复用既有支付、订单、退款和账务能力，不新增支付渠道；退款成功后才触发权益撤销。零价领取不生成支付流水。 |
| 法务 | 合同撤销需有可追溯的授权依据，普通商品下架不得用于批量撤销用户有效权益；既有 CDKEY 实名、未成年人、跨境及退款合规继续使用原规则和阻塞结论。 |
| 版权 | 仅已发布且发行授权有效的游戏可开放购买／领取；授权变化停止新获取，是否撤销特定用户权益需走明确合同处置，不自动推导。 |
| 其他合规 | 违规撤销需限定授权角色并记录依据；用户侧只展示必要原因，不泄露内部证据或个人敏感信息。 |

## 五、待确认项

| 待确认问题 | 默认建议 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 首款盖世包体游戏采用付费购买还是零价领取 | 以已签合同的价格／领取条款为准；页面和数据模型保持两种获取方式互斥，商品发布前只启用其中一种 | 阻塞游戏详情主动作与价格、确认页支付区、结果文案、退款规则和运营配置最终冻结；不阻塞共用页面结构、权益状态和游戏库互斥规则 | 阻塞 |
