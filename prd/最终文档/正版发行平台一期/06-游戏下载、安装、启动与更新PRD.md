## 一、文档概述

### 1.1 背景概述

- **需求背景：** 正版发行平台一期需让已获得“盖世直接下载”有效权益的 Windows 用户，从游戏库完成正式版本下载、安装、启动和后续更新，并可在异常时修复或卸载。
- **当前方式：** 当前 PC 游戏库可证明列表、详情和更多菜单外壳；下载管理仅能证明入口、标题、返回和空状态。包体发布链路已输出唯一当前线上版本及下载／启动开关，权益链路已输出有效权益和游戏库动作，但本地任务、失败恢复与文件保护尚缺统一规则。
- **问题：** 若任务状态、路径与空间校验、同游戏任务冲突、强制更新和退出恢复未统一，用户可能重复下载、破坏可运行版本或在无权益时启动；修复和卸载若边界不清，还可能误删权益或用户非托管文件。
- **证据：** 已批准一期规格明确“游戏库下载→选择安装位置→暂停／继续／取消／重试→校验安装→启动前校验→必须更新→更新后启动”，以及更新失败应保持任务、完整本地版本和重试入口；页面证据基线要求进行态与新增页面使用产品低保真，不能以当前空状态或历史 Mac 方案冒充 Windows 现状。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 仅包含 C 端 Windows 页面：安装位置选择、下载任务、下载管理、安装进度与结果、游戏库启动状态、必须更新提示、更新任务、启动失败恢复、游戏管理、修复确认与进度、卸载确认。只复用当前 PC 游戏库、下载管理入口／空态和更多菜单外壳；进行态及其余页面为本期产品低保真。 |
| 业务边界 | [已确认] 只处理 `delivery_type=gamehub_direct_download` 的单游戏乙方包体发行闭环。下载、安装、启动、更新和修复要求有效权益及可用当前线上版本；权益失效但本机仍有安装记录时，仅允许卸载该实际安装版本的托管文件。覆盖首次下载、完整性校验、安装、启动前权益／版本／运行开关校验、强制更新、修复和卸载；不处理 CDKEY 游戏文件。 |
| 运营边界 | 平台发行运营通过版本发布和运行开关决定当前线上版本、新下载及启动是否可用；客户端只消费已发布结果和可理解原因。本文不新增运营后台、开发者回滚、用户灰度或本地版本选择。 |
| 人力边界 | 发行运营负责线上版本和暂停／恢复原因；服务端提供有效权益、当前线上版本、版本清单和运行开关；Windows 客户端负责路径、空间、本地任务、校验、安装、启动、修复和卸载；测试与数据人员验证状态和事件。沿用已发布能力，不开展程序预研。 |

#### 一期明确不包含

1. CDKEY 游戏的下载、安装、启动或更新。
2. Mac、Linux、移动端、主机包体及跨系统安装迁移。
3. 预载、P2P、多下载源、多正式分支、用户选择正式版本、复杂增量包和开发者自助回滚。
4. 离线设备管理、高级 DRM、反作弊、强加壳和盗版监控。
5. 云存档、存档备份、存档恢复、用户文件迁移或多安装目录管理。
6. 下载限速、定时下载、带宽调度、CDN 策略和跨设备续传。
7. 游戏内更新器、DLC、Mod、创意工坊、语言包或可选组件管理。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 当前线上版本 | Current Live Version | 平台当前向新下载和需更新用户提供的唯一已发布正式版本；由包体发布链路输出。 |
| 当前完整本地版本 | Current Complete Local Version | 用户设备上最后一次完成完整性校验并安装成功的版本；更新失败不得破坏该版本文件，但强制更新未完成时仍不可启动。 |
| 本地任务 | Local Task | 某用户设备针对某游戏执行的一次下载安装、更新或修复过程，具备唯一 `task_id`、目标版本、安装路径、进度、阶段、状态和失败结果。 |
| 已替代任务 | Superseded Task | 旧失败任务因目标版本失效而重试，且最新目标的新 `task_id` 已创建成功后，旧任务进入的不可恢复终态 `superseded`；该终态不占用同游戏唯一非终态任务名额。 |
| 版本清单 | Version Manifest | 已发布版本中用于判断所需文件、大小、完整性和启动信息的受控清单；客户端仅消费平台返回的有效清单，不允许用户编辑。 |
| 强制更新 | Required Update | 平台判定当前完整本地版本不能继续启动，必须更新至指定当前线上版本；更新失败时旧文件保持完整，但启动仍被拦截。 |
| 运行开关 | Runtime Switch | 平台针对已发布游戏控制新下载或启动是否可用的状态；暂停与恢复不删除权益、本地任务和游戏文件。 |
| 托管游戏文件 | Managed Game Files | 当前版本清单明确归属于游戏安装的文件。修复和卸载只处理此范围，不删除权益和未列入清单的用户文件。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 为已获得盖世权益的 Windows 用户提供一条可恢复、可校验且不破坏完整本地版本的本地交付链路；有效权益用于交付，失效权益只保留本机卸载能力。 |
| 目标用户 | 已购买或领取盖世包体游戏、交付方式为“盖世直接下载”且在 Windows 客户端使用游戏库的用户；权益失效但已安装的用户仅使用卸载能力。 |
| 核心目标 | 用户可完成首次下载、安装、启动和强制更新；网络、空间、路径、任务、客户端退出或更新失败时有明确恢复；修复／卸载不删除权益。 |
| 使用场景 | 用户在游戏库下载首个正式版本，之后启动游戏；平台发布新正式版本后，用户完成强制更新再启动；文件异常时修复，不再使用时卸载后仍可重新下载。 |
| 功能概述 | 安装位置、下载任务、任务管理、完整性校验、安装结果、启动前校验、强制更新、失败恢复、修复、卸载、状态冲突和数据采集组成闭环。 |

#### 下游输入与本地对象

| 对象 | 唯一来源 | 客户端使用规则 | 冲突与历史 |
|---|---|---|---|
| 用户权益 | 用户购买、权益与游戏库链路 | 仅 `entitlement_status=valid` 且 `delivery_type=gamehub_direct_download` 可下载、安装、启动、更新或修复 | 商品下架不自动撤销权益；权益失效后停止交付与启动，不删除已安装文件，仅允许卸载该安装记录对应的托管文件 |
| 当前线上版本 | 包体测试发布链路 | 新下载、强制更新和修复只读取唯一已发布版本及版本清单 | 发布失败继续读取原线上版本；新版本成功后旧线上版本进入历史，不供新任务选择 |
| 下载／启动开关 | 包体线上版本处置 | 下载暂停时不新建／继续网络下载；任务在等待／网络阶段遇下载开关关闭时进入失败；启动暂停只阻止启动，不中断已开始的下载、校验或安装 | 开关恢复前任务、权益和本地文件不删除；发布修复版不自动恢复暂停开关 |
| 本地安装记录 | Windows 客户端 | 一个用户设备上的同一游戏仅有一个当前安装路径和一个当前完整本地版本 | 卸载清除安装记录但不清除权益；失败任务留存目标版本和恢复入口 |
| 本地任务 | Windows 客户端与服务端校验结果 | 同一游戏同时最多一个非终态下载安装、更新或修复任务；已安装、已取消和已替代不占用名额，失败仍占用 | 重复操作返回当前非终态任务；目标失效重试通过原子替换提交旧 `superseded` 与新 `waiting`，不得产生两个非终态任务抢写同一目录 |

#### 任务与游戏操作优先关系

| 当前条件 | 允许动作 | 禁止动作 | 恢复原则 |
|---|---|---|---|
| 无有效权益 | 查看权益状态；存在安装记录时卸载该实际安装版本的托管文件 | 下载、继续任务、安装、启动、更新、修复 | 权益恢复有效后重新校验；原目标仍有效时由用户重试原任务，原目标已失效时按原子替换规则创建最新目标新任务 |
| 有效下载／更新／修复任务 | 查看、暂停／继续、取消或重试当前任务 | 为同一游戏新建另一任务、启动、卸载 | 当前任务成功、取消或失败处置完成后再执行下一动作 |
| 游戏运行中 | 查看游戏状态 | 更新、修复、卸载；不重复启动 | 关闭游戏进程并刷新状态后继续 |
| 下载暂停 | 查看任务、等待平台恢复 | 新建或继续需要网络下载的任务 | 开关恢复且权益、版本、路径和空间重新校验通过后继续原任务 |
| 启动暂停 | 下载、安装、修复可按下载开关执行 | 启动游戏 | 开关恢复后启动前重新校验，不重新安装 |
| 强制更新未完成 | 查看更新、继续或重试更新 | 启动旧版本 | 更新成功并完成校验安装后开放启动 |

## 三、功能需求

### 3.1 C 端功能需求

#### 3.1.1 安装位置选择页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 选择一个可写且空间充足的 Windows 安装位置，并在创建下载任务前完成校验。 |
| 场景描述 | 已获得有效盖世权益且尚未安装游戏的用户，从游戏库点击“下载”后确认目标版本、所需空间和安装位置。 |
| 输入／前置条件 | `delivery_type=gamehub_direct_download`、权益有效、游戏存在当前线上版本、下载开关开启，且同一游戏无有效任务。客户端可读取版本清单、本机磁盘和目录权限。 |
| 需求描述 | **图示：**<br>![安装位置](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@9bff1252e90fc73af877672143f16a13c6762d5b/public/prd/genuine-game-distribution-phase1/06-install-launch-update/06-install-path.png)<br>*图 3.1.1-1：目标版本、路径、所需空间和校验结果的产品低保真；历史 Mac 方案只能提供规则参考，不是当前 Windows 页面证据。*<br>**界面文字与布局：** 顶部展示游戏与目标版本，中部展示安装路径、修改入口、所需空间及可用空间，底部为“开始下载”和返回动作；校验原因在对应字段就地展示。<br>**详细说明：** 本页只选择单一当前安装路径，不提供多个安装、副本迁移或版本分支选择。<br>**展示说明：**<br>1. 展示游戏名称、封面、当前线上版本、下载大小、安装后预计占用、本次任务所需空间、目标路径和磁盘可用空间；所需空间由版本清单和本地任务估算结果提供。<br>2. 默认读取客户端已配置且当前可用的安装根目录；目录不存在、不可写或空间不足时不默认选中，并展示“请选择可用安装位置”。<br>3. 路径状态覆盖可用、路径格式无效、目录不可创建、无写入权限、空间不足和被同游戏任务占用；原始完整路径只在本机显示，不进入埋点。<br>4. “开始下载”仅在权益、版本、下载开关、路径、空间和任务冲突均通过时可用；否则展示对应原因。<br>**交互说明：**<br>1. 修改路径后立即重新校验路径格式、可创建／可写、同游戏目录占用和可用空间；失败不创建目录或任务，用户可继续选择。<br>2. 点击“开始下载”时再次校验全部前置；成功创建唯一任务并进入下载任务页，重复点击返回同一 `task_id`，失败停留本页并展示原因。<br>3. 返回游戏库不创建任务；页面重新进入时可继续使用仍有效的上次选择，失效路径必须重新选择。 |
| 输出／后置条件 | 创建一条目标版本、安装路径和权益已锁定的下载安装任务，初始状态为等待或下载中，并进入下载任务页。 |
| 补充说明 | 1. 本文不规定固定盘符、目录名或安全空间百分比；任务所需空间必须覆盖版本下载、校验和安装过程的实际需要，具体值由客户端基于有效清单计算并展示。<br>2. 下载开始后空间变化仍需在写入和安装前重新校验；不足时进入失败且沿用已下载数据。<br>3. 游戏已安装时不进入本页；更新、修复或卸载使用当前安装路径。 |

#### 3.1.2 下载任务页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 展示单个游戏下载、校验和安装过程，并提供暂停、继续、取消和失败重试。 |

### 3.3 本地任务状态与冲突规则

#### 本地任务状态

| 状态 | 进入／退出 | 页面表现与允许操作 | 失败、恢复和历史 |
|---|---|---|---|
| 等待 | 任务创建成功或等待资源／前置；开始网络或校验后退出 | 显示等待原因；可取消 | 前置恢复后进入下载中、更新中或校验中；失败进入失败 |
| 下载中 | 首次下载或修复补文件开始；暂停、完成、失败或取消后退出 | 展示网络进度；可暂停、取消 | 网络中断进入失败，数据可继续时留存进度 |
| 暂停 | 用户暂停或退出客户端网络任务后进入；继续、取消或条件失效后退出 | 展示进度和暂停原因；可继续或取消 | 继续前重校权益、版本、开关、路径和空间；条件失效则进入失败 |
| 校验中 | 文件下载完成或修复开始后进入；通过、失败或客户端退出后退出 | 展示完整性进度；不允许暂停／取消 | 失败记录缺失／损坏或清单问题；可从校验或补下载恢复 |
| 安装中 | 校验通过并开始首次安装或更新应用后进入；成功、失败或客户端退出后退出 | 展示安装进度；不允许暂停／取消 | 失败不写入完整本地版本；重试安装或补文件 |
| 已安装 | 目标版本完整校验并安装成功后进入；后续更新、卸载或本地异常后退出 | 游戏库显示启动或必须更新 | 是任务成功终态；卸载不删除权益和任务历史 |
| 更新中 | 更新网络阶段开始；暂停、校验、失败或取消后退出 | 展示更新下载进度；可暂停，网络阶段可取消 | 失败或取消保持当前完整本地版本文件 |
| 失败 | 前置、下载、校验、安装、更新或修复任务未完成后进入；原目标重试成功、取消成功或原子替换成功后退出 | 同时展示失败阶段、原因、“重试”和“取消任务” | 原目标仍有效时重试使用原 `task_id`；目标失效时先尝试创建新任务，创建失败保持失败，创建成功才进入已替代；取消成功进入已取消 |
| 已取消 | 等待、下载中、更新中、暂停或失败由用户取消成功后进入 | 展示已取消并返回游戏库 | 是任务终态；只终止该 `task_id` 写入并清理其暂存文件，不改当前完整版本、权益和未托管文件 |
| 已替代 | 目标失效的失败任务重试时，最新目标新任务创建成功并完成原子提交后进入 | 展示“任务已按最新版本重新创建”和“查看新任务”；不允许重试、取消或恢复旧任务 | 是任务终态；保留旧任务历史及关联新 `task_id`，不占用同游戏唯一非终态任务名额 |

#### 任务冲突与恢复

| 场景 | 判断与优先关系 | 用户结果 | 恢复与历史 |
|---|---|---|---|
| 同一游戏多任务 | 单个游戏只能保持一条非终态任务；已安装、已取消和已替代不计入，失败仍计入 | 普通新动作进入当前非终态任务，不创建第二条 | 目标失效重试仅允许原子替换；提交后旧任务为已替代、新任务为等待，任何时点不得存在两条非终态任务 |
| 目标失效原子替换 | 锁定旧 `failed` 任务，按最新线上版本创建新 `task_id`，并校验同游戏唯一非终态约束 | 新任务创建成功才同时提交新 `waiting` 和旧 `superseded`；用户进入新任务 | 创建或提交失败时整体回滚，旧任务保持 `failed` 且仍可重试／取消，不产生可见新任务；重复 `action_id` 返回原结果 |
| 客户端退出 | 网络阶段保存进度并暂停；校验／安装阶段中断记失败 | 重开后显示暂停或失败及手动恢复入口 | 不自动消耗网络或把中断版本标为已安装 |
| 网络中断 | 下载／更新／修复补文件进入失败，已完成数据保持 | 显示网络中断、“重试”和“取消任务” | 网络恢复后从可继续位置恢复；重复重试幂等；取消成功进入已取消 |
| 空间或路径失效 | 创建任务、写入和安装前均校验；失败优先阻断文件写入 | 显示所需／可用空间或路径原因 | 空间释放或权限恢复后重试；不清空已通过数据 |
| 游戏运行中 | 启动进程优先于更新、修复和卸载 | 提示先退出游戏，不创建冲突任务 | 进程结束后重新校验并由用户发起 |
| 强制更新 | 强制版本规则优先于本地旧版本完整状态 | 更新成功前不开放启动 | 更新失败保持旧完整文件和任务；强制条件解除或更新成功后才可启动 |
| 等待／网络阶段条件变化 | 权益、下载开关或目标版本在任务执行中变化 | 当前任务进入失败，展示具体原因、“重试”和“取消任务” | 保留可恢复数据；条件恢复且原目标仍有效时按原任务重试，旧目标失效时执行原子替换，替换失败仍保持失败 |
| 校验阶段条件变化 | 当前原子校验完成前不强制中断 | 校验中不提供暂停或取消；完成后、安装前重校全部条件 | 不通过进入失败且不安装；已通过数据保留，原目标仍有效时可重试 |
| 安装／版本切换阶段条件变化 | 安装与当前完整版本切换使用原子保护 | 条件失效时不得把目标版本切换为当前完整本地版本 | 已有完整旧版保持；首次安装保持未安装；目标仍有效时重试原任务，目标失效时按原子替换结果进入已替代或保持失败 |
| 游戏下架／开关变化 | 下架不删除权益和文件；下载开关控制任务，启动开关只控制启动 | 启动开关关闭不打断下载、校验或安装；游戏库留存条目并显示平台原因 | 开关恢复后重校；修复版发布不自动恢复暂停开关 |
| 权益失效 | 权益状态优先于本地安装和任务 | 等待／网络任务进入失败；安装提交不得切换版本；停止新下载、启动、更新和修复，仅允许卸载已安装托管文件 | 权益恢复有效后由用户重试；当前完整版本、未托管文件和任务历史不硬删除 |
| 取消与暂存清理 | 取消只逻辑终止当前 `task_id` 的后续写入，并清理该任务暂存文件 | 成功进入已取消；不得删除当前完整版本、权益或未托管文件 | 暂存清理失败单独记录日志，不阻塞后续新任务；用户取消后重新发起时创建新任务，不使用已替代终态 |

### 3.4 统一操作日志规则

| 日志范围 | 创建／更新时机 | 结果要求 | 异常与保留 |
|---|---|---|---|
| 下载、更新、修复 | 任务创建、阶段切换、暂停、继续、重试、取消、成功、失败或替代时记录 | 同一动作通过 `action_id` 关联；原子替换成功同时记录旧任务 `failed→superseded` 和新任务创建为 `waiting`，失败只记录旧任务仍为 `failed` | 重复 `action_id` 返回原结果；取消暂存清理失败另记清理失败日志，不改取消终态，不阻塞新任务 |
| 卸载 | 确认卸载并持久化动作后立即写 `result=processing`；成功、失败或中断时更新该动作结果 | 使用实际安装记录和对应版本清单；成功后更新为 `success` 并记录未安装，失败／中断更新对应终态 | `processing` 期间 `finished_at` 为空；中断／失败保留安装记录并记录完整性异常，不得误记卸载成功 |
| 启动 | 每次启动前校验和启动执行产生结果时记录 | 无本地任务也记录独立 `action_id`；记录校验前后状态和启动结果 | 不记录启动敏感参数、进程路径或错误堆栈 |

| 字段组 | 字段 | 必填规则 | 口径 |
|---|---|---|---|
| 标识 | `log_id`、`action_id`、`game_id`、`uid` | 每条日志必填 | `log_id` 唯一；`action_id` 关联同一次用户／系统动作 |
| 任务与版本 | `task_id`、`related_task_id`、`target_version_id`、`installation_record_id` | 有任务或安装记录时必填；无关联任务时对应字段为空 | 原子替换日志以 `task_id` 记录旧任务、`related_task_id` 记录新任务；目标版本取动作对应版本；卸载取实际安装版本 |
| 状态与动作 | `before_status`、`after_status`、`stage`、`action`、`reason` | 每条日志必填；无阶段时 `stage=not_applicable` | 记录动作前后状态、执行阶段、用户动作／系统动作和可归一原因 |
| 责任与结果 | `operator_type`、`result`、`failure_stage`、`failure_type`、`created_at`、`finished_at` | 每条日志均必填 `result`；仅 `processing` 时 `finished_at` 为空 | `result`：`processing`＝进行中、`success`＝成功、`failure`＝失败、`cancelled`＝已取消、`interrupted`＝中断；成功／进行中失败字段为 `none`，其他终态记录阶段和类型 |
| 敏感信息 | 完整本地路径、文件内容、启动凭据和敏感参数 | 禁止记录 | 只记录安装记录标识与路径状态，不记录完整本地路径 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 新增并复用第 5 份 PRD 的游戏库动作上下文。所有本地交付事件仅在 `delivery_type=gamehub_direct_download` 时上报；`campaign_id` 从产生权益的订单／领取归因快照向下载、安装、首次启动和更新链路传递，无有效归因时为空。

#### 4.1.1 指标口径

| 指标名称 | 口径（含公式、分子和分母） | 去重与时间窗口 | 数据源与决策用途 |
|---|---|---|---|
| 下载任务成功率 | 分子为下载阶段结果 `game_download_result.result=success` 的任务数；分母为选定时间窗内进入下载终态成功／失败／取消的任务数，未终态任务单列不进入分母 | 按 `task_id + target_version_id` 去重，取每个任务最后下载结果；按自然日／周和 `campaign_id` 拆分 | 下载任务结果；判断首次内容获取的网络交付质量 |
| 安装成功率 | 分子为 `game_install_result.result=success` 的任务数；分母为选定时间窗内进入安装终态成功／失败的任务数 | 按 `task_id + target_version_id` 去重，取最后安装结果；自然日／周 | 安装结果；定位校验通过后是否能形成完整本地版本 |
| 首次启动成功率 | 分子为选定时间窗内发生启动尝试且已取得首次成功启动的用户游戏数；分母为同一时间窗内发生过启动尝试的用户游戏数 | 按 `uid + game_id` 去重；只有该用户该游戏历史首个成功启动事件 `is_first_launch=true`，失败事件和后续成功均为 `false`；按自然日／周及首个成功事件的 `campaign_id` 拆分 | 启动结果；失败后再次成功仍能进入首次真实游玩，不把首次失败永久断数 |
| 更新成功率 | 分子为 `game_update_result.result=success` 的更新任务数；分母为选定时间窗内进入更新终态成功／失败／取消的任务数，未终态任务单列 | 按 `task_id + from_version_id + target_version_id` 去重，取最后终态；自然日／周 | 更新结果；判断强制更新是否阻塞用户回到可启动状态 |

| `game_launch_result` | 游戏库启动／启动失败／新增 | 每次启动前校验或启动执行产生终态时上报；游戏进程成功创建且平台确认启动记为成功；仅该 `uid + game_id` 历史首个成功终态写 `is_first_launch=true`，失败及后续成功均写 `false`；`task_status` 条件必填，无关联任务时传 `not_applicable` | `event_id, action_id, uid, campaign_id, game_id, entitlement_id, delivery_type, task_status, from_version_id, target_version_id, result, failure_stage, failure_type, is_first_launch` |
| `game_update_result` | 更新任务／新增 | 强制更新整体成功、失败或取消时上报；目标版本写为当前完整本地版本才记成功 | `event_id, uid, campaign_id, game_id, entitlement_id, delivery_type, task_id, from_version_id, target_version_id, task_type, task_status, result, failure_stage, failure_type` |
| `game_repair_result` | 修复确认与进度／新增 | 修复成功、失败或任务取消后上报；确认态取消未创建任务，不上报；网络阶段或失败态取消以任务进入 `cancelled` 记取消，托管文件校验通过且完整性结果提交成功记成功 | `event_id, uid, campaign_id, game_id, entitlement_id, delivery_type, task_id, action_id, task_type, task_status, from_version_id, target_version_id, result, failure_stage, failure_type` |
| `game_uninstall_result` | 卸载确认／新增 | 已持久化的卸载动作取得成功／失败结果时上报；按实际安装版本清单删除托管文件并清除安装记录才记成功，中断或部分失败均记失败 | `event_id, action_id, uid, campaign_id, game_id, entitlement_id, delivery_type, from_version_id, result, failure_stage, failure_type` |

#### 4.1.3 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| `event_id` | string／是 | 单次事件唯一标识，用于事件级去重 | `evt_20260901_1001` |
| `action_id` | string／条件必填 | 开始下载、任务操作、启动、修复或卸载动作的幂等标识；对应动作事件必填 | `act_81001` |
| `uid` | string／是 | 当前登录用户唯一标识 | `user_10001` |
| `campaign_id` | string／否 | 产生当前权益的有效精准投放归因；自然流量或无归因时为空 | `campaign_70001` |
| `game_id` | string／是 | 游戏项目唯一标识，与权益和精准投放连接 | `game_40001` |
| `entitlement_id` | string／是 | 与本机任务或安装记录关联的盖世权益标识；下载、安装、启动、更新和修复时须有效，卸载时允许该权益已失效 | `entitlement_50001` |
| `delivery_type` | enum／是 | 全局交付方式枚举；本文事件只允许盖世直接下载 | `gamehub_direct_download`＝盖世直接下载；`third_party_activation`＝第三方平台激活，不允许上报本文事件 |
| `task_id` | string／条件必填 | 本地任务唯一标识；任务创建成功后及下载、安装、更新、修复事件必填 | `task_60001` |
| `task_type` | enum／条件必填 | 本地任务类型；任务事件必填 | `download_install`＝首次下载安装；`update`＝强制更新；`repair`＝文件修复 |
| `task_status` | enum／条件必填 | 事件发生后的任务状态；任务事件按实际状态上报，启动事件无关联任务时传 `not_applicable` | `not_applicable`＝无关联任务；`waiting`＝等待；`downloading`＝下载中；`paused`＝暂停；`verifying`＝校验中；`installing`＝安装中；`installed`＝已安装；`updating`＝更新中；`failed`＝失败；`cancelled`＝已取消；`superseded`＝旧任务已被最新目标新任务替代 |
| `task_action` | enum／条件必填 | 任务操作结果事件的动作 | `pause`＝暂停；`continue`＝继续；`cancel`＝取消；`retry`＝重试 |
| `from_version_id` | string／否 | 动作前的当前完整本地版本；首次下载时为空 | `version_50001` |
| `target_version_id` | string／条件必填 | 本次下载、安装、启动校验、更新或修复对应的目标／当前线上版本 | `version_50002` |
| `result` | enum／是 | 事件业务结果 | `success`＝成功；`failure`＝失败；`cancelled`＝用户取消 |
| `failure_stage` | enum／是 | 失败或取消所在阶段；成功使用无失败 | `none`＝无失败；`precheck`＝前置校验；`download`＝网络下载；`verify`＝完整性校验；`install`＝安装／应用；`launch`＝启动；`cleanup`＝卸载清理 |
| `failure_type` | enum／是 | 归一失败原因；成功使用无失败 | 基础：`none`＝无失败；`entitlement_invalid`＝权益无效；`delivery_mismatch`＝交付方式不符；`runtime_paused`＝下载／启动暂停；`version_unavailable`＝目标版本不可用；`target_version_changed`＝任务执行中线上目标版本变化；`mandatory_update`＝必须更新<br>本地环境：`path_invalid`＝路径不可用；`permission_denied`＝目录或对象无权限；`space_insufficient`＝空间不足；`game_running`＝游戏运行中；`task_conflict`＝同游戏任务冲突<br>任务执行：`network_interrupted`＝网络中断；`integrity_failed`＝完整性失败；`install_failed`＝安装失败；`launch_failed`＝启动执行失败；`user_cancelled`＝用户取消；`service_error`＝其他服务失败 |
| `is_first_launch` | boolean／条件必填 | 是否为该用户该游戏历史首次成功启动事件；启动结果事件必填，并以 `uid + game_id` 原子判定 | `true`＝本事件成功且此前无成功启动；`false`＝本事件失败，或此前已有成功启动 |

#### 4.1.4 数据贯通规则

| 场景 | 贯通字段 | 成功判定 | 边界与去重 |
|---|---|---|---|
| 权益到开始下载 | `campaign_id + game_id + entitlement_id + delivery_type` | 下载任务创建成功并取得 `task_id` | `campaign_id` 读取权益来源快照，不因后来页面入口改变；无归因时为空 |
| 下载到安装 | `task_id + game_id + target_version_id` | 下载成功后校验安装成功，任务为已安装 | 每个任务和目标版本取最后阶段结果；取消与失败分开统计 |
| 安装到首次启动 | `uid + game_id + entitlement_id + target_version_id` | 该 `uid + game_id` 历史首个成功启动终态写 `is_first_launch=true` | 失败事件一律为 `false`；首次失败后的首个成功仍为 `true`，后续成功为 `false`；并发成功只允许一个事件取得首次标记 |
| 目标失效任务替换 | 同一 `action_id` 关联旧 `task_id` 与最新目标新 `task_id` | 原子提交成功后，先上报旧任务 `game_task_action_result`：`failed→superseded`，再上报新任务 `game_download_start_result`：新 `task_id→waiting` | 两个事件均在提交后产生，分别按 `event_id` 去重，并以 `action_id + event_name + task_id` 防重复；创建／提交失败时旧任务保持 `failed`，不上报新任务成功事件 |
| 更新回到启动 | `task_id + from_version_id + target_version_id` | 更新成功且新版本写为当前完整本地版本 | 更新失败不覆盖旧本地版本；强制条件仍有效时旧版本不可启动 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容 | 仅支持一期指定的 Windows 客户端和正式包体；CDKEY、Mac、Linux、移动端及主机条目不得进入本地任务。 |
| 一致性 | 权益、当前线上版本、运行开关、本地任务和安装记录的状态版本必须可核对；任务与安装记录保留关联的 `entitlement_id`；同一游戏同时最多一个有效任务，重复动作、回调和客户端重开不得产生多任务或状态回退。 |
| 文件保护 | 首次安装、更新和修复只有在完整性校验、安装完成且提交前条件有效后写入当前完整本地版本；条件失效、失败或取消保持旧完整文件。修复只处理目标版本清单中的托管文件，卸载只处理实际安装版本清单中的托管文件。 |
| 安全 | 启动凭据、敏感参数、文件内容和完整本地路径不进入页面外链、埋点、普通日志或操作日志；任务只允许当前用户和本机访问。 |
| 数据存储 | 本地任务、目标版本、阶段、进度、失败结果、安装记录、最后完整版本、统一操作日志及“卸载中”动作需在客户端退出后可恢复；卸载、取消和权益失效不删除云端权益与业务历史。取消暂存清理失败与卸载中断需保留独立结果，不阻塞合法的新动作。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 版本与开关 | 发行运营发布唯一当前线上版本，并分别维护下载／启动开关及可理解原因；发布修复版后暂停开关保持，需验证后人工恢复。 |
| 用户文案 | 路径、空间、网络、完整性、安装、强制更新、权益、任务冲突和运行暂停使用归一原因；不向用户展示启动敏感参数、文件清单明细或内部错误堆栈。 |
| 异常协同 | 更新失败不得把用户置于无完整本地版本状态；权益、版本或运行开关异常分别回到对应责任链路，不用重新下载掩盖上游问题。 |

### 4.4 版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 版权 | 客户端只下载授权范围内、已测试通过并正式发布的版本；目标版本失效或游戏运行开关限制时停止对应动作。 |
| 用户文件 | 修复和卸载只处理托管游戏文件；未列入版本清单的用户文件、存档和配置不主动删除。本文不承诺云存档或备份。 |
| 权益 | 商品停售、游戏下架、本地卸载与权益撤销是独立状态；本地动作不得修改订单、领取或权益。 |
