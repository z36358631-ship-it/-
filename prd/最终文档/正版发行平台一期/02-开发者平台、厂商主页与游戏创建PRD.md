## 一、文档概述

### 1.1 背景概述

- **需求背景：** 正版发行平台一期需让首个已签约厂商在统一入口完成账号登录、厂商建档、游戏建档和资料审核，并在 C 端形成可追溯的厂商主页与游戏详情厂商入口。
- **当前方式：** 盖世已有游戏详情页面外壳和后台列表、审核等通用组件，但尚无面向正版发行合作方的受邀账号、固定模板厂商主页及厂商／游戏资料审核闭环。
- **问题：** 合作方缺少提交和跟踪资料的统一入口；平台发行运营无法在同一对象下核对签约范围、厂商资料和游戏资料；C 端厂商身份与已发布游戏缺少固定承载页。
- **证据：** 已批准的一期产品规格确认只服务受邀签约厂商，固定模板厂商主页仅展示厂商资料和已发布游戏；2026-08-31 会议确认开发者能力属于一期发行闭环。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] C 端包含固定模板厂商主页、游戏详情厂商信息区；B 端包含受邀账号登录、开发者工作台首页、厂商资料、游戏列表、创建／编辑游戏、资料审核结果，以及平台侧合作方账号配置、厂商资料审核、游戏资料审核。CDKEY 供给、包体版本、测试发布、投放需求和发行数据仅在工作台展示入口或状态摘要，不把其业务页面纳入本文。 |
| 业务边界 | [已确认] 服务 1 个已签约厂商和一期首款游戏；账号由平台代建并绑定唯一厂商，合作方只看本厂商对象。厂商资料和游戏资料先审核后成为有效版本；固定主页只展示已发布游戏。CDKEY 与盖世包体两种发行方式在本页只完成游戏资料选择和 C 端标签衔接。 |
| 运营边界 | 平台发行运营创建、启停合作方账号，审核厂商和游戏资料，核对发行授权、授权地区及合同合作范围，必要时修正游戏标签。游戏、商品、版本和投放的正式发布由对应运营流程执行，开发者无直接发布权限。 |
| 人力边界 | 已签约厂商维护自身资料与游戏资料；平台发行运营维护账号、审核资料和操作记录；产品、设计、服务端、测试和客户端分别承担规则、页面、业务能力、验证及 C 端入口改造。开发者平台与运营后台为 Web 页面，C 端厂商主页和游戏详情入口由客户端承载。不开展程序预研。 |

#### 一期明确不包含

1. 公众注册、开发者申请入驻和开放生态。
2. 合作方自行创建成员、角色分级或复杂权限配置。
3. 在线合同签署、合同文件管理、结算账户、自动分账和提款。
4. 厂商主页自定义装修、社区、私域运营、测试招募和内容发布。
5. 开发者直接发布游戏、商品、版本或投放计划。
6. 将既有包体管理流、CDKEY 供给页、投放页或数据看板定义为本文页面。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 受邀账号 | Invited Account | 由平台发行运营代建并绑定唯一厂商的登录账号；无公众注册入口。 |
| 厂商资料版本 | Publisher Profile Revision | 厂商名称、Logo、简介、官网和联系信息组成的一次提交快照；审核中不可覆盖，驳回后基于原输入修订。 |
| 游戏资料版本 | Game Profile Revision | 游戏基本资料、宣传素材、语言、地区、系统要求、标签和发行方式组成的一次提交快照。 |
| 已批准快照 | Approved Snapshot | 最近一次审核通过、可供平台业务或 C 端读取的厂商／游戏资料；新修改审核期间继续使用上一已批准快照。 |
| 关键资料 | Critical Profile Fields | 会改变用户识别、发行范围或交付判断的字段，包括厂商公开资料，以及游戏名称、素材、简介、语言、地区、系统要求、标签和发行方式。 |
| 游戏标签 | Game Taxonomy Tag | 开发者从平台标签库提交的类型、题材、玩法、适配设备及系统标签；仅平台审核通过或修正后的标签可在 C 端及正式投放中生效。 |
| 发布前置 | Release Prerequisite | 资料审核通过后仍须满足的商业条件，包括有效发行授权、发行地区在授权范围内及合同合作范围覆盖本游戏；价格、分成和结算责任由商品发布流程继续校验。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向首个受邀签约厂商的资料建档与审核闭环，并以固定模板在 C 端展示有效厂商资料和已发布游戏。 |
| 目标用户 | 已签约厂商的开发者账号、平台发行运营、浏览正版游戏的盖世用户。 |
| 核心目标 | 合作方可完成账号登录、厂商与游戏资料提交及驳回修订；运营可完成账号绑定、资料审核和发布前置核对；用户可从游戏详情进入可信的厂商主页。 |
| 使用场景 | 平台为签约厂商代建账号，厂商提交厂商及首款游戏资料，运营审核通过后进入 CDKEY 供给或包体版本准备；游戏发布后用户查看厂商主页及其已发布游戏。 |
| 功能概述 | 账号准入、厂商建档、游戏建档、资料审核、标签生效、已批准快照、固定主页和游戏详情厂商入口组成一条闭环。 |

#### 共享对象关系

| 对象 | 归属与数据范围 | 本文状态 | 后续去向 |
|---|---|---|---|
| 合作方账号 | 平台创建并绑定唯一厂商；合作方只读自身绑定关系 | 已启用、已停用 | 登录开发者工作台或被拒绝登录 |
| 厂商资料 | 合作方维护本厂商；运营审核签约范围内对象 | 草稿、审核中、已驳回、已通过 | 已通过快照用于 C 端固定主页和游戏详情厂商信息 |
| 游戏项目与资料 | 合作方只见本厂商游戏；运营见签约范围对象 | 草稿、资料审核中、已驳回、资料已通过，以及后续发布状态摘要 | 资料通过后进入 CDKEY 供给或包体版本准备 |
| 游戏标签 | 开发者提交候选标签；运营审核、移除或替换 | 未生效、已生效 | 已生效标签用于 C 端展示和正式投放规则 |
| 厂商主页 | C 端读取厂商已批准快照及该厂商已发布游戏 | 可访问、暂无已发布游戏、暂不可用 | 用户进入已发布游戏详情或返回来源页 |

## 三、功能需求

### 3.1 C 端功能需求

#### 3.1.1 固定模板厂商主页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 厂商公开资料与已发布游戏的固定展示页。 |
| 场景描述 | 用户在已发布游戏详情选择发行厂商，查看该厂商身份、简介、官网及其在盖世已发布的游戏。 |
| 输入／前置条件 | 厂商存在已批准资料快照；用户从游戏详情厂商信息区或有效厂商主页地址进入。页面不要求登录。 |
| 需求描述 | **图示：**<br>![固定厂商主页](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@b9882567090ebc419575ae61cbb55e7eb731d411/public/prd/genuine-game-distribution-phase1/02-developer/02-vendor-home.png)<br>*图 3.1.1-1：C 端固定模板厂商主页结构示意，表达厂商资料、官网入口、已发布游戏卡片及无游戏状态。*<br>**界面文字与布局：** 页面上方为返回与“厂商主页”标题，中部为 Logo、厂商名称、简介和官网，底部为“已发布游戏”卡片区；卡片并列展示封面、游戏名、标签摘要及唯一交付方式，空状态保留厂商信息。<br>**详细说明：** 页面采用固定模板，不提供换肤、组件增删、内容流或厂商自定义装修。<br>**展示说明：**<br>1. 顶部展示返回入口和页面标题“厂商主页”；主体展示厂商 Logo、厂商名称、简介及官网入口，联系姓名、电话和邮箱不在 C 端展示。<br>2. “已发布游戏”区只读取归属本厂商且状态为已发布的游戏；每张卡片展示封面、游戏名称、游戏标签摘要及唯一交付方式“第三方平台激活”或“盖世直接下载”。<br>3. 游戏默认按首次发布时间倒序；发布时间相同按游戏创建时间倒序。未发布、资料已通过但未发布及已下架游戏均不显示。<br>4. 厂商无已发布游戏时维持厂商信息，并在游戏区显示“暂无已发布游戏”；官网未填写时不展示官网入口。厂商资料不可用时展示“厂商主页暂不可用”及“返回”入口，不展示历史或未审核资料。<br>**交互说明：**<br>1. 选择返回后回到来源游戏详情并恢复进入前位置；无有效来源时返回上一可用页面。<br>2. 选择官网入口后按客户端既有外部链接规则打开已批准的 HTTPS 地址；地址失效时留在本页并显示“官网暂时无法打开，请稍后重试”。<br>3. 选择游戏卡片后先校验游戏仍为已发布；通过后进入该游戏详情，状态已变化时刷新列表并显示“该游戏暂不可查看”。 |
| 输出／后置条件 | 用户进入目标游戏详情或外部官网；页面始终只展示已批准厂商资料和已发布游戏。 |
| 补充说明 | 1. 新厂商资料审核期间继续展示上一已批准快照；从未通过审核的厂商资料不生成可访问主页。<br>2. 游戏下架后从列表移除，但不影响厂商其他已发布游戏。<br>3. 一期只覆盖单个首发游戏，不提供分页、筛选、搜索或厂商自定义排序。 |

##### 页面状态

| 状态 | 进入／退出 | 表现与操作 | 结果与恢复 |
|---|---|---|---|
| 正常 | 厂商资料可用且存在已发布游戏；游戏全部下架后退出 | 展示厂商信息和游戏卡片，可进入详情或官网 | 单个游戏失效时刷新列表，其余内容不变 |
| 暂无已发布游戏 | 厂商资料可用且已发布游戏数为 0；游戏发布后退出 | 展示厂商信息和“暂无已发布游戏”，官网可用时仍可打开 | 游戏发布后刷新为正常状态 |
| 暂不可用 | 厂商无已批准快照、账号／合作关系被平台停用且主页不可公开，或资料读取失败 | 显示“厂商主页暂不可用”和“返回”，不展示未审核资料 | 条件恢复后重新进入或刷新；读取失败不以旧缓存冒充最新结果 |

#### 3.1.2 游戏详情厂商信息区

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 游戏详情中的发行厂商身份及厂商主页入口。 |

| 输入／前置条件 | 游戏已发布；游戏绑定唯一厂商；厂商名称来自已批准快照。交付方式、购买／领取和限制信息按游戏详情主规则展示。 |
| 需求描述 | **图示：**<br>![详情厂商入口](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@b9882567090ebc419575ae61cbb55e7eb731d411/public/prd/genuine-game-distribution-phase1/02-developer/02-game-publisher-entry.png)<br>*图 3.1.2-1：C 端游戏详情结构示意，仅表达新增的发行厂商信息区及其与交付方式区域的关系。*<br>**界面文字与布局：** 页面沿用游戏详情的信息层级，发行厂商信息组位于游戏基础资料中，展示“发行厂商”、Logo、名称和主页可用状态；唯一交付方式位于相邻信息区，二者同时可见。<br>**详细说明：** 本页仅定义厂商信息区，不重做游戏详情媒体、商品或交付链路。<br>**展示说明：**<br>1. 在游戏基础信息区展示字段名“发行厂商”、厂商 Logo 和厂商名称；名称使用厂商已批准快照，不能显示审核中修改稿。<br>2. 厂商主页可访问时，厂商名称和 Logo 显示可进入状态；暂不可访问时仍展示发行厂商名称，但入口为不可用状态并标注“主页暂不可用”。<br>3. 厂商信息区与唯一交付方式同时可见；交付方式仍只能是“第三方平台激活”或“盖世直接下载”之一，厂商入口不得遮挡或弱化交付限制。<br>**交互说明：**<br>1. 选择可用的厂商名称或 Logo 后进入对应固定模板厂商主页；返回后恢复游戏详情原位置。<br>2. 选择不可用入口时不跳转，并在信息区显示“厂商主页暂不可用”；刷新后按最新厂商状态恢复。<br>3. 厂商资料更新审核通过后，重新进入或刷新详情读取新已批准快照；审核中不改变线上展示。 |
| 输出／后置条件 | 用户进入与当前游戏绑定的厂商主页，或留在详情查看明确的发行厂商身份和不可用原因。 |
| 补充说明 | 1. 游戏与厂商绑定关系由平台创建和审核，C 端不提供切换厂商能力。<br>2. 厂商名称修改审核期间不影响已发布游戏的旧名称展示；审核通过后两处统一更新。<br>3. 本信息区不展示厂商联系信息、合同信息或结算信息。 |

### 3.2 B 端功能需求

#### 3.2.1 受邀账号登录页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 平台代建合作方账号的身份校验入口。 |

### 4.1 埋点与数据需求

| `result` | enum／是 | 登录处理结果 | `success`＝建立会话；`failure`＝未建立会话 |
| `failure_type` | enum／是 | 登录失败类型；成功时传 `none` | `none`＝无失败；`invalid_credential`＝凭据错误；`account_disabled`＝账号停用；`permission_denied`＝绑定或权限失败；`network_or_service`＝网络或服务失败 |
| `profile_revision_id` | string／是 | 厂商资料审核版本唯一标识 | `vendor_rev_30001` |
| `submit_type` | enum／是 | 本次提交类型 | `first_submit`＝首次提交；`resubmit`＝驳回后重新提交；`modification`＝已通过后修改提交 |
| `review_result` | enum／是 | 审核终态 | `approved`＝已通过；`rejected`＝已驳回 |
| `reject_reason_code` | enum／是 | 驳回原因分类；通过时传 `none` | `none`＝通过；`missing_info`＝资料不完整；`invalid_asset`＝素材不合规；`rights_conflict`＝授权冲突；`region_conflict`＝地区冲突；`tag_adjustment`＝标签需调整；`other`＝其他原因 |
| `operator_role` | enum／是 | 审核操作角色 | `platform_ops`＝平台发行运营 |
| `game_id` | string／是 | 游戏项目唯一标识 | `game_40001` |
| `game_revision_id` | string／是 | 游戏资料审核版本唯一标识 | `game_rev_50001` |
| `release_mode` | enum／是 | 游戏唯一发行方式 | `third_party_activation`＝第三方平台激活；`gamehub_direct_download`＝盖世直接下载 |
| `source_page` | enum／是 | 厂商主页访问或卡片点击来源 | `game_detail`＝游戏详情；`vendor_home`＝厂商主页；`direct`＝有效地址直接进入 |
| `page_state` | enum／是 | 厂商主页返回状态 | `normal`＝存在已发布游戏；`empty_games`＝暂无已发布游戏；`unavailable`＝主页暂不可用 |
| `target_state` | enum／是 | 厂商入口处理结果 | `opened`＝成功进入厂商主页；`unavailable`＝入口不可用未跳转 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容 | 开发者与运营页面支持公司当前指定的桌面浏览器；C 端厂商主页和详情厂商信息区沿用当前游戏详情的横竖屏容器与返回规则。本 PRD 不新增 Mac、Linux、移动端或主机包体字段。 |
| 安全 | 受邀账号每次读取和提交均校验绑定厂商；越权请求不返回对象存在性和内容。密码不可在列表、日志或导出中明文展示；联系信息只对本厂商账号和有权限运营可见。 |
| 数据存储 | 厂商与游戏每次提交、审核结果、标签修正和线上已批准快照均保留版本关系；停用账号、驳回资料或游戏下架不删除历史审核和操作记录。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 平台发行运营代建账号、绑定唯一厂商、维护线下合同元数据并执行启停；审核厂商与游戏资料，维护标签生效结果。账号、资料和审核状态变化同步至开发者工作台。 |
| 内容／素材 | 合作方提交厂商 Logo、简介、官网、联系信息及游戏图标、封面、截图、文案、语言、地区、系统要求、标签和发行方式；运营按签约与版权范围审核。 |
| 上线协同／推广 | 游戏资料通过后才可进入 CDKEY 供给或包体版本准备；正式发布前必须重新校验发行授权、授权地区、合同合作范围及商品侧商业条件。精准投放不在本页配置。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 本 PRD 不建设结算账户、分账或提款；正式发布前须由后续商品／发布流程确认价格或零价领取条件、分成及结算责任。 |
| 法务 | 厂商须完成线下签约；发行授权在有效期内、销售地区未超出授权地区且合同合作范围覆盖本游戏及发行方式，方可正式发布。账号配置页只记录合同元数据，不提供在线签署。 |
| 版权 | 厂商对名称、Logo、游戏素材、文案及官网链接具备合法使用权；运营审核不替代厂商版权责任，侵权或授权失效时阻塞发布并进入平台处置。 |
| 其他合规 | 联系手机和邮箱不在 C 端展示；地区、语言、未成年人和数据处理遵循平台已有合规要求。开发者不能查看其他厂商数据或用户个人数据。 |
