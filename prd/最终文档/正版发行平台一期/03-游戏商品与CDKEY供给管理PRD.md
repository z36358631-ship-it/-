## 一、文档概述

### 1.1 背景概述

- **需求背景：** 正版发行平台一期需把已签约厂商的游戏项目与 CDKEY 商品、SKU、供应来源和销售状态连接起来，使平台发行运营可完成供给准备、可售发布和异常处置，开发者可查看自身游戏的供给结果。
- **当前方式：** 现有 CDKEY 方案已定义用户购买、支付、订单、Key 交付、激活指引和退款，评审后确定以供应商 API 提供价格、活动价、库存、取码和激活能力；旧版后台本地定价、批量导码及本地库存预警方案已废止。
- **问题：** 现有资料未形成厂商、游戏、商品 SKU、激活平台、销售地区、供应来源和商业门禁的统一管理关系；开发者无法在不接触 Key 与供应商敏感信息的前提下查看供给状态；供应异常后的停售、恢复和旧订单边界缺少一致口径。
- **证据：** 已批准的一期规格明确 CDKEY 分支只新增供给侧和平台衔接；2026-07-31 评审修订设计确认供应商 API 为默认供货模式，并废止本地独立定价、批量导码和本地库存预警。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 本文只包含 B 端。开发者侧包含“游戏商品与供给状态页”“供给异常详情页”；平台发行运营侧包含“游戏商品列表页”“商品／SKU 配置页”“供应来源关联页”“库存与供给异常页”。不新增 C 端页面；C 端继续读取有效 SKU、价格与可售结果，并沿用“第三方平台激活”交付方式。 |
| 业务边界 | [已确认] 只覆盖 CDKEY 商品、SKU、激活平台、销售地区、供应来源、价格／库存同步、可售／停售及异常恢复。用户购买、支付、订单、Key 交付、激活指引和退款完整复用既有 CDKEY PRD，不在本文重新定义。[待确认] 当前实际供给方式尚未由业务确认，默认建议复用现有供应商 API；受控直接供 Key 只作为补充来源类型，不开放开发者批量明文上传。 |
| 运营边界 | 平台发行运营配置商品与 SKU、关联供应来源、核对商业门禁、发布可售、停售并确认恢复；开发者只读查看本厂商结果。资料审核通过仅代表游戏资料有效，不等于商品可发布。平台不在本文建设本地价格维护、Key 明细管理或库存阈值告警。 |
| 人力边界 | 已签约厂商提供游戏和线下商务资料；平台发行运营维护商品、供给关系及处置记录；商务／财务／法务确认授权、地区、定价或领取条件、分成与结算责任；产品、设计、服务端、测试和数据人员完成页面、业务规则及数据采集。不开展程序预研。 |

#### 一期明确不包含

1. 开发者自助创建、定价、发布、停售或恢复商品。
2. 开发者批量上传、查看、复制或导出明文 Key。
3. 平台运营本地批量导码、本地 Key 明细查看和本地库存阈值预警。
4. 脱离供应商数据维护一套独立零售价、活动价或库存数量。
5. 重做详情、确认订单、支付、订单中心、Key 展示、一键激活和退款流程。
6. 多供应来源自动路由、智能比价、自动切换供应商和多级供应商结算。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 商品 | Product | 关联一个已审核游戏项目且交付方式为“第三方平台激活”的交易对象；一个商品可包含多个 SKU。 |
| SKU | Stock Keeping Unit | 商品在版本、激活平台、适用范围和销售地区等维度形成的可交易单元；SKU 名称、版本和适用范围以关联供应来源的有效商品数据为准。 |
| 供应来源 | Supply Source | 为 SKU 提供价格、活动价、库存、取码或激活能力的来源。一期默认类型为供应商 API；受控直接供 Key 仅能关联平台已批准的安全供给记录。 |
| 供给状态 | Supply Status | 平台根据供应来源返回结果归一后的状态：待关联、可供货、库存不足、售罄、异常或未知；“库存不足”只读取供应来源明确返回的状态，不使用平台本地阈值推算。 |
| 可售状态 | Sale Status | 商品或 SKU 面向新订单的状态：不可售、可售或停售。可售需同时满足资料、商业、配置和供给门禁。 |
| 商业门禁 | Commercial Gate | 正式可售前必须满足的条件：发行授权有效、销售地区在授权范围、价格或领取条件明确、分成明确、结算责任明确。 |
| 价格快照 | Price Snapshot | 既有 CDKEY 订单在创建时保存的商品、SKU、实付价格和活动信息；供应价格后续变化不反向改写该订单。 |
| 供给异常 | Supply Incident | 库存不足／售罄、价格无效、来源不可用、映射失效或商业门禁失效等导致新售受限的记录；每条记录具备发现、待恢复确认和已恢复过程。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向受邀签约厂商的 CDKEY 供给管理闭环，由平台运营完成商品配置、来源关联、可售发布及异常恢复，开发者只读查看自身游戏结果。 |
| 目标用户 | 已签约厂商的受邀开发者账号、平台发行运营，以及参与门禁确认的商务、财务和法务人员。 |
| 核心目标 | 建立一个商品到多个 SKU、每个 SKU 到一个生效供应来源的稳定关系；确保只有门禁齐全且供给正常的 SKU 可进入新售；异常处置不暴露 Key、不修改旧订单。 |
| 使用场景 | 游戏资料通过后，运营建立商品和 SKU，关联来源并校验商业条件；发布后持续读取供给状态，发生异常时停止新增销售，恢复后由运营确认重新可售。 |
| 功能概述 | 商品列表、SKU 配置、来源关联、供给同步、可售门禁、停售恢复、异常记录、开发者只读状态和操作审计组成供给侧闭环。 |

#### 对象、数据源与状态分层

| 对象／口径 | 唯一数据来源 | 状态或生效规则 | 影响范围 |
|---|---|---|---|
| 游戏与发行方式 | 游戏已批准快照 | 游戏资料已通过，且发行方式为“第三方平台激活”时才可创建 CDKEY 商品 | 决定商品归属、厂商范围及 C 端交付方式 |
| 商品与 SKU 结构 | 平台发行运营配置 | 一个商品关联一个游戏；一个商品可含多个 SKU；同一游戏不得重复关联同一供应商商品 | 决定可售单元和列表聚合结果 |
| SKU 名称、版本、激活平台、适用范围 | 生效供应来源的商品数据 | 来源校验成功后写入有效快照；来源数据缺失或冲突时 SKU 不可售 | 决定用户可选版本及激活限制 |
| 销售地区 | 平台运营从游戏已批准销售地区中选择 | 必须同时属于游戏已批准销售地区、有效授权地区和供应来源适用范围 | 决定 SKU 对哪些地区的新用户可见 |
| 常规价格、活动价、币种、活动有效期 | 生效供应来源同步结果 | 不提供本地独立价格输入；有效活动价优先，活动失效后读取来源常规价格；无有效价格时不可售 | 只影响同步成功后的新订单展示和新建订单 |
| 库存与供给能力 | 生效供应来源同步结果 | 供应来源明确返回可供货方可进入可售；不足、售罄、异常或未知均停止新增可售曝光 | 不取消旧订单，不删除已交付 Key |
| 订单价格与履约来源 | 既有订单价格及履约快照 | 商品、价格或来源后续变更不覆盖旧订单；待支付有效期、支付后取码及失败退款沿用既有 CDKEY 规则 | 保证历史订单可追溯和逆向处理稳定 |

#### 可售／发布门禁

| 门禁组 | 通过条件 | 未通过表现 | 恢复与冲突处理 |
|---|---|---|---|
| 资料门禁 | 厂商资料和游戏资料已通过，游戏发行方式为“第三方平台激活” | 商品可保存配置，但不能发布可售；展示缺失项 | 资料补齐后重新计算，不要求重建未变化 SKU |
| 授权门禁 | 发行授权在有效期内，商品销售地区均在授权地区，合同合作范围覆盖 CDKEY 发行 | 阻塞发布；已售商品进入停售并记录原因 | 授权恢复后仍需运营确认，历史资料审核结果不被改写 |
| 商业门禁 | 价格或领取条件、分成和结算责任均有明确结果 | 标记“商业条件未齐”，不可进入可售 | 商务信息补齐后重新校验；本文不建设自动结算 |
| SKU 门禁 | 至少一个 SKU 配置完成，激活平台、适用范围、销售地区和交付能力有效 | 商品保持不可售，定位到具体 SKU 字段 | 修正配置后可重新校验，不复制旧错误值到新版本 |
| 供给门禁 | SKU 已关联一个生效来源，价格有效，供给状态为可供货 | 不展示新购入口；库存或来源异常生成供给异常 | 来源恢复后先进入待恢复确认，不自动重新开售 |
| 发布门禁 | 上述条件全部通过，操作人为平台发行运营 | “发布可售”不可执行，并展示门禁清单 | 并发变化时以提交瞬间的服务端状态为准；失败不产生部分可售 SKU |

### 2.2 产品流程

横向流程从左到右为：游戏资料通过 → 平台创建商品与 SKU → 绑定激活平台、适用范围和销售地区 → 关联供应来源 → 校验发行授权、价格或领取条件、分成及结算责任 → 同步价格与供给状态 → 发布可售 → 供给不足、来源异常、商业条件失效或运营停售 → 停止新增可售曝光 → 来源恢复并由运营确认 → 恢复可售 → 开发者查看本厂商供给与异常结果。开发者始终无发布、停售、恢复、Key 明文和供应商敏感信息权限。

## 三、功能需求

### 3.2 B 端功能需求

#### 3.2.1 游戏商品与供给状态页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 开发者查看本厂商 CDKEY 商品、SKU、可售门禁和供给状态。 |

| 输出／后置条件 | 开发者获得本厂商商品、SKU、门禁和供给的只读结果，或进入本厂商某条异常详情。 |
| 补充说明 | 1. 价格和库存来源发生变化时只展示平台已保存的最新有效结果；未知值不作可售判断。<br>2. 商品停售或来源异常不改写开发者侧历史订单统计，也不提供旧订单处置入口。<br>3. 页面无 Key 上传、查看、复制、导出、商品编辑和销售状态操作。 |

##### SKU 列表与数据范围

| 规则项 | 数据与范围 | 展示与操作 | 异常与恢复 |
|---|---|---|---|
| 数据源 | 当前账号绑定厂商下、发行方式为第三方激活的游戏商品及 SKU 有效快照 | 每个 SKU 一行；商品状态在页头聚合 | 发现越权对象时整条不返回并记录访问结果 |
| 搜索与筛选 | SKU 名称包含匹配；激活平台、销售地区、供给状态、可售状态可组合 | 任一条件改变后回到第 1 页 | 查询失败保留条件并允许重试 |
| 排序与分页 | 异常生效中的 SKU 优先，其余按更新时间倒序；同时间按 SKU 创建时间倒序 | 默认每页 20 条，可切换 20、50、100 条 | 页码越界时回到最后有效页，不重复展示记录 |
| 页面权限 | 开发者只读本厂商状态；平台发行运营不通过本页编辑 | 无跨厂商、明文 Key、供应商敏感数据或导出能力 | 越权不返回对象内容，保留账号、目标和结果日志 |

| 要素 | 内容说明 |

### 3.3 统一操作日志规则

商品、SKU、供应来源和销售状态的每次操作尝试均写入一条日志，成功与失败都记录。固定字段为 `log_id`、`action_id`、唯一动作值、对象类型、对象 ID、对象版本、变更前值、变更后值、原因、操作人、操作角色、操作来源、结果、失败类型和发生时间。创建动作在失败且尚未分配对象 ID 时允许该对象 ID 为空，但必须记录 `action_id`、父对象 ID 和提交版本；自动动作的操作人固定为 `system`，角色和来源必须写明系统任务，不得伪装成人工操作。

| 动作（唯一值） | 对象 ID 与版本 | 变更前后值与原因 | 操作主体与来源 |
|---|---|---|---|
| `create_product`＝创建商品 | `game_id`；成功或已分配时记录新 `product_id` 和初始版本 | 前值为空；后值为商品配置快照；失败也记录提交内容摘要、`result` 和 `failure_type` | `operator_id + platform_ops + product_editor`；记录 `occurred_at` |
| `edit_product`＝编辑商品 | 当前 `product_id`、原版本及新版本 | 前值为上一有效版本，后值为本次编辑版本；记录编辑原因、结果和失败类型 | `operator_id + platform_ops + product_editor`；时间取本次提交完成点 |
| `invalidate_product`＝使商品失效 | 目标 `product_id` 与失效操作版本 | 前值为当前商品状态，后值为已失效；原因必填，失败时保留原状态 | `operator_id + platform_ops + product_status_action`；记录发生时间 |
| `create_sku`＝创建 SKU | 父 `product_id`；成功或已分配时记录新 `sku_id` 和初始版本 | 前值为空，后值为 SKU 配置快照；记录结果及失败类型 | `operator_id + platform_ops + sku_editor`；记录创建完成时间 |
| `edit_sku`＝编辑 SKU | 父 `product_id`、目标 `sku_id`、原版本和编辑后版本 | 前值为上一 SKU 版本，后值为本次编辑版本；记录编辑原因和处理结果 | `operator_id + platform_ops + sku_editor`；失败同样留痕 |
| `invalidate_sku`＝使 SKU 失效 | 父 `product_id`、目标 `sku_id` 与失效操作版本 | 前值为当前 SKU 状态，后值为已失效；原因必填 | `operator_id + platform_ops + sku_status_action`；记录结果、失败类型和时间 |
| `link_source`＝关联供应来源 | `product_id + sku_id`，以及新 `source_relation_id` 和初始关系版本 | 前值为未关联，后值为来源关系快照；记录选择原因和校验结果 | `operator_id + platform_ops + supply_link_page`；失败关系不生效但记录日志 |
| `change_source`＝变更供应来源 | `product_id + sku_id`、原／新 `source_relation_id` 及变更版本 | 前值为原来源关系，后值为新关系；变更原因必填 | `operator_id + platform_ops + source_change_action`；记录结果、失败类型和时间 |
| `unlink_source`＝解除供应来源 | `product_id + sku_id`、目标 `source_relation_id` 与解除版本 | 前值为生效关系，后值为未关联／原关系失效；解除原因必填 | `operator_id + platform_ops + source_unlink_action`；失败时原关系不变 |
| `publish`＝发布可售 | `product_id + sku_id` 与发布后的销售状态版本 | 前值为不可售／停售，后值为可售；记录门禁快照及发布原因 | `operator_id + platform_ops + product_list_page`；记录结果、失败类型和时间 |
| `stop_sale`＝人工停售 | `product_id + sku_id` 与停售后的销售状态版本 | 前值为可售，后值为停售；停售原因必填 | `operator_id + platform_ops + sale_stop_action`；失败也记录 |
| `auto_stop_sale`＝系统自动停售 | `product_id + sku_id + sale_state_version + exception_id` | 前值为可售，后值为停售；原因取触发异常，不接受人工改写 | `system + system + exception_guard`；记录结果、失败类型和发生时间 |
| `resume_sale`＝恢复可售 | `product_id + sku_id` 与恢复后的销售状态版本 | 前值为停售，后值为可售；记录恢复门禁快照和确认原因 | `operator_id + platform_ops + stock_error_page`；失败时保持停售并留痕 |
| `retry_sync`＝同步重试 | `product_id + sku_id + source_relation_id + sync_action_version` | 前值为最近一次同步状态，后值为本次同步结果；记录重试原因 | 人工重试记 `operator_id + platform_ops + stock_error_page`；系统调度另记 `system + system + scheduled_sync` |

日志的 `result` 只使用成功或失败，成功时 `failure_type=none`，失败时必须写具体失败类型；任何日志均不得写入 Key 明文、接口凭据、完整供应商报文、合同金额或结算账户。

### 4.1 埋点与数据需求

#### 4.1.1 指标口径

| 指标名称 | 口径（含公式、分子和分母） | 去重与时间窗口 | 数据源与决策用途 |

| 供应同步成功率 | `cdkey_supply_sync_result` 中 `result=success` 的同步次数 ÷ 同事件全部同步次数 | 按 `action_id` 去重；按自然日和来源类型统计 | 供应同步事件；定位来源稳定性，不作为本地库存预警 |
| 供给异常恢复时长 | 每条已恢复异常的恢复成功时间减首次发现时间，统计中位数及未恢复数量 | 按 `exception_id` 去重；按自然周统计，跨周异常计入恢复周 | 异常状态事件；判断运营处置效率 |
| 发布／恢复门禁通过率 | 成功发布或恢复动作数 ÷ 全部发布或恢复提交动作数 | 按 `action_id` 去重；按自然周统计 | 销售状态事件；识别配置或商业前置缺失 |

#### 4.1.2 埋点事件

| 事件 | 页面／类型 | 触发与成功 | 参数 |
|---|---|---|---|
| `cdkey_product_config_result` | B 端商品／SKU 配置页／新增 | 商品或 SKU 创建、编辑、失效提交后上报一次；目标配置版本成功写入记为成功，失败也上报。仅 `config_action=create_product` 且 `result=failure` 时允许 `product_id` 为空 | `action_id, vendor_id, game_id, product_id, sku_id, config_action, result, failure_type, operator_role` |
| `cdkey_supply_link_result` | B 端供应来源关联页／新增 | 关联、变更或解除提交后上报；生效关系完整写入记为成功，半生效不记成功 | `action_id, vendor_id, game_id, product_id, sku_id, source_type, link_action, result, failure_type, operator_role` |
| `cdkey_supply_sync_result` | 服务端供应同步／新增 | 每次同步完成后上报；价格及供给归一结果成功保存记为成功，每次重试使用新 `action_id` | `action_id, vendor_id, game_id, product_id, sku_id, source_type, supply_status, result, failure_type` |
| `cdkey_sale_state_change` | B 端游戏商品列表页／新增 | 发布、停售或恢复提交后上报；目标销售状态首次成功写入记为成功，并发重复结果不重复记成功 | `action_id, vendor_id, game_id, product_id, sku_id, sale_action, sale_status, result, failure_type, operator_role` |
| `cdkey_supply_exception_state_change` | B 端库存与供给异常页／新增 | 异常首次生成、进入待恢复确认或确认恢复后上报；目标异常状态成功写入记为成功 | `action_id, vendor_id, game_id, product_id, sku_id, source_type, exception_id, exception_type, exception_action, supply_status, result, failure_type, operator_role` |

#### 4.1.3 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| `action_id` | string／是 | 一次配置、同步、状态或异常动作的去重标识 | `act_20260901_00001` |
| `vendor_id` | string／是 | 厂商唯一标识 | `vendor_10001` |
| `game_id` | string／是 | 游戏项目唯一标识 | `game_40001` |
| `product_id` | string／条件必填 | 平台商品唯一标识；仅 `cdkey_product_config_result` 同时满足 `config_action=create_product` 且 `result=failure` 时可空，其余已存在对象或成功结果均必填 | `product_60001` |
| `sku_id` | string／否 | SKU 唯一标识；首次创建商品且尚无 SKU 时为空 | `sku_70001` |
| `config_action` | enum／是 | 商品／SKU 配置动作 | `create_product`＝创建商品；`edit_product`＝编辑商品；`invalidate_product`＝使商品失效；`create_sku`＝创建 SKU；`edit_sku`＝编辑 SKU；`invalidate_sku`＝使 SKU 失效 |
| `source_type` | enum／是 | 供应来源类型 | `supplier_api`＝供应商 API；`controlled_direct`＝平台批准的受控直接供给 |
| `link_action` | enum／是 | 来源关系动作 | `link_source`＝首次关联；`change_source`＝停售后变更；`unlink_source`＝解除关系 |
| `supply_status` | enum／是 | 归一供给状态 | `pending_link`＝待关联；`available`＝可供货；`low`＝来源明确返回库存不足；`sold_out`＝售罄；`abnormal`＝来源异常；`unknown`＝无法可靠判断 |
| `sale_action` | enum／是 | 销售状态动作 | `publish`＝发布可售；`stop_sale`＝停止新增销售；`resume_sale`＝确认恢复可售 |
| `sale_status` | enum／是 | 动作后的销售状态 | `unavailable`＝不可售；`saleable`＝可售；`stopped`＝停售 |
| `exception_id` | string／是 | 供给异常唯一标识 | `incident_80001` |
| `exception_type` | enum／是 | 异常分类 | `stock_low`＝库存不足；`stock_out`＝售罄；`price_invalid`＝价格无效；`source_unavailable`＝来源不可用；`mapping_invalid`＝来源映射失效；`commercial_gate_invalid`＝商业门禁失效 |
| `exception_action` | enum／是 | 异常状态动作 | `detected`＝首次发现；`recovery_ready`＝进入待恢复确认；`recovered`＝运营确认恢复 |
| `result` | enum／是 | 业务动作处理结果 | `success`＝目标状态或版本写入成功；`failure`＝未写入目标结果 |
| `failure_type` | enum／是 | 失败分类；成功时传 `none` | `none`＝无失败；`permission_denied`＝无权限；`validation_failed`＝字段校验失败；`state_conflict`＝状态或并发冲突；`source_unavailable`＝供应来源不可用；`business_gate_blocked`＝发布门禁未通过；`service_error`＝平台服务失败 |
| `operator_role` | enum／是 | 执行动作的角色；系统事件无人工操作时使用 system | `platform_ops`＝平台发行运营；`system`＝平台同步或异常任务 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容 | 开发者平台和运营后台支持公司当前指定的桌面浏览器；本文不新增 C 端页面或海外包购买能力。 |
| 安全 | 开发者每次读取均校验绑定厂商；供应商凭据、完整报文和 Key 明文不进入页面、导出、埋点或普通操作日志。平台运营可见供应商映射，但无 Key 明文查看能力。 |
| 数据存储 | 商品、SKU、来源关联、价格／供给快照、商业门禁、异常和操作记录保留版本关系；停售、来源切换和 SKU 失效不删除旧订单引用。 |
| 一致性 | 发布、停售、恢复和来源变更必须以提交时服务端状态完成完整校验；失败不产生部分可售、半生效来源或重复异常终态。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 平台发行运营建立商品和 SKU、选择销售地区、关联供应来源、执行可售校验及发布；供应异常后停止新增销售，来源恢复后人工确认。 |
| 内容／资料 | 开发者提供游戏和商务协作资料；运营使用游戏已批准快照及线下已确认的授权、地区、定价或领取条件、分成和结算责任，不在商品页补造未确认资料。 |
| 上线协同／推广 | 商品可售后才可进入面向新用户的详情购买和精准投放；停售或无可售 SKU 时停止新增购买曝光及关联投放，旧订单继续按既有规则处理。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 正式可售前必须明确价格或领取条件、分成及结算责任；本文只记录门禁结果，不建设自动结算、税务、发票、复杂分账或提款。 |
| 法务 | 发行授权须在有效期内，销售地区不得超出授权地区，合同合作范围须覆盖游戏及 CDKEY 发行；失效后停止新增销售。 |
| 版权 | 厂商须拥有游戏发行及相关商品信息的合法授权；平台资料审核不替代厂商责任，授权争议进入停售处置。 |
| 其他合规 | Key、供应商凭据和合同敏感内容按最小权限处理；开发者不得访问其他厂商、供应商敏感信息或用户个人订单。 |
