## 二、背景与目标

盖世手机用户通过云游戏、Steam登录下载或自己导入游戏，希望使用指定进度，又不丢失原存档。现有页面未区分运行环境、兼容信息和覆盖风险，文件定位失败时也缺少移动端处理说明。

本次在现有免费存档页面补充适用环境、文件定位、备份恢复与审核。游戏名称、封面可以识别，版本、DLC及MOD不能据此推断；不要求用户填写自己不知道的信息。云游戏处理云运行环境中的用户存档，Steam登录下载和自己导入处理手机上对应运行环境的存档。

## 三、故事介绍

### 3\.1 用户与运营场景

- **使用者**：在游戏详情“存档”tab查看当前环境可用的共享存档，退出游戏、确认同步影响并备份后应用，再进入游戏核对进度。
- **分享者**：在“我的存档”选择或定位文件，填写标题、描述后提交审核；运营验证适用环境后上架。

### 3\.2 价值分析

免费使用指定进度，并在替换前保留原进度；无法自动定位时通过手机系统选择器授权文件。玩家提交补充官方存档，后台验证后公开。

### 3\.3 核心体验路径

![移动端存档使用与恢复流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@f223221f21b7ea7044b3315c7cf9a4008110629e/public/prd/cloud-save-mobile-20261027/00-flow.png)

- **使用者核心链路**：游戏详情页“存档”tab → 按当前游戏及已验证环境浏览 → 查看要求 → 退出游戏并核对云同步 → 确认使用 → 自动备份原进度 → 备份成功后替换 → 进入游戏核对进度

- **分享者核心链路**：我的页 → 我的存档 → 发布存档 → 定位或选择文件 → 填写信息 → 提交待审核 → 运营验证适用环境 → 上架

- **运营核心链路**：后台存档管理 → 新建或编辑存档 → 上传文件及配置 → 逐环境验证并填写测试说明 → 上架 → 管理下架

### 3\.4 产品指标预测

1. 存档浏览→详情点击率：首月持续观察并建立基线

2. 存档应用成功率：目标 \> 95%，只衡量写入完成，不代表游戏内读档成功

3. 首批覆盖：Top 20游戏，每游戏2\-3个官方存档

4. 玩家上传：首月观察玩家发布存档数量并建立基线

### 3\.5 路径规划

- **V1\.0（当前）**：跑通官方与玩家存档审核上架\+免费浏览\+备份后使用与恢复

#### 适用环境与兼容信息

运行环境分为“云游戏 / Steam登录下载 / 自己导入”，取当前启动方式；Demo外部切换仅用于评审。游戏名、封面和来源不能证明存档格式、版本、DLC或MOD兼容。广场先按当前游戏及后台已验证的适用环境过滤，再应用时间、搜索和排序；适用环境未配置或未验证的存档不公开。

详情显示作者已知要求；游戏版本缺失显示“未确认”，DLC／MOD要求缺失显示“作者未说明”。版本未知允许继续查看，在使用前保留“兼容性未确认”提示，不要求用户猜测填写。若已知不匹配则不能应用；仅环境验证通过也不能保证当前版本可读。切换运行环境后重新过滤，使用和恢复操作提交前再次校验对象与环境，不能沿用上一环境的确认结果。

#### 使用存档：覆盖、备份与云同步

![移动端使用确认](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@f223221f21b7ea7044b3315c7cf9a4008110629e/public/prd/cloud-save-mobile-20261027/13-use-confirm.png)

主页面、已使用存档与游戏中入口遵循同一检查顺序。云游戏保护云运行环境中的用户原档；手机端保护对应游戏运行环境的原档。

| 条件／步骤 | 展示与处理 |
|---|---|
| 游戏仍在运行 | 提示先保存并退出游戏，退出完成后再使用或恢复；不在运行中替换。 |
| 目标位置或权限未确认 | 提示重试定位或重新授权，只访问系统选择器授权范围；仍无法定位目标则不覆盖。选到一个源文件不代表已找到目标位置。 |
| 云同步未确认或存在冲突 | 阻止覆盖和恢复，先核对本地／云端进度与时间并处理冲突，不能一律选择本地。暂停同步须能确认生效；恢复同步前仍需核对上传方向。 |
| 同步已暂停并确认，或云运行环境可控 | 展示该环境的覆盖影响后继续。Steam或盖世云同步后续仍可能上传替换后的进度；不承诺云端永远不变。 |
| 有原存档 | 确认框说明将自动备份当前环境进度、备份成功后替换及已知同步影响；用户点击“备份并使用”后自动备份，成功才替换。备份失败提示“备份失败”，原进度不变；取消不执行备份或替换。 |
| 无原存档 | 明确显示“当前环境没有原存档，无需备份，将写入这份存档”，确认按钮为“使用”；目标位置和同步检查仍须通过。不能把未找到或无权限当作没有原档。 |
| 应用完成 | 记录进入“我的存档”，显示“存档已应用，请进入游戏检查”；应用成功不等于游戏验证成功。下载或写入失败不破坏原档，可重试；应用失败若已生成备份，该备份仍保留在“已备份”。 |
| 恢复备份 | 从“已备份”选择当前游戏及相同环境的备份；确认框说明将先保护当前进度，用户点击“备份并恢复”后自动备份，成功才恢复所选备份；无当前原档则明确无需备份。失败不覆盖，成功显示“备份已恢复，请进入游戏检查”。 |

**备份范围**：备份记录独立于普通本地存档4个名额；云游戏备份位于云环境，不声称保存在手机。存储位置、保留数量／时长、跨设备是否可见及生产恢复能力待研发确认；缺少可靠备份能力时，有原档的使用与恢复不能开放覆盖。

**Demo边界**：外部场景控件模拟正常、未找到、无原档、权限不足、空间不足、备份失败、应用失败及同步暂停／冲突／未确认／可控云环境。浏览器文件选择只演示授权选择流程，备份、恢复和云同步均为示例状态，不证明手机或云端真实文件已处理。

## 六、埋点需求

数据结论：改造存档使用与提交埋点的成功定义，保留现有事件ID及参数。应用成功以目标文件写入完成为准，提交成功以服务端接收并生成待审核记录为准；均不代表游戏读档成功或已公开上架。成功事件按同一操作任务去重，重试成功只记一次，取消、失败及未知不报成功。

## 七、运营需求
