## 二、背景与目标

盖世手机用户通过云游戏、Steam登录下载或自己导入游戏，希望使用指定进度，又不丢失原存档。现有页面未区分运行环境、兼容信息和覆盖风险，文件定位失败时也缺少移动端处理说明。

本次在现有免费存档页面补充适用环境、文件定位、备份恢复与发布后管理，跨游戏存档统一在搜索页“存档”Tab展示，首页沿用推荐及搜索入口；游戏详情仅管理当前游戏存档。Steam登录下载按当前游戏实际安装版本匹配存档记录的适用版本后展示；云游戏和自己导入按提交环境及兼容信息核对。游戏名称、封面不能证明版本、DLC或MOD兼容，不要求用户填写自己不知道的信息。云游戏处理云运行环境中的用户存档，Steam登录下载和自己导入处理手机上对应运行环境的存档。

## 三、故事介绍

### 3\.1 用户与运营场景

- **使用者**：从首页搜索入口进入搜索页，在“存档”Tab跨游戏查找存档；进入详情后退出游戏、确认同步影响并备份后应用，再进入游戏核对进度。游戏详情“存档”tab仍可直接进入该游戏。
- **分享者**：在“我的存档”选择或定位文件，填写标题、描述后发布；标题、内容描述及非空手填版本号通过敏感词检测即公开，运营在发布后测试或处理举报。

### 3\.2 价值分析

免费使用指定进度，并在替换前保留原进度；无法自动定位时通过手机系统选择器授权文件。玩家提交补充官方存档，标题、描述及非空手填版本号通过敏感词检测后直接公开。

### 3\.3 核心体验路径

![移动端存档使用与恢复流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@f85698eea1faa1353b6c7dc5e392ac0761d5042d/public/prd/cloud-save-multigame-20261027/00-flow.png)

- **使用者核心链路**：首页搜索入口 → 搜索页“存档”Tab→ 按当前环境筛选（Steam同时匹配实际安装版本）→ 查看详情要求 → 退出游戏并核对云同步 → 确认使用 → 自动备份原进度 → 备份成功后替换 → 用户手动启动游戏核对进度

- **分享者核心链路**：游戏详情“存档”Tab → 我的存档 → 发布存档 → 定位或选择文件 → 填写信息 → 标题、描述及非空手填版本号敏感词检测 → 通过后直接发布。未完成时可保存发布草稿，继续编辑后仍须通过提交校验。

- **运营核心链路**：后台存档管理 → 查看已发布存档或举报 → 下载对应游戏及原始存档 → 测试并记录结果 → 有问题时填写原因下架 → 通知作者

### 3\.4 产品指标预测

1. 存档浏览→详情点击率：首月持续观察并建立基线

2. 存档应用成功率：目标 \> 95%，只衡量写入完成，不代表游戏内读档成功

3. 首批覆盖：Top 20游戏，每游戏2\-3个官方存档

4. 玩家上传：首月观察玩家发布存档数量并建立基线

### 3\.5 路径规划

- **V1\.0（当前）**：跑通官方与玩家存档直接发布\+免费浏览\+备份后使用与恢复

#### 使用存档：覆盖、备份与云同步

主页面、已使用存档与游戏中入口遵循同一检查顺序。云游戏保护云运行环境中的用户原档；手机端保护对应游戏运行环境的原档。
