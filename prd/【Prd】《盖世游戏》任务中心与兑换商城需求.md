## 一、文档概述

### 1.1 背景概述

- **需求背景：** 盖世游戏已有“完成普通任务—获得奖励—兑换虚拟／实物商品—履约”链路，本期需更新任务中心与兑换商城的竖屏样式，并消除资产命名冲突。
- **当前方式：** 玩家在旧任务中心查看统一称为“盖世币”的任务奖励和商城余额；运营在任务配置、奖品配置、兑换与发货页面维护任务、商品和订单。
- **问题：** 旧名称与发行人计划的充值资产、发行任务结算奖励重名，用户无法直接判断余额来源、使用范围和京东卡兑换资格；旧 Demo 还存在视觉过时、横竖屏混排和远程资源依赖。
- **现有参考：** 历史方案参考 233 乐园的“任务奖励＋积分商城”促活方式；可借鉴任务反馈与商城消耗闭环，但不照搬其资产名称、页面层级或活动规则。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 改造盖世游戏 App 竖屏任务中心、积分明细、兑换商城、兑换确认、兑换记录、地址／物流和规则页；同步现有任务与兑换后台字段。不改横屏，不新增一级入口。 |
| 业务边界 | 普通任务只产出盖世积分；本商城只消耗盖世积分并保留虚拟权益、实物商品和履约。不支持积分与盖世币互换，不在本商城展示京东卡。 |
| 运营边界 | 运营继续配置普通任务、虚拟／实物商品、库存、限兑和上下架，并处理实物发货及异常订单；不重复建设发行人计划京东卡后台。 |
| 人力边界 | 产品定义规则；UI 提供最终视觉；H5／服务端实现页面与接口；账务、任务、商城和履约服务提供数据；测试覆盖主链路与异常；运营维护配置。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 盖世积分 | Gaishi Point | 用户完成任务中心普通任务获得的奖励，只能用于本需求的兑换商城，不可兑换京东卡。`GAISHI_POINT` 为建议账务标识。 |
| 盖世币 | Gaishi Coin | 发行人计划使用的资产名称；充值所得用于发行任务预算，发行任务结算所得可在发行人计划兑换京东电子卡。`GAISHI_COIN` 为建议账务标识。 |
| 兑换商城 | Points Store | 本 PRD 中指只展示并消耗盖世积分的任务中心商城，不含发行人计划京东卡商品。 |
| 虚拟权益 | Virtual Benefit | 兑换成功后由系统直接发放到账号的时长、装扮或其他数字权益。 |
| 实物商品 | Physical Product | 兑换后需用户填写地址，并由运营发货和同步物流的商品。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 为盖世游戏玩家提供“普通任务—盖世积分—兑换商城—虚拟／实物履约”闭环，并与发行人计划盖世币隔离。 |
| 目标用户 | 完成普通任务并兑换商品的玩家；配置任务、商品和订单的运营；查询异常的客服与审计人员。 |
| 核心目标 | 统一任务中心资产认知，保留现有兑换及履约能力，更新为可离线运行、可操作的 GameHub 竖屏 Demo。 |
| 使用场景 | 玩家查看任务、领取积分、浏览商城、兑换权益或实物、填写地址和查询物流；运营配置任务与商品并处理发货。 |
| 功能概述 | C 端包含任务中心、积分明细、兑换商城、兑换确认、兑换记录与规则；B 端包含任务配置、奖品配置、兑换与发货。 |

#### 资产与商城关系

| 资产 | 账务来源 | 可用范围 | 京东卡资格 |
|---|---|---|---|
| 盖世积分 | 普通任务奖励；建议标识 `GAISHI_POINT` | 任务中心兑换商城的虚拟权益和实物商品 | 不可兑换 |
| 充值盖世币 | 用户付费充值；建议来源 `RECHARGE` | 创建或追加发行任务预算 | 不可兑换 |
| 发行任务奖励盖世币 | 参与发行任务并完成结算；建议来源 `PUBLISHER_REWARD` | 发行人计划中的消费或兑换 | 可兑换 |

##### 任务状态

| 状态 | 进入／退出 | 页面表现与操作 | 失败与恢复 |
|---|---|---|---|
| 未完成 | 任务有效且进度未达标；达标后退出 | 显示“去完成” | 目标页失败不改变任务状态 |
| 可领取 | 进度达标且未领取；领取成功后退出 | 显示橙色“领取” | 请求失败恢复可点击，不入账 |
| 已完成 | 领取成功进入；当前周期结束后按任务规则退出 | 按钮置灰 | 重复请求返回原结果，不重复入账 |
| 失效／下架 | 任务被停用或超出生效时间进入 | 刷新后移出可做列表 | 未成功领取的请求不入账 |
