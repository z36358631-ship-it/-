## 一、文档概述

### 1.1 背景概述

- **需求背景：** 发行人计划需要让实名发布者快速发起推广任务，让认证创作者提交外站作品并获得盖世币奖励，同时支持分批开放和异常止损。
- **当前方式：** 任务发布和投稿依赖人工审核，数据抓取、金额确认和异常处置边界不完整；功能也缺少总开关和稳定灰度。旧钱包存在现金提现语义，且未区分充值和发行任务奖励来源。
- **问题：** 人工逐条审核无法支撑任务量增长；抓取失败直接视为零点赞会误伤创作者；人工可改金额会造成账务风险；功能全量开放时缺少稳定放量和快速停止新曝光能力。
- **现有产品与参考：** 本期复用现有发行人任务、钱包、充值、兑换商城、奖品配置和兑换订单结构。竞品判断仅参考本地已有的 233 乐园发行人计划和积分商城资料，外部页面未做实时核验，不将未核验内容作为规则依据。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 涉及盖世游戏 App“我的－社区”个人中心中的发行人计划入口，以及找任务、玩法说明、任务详情、做任务、提交投稿、创建发行任务、钱包、充值和兑换商城；涉及运营后台的数据看板、任务管理、任务审核、视频审核、结算管理、风控中心、创作者审核、京东卡管理和兑换订单。灰度配置由功能列表统一管理，导航位置复用运营后台现有配置区域。 |
| 业务边界 | 实名用户可发布任务和兑换京东卡；任务全部明确通过机器审核后自动发布，不确定结果转人工异常处理。投稿内容和数据完整获取、校验通过后进入待人工结算；最终金额由系统只读计算，运营按任务级批次人工确认。任务中心盖世积分与发行人计划盖世币分账，仅发行任务奖励来源盖世币可兑换京东卡。 |
| 灰度边界 | 功能已包含在安装包内，服务端配置控制入口，无需再次发版。本期发行人计划仅国内包开放；灰度配置按功能、包体和 App 版本区分，20%、50%时仅登录且 UID 命中可见，100%时包括未登录入口可见。仅允许扩量或关闭；总开关关闭后所有发行人计划入口隐藏，存量记录和资产保留，已受理履约继续处理。 |
| 运营边界 | 运营处理机器不确定结果、任务普通／风险下架、投稿重抓／挂起／驳回、任务级结算和专属标签定向邀请；维护功能灰度、京东卡商品、卡密库存、告警与异常订单。 |
| 人力边界 | 客户端按包体、App版本、登录状态及服务端灰度结果展示入口并承载页面；服务端负责 UID 稳定分桶、新增操作终审、存量识别、机审编排、数据校验、预算预留、只读计奖、幂等入账和资产来源；运营只处理异常和最终结算确认；测试覆盖分包分版本、登录、切号、多设备、仅扩量、关闭重开、冷启动缓存、并发与已受理履约。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 盖世积分 | GameHub Points | 用户完成任务中心普通任务获得的奖励单位；与盖世币分账，不计入盖世币总余额或京东卡可兑换余额。 |
| 盖世币 | GameHub Coins | 发行人计划的任务预算与奖励单位，可由充值或参与发行任务并结算获得；是否可兑换京东卡取决于取得来源。 |
| 盖世币总余额 | 无 | 用户账户内所有未消耗盖世币之和，包含充值、发行任务结算及其退回等来源，不包含盖世积分；钱包展示该值。 |
| 可兑换盖世币 | Redeemable Balance | 按流水来源计算、允许兑换京东电子卡的盖世币。当前只有参与发行任务并结算获得的盖世币计入；兑换只扣减该余额。 |
| 充值盖世币 | Recharge Balance | 用户付费充值获得的盖世币及由该来源冻结后退回的未消耗部分；只可用于发布或追加发行任务预算，不计入可兑换余额。 |
| 来源继承 | Source Inheritance | 任务取消、审核驳回或结算后退回预算时，每笔盖世币恢复为冻结前的来源属性，不因退回改变兑换资格。 |
| 京东电子卡 | JD E-card | 由运营采购并导入卡密的虚拟商品；用户兑换成功后系统自动分配唯一卡密，不产生实物履约。 |
| 卡密预占 | Code Reservation | 兑换请求处理中把一张未使用卡密原子绑定到唯一订单，阻止并发订单再次使用；预占不等于已向用户展示。 |
| 待核对 | Pending Review | 发放请求已执行但结果不确定，无法判断卡密是否已暴露给用户的订单状态；该状态不得自动退款或再次发卡。 |
| 实名主体 | Verified Subject | 完成实名认证的账号主体；同一实名主体按北京时间自然日最多成功提交 10 个任务。 |
| 认证创作者 | Certified Creator | 实名、社区动态不少于 5 篇且粉丝达到运营配置门槛的用户；认证通过后只获得投稿权限，不自动获得专属标签。 |
| 专属标签 | Creator Tag | 运营根据已认证创作者的后续产出定向邀请授予的独立状态，与创作者认证通过动作分离。 |
| 机器审核 | Machine Review | 对任务文字、描述、投稿要求、图片内容安全、OCR 敏感词、账号资格、当日次数和预算执行自动检查；全部明确通过才自动发布。 |
| 标准化平台内容 ID | Normalized Content ID | 从外站作品链接解析的平台内唯一内容标识，与平台一起用于投稿去重和幂等处理。 |
| 数据校验通过 | Data Validation Passed | 标题、描述、标签、发布时间、时长、点赞数等必需数据完整取得，且平台、任务规则、唯一性和风险校验均通过。 |
| 预算预留 | Budget Reservation | 投稿数据校验通过时按该任务单稿奖励上限占用预算；结算、驳回或任务结束后按实际结果释放差额。 |
| 任务期限 | Task Duration | 创建任务必选15、30、60、90或180天，默认30天；从审核通过并正式发布时起算，1天按连续24小时计算，审核等待不消耗期限。 |
| 任务截止时间 | Task Deadline | 正式发布时间＋所选期限×24小时；也是正常接收新投稿的截止点，服务端时间达到该点即不再接收。延期成功后使用新的任务截止时间。北京时间展示到分钟，判定使用服务端实际时间精度。 |
| 点赞统计截止时间 | Like Snapshot Deadline | 约定任务截止时间＋7×24小时，系统自动生成且只读；延期后自动改为新的任务截止时间＋7天。用于最终点赞快照，不等于奖励到账时间；提前结束或下架仅停止新增投稿，沿用原约定统计截止，不缩短已有投稿窗口；历史任务迁移见待确认项。 |
| 结算批次 | Settlement Batch | 以任务为单位汇总到期投稿的人工确认对象；通过任务 ID、批次 ID 和投稿 ID 保证入账幂等。 |
| 普通下架／风险下架 | Normal／Risk Takedown | 普通下架停止新增投稿，已有投稿继续结算；风险下架同时挂起未结算投稿，待风险处理。 |
| UID 灰度 | UID Rollout | 在指定包体和版本范围内，服务端按 UID 稳定选择开放用户；20%、50%时未登录隐藏入口，100%时未登录也可见。UID 选择算法由研发确定，不以设备 ID 替代 UID。 |
| 新增操作 | New Action | 发布新任务或首次参与任务。已有任务关系不等于已经受理本次操作；新提交投稿、追加预算、充值或兑换仍是用户主动发起的请求，总开关关闭后不能据此绕过前台停用。 |
| 存量关系 | Existing Relation | 服务端已有任务、参与、投稿、待发奖励、余额或订单。关闭不删除记录、不清空资产；存量关系不是总开关关闭后的入口豁免。已受理订单、奖励和外部回调继续按原业务规则处理。 |

**本轮时间兼容口径：** 用户已确认五档期限、默认30天、审核通过正式发布起算及结束后7天统计。提前结束／下架仅停止新增投稿，已有投稿保留原约定或延期后的点赞统计截止，是保护已有履约约定的边界解释，并非另一次用户确认；本轮不改变原提前终止流程。

### 2.3 灰度发布方案

本功能随 App 包发布，灰度配置只控制已具备该功能的用户是否看到入口、能否使用；调整配置无需再次发版或推送安装包。本期发行人计划仅在国内包开放，海外包保持关闭；创作者中心和任务中心仍按各自规则展示。

#### 2.3.1 账号、UID 与国内／海外分别灰度

账号是登录身份，UID 是账号在服务端的唯一标识，灰度选人使用 UID；它们不是两套独立抽样条件。同一账号在国内包与海外包共用同一UID，不新建国内UID／海外UID；换设备仍使用同一UID，换账号则按新UID判断。国内／海外属于包体归属，不能从 UID 数字、手机号或邮箱直接推断。

1. 灰度按“功能＋包体＋App 版本”配置。国内包、海外包分别设置开关与比例，各自按本包体候选 UID 计算，不把全体账号的 20% 再分摊给两个包体。发行人计划本期国内包逐步放量，海外包关闭，关闭不等于新增一个可选的 0% 档位。
2. UID 的包体归属使用服务端记录的最近一次登录包体；仅成功登录时更新该账号最近登录包体；普通冷启动或业务请求携带当前包体和App版本用于准入，不改写最近登录事实。不能通过手机号、邮箱、设备或 UID 本身推断国区。当前请求为海外包时不开放发行人计划，即使同一 UID 曾在国内包命中。
3. 服务端按 UID 稳定抽取用户，具体算法和桶值范围由研发确定；原 0～9999 方案只是参考，不作为固定实现要求。算法必须满足：同一配置范围和轮次内结果稳定、20%用户包含在50%中、关闭再按原比例开启仍是同一批用户。
4. 同 UID 在相同包体、版本规则下跨设备和重新登录结果一致；切号、切包或升级到其他版本规则后重新判断，不能复用上一账号、包体或版本的结果。内部测试白名单与正式灰度分开统计，且不能绕过本期国内包范围和总开关。

**分别配置示例（说明通用能力，不代表本期发行人开放海外）：**

| 功能范围 | 国内包设置 | 海外包设置 | 选取结果 |
|---|---|---|---|
| 两边各20%的通用场景 | 开启，20% | 开启，20% | 国内候选UID中稳定选20%，海外候选UID中另选20%；不是两个包共用全体账号20%的名额 |
| 两边不同比例的通用场景 | 开启，50% | 开启，20% | 两边分别执行各自比例，互不改变对方已命中用户 |
| 本期发行人计划 | 开启后20%→50%→100% | 关闭 | 只开放国内；海外不因国内扩量而开放 |

候选人群按同一统计快照中的最近登录包体与适用版本归属；同一UID不在同一快照重复计算。跨包登录后进入新的包体规则，不能携带旧包体结果直接通行。稳定选择算法的实际比例分布由研发提供样本验证，不用两边用户数凑一个全局配额。

#### 2.3.2 用户状态与入口

#### 2.3.3 扩量、关闭与存量

[已确认] 本节第4、5项已由用户在本轮确认：前台暂停操作，已受理后台履约继续，资产与记录保留。

1. 同一功能、包体、版本规则允许从 20% 扩至 50%、再扩至 100%，可保持原比例或关闭；不允许 50%改20%、100%改50%等缩量。后台与服务端同时拒绝降档，不能通过关闭再开启改成更低比例。
2. 关闭保留本规则已达到的比例与用户选择结果；重新开启沿用关闭前比例和同一批用户，不重新抽样。新 App 版本单独建立规则，不改变旧版本的配置，也不能用修改版本范围规避已开放规则的比例限制。
3. 已形成的任务、预算冻结／退回、参与、投稿、待发奖励、余额和兑换订单继续保存；仅浏览、打开表单或未成功提交的本地草稿不属于已受理记录。
4. 总开关用于停用用户侧功能，不自动取消任务、清空余额或废弃已受理订单。机审、取数、人工结算、已确认发奖、已受理兑换发卡／退款及外部回调继续按原规则完成并保持幂等；具体风险任务仍由运营普通下架或风险下架处理。
5. 关闭生效后，用户不能发起新的投稿、追加预算、充值或兑换，即使已持有任务关系或余额；尚未被服务端受理的表单不生成业务记录、不冻结预算、不扣币。重新开启后恢复可访问范围，历史记录和权益按原状态展示。

#### 2.3.4 拉取与缓存

1. App 每次冷启动拉取功能配置；本轮不要求每次热启动、切页面或回前台都拉取，也不要求后台关闭后实时推送消除所有已打开入口。登录、退出登录、切号、切包或 App 版本变化时重新判断当前上下文，防止缓存串用。
2. 配置请求失败、超时或返回不可用数据时，沿用相同账号状态、包体、版本最近一次成功结果，不把网络失败当作“已关闭”。从未取得有效结果或上下文改变后没有对应缓存时，默认隐藏；下次成功拉取后恢复。
3. 成功取得“关闭”或“不适用当前范围”的有效结果后，替换旧缓存并隐藏相关入口，不能继续沿用旧开启结果。缓存只是客户端展示依据，服务端仍校验当前规则与业务资格；关闭后残留页面发起请求被拒绝，不产生新增业务副作用。
4. 退出登录立即清除个人任务、钱包等账号数据；20%、50%隐藏入口，100%可显示通用入口，不展示上一账号数据。迟到的旧账号或旧版本响应不能覆盖当前上下文结果。

后台维护功能灰度列表，本期增加发行人计划规则；后续其他功能可复用列表，但不在本次创建租号、创作者中心或任务中心的新灰度业务。

|---|---|---|
| 功能、包体、App 版本 | 标识本条规则的适用范围，国内／海外独立；发行人计划海外保持关闭 | 同一功能、包体、版本不能有冲突规则；不能把不同包体的用户合成一个比例分母 |
| 总开关与比例 | 比例仅20%、50%、100%；仅扩量、保持或关闭 | 关闭保留比例，重开原档；降档、非法值或冲突保存失败，上一版保持有效 |
| 轮次、配置版本、修改人和时间 | 服务端维护与展示；轮次不可被运营随意重置 | 每次成功保存生成新配置版本，记录前后值；并发旧版本不得覆盖新版本 |

首次按20%开放，确认核心链路稳定且没有严重故障、权限绕过、资金或奖励错误后人工扩至50%、100%；出现严重问题关闭对应范围，不缩量。观察与对比须按包体、App版本、规则及配置版本拆分。研发提供稳定选择、边界、比例分布、关闭重开与分包分版本的可复现测试方法；不把原方案中的固定桶值、固定观察小时数或示例技术阈值当作会议已确认标准。

**任务状态**

| 状态 | 进入条件 | 可执行操作 | 退出与异常 |
|---|---|---|---|
| 草稿 | 用户保存未提交表单 | 查看、继续编辑、删除 | 提交成功进入机器审核中 |

| 人工异常处理 | 机器审核超时、无响应或结果不确定 | 重新检测、驳回 | 重新检测明确通过后自动发布；驳回按来源退回预算 |

| 待人工结算 | 任务内可结算投稿已形成批次 | 处理异常、确认结算 | 确认后进入已结算；无有效投稿进入已结束 |
| 审核不通过／已取消／已结算／已结束 | 对应终态条件成立 | 只读查看、必要申诉 | 不重复冻结、发布或发奖 |

**投稿状态**

| 状态 | 进入条件 | 可执行操作 | 退出与异常 |
|---|---|---|---|
| 已提交／数据抓取中 | 唯一投稿记录创建成功 | 查看 | 完整校验通过进入待人工结算；超时进入抓取重试；缺失或风险进入人工处理／风险挂起 |
| 数据校验通过，待人工结算 | 内容与必需数据完整且规则通过，已按单稿上限预留 | 查看、人工挂起、驳回 | 进入任务级结算批次后由人工确认 |
| 抓取重试 | 接口超时或数据未取全 | 重新抓取、驳回 | 成功后重算预计奖励并预留；失败时状态不变 |
| 人工处理／风险挂起 | 关键字段缺失、删除、私密、重复或命中风险 | 重新抓取、恢复、驳回 | 风险挂起继续占用预留；驳回释放预留；不得按 0 点赞结算 |

**奖励与预算规则**

| 项目 | 公式／规则 |
|---|---|
| 预计奖励 | 预计奖励 = min（当前点赞数 × 每赞单价，单稿奖励上限） |
| 结算奖励 | 结算奖励 = min（结算快照点赞数 × 每赞单价，单稿奖励上限） |
| 投稿预留 | 投稿数据校验通过时，系统按该任务的单稿奖励上限预留预算 |
| 结算释放 | `释放金额 = 单稿奖励上限 - 结算奖励`；驳回释放全部预留，风险挂起不释放 |

##### 卡密状态流转

| 状态 | 进入／退出 | 表现与操作 | 结果与恢复 |
|---|---|---|---|
| 未使用 | 合法且唯一的卡密导入成功，或已预占卡密确认未暴露后释放；原子预占后进入已预占，人工作废后进入作废 | 默认脱敏；可被兑换请求预占，可由有权限人员作废 | 预占失败保持未使用，不减少可用库存 |
| 已预占 | 唯一订单锁定卡密后进入；发放成功进入已发放，结果不确定进入待核对，明确失败且确认未暴露后进入未使用或作废 | 默认脱敏；只可查看绑定订单，不可再次分配 | 订单、扣币或发放明确失败时按事务结果回退；无法确认是否暴露时不得释放 |
| 已发放 | 卡密已向用户展示或核对确认已暴露后进入；无正常退出 | 默认脱敏；有权限人员可查看审计信息，不可释放或再次发放 | 终态；误操作不得回退为未使用，异常通过订单和审计处理 |
| 待核对 | 发放超时或结果不确定后进入；确认已暴露进入已发放，确认未暴露并退款后进入未使用或作废 | 默认脱敏；有权限人员核对绑定订单和暴露证据 | 不得自动退款或再次发卡；核对失败保持待核对并升级处理 |
| 作废 | 卡密格式错误、过期、泄露或人工确认不可用后进入；无正常退出 | 默认脱敏；只可查看作废原因和审计记录 | 终态；不可撤销为可用库存，误作废走人工异常流程 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 灰度准入 | 服务端按功能、国内／海外包及App版本匹配规则，再判断总开关与UID比例；本期发行人仅国内开放。20%、50%未登录隐藏，100%游客入口可见但业务仍需登录。仅扩量或关闭，关闭再开保持原比例与同批UID；算法和测试边界由研发提供，不限定0～9999。总开关关闭拒绝前台进入与操作，已受理履约和资产保留。 |
| 配置拉取与缓存 | 每次冷启动拉取；相同账号状态、包体和版本范围失败沿用最近成功结果，无有效缓存默认隐藏。切号、登录状态、包体或App版本变化重新判断；成功关闭结果必须覆盖旧开启缓存。入口收回不要求实时推送；服务端动作终审仍按当前有效规则拦截。 |
| 实名与限次 | 发布任务与兑换均要求实名认证。入口未实名时拉起实名认证弹窗，成功后只恢复原动作；任务提交与兑换接口再次校验。发布任务按实名主体聚合，北京时间自然日最多成功提交 10 次；次数计数、任务创建和预算冻结需幂等。投稿另校验创作者认证，认证与专属标签分离。 |
| 任务机审 | 保存文字、图片内容安全、OCR、账号、次数、预算和规则版本结果；全部明确通过才自动发布。超时、无响应或不确定进入人工异常处理；取消后的审核回调不得重新上架。 |
| 任务时间 | 创建仅接收15／30／60／90／180天期限，默认30天；正式发布时由服务端计算并保存发布时间、任务截止、点赞统计截止，1天为24小时。新投稿仅在服务端受理时间早于任务截止时允许；正常统计截止固定为任务截止＋7天，延期原子更新两个截止，追加预算和重复回调不重置时间。客户端只读日期不能覆盖服务端结果；提前终止仅记录停止接收时间，已有投稿的约定统计截止不变；历史任务迁移按待确认项核对。 |
| 外站取数 | 保存平台、标准化内容 ID、原链接、标题、描述、标准化话题、发布时间、时长、点赞数、抓取时间、任务提交时间快照、校验结果和证据版本。必须同时包含实际推广游戏话题和“盖世游戏”话题，且作品发布时间不早于任务提交时间；缺话题、时间过早、抓取失败、字段缺失、删除、私密、重复或风险均不得生成正常结算结果。 |
