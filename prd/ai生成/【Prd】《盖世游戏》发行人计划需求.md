## 一、文档概述

### 1.1 背景概述

- **需求背景：** 发行人计划需要让实名发布者快速发起推广任务，让认证创作者提交外站作品并获得盖世币奖励，同时支持分批开放和异常止损。
- **当前方式：** 任务发布和投稿依赖人工审核，数据抓取、金额确认和异常处置边界不完整；功能也缺少总开关和稳定灰度。旧钱包存在现金提现语义，且未区分充值和发行任务奖励来源。
- **问题：** 人工逐条审核无法支撑任务量增长；抓取失败直接视为零点赞会误伤创作者；人工可改金额会造成账务风险；功能全量开放时缺少稳定放量和快速停止新曝光能力。
- **现有产品与参考：** 本期复用现有发行人任务、钱包、充值、兑换商城、奖品配置和兑换订单结构。竞品判断仅参考本地已有的 233 乐园发行人计划和积分商城资料，外部页面未做实时核验，不将未核验内容作为规则依据。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 涉及盖世游戏 App 发行人计划的找任务、玩法说明、任务详情、做任务、提交投稿、创建发行任务、钱包、充值和兑换商城；涉及运营后台的数据看板、任务管理、任务审核、视频审核、结算管理、风控中心、创作者审核、京东卡管理和兑换订单。不新增一级导航。 |
| 业务边界 | 实名用户可发布任务和兑换京东卡；任务全部明确通过机器审核后自动发布，不确定结果转人工异常处理。投稿内容和数据完整获取、校验通过后进入待人工结算；最终金额由系统只读计算，运营按任务级批次人工确认。任务中心盖世积分与发行人计划盖世币分账，仅发行任务奖励来源盖世币可兑换京东卡。 |
| 灰度边界 | 功能总开关控制发行人计划的新曝光和新参与，比例仅支持 20%、50%、100%；灰度对象是功能准入，不是投稿作品外部发布。关闭或缩量不影响已发布任务、已投稿内容和待结算记录。 |
| 运营边界 | 运营处理机器不确定结果、任务普通／风险下架、投稿重抓／挂起／驳回、任务级结算和专属标签定向邀请；维护功能灰度、京东卡商品、卡密库存、告警与异常订单。 |
| 人力边界 | 客户端按服务端灰度结果展示入口并承载页面；服务端负责稳定分桶、机审编排、数据校验、预算预留、只读计奖、幂等入账和资产来源；运营只处理异常和最终结算确认；测试覆盖状态、并发、异常恢复和存量履约。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 盖世积分 | GameHub Points | 用户完成任务中心普通任务获得的奖励单位；与盖世币分账，不计入盖世币总余额或京东卡可兑换余额。 |
| 盖世币 | GameHub Coins | 发行人计划的任务预算与奖励单位，可由充值或参与发行任务并结算获得；是否可兑换京东卡取决于取得来源。 |
| 盖世币总余额 | 无 | 用户账户内所有未消耗盖世币之和，包含充值、发行任务结算及其退回等来源，不包含盖世积分；钱包展示该值。 |
| 可兑换盖世币 | Redeemable Balance | 按流水来源计算、允许兑换京东电子卡的盖世币。当前只有参与发行任务并结算获得的盖世币计入；兑换只扣减该余额。 |
| 充值盖世币 | Recharge Balance | 用户付费充值获得的盖世币及由该来源冻结后退回的未消耗部分；只可用于发布或追加发行任务预算，不计入可兑换余额。 |
| 来源继承 | Source Inheritance | 任务取消、审核驳回或结算后退回预算时，每笔盖世币恢复为冻结前的来源属性，不因退回改变兑换资格。 |
| 京东电子卡 | JD E-card | 由运营采购并导入卡密的虚拟商品；用户兑换成功后系统自动分配唯一卡密，不产生实物履约。 |
| 卡密预占 | Code Reservation | 兑换请求处理中把一张未使用卡密原子绑定到唯一订单，阻止并发订单再次使用；预占不等于已向用户展示。 |
| 待核对 | Pending Review | 发放请求已执行但结果不确定，无法判断卡密是否已暴露给用户的订单状态；该状态不得自动退款或再次发卡。 |
| 实名主体 | Verified Subject | 完成实名认证的账号主体；同一实名主体按北京时间自然日最多成功提交 10 个任务。 |
| 认证创作者 | Certified Creator | 实名、社区动态不少于 5 篇且粉丝达到运营配置门槛的用户；认证通过后只获得投稿权限，不自动获得专属标签。 |
| 专属标签 | Creator Tag | 运营根据已认证创作者的后续产出定向邀请授予的独立状态，与创作者认证通过动作分离。 |
| 机器审核 | Machine Review | 对任务文字、描述、投稿要求、图片内容安全、OCR 敏感词、账号资格、当日次数和预算执行自动检查；全部明确通过才自动发布。 |
| 标准化平台内容 ID | Normalized Content ID | 从外站作品链接解析的平台内唯一内容标识，与平台一起用于投稿去重和幂等处理。 |
| 数据校验通过 | Data Validation Passed | 标题、描述、标签、发布时间、时长、点赞数等必需数据完整取得，且平台、任务规则、唯一性和风险校验均通过。 |
| 预算预留 | Budget Reservation | 投稿数据校验通过时按该任务单稿奖励上限占用预算；结算、驳回或任务结束后按实际结果释放差额。 |
| 点赞统计截止时间 | Like Snapshot Deadline | 任务结算使用的最终点赞数据快照截止点，必须晚于投稿截止时间。 |
| 结算批次 | Settlement Batch | 以任务为单位汇总到期投稿的人工确认对象；通过任务 ID、批次 ID 和投稿 ID 保证入账幂等。 |
| 普通下架／风险下架 | Normal／Risk Takedown | 普通下架停止新增投稿，已有投稿继续结算；风险下架同时挂起未结算投稿，待风险处理。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 用机器审核和自动取数承接高频处理，用系统公式与任务级人工确认控制最终发奖，并通过稳定灰度分批开放；资产仍按盖世积分、充值盖世币和发行任务奖励盖世币分账。 |
| 目标用户 | 发布推广任务的实名用户；提交外站作品的认证创作者；处理异常、结算、灰度、商品和订单的运营人员。 |
| 核心目标 | 机器审核明确通过后自动发布；完整数据校验通过后自动进入待人工结算；最终发奖由运营确认但金额不可修改；功能可按 20%／50%／100% 稳定放量并保护存量履约。 |
| 使用场景 | 发布者创建任务并冻结预算；创作者提交作品链接；系统抓取数据、预留预算；运营处理异常并确认结算；创作者收到盖世币后兑换京东卡。 |
| 功能概述 | C 端增加任务机审、投稿自动取数、预计奖励、预算预留、新操作灰度准入和发布／兑换实名认证门槛；实名认证成功后只恢复原动作，不自动提交任务、不自动兑换或扣减盖世币。B 端把常规人工审核改为机器记录与异常处理，增加任务级人工结算、认证与标签分离、功能外放设置。 |

### 2.2 产品流程

![产品流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@5bb4b32eaa6ece410627dd25a4f4040ed03f97a1/public/prd/publisher-plan-v2/00-product-flow.png)

*产品流程：1 实名后创建任务 → 2 配置图片与奖励 → 3 机器审核通过后自动发布 → 4 已实名且已认证创作者查看任务 → 5 提交外站作品链接 → 6 系统抓取数据、校验并按单稿上限预留预算 → 7 运营按任务级批次人工确认系统计算结果 → 8 发行任务奖励盖世币到账。异常任务、投稿和结算进入人工处置，不默认放行或按 0 点赞结算。*

#### 3.1.4 做任务

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 管理用户参与和发布的发行人任务，查看审核、结算和任务状态。 |

| 状态 | 进入条件 | 可执行操作 | 退出与异常 |
|---|---|---|---|
| 已提交／数据抓取中 | 唯一投稿记录创建成功 | 查看 | 完整校验通过进入待人工结算；超时进入抓取重试；缺失或风险进入人工处理／风险挂起 |

| 抓取重试 | 接口超时或数据未取全 | 重新抓取、驳回 | 成功后重算预计奖励并预留；失败时状态不变 |
| 人工处理／风险挂起 | 关键字段缺失、删除、私密、重复或命中风险 | 重新抓取、恢复、驳回 | 风险挂起继续占用预留；驳回释放预留；不得按 0 点赞结算 |

**奖励与预算规则**

| 项目 | 公式／规则 |
|---|---|
| 预计奖励 | 预计奖励 = min（当前点赞数 × 每赞单价，单稿奖励上限） |
| 结算奖励 | 结算奖励 = min（结算快照点赞数 × 每赞单价，单稿奖励上限） |
| 投稿预留 | 投稿数据校验通过时，系统按该任务的单稿奖励上限预留预算 |
| 结算释放 | `释放金额 = 单稿奖励上限 - 结算奖励`；驳回释放全部预留，风险挂起不释放 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 灰度准入 | 服务端为最终判定方；登录用户使用 `account_id`，未登录使用稳定 `installation_id`，按固定 `rollout_seed` 计算 0～99 桶值。同一轮次结果稳定，20% 扩至 50% 时原命中用户继续命中。配置读取失败或非法时拒绝新曝光；已有关系继续履约。 |
| 实名与限次 | 发布任务与兑换均要求实名认证。入口未实名时拉起实名认证弹窗，成功后只恢复原动作；任务提交与兑换接口再次校验。发布任务按实名主体聚合，北京时间自然日最多成功提交 10 次；次数计数、任务创建和预算冻结需幂等。投稿另校验创作者认证，认证与专属标签分离。 |
| 任务机审 | 保存文字、图片内容安全、OCR、账号、次数、预算和规则版本结果；全部明确通过才自动发布。超时、无响应或不确定进入人工异常处理；取消后的审核回调不得重新上架。 |
| 外站取数 | 保存平台、标准化内容 ID、原链接、标题、描述、标签、发布时间、时长、点赞数、抓取时间、校验结果和证据版本。抓取失败、字段缺失、删除、私密、重复或风险不得生成正常结算结果。 |
| 预算与结算 | 数据校验通过时按单稿上限预留；最终金额由结算快照、每赞单价和单稿上限计算，前端与后台只读。以任务 ID＋结算批次＋投稿 ID 保证人工确认和盖世币入账幂等，释放差额和原来源可追溯。 |
| 操作审计 | 记录机审异常处理、重新抓取、挂起、恢复、驳回、普通／风险下架、认证、标签邀请、灰度保存和结算确认的操作人、时间、前后状态、规则或配置版本。 |
| 安全 | 卡密加密存储和传输，页面、普通日志、报表、下载文件默认脱敏；脱敏时只显示末 4 位，其余以 `*` 替代，长度不超过 4 位时全部隐藏。完整卡密只在授权查看或用户主动查看时短时返回，查看、复制、作废、核对均写不可删除的审计记录。 |
| 一致性 | 兑换使用幂等请求；唯一卡密预占、可兑换余额扣减和订单创建必须形成可恢复的一致操作。同一请求只产生一笔扣减、一个订单和一张卡；并发抢最后一张卡只有一个成功结果。 |
| 异常恢复 | 明确失败且卡密未暴露时幂等退回；发放结果不确定时保持卡密、扣减和订单绑定并进入待核对，不得自动退款或再次发卡。客户端刷新、重登或超时后按订单号恢复结果。 |
| 数据存储 | 盖世积分与盖世币分别维护余额和流水；盖世币流水保存充值或发行任务奖励来源及原流水关联。商品与订单保存下单快照；卡密状态、绑定订单、查看记录和异常处理全程可追溯。存储期限按财务、法务和安全确认结果执行。 |
| 库存告警 | 可用库存只统计未使用、未预占、未发放、未作废的卡密；导入、预占、发放、释放、作废、上下架或保存设置后，重新判断受影响的已上架 SKU。每个 SKU 独立保存低库存状态、上次提醒时间和下次允许提醒时间；持续低库存按重复提醒间隔去重并定时复查，恢复到阈值以上后重置。 |
| Webhook 安全 | Webhook 服务端加密保存，接口响应和页面均脱敏，仅库存告警配置权限可查看或修改，完整地址不进入普通日志。发送结果按 SKU 和目标地址写既有操作日志但不记录密钥；发送失败在下一次允许提醒时重试，不参与或阻断兑换、发卡、卡密入库事务。 |
| 配置迁移 | 商品数据停止新增或编辑 SKU 级阈值。真实线上旧 SKU 阈值不一致时，启用全局告警前由运营确认唯一全局值，不取平均值或静默覆盖；旧值只作历史审计，不参与新告警计算。 |
| 兼容 | 复用当前发行人计划支持的 App 版本与横竖屏容器；旧版本没有兑换商城入口时不影响存量任务履约，服务端仍必须执行灰度、新动作资格和资产来源校验。 |

### 4.3 质量保障

| 范围 | 必测项 |
|---|---|
| 灰度 | 总开关、20%／50%／100%、同主体稳定、20% 扩 50% 包含关系、100% 全量、配置失败关闭新曝光、缩量后存量继续 |
| 发布 | 未实名入口弹窗、认证成功进入创建页但不自动提交、最终提交二次实名校验、日 10 次、预算 5,000～10,000,000、图片与 OCR、明确通过自动发布、明确拒绝退回、不确定转人工、审核中取消和重复提交幂等 |
| 投稿 | 双认证、平台域名、内容 ID 去重、完整取数自动进入待人工结算、按单稿上限预留、超时重试、删除／私密／风险挂起、预算不足 |
| 结算 | 任务级批次、系统金额只读、人工确认、风险拦截、重抓重算、驳回释放、差额释放、重复确认不重复入账 |
| 回归 | 钱包来源、固定充值 SKU、兑换未实名弹窗、认证成功仅恢复确认、最终兑换二次实名校验、京东卡与卡密、普通／风险下架、认证与专属标签分离、旧版本存量访问 |

### 4.4 运营需求

| 需求项 | 具体要求 |
|---|---|
| 功能外放 | 运营手动设置功能总开关和 20%／50%／100% 比例，按配置版本观察主链路与错误指标；严重异常时关闭新曝光，存量任务继续履约。 |
| 审核与结算 | 运营只处理机审不确定任务、取数异常和风险投稿；最终按任务级批次确认系统计算金额，不得修改点赞、单价、单稿上限、创作者、来源或金额。高金额是否双人复核见待确认项。 |
| 运营配置 | 维护创作者粉丝门槛、外站平台、重试策略、固定充值 SKU、京东卡商品和库存告警。真实线上旧 SKU 阈值不一致时，启用前确认唯一全局值，不取平均值或静默覆盖。 |
| 内容／素材 | 准备经授权的京东卡卡面、盖世积分／盖世币区分说明、兑换规则、使用说明、有效期说明、客服口径和异常订单处理口径；禁止承诺未由京东或采购合同确认的权益。 |
| 库存与异常 | 上架前导入足量合法卡密并核对批次；收到 SKU 低库存提醒后补充库存或下架商品，并通过既有操作日志核对发送失败。每日处理待核对和三账差异，不得以补发或退款绕过核对；不新增独立告警中心。 |

## 五、待确认项

| 待确认问题 | 默认建议 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 正式支持的外站平台及各平台内容／数据接口 | 首期只开放已完成授权、可稳定取得标题、描述、标签、发布时间、时长和点赞数的平台 | 影响可投稿平台、抓取成功率、重试与证据留存 | 阻塞对应平台上线 |
| 文字、图片内容安全、OCR 服务及超时重试次数 | 复用既有内容安全服务；按服务能力设置有限重试，仍不确定转人工异常处理 | 影响任务自动发布率、超时与误判处理 | 阻塞机审上线 |
| 创作者粉丝门槛初值 | 社区动态不少于 5 篇固定；粉丝门槛由运营在正式上线前确认并可配置 | 影响创作者准入范围和测试数据 | 阻塞认证规则上线 |
| 高金额结算是否双人复核及阈值 | 先按单批次系统金额设置可配置阈值，超过后需两名不同权限人员确认 | 影响结算权限、状态和审计 | 阻塞高金额发奖 |
| 正式充值 SKU | 运营与财务确认档位、实付金额、上下架和退款口径；不提供用户自定义金额 | 影响充值页数据和支付用例 | 阻塞充值上线 |
| 混合来源余额用于任务预算时，先扣哪一类盖世币 | 建议先扣不可兑换的充值来源，再扣可兑换的任务结算来源；冻结明细逐笔记录，退回逐笔继承来源，可减少用户误用可兑换奖励 | 影响创建任务、追加预算、取消、驳回、结算退回和钱包流水；不确认会导致来源扣减与用户预期不一致 | 阻塞预算来源开发 |

| 正式卡面额、所需盖世币、单用户限兑和使用说明 | 运营根据采购成本、库存和经济模型确认；Demo 示例不得直接作为正式配置 | 影响正式商品数据、测试用例和用户规则 | 阻塞上线 |
| 卡密批量导入的单次数量上限 | 研发完成解析、校验和入库压测后给出可配置上限；页面显示当前限制并在上传前拦截 | 影响大批次导入效率和边界测试，不影响字段及状态开发 | 阻塞上线，不阻塞页面开发 |
