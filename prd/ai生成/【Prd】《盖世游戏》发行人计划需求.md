## 一、文档概述

### 1.1 背景概述

- **需求背景：** 发行人计划使用盖世币承载发布者的任务预算和创作者的任务奖励。运营要求创作者奖励不再直接兑换现金，改为自主兑换京东电子卡。
- **当前方式：** 发布者充值盖世币后创建推广任务；创作者提交外站作品并通过审核、结算后获得盖世币。V1 钱包把盖世币换算为人民币并提供提现，未区分充值和任务奖励来源。
- **问题：** 如果只把提现入口改成京东卡兑换，充值所得盖世币也可能进入兑换链路，形成“充值盖世币—兑换京东卡”的近现金通道；现有后台也缺少京东卡商品、卡密库存、兑换订单和异常核对能力。
- **现有产品与参考：** 本期复用现有发行人任务、钱包、充值、兑换商城、奖品配置和兑换订单结构。竞品判断仅参考本地已有的 233 乐园发行人计划和积分商城资料，外部页面未做实时核验，不将未核验内容作为规则依据。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 涉及盖世游戏 App 发行人计划的找任务、玩法说明、任务详情、做任务、提交投稿、创建发行任务、钱包、充值和京东卡兑换；涉及运营后台的数据看板、任务管理、任务审核、视频审核、结算管理、风控中心、创作者审核、京东卡管理和兑换订单。不新增导航层级，不独立建设第二套发行人商城。 |
| 业务边界 | 继续统一使用“盖世币”，按流水来源计算可兑换余额；发行人任务结算所得可兑换，充值所得及其取消、驳回、结算退回部分不可兑换。只支持京东电子卡卡密自动发放，不含现金兑付、其他卡种、实体卡、配送信息、转赠、出售或回收。 |
| 运营边界 | 运营配置京东卡商品、面额、所需盖世币、限兑、上下架、库存预警和使用说明；导入与核对卡密、处理异常订单并维护审计记录。正式面额、价格、采购渠道和说明须在上线前确认。 |
| 人力边界 | 产品定义来源口径和状态；UI 复用现有 C/B 端结构补充新增状态；客户端负责 App 页面、卡密查看与复制；服务端负责余额来源、幂等兑换、卡密与订单一致性；运营负责商品和卡密；测试覆盖来源隔离、并发与异常恢复；数据负责埋点和对账看板；财务、法务负责税务、凭证、采购及协议结论。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 盖世币总余额 | 无 | 用户账户内所有未消耗盖世币之和，包含充值、发行人任务结算及其退回等来源；钱包展示该值。 |
| 可兑换盖世币 | Redeemable Balance | 按流水来源计算、允许兑换京东电子卡的盖世币。当前仅发行人任务结算给创作者的盖世币计入；兑换只扣减该余额。 |
| 充值盖世币 | Recharge Balance | 用户付费充值获得的盖世币及由该来源冻结后退回的未消耗部分；只可用于发布或追加发行任务预算，不计入可兑换余额。 |
| 来源继承 | Source Inheritance | 任务取消、审核驳回或结算后退回预算时，每笔盖世币恢复为冻结前的来源属性，不因退回改变兑换资格。 |
| 京东电子卡 | JD E-card | 由运营采购并导入卡密的虚拟商品；用户兑换成功后系统自动分配唯一卡密，不产生实物履约。 |
| 卡密预占 | Code Reservation | 兑换请求处理中把一张未使用卡密原子绑定到唯一订单，阻止并发订单再次使用；预占不等于已向用户展示。 |
| 待核对 | Pending Review | 发放请求已执行但结果不确定，无法判断卡密是否已暴露给用户的订单状态；该状态不得自动退款或再次发卡。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 在保留统一盖世币名称和现有发行人任务体系的前提下，按流水来源隔离兑换资格，并复用现有商城结构提供京东电子卡兑换、卡密自动发放和后台核对。 |
| 目标用户 | 完成发行人任务并获得盖世币的创作者；充值盖世币发布任务的发布者；负责任务、商品、卡密、订单和风险处理的运营、审核与财务人员。 |
| 核心目标 | 让符合资格的任务奖励可兑换京东电子卡，同时保证充值盖世币不可进入兑换链路；每笔兑换只扣一次、建一单、分配一卡，异常结果可恢复和审计。 |
| 使用场景 | 创作者结算后查看钱包并兑换京东卡；发布者充值、创建或追加任务预算；运营维护商品和卡密，核对发放结果不确定的订单。 |
| 功能概述 | C 端保留任务参与、发布、钱包和充值流程，钱包新增京东卡入口，兑换页只显示可兑换余额；B 端保留任务运营页面，新增京东卡商品、卡密库存和兑换订单。 |

##### 卡密状态流转

| 当前状态 | 进入条件 | 可见内容／可执行操作 | 退出事件 | 下一状态 | 失败与恢复 |
|---|---|---|---|---|---|
| 未使用 | 合法且唯一的卡密导入成功，或预占卡密确认从未暴露后释放 | 默认脱敏；可被兑换请求预占，可由有权限人员作废 | 原子预占；人工作废 | 已预占；作废 | 预占失败保持未使用，不减少可用库存 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 改造发行人钱包事件，新增京东卡兑换事件和服务端对账指标。

#### 4.1.1 指标口径

| 指标名称 | 口径（含公式、分子和分母） | 去重与时间窗口 | 数据源与决策用途 |
|---|---|---|---|
| 京东卡兑换转化率 | 已发放订单用户数 ÷ 京东卡兑换页曝光用户数 | UID 去重，按自然日、自然周和版本周期 | 埋点与订单；判断符合资格用户是否完成兑换 |
| 发放成功率 | 已发放订单数 ÷ 已有明确终态订单数；明确终态为已发放、发放失败、已退回 | 订单号去重，按订单创建日统计，每日更新 | 订单服务；监控自动发放质量 |
| 待核对订单数 | 统计时点状态为待核对的订单数量 | 订单号去重，实时值及每日快照 | 订单服务；控制异常积压 |
| 充值来源误兑数 | 兑换扣减流水中包含充值来源盖世币的订单数 | 订单号去重，实时监控及每日汇总；上线红线为 0 | 盖世币账与订单账；验证来源隔离 |
| 重复卡密发放数 | 同一卡密绑定超过一个已发放或待核对订单的卡密数量 | 卡密标识去重，实时监控及每日汇总；上线红线为 0 | 卡密库存账与订单账；验证唯一分配 |
| 三账差异数 | 盖世币扣减、卡密状态和订单状态无法按订单号形成合法对应关系的订单数 | 订单号去重，每日全量对账；上线红线为 0 | 盖世币账、库存账、订单账；触发异常核对 |
| 未授权卡密暴露数 | 无有效授权或无审计记录的完整卡密访问次数 | 操作请求去重，实时监控及每日汇总；上线红线为 0 | 权限服务与审计日志；验证敏感信息保护 |
