## 二、背景与目标

### 2.1 需求背景

部分用户持有合法的本地主机游戏文件，希望直接在盖世游戏 App 内导入、安装和运行。当前只能使用独立模拟器处理文件、设置、存档和按键，流程分散，安装状态和失败原因也不清楚。

本期将模拟器能力接入现有游戏库。平台仅提供运行工具，不提供、不上传游戏资源；首版不在主页、探索和全局搜索收录主机游戏。

### 2.2 目标与成功指标

|目标类型|目标|指标口径|基线|目标值|观察周期|
|---|---|---|---|---|---|
|使用|验证主机游戏能力的实际需求|主机游戏 Tab 去重用户数 / 游戏库去重用户数|无|上线后建立基线|14 天|
|导入|降低本地游戏导入门槛|安装成功用户数 / 选择导入方式用户数|无|[高风险假设] ≥40%|14 天|
|运行|验证模拟器可用性|成功进入游戏用户数 / 点击启动用户数|无|[高风险假设] ≥30%|14 天|
|稳定|定位失败环节|识别、安装、插件和启动失败率|无|持续下降|30 天|

## 三、故事介绍

### 3.1 用户与运营场景

- 支持设备用户：进入游戏库“主机游戏”，导入本地文件，安装后启动游戏，并在同一入口管理存档、设置和游戏文件。
- 不支持设备用户：仍能看到“主机游戏”，进入后看到不支持说明，不能导入或启动。
- 运营与研发：在后台配置引擎插件版本、更新策略和灰度范围，失败时可停用或回滚。

### 3.2 价值分析

- 用户不必在多个工具间切换，可在现有游戏库完成导入、安装、启动和管理。
- 平台只处理用户主动选择的本地文件，降低游戏资源分发风险。
- 插件化便于独立更新模拟器能力，异常不影响 App 其他游戏类型。

### 3.3 核心体验路径

1. <span style="background-color: #FEF794; color: #1677FF;"><strong>单 PKG</strong></span>：游戏库 → 主机游戏 → 导入游戏 → 选择 PKG → 文件管理器单选文件 → 识别文件 → 解压并安装 → 自动返回主机游戏 → 启动。
2. <span style="background-color: #FEF794; color: #1677FF;"><strong>游戏文件夹</strong></span>：游戏库 → 主机游戏 → 导入游戏 → 导入游戏文件夹 → 选择目录 → 扫描并识别多款游戏 → 勾选游戏 → 安装 → 自动返回主机游戏。
3. 游戏管理：主机游戏卡 → 启动，或点击更多 → 安装更新/DLC、存档管理、游戏设置、按键与布局、移除游戏。
4. 存档管理：更多 → 存档管理 → 下拉刷新，或点击右上角导入存档 → 导入、导出、删除。
5. 游戏内：启动 → 必要组件检测 → 横屏游戏 → 打开侧边栏 → 继续、显示触控按键、按键与布局、手柄映射、退出游戏。

### 3.4 产品指标预测

首期以建立真实基线为主，不承诺收入指标。重点观察导入漏斗、安装成功率、启动成功率、失败原因和 7 日复用率。

### 3.5 路径规划

- V1.0：完成本地导入、安装、运行、存档、设置和插件灰度闭环。
- 后续：根据设备覆盖和失败数据评估压缩包直导、单游戏驱动配置和云能力，不纳入本期。

### 4.4 状态流转

|当前状态|触发事件|条件|下一状态|失败处理|
|---|---|---|---|---|
|游戏库|选择 PKG|权限可用|文件管理器单选|取消则返回导入弹窗|
|文件管理器单选|选择 1 个 PKG|文件可读取|识别中|无效则显示原因并重新选择|
|游戏库|选择游戏文件夹|权限可用|目录扫描中|取消则返回导入弹窗|
|目录扫描中|扫描完成|识别到有效游戏|待勾选|无有效游戏则重新选择目录|
|待勾选|勾选游戏|至少 1 款、空间充足|解压中|未勾选或空间不足时按钮不可用|
|识别成功|点击安装|空间充足|解压中|任务创建失败时保留识别结果|
|解压中|解压完成|文件有效|安装中|失败清理当前未完成内容|
|安装中|安装和校验完成|至少 1 款成功|主机游戏库|失败项显示原因，不生成残缺卡片|
|主机游戏库|点击启动|设备支持、组件就绪|运行中|组件未就绪进入必要组件流程|
|运行中|确认退出|—|横版主机游戏库|取消则继续游戏|
