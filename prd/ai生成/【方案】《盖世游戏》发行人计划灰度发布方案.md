# 《盖世游戏》发行人计划灰度发布方案

> 日期：2026-09-16｜版本：V1.0｜状态：待评审

## 一、方案结论

- **灰度类型：** 风险控制型渐进放量，不是 A/B 实验，不用于证明功能带来因果提升。
- **圈选方式：** `[已确认]` 资格过滤后进行稳定随机分桶，不按注册时间、活跃度、消费能力或创作者等级挑选。
- **放量档位：** `[已确认]` 仅支持关闭、20%、50%、100%。向上放量不可跳级；出现风险可直接降级或关闭。
- **分桶关系：** 20% 命中桶值 0～19，50% 命中 0～49，100% 命中全部；20% 扩至 50% 时原用户全部保留。
- **存量保护：** 关闭或缩量只阻止新曝光和新参与；已发布任务、已投稿内容、待结算记录和已生成订单继续履约。

## 二、目标与边界

### 2.1 目标

1. 控制发行人计划新入口、新任务发布和新投稿参与的影响范围。
2. 分阶段验证页面、接口、机器审核、外站取数、预算预留、人工结算和资产流水是否稳定。
3. 发生异常时快速停止新增关系，同时保护已建立关系的用户权益。

### 2.2 不包含

1. 不按用户标签、创作者等级、历史消费或地区分别配置灰度比例。
2. 不增加运营白名单、黑名单或任意百分比配置。
3. 不把投稿作品在抖音、B站、快手或小红书的外部发布作为灰度对象。
4. 不因灰度关闭自动下架任务、撤回投稿、取消结算或退款；风险任务使用既有普通下架／风险下架流程。

## 三、候选人群

用户进入稳定分桶前需满足以下基础条件：

| 条件 | 判断口径 | 不满足时 |
|---|---|---|
| 产品范围 | 位于发行人计划现有支持地区和产品范围 | 不进入新曝光候选池 |
| 客户端版本 | App 版本满足发行人计划最低支持版本 | 不展示新入口，直达请求拒绝新进入 |
| 主体标识 | 登录用户存在稳定 `account_id`；未登录用户存在稳定 `installation_id` | 标识缺失时拒绝新曝光 |
| 账号状态 | 账号未被既有全局安全策略限制 | 按既有安全策略处理，不建立新关系 |
| 灰度配置 | `enabled`、`rollout_percent`、`rollout_seed` 和 `config_version` 均有效 | 配置读取失败或非法时按关闭处理 |

实名认证、创作者认证、每日发布次数、预算、任务状态和投稿资格不用于决定是否命中灰度；用户命中灰度后，在具体动作发生时继续执行这些既有业务校验。

### 3.1 存量用户例外

以下用户不受当前灰度比例限制，但只允许继续既有关系：

- 已发布任务的发布者可继续查看任务、结束任务和处理预算。
- 已加入任务或已投稿的创作者可继续查看投稿、等待取数和结算。
- 已进入待结算、风险挂起、抓取重试或人工处理的记录继续按原流程处理。
- 已生成的兑换订单继续恢复结果和发卡，不因灰度关闭中断。

存量例外不得用于创建新任务、加入新任务或提交新的投稿作品。

## 四、稳定分桶规则

### 4.1 主体选择

| 用户状态 | 分桶主体 | 规则 |
|---|---|---|
| 已登录 | `account_id` | 同一账号跨设备、重启和重新登录保持同一结果 |
| 未登录 | `installation_id` | 仅控制入口曝光；清除安装标识或重新安装后可能重新分桶 |
| 未登录后登录 | 切换为 `account_id` | 登录结果覆盖设备结果；所有发布、投稿和兑换动作以账号结果为准 |
| 切换账号 | 新账号的 `account_id` | 每个账号独立判断，不继承上一个账号结果 |

未登录用户命中入口、登录后账号未命中时，保留当前页面但拒绝建立新关系，按既有不可用反馈处理；不新增专用页面、弹窗或 Toast。

### 4.2 计算方式

```text
subject_key = subject_type + ":" + subject_id
bucket = stable_hash(subject_key + ":publisher_plan:" + rollout_seed) % 100
```

- 服务端是最终判定方，客户端不得自行计算并作为放行依据。
- 固定哈希算法、字符编码和取模规则由服务端统一维护；同一灰度轮次内不得变化。
- `rollout_seed` 在同一灰度轮次内固定，调整比例不得更换。
- 只有关闭上一轮灰度并创建新轮次时才允许生成新 `rollout_seed`；新轮次会重新圈选用户，必须生成新的配置版本并保留审计记录。

### 4.3 档位命中

| 状态／比例 | 命中范围 | 新曝光与新参与 |
|---|---|---|
| 关闭 | 无 | 全部拒绝 |
| 20% | `bucket` 为 0～19 | 允许 |
| 50% | `bucket` 为 0～49 | 允许 |
| 100% | `bucket` 为 0～99 | 允许 |

缩量时按同一规则反向收口。例如从 50% 降至 20% 后，桶值 20～49 的用户停止新曝光和新参与，但其存量任务与投稿继续履约。

## 五、放量节奏

以下时间和样本量为 `[建议默认]`，正式执行前可根据历史日活与主链路量级调整，但必须在放量前记录最终值。

| 阶段 | 最短观察 | 最低有效样本 | 进入条件 | 下一步 |
|---|---|---|---|
| 关闭→20% | 24 小时 | 入口曝光去重主体 ≥1,000，且任务发布成功／投稿记录创建成功合计 ≥100 | QA 全量通过；配置、埋点、告警可用；无未关闭的 P0／P1 问题 | 满足全部升级条件后进入 50% |
| 20%→50% | 48 小时 | 入口曝光去重主体 ≥3,000，且任务发布成功／投稿记录创建成功合计 ≥300 | 20% 阶段全部硬性指标通过；异常已闭环 | 满足全部升级条件后进入 100% |
| 50%→100% | 48 小时 | 入口曝光去重主体 ≥5,000，且任务发布成功／投稿记录创建成功合计 ≥500 | 50% 阶段全部硬性指标通过；产品、研发、测试、运营完成记录确认 | 进入全量并继续观察 72 小时 |
| 100%观察 | 72 小时 | 不设新增门槛 | 持续监控护栏指标 | 结束灰度轮次或按风险降级 |

规则：

1. “最短观察时间”和“最低有效样本”必须同时满足；未满足时保持当前档位。
2. 连续 7 天仍达不到最低样本时，不自动升级，由产品和数据基于实际流量重新设定样本门槛并记录原因。
3. 向上放量只能按 20%→50%→100% 执行，不允许从关闭直接进入 50% 或 100%。
4. 降级可以从任意档位直接降到更低档位或关闭。
5. 每次调整必须生成新 `config_version`，记录调整前后比例、操作人和时间。

## 六、升级指标与判定

### 6.1 硬性升级条件

以下条件全部满足才可升级：

| 类型 | 指标 | `[建议默认]`升级标准 |
|---|---|---|
| 重大风险 | P0／P1事故 | 0 起 |
| 资产安全 | 重复扣币、重复发奖、金额错误、账实不一致 | 0 起 |
| 权限安全 | 未命中用户被服务端放行、越权查看或操作 | 0 起 |
| 页面稳定性 | 发行人计划页面进入成功率 | ≥99% |
| 接口稳定性 | 核心接口技术成功率 | ≥98%，业务规则拒绝不计技术失败 |
| 数据完整性 | 灰度准入与配置变更事件有效上报率 | ≥98% |
| 分流质量 | 实际命中比例与配置比例的绝对偏差 | 样本≥1,000后不超过 1.5 个百分点 |
| 用户风险 | 与本功能直接相关的重大投诉 | 0 起 |

### 6.2 观察指标

以下指标用于发现问题，不单独决定升级：

- 入口点击率、页面进入成功率。
- 创建任务开始率、任务提交成功率、机审明确通过率和机审异常率。
- 投稿开始率、投稿提交成功率、外站取数完整率和抓取重试率。
- 待人工结算量、结算完成率、风险挂起率和平均处理时长。
- 页面错误率、接口失败率、投诉量和客服咨询量。

观察指标必须按 `config_version`、灰度比例、主体类型、App版本、平台和任务维度拆分，禁止把不同配置版本的数据混算。

### 6.3 升级决策

- **通过：** 最短观察时间和最低样本均满足，所有硬性指标通过，未发现未闭环风险。
- **继续观察：** 硬性指标通过但样本不足，或异常原因已定位但修复后的稳定观察不足一个完整窗口。
- **不通过：** 任一硬性指标失败；不得升级，按问题级别保持当前档位、降级或关闭。

## 七、止损与回滚

### 7.1 立即关闭

任一情况发生时，直接关闭新曝光和新参与：

1. 出现 P0／P1 事故。
2. 出现重复扣币、重复发奖、错误结算、账实不一致或卡密越权暴露。
3. 服务端灰度失效，未命中用户被批量放行。
4. 出现数据丢失、任务／投稿状态不可恢复或大面积错误状态。
5. 出现与本功能直接相关的重大合规或舆情风险。

### 7.2 降一级

页面进入成功率、核心接口技术成功率或埋点完整率连续两个 15 分钟窗口未达到升级标准时，先降一级；降级后一个窗口仍未恢复则关闭。

### 7.3 回滚后的处理

- 停止新的入口曝光、任务创建、任务加入和投稿提交。
- 存量任务、投稿、取数、结算、预算退回和订单履约继续处理。
- 风险任务是否挂起或下架，由既有风险下架流程决定，不能由灰度开关代替。
- 保留故障期间全部配置版本、准入记录、错误日志和业务流水，用于复盘。
- 问题修复后从 20% 重新开始，不直接恢复至故障前比例。

## 八、后台配置与权限

| 配置／记录 | 规则 |
|---|---|
| `enabled` | 功能总开关；关闭时比例不可编辑但保留上次值 |
| `rollout_percent` | 仅允许 20、50、100 |
| `rollout_seed` | 服务端生成、后台只读；同一轮次固定 |
| `config_version` | 每次成功保存递增；并发版本冲突时拒绝后提交 |
| `updated_by`／`updated_at` | 记录操作人与服务端时间；写入失败则整次保存失败 |

- 常规放量由产品提出，研发、测试、运营核对后，由具备配置权限的运营人员执行。
- 紧急关闭可由当班具备权限的运营或研发人员先执行，随后补充事故记录和影响范围。
- 保存失败、非法比例或版本冲突不得覆盖上一版有效配置。
- 配置读取失败时拒绝新曝光和新参与，存量关系继续履约。

## 九、数据与埋点

### 9.1 复用事件

| 事件 | 触发 | 必要参数 |
|---|---|---|
| `publisher_rollout_gate_result` | 每次服务端完成灰度准入判断 | `subject_type`, `subject_key_hash`, `bucket`, `rollout_percent`, `eligible`, `config_version` |
| `publisher_rollout_config_update` | 运营保存开关或比例，成功和失败均上报 | `operator_uid`, `before_enabled`, `after_enabled`, `before_percent`, `after_percent`, `config_version`, `result_status`, `fail_reason` |

### 9.2 统计口径

- 命中比例＝`eligible=true` 的去重主体数 ÷ 完成准入判断的去重主体数。
- 去重主体按事件中的 `subject_type + subject_key_hash` 统计；`subject_key_hash` 由服务端对稳定主体键不可逆散列，埋点不传原始账号或安装标识。账号与安装标识不得直接合并为同一主体。
- 技术成功率排除业务规则拒绝、未实名、未认证、次数超限、预算不足等预期结果。
- 每个配置版本单独统计；配置切换时以服务端生效时间切分数据窗口。
- 灰度是风险放量，不进行显著性检验，也不以转化率提升作为升级的必要条件。

## 十、测试清单

1. 关闭、20%、50%、100%四档准入结果正确。
2. 同一账号跨设备、重启和重新登录结果稳定。
3. 未登录使用安装标识，登录后切换为账号结果。
4. 20%扩至50%时原20%用户全部保留；50%缩至20%时桶值20～49停止新参与。
5. 配置读取失败、非法比例、种子缺失和版本冲突均拒绝新曝光。
6. 未命中用户的直达请求和服务端接口不能建立新任务或投稿关系。
7. 灰度关闭或缩量后，存量任务、投稿、结算和订单继续履约。
8. 灰度配置保存、准入判断和失败原因埋点完整。
9. 紧急关闭后新请求被拦截，重复执行关闭保持幂等。
10. 新轮次更换种子后重新分桶，旧轮次配置和审计记录可追溯。

## 十一、角色分工

| 角色 | 职责 |
|---|---|
| 产品 | 确认阶段目标、升级条件和影响范围；发起放量或降级 |
| 运营 | 执行配置、观察投诉与业务异常、处理存量任务 |
| 研发 | 保证服务端准入、配置版本、失败关闭、日志和存量旁路正确 |
| 测试 | 验证档位、身份切换、扩缩量、异常恢复、权限和存量履约 |
| 数据 | 核对分流比例、事件完整性和各配置版本指标 |
