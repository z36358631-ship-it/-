## 二、背景与目标

背景：

- 程序已在 Mac 端完成一版 MOD 功能效果，入口基本确定在游戏详情，但页面结构、交互、状态和跨端规则未经过完整产品设计。
- 创意工坊可作为信息层级参考，但创意工坊是官方内容，用户执行“订阅”；本期 MODS 来自外部非官方来源，用户执行“下载、安装和本机管理”，两者不能合并。
- 本期需要同时定义 Mac 与 APP 端。APP 支持竖屏、横屏以及运行中切换；当前只更新 Mac Demo，APP 以 PRD 作为后续设计和开发依据。

目标：

- 为《饥荒联机版》建立从“游戏详情发现 → 浏览 → 查看详情 → 安装 → 本机管理”的 MODS 完整路径。
- 让 Mac 与 APP 使用同一业务规则，并明确两端布局差异、APP 横竖屏切换和设备级安装边界。
- 国内包与海外包共用 MODS 能力；海外使用 `GameHub` 和现有多语言能力，不依赖海外不存在的云游戏。

核心边界：

- 本期仅做 C 端，不输出 B 端章节。
- 外部内容由既有来源同步，来源安全性暂按现有方案处理，本期不新增上传、审核和安全运营后台。
- 安装跟随设备。同一账号在其他设备登录后，需要在该设备重新安装。
- 本期不展示启动检查、启动恢复或异常退出恢复页面，不改造游戏启动流程。
- 本期不改造创意工坊，只参考其页面信息层级。

## 三、故事介绍

### 3.1 用户场景

- Mac 用户在《饥荒联机版》游戏详情看到独立的“MODS”区域，直接浏览 3 个热门 MOD；点击热门卡片查看详情，或点击“查看全部”进入 MODS 浏览页。
- 用户在浏览页通过搜索和排序找到目标 MOD，点击整张卡片进入详情；未安装项可在卡片右下角安装，已安装项可直接切换当前设备的启用状态。
- 用户进入“已安装”，通过“全部、可更新”找到需要管理的 MOD，可直接切换启用状态，也可进入详情更新或卸载。
- APP 用户从游戏详情“更多”进入 MODS，在竖屏和横屏之间切换时继续查看同一页签、同一 MOD 和同一任务，不重复下载或安装。
- 海外用户在 `GameHub` 使用同一 MODS 能力，界面跟随海外包现有语言设置；页面不出现云游戏入口或云游戏依赖。

### 3.2 价值分析

- 发现效率：游戏详情直接露出 3 个热门内容，减少从详情到目标 MOD 的路径。
- 使用效率：浏览、详情、安装和管理形成连续路径，卡片信息收敛到判断所需字段。
- 状态可信：持续展示“仅此设备”，避免用户把 Mac、手机和平板的安装状态误认为账号同步。
- 跨端一致：Mac 与 APP 使用同一业务状态；APP 横竖屏仅改变布局，不改变数据和任务。
- 业务隔离：MODS 使用下载和安装语义，创意工坊保持订阅语义，避免用户混淆来源和结果。

### 3.3 核心体验路径

- Mac 热门路径：游戏详情 → MODS 热门卡片 → MOD 详情 → 安装到此设备。
- Mac 全量路径：游戏详情 → 查看全部 → 浏览 → 搜索或排序 → 点击卡片 → MOD 详情 → 安装。
- Mac 管理路径：MODS → 已安装 → 全部或可更新 → 点击卡片 → 启用、停用、更新或卸载。
- APP 路径：游戏详情 → 更多 → MODS → 浏览或已安装 → MOD 详情 → 安装或管理。
- APP 旋转路径：竖屏页面 → 旋转为横屏 → 保留页面与任务 → 继续操作；横屏转竖屏同理。

### 3.4 产品指标预测

|指标|首期目标|统计口径|
|---|---|---|
|游戏详情 MODS 区点击率|建立基线，灰度期持续观察|点击热门 MOD 或“查看全部”的设备数 / MODS 区曝光设备数|
|详情到安装点击转化率|不低于 20%|点击安装的唯一设备与 MOD 组合 / 详情曝光的唯一设备与 MOD 组合|
|安装成功率|不低于 95%|安装成功任务数 / 创建成功的安装任务数|
|重复任务数|0|同一设备、游戏、MOD 同时存在的重复活动任务数|
|APP 旋转任务连续率|100%|旋转后仍复用原任务的次数 / 有活动任务时旋转次数|
|跨设备状态误写事件|0|本机状态被其他设备安装记录覆盖的确认事件数|

### 3.5 路径规划

- V1.0：完成 DST 的 Mac 与 APP 方案；当前交付 Mac 高保真 Demo；支持发现、浏览、详情、安装、更新、启停、卸载和设备级状态。
- 后续版本：根据灰度数据评估更多游戏接入、内容推荐和运营配置，不在本期预留空入口。

本期非目标：

- 创意工坊订阅、取消订阅和官方内容管理。
- MOD 上传、发布、评论、评分和用户创作工具。
- 账号级安装同步、跨设备自动安装和跨设备启用值同步。
- 启动检查、启动确认、异常退出恢复和游戏内 MOD 管理。
- 海外云游戏能力。

## 四、概要设计

### 4.1 模块设计

|模块|Mac|APP 竖屏|APP 横屏|
|---|---|---|---|
|游戏详情入口|独立 MODS 区，露出 3 个热门组件、总量和查看全部|游戏详情“更多”菜单中的 MODS 入口|与竖屏入口一致|
|浏览页|两列卡片；排序仅“热门趋势、下载量、最新发布”；已安装卡片可快捷启停|单列卡片；排序使用现有控件|两列卡片；顶部集中操作|
|已安装页|两列管理卡片；筛选仅“全部、可更新”；不提供排序；卡片可快捷启停|单列卡片；沿用 APP 现有排序和筛选|两列卡片；规则与竖屏一致|
|MOD 详情|居中弹窗；标题下显示作者、下载量、文件大小；已安装项可快捷启停|全屏页面|左右分栏页面|
|安装与更新|任务状态显示在原卡片和详情|任务脱离页面生命周期|旋转后复用同一任务|
|卸载|二次确认弹窗|二次确认弹窗|二次确认弹窗|

#### 4.2.3 APP 横竖屏切换

旋转必须保留：

- 当前页面、浏览/已安装 Tab、搜索词、排序和筛选。
- 当前打开的 MOD、预览图、阅读章节和返回路径。
- 列表数据、滚动锚点和已加载页。
- 任务 ID、已下载字节、校验和安装进度。

旋转只改变单列/两列、全屏/左右分栏等布局，不重新请求目录第一页，不重复下载、校验或安装。

#### 4.2.4 设备级安装边界

- Mac 与每台 APP 设备分别保存安装版本、启用值和任务状态。
- 所有已安装状态持续展示“仅此设备”。
- 同一账号换设备后不显示另一设备为“已安装”，用户需要在新设备重新安装。
- 登录、退出或切换账号不得用云端或其他设备记录覆盖当前设备的实际文件状态。
- 卸载只删除当前设备中的 MOD 安装文件，不删除游戏存档和用户 MOD 配置。

#### 4.2.7 当前端可安装目录口径

“当前端可安装目录”同时用于游戏详情 MOD 总量、热门 3 个、浏览列表、搜索和排序，必须满足：

- 游戏标识为 `steam:322330`，来源状态有效，未下架。
- 当前平台存在可下载包，包版本、大小、地址和校验值完整。
- 名称、作者、封面、简介、必要依赖、发布时间、下载量和文件大小等展示与安装字段完整；<mark><strong><span style="color:#3370ff">兼容性和最新版本可继续作为安装判断数据，但不在 Mac 详情展示</span></strong></mark>。
- 当前平台和游戏版本可安装，必要依赖可满足。

当前平台不可用、来源失效、已下架、缺少当前端包、必要字段缺失或安装被阻塞的 MOD 不计入总量、不进入热门 3 个、不进入浏览和搜索结果。

热门规则：

- <mark><strong><span style="color:#3370ff">在当前端可安装目录内按近 24 小时下载激增百分比降序取前 3 个。</span></strong></mark>
- 激增百分比相同时按下载量降序，再按发布时间倒序，仍相同时按 MOD ID 稳定排序。
- 激增百分比或下载量缺失时按 0 处理；发布时间缺失时按最旧处理。
- 目录、近 24 小时激增百分比、下载量和发布时间每 15 分钟同步一次；刷新失败保留最近一次成功目录并标记刷新失败，不把失效项重新加入。

排序数据映射：

|产品排序|同步字段|方向|
|---|---|---|
|热门趋势|`trend_growth_24h`|降序|
|下载量|`download_count`|降序|
|最新发布|`published_at`|降序|
|稳定末级|`mod_id`|升序|

服务端、运营同步和客户端排序合同统一使用以上字段，不以更新时间或最新版本时间替代发布时间。

#### 4.2.8 进程重启恢复

所有阶段复用原任务 ID。恢复前先读取任务记录、当前版本指向和文件清单，按下表得到唯一结果：

|进程退出时点|重启后的处理|文件与本机状态|
|---|---|---|
|等待下载或下载中|从已验证的下载字节继续；续传条件失效时转为“下载已中断”，由用户继续或取消|保留有效字节；不写入安装事实；旧版和启用值不变|
|包已下载，校验未完成|从头重新校验完整下载包，不沿用未完成的校验结果|校验成功后继续安装；失败则删除错误包和本任务临时文件|
|校验完成，安装/更新尚未提交|删除未完成的新版本目录，再使用已校验包从安装阶段重新执行|当前版本指向不变；未安装项仍未安装；更新项继续使用旧版和原启用值|
|新版本指向已切换，本机状态尚未提交|核对新版本文件清单；完整则补交本机状态并结束成功，不完整则回退旧版并结束失败|不得出现两个当前版本；回退时保留旧版和更新前启用值|
|任务记录损坏或无法判断阶段|清理非当前版本的 staging 和未完成目录，任务结束失败|保留唯一可确认的当前版本和启用值；显示重试，不自动创建新任务|
