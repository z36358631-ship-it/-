## 二、背景与目标

### 2.1 背景

Mac 端已完成第一版 MOD 功能，但 APP 尚无经过产品设计的完整路径。APP 已有创意工坊，用户通过游戏详情“更多菜单”进入，再完成浏览和订阅。MODS 来自外部同步，用户动作是下载、安装和本机管理，不能与创意工坊的官方订阅混用。

### 2.2 目标

1. 在不改变现有游戏详情结构的前提下，新增独立 MODS 入口。
2. 复用创意工坊的信息层级，提供 MOD 浏览、搜索、排序、下载安装、启停、更新和卸载。
3. 支持 APP 竖屏、横屏及运行中旋转，旋转不丢失页面与任务状态。
4. 明确设备边界：安装文件、安装状态和启用值只属于当前 APP 设备。

### 2.3 本期范围

- 仅 C 端 APP。
- 《饥荒》游戏详情及“更多菜单”入口。
- MODS 浏览、已安装、MOD 详情。
- 下载、校验、安装、启停、更新、卸载。
- 竖屏、横屏及运行中旋转。
- 国内包和海外包。

### 2.4 非目标

- 不改造创意工坊页面、订阅逻辑或数据。
- 不合并创意工坊和 MODS 入口。
- 不做启动检查、冲突检查和异常退出恢复。
- 不做跨设备自动下载或状态同步。
- 不新增 B 端；目录、文案、图片和文件由现有外部同步链路提供。
- 本期按“外部同步内容已完成安全处理”的前提设计，不新增客户端安全确认页。

## 三、故事介绍

### 3.1 用户与运营场景

#### 场景一：发现并安装 MOD

用户打开《饥荒》详情 → 点击“更多” → 点击“MODS” → 在浏览页搜索或切换排序 → 点击卡片查看详情 → 点击“下载安装” → 安装完成并在当前设备启用。

#### 场景二：管理已安装 MOD

用户进入“已安装” → 通过卡片开关启用或停用 → 点击卡片查看完整说明 → 检查更新或卸载。所有操作只修改当前 APP 设备。

#### 场景三：运行中旋转

用户在列表、详情或安装过程中旋转设备 → 页面从单列切换为双列或从覆盖层切换为左右分栏 → 当前 Tab、筛选、MOD 和任务进度保持不变。

### 3.2 价值分析

- 发现效率：用户无需离开 APP 即可浏览适用于当前游戏的 MOD。
- 使用效率：下载、安装和本机启停形成一条完整路径。
- 认知一致：页面层级参考创意工坊，但官方订阅与外部安装保持隔离。
- 海外覆盖：海外包无云游戏不影响 MODS，本地安装管理可独立提供。

### 3.3 核心体验路径

- 入口：游戏详情 → 更多菜单 → MODS。
- 浏览：浏览 → 搜索或排序 → 卡片 → MOD 详情。
- 安装：MOD 详情 → 下载安装 → 下载 → 校验 → 安装 → 已启用。
- 管理：已安装 → 快捷启停，或进入详情 → 更新/卸载。
- 旋转：任一 MODS 页面 → 旋转设备 → 使用同一状态继续操作。

### 3.4 产品指标目标

|指标|目标|统计口径|
|---|---|---|
|MODS 入口成功率|≥99.9%|点击 MODS 后成功进入列表的次数/点击次数|
|安装任务成功率|≥95%|安装成功任务数/创建安装任务数，用户主动取消不计失败|
|启停操作成功率|≥99.5%|启停写入成功次数/启停操作次数|
|重复安装任务率|0|`app_mods_task_create_result` 中 `active_task_count>1` 的次数/任务创建请求次数|
|旋转状态丢失率|0|`app_mods_orientation_change` 中 `state_consistency_result=failed` 的次数/旋转完成次数|
|MODS 页面无崩溃会话率|≥99.8%|进入过 MODS 页面且未发生 MODS 相关崩溃的会话数/进入过 MODS 页面的会话数|

- 国内包、海外包分别统计；默认观察滚动 24 小时。
- 安装、启停指标达到每个包体 200 次有效操作后才用于放量判断；样本不足时继续观察，不自动放量。
- 数据源为第六章客户端埋点和现有崩溃平台；产品数据负责人维护看板，研发负责人核对崩溃归因，产品负责人作 Go/No-Go 决策。

### 3.5 路径规划

- V1.0（本期）：完成入口、浏览、已安装、详情、本机安装管理和横竖屏。
- 后续版本：根据实际数据评估依赖安装、启动检查、冲突处理和异常退出恢复。

#### 4.2.1 入口与业务隔离

|维度|MODS|创意工坊|
|---|---|---|
|内容来源|外部同步内容|官方接入内容|
|用户动作|下载、校验、安装、启停、更新、卸载|订阅、取消订阅|
|设备状态|仅当前 APP 设备|沿用创意工坊现有规则|
|本期处理|完整实现|不改造，仅保留入口作为参考|

- 两套能力不得复用入口名称、用户动作、安装状态或任务文案。
- MODS 页面不得出现“订阅、取消订阅、我的订阅”。
- 创意工坊状态变化不得修改 MODS 的本机记录，反向同理。

#### 4.2.2 浏览、搜索与排序

##### 搜索

- 仅浏览页显示搜索框；已安装页不显示搜索或空占位。
- 按 MOD 名称、作者模糊匹配；输入前后空格不参与匹配。
- 最多输入 50 个字符，超出后不继续录入。
- 输入后 300ms 触发搜索；清空立即恢复当前排序下的目录。
- 不展示搜索建议、历史或关键词高亮。
- 无结果显示“没有找到相关 MOD”，提供“清空搜索”。

##### 排序

|排序子 Tab|第一排序|第二排序|第三排序|
|---|---|---|---|
|热门|近24小时下载增幅降序|发布时间倒序|MOD ID 升序|
|下载最多|累计下载量降序|发布时间倒序|MOD ID 升序|
|最新发布|发布时间倒序|累计下载量降序|MOD ID 升序|

- 默认“热门”。
- 切换排序后重新请求首批数据，并回到列表顶部。
- 搜索词保留；搜索与排序共同生效。

##### 加载

- 首批和每批加载 20 条，使用服务端分页令牌追加加载。
- 不显示总页数；服务端返回总量时可在埋点记录，不在本期页面展示。
- 追加加载保留已加载内容；返回列表恢复原页签、查询条件和滚动锚点。
- 首次加载显示卡片骨架；追加加载在列表底部显示“加载中”。
- 分页令牌为空时显示“没有更多了”。
- 首次加载失败显示“加载失败，点击重试”；追加失败保留已加载内容并提供“重新加载”。

#### 4.2.3 卡片规则

- 标题最多两行，短简介最多两行；超出截断，详情展示完整内容。
- 作者单行展示；过长时截断。
- 下载量：0～9,999 显示整数；10,000 起以“万”缩写，最多保留一位小数。
- 文件大小按来源返回值展示，统一使用 KB、MB、GB。
- 预览图失败显示默认占位图，不阻断卡片和安装操作。
- 卡片内安装、启停操作不进入详情；点击卡片其他区域进入详情。
- 卡片获得键盘焦点时，Enter 或空格进入详情；安装按钮和快捷开关获得焦点时，Enter 或空格只执行自身操作。
- 安装或启停进行中禁用同一 MOD 的重复操作，其他 MOD 可继续浏览。

#### 4.2.4 已安装与启停

- “全部”展示当前设备所有已安装 MOD。
- “可更新”只展示已确认存在新内容的 MOD。
- 已安装页不读取浏览搜索词；切换 Tab 不清空浏览搜索词。
- 快捷开关和详情状态按钮读取同一启用值。
- 点击启用/停用后先进入处理中；写入成功再更新文案和颜色。
- 写入失败恢复原值，提示“启用状态修改失败，请重试”。
- 更新信息未知或来源失效的 MOD 不进入“可更新”，但仍可启停和卸载本地版本。

#### 4.2.5 详情焦点与关闭

- 打开 MOD 详情后，焦点进入详情关闭按钮；背景页面不参与焦点顺序。
- Tab 和 Shift+Tab 只在当前详情层内循环；卸载确认打开时只在确认层内循环。
- Esc 优先关闭卸载确认，其次关闭详情。
- 关闭详情后，焦点返回触发详情的原卡片；原卡片已不存在时返回当前页第一个可操作控件。

#### 4.2.6 安装、更新与卸载

##### 状态流转

|当前状态|用户操作|下一状态|失败处理|
|---|---|---|---|
|未安装|下载安装|等待下载 → 下载中 → 校验中 → 安装中 → 已安装且启用|保留失败原因，可重试；不显示已安装|
|已安装且启用|停用|已安装且停用|恢复启用，显示失败提示|
|已安装且停用|启用|已安装且启用|恢复停用，显示失败提示|
|已安装|更新|下载更新 → 校验 → 安装 → 保留原启用值|保留旧版和原启用值，可重试|
|已安装|卸载并确认|未安装|保留原文件与状态，显示失败提示|

##### 防重与后台

- 同一设备、同一游戏、同一 MOD 同时只能存在一条安装或更新任务。
- 重复点击绑定原任务，不创建第二条任务。
- 同一 MOD 的安装、更新、启停和卸载共用一把设备操作锁；第一条已受理操作完成或失败前，后续冲突操作不进入队列。
- 安装或更新中，卡片和详情的启停、更新、卸载均禁用；启停写入中，更新和卸载禁用；卸载确认或卸载中，其他操作禁用。
- 卡片和详情读取同一操作锁与状态；任一入口受理操作后，另一入口同步进入处理中或禁用态。
- 冲突操作提示“当前 MOD 正在处理，请稍后再试”；不得静默失败，也不得以卸载覆盖安装中的文件。
- 不同 MOD 可并行执行任务；同一 MOD 的操作结束后，以设备实际文件和启用值统一刷新卡片与详情。
- 进入后台后优先继续下载；系统暂停时保存任务 ID、已下载字节和续传信息。
- 回到前台自动尝试续传一次；失败时显示“继续 / 取消”。
- 页面关闭、切 Tab 或旋转不取消任务。
- 更新失败不得覆盖可用旧版。

- 列表滚动锚点和详情阅读位置。
- 下载、校验、安装或更新任务 ID、阶段和进度。
- 本机安装状态、启用值和尚未提交的卸载确认。

#### 4.2.8 国内与海外

- **国内包产品名显示“盖世游戏”，国内包沿用中文界面。**
- **海外包产品名显示“GameHub”，不得使用 GaishiGame；页面沿用海外包既有多语言能力。**
- **国内包和海外包均提供入口、浏览、下载、安装、本机管理和横竖屏能力。**
- 来源文本没有当前语言译文时展示来源原文，不由客户端自动生成译文。
- 本需求不依赖云游戏、实名认证或登录方式。未登录用户可浏览、安装和管理当前设备文件；登录过期不取消设备任务。
- 国内和海外的 MODS 安装状态均按设备隔离，不使用账号状态替代。
- 外部同步目录可同源，但每条 MOD 必须携带区域可见范围：仅国内、仅海外、国内和海外。字段缺失或值非法时默认两端均不展示。
- 客户端按包体区域请求目录，服务端只返回当前区域可见内容；国内、海外的排序和下载量使用各自区域返回口径。
- 现有外部同步链路必须支持按 MOD ID 和区域单独隐藏；区域隐藏后从目录和搜索中消失，不影响另一地区。
- 已安装内容被区域下架后仍可在当前设备启停和卸载，不再提供详情更新；详情显示“来源内容暂不可用”。
- 投诉、版权或合规紧急下架由内容运营发起，30 分钟内完成目标区域隐藏并刷新目录缓存；不需要关闭整个 MODS 入口。

## 七、运营需求

1. 内容运营是目录放行 DRI。上线前至少准备 20 条《饥荒》MOD，逐条确认 MOD ID、区域可见范围、版权或授权凭证引用、安全处理完成标记、封面、名称、作者、简介、安装说明、更新记录、下载量和文件大小。
2. 首批目录在上线前 2 个工作日冻结；冻结后只处理阻断性修正和紧急下架。内容运营、产品、测试在发布清单中签字后方可放量。
3. 外部目录常规同步频率不低于每小时一次；同步失败连续 2 次由服务端负责人告警内容运营。客户端保留最近一次成功目录并显示刷新失败。
4. 海外包需准备现有多语言框架内的页面固定文案和支持语言清单，由海外运营验收；来源内容无译文时显示原文。
5. 配置 MODS 远程功能开关，可按包体、版本和灰度人群关闭入口；另保留现有外部链路的“MOD ID + 区域”内容隐藏能力。
6. 投诉或紧急下架 SOP：客服/运营登记 MOD ID 与目标区域 → 内容运营 15 分钟内判断 → 需要下架时 30 分钟内隐藏 → 服务端刷新目录缓存 → 运营复查搜索和详情 → 24 小时内补充处置记录。版权、安全或合规投诉未能及时判断时先隐藏。
7. 上线前准备目录为空、来源失效、服务异常和区域下架文案；本期不新增运营后台，以上配置沿用现有外部同步链路和远程开关。

## 八、上线与灰度

### 8.1 灰度策略

1. 先对内部账号和测试设备开放。
2. 国内包、海外包分别按 1% → 10% → 30% → 100% 放量；每档至少观察 24 小时，且安装和启停分别达到 200 次有效操作。
3. 放量门槛：安装任务成功率≥95%、启停成功率≥99.5%、重复安装任务率=0、旋转状态丢失率=0、MODS 页面无崩溃会话率≥99.8%。
4. 暂停门槛：滚动 2 小时且安装任务≥50 次时，安装成功率<90%或无崩溃会话率<99.5%；或任意时间出现重复安装任务、区域内容越界。达到任一门槛即停止当前包体继续放量。
5. 回退门槛：暂停后 2 小时未恢复，或出现批量文件损坏、连续崩溃、错误区域内容无法单条隐藏；产品负责人通知研发关闭对应包体入口。
6. 产品数据负责人维护按包体拆分的埋点与崩溃看板，研发负责人确认技术异常，内容运营确认区域内容，产品负责人作每档 Go/No-Go 决策并留档。
7. 放量期间不改变创意工坊入口和订阅能力。

### 8.2 回退

- 关闭 MODS 远程开关后隐藏入口，不删除用户已安装文件。
- 已在进行中的任务允许结束或按任务中心规则取消，不直接清理临时文件。
- 回退不修改创意工坊订阅状态。
