## 二、背景与目标

### 2.1 需求背景

目标用户是希望在手机上运行暗黑系列 PC 版的盖世游戏用户。用户当前只能在 Windows PC 游玩，或按测试链路手动下载 Battle.net、导入客户端、进入虚拟桌面、安装登录兼容文件、下载游戏，再回到盖世启动。该链路长，且存在三项阻塞：

1. Battle.net 在虚拟桌面内存在黑屏及字体、登录补丁兼容问题。
2. Battle.net 下载游戏时存在客户端卡死问题。
3. 游戏内当前仅支持键盘模式，虚拟手柄尚未完成兼容。

因此，本周宣发不能使用“立即游玩”口径。先用预热页准确说明进度、展示已取得的实机证据并管理用户预期；全部门禁通过后再切换正式支持详情页。

[高风险假设] “首发”属于市场声明，正式对外前需完成竞品与法务核验。本期不得使用“唯一支持”“全机型兼容”等不可验证表述。

## 三、故事介绍

### 3.1 用户与运营场景

- 预热用户：用户启动盖世游戏，看到“暗黑系列即将支持”，点击“查看适配进度”进入 H5 首屏，依次查看当前状态、实机视频、三项关卡、适配范围和预计流程。
- 正式支持用户：技术门禁通过后，用户启动盖世游戏，看到“暗黑系列现已支持”，点击“查看详情”进入正式页，选择暗黑4或暗黑3，查看对应推荐配置、图文启动步骤和 FAQ。
- 发布人员：根据项目验收结论切换启动弹窗和 H5 地址；不得同时向同一用户展示预热与正式口径。

### 3.2 价值分析

- 对用户：提前知道支持范围和真实进度，避免按未稳定链路反复尝试；正式支持后可按图文步骤完成设置。
- 对业务：在技术收口期间保留宣发窗口，同时避免把“测试跑通”误写成“普通用户可用”。
- 对产品：沉淀暗黑系列长期兼容说明页，后续可更新视频、配置和 FAQ，不依赖运营活动维持价值。

### 3.3 核心体验路径

#### 预热阶段

盖世游戏启动 → 弹出“暗黑系列即将支持” → 点击“查看适配进度” → 打开预热 H5 首屏 → 查看视频与适配进度 → 查看预计流程和 FAQ

#### 正式支持阶段

盖世游戏启动 → 弹出“暗黑系列现已支持” → 点击“查看详情” → 打开正式详情 H5 首屏 → 选择暗黑4/暗黑3 → 查看推荐配置 → 查看启动方法 → 查看 FAQ

### 3.4 产品指标预测

- 预热页先建立弹窗点击率、视频互动率、适配进度曝光率和页面停留时长基线。
- 正式页重点看分游戏选择率、推荐配置与启动方法 Tab 点击率、FAQ 到达率。
- [高风险假设] 当前没有历史同类页面数据，2.2 中内容互动目标仅作首版观察线，上线7天后按真实基线调整。

### 3.5 路径规划

1. 本周：上线预热弹窗和预热 H5，只表达“即将适配/适配进行中”。
2. 技术收口：解决 Battle.net 登录、游戏下载卡死和虚拟手柄三项问题。
3. 灰度验证：用普通用户完成从 Battle.net 安装到进入游戏的完整链路。
4. 正式发布：切换正式弹窗和详情页；同步最终实机视频、配置参数和图文攻略。

### 4.2.1 登录态、刷新与内容规则

- H5 内容无需登录即可查看，不展示用户昵称、UID或设备识别结果。
- 页面不提供用户输入、评论、分享或个人信息收集。
- 适配进度和配置为版本内容，不自动轮询；页面重新打开后读取最新发布版本。
- 文案超过容器宽度时允许自然换行；游戏名、状态标签不得截断到无法识别。
- 国内官方包使用中文；[假设] 本期不在海外包展示，海外版如后续上线需另行提供多语言素材和 GameHub 品牌文案。

### 4.2.2 异常与降级

|场景|触发条件|处理方式|提示文案|
|---|---|---|---|

|配置素材缺失|正式页缺少某游戏参数或步骤图|阻塞正式页发布，不得用另一款游戏内容占位|不对用户展示|
|状态地址配置错误|预热阶段指向正式页|立即回退资源地址并停止正式页曝光|不对用户展示错误口径|
|弱网重复点击|页面尚未打开时多次点击 CTA|首次点击后进入跳转中状态，后续点击不重复打开|不重复提示|

### 9.2 待确认项

#### 必须确认（阻塞正式发布）

1. [待确认] 三项技术门禁的量化阈值。默认建议：暗黑4、暗黑3各覆盖至少3款代表设备，每款设备连续完成10次全链路，登录成功率和游戏下载完成率均≥95%，无阻塞性虚拟手柄问题。未确认会影响测试验收和正式上线。引用：4.1.2。
2. [待确认] Battle.net 登录兼容包是自动集成还是用户手动安装。默认建议：随容器或 Battle.net 启动自动加载；如必须手动安装，正式攻略需增加下载来源、版本校验、失败恢复和卸载方法。未确认会影响开发、测试和启动方法。引用：4.2“启动方法”。
3. [待确认] 正式页启用时间与拍板人。默认建议：由 CTO 在兼容研发、测试共同签字后确认切换。未确认会影响正式页上线。引用：3.5、4.1.1。
4. [待确认] 暗黑4、暗黑3最终推荐参数及盖世版本。默认建议：只展示对应设备和版本下已重复验证的参数，不把 Demo 数值直接当生产结论。未确认会影响正式页内容验收。引用：4.2“推荐配置”。

#### 建议确认（影响完整度）

1. [待确认] 启动弹窗频控。默认建议：同一用户每天最多曝光1次，点击 CTA 或关闭后当天不再曝光；正式支持状态切换后允许重新曝光1次。未确认会影响用户打扰度和数据口径。引用：4.2“启动弹窗”。
2. [待确认] 预热页是否在 App 外投放。默认建议：本期只在国内官方包启动弹窗进入；如对外投放，另补 App 下载承接和未安装用户路径。未确认会影响宣发渠道，不阻塞 App 内上线。引用：2.3、4.2.1。
3. [待确认] “首发”市场表述。默认建议：完成竞品和法务核验前只写“首发适配进行中”，不写“唯一支持”。未确认会影响对外文案。引用：2.1、5。

#### 可后续补充

1. [待确认] 上线7天后的指标目标调整。默认建议：按真实基线复盘弹窗点击、视频互动和 Tab 使用率。未确认不影响本期开发。引用：2.2、3.4。
2. [待确认] FAQ 后续增补机制。默认建议：每周汇总共性问题，经兼容研发确认后随 H5 版本发布。未确认不影响本期开发。引用：八。
