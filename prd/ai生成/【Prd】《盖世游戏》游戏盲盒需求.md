## 一、文档概述

### 1.1 背景概述

- **需求背景：** 盖世游戏希望在现有游戏库中增加低决策成本的随机推荐，帮助“有多款游戏可玩、但此刻不知道玩什么”的用户快速选中一款。
- **当前解决方式：** 用户在个人游戏库、已登录 Steam 库和已导入游戏中逐款浏览，再通过秒玩、现有启动入口或游戏详情完成后续操作。
- **存在问题：** 当可玩游戏较多时，用户需要反复浏览和比较；若随机结果未明确适配或启动成本过高，推荐反而会增加失败成本。
- **问题证据：** 竞品页的单款揭晓和“再抽一次”证明随机推荐可减少选择步骤；但竞品内容基本即点即玩，与盖世 PC 游戏的拥有、下载、安装、兼容和账号成本不等价。当前无用户行为基线，本期需用启动和有效游玩验证价值。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 覆盖 Android 国内版和海外版、竖屏和掌机横屏；涉及现有游戏库及现有游戏详情的入口承接；不覆盖 Mac、Web、iOS 和 B 端。 |
| 业务边界 | 包含首位盲盒功能卡、候选过滤与去重、加权随机、同轮不重复、结果重校验、查看详情、再抽一次、五种语言和数据归因；不新增首页入口、直接启动、下载、Steam 登录引导、次数限制、任务、奖励、后台配置或新的游戏获取／启动路径。 |
| 运营边界 | 运营只需配合五语言文案校对、已有封面可用性检查和指标基线准备；无运营后台、活动、奖品或素材投放。 |
| 人力边界 | 产品定义候选、权重和数据口径；UI 输出横竖屏功能卡与弹窗状态；Android 客户端负责入口、弹窗、动画、详情承接和埋点；服务端／数据侧提供候选依赖与归因能力；测试覆盖算法、状态、横竖屏和多语言；运营／本地化完成文案与素材检查。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 有效推荐池 | Eligible pool | 按当前账号、设备和时点聚合候选后，完成统一游戏实体去重，并排除待验证、不兼容、下架、维护中、链路失效和无法确认可玩的游戏后得到的集合。 |
| 可直接游玩 | Ready | 当前设备已有可用的秒玩、Steam 或导入启动链路，无需先下载游戏包体即可按现有逻辑启动。 |
| 未下载 Steam 游戏 | Uninstalled | Steam 已登录且该游戏已明确适配可玩，但当前设备未完成游戏包下载；命中后由用户在现有详情页自行获取。 |
| 抽取会话 | Draw session | 用户每次打开盲盒弹窗至关闭弹窗的完整过程；同一会话内“再抽一次”不新建会话。 |
| 有效游玩 | Effective play | 盲盒结果展示后 24 小时内，用户由该结果进入详情并成功启动同一游戏，且单次实际游玩时长达到 5 分钟。 |
| `game_id` | Game identifier | 同一游戏跨个人库、Steam、秒玩和导入来源的统一游戏实体标识。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 游戏盲盒是游戏库内的轻量随机推荐功能，仅负责从当前设备已明确适配可玩的游戏中命中 1 款，不新增游戏获取或启动路径。 |
| 目标用户 | Android 端有效推荐池不少于 2 款，且进入游戏库后没有明确游玩目标的用户。 |
| 核心目标 | 降低选游戏的决策成本，验证随机推荐能否提高成功启动和有效游玩。入口点击、抽取次数和再抽次数只用于解释过程，不作为成功结论。 |
| 使用场景 | 用户进入“我的游戏”，不想逐款浏览和比较，希望快速获得一款适配可玩的游戏建议。 |
| 功能概述 | 游戏库有资格时在列表首位展示盲盒卡；点击后在当前页打开固定弹窗，局部轮换候选信息并命中 1 款；用户可查看详情、再抽一次或关闭；详情页继续沿用现有获取和启动能力。 |

### 2.2 产品流程

**核心流程：** 符合资格的用户进入游戏库 → 点击“游戏盲盒”首位功能卡 → 当前游戏库上打开居中弹窗 → 系统在固定内容位轮换候选并重校验 → 命中 1 款游戏 → 用户查看详情、再抽一次或关闭 → 在现有详情页自行获取或启动。

关键分支：

1. 有效推荐池少于 2 款时，不展示盲盒卡，真实游戏自动补回第一位。
2. Steam 未登录时只使用盖世个人游戏库，不弹出 Steam 登录引导。
3. 结果在展示前失效时，移出该候选并继续抽取；无剩余候选或网络失败时，在原弹窗中展示失败状态，用户可重试或关闭。
4. 命中未下载游戏时不改变弹窗结构；用户点击“查看详情”后在现有详情页自行获取。

| 场景描述 | 用户进入游戏库后没有明确游玩目标，希望从自己当前可玩的游戏中快速获得 1 款建议。 |

| 当前状态 | 进入条件 | 可见内容／可执行操作 | 退出事件 | 下一状态 | 失败与回退 |
|---|---|---|---|---|---|
| 入口不可见 | 有效推荐池少于 2 款 | 不展示盲盒卡；真实游戏从第一位开始 | 刷新后有效推荐池不少于 2 款 | 入口可见 | 候选数量无法获取时保持不可见 |

#### 3.1.2 现有游戏详情

| 要素 | 内容说明 |

| 功能简介 | 承接盲盒命中结果，让用户在现有游戏详情中继续获取、下载或启动，并完成盲盒启动与有效游玩归因。本期不新增详情页可见能力。 |
| 场景描述 | 用户在盲盒命中结果中点击“查看详情”，需要了解或获取该游戏，并按现有方式启动。 |
| 输入／前置条件 | 1. 盲盒已命中并重校验通过唯一游戏结果。<br>2. 跳转时携带命中游戏 `game_id`、抽取会话标识和当前结果序号，只用于页面恢复和数据归因。 |
| 需求描述 | **图示：** 本期不修改现有游戏详情 UI，无新增页面图示。<br>**详细说明：**<br>1. **展示说明：** 游戏名称、封面、简介、标签、兼容结论、获取／下载和启动入口均沿用现有详情页及当前游戏状态；不增加“来自盲盒”、安装状态、新按钮或新提示。<br>2. **交互说明：** 可直接游玩的游戏沿用当前秒玩、Steam 或导入启动逻辑；未下载游戏沿用当前获取和下载流程。盲盒不决定同一游戏的启动方式。用户返回游戏库时，恢复详情跳转前的盲盒命中结果和同轮不重复记录；弹窗不自动重抽。 |
| 输出／后置条件 | 1. 用户未启动游戏并返回时，原盲盒命中结果及抽取会话继续保留。<br>2. 用户在结果展示后 24 小时内从该结果进入详情并成功启动同一游戏时，记录盲盒启动归因；单次实际游玩达到 5 分钟时，记录有效游玩。 |
| 补充说明 | 详情加载失败、下载失败、启动失败、兼容提示、用户取消和状态刷新均沿用现有详情页逻辑；失败不清空当前抽取会话的命中记录。超过 24 小时、启动其他游戏、启动失败或单次游玩不足 5 分钟时，不计入对应的启动或有效游玩转化。 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 新增游戏盲盒埋点，改造已有游戏启动结果埋点，复用已有游戏会话时长埋点及现有成功判定口径。

#### 4.1.1 指标口径

| 指标名称 | 口径（含公式、分子和分母） | 去重与时间窗口 | 数据源与决策用途 |
|---|---|---|---|
| 24 小时启动转化率 | 结果展示后 24 小时内，从该结果进入详情并成功启动同一游戏的用户数 ÷ 获得至少一次有效结果的用户数 | 用户按自然日去重；每次有效结果独立计算 24 小时，用户日粒度只计 1 次转化 | 结果展示事件 + 已有启动结果事件；判断随机推荐是否促进启动 |
| 24 小时有效游玩率 | 结果展示后 24 小时内，从该结果进入详情、成功启动同一游戏且单次实际游玩达到 5 分钟的用户数 ÷ 获得至少一次有效结果的用户数 | 用户按自然日去重；单次游玩达标，同日多次达标只计 1 个用户 | 结果展示事件 + 启动结果事件 + 已有游戏会话时长事件；作为功能的核心效果指标 |
| 查看详情率 | 点击“查看详情”的有效结果次数 ÷ 有效结果展示次数 | 按 `draw_session_id + draw_index` 去重；同一抽取会话 | 结果展示和操作点击事件；解释用户对结果的接受程度 |
| 再抽一次率 | 点击“再抽一次”的有效结果次数 ÷ 有效结果展示次数 | 按 `draw_session_id + draw_index` 去重；同一抽取会话 | 结果展示和操作点击事件；解释结果不接受和连续抽取行为 |

#### 4.1.2 埋点事件

| 事件名称 | 类型 | 对应页面 | 触发时机与成功判定 | 参数 |
|---|---|---|---|---|
| `game_blind_box_entry_expose` | 新增 | C 端／游戏库／盲盒入口卡 | 符合入口资格且盲盒卡实际进入可见区域时上报；同一游戏库页面会话只上报第一次可见 | `orientation, locale, eligible_pool_size, steam_login_state` |
| `game_blind_box_entry_click` | 新增 | C 端／游戏库／盲盒入口卡 | 点击或 A 键确认盲盒卡，客户端接收操作并生成抽取会话时上报 | `orientation, locale, eligible_pool_size, steam_login_state, draw_session_id` |
| `game_blind_box_result_expose` | 新增 | C 端／游戏库／命中结果 | 结果通过重校验、停止轮换且唯一游戏实际展示时上报；每个 `draw_session_id + draw_index` 只上报 1 次 | `orientation, locale, draw_session_id, draw_index, game_id, result_state, weight_class, pool_size, steam_login_state` |
| `game_blind_box_action_click` | 新增 | C 端／游戏库／命中结果 | 客户端接收“查看详情”“再抽一次”或关闭操作时上报；抽取中的禁用按钮不上报 | `orientation, locale, draw_session_id, draw_index, game_id, result_state, action` |
| `game_launch_result` | 改造已有 | C 端／现有游戏详情／启动结果 | 已有游戏启动流程返回成功、失败或用户取消时上报；成功判定沿用现有口径，盲盒来源增加抽取归因参数 | `game_id, launch_result, launch_source, draw_session_id, draw_index, failure_reason` |
| `game_blind_box_effective_play` | 新增 | C 端／现有游戏详情／游戏会话 | 归因游戏的单次实际游玩首次达到 5 分钟时上报；同一抽取结果只上报 1 次 | `game_id, draw_session_id, draw_index, play_duration_bucket` |
| 已有游戏会话时长事件（沿用线上事件名） | 复用已有 | 游戏会话 | 沿用已有游戏会话结束与实际游玩时长上报时机；不因盲盒重复上报，用于校验 5 分钟有效游玩 | `game_id, actual_play_duration_seconds` |

#### 4.1.3 参数说明

| 参数名 | 类型 | 必填 | 说明 | 枚举／示例 |
|---|---|---|---|---|
| `orientation` | string（enum） | 是 | 当前游戏库方向 | `portrait` = 竖屏；`landscape` = 横屏 |
| `locale` | string（enum） | 是 | 当前客户端语言 | `zh-CN` = 简中；`en-US` = 英语；`ru-RU` = 俄语；`ja-JP` = 日语；`pt-BR` = 巴西葡萄牙语 |
| `eligible_pool_size` | integer | 是 | 进入页面时去重与过滤后的有效候选数量 | `12` |
| `steam_login_state` | string（enum） | 是 | Steam 当前登录与库同步状态 | `logged_in` = 已登录并可读取库；`logged_out` = 未登录；`sync_failed` = 已登录但库同步失败 |
| `draw_session_id` | string | 是 | 每次打开盲盒弹窗生成的唯一会话标识 | `a7f...` |
| `draw_index` | integer | 是 | 当前抽取会话内第几次有效结果，从 1 开始递增 | `2` |
| `game_id` | string | 是 | 去重后的统一游戏实体标识 | `silksong` |
| `result_state` | string（enum） | 是 | 结果的内部可用状态，只用于数据分析，不在弹窗展示 | `ready` = 可直接游玩；`uninstalled` = 未下载、需进入详情获取 |
| `weight_class` | string（enum） | 是 | 命中候选的权重档 | `recent_1x` = 30 天内玩过；`inactive_2x` = 超过 30 天未玩；`never_2x` = 可直接游玩且从未启动；`uninstalled_1x` = 未下载 |
| `pool_size` | integer | 是 | 本次抽取时去重与过滤后的候选数量 | `12` |
| `action` | string（enum） | 是 | 用户点击的弹窗操作 | `details` = 查看详情；`redraw` = 再抽一次；`close` = 关闭弹窗 |
| `launch_result` | string（enum） | 是 | 已有启动流程结果 | `success` = 成功；`failed` = 失败；`cancelled` = 用户取消 |
| `launch_source` | string（enum） | 是 | 启动归因来源 | `blind_box_details` = 从盲盒结果进入详情后启动；其他枚举沿用已有定义 |
| `failure_reason` | string（enum） | 否 | 启动失败原因；成功或用户取消时可为空 | 沿用已有启动失败枚举；示例：`engine_failed` = 引擎启动失败 |
| `play_duration_bucket` | string（enum） | 是 | 盲盒归因的有效游玩时长档 | `5m` = 首次达到 5 分钟 |
| `actual_play_duration_seconds` | integer | 是 | 已有游戏会话实际游玩时长，用于复核有效游玩 | `600` |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 性能与动画 | 正常动态效果下约每 100ms 更新一款候选，总时长约 1.2 秒，命中收束约 190ms；开启系统“减少动态效果”时约 180ms 直接命中。仅封面、名称、评分和类型标签可变化，页面、遮罩、弹窗外框、标题、关闭按钮和双按钮不得闪烁或重建。 |
| 兼容性 | 支持 Android 国内版与海外版、竖屏与掌机横屏；横屏使用独立页面结构、弹窗布局和焦点顺序，不通过旋转、拉伸或整体缩放复用竖屏。 |
| 稳定性 | 同一弹窗打开期间，遮罩、弹窗外框、标题、关闭按钮、内容位和双按钮保持同一实例；反复重抽、切换语言和横竖屏后不得出现多弹窗、多结果、整页闪屏或焦点丢失。 |
| 异常降级 | 候选请求、结果校验或封面加载失败时，按第三章的失败、重试和局部底图降级；不得把失效或缓存游戏当作本次有效结果。 |
| 数据一致性 | 候选列表建立前和结果展示前均校验兼容与可用状态；同一游戏跨来源按统一 `game_id` 去重；归因时校验 `game_id + draw_session_id + draw_index` 与 24 小时窗口。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 五语言文案校对 | 校对简中、英语、俄语、日语和巴西葡萄牙语的入口标题与副文案、“随机选择中”、“查看详情”、“再抽一次”、“暂时无法抽取”、“网络异常，请稍后再试”、“关闭”和“暂无评分”。俄语和巴西葡萄牙语按最长文案检查，按钮不得截断核心动词；翻译缺失时不显示空字符串或语言键名。 |
| 内容／素材准备 | 检查客户端已有游戏封面、评分、类型标签和游戏名本地化是否可用。盲盒聚合图和结果不新增、修改或伪造游戏素材。 |
| 指标基线准备 | 数据侧提供符合入口资格用户的历史 24 小时启动率和有效游玩率，产品据此补充功能上线后的目标值；未提供前不编造提升比例。 |

### 4.4 版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 版权需求 | 盲盒功能卡聚合图、轮换内容和命中结果只使用当前客户端已有且允许在盖世游戏内展示的游戏封面、名称、评分和类型标签；不引入第三方新素材。 |

## 五、待确认项

| 待确认问题 | 默认建议 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 客户端／服务端是否已提供跨个人库、Steam、秒玩和导入来源的统一 `game_id` | 复用现有游戏中心统一游戏实体，不在盲盒内建立第二套映射 | 无法稳定去重时，同一游戏可能跨来源重复入池，影响候选、概率、同轮不重复和埋点归因 | 阻塞候选算法与数据开发 |
| 已有启动与游戏会话事件是否能携带盲盒归因，并提供可用的成功启动和实际游玩时长 | 改造已有启动结果事件携带抽取归因，复用已有游戏会话时长口径，不建立第二套启动与时长事件 | 无法准确计算 24 小时启动转化率和有效游玩率，影响数据开发与效果判断 | 阻塞数据开发与数据验收，不阻塞 UI 开发 |
| 符合入口资格用户的历史启动／有效游玩基线及本期目标值 | 先按第 4.1 节口径开发和采集，由数据侧输出历史基线后，产品补充目标值；不用抽取次数替代效果指标 | 不影响业务和 UI 开发，但在目标值确认前无法对功能效果做达成／未达成结论 | 不阻塞 |
