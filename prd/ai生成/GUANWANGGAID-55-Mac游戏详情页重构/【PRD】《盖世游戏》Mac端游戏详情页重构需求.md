## 一、文档概述

### 1.1 背景概述

**需求背景：** Mac 游戏详情页 UI 已确定，需补齐定稿对应的展示、操作和状态说明，供客户端、设计及测试使用。

**当前方式：** 用户通过现有游戏入口查看详情，使用获取、安装、启动、云玩、社区、成就和 MOD 等功能。

**问题：** 新布局尚缺少统一的交互说明，未入库与已入库、入库与安装状态容易混淆。本次整理页面信息和入口位置，复用已有业务能力。

**证据：** 任务说明要求“全部复用现有功能”；新版定稿为 `Downloads/详情页/未入库.jpg`、`已入库.jpg`。本次补充“旧版详情”中的五张旧截图。旧图显示《无主之地3》的 Steam 游戏获取页、兼容性评价详情、讨论区空态／失败态及创意工坊加载态，没有旧已安装启动页。截图中的游戏内容及数值用于表现布局，不作为固定业务规则。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | Mac 客户端游戏详情页，覆盖未入库、已入库两种布局；全局导航与既有组件随页面呈现。不改移动端、游戏库及其他页面。 |
| 业务边界 | 调整信息层级、重排已有元素并承接新版新增展示／入口；底层获取、安装、启动、云玩、游戏设置、社区、成就、商品、兼容性及 MOD 优先复用原功能。旧图未证明的数据和目标在接入前逐项核对，不将“新增展示”扩成新业务。购买、计费、权限、同步、审核和后台规则不在本次重定范围。 |
| 运营边界 | 无新增配置和运营流程；继续使用当前游戏资料、商品、兼容性、社区及 MOD 内容。 |
| 人力边界 | 产品补齐规则与埋点方案，设计核对定稿，Mac客户端重排页面、连接原入口并对齐事件字典，测试及数据侧验证触发和统计口径；服务端维持既有能力，不因本次改版新增业务规则。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 未入库／已入库 | 无 | 当前用户的游戏库中是否已有该游戏记录；取既有入库结果，不按点击按钮或展示截图判断。 |
| 未安装／已安装 | 无 | 当前 Mac 设备、当前所选游戏版本的实际安装状态；已入库不等于已安装。 |
| 原功能 | 无 | 该入口在 Mac 客户端对应的既有能力，包括前置校验、目标页面、执行、结果、取消及失败恢复。 |
| 预览 | 无 | 用于本次 UI 评审的本地演示；点击入口只提示“复用原有功能”，不实际执行业务。 |
| MOD | Modification | 当前游戏的既有 MOD 内容和操作；本次只调整详情页中的展示及入口。 |

## 三、功能需求

### 3.1 C 端功能需求

**旧新对照口径：** “复用”表示旧图已有对应元素；“复用并调整”表示保留内容或能力但调整位置、名称或外观；“新增展示／入口”表示新版详情页增加了这项可见表现，所给旧图没有对应元素，不代表整个客户端没有此能力。新增页面展示仍优先承接现有业务，不因表中“新增”另造算法、支付、发帖或成就体系。截图只能证明可见内容，不能独立证明点击目标、数据来源及权限。

旧版来源包括讨论区失败态及工具、兼容性评价详情、工坊及商品介绍、介绍及讨论空态、详情首屏。原文件见附录。文档按未入库和已入库两页组织，小区域合并，大模块独立配图；各表直接使用元素名称和旧版来源名称。

**交互约定：** 下表写正式产品的展示和操作。所有新增可见入口也只连接原业务目标；目标未由资料证明的，接入前核对。预览全部业务点击仍只 Toast“复用原有功能”，不据表格实现新业务页面。页面内无明确操作外观的字段默认只展示，只有原组件已有点击行为才复用。

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 本轮补充正式产品的新增及改造埋点方案，用于区分未入库／已入库详情的访问、模块触达、操作意图、读取异常及有效停留；业务成功继续取原流程真实结果。此结论替代V1.1的数据范围结论，不改变已定稿页面或业务能力。

#### 4.1.1 上报范围与命名

1. 事件均由正式Mac客户端触发。现有APP链路文档已定义game_detail_view、game_launch_click、instant_play_click，兼容性文档已定义compat_entry_click，作为改造候选；文档存在不等于Mac已经接入。其他四个mac_game_detail_*为新增建议。接入前检查Mac事件注册表：已有等价事件时沿用原名并补齐本文字段，不同时发送两个同义事件；无等价事件时按本文注册。
2. 本节聚焦详情页：主操作、云玩、兼容详情与其他交互分别记录。系统窗口三圆、全局搜索、下载、账号、侧栏及顶栏全局工具继续原埋点，沿用原来源公参；不为详情改版新建同义全局事件。返回和刷新纳入本页交互。
3. 本地Demo不接正式SDK、不发送本文任何事件；Toast、预览状态切换、查看PRD和截图均不计正式曝光、点击或业务成功。

5. 接受操作指原可用控件的有效激活进入处理函数；随后原流程要求登录、资格校验或返回失败，也仍是一次点击事实，不把它删除或改成成功。埋点中的访问/状态边界只用于统计，不驱动新增页面动作。

#### 4.1.5 曝光、去重与统计口径

1. **模块曝光阈值：** 统计模块的有效内容区，不含只剩标题的收起态；可见宽度达到模块宽度的50%，可见高度达到min（模块高度，有效视口高度）的50%，并在前台连续保持1秒才计一次。长介绍、帖子流和商品区按该高度规则处理，不要求整块长内容同时可见。隐藏、遮挡、加载、空态、失败均不计正常内容曝光。
2. **访问与状态切换：** 每个detail_visit_id只对应一个游戏、账号及已确认布局。后台恢复、刷新和尺寸变化不新建访问；真实入库状态变化须先结算旧停留，再以新ID及state_change产生一次新布局访问，避免已入库点击没有相应分母。旧请求的迟到结果只能保留旧ID，不能记到当前访问。
3. **点击独占：** 一个被接受的用户动作只进入一个详情点击事件；点击子按钮不得再触发行点击。一次请求由相同action_id串联，重复回调/补传保留event_id。用户明确再次执行且原组件接受的新动作使用新action_id。快速点击不足1秒仍记录点击，不补造模块曝光；模块点击率只统计点击前已曝光的访问，全部有效点击另按详情访问统计。
4. **真实业务结果：** 下载、启动、云玩、商品交易、发帖及点赞的成功/失败/取消继续由原流程负责；点击不是完成，打开外部程序不是启动成功，下载完成不是入库成功。历史资料中game_download_start／game_download_complete、game_play_success／game_play_fail、cloud_game_enter及pay_result仅作为现行结果核对线索，不照搬APP的5秒/30秒阈值到Mac。若现行Mac结果没有可靠action_id或原请求关联，标记无法归因，不按同游戏+近似时间拼成成功。原结果事件的完整字段沿其原字典，不在本方案重复改造业务终态。
5. **观察窗口：** 页面及模块事件按数据平台业务日统计；本稿建议Asia/Shanghai自然日，接入前与现行看板时区对齐。转化按进入详情的自然日分组，只关联同detail_visit_id及对应action_id的原结果。发起窗要求动作在原访问存续期间且入页后24小时内被有效接受；结果窗截止入页后24小时。访问结束不截断已发起动作的可靠异步结果归因，不要求结果发生时详情仍可见。未满24小时且仍有未决操作的分组标观察中，缺失/未知不补成失败。

#### 4.1.6 数据验证与接入约束

1. 两种布局分别进入、滚动、返回重入；确认view每visit一次，模块按阈值曝光一次，刷新/后台恢复不重复。未入库后真实入库变化生成新visit；安装中与已安装不得改变入库事实。
2. 骨架、成功空集合、读取失败、显式重试及旧请求迟到分别核对。只有原真实终态才报module_result，loaded与empty、failed互斥；正常曝光不得由空态或错误占位触发。
3. 主操作、云玩、兼容入口及34种其他交互逐一检查；一次点击不得专属/通用双报，不得按钮/卡片冒泡双报。核对target_type、真实ID、位置及请求选项，不将选项请求当已成功。
4. 前台停留→后台→恢复→返回，逐段时长之和只含有效可见时间；背景不重复结算，补传保持段ID。关闭异常没有可靠最后一段时保留缺失，不补0或按最后日志倒推。
5. 对获取/安装/启动/云玩、社区和交易分别核对原流程结果及取消/失败：Toast、弹窗打开、外部应用唤起或下载完成不得偷换为其他成功。确认关联ID可用后再使用转化指标，并检查异步结果归属原访问。
6. 检查32个参数的类型、枚举和条件必填；缺稳定内容ID允许null但不计算对象级去重，失败原因只用归一编码。历史字段名/来源/方向有差异时先形成明确映射并同步字典，本稿不能代替真实SDK上报验收。Demo应保持无正式事件请求。
