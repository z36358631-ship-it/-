# 【PRD】盖世启动台首次使用反馈与 Dock 入口优化



## 一、文档概述



### 1\.1 背景



- 用户从 GameHub 打开启动台时，客户端缺少加载和转场反馈，主页直接消失，用户无法判断是否触发成功。

- 用户首次进入后不清楚启动台的用途、返回方式和设置入口。

- 启动台与 GameHub 图标识别度不足，Dock 入口缺少首次激活反馈。



### 1\.2 需求目标



1. 用户点击后立即获得“正在打开”反馈。

2. 首次进入时，让用户知道启动台的用途、返回方式和设置入口。

3. 通过真实控件完成引导，帮助用户添加 Dock 快速入口。

4. 提高启动台 Dock 图标的辨识度，与 GameHub 主应用区分。



### 1\.3 需求边界



|边界类型|范围|
|---|---|
|客户端|macOS GameHub 客户端、盖世启动台及 Dock 入口|
|本期包含|打开反馈、首次进入引导、设置入口引导、Dock 开关、Dock 首次激活动效、返回 GameHub|
|本期不包含|启动台应用列表、搜索、分组、排序和数据源改造；Windows 端适配|



### 1\.4 术语



|术语|定义|
|---|---|
|启动台|全屏展示并打开本机应用的 GameHub 功能|
|首次进入|当前引导版本下，用户首次成功进入启动台|
|Dock 入口|位于 macOS Dock 中、可直接打开盖世启动台的独立图标|
|引导版本|用于控制新版引导是否需要再次展示的版本标识|



## 二、产品方案



### 2\.1 核心流程



`新版本入口显示红点 → GameHub 点击启动台，红点消失 → 显示打开反馈 → 启动台淡入 → 首次使用引导 → 点击“…” → 点击“设置” → 开启“添加到程序坞” → Dock 图标跳动并显示名称`



### 2\.2 方案概述



|阶段|用户感知|系统行为|
|---|---|---|
|新版本红点|发现启动台新功能|按客户端本地版本展示一次，点击入口后立即消失|
|打开反馈|明确已经点击成功|保留 GameHub 主页作为背景，居中显示“正在打开盖世启动台…”|
|首次进入|理解功能和返回方式|启动台淡入、缩放出现，显示首次使用引导|
|设置引导|按照提示完成真实操作|依次高亮“…”、“设置”和“添加到程序坞”开关|
|Dock 激活|确认快速入口已生效|专用图标跳动 3 次，并显示“盖世启动台”|



## 三、功能需求



### 3\.1 新版本一次性红点



|项目|需求|
|---|---|
|展示条件|客户端升级到包含启动台的目标版本，且本地已读版本小于当前红点版本|
|展示位置|GameHub 左侧启动台九宫格入口右上角|
|消失时机|用户点击启动台入口时立即消失，不以启动台打开成功为前提|
|存储维度|按客户端本地记录 `launchpad_badge_seen_version`；不关联用户 ID，不上传云端|
|账号规则|同一客户端上切换或退出账号，红点不再出现|
|版本规则|后续客户端需要再次提示时，提升红点版本号；重装或更换设备后按新客户端处理|



### 3\.2 点击后的打开反馈



|要素|需求|
|---|---|
|触发|用户从 GameHub 主入口或 Dock 入口打开启动台|
|即时反馈|点击后立即显示 Loading，文案为“正在打开盖世启动台…”|
|背景|启动台准备完成前，保留当前 GameHub 页面，不显示空白页或桌面|
|转场|准备完成后，Loading 消失，启动台以透明度 `0→1`、缩放 `0.96→1` 的方式进入，建议时长 300–450 ms|
|完成条件|以启动台数据和界面实际就绪为准，不使用固定时长代替加载状态|



#### 异常处理



|异常|处理|
|---|---|
|加载失败|关闭 Loading，保留原 GameHub 页面，提示“启动台打开失败，请重试”|
|重复点击|Loading 期间忽略重复触发，不创建多个启动台实例|
|启动台已打开|将已有窗口置前，不重复初始化|



### 3\.3 首次进入引导



#### 3\.3\.1 第一步：功能说明



|项目|需求|
|---|---|
|展示条件|用户当前引导版本未完成或未跳过|
|标题|已进入盖世启动台|
|正文|在这里浏览、搜索并打开电脑上的应用。按 `Esc` 返回 GameHub。|
|操作|“跳过引导”、“认识设置入口”|
|交互|点击“认识设置入口”进入第二步；点击“跳过引导”结束引导|



#### 3\.3\.2 第二步：设置入口



|项目|需求|
|---|---|
|引导文案|从这里找到设置|
|第一个目标|遮罩其他区域，高亮搜索框右侧“…”按钮；用户须点击真实按钮继续|
|第二个目标|菜单展开后隐藏引导卡片，高亮真实“设置”菜单项|
|进入设置|点击“设置”后打开设置窗口，移除页面引导卡片和遮罩|
|原则|不使用脱离真实控件的“知道了”按钮跳过操作|



### 3\.4 添加到 Dock



|项目|需求|
|---|---|
|入口|启动台右上角“…” → “设置” → “添加到程序坞”|
|默认状态|关闭|
|引导提示|开关旁显示“添加到程序快速启动”，指向开关，不遮挡设置内容|
|开启动效|开关从左向右滑动，状态色由灰色变为 GameHub 主题红|
|开启结果|在 macOS Dock 中创建“盖世启动台”独立入口，并保存开关状态|
|关闭结果|从 Dock 移除启动台入口；不影响 GameHub 内的启动台入口|
|失败处理|开关恢复原状态，提示“添加失败，请重试”|



### 3\.5 Dock 首次激活



|项目|需求|
|---|---|
|图标|使用启动台九宫格图标，右下角叠加 GameHub 品牌角标；角标必须完整收在主图标边界内|
|规格|512×512 px，透明背景，符合 macOS 图标边距|
|名称|盖世启动台|
|触发条件|用户首次成功开启“添加到程序坞”|
|动效|Dock 图标连续跳动 3 次后停止|
|名称提示|跳动时在图标上方显示“盖世启动台”，样式参照 macOS Dock 名称气泡|
|重复规则|仅首次成功添加时跳动；后续普通启动不重复播放|
|点击行为|直接打开盖世启动台；已打开时将启动台置前|



### 3\.6 返回 GameHub



|项目|需求|
|---|---|
|操作|用户按 `Esc`|
|结果|关闭或隐藏启动台，返回进入前的 GameHub 窗口|
|状态保留|GameHub 恢复原页面、滚动位置和已打开内容，不重新加载首页|
|引导期间|按 `Esc` 优先关闭当前设置窗口；无弹窗时返回 GameHub|



### 3\.7 引导展示规则



|场景|处理|
|---|---|
|首次进入当前引导版本|显示完整引导|
|完成 Dock 开关操作|记录当前引导版本为已完成|
|点击“跳过引导”|记录当前引导版本为已跳过，当前版本不再自动展示|
|中途退出且未跳过|不记录完成，下次进入从第一步重新展示|
|引导版本升级|可再次展示；是否升级由客户端版本配置决定|
|普通再次进入|不展示引导，直接进入启动台|



## 四、状态与优先级



### 4\.1 界面优先级



|当前状态|`Esc` 行为|其他操作|
|---|---|---|
|Loading|取消本次打开并返回 GameHub|忽略重复打开|
|首次引导|返回 GameHub，不记录完成|仅当前高亮目标可继续引导|
|更多菜单|关闭菜单|点击“设置”进入下一步|
|设置窗口|关闭设置窗口|开启或关闭 Dock 入口|
|启动台默认态|返回 GameHub|正常浏览、搜索和打开应用|



### 4\.2 视觉与文案规则



|项目|要求|
|---|---|
|主色|GameHub 主题红 `#FF4D4F`|
|引导卡片|深色半透明背景、白色标题、中性灰正文，与 GameHub 深色界面一致|
|高亮|红色描边及外发光；同一时刻仅高亮一个主操作|
|遮罩|降低非当前目标区域亮度，不改变原页面布局|
|按钮|主操作使用红色，次操作使用中性灰；焦点状态可见|
|动效降级|开启系统“减少动态效果”时，取消缩放和跳动，保留淡入与文字提示|



## 五、数据埋点



|事件|触发时机|核心参数|
|---|---|---|
|`launchpad_badge_view`|新版本红点展示|`badge_version`, `client_version`|
|`launchpad_badge_consume`|用户点击启动台入口，红点消失|`badge_version`, `client_version`|
|`launchpad_open_click`|点击 GameHub 或 Dock 启动台入口|`entry_source`, `guide_version`|
|`launchpad_open_result`|启动台打开成功或失败|`entry_source`, `result`, `duration_ms`, `failure_code`|
|`launchpad_guide_view`|首次引导步骤展示|`guide_version`, `step`|
|`launchpad_guide_action`|点击引导目标或跳过|`guide_version`, `step`, `action`|
|`launchpad_dock_toggle_result`|Dock 开关返回结果|`target_state`, `result`, `failure_code`|
|`launchpad_dock_first_activation`|Dock 入口首次激活|`guide_version`|
|`launchpad_exit`|通过 `Esc` 返回 GameHub|`source_state`, `stay_duration_ms`|



### 5\.1 参数取值



|参数|取值|
|---|---|
|`badge_version`|当前一次性红点版本号|
|`client_version`|当前 GameHub 客户端版本|
|`entry_source`|`gamehub` / `dock`|
|`result`|`success` / `fail`|
|`step`|`intro` / `more` / `settings` / `dock_toggle`|
|`action`|`next` / `target_click` / `skip` / `exit`|
|`target_state`|`on` / `off`|
|`failure_code`|`load_failed` / `dock_add_failed` / `dock_remove_failed` / `unknown`|



## 六、技术与非功能要求



|需求项|要求|
|---|---|
|状态持久化|客户端本地保存红点已读版本、引导版本、完成／跳过状态和 Dock 开关状态；红点状态不按账号分开存储|
|幂等|重复打开、重复开启 Dock 入口不创建重复实例或图标|
|性能|点击后 100 ms 内出现可见反馈；转场期间不阻塞主线程|
|可访问性|所有可操作控件支持键盘焦点；文字与背景对比度不低于 4\.5:1|
|系统兼容|尊重 macOS “减少动态效果”设置；Dock 能力按当前支持的 macOS 版本验收|
|日志|记录启动失败和 Dock 增删失败，不记录用户本机应用列表|



## 七、验收标准



|编号|场景|验收结果|
|---|---|---|
|AC\-00|目标版本首次启动 GameHub|启动台入口显示红点；点击后立即消失，切换账号或重启客户端均不再显示|
|AC\-01|从 GameHub 点击启动台|100 ms 内显示“正在打开盖世启动台…”，主页在准备完成前保留|
|AC\-02|启动台准备完成|Loading 结束，启动台淡入并完成缩放转场|
|AC\-03|首次进入当前引导版本|显示功能说明、`Esc` 返回方式和“认识设置入口”|
|AC\-04|进入设置引导|用户须依次点击真实“…”和“设置”控件，页面无“知道了”替代操作|
|AC\-05|打开设置|Dock 开关旁显示“添加到程序快速启动”，不遮挡设置内容|
|AC\-06|首次开启 Dock 入口|开关滑动到开启状态，Dock 出现专用图标，图标跳动 3 次并显示“盖世启动台”|
|AC\-07|点击 Dock 图标|直接打开或置前盖世启动台|
|AC\-08|按 `Esc`|按状态优先级关闭弹窗、菜单或启动台，返回前恢复 GameHub 原状态|
|AC\-09|再次进入|已完成或已跳过当前版本引导时，不再自动展示|
|AC\-10|异常与重复触发|不出现空白页、重复窗口或重复 Dock 图标；失败后可重试|
