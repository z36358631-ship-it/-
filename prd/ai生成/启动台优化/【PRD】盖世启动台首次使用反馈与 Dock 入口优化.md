## 一、文档概述

### 1.1 背景概述

- **需求背景：** GUANWANGGAID-57“启动台优化”调整 macOS 客户端的启动台入口和首次使用路径。
- **当前方式：** 旧方案从客户端侧边栏进入启动台，再从启动台设置添加 Dock 入口。
- **问题：** 客户端直接入口与 Dock 入口路径重复；首次使用前缺少清晰的启用说明，打开过程和返回方式也需提供反馈。
- **本期方向：** 从客户端设置启用 Dock 入口，成功后自动进入启动台，并用真实控件完成使用引导。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | macOS GameHub 客户端主页、客户端设置、盖世启动台及 macOS Dock；不涉及 Windows、Web 或后台页面 |
| 业务边界 | 移除侧边栏启动台入口及红点；客户端设置启用 Dock；打开反馈、两类引导、Dock 首次激活、返回及异常恢复；应用列表、搜索、分组、排序、应用来源、快捷键与其他既有唤起能力沿用 |
| 运营边界 | 无新增运营配置、推广、报表或指标 |
| 人力边界 | 产品定义规则；UI 处理客户端设置与引导的视觉融合；客户端实现原生 Dock、窗口、状态与事件；测试验证主链路、失败、重复触发及状态恢复 |

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 启动台 | Launchpad | 全屏展示并打开本机应用的 GameHub 功能 |
| 程序坞入口 | Dock entry | macOS Dock 中名为“盖世启动台”的独立图标，点击后打开或置前启动台 |
| 入口介绍与设置提示 | 无 | 首页介绍实际展示即记已读；“去设置”定位原行并展示遮罩提示。关闭提示不要求添加，通知已读与 Dock 选择分开保存 |
| 使用引导 | 无 | 启动台实际打开后介绍用途和返回，再引导真实“…”→“设置”；实际到达启动台设置为完成 |
| 引导版本 | Guide version | 入口通知与使用引导各自维护的版本标识；入口通知记录已读，使用引导记录完成或跳过，互不替代 |
| 首次激活 | First activation | 当前客户端本地记录中第一次成功添加 Dock 入口；后续关闭再开启不重新计算首次 |

**Dock 开关状态流转**

| 状态 | 进入／退出 | 表现与操作 | 结果与恢复 |
|---|---|---|---|
| 关闭 `off` | 无记录或成功移除后；点击开启进入添加中 | 灰色关闭；两处设置均可请求开启 | 入口不存在；添加失败仍关闭 |
| 添加中 `adding` | 收到有效开启请求；原生操作返回后结束 | 保留原状态，暂禁两处开关和关闭设置操作 | 成功进入开启；失败回关闭 |
| 开启 `on` | 添加成功或沿用已有开启记录；点击关闭进入移除中 | 红色开启；两处设置均可请求关闭 | 入口存在；客户端设置开启成功后自动打开启动台 |
| 移除中 `removing` | 收到有效关闭请求；原生操作返回后结束 | 保留原状态，暂禁两处开关和关闭设置操作 | 成功进入关闭；失败回开启 |

添加、移除、成功保存与失败恢复规则与客户端设置一致，两处实时显示同一状态。这里关闭只移除入口；这里重新开启只恢复 Dock，不另行打断或重开当前启动台。<br>6. **返回：** 按 Esc 先关闭当前设置窗口；无设置时先关闭更多菜单；无上述层时退出启动台，恢复进入前 GameHub 页面、滚动位置和已打开内容，不重新加载首页。 |
| 输出／后置条件 | 打开成功：启动台可用，满足条件时展示使用引导；使用引导成功：真实设置已打开且当前版本完成；返回后恢复原 GameHub 状态，Dock 开关按其独立结果保留 |
| 补充说明 | 1. **打开失败：** 结束 Loading，保留原 GameHub 页面，提示“启动台打开失败，请重试”；已成功添加的 Dock 入口与开启状态不回滚，用户可从 Dock 重试。[打开失败图](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@44322d5358cd5ed423d79c46e749f14fc64341ae/public/prd/guanwanggaid-57-launchpad-20261014/12-open-failed.png)。<br>2. **打开取消：** 首次 Dock 激活反馈期间按 Esc，取消待执行的自动打开；此时未发起实际打开请求，不产生打开触发、打开结果或启动台退出事件。Loading 中按 Esc 则取消本次有效打开并记录取消结果。两种情况均回到原 GameHub 页面，不撤销已添加的 Dock、不重置首次激活或通知已读、不完成使用引导；取消后该次等待或迟到就绪结果不得再打开启动台。<br>3. **引导中断：** 未完成且未跳过时离开启动台，不记完成；下次成功进入从功能介绍重新开始。按 Esc 仅关闭菜单时回到“…”引导，仍未完成。<br>4. **设置增删失败：** 保持操作前开关及入口，在当前启动台设置显示“添加失败，请重试”或“移除失败，请重试”，允许重试，不退出启动台。<br>5. **版本与账号：** 两类引导按各自版本保存；入口通知实际展示后不自动重播，使用引导完成或跳过当前版本后不自动重播。只有对应通知或使用引导版本提升才可重新提示；客户端重启、退出或切换账号不重置本地状态。<br>6. **动态效果与焦点：** 系统减少动态效果开启时取消缩放，保留淡入和文字反馈；键盘焦点可见。引导高亮不改变原页面布局，同一时刻只高亮一个主目标。 |

**启动台状态与返回**

| 状态 | 进入／退出 | 表现与操作 | 结果与恢复 |
|---|---|---|---|

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 改造／复用。保留原打开、引导、Dock 操作、首次激活及退出事件的统计用途；删除 `launchpad_badge_view`、`launchpad_badge_consume` 与 `badge_version`；原 `launchpad_open_click` 改为 `launchpad_open_trigger`，同时覆盖自动触发、Dock 点击和既有快捷键。本轮不新增指标、报表或后台配置；Demo 未接入真实数据上报。

#### 4.1.1 埋点事件

| 事件 | 页面／类型 | 触发与成功 | 参数 |
|---|---|---|---|
| `launchpad_open_trigger` | C 端／客户端设置、Dock、既有快捷键；改造 | 接受一次有效打开或置前请求时上报一次；客户端设置开启成功后由系统触发，Dock 为用户点击，既有快捷键为用户键盘操作。加载期间被忽略的重复请求不上报。以该次请求为去重单位，不按账号另拆 | `entry_source`, `guide_version` |
| `launchpad_open_result` | C 端／启动台；改造 | 每次有效请求仅上报一个终态：实际可见且可操作为成功，实际加载失败为失败，Loading 中 Esc 为取消；已有窗口置前后可见也为成功。时间从接受请求到终态，迟到回调不得重复上报 | `entry_source`, `result`, `duration_ms`, `failure_code` |
| `launchpad_guide_view` | C 端／客户端主页、常规设置、启动台；改造 | 引导步骤实际可见时上报；同一次有效步骤展示只报一次，单纯重绘不重复。下一次合法重展示可再次上报；通知已读后不自动重播首页卡，使用引导完成或跳过后不重播；同一次“去设置”导航仍可展示设置提示 | `guide_type`, `guide_version`, `step` |
| `launchpad_guide_action` | C 端／客户端主页、常规设置、启动台；改造 | 真实目标操作、下一步、跳过或关闭当前可见提示时上报一次；入口介绍实际曝光或设置新增行实际可见使通知首次变为已读时上报 `complete`，同一通知版本只报一次；使用引导实际到达真实设置才上报 `complete`。介绍已读后仍允许上报当前卡片或设置提示的点击、关闭；Dock 添加成功或失败不改变已读结果。每个有效操作或完成结果去重 | `guide_type`, `guide_version`, `step`, `action` |
| `launchpad_dock_toggle_result` | C 端／客户端设置、启动台设置；改造 | 一次有效添加／移除请求返回时上报一次；以系统 Dock 实际添加／移除成功判定，失败保持原状态。处理中被忽略的操作不报，打开结果另报 | `toggle_source`, `target_state`, `result`, `failure_code` |
| `launchpad_dock_first_activation` | C 端／Dock；复用 | 当前客户端第一次实际添加成功后上报一次并保存激活记录；减少动态效果取消跳动仍算首次添加成功；关闭再开启不重复，打开失败不回滚 | `guide_version` |
| `launchpad_exit` | C 端／启动台；改造 | Esc 真正离开启动台、取消 Loading，或更多菜单“退出启动台”时上报一次；仅关闭设置或菜单不报退出。一次打开请求到退出构成一个本地访问过程 | `source_state`, `exit_method`, `stay_duration_ms` |

#### 4.1.2 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| `entry_source` | enum／是 | 引发本次有效打开请求的入口 | `client_settings`＝客户端设置由关开启成功后的自动打开；`dock`＝点击 Dock 入口；`shortcut`＝使用已配置快捷键 |
| `guide_type` | enum／是 | 本次展示或操作所属引导 | `enable`＝入口介绍与设置提示；`usage`＝启动台使用引导 |
| `guide_version` | string／是 | 引导事件取对应 `guide_type` 的当前版本；打开触发和首次激活取当前使用引导版本，不表示已完成 | 示例：`enable_v2`、`usage_v2`；版本由客户端现有版本策略确定 |
| `step` | enum／是 | 引导的实际步骤；须与引导类型匹配 | `announcement`＝首页入口介绍；`client_dock_toggle`＝客户端 Dock 开关提示；`intro`＝使用引导的用途介绍；`more`＝使用引导的真实更多按钮；`settings`＝使用引导的真实设置菜单项 |
| `action` | enum／是 | 一次实际引导操作或完成结果；目标点击和其后成功完成可分别上报，不能相互替代 | `target_click`＝点击入口介绍“去设置”或设置提示中的客户端开关，或使用引导点击真实更多／设置目标；`next`＝使用引导点击“认识设置入口”；`skip`＝使用引导点击“跳过引导”；`exit`＝关闭入口介绍或设置提示，或未完成、未跳过使用引导时离开启动台；`complete`＝首页介绍实际展示或常规设置新增行实际可见后记通知已读，或使用引导实际到达启动台设置 |
| `toggle_source` | enum／是 | 发起 Dock 添加或移除请求的设置页面 | `client_settings`＝客户端设置；`launchpad_settings`＝启动台既有设置 |
| `target_state` | enum／是 | 本次请求希望达到的 Dock 开关状态 | `on`＝开启／添加入口；`off`＝关闭／移除入口 |
| `result` | enum／是 | 本次操作终态；Dock 操作仅使用成功或失败，打开结果可使用取消 | `success`＝窗口实际就绪／置前可见，或 Dock 操作实际成功；`fail`＝本次操作失败；`cancel`＝本次打开被用户在 Loading 中按 Esc 取消 |
| `failure_code` | string／是 | 终态原因；成功和取消时传空字符串，失败时必须传已定义错误值；Dock 错误不写入打开结果 | `load_failed`＝启动台加载失败；`dock_add_failed`＝Dock 添加失败；`dock_remove_failed`＝Dock 移除失败；`unknown`＝未识别的失败；`""`＝成功或取消，没有失败原因 |
| `duration_ms` | int／是 | 本次有效打开请求从被接受到成功、失败或取消的耗时；置前按请求到窗口可见计算，非负 | 示例：`420`，单位毫秒；同一请求只计算一次 |
| `source_state` | enum／是 | 真正离开或取消前的启动台状态；不是返回到的页面 | `loading`＝打开中；`intro`＝使用引导介绍；`more_guide`＝更多按钮引导；`more_menu`＝更多菜单；`default`＝启动台默认态。按 Esc 仅关闭菜单／设置时不产生退出事件，因此设置窗口不属于退出来源值 |
| `exit_method` | enum／是 | 导致真正退出或打开取消的操作 | `esc`＝按 Esc；`more_menu`＝点击更多菜单中的“退出启动台” |
| `stay_duration_ms` | int／是 | 本次可见打开反馈开始至真正退出的持续时间，含打开等待及启动台使用；Loading 取消计算到取消，已有窗口置前不重置当前未结束访问过程，非负 | 示例：`12500`，单位毫秒；同一访问过程只上报一次退出 |

事件保留原有客户端通用上下文，不另建账号维度状态；本期不新增指标分母或统计窗口。`enable` 使用 `announcement`、`client_dock_toggle`；`usage` 使用 `intro`、`more`、`settings`。通知已读完成使用实际曝光的 `announcement` 或 `client_dock_toggle`，同一通知版本只报一次，使用完成使用 `settings`。入口介绍与设置提示的 `action` 仅允许 `target_click`、`exit`、`complete`；使用 `intro` 允许 `next`、`skip`、`exit`，`more` 允许 `target_click`、`exit`，`settings` 允许 `target_click`、`complete`、`exit`。普通设置新增行实际可见但未展示提示时，仍可上报一次 `enable`／`client_dock_toggle`／`complete` 表示通知已读，不报提示曝光或目标点击。通知已读完成事件按实际曝光上报；其余引导操作只在对应卡片、提示或使用引导实际可见时上报，普通开关操作只报 Dock 结果。退出事件仅在真实离开时产生，关闭层不增加一次访问。

| 需求项 | 具体要求 |
|---|---|
| 性能 | 有效打开请求后 100 ms 内提供可见反馈，转场不阻塞主线程；生产环境以界面和数据实际就绪结束 Loading，不使用 Demo 固定 1.6 秒代替真实状态 |
