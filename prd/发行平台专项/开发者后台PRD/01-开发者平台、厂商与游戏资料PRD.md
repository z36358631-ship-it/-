## 一、文档概述

### 1.1 背景概述

- **需求背景：** 新发行平台一期以独立主体、独立域名、独立数据库和独立开发者账号运行，需让首个已签约厂商完成 Game 建档、APPID 创建、SDK 获取和资料提交，为 CDKEY、包体发行、投放及数据提供统一上游对象。
- **当前方式：** 合同、主体资质、定价和上架审核在线下完成；游戏资料、APPID、SDK、包体和发行结果尚未在独立开发者平台形成统一主线。现有盖世后台和社区可提供通用组件及评论能力，但不能作为新平台账号或业务数据库直接复用。
- **问题：** 若沿用盖世玩家账号、原后台数据库或在线商务审核，会混淆主体与权限；若 Game、APPID、商品、包体和数据没有统一关系，下游将各自生成游戏标识；若继续按 Windows 单系统和自建标签库设计，会与一期三系统和 Steam 全量标签结论冲突。
- **证据：** 2026-09-01《游戏平台进度会》确认独立平台边界、Windows／Mac／Linux、线下商务审核、Google Docs 文档托管、Steam 全量标签、最小 SDK 及首次授权后离线运行；本次开发者后台专项不新增独立 C 端页面。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 本文只包含 B 端：首次介绍与独立开发者账号登录、工作台、厂商资料、游戏列表、创建／编辑游戏、APPID 与 SDK 接入、资料线下结果，以及平台侧账号配置、厂商线下资质结果录入、游戏资料与上架线下结果录入，共 10 个业务页面。Google Docs 只作为外部文档入口，不在平台内建设内容中心。CDKEY、包体、投放和发行数据仅展示入口或状态摘要。 |
| 业务边界 | [已确认] 一期先服务首批已签约厂商和试点 Game，但数据模型不得写死单厂商／单游戏：一个开发者账号绑定唯一厂商，一个厂商可管理多个 Game，一个 Game 创建一个平台 APPID。APPID 连接 SDK、商品、包体和数据。游戏资料支持 Windows、Mac、Linux，无移动端。合同、主体资质、定价和上架审核在线下完成，后台只录入结果和依据摘要；下游只读取有效结果及已确认资料快照。 |
| 运营边界 | 平台发行运营创建、启停独立开发者账号，录入线下合同／资质／上架结果，核对授权地区及合作范围；不在本文建设在线合同、自动资质审核、定价审批或上架审批。游戏、商品、版本和投放的实际生效由对应流程执行。 |
| 人力边界 | 已签约厂商维护本厂商与游戏资料、创建 APPID 并下载 SDK；商务／法务在线下完成合同与资质审核，发行运营录入结果；SDK 团队维护三系统 SDK 包及 Google Docs；服务端、测试和数据人员分别承担平台隔离、业务能力、验证及数据采集。 |

#### 一期明确不包含

1. 公众注册、开发者申请入驻和开放生态。
2. 合作方自行创建成员、角色分级或复杂权限配置。
3. 在线合同签署、自动资质审核、在线定价／上架审批、合同文件管理、结算账户、自动分账和提款。
4. 独立 C 端厂商主页、游戏详情改造、厂商主页装修、私域运营、测试招募和内容发布；游戏评论继续复用社区后台，不在开发者平台重复建设。
5. 开发者直接发布游戏、商品、版本或投放计划。
6. 将既有包体管理流、CDKEY 供给页、投放页或数据看板定义为本文页面。
7. 组织成员自助管理、角色自定义、IP 白名单、多项目凭证、通用 OpenAPI 管理和移动端包体。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 受邀账号 | Invited Account | 由平台发行运营代建并绑定唯一厂商的登录账号；无公众注册入口。 |
| 独立开发者账号 | Developer Account | 由新发行平台账号系统维护的合作方账号；不复用盖世玩家账号、社区账号会话或原运营后台账号。本文中的“受邀账号”均指该账号。 |
| Game | Game | 新发行平台的游戏主对象，归属唯一厂商；连接资料、APPID、商品、包体、投放和发行数据。 |
| APPID | Application ID | 一个 Game 在新发行平台中的公开应用标识；一期一个 Game 只创建一个 APPID，不等同于 Steam AppID，也不是密钥。 |
| 厂商资料版本 | Publisher Profile Revision | 厂商名称、Logo、简介、官网和联系信息组成的一次提交快照；待线下结果时不可覆盖，需修改后基于原输入修订。 |
| 游戏资料版本 | Game Profile Revision | 游戏基本资料、宣传素材、语言、地区、系统要求、标签和发行方式组成的一次提交快照。 |
| 已确认快照 | Confirmed Snapshot | 最近一次由运营录入线下确认结果、可供下游商品、版本、投放或既有 C 端读取的厂商／游戏资料；新修改待线下结果期间继续使用上一有效快照。 |
| 关键资料 | Critical Profile Fields | 会改变用户识别、发行范围或交付判断的字段，包括厂商公开资料，以及游戏名称、素材、简介、语言、地区、系统要求、标签和发行方式。 |
| 游戏标签 | Steam Tag | 复用 Steam 全量标签字典中的标签 ID 与名称；开发者从完整字典选择，平台不自建平行标签或新增自定义标签。仅线下确认后录入的最终标签可用于展示和投放。 |
| 线下审核结果 | Offline Review Result | 商务、法务或发行运营在线下完成合同、主体资质、定价或上架判断后，由有权限运营录入的结果、原因摘要、审核人和时间；后台不自动做出审批结论。 |
| 发布前置 | Release Prerequisite | 资料结果确认为可用后仍须满足的商业条件，包括有效发行授权、发行地区在授权范围内及合同合作范围覆盖本游戏；价格、分成和结算责任由商品发布流程继续读取线下确认结果。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向首批受邀签约厂商的独立开发者平台基础、Game→APPID 接入与资料结果闭环，为后续商品、包体和投放提供统一上游对象。 |
| 目标用户 | 已签约厂商的开发者账号、平台发行运营。 |
| 核心目标 | 合作方使用独立账号完成厂商与三系统游戏资料、APPID 和最小 SDK 接入；运营录入线下合同／资质／上架结果；所有下游共用同一 Game 与 APPID。 |
| 使用场景 | 平台为签约厂商代建独立账号；合作方完成 Game 资料后创建 APPID，下载 Windows／Mac／Linux SDK 并从 Google Docs 查看文档；运营把线下审核结果录入系统，满足前置后进入 CDKEY 或包体流程。 |
| 功能概述 | 独立账号、Game 建档、APPID、SDK 下载、外部文档、线下结果录入、Steam 标签和已确认快照组成上游闭环。 |

#### 共享对象关系

| 对象 | 归属与数据范围 | 本文状态 | 后续去向 |
|---|---|---|---|
| 合作方账号 | 平台创建并绑定唯一厂商；合作方只读自身绑定关系 | 已启用、已停用 | 登录开发者工作台或被拒绝登录 |
| 厂商资料 | 合作方维护本厂商；运营只录入签约范围内对象的线下结果 | 草稿、待线下结果、需修改、已确认 | 已确认快照供下游业务和既有 C 端读取 |
| 游戏项目与资料 | 合作方只见本厂商游戏；运营只录入签约范围对象的线下结果 | 草稿、待线下结果、需修改、已确认，以及后续发布状态摘要 | 资料确认为可用后进入 CDKEY 供给或包体版本准备 |
| 游戏标签 | 开发者从 Steam 全量标签选择；运营按线下结论录入最终结果 | 未确认、已确认 | 已确认标签用于 C 端展示和正式投放规则 |
| APPID | 归属一个 Game；开发者创建并只读查看 | 未创建、正常、已停用 | SDK 初始化、首次启动授权、商品、包体与发行数据共同引用 |

#### 竞品借鉴结论

| 竞品 | 已核对能力 | 一期可借鉴 | 一期不采用 |
|---|---|---|---|
| Steamworks | Partner onboarding、Application、商店资料与发行清单 | 以游戏项目为中心组织资料；分步骤呈现完成状态；审核前明确缺失项 | 公开接入、协议在线签署、产品提交费、税务和银行账户流程 |
| WeGame 开发者平台 | 公司账号与资质、游戏注册、资料提交、协议、开发接入与测试／发行能力 | 公司、Game 与 APPID 分层；接入步骤和结果状态清晰；SDK 与文档从游戏上下文进入 | 公众注册、在线协议、在线资质／定价／上架审批、复杂组织权限 |
| TapTap 开发者中心（登录后受限实测） | 当前个人开发者账号可见游戏 ID、Client ID／Token／Secret、公钥、移动端签名配置和服务能力入口 | 借鉴“应用上下文＋凭证摘要＋能力入口”的信息结构；未开放页面统一标记待验证 | 把移动端包名／证书字段、完整服务开关或未验证后台能力直接搬入 PC 一期 |
| 本期方案 | 独立受邀账号、账号绑定单厂商、厂商下多 Game、每个 Game 对应唯一 APPID、线下审核结果录入 | 保留对象与步骤清晰，并以 Google Docs 降低一期文档系统成本 | 不复制开放生态、在线商务审批或通用凭证平台 |

#### 后台生效结果与下游影响（非页面范围）

| 后台结果 | C 端消费规则 | 异常与恢复 |
|---|---|---|
| 厂商／游戏资料首次确认为可用 | 仅向既有游戏详情及后续发行链路提供已确认快照；本文不新增厂商主页或详情页面 | 无已确认快照时不得把草稿、待线下结果或需修改内容暴露到 C 端 |
| 已确认资料再次修改 | 待线下结果期间继续使用上一有效快照；新结果确认为可用后原子切换新快照 | 切换失败继续使用上一有效快照并记录同步异常，不出现半更新字段 |
| Steam 标签结果确认 | 既有 C 端展示与发行投放只读取 Steam 标签字典中的最终生效标签 | 草稿、已停用标签或未完成线下确认的选择不得用于展示和投放 |
| 游戏下架、授权失效或合作关系停用 | 下游发布、销售和投放按各自门禁停止新增曝光或获取 | 状态恢复后由对应商品／发布／投放流程重新校验，不由本页直接恢复上线 |

##### 角色权限与数据范围

| 角色 | 权限与范围 | 禁止与越权 | 日志 |

| 已确认／前置未满足 | 资料已确认，但 APPID、授权或商业线下结果缺失、过期或范围不覆盖 | 可继续技术接入和非发布准备；正式发布入口被阻塞 | 补齐线下结果后重新计算，无需开发者重复提交未变化资料 |
| 需修改 | 线下结论指出资料、素材、地区或标签需修改后进入 | 展示原因摘要，开发者修改后重新提交 | 原输入和结果记录保留 |
| 已发布修改稿待线下结果 | 已发布 Game 提交关键资料修改后进入 | C 端继续展示上一有效快照 | 新结果确认后切换快照；需修改时线上内容不变 |

##### 游戏结果列表规则

| 规则项 | 数据与范围 | 展示与操作 | 异常与恢复 |
|---|---|---|---|
| 数据源 | 签约范围内全部 Game 资料版本及其线下结果 | 每个版本一行；当前有效版本明确标记 | 越权对象不展示并记录访问结果 |
| 搜索与筛选 | Game／厂商名称、`game_id`、`app_id` 匹配；发行方式、支持系统、结果状态可组合 | 任一检索条件改变后返回第 1 页，每页 20 条 | 查询失败保留条件并可重试 |
| 排序 | 待线下结果排在其他状态前；同状态依次按提交时间、版本创建时间升序 | 不支持批量排序或批量结果录入 | 数据变化后刷新并避免重复记录 |
| 页面状态 | 加载中、正常、空队列、筛选无结果、加载失败、无权限 | 各状态显示明确文案和恢复动作 | 加载失败不展示其他环境或缓存对象 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 新增。采集独立账号激活、资料提交、线下结果录入、APPID 创建和三系统 SDK 下载；不在本 PRD 统计 C 端访问、CDKEY、包体、投放或交易漏斗。埋点只记录对象标识与结果，不记录密码、合同正文、个人联系方式或 SDK 下载临时地址。

#### 4.1.1 指标口径

| 指标名称 | 口径（含公式、分子和分母） | 去重与时间窗口 | 数据源与决策用途 |
|---|---|---|---|
| 受邀账号 7 日激活率 | 分子为符合分母且在 `created_at` 起 7 日内首次登录成功的账号数；分母为账号主表中 `created_at` 落入同一 cohort 日、创建时状态为已启用且绑定已签约厂商的受邀账号数。平台标记为测试且创建后即停用或删除、未进入可交付状态的测试账号排除；已激活后停用的账号仍计入原 cohort | 按 `account_id` 去重；以账号主表 `created_at` 为创建时间，观察窗口为 `[created_at, created_at + 7×24 小时)`；首次成功登录由 `developer_login_result` 的 `result=success` 判断 | 合作方账号主表与首次成功登录事件，不新增账号创建事件；判断凭据交付是否完成 |
| 厂商资料首轮确认率 | 首次提交后的首个线下结果为已确认的厂商数 ÷ 同期首次提交厂商数 | 按 `vendor_id` 去重；按自然周统计 | 厂商提交与线下结果事件；判断建档规则是否清楚 |
| Game 资料首轮确认率 | 首次提交后的首个线下结果为已确认的 Game 数 ÷ 同期首次提交 Game 数 | 按 `game_id` 去重；按自然周统计 | Game 提交与线下结果事件；判断字段和素材要求是否清楚 |
| 资料结果录入时长 | 首次成功录入时间减去对应资料版本提交时间，分别统计厂商与 Game 的中位数 | 按资料版本去重；按自然周统计，不合并不同版本 | 提交与线下结果事件；判断线下协作和录入效率，不代表线上自动审批时长 |
| APPID 创建完成率 | 已成功创建 APPID 的 Game 数 ÷ 同期资料已确认且有接入资格的 Game 数 | 按 `game_id` 去重；按自然周 cohort 统计 | `appid_create_result` 与 Game 状态快照；判断技术接入启动情况 |
| SDK 下载成功率 | `sdk_download_result` 中 `result=success` 的次数 ÷ 同事件全部有效下载请求次数 | 按 `action_id` 去重；按系统和自然日统计 | SDK 下载事件；发现包配置或下载服务异常 |

#### 4.1.2 埋点事件

| 事件 | 页面／类型 | 触发与成功 | 参数 |
|---|---|---|---|
| `developer_login_result` | B 端受邀账号登录页／新增 | 用户提交登录后上报一次；服务端返回成功并建立会话记为成功，重复点击不重复上报提交 | `event_id, vendor_id, account_id, result, failure_type, occurred_at` |
| `vendor_profile_submit` | B 端厂商资料页／新增 | 不可变资料版本创建成功时上报；保存草稿不上报 | `event_id, vendor_id, account_id, profile_revision_id, submit_type, occurred_at` |
| `vendor_offline_result_record` | B 端厂商线下资质结果录入页／新增 | 运营提交录入后上报一次；同一 `action_id` 仅在结果首次成功写入时记成功，失败也上报 | `event_id, action_id, vendor_id, profile_revision_id, offline_result, reason_code, result_source, operator_role, result, failure_type, occurred_at` |
| `game_profile_submit` | B 端创建／编辑游戏页／新增 | Game 不可变资料版本创建成功时上报；保存草稿不上报 | `event_id, vendor_id, account_id, game_id, game_revision_id, distribution_mode, submit_type, occurred_at` |
| `game_offline_result_record` | B 端游戏资料与上架线下结果录入页／新增 | 运营提交录入后上报一次；资料结果和最终 Steam 标签原子写入记成功，失败也上报 | `event_id, action_id, vendor_id, game_id, app_id, game_revision_id, distribution_mode, offline_result, reason_code, result_source, operator_role, result, failure_type, occurred_at` |
| `appid_create_result` | B 端 APPID 与 SDK 接入页／新增 | 点击创建后上报一次；新建成功或幂等返回该 Game 既有 APPID 均记成功，失败也上报 | `event_id, action_id, vendor_id, account_id, game_id, app_id, result, failure_type, occurred_at` |
| `sdk_download_result` | B 端 APPID 与 SDK 接入页／新增 | 发起 SDK 下载并由服务端成功生成有效下载响应记成功；未配置、无权限或服务失败也上报 | `event_id, action_id, vendor_id, account_id, game_id, app_id, sdk_os, sdk_version, result, failure_type, occurred_at` |

#### 4.1.3 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| `event_id` | string／是 | 事件唯一标识；数据层按此字段去重 | `evt_20260902_001` |
| `action_id` | string／条件必填 | APPID 创建、SDK 下载或结果录入的一次动作唯一标识；用于幂等与统计去重 | `action_20260902_001` |
| `vendor_id` | string／是 | 平台厂商唯一标识 | `vendor_10001` |
| `account_id` | string／条件必填 | 独立开发者账号唯一标识；开发者侧事件必填，运营自动任务可不传；报表使用脱敏标识 | `dev_account_20001` |
| `game_id` | string／条件必填 | Game 唯一标识；Game、APPID、SDK 相关事件必填 | `game_40001` |
| `app_id` | string／条件必填 | 平台 APPID；APPID 创建失败且尚未生成对象时可空，Game 结果录入在 APPID 未创建时可空，其余接入事件必填 | `app_60001` |
| `profile_revision_id` | string／条件必填 | 厂商资料版本唯一标识；厂商提交和结果录入事件必填 | `vendor_rev_30001` |
| `game_revision_id` | string／条件必填 | Game 资料版本唯一标识；Game 提交和结果录入事件必填 | `game_rev_50001` |
| `submit_type` | enum／条件必填 | 本次资料提交类型 | `first_submit`＝首次提交；`resubmit`＝需修改后重新提交；`modification`＝已确认后修改提交 |
| `distribution_mode` | enum／条件必填 | Game 提交与结果录入事件必填的发行方式 | `third_party_activation`＝第三方平台激活；`gamehub_direct_download`＝盖世直接下载 |
| `offline_result` | enum／条件必填 | 运营按线下结论录入的资料结果 | `confirmed`＝已确认；`changes_required`＝需修改 |
| `reason_code` | enum／条件必填 | 结果原因分类；已确认时传 `none` | `none`＝无需修改；`missing_info`＝资料不完整；`invalid_asset`＝素材需调整；`rights_conflict`＝授权冲突；`region_conflict`＝地区冲突；`tag_adjustment`＝标签需调整；`commercial_result_missing`＝商业结果缺失；`other`＝其他 |
| `result_source` | enum／条件必填 | 线下结论来源 | `business`＝商务；`legal`＝法务；`publishing_ops`＝发行运营；`joint`＝联合结论 |
| `sdk_os` | enum／条件必填 | SDK 下载目标系统 | `windows`＝Windows；`macos`＝macOS；`linux`＝Linux |
| `sdk_version` | string／条件必填 | 目标系统 SDK 版本；包未配置导致失败时可空 | `1.0.0` |
| `operator_role` | enum／条件必填 | 结果录入操作角色 | `platform_ops`＝平台发行运营 |
| `result` | enum／条件必填 | 登录、创建、下载或录入动作的技术处理结果 | `success`＝成功；`failure`＝失败 |
| `failure_type` | enum／条件必填 | 技术失败类型；成功时传 `none` | `none`＝无失败；`invalid_credential`＝凭据错误；`account_disabled`＝账号停用；`permission_denied`＝无权限；`object_not_found`＝对象不存在；`state_conflict`＝状态冲突；`package_not_configured`＝SDK 包未配置；`document_not_configured`＝文档未配置；`network_or_service`＝网络或服务失败；`validation_failed`＝校验失败 |
| `occurred_at` | datetime／是 | 业务动作取得当前结果的服务端时间；使用带时区 ISO 8601 | `2026-09-02T12:00:00+08:00` |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 平台隔离 | 新发行平台使用独立正式域名、独立环境域名、独立开发者账号系统和独立业务数据库；不得把盖世主站／社区登录态或原后台数据库直接作为开发者平台权限与主数据来源。主站和社区仅通过 `game_id` 映射或受控接口消费已确认资料。 |
| 兼容 | 开发者与运营页面支持公司当前指定的桌面浏览器；Game 与 SDK 支持 Windows／Mac／Linux，无移动端或主机字段。本 PRD 不新增 C 端页面。 |
| SDK 与文档 | 三系统 SDK 包独立版本化并提供文件校验值；能力仅限初始化、登录、权益、首次启动授权、错误码和日志。开发文档由 Google Docs 托管，平台只保存受控外链与可用状态。 |
| 安全 | 独立开发者账号每次读取和提交均校验 `vendor_id + game_id + app_id` 关系；越权请求不返回对象存在性和内容。密码、联系方式、SDK 临时下载地址和线下敏感依据不可进入普通日志或埋点。 |
| 数据存储 | 厂商与 Game 每次提交、线下结果、Steam 标签最终值和已确认快照均保留版本关系；APPID 与 Game 的唯一绑定不可删除或覆盖。停用账号、资料需修改或 Game 下架不删除历史版本和操作记录。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 平台发行运营代建独立账号、绑定唯一厂商、维护线下合同元数据并执行启停；只录入厂商与 Game 的线下结果及最终 Steam 标签。账号、资料和结果状态变化同步至开发者工作台。 |
| SDK 与文档 | SDK 团队分别维护 Windows／Mac／Linux 当前有效包、版本、校验值和下载地址，并维护 Google Docs 正式文档；未配置内容不得由运营临时填充或伪造。 |
| 内容／素材 | 合作方提交厂商 Logo、简介、官网、联系信息及 Game 图标、封面、截图、文案、语言、地区、三系统要求、Steam 标签和发行方式；运营可做完整性检查，但按线下结论录入结果。 |
| 上线协同／推广 | Game 资料已确认、APPID 正常且线下授权、定价和上架结果满足后才可进入 CDKEY 供给或包体版本准备；正式发布前由对应流程重新校验。精准投放不在本页配置。 |
| 评论管理 | 游戏评论与社区内容治理复用现有社区后台；开发者平台只通过 `game_id` 展示必要状态或入口，不新建评论审核、申诉或内容治理页面。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 本 PRD 不建设结算账户、分账、提款或在线定价审批；正式发布前须读取线下确认的价格／零价领取条件、分成及结算责任。 |
| 法务 | 厂商须完成线下签约；发行授权在有效期内、销售地区未超出授权地区且合同合作范围覆盖本游戏及发行方式，方可正式发布。账号配置页只记录合同元数据，不提供在线签署。 |
| 版权 | 厂商对名称、Logo、Game 素材、文案及官网链接具备合法使用权；平台的资料完整性校验和结果录入不替代厂商版权责任，侵权或授权失效时阻塞发布并进入平台处置。 |
| 其他合规 | 联系手机和邮箱不在 C 端展示；地区、语言、未成年人和数据处理遵循平台已有合规要求。开发者不能查看其他厂商数据或用户个人数据。 |
