## 一、文档概述

### 1.1 背景概述

- **需求背景：** 盖世游戏需要面向 PC 游戏厂商提供独立开发者入口。第一份文档先闭环账号进入、企业资质提交、平台审核和内容运营，让合作方能自行完成申请并持续查看结果。
- **当前方式：** 合作方通过线下联系了解接入要求，主体、银行、协议和联系人资料依赖人工收集；审核结果也由运营逐一通知。
- **问题：** 缺少统一入口与标准字段，资料易遗漏、审核过程不可追踪；游戏管理、包体、CDKEY 和投放等后续能力也缺少可靠的企业资格前置。
- **竞品借鉴：** TapTap 的开发者首页先解释平台价值，再进入登录和控制台；Steamworks 将合作介绍、资料准备、协议确认和正式提交串成清晰的入驻链路。本期借鉴“先理解、后提交、状态可追踪”，不照搬 Steam Direct 付费步骤，也不开放无门槛游戏发行。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 包含开发者平台官网、首页登录弹窗、平台注册／企业认证选择、平台开发者控制台、游戏项目创建入口、帮助中心、企业认证介绍与单页表单、认证结果、运营审核列表与独立详情、企业认证文章配置、帮助中心导航与子文档配置。Web 页面需同时适配桌面与手机。 |
| 业务边界 | [已确认] 登录成功只创建或识别平台账号；选择“注册平台开发者”无需审核，默认进入游戏管理并可创建游戏项目，但提交游戏发行前必须完成企业认证。企业认证无草稿态，同一账号同一时间最多存在 1 条审核中申请；正式提交后由平台运营在 5 个工作日内审核。拒绝可修改并生成新修订重提，通过后开通后续发行资格，下架后收回资格且不可重提。 |
| 运营边界 | [已确认] 发行运营查询申请、查看提交快照、通过、拒绝和下架；维护企业认证文章、帮助导航和子文档。内容先存草稿，再逐条发布。运营不能改企业提交快照。 |
| 人力边界 | 企业用户填写并维护本企业资料；发行运营审核和维护内容；法务确认协议最终文本；UI 与服务端实现响应式 Web、状态、权限、附件和审计；测试覆盖中英文、桌面／手机、正常／失败／并发状态。 |

#### 一期明确不包含

1. 除基础游戏项目创建外的完整游戏资料、单游戏详情、商店、版本管理、游戏测试、游戏包管理和买断制游戏资质审核。
2. SDK 基础服务、盖世游戏登录、启动校验、云存档、APK 加固等开发者服务的实际接入；本期仅在控制台和帮助中心占位。
3. CDKEY 批次、自助生成、第三方渠道 API 与接口说明；由下一份 CDKEY PRD 定义。
4. 包体上传、测试、审核、版本发布与回滚；由后续包体 PRD 定义。
5. 精准化投放、Campaign／渠道归因及浏览／下载／预约／转化／收益的正式数据口径；控制台仅展示示例结构，由后续投放与数据 PRD 定义。
6. 广告接入、复杂组织成员权限、自动结算、提现、在线付费入驻和 Steam Direct 费用。
7. 企业官网字段；企业认证表单不采集“HTTPS 官网”。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 平台账号 | Platform Account | 用户通过手机号、邮箱或盖世游戏扫码完成身份验证后创建的登录账号；账号存在不代表企业认证通过。 |
| 平台开发者 | Platform Developer | 选择“注册平台开发者”后获得的基础身份，可使用控制台、创建游戏项目、查看帮助中心和申请企业认证；未通过企业认证时不能提交游戏发行。 |
| 企业开发者 | Enterprise Developer | 企业认证状态为 `approved` 的平台账号，具备后续游戏接入与发行能力。 |
| 企业认证申请 | Company Verification Application | 企业用户正式提交的主体、工商、银行、厂商品牌、联系人和协议确认快照，以 `application_id` 唯一标识。 |
| 申请修订 | Application Revision | 首次提交为 `REV-01`；拒绝后修改并重新提交时递增。旧修订和审核记录不可覆盖。 |
| 内容版本 | Content Revision | 每发布、删除一条线上内容生成的新版本。企业提交时记录所接受的协议版本。 |
| 正式提交 | Formal Submission | 表单通过校验后一次性提交审核；本期不提供保存草稿。提交前可清空重填，提交后不可修改当前快照。 |
| 下架 | Delisted | 已通过企业因平台处理被收回发行合作资格的终态；企业仍可登录查看原因和历史，但不能重新提交本申请。 |

| `unsubmitted` | 平台账号尚未提交；正式提交后退出。 | 展示申请入口、认证介绍和可填写表单。 | 提交失败保持本状态并保留当前页面输入。 |

| `approved` | 运营通过进入；运营下架后退出。 | 游戏管理不展示正常认证状态条；开通后续发行资格。 | 通过结果不可由企业撤销；平台生成固定短信／邮件通知并附开发者后台链接。 |
| `rejected` | 运营拒绝进入；企业重新提交后退出。 | 平台内展示拒绝原因和修改入口；短信／邮件只提示审核未通过并附开发者后台链接。 | 重新提交生成新修订并进入 `pending`；旧修订只读。 |

| `managed_content_publish` | B 端／内容配置／新增 | 点击列表“发布”后上报；本条线上内容更新为成功。 | `content_scope, content_type, content_id, content_revision, result` |

#### 4.1.3 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| `language` | enum／是 | 当前页面语言。 | `zh`＝中文；`en`＝English。 |
| `login_method` | enum／是 | 本次登录方式。 | `mobile_code`＝手机号验证码；`email_code`＝邮箱验证码；`gamehub_qr`＝盖世扫码。 |
| `result` | enum／是 | 对应动作结果。 | `success`＝成功；`validation_failed`＝前端校验失败；`request_failed`＝请求失败；`conflict`＝状态或版本冲突。 |
| `account_tier` | enum／是 | 用户选择的入驻方式。 | `registered`＝平台开发者；`enterprise`＝企业认证。 |
| `application_id` | string／否 | 企业申请唯一标识；提交失败尚未生成时为空。 | `ENT-20260903-001`。 |
| `revision` | int／否 | 企业申请修订号。 | `1`。 |
| `verification_status` | enum／是 | 企业认证当前状态。 | `pending`＝审核中；`approved`＝已通过；`rejected`＝未通过；`delisted`＝已下架。 |
| `keyword_length` | int／是 | 去除首尾空格后的搜索词长度。 | `4`。 |
| `result_count` | int／是 | 本次帮助搜索命中文章数。 | `3`。 |
| `review_action` | enum／是 | 运营审核动作。 | `approve`＝通过；`reject`＝拒绝；`delist`＝下架。 |
| `content_scope` | enum／是 | 本次发布的内容范围。 | `certification`＝企业认证文章；`help_center`＝帮助中心导航与子文档。 |
| `content_type` | enum／是 | 发布对象类型。 | `article`＝企业认证文章；`navigation`＝帮助导航；`document`＝帮助子文档。 |
| `content_id` | string／是 | 发布对象唯一编号。 | `CERT-ARTICLE-001`、`HC-NAV-001`、`HC-DOC-001`。 |
| `content_revision` | int／否 | 发布成功后的线上版本；失败时为当前版本。 | `6`。 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 兼容 | Web 支持桌面宽屏与手机端；320px、390px 不出现页面根节点横向溢出。桌面内容区随可用宽度伸缩，不固定为窄画布；运营表格和文章表格可在自身容器横向滚动。 |
| 安全 | 平台账号会话、企业申请、审核和内容发布均由服务端鉴权；营业执照、银行证明使用私有存储和短时访问地址；银行账号默认脱敏为 `**** 后四位`。 |
| 富文本安全 | 草稿保存和发布前均清理脚本、事件属性、危险协议和禁用标签；链接仅限 HTTPS，图片仅用平台上传地址。 |
| 状态一致性 | 申请审核和内容发布均用版本／幂等控制；并发动作仅首个成功结果生效，其余提示刷新。 |
| 数据存储 | 分开保存内容草稿与线上版本；保留申请快照、修订、协议版本、审核结果、原因、操作人、时间和附件引用。历史记录不可覆盖。 |

### 4.3 运营需求

| 需求项 | 具体要求 |

| 内容／素材 | 法务提供两份协议的最终完整文本；运营提供认证介绍、帮助文章、服务时间和联系渠道。统一邮箱为 `dev@xiaoji.com`。 |
| 审核处理 | 运营在企业提交后 5 个工作日内完成通过或拒绝；拒绝原因需明确到待修改资料项，下架原因需说明影响范围。 |
