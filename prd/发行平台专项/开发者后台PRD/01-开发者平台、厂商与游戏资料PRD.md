## 一、文档概述

### 1.1 背景概述

- **需求背景：** 新发行平台一期以独立品牌、独立域名、独立账号权限和独立业务数据库运行，同时需要降低既有盖世合作方的登录门槛。登录支持新平台账号密码和盖世游戏平台第三方登录；身份验证成功后，未取得开发者资格的用户先提交开发者注册资料。
- **当前方式：** V1.4 按“运营预先创建并绑定厂商账号，合作方登录即进入工作台”设计，未区分登录身份与开发者资格，也未覆盖盖世游戏平台作为第三方身份源的登录和绑定。
- **问题：** 若登录成功直接授予开发者权限，会把盖世玩家身份误当成发行资质；若按邮箱静默合并账号，可能造成串号或权限劫持；若登录页沿用盖世主题、Cookie 或业务数据，会破坏新发行平台的独立边界。
- **证据：** 2026-09-01《游戏平台进度会》确认新发行平台与盖世游戏在域名、数据库和账号权限上隔离；2026-09-02 进一步确认登录采用“独立账号密码＋盖世游戏平台第三方登录”，选择方案 A，首次身份验证后进入开发者注册资料提交。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 本文只包含 B 端：独立平台登录、盖世游戏平台第三方登录与自动建号映射、开发者注册／厂商资料、工作台、游戏列表、创建／编辑游戏、APPID 与 SDK 接入、资料结果，以及平台侧账号管理、厂商线下结果录入、游戏资料与上架线下结果录入，共 10 个业务页面。Google Docs 只作为外部文档入口。 |
| 业务边界 | [已确认] 平台账号与开发者资格分层：账号密码仅登录已存在且已设置密码的 `account_id`，不得因账号不存在而自动注册；盖世身份首次授权时自动创建独立 `account_id`、建立唯一映射并登录，不提供绑定或注册选择。任一方式登录成功均不自动取得开发者资格；无资格账号提交开发者／厂商资料，结果已确认后绑定唯一 `vendor_id` 并进入工作台。一个账号一期只绑定一个厂商，一个厂商可管理多个 Game，一个 Game 创建一个平台 APPID。 |
| 运营边界 | 平台发行运营管理独立账号启停、密码设置／重置协助、盖世身份映射异常和唯一厂商关系，录入线下合同／资质／上架结果；不在线签约、不自动审核资质，不因盖世扫码、自动建号或授权成功自动确认开发者资格。 |
| 人力边界 | 申请人完成登录、开发者注册资料及后续 Game 建档；盖世账号团队提供受控第三方授权能力；发行平台账号团队维护独立会话、凭据和身份映射；商务／法务在线下完成合同与资质审核，发行运营录入结果；SDK、服务端、测试和数据团队分别承担三系统接入、隔离、验证及数据采集。 |

#### 一期明确不包含

1. 盖世登录成功后自动成为开发者、自动绑定厂商或直接进入工作台。
2. 微信、QQ、Google、Apple、Steam 等其他第三方登录，以及邮箱验证码免密登录。
3. 合作方自行创建成员、角色分级、多账号同厂商或复杂权限配置。
4. 在线合同签署、自动资质审核、在线定价／上架审批、合同文件管理、结算账户、自动分账和提款。
5. 独立 C 端厂商主页、游戏详情改造、厂商主页装修、私域运营、测试招募和内容发布；游戏评论继续复用社区后台。
6. 开发者直接发布游戏、商品、版本或投放计划。
7. 将既有包体管理流、CDKEY 供给页、投放页或数据看板定义为本文页面。
8. IP 白名单、多项目凭证、通用 OpenAPI 管理和移动端包体。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 独立平台账号 | Platform Account | 新发行平台的登录主体，以 `account_id` 唯一标识；账号密码、盖世第三方身份均只是其登录凭据。账号本身不等于开发者资格。 |
| 账号密码登录 | Password Login | 使用新发行平台的账号／邮箱与密码建立独立平台会话；不读取盖世 Cookie 或玩家业务数据。 |
| 盖世第三方登录 | GameHub Sign-in | 新发行平台向盖世游戏平台发起受控授权，取得稳定身份标识后映射到 `account_id`。PC Web 默认使用盖世游戏 App 扫码确认；授权完成后仍由新平台签发会话。 |
| 盖世身份映射 | GameHub Identity Mapping | 盖世身份首次授权时，由服务端将稳定身份标识唯一映射到自动创建的独立 `account_id`；再次授权直接定位同一账号。同一盖世身份不得映射多个平台账号，不按相同邮箱与既有平台账号静默合并。 |
| 开发者注册 | Developer Registration | 已登录但尚无开发者资格的账号提交主体、品牌和联系资料，等待平台录入线下确认结果的流程。结果已确认前不可进入工作台或创建 Game／APPID。 |
| 独立开发者账号 | Developer Account | 开发者注册结果已确认、账号处于启用且已绑定唯一 `vendor_id` 的独立平台账号。 |
| Game | Game | 新发行平台的游戏主对象，归属唯一厂商；连接资料、APPID、商品、包体、投放和发行数据。 |
| APPID | Application ID | 一个 Game 在新发行平台中的公开应用标识；一期一个 Game 只创建一个 APPID，不等同于 Steam AppID，也不是密钥。 |
| 厂商资料版本 | Publisher Profile Revision | 开发者注册或后续修改时提交的主体、品牌公开资料和联系信息快照；待线下结果时不可覆盖。 |
| 游戏资料版本 | Game Profile Revision | 游戏基本资料、宣传素材、语言、地区、系统要求、标签和发行方式组成的一次提交快照。 |
| 已确认快照 | Confirmed Snapshot | 最近一次由运营录入线下确认结果、可供下游商品、版本、投放或既有 C 端读取的厂商／游戏资料；新修改待线下结果期间继续使用上一有效快照。 |
| 关键资料 | Critical Profile Fields | 会改变用户识别、发行范围或交付判断的字段，包括厂商公开资料，以及游戏名称、素材、简介、语言、地区、系统要求、标签和发行方式。 |
| 游戏标签 | Steam Tag | 复用 Steam 全量标签字典中的标签 ID 与名称；平台不自建平行标签或新增自定义标签。仅线下确认后的最终标签可用于展示和投放。 |
| 线下审核结果 | Offline Review Result | 商务、法务或发行运营在线下完成合同、主体资质、定价或上架判断后，由有权限运营录入的结果、原因摘要、审核人和时间。 |
| 发布前置 | Release Prerequisite | 资料结果确认为可用后仍须满足的商业条件，包括有效发行授权、发行地区在授权范围内及合同合作范围覆盖本游戏。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向发行合作方的独立开发者平台身份、注册、Game→APPID 接入与资料结果闭环；盖世游戏平台只作为可选第三方身份源。 |
| 目标用户 | 申请开发者资格的合作方、已确认开发者、平台发行运营。 |
| 核心目标 | 通过账号密码或盖世第三方登录建立独立平台身份；未注册用户提交开发者资料，结果已确认后再进入工作台，并为后续 Game、APPID、商品、包体和数据提供唯一上游关系。 |
| 使用场景 | 申请人完成身份登录后提交开发者／厂商资料并查看结果；已确认开发者使用任一已配置凭据登录工作台，维护 Game、创建 APPID、下载三系统 SDK 并打开 Google Docs；运营处理账号异常并录入线下结果。 |
| 功能概述 | 已有独立账号密码登录、盖世第三方登录与首次自动建号映射、开发者注册、唯一厂商关系、Game 建档、APPID、SDK 下载、外部文档和线下结果录入组成上游闭环。 |

#### 共享对象关系

| 对象 | 归属与数据范围 | 本文状态 | 后续去向 |
|---|---|---|---|
| 独立平台账号 | 归属一个自然登录主体；凭据为账号密码及可选盖世身份映射 | 已启用、已停用 | 身份登录成功后按开发者注册状态分流 |
| 盖世身份映射 | 一个盖世稳定身份最多映射一个 `account_id`，一个 `account_id` 一期最多映射一个盖世身份 | 首次建号中、已映射、冲突待处理 | 首次授权原子建号并映射；再次授权直接登录；解绑或冲突不删除平台业务数据 |
| 开发者注册／厂商资料 | 已登录账号提交；首次确认后账号绑定唯一厂商 | 未提交、草稿、待线下结果、需修改、已确认 | 已确认后开放工作台；修改稿未确认时继续使用上一有效快照 |

| 游戏标签 | 开发者从 Steam 全量标签选择；运营按线下结论录入最终结果 | 未确认、已确认 | 已确认标签用于 C 端展示和正式投放规则 |
| APPID | 归属一个 Game；开发者创建并只读查看 | 未创建、正常、已停用 | SDK 初始化、首次启动授权、商品、包体与发行数据共同引用 |

#### 后台生效结果与下游影响（非页面范围）

| 后台结果 | 下游消费规则 | 异常与恢复 |
|---|---|---|
| 身份登录成功但开发者资料未确认 | 只开放注册资料、结果和账号安全相关页面；工作台、Game、APPID、CDKEY、包体、投放和数据接口均拒绝访问 | 请求被拒绝时按注册状态返回资料填写、结果等待或修改入口，不泄露任何厂商数据 |
| 厂商／游戏资料首次确认为可用 | 向既有游戏详情及后续发行链路提供已确认快照；本文不新增厂商主页或详情页面 | 无已确认快照时不得把草稿、待线下结果或需修改内容暴露到下游 |
| 已确认资料再次修改 | 待线下结果期间继续使用上一有效快照；新结果确认为可用后原子切换 | 切换失败继续使用上一有效快照并记录同步异常 |
| Steam 标签结果确认 | 既有 C 端展示与发行投放只读取 Steam 标签字典中的最终生效标签 | 草稿、已停用标签或未完成线下确认的选择不得用于展示和投放 |
| 账号、授权或合作关系停用 | 新登录、下游发布、销售和投放按各自门禁停止 | 已有业务数据和历史记录不删除；恢复后由对应流程重新校验 |

### 2.2 产品流程

横向主线为：已有独立账号密码登录，或选择盖世第三方登录 → 盖世扫码确认后按稳定身份查找唯一映射；已有映射直接登录，无映射则原子创建独立 `account_id`、写入唯一映射并登录 → 按开发者注册状态分流 → 未提交／需修改时填写开发者与厂商资料，待线下结果时查看进度，已确认时进入工作台 → 创建 Game 并填写 Windows／Mac／Linux 资料与 Steam 标签 → 创建唯一 APPID → 下载 SDK／打开 Google Docs → 运营录入线下合同、资质及上架结果 → 进入 CDKEY 或包体准备。

## 三、功能需求

### 3.2 B 端功能需求

#### 3.2.1 独立账号与盖世第三方登录页

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 在新发行平台独立品牌页面完成已有账号密码登录，或通过盖世游戏平台第三方授权自动建号／登录，再进入开发者注册状态分流。 |

| `action_id` | string／条件必填 | 登录、自动建号、APPID、SDK 或结果录入的一次动作标识 | `action_20260903_001` |
| `account_id` | string／条件必填 | 独立平台账号；登录或自动建号失败且未产生账号时可空，其余开发者侧事件必填 | `dev_account_20001` |
| `vendor_id` | string／条件必填 | 厂商标识；注册首次提交成功前及未确认登录时可空，厂商结果、Game、APPID、SDK 事件必填 | `vendor_10001` |
| `game_id` | string／条件必填 | Game 唯一标识；Game、APPID、SDK 相关事件必填 | `game_40001` |
| `app_id` | string／条件必填 | 平台 APPID；创建失败或 Game 结果录入时尚未生成可空 | `app_60001` |
| `profile_revision_id` | string／条件必填 | 开发者注册／厂商资料版本；资料提交和厂商结果录入必填 | `vendor_rev_30001` |
| `game_revision_id` | string／条件必填 | Game 资料版本；Game 提交和结果录入必填 | `game_rev_50001` |
| `login_method` | enum／条件必填 | 登录事件采用的身份凭据 | `password`＝独立账号密码；`gamehub`＝盖世第三方登录 |
| `registration_status` | enum／条件必填 | 登录或自动建号终态时的开发者注册状态 | `unsubmitted`＝未提交；`draft`＝草稿；`pending_offline_result`＝待线下结果；`changes_required`＝需修改；`confirmed`＝已确认；`disabled`＝账号停用 |
| `submit_type` | enum／条件必填 | 本次资料提交类型 | `first_submit`＝首次注册提交；`resubmit`＝需修改后重新提交；`modification`＝已确认后修改提交 |
| `distribution_mode` | enum／条件必填 | Game 发行方式 | `third_party_activation`＝第三方平台激活；`gamehub_direct_download`＝盖世直接下载 |
| `offline_result` | enum／条件必填 | 运营按线下结论录入的资料结果 | `confirmed`＝已确认；`changes_required`＝需修改 |
| `reason_code` | enum／条件必填 | 结果原因；已确认时传 `none` | `none`＝无需修改；`missing_info`＝资料不完整；`invalid_asset`＝素材需调整；`rights_conflict`＝授权冲突；`region_conflict`＝地区冲突；`tag_adjustment`＝标签需调整；`commercial_result_missing`＝商业结果缺失；`other`＝其他 |
| `result_source` | enum／条件必填 | 线下结论来源 | `business`＝商务；`legal`＝法务；`publishing_ops`＝发行运营；`joint`＝联合结论 |
| `sdk_os` | enum／条件必填 | SDK 下载目标系统 | `windows`＝Windows；`macos`＝macOS；`linux`＝Linux |
| `sdk_version` | string／条件必填 | 目标系统 SDK 版本；包未配置导致失败时可空 | `1.0.0` |
| `operator_role` | enum／条件必填 | 结果录入操作角色 | `platform_ops`＝平台发行运营 |
| `result` | enum／条件必填 | 当前动作技术处理结果 | `success`＝成功；`failure`＝失败 |
| `failure_type` | enum／条件必填 | 技术失败类型；成功时传 `none` | `none`＝无失败；`invalid_credential`＝凭据错误；`qr_expired`＝二维码过期；`authorization_cancelled`＝用户取消授权；`identity_conflict`＝身份映射冲突；`account_provision_failed`＝自动建号事务失败；`account_disabled`＝账号停用；`permission_denied`＝无权限；`object_not_found`＝对象不存在；`state_conflict`＝状态冲突；`package_not_configured`＝SDK 包未配置；`document_not_configured`＝文档未配置；`network_or_service`＝网络或服务失败；`validation_failed`＝校验失败 |
| `occurred_at` | datetime／是 | 业务动作取得当前结果的服务端时间；带时区 ISO 8601 | `2026-09-03T12:00:00+08:00` |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 平台隔离 | 新发行平台使用独立品牌、正式域名、环境域名、账号权限、会话 Cookie 和业务数据库。盖世游戏平台只通过受控授权返回稳定身份标识和完成登录所需的最小信息，不复用盖世登录态、会员、游戏资产或玩家业务数据库。 |
| 兼容 | 开发者与运营页面支持公司当前指定的桌面浏览器；盖世扫码须明确支持的 App 版本和移动端系统。Game 与 SDK 支持 Windows／Mac／Linux，无移动端包体或主机字段。 |
| SDK 与文档 | 三系统 SDK 包独立版本化并提供文件校验值；能力仅限初始化、登录、权益、首次启动授权、错误码和日志。开发文档由 Google Docs 托管。 |
| 安全 | 盖世授权请求须短时有效、一次消费并绑定当前浏览器会话；确认、取消、超时和重复回调按幂等终态处理。首次授权的 `account_id` 创建、身份映射和会话建立须在同一事务或具备等价补偿；任一步失败不得遗留可登录的孤立状态。不得按邮箱静默合并。 |
| 权限 | 未确认账号只能维护开发者注册资料和查看结果；工作台及下游接口每次校验账号启用、注册已确认及 `account_id + vendor_id + game_id + app_id` 关系，越权时不返回对象存在性。 |
| 数据存储 | 独立账号凭据、盖世身份映射、注册资料、厂商与 Game 版本及线下结果分别留存关系和审计记录。解绑、停用、需修改或 Game 下架均不删除历史业务对象。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 运营配置 | 平台发行运营管理账号启停、密码设置／重置协助、盖世映射异常和唯一厂商关系；录入开发者注册、厂商与 Game 的线下结果及最终 Steam 标签。不得因扫码或自动建号成功确认开发者资格。 |
| 身份协同 | 盖世账号团队提供正式授权应用、回调白名单、二维码状态和稳定身份标识；发行平台仅保存映射和授权审计所需信息。 |
| SDK 与文档 | SDK 团队分别维护 Windows／Mac／Linux 当前有效包、版本、校验值和下载地址，并维护 Google Docs 正式文档。 |
| 内容／素材 | 申请人提交主体、品牌、联系人及 Game 资料；运营可做完整性检查，但按既有线下结论录入结果。 |
| 上线协同／推广 | 开发者注册和 Game 资料已确认、APPID 正常且线下授权、定价和上架结果满足后，才可进入 CDKEY 或包体准备；正式发布前由对应流程重新校验。 |
| 评论管理 | 游戏评论与社区内容治理复用现有社区后台；开发者平台不新建评论审核、申诉或内容治理页面。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 本 PRD 不建设结算账户、分账、提款或在线定价审批；正式发布前读取线下确认的价格／零价领取条件、分成及结算责任。 |
| 法务 | 登录页和首次盖世授权须展示新发行平台协议、隐私政策，以及盖世身份用于自动创建独立平台账号和后续登录的目的；厂商仍须在线下完成签约与主体资质核验。 |
| 版权 | 厂商对名称、Logo、Game 素材、文案及官网链接具备合法使用权；平台资料完整性校验和结果录入不替代厂商版权责任。 |
| 其他合规 | 只从盖世授权获取建立身份映射所需的最小信息；不得将玩家昵称、会员、游戏资产或行为数据用于开发者资格判断。联系手机和邮箱不在 C 端展示，开发者不能查看其他厂商或用户个人数据。 |

## 五、待确认项

| 待确认问题 | 推荐方案 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 盖世游戏平台可提供的正式登录协议、稳定身份字段、二维码状态与回调方式是什么 | 使用受控 OAuth／扫码授权，只返回稳定身份标识和最小登录信息；不共享 Cookie 或玩家业务数据 | 影响二维码状态、映射唯一性、回调安全和联调 | 阻塞盖世第三方登录开发 |
| 独立账号密码的账号标识、初始设置与找回渠道是什么 | 登录框支持账号／邮箱且只登录已有凭据；盖世首次登录后通过已验证邮箱设置平台密码，忘记密码也只通过已验证邮箱重置 | 影响密码首次设置、找回和客服处理；不影响盖世自动建号与登录主链路 | 阻塞账号密码闭环，不阻塞盖世登录 |
| 新发行平台正式独立域名、测试／预发布环境域名分别是什么 | 各环境使用明确独立子域名，并在 Cookie、盖世回调白名单和监控中隔离 | 影响登录、外链、回调、环境隔离与上线验收 | 阻塞部署配置 |
| Google Docs 正式文档地址及访问范围是什么 | 使用公司可控账号维护只读正式文档，对已确认开发者开放查看，不允许匿名编辑 | 影响开发文档入口和权限失败提示 | 阻塞文档入口上线 |
| Windows／Mac／Linux SDK 一期首发版本、包地址与校验值是什么 | 三系统分别提供版本号、受控下载地址、SHA-256 和责任人，能力集保持一致 | 影响 SDK 卡片字段、下载测试与接入 | 阻塞 SDK 下载上线 |
| Steam 全量标签字典通过何种方式和频率同步 | 平台服务定期同步标签 ID／名称／状态／版本；历史资料保留提交时快照 | 影响标签搜索、停用标签处置和历史一致性 | 阻塞标签字段定稿 |
