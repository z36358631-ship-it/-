## 一、文档概述

### 1.1 背景概述

- **背景：** 盖世游戏需为 PC 游戏厂商提供独立入口。本期闭环登录、企业认证、审核和内容维护，支持厂商自助申请及查结果。
- **现状：** 厂商线下咨询；运营人工收集主体、银行、协议和联系人资料，并逐一通知结果。
- **问题：** 入口和字段不统一，资料易漏，进度不可查；游戏发行、包体、CDKEY 和投放也缺少企业资格前置。
- **竞品：** TapTap 先介绍平台再登录；Steamworks 串联介绍、备料、协议和提交。本期沿用此顺序，去掉 Steam Direct 付费，不开放免审发行。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 开发者官网、登录、入驻选择、游戏管理、厂商设置、帮助中心、企业认证及结果；运营端含申请列表、详情、审核、认证文章、帮助导航和子文档。Web 适配桌面和手机。 |
| 业务边界 | 登录后创建或识别平台账号。平台注册免审；游戏发行前须通过企业认证。认证无草稿，同一账号最多有 1 条审核中申请。运营在提交后 5 个工作日内审核；审核中可撤回，拒绝或下架后可修改重提。认证通过后，企业主体、厂商资料、财务信息分开申请修改；新值通过前沿用原值。 |
| 运营边界 | 发行运营可查认证／资料修改申请和提交快照，核对变更前后值，执行通过、拒绝或下架；可维护认证文章、帮助导航和子文档。内容先存草稿，再逐条发布。不得改企业提交值。 |
| 人力边界 | 企业用户提交；发行运营审核及维护内容；法务确认协议；UI、服务端实现响应式 Web、状态、权限、附件和审计；测试覆盖中英文、桌面／手机、成功／失败／并发。 |

#### 一期明确不包含

1. 基础游戏项目创建以外的游戏资料、详情、商店、版本、测试、包体和买断制资质审核。
2. 盖世登录、启动校验、云存档、APK 加固等 SDK 服务接入；本期只占位。
3. CDKEY 批次、自助生成、第三方渠道 API 和接口说明；由下一份 PRD 定义。
4. 包体上传、测试、审核、发布及回滚；由后续 PRD 定义。
5. 精准投放、Campaign／渠道归因及浏览、下载、预约、转化、收益口径；本期只展示示例结构。
6. 广告接入、复杂成员权限、自动结算、提现、付费入驻和 Steam Direct 费用。
7. 企业官网；认证表单不采集“HTTPS 官网”。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 平台账号 | Platform Account | 通过手机号、邮箱或盖世扫码验证后创建的账号；有账号不等于已认证。 |
| 平台开发者 | Platform Developer | 选择“注册平台开发者”后获得的基础身份，可进控制台、建游戏、看帮助和申请企业认证；未认证不能提交发行。 |
| 企业开发者 | Enterprise Developer | 企业认证为 `approved` 的平台账号，可接入和发行游戏。 |
| 企业认证申请 | Company Verification Application | 企业提交的主体、工商、银行、品牌、联系人和协议快照，以 `application_id` 唯一标识。 |
| 资料修改申请 | Vendor Profile Change Application | 已认证企业修改主体、厂商或财务资料后提交的审核申请；通过前沿用原值。 |
| 申请修订 | Application Revision | 首次提交为 `REV-01`；拒绝后重提时递增。旧修订和审核记录不可覆盖。 |
| 内容版本 | Content Revision | 每次发布或删除线上内容生成的版本。申请记录用户接受的协议版本。 |
| 正式提交 | Formal Submission | 表单校验通过后一次提交；无草稿。提交前可清空，提交后当前快照只读。 |
| 下架 | Delisted | 平台收回已认证企业的发行资格；企业仍可登录查原因和历史，修改后可重提认证。 |
