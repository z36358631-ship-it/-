## 一、文档概述

### 1.1 背景概述

- **需求背景：** 已完成企业认证的游戏开发者和发行商需要在发行平台内查看自己游戏的销量、免费领取、退款、拒付、预估收入和待结算数据。
- **当前方式：** 销售与逆向交易曾以独立 Demo 表达，正式账单、差异、发票和付款由“开发者财务结算”模块承接；开发者在统一游戏管理后台内缺少稳定的数据入口。
- **问题：** 经营指标、订单定位和财务摘要分散，开发者无法用同一筛选口径解释销量变化，也容易把动态预估收入误认为正式结算金额。
- **解决方案：** 在统一 02 开发者后台的单游戏控制台新增“经营数据”，固定展示当前游戏的“经营概览→订单明细→收入与结算”；需要确认账单或查询正式流水时进入第十五份财务模块。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 只改开发者后台 B 端：在统一 02 Demo 的单游戏控制台新增“经营数据”功能及三个页签，并与现有第十五份财务模块跳转联动。平台级侧边栏仍只保留“游戏管理”“厂商设置”；不修改玩家购买、激活、下载、订单删除或退款申请页面。 |
| 业务边界 | 只统计买断游戏本体与永久 DLC；平台只覆盖 Android、Mac；履约方式只覆盖直接购买、CDKEY。包体、版本、分区定价、折扣、评分评价、社区互动、广告投放不在本需求内。 |
| 运营边界 | 运营负责维护数据口径版本并处理异常数据；本需求不新增运营配置页面，不允许运营在该看板修改订单、退款、拒付或结算终态。 |
| 人力边界 | 服务端按厂商权限返回聚合指标、脱敏订单和账单摘要；Web 前端实现查询、页签、详情和财务跳转；数据团队校验指标与埋点；财务系统提供正式账单状态；测试覆盖权限、口径、状态和响应式表现。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 直接购买 | Direct Purchase | 用户付款后，平台直接向购买账号发放游戏或 DLC 永久权益；内部履约枚举固定为 `account_entitlement`。 |
| CDKEY | Content Delivery Key | 用户下单后获得可一键激活的 Key；开发者侧只记录 Key 已交付，不展示 Key 明文。 |
| 业务来源 | `ledger_source` | 财务流水的业务归属，枚举为 `direct_sale`（平台直销）、`external_key`（外部 Key 采购）、`gamehub_key`（盖世 Key 渠道）；它与履约方式分开记录。 |
| 履约订单队列 | Fulfilled Order Cohort | 按筛选期内的履约完成时间选出订单，并以同一数据截止时间读取这些订单的退款和拒付当前结果；付费销量、退款率和净销量必须使用同一队列。 |
| 付费销量 | Paid Sales | 应付金额大于 0 且完成履约的订单数。直接购买以账号权益生效为准，CDKEY 以 Key 成功交付为准。 |
| 免费领取 | Free Claim | 应付金额等于 0 且完成履约的订单数。 |
| 净销量 | Net Sales | 同一履约订单队列中的付费销量减去截至数据截止时间已完全退款或拒付败诉的订单数；同一订单只扣一次。 |
| 拒付 | Chargeback | 支付机构发起的争议扣款。待裁决只计风险，败诉后才扣减收入。 |
| 预估收入 | Estimated Revenue | 当前筛选范围内按销售额和逆向交易、费用动态计算的非正式收入。 |
| 待结算 | Pending Settlement | 第十五份财务模块返回的当前厂商已锁定结算单未清偿余额；在单游戏经营数据页中作为厂商账单摘要展示，仅随当前厂商、账期和结算币种变化，不按当前游戏及其他经营条件重新分摊。 |
| 对账流水号 | Reconciliation ID | 平台为一笔交易生成的稳定核账编号；可供开发者沟通定位，但不能反查玩家身份。 |
| 用户端已删除 | Deleted from User List | 玩家仅从自己的订单列表移除记录；不改变交易状态、经营统计和财务对账。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向发行平台开发者的单游戏只读经营入口，用当前游戏下的统一筛选快照串联指标观察、脱敏订单定位和财务摘要。 |
| 目标用户 | 已完成企业认证、拥有当前厂商经营数据权限且有权管理当前游戏的开发者、发行商及财务人员；资格暂停账号可查看授权范围内的历史只读数据。 |
| 核心目标 | 让开发者解释销量及逆向交易变化，定位可用于核账的订单，并区分预估收入与正式结算。 |
| 使用场景 | 日常观察销量、核查免费领取、定位退款或拒付订单、月度结算前预核、进入正式账单处理。 |
| 功能概述 | 单游戏控制台依次提供“版本发布”“发布记录”“资质认证”“经营数据”；进入“经营数据”后提供经营概览、订单明细、收入与结算三个页签，当前游戏固定，其他筛选使用同一数据快照。 |

### 2.2 产品流程

![数据看板流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@ec8bcb663117df2e8dddb749a3374849834b2b12/public/prd/publisher-data-dashboard/01-product-flow.png)

*图 2.2-1：开发者从经营概览定位异常订单，再进入正式对账。*

流程说明：

1. 企业开发者从“游戏管理”进入有权管理的目标游戏，再点击单游戏控制台中的“经营数据”，默认查看该游戏近 30 天经营概览。
2. 开发者组合筛选时间、商品、履约、地区、平台和订单状态，页面固定当前游戏并统一刷新数据快照。
3. 发现退款或拒付异常后进入“订单明细”，通过对账流水号或脱敏订单号定位记录并查看只读详情。
4. 开发者进入“收入与结算”核对动态预估和锁定待结算摘要；需要正式处理时跳转第十五份财务模块。

## 三、功能需求

### 3.1 B 端功能需求

| 输出／后置条件 | 页面形成一份带更新时间和口径版本的经营快照；开发者可继续定位订单或查看收入与结算。 |
| 补充说明 | 1. 服务端按登录会话绑定的厂商确定数据范围，并校验请求 Game ID 属于当前厂商且当前账号有权管理；不接受前端传入其他厂商编号或越权 Game ID 扩大范围。<br>2. 个人、未认证、审核中、已驳回、无厂商数据权限或无当前游戏管理权限的账号不展示“经营数据”入口；直接访问时回到游戏管理且不泄露记录是否存在。<br>3. 订单明细展示交易原币；销售额、退款、拒付和预估收入统一折算到财务主体结算币种并展示汇率版本。汇率或必要费用缺失时聚合结果显示“估算中／--”，不按 0 计算。<br>4. 一个厂商存在多个结算币种时，待结算必须按币种分别展示，禁止直接相加；页面明确待结算为厂商账单摘要。 |

##### 角色权限与数据范围

| 账号状态／角色 | 权限与范围 | 禁止与越权 | 历史与恢复 |
|---|---|---|---|
| 企业认证已通过且有经营数据与当前游戏权限 | 查看当前游戏聚合指标和脱敏订单，并查看厂商结算摘要 | 不可跨游戏查询，不可修改订单、退款、拒付或账单终态 | 任一权限撤销后立即停止新查询 |
| 企业财务权限且有当前游戏权限 | 查看当前游戏经营数据，并可从看板进入有权访问的财务模块 | 看板内不能确认账单、提交差异、处理发票或付款 | 财务操作日志由第十五份模块记录 |
| 企业资格已暂停 | 查看暂停前已授权游戏形成的历史只读数据 | 不可跨游戏查询，不可创建、编辑、提审或执行财务操作 | 资格恢复后按最新授权恢复查询 |
| 个人、未提交、审核中、已驳回、无厂商授权或无当前游戏权限 | 不展示真实经营数据 | 服务端统一拒绝越权查询，不返回游戏或订单是否存在 | 完成企业认证并获得对应授权后生效 |

##### 订单状态与统计影响

| 状态 | 进入条件 | 页面表现与统计影响 | 后续结果 |
|---|---|---|---|
| 交易完成 | 金额大于 0 且权益生效或 Key 已交付 | 计入付费销量和销售额 | 后续退款或拒付不回写历史毛销量 |
| 免费领取 | 金额等于 0 且完成履约 | 计入免费领取，不计销售额 | 权益继续有效 |
| 退款处理中 | 已发起退款但渠道未确认成功 | 展示处理中，不计退款成功，不扣预估收入 | 成功后进入已退款；失败后回到原交易状态 |
| 已退款 | 渠道确认退款成功 | 计退款成功；按实际退款金额扣预估收入；完全退款扣净销量 | 迟到退款进入下一账期调整 |
| 拒付待裁决 | 支付机构已确认争议打开 | 展示风险金额，不扣预估收入和净销量 | 裁决后进入胜诉或败诉 |
| 拒付胜诉 | 支付机构确认平台胜诉 | 清除风险，保留收入和净销量 | 只读终态 |
| 拒付败诉 | 支付机构确认平台败诉 | 扣拒付金额和净销量 | 迟到结果进入下一账期调整 |
| 已关闭 | 未完成支付或履约，订单关闭 | 不计销量、销售额、收入和待结算 | 只读终态 |

##### 经营看板与财务模块边界

| 对象 | 数据看板展示 | 财务模块处理 | 一致性要求 |
|---|---|---|---|
| 预估收入 | 按当前交易快照动态计算 | 不作为付款依据 | 使用相同原币、汇率版本、结算币种和规则版本 |
| 待结算 | 按结算币种展示财务模块返回的已锁定且未清偿摘要 | 确认正式金额、部分付款和付款状态 | 第十五份财务模块为唯一事实来源；经营筛选不得重新分摊 |
| 对账流水 | 展示订单级脱敏摘要并提供跳转 | 提供完整结算流水查询和导出 | 对账流水号、SKU、履约和资金方向一致 |
| 账单与付款 | 只展示摘要 | 处理确认、差异、发票、付款和凭证 | 看板不得修改正式状态 |

### 4.1 埋点与数据需求

**数据结论：** 新增开发者经营指标、页面使用事件和参数。

#### 4.1.1 指标口径

| 指标名称 | 口径（含公式、分子和分母） | 去重与时间窗口 | 数据源与决策用途 |
|---|---|---|---|
| 付费销量 | 筛选期内应付金额＞0 且完成履约的订单数 | 先按 `fulfillment_completed_at` 选出履约订单队列，再按 `order_id + fulfillment_type` 去重 | 订单与履约；判断付费规模 |
| 免费领取 | 筛选期内应付金额＝0 且完成履约的订单数 | 与付费销量使用同一履约完成时间窗口，按 `order_id + fulfillment_type` 去重 | 订单与履约；判断免费转化规模 |
| 销售额 | 履约订单队列内付费订单的实付金额之和 | 支付按 `payment_id` 首次成功去重；交易原币按当前快照汇率版本折算为财务主体结算币种 | 支付、订单、履约；解释收入基数 |
| 退款成功 | 履约订单队列内，截至 `data_cutoff_at` 已完全退款的订单数与实际退款金额 | 订单数按 `order_id` 去重，金额按成功退款流水汇总；迟到退款仍进入后续正式账期调整 | 退款终态；识别队列内逆向交易 |
| 退款率 | 同一履约订单队列内完全退款订单数 ÷ 付费销量 | 分子、分母必须来自同一订单队列和同一数据截止时间；分母为 0 时显示“--” | 订单与退款；判断商品质量和售后风险 |
| 拒付风险 | 履约订单队列内，截至 `data_cutoff_at` 已打开且未裁决的拒付案例数与风险金额 | 按拒付案例号去重；只提示风险，不扣净销量和预估收入 | 支付机构拒付；预警潜在损失 |
| 拒付败诉 | 履约订单队列内，截至 `data_cutoff_at` 已败诉的订单数与金额 | 订单数按 `order_id` 去重；迟到裁决仍进入后续正式账期调整 | 支付机构拒付；确认队列内实际损失 |
| 净销量 | 同一履约订单队列内的付费销量－完全退款订单数－拒付败诉订单数 | 同一订单退款与拒付只扣一次；部分退款不扣销量 | 订单、退款、拒付；判断有效成交 |
| 预估收入 | 折算后销售额－成功退款－拒付败诉－税费－渠道费－平台分成＋调整项 | 以同一订单队列和 `data_cutoff_at` 计算；展示 `settlement_currency` 与 `fx_version`；缺少汇率或必要费用时为“估算中／--” | 交易、费用和规则快照；供结算前预核 |
| 待结算 | 第十五份财务模块返回的锁定账单未清偿余额 | 只按当前厂商、账期、结算币种读取；多个结算币种分别展示，禁止相加；不按经营筛选重新分摊 | 财务账单与付款；提示正式待处理规模 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 数据计算 | 指标和金额由服务端按同一快照计算，前端只展示结果、更新时间和口径版本；金额使用整数最小单位或 Decimal，不能使用二进制浮点数。 |
| 权限 | 服务端从登录会话解析 `vendor_id` 和数据权限，同时校验 `game_id` 属于当前厂商且账号有权管理；不信任 URL、前端筛选或请求体中的厂商编号。聚合、列表、详情和财务跳转分别校验厂商与游戏权限。 |
| 一致性 | 同一筛选操作返回同一快照版本；看板与财务模块使用相同的订单、对账流水号、结算单号、原币、汇率版本、结算币种和规则版本。 |
| 跳转契约 | `#/settlement` 仅接收 `statement`、`ledger_source`；`#/settlement/flows` 仅接收固定当前 `game`、`fulfillment`、`range`、`ledger_source`。`vendor_id` 不进入 URL，由目标页从会话重新解析；`game` 必须为当前游戏的稳定 Game ID，不允许为 `all` 或游戏名称。目标页对白名单外、枚举非法、无权限或不可见数据统一降级到默认列表，不返回数据是否存在。 |
| 安全 | 列表、详情、日志和埋点不得包含玩家身份、设备、支付账号、支付凭证、Key 明文、客服记录和内部处理材料；越权结果不得泄露记录存在性。 |
| 兼容 | 支持发行平台桌面 Web 页面，并保证 390px 窄屏无页面根节点横向溢出；宽表仅在表格容器内横向滚动。 |
| 异常恢复 | 接口失败时保留页签、筛选和滚动位置；重试不重复生成销量或流水；跳转财务失败时保留当前页面。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 口径维护 | 运营与数据团队维护可追溯的数据口径版本、更新时间和变更说明；口径变化不能静默改写已锁定账单。 |
| 异常协同 | 支付成功未履约、退款拒付冲突、汇率或必要费用缺失进入平台异常队列；开发者侧只展示可理解状态，不暴露内部处理材料。 |
| 客服定位 | 客服和财务使用对账流水号定位订单；不得要求开发者提供玩家隐私、支付凭证或 Key 明文。 |

### 4.4 财务、法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 财务 | 看板金额为动态预估；正式金额、账单确认、差异、发票、付款和凭证以第十五份财务模块为准。待结算未清偿余额也以该模块为唯一事实来源。已锁定账单不可改写，迟到退款、拒付和费用进入下一账期调整并关联原订单与原账单。 |
| 法务 | 本需求不新增协议或资质；企业认证失效时按权限规则停止新数据查询，资格暂停账号仅保留授权的历史只读范围。 |
| 版权 | 页面只展示当前厂商有权管理的游戏名称、商品和素材；不得跨厂商返回其他主体数据。 |
| 其他合规 | 跨境与多币种交易保留原币、汇率版本和结算币种；页面及导出遵循数据最小化和订单脱敏要求。 |
