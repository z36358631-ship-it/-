## 一、文档概述

### 1.1 背景概述

- **需求背景：** [已确认] 已通过企业认证的游戏开发者和发行商，需要在单个游戏下判断站内曝光获取与玩家质量。
- **当前方式：** [已确认] 旧方案把经营概览、订单明细和收入结算放在同一看板，并同时展示漏斗、来源分析和趋势切换，用户无法快速定位一个指标的逐日变化。
- **问题：** 页面任务过多；收费游戏缺少购买用户口径；各指标不能统一下钻；指标定义与日期数据的查看操作不一致。
- **解决方案：** [已确认] 单游戏“经营数据”只保留“曝光转化”“用户数据”两页签。每个指标均可点击并进入同一按日详情，支持图表、表格、刷新、全屏和 CSV 导出；指标定义与日期数据均采用鼠标悬浮查看。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 只改开发者平台 B 端单游戏控制台的“经营数据”；不修改 C 端。页面不展示经营概览、订单明细、收入与结算、商品类型、站内转化漏斗、来源分析或独立“数据口径”入口。 |
| 业务边界 | 统计当前游戏在 Mac 平台的曝光、购买、下载、启动、留存和游戏时长。来源位置仅作为曝光转化筛选条件；订单查询、财务对账、评分评价、社区互动、预约和广告投放不在本需求内。 |
| 运营边界 | 运营和数据团队维护统计口径、数据截止时间及异常处理；本期不新增运营配置页面。 |
| 人力边界 | Web 前端实现双页签、筛选、日期选择、指标卡和按日详情；服务端按厂商与游戏权限返回聚合数据及逐日序列；数据团队实现指标口径与埋点；测试覆盖权限、筛选、日期边界、指标下钻、留存成熟度、悬浮、导出和响应式。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 当前游戏 | Current Game | 开发者从“游戏管理”进入且有权管理的单个游戏；看板内不提供游戏切换。 |
| UV | Unique Visitor / User | 按对应指标的账号或访问者标识去重后的用户数。周期 UV 按所选日期区间跨日去重，不等于每日 UV 相加。 |
| 购买用户 | Purchasing User | 当前游戏存在已上架收费商品时，在所选日期区间内支付成功的去重账号；同一账号购买游戏本体或多个 DLC 只计 1 人。后续退款或拒付不回溯改写购买事件。 |
| 成功获取用户 | Successful Acquisition User | 在所选日期区间内完成下载或成功启动任一行为的去重账号；同一账号完成多个行为只计 1 人。原“履约成功”并入该指标，不再独立展示。 |
| 留存成熟度 | Retention Maturity | 新增玩家自首次成功启动日起，已完整经过第 1、3、7 个自然日后，才进入对应留存率分母。 |
| 来源位置 | Source Position | 用户进入游戏详情或相关获取链路时对应的站内位置或访问渠道，仅作为曝光转化筛选条件。 |
| 数据截止时间 | Data Cutoff | 当前快照已处理完成的数据终点；快捷周期和未来日期禁用均以该时间所在日期为准。 |
| 按日详情 | Daily Detail | 当前选中指标在所选区间内按自然日输出的图表或表格；图表横轴文案可稀疏展示，但每天均有数据位置或“—”。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向发行平台企业开发者的单游戏只读数据入口，分别回答“曝光、购买和获取表现如何”以及“获取后的玩家是否启动、留存并持续游玩”。 |
| 目标用户 | 企业认证已通过，且拥有当前游戏经营数据权限的开发者、发行商和数据分析人员。 |
| 核心目标 | 让开发者在同一时间、来源和地区范围内点击任一指标查看逐日明细，定位商店页承接或玩家质量变化。 |
| 使用场景 | 版本发布后观察曝光获取；收费游戏查看购买用户；活动期比较来源和地区；日常跟踪新增、活跃、留存及游戏时长。 |
| 功能概述 | 默认进入“曝光转化”：免费游戏展示五项指标，存在已上架收费商品的游戏增加“购买用户数”；切换“用户数据”后展示六项玩家指标。两页签复用同一套按日图表、表格、刷新、全屏和导出能力。 |

### 2.2 产品流程

![数据看板流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@506c2bb19603b713f8567edb4fef7771c4cbe332/public/prd/publisher-data-dashboard/01-product-flow.png)

*图 2.2-1：从单游戏控制台进入经营数据，查看曝光转化、筛选范围并切换用户数据。*

流程说明：

1. 企业认证已通过且有权限的开发者从“游戏管理”进入当前游戏，点击“经营数据”。
2. 页面默认展示 Mac 平台近 30 天、全部来源和全部地区的曝光转化；默认选中“有效曝光”。
3. 开发者调整时间、来源或地区，点击任一指标卡查看该指标的逐日图表或表格；鼠标悬浮问号查看指标定义。
4. 开发者切换“用户数据”，沿用时间和地区，点击活跃、新增、留存或时长指标查看逐日详情。

### 3.1 B 端功能需求

#### 3.1.1 P10-01 单游戏数据看板

| 输出／后置条件 | 页面形成当前游戏、Mac、时间、来源和地区条件下的曝光获取或玩家质量快照，并展示当前选中指标的逐日详情。 |

##### 曝光转化指标

| 指标 | 定义与公式 | 去重与时间归属 | 无法计算 |
|---|---|---|---|
| 有效曝光 | 当前游戏卡片在站内完成有效展示的 UV | 周期卡按账号跨日去重；逐日详情中同一账号同一自然日重复曝光计一次 | 字段缺失显示“—” |
| 游戏卡点击率 | 游戏卡点击 UV ÷ 有效曝光 UV | 周期卡使用周期去重分子和分母；逐日详情使用当日分子和分母，不平均每日百分比 | 分母为 0 显示“—” |
| 详情页访问 | 成功打开当前游戏详情页的 UV | 周期卡按账号跨日去重；逐日详情按账号和自然日去重 | 字段缺失显示“—” |
| 购买用户数 | 当前游戏下支付成功的去重账号数；仅在存在已上架收费游戏本体或 DLC 时展示 | 同一账号购买多个收费商品仍计 1 人；按支付成功日归属，退款或拒付不回溯冲减购买事件 | 无购买显示 0；字段缺失显示“—” |
| 详情获取转化率 | 成功获取用户数 ÷ 详情页访问 UV | 分子为同一筛选范围和详情访问队列中完成下载或成功启动任一行为的周期去重账号；逐日详情按当日分子和分母计算 | 分母为 0 显示“—” |
| 成功获取用户数 | 完成下载或成功启动任一行为的去重账号数 | 同一账号完成多种行为只计 1 人；周期卡跨日去重，逐日详情按自然日去重 | 字段缺失显示“—” |

##### 用户数据指标

| 指标 | 定义与公式 | 去重与时间归属 | 无法计算 |
|---|---|---|---|
| 活跃玩家数 | 统计期内至少成功启动一次当前游戏的账号数 | 周期卡按账号跨日去重；逐日详情按账号和自然日去重；固定 Mac | 无有效启动显示 0；字段缺失显示“—” |
| 新增玩家数 | 统计期内首次成功启动当前游戏的账号数 | 按账号首次成功启动日归属；同一账号仅有一个首次日 | 未产生新增玩家时显示 0；数据字段缺失时显示“—” |
| 次日留存 | 第 1 个自然日再次成功启动的成熟新增玩家数 ÷ 已观察满 1 日的新增玩家数 | 按首次启动 cohort 日展示；未成熟 cohort 不进入分母 | 无成熟分母显示“—” |
| 3 日留存 | 第 3 个自然日再次成功启动的成熟新增玩家数 ÷ 已观察满 3 日的新增玩家数 | 归属到玩家首次启动所在 cohort 日；只统计已完整观察 3 日的 cohort | 无成熟分母显示“—” |
| 7 日留存 | 第 7 个自然日再次成功启动的成熟新增玩家数 ÷ 已观察满 7 日的新增玩家数 | 归属到玩家首次启动所在 cohort 日；只统计已完整观察 7 日的 cohort | 无成熟分母显示“—” |
| 平均游戏时长 | 有效游戏会话总时长 ÷ 活跃玩家数 | 周期卡按活跃玩家加权；逐日详情使用当日有效时长与当日活跃玩家；单次不足 1 分钟的异常会话不计入 | 分母为 0 或字段缺失显示“—” |

##### 日期范围规则

| 范围 | 起止日期 | 默认与边界 | 失败与恢复 |
|---|---|---|---|
| 昨日／今日 | 昨日为数据截止日前一日；今日为数据截止日 | 起止日为同一天 | 查询失败保留原已生效区间 |
| 近 7 天／近 30 天 | 包含数据截止日及起始日 | 默认近 30 天 | 查询失败保留原已生效区间 |
| 上月／本月 | 上一完整自然月；本月 1 日至数据截止日 | 未来日期禁用 | 查询失败保留原已生效区间 |
| 自定义 | 用户选择开始日与结束日，起止日均计入 | 最长 180 个自然日；结束日不得晚于数据截止日 | 非法区间禁用“应用”；取消不改变原区间 |

##### 角色权限与数据范围

| 账号状态／角色 | 权限与范围 | 禁止与越权 | 恢复 |
|---|---|---|---|
| 企业认证已通过且有经营数据与当前游戏权限 | 查看当前游戏的曝光转化、用户数据和逐日详情；导出当前筛选的 CSV | 不可跨厂商或跨游戏查询，不可修改数据 | 权限恢复或重新授权后按最新范围查询 |
| 企业资格暂停且保留历史查看权 | 只读查看暂停前已授权游戏形成的历史聚合数据 | 不可查询暂停后新增数据，不可切换越权游戏 | 资格恢复后按最新授权恢复查询 |
| 个人、未提交、审核中、已驳回或无对应权限 | 不展示真实经营数据 | 服务端拒绝越权请求且不泄露数据是否存在 | 企业认证通过并获得厂商及游戏权限后生效 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 改造数据看板浏览、页签和筛选事件；新增指标选择、详情展示方式、刷新、全屏、导出和指标定义展示事件。不采集高频日期区域悬浮事件，不采集订单或结算页面事件。

#### 4.1.1 埋点事件

| 事件 | 页面／类型 | 触发与成功 | 参数 |
|---|---|---|---|
| publisher_dashboard_view | 数据看板／改造 | 权限校验完成且首屏查询结束后上报一次；空态、失败和无权限分别记录结果 | vendor_id, qualification_status, game_id, platform, dashboard_tab, time_range, start_date, end_date, source_position, region_filter_type, region_filter_value, data_cutoff_at, result |
| publisher_dashboard_tab_click | 页签／改造 | 点击目标页签且页面完成切换后上报 | vendor_id, game_id, dashboard_tab, result |
| publisher_dashboard_filter_change | 筛选／改造 | 新筛选提交且当前页签查询结束后上报；失败仍记录 error | vendor_id, game_id, platform, dashboard_tab, filter_name, filter_value, time_range, start_date, end_date, source_position, region_filter_type, region_filter_value, data_cutoff_at, result |
| publisher_dashboard_metric_select | 指标卡／新增 | 点击指标卡且共享详情切换到目标指标后上报 | vendor_id, game_id, dashboard_tab, metric_name, data_granularity, result |
| publisher_dashboard_detail_view_change | 按日详情／新增 | 点击“图表”或“表格”且展示方式完成切换后上报 | vendor_id, game_id, dashboard_tab, metric_name, detail_view, data_granularity, result |
| publisher_dashboard_detail_refresh | 按日详情／新增 | 点击刷新并在请求完成后上报成功或失败 | vendor_id, game_id, dashboard_tab, metric_name, time_range, start_date, end_date, data_cutoff_at, result |
| publisher_dashboard_detail_fullscreen | 按日详情／新增 | 进入或退出全屏后上报 | vendor_id, game_id, dashboard_tab, metric_name, fullscreen_state, result |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 查询上下文 | 服务端从登录会话解析 vendor_id，校验 game_id 属于当前厂商且账号有权管理；不信任 URL 或请求体中的厂商编号。平台固定 mac。 |
| 筛选作用域 | 时间与地区作用于两页签；来源位置只作用于曝光转化。商品类型不参与页面展示、请求、缓存键或导出。 |
| 快照一致性 | 同一次查询返回统一 data_cutoff_at；周期指标和当前按日详情基于同一截止时间。请求乱序时只应用最后一次有效结果。 |
| 逐日序列 | 返回所选起止日内每个自然日的数据；无成熟值返回空值并显示“—”。横轴可稀疏展示日期文案，表格和 CSV 必须保留每一天。 |
| 收费判断 | 当前游戏本体或任一 DLC 存在已上架收费 SKU 时展示“购买用户数”；全部商品均免费时不返回该指标，前端不得显示空卡片。 |
| 去重与转化 | 周期 UV 跨日去重；每日 UV 按自然日去重。购买用户数取当前游戏下支付成功账号并集；详情获取转化率使用同一详情访问队列中的成功获取用户数除以详情页访问 UV；下载和成功启动取用户并集。 |
| 留存成熟度 | 按新增玩家首次成功启动日构建 cohort，分别剔除未观察满 1、3、7 个自然日的 cohort，再计算留存率。 |
| 状态迁移 | 旧选中指标 fulfillment_success 迁移为 acquisition_success；旧 reservation_users 选中态回退为 impression；旧商品类型值不影响数据；旧页签 overview、orders、revenue 迁移为 conversion；旧合法 90d 起止日保留并转换为 custom，非法区间回退 30d。日期浮层、指标浮层和全屏等瞬时状态不恢复。 |
| 导出 | CSV 与当前页面复用同一数据快照，包含当前游戏、页签、指标、时间、来源、地区、平台，以及每个自然日的值和较前一日变化；文件名包含游戏、页签、指标和起止日。 |
| 无障碍 | 页签和指标卡提供选中态；问号包含可读名称和说明关联；日期浮层为模态对话框并管理焦点；每日区域可键盘聚焦并读出日期、指标和值；Esc 关闭后焦点回到触发控件。 |
| 安全 | 仅返回当前厂商与当前游戏的聚合数据；不展示或上报玩家身份、设备号、支付账号、Key 明文或其他可识别交易信息。越权响应不泄露记录是否存在。 |
| 兼容 | 支持桌面 Web。桌面筛选保持一行；390px 窄屏允许筛选和指标在自身容器横向滚动，页面根节点不得横向溢出；日期浮层展示单月并支持前后翻月；指标定义浮层不得被容器裁切。 |
| 异常恢复 | 查询、刷新或导出失败时保留上一份成功数据、页签、筛选、选中指标和滚动位置；日期取消或校验失败不修改已生效条件；重新请求不重复累计指标。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 口径维护 | 数据团队维护指标公式、去重、留存成熟度和数据截止时间；口径变更需留痕，不静默改写已导出的历史报表。 |
| 异常处理 | 数据延迟、字段缺失或分母不可用时返回明确状态；前端显示“—”及说明，不以 0 替代未知值。 |
| 隐私阈值 | 来源或地区筛选后的聚合样本低于平台统一阈值时，按隐私规范隐藏数值或显示“<10”，不得反推出单个玩家。 |

### 4.4 法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 法务 | 本需求不新增协议、资质、交易、退款或结算规则。 |
| 版权 | 仅展示当前厂商有权管理的游戏名称和聚合经营数据。 |
| 数据合规 | 按最小必要原则返回聚合数据；账号去重、匿名标识关联及跨地区处理遵循平台现有隐私规范。 |
