## 一、文档概述

### 1.1 背景概述

- **需求背景：** [已确认] 已通过企业认证的游戏开发者和发行商，需要在单个游戏下判断站内流量转化与玩家质量。
- **当前方式：** [已确认] 旧方案把经营概览、订单明细、收入与结算放在同一看板，筛选和指标解释分散，难以快速定位游戏在站内转化或留存上的问题。
- **问题：** 页面同时承载经营、订单和财务任务，信息层级过重；用户指标缺失；时间控件、地区筛选和指标定义不够直接。
- **解决方案：** [已确认] 单游戏“经营数据”只保留“曝光转化”“用户数据”两页签。平台固定 Mac；筛选栏保持一行；时间支持快捷周期与自定义日期；每个数据指标旁提供问号定义。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 只改开发者平台 B 端单游戏控制台的“经营数据”。页签仅保留“曝光转化”“用户数据”；不在本页面展示订单明细、收入与结算或独立“数据口径”入口；不修改 C 端。 |
| 业务边界 | 统计当前游戏在 Mac 平台的买断游戏本体与永久 DLC 数据。曝光转化覆盖站内发现至履约；用户数据覆盖启动、留存与游戏时长。评分评价、社区互动、预约、广告投放、财务对账和订单查询不在本需求内。 |
| 运营边界 | 运营和数据团队维护统计口径、数据更新时间和异常处理；本期不新增运营配置页面。 |
| 人力边界 | Web 前端实现两页签、筛选、日期浮层、趋势和指标说明；服务端按厂商与游戏权限返回聚合数据；数据团队实现口径与埋点；测试覆盖权限、日期边界、筛选作用域、留存成熟度、迁移与响应式交互。 |

### 1.3 术语定义

| 术语／缩写 | 英文全称（按需） | 定义与判断口径 |
|---|---|---|
| 当前游戏 | Current Game | 开发者从“游戏管理”进入且有权管理的单个游戏；看板不提供游戏切换。 |
| UV | Unique Visitor / User | 按对应指标的账号或访问者标识去重后的用户数。 |
| 有效曝光 | Qualified Impression | 游戏卡片在站内满足统一可见面积与时长阈值的曝光；同一用户同一自然日重复曝光仅计一次。 |
| 成功获取 | Successful Acquisition | 用户支付成功或免费领取成功并获得游戏权益。 |
| 履约成功 | Fulfillment Success | 直接购买的账号权益生效，或 CDKEY 完成交付。 |
| 新增玩家 | New Player | 统计期内首次成功启动当前游戏的去重账号。 |
| 留存成熟度 | Retention Maturity | 新增玩家自首次启动日起，已完整经过对应第 1、3、7 个自然日，才进入相应留存率分母。 |
| 来源位置 | Source Position | 用于区分用户第一次进入本次漏斗的站内位置或访问渠道。 |
| 数据截止时间 | Data Cutoff | 本次快照已处理完成的数据终点；快捷周期和未来日期禁用均以该时间所在日期为准。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 面向发行平台企业开发者的单游戏只读数据入口，用两页分别回答“用户从哪里来、在哪一步流失”和“获取后是否启动、留存及持续游玩”。 |
| 目标用户 | 企业认证已通过且拥有当前游戏经营数据权限的开发者、发行商和数据分析人员；资格暂停但保留历史查看权的账号只读查看授权范围内历史数据。 |
| 核心目标 | 让开发者用同一时间和地区范围判断曝光转化与玩家质量，定位素材、商店页、获取链路或游戏体验问题。 |
| 使用场景 | 版本发布后观察站内转化；活动期比较来源和地区表现；日常跟踪新增、活跃、留存与游戏时长。 |
| 功能概述 | 默认进入“曝光转化”，展示六项核心指标、七步漏斗、趋势和来源分析；切换“用户数据”后展示活跃、新增、次日／3 日／7 日留存、人均游戏时长及用户趋势。 |

流程说明：

1. 企业认证已通过且有权限的开发者从“游戏管理”进入当前游戏，点击“经营数据”。
2. 页面默认展示当前 Mac 游戏近 30 天、全部商品、全部来源和全部地区的曝光转化数据。
3. 开发者调整时间、商品、来源或地区，查看六项核心指标、七步漏斗、趋势和来源分析；点击问号查看指标定义。
4. 开发者切换“用户数据”，沿用时间与地区，查看活跃、新增、留存、游戏时长及趋势。

##### 曝光转化指标

| 指标 | 定义与公式 | 去重与窗口 | 无法计算 |
|---|---|---|---|
| 有效曝光 | 当前游戏或独立 DLC 卡片在站内完成有效展示的 UV | 同一用户、同一游戏或 SKU、同一自然日重复曝光计一次；入口发生在筛选期内 | 字段缺失显示“—” |
| 游戏卡点击率 | 游戏卡点击 UV ÷ 有效曝光 UV | 点击归属于同一入口队列 | 分母为 0 显示“—” |
| 详情页访问 | 成功打开当前游戏详情页的 UV | 按用户与当前游戏去重 | 字段缺失显示“—” |
| 详情获取转化率 | 成功获取 UV ÷ 详情页访问 UV | 使用同一入口队列和数据截止时间 | 分母为 0 显示“—” |
| 购买／领取点击 | 在详情页点击购买或免费领取的 UV | 按用户与 SKU 去重 | 字段缺失显示“—” |
| 创建订单 | 成功创建付费或免费订单的 UV | 重复创建同一订单不重复计入 | 字段缺失显示“—” |
| 成功获取 | 支付成功或免费领取成功并获得游戏权益的 UV | 付费按首次成功支付去重；免费领取按成功终态去重 | 字段缺失显示“—” |
| 履约成功 | 账号权益生效或 CDKEY 完成交付的 UV | 按订单与履约类型成功终态去重后，再按用户去重 | 字段缺失显示“—” |
| 曝光到获取转化率 | 成功获取 UV ÷ 有效曝光 UV | 入口发生后 7×24 小时归因；成功获取时冻结来源 | 分母为 0 显示“—” |
| 来源位置 | 用户首次进入本次漏斗时对应的站内位置或访问来源 | 成功获取采用 7×24 小时内最后一次有效非直接触点；无触点归自然直达 | 无法识别时归“其他” |

#### 3.1.3 P10-03 用户数据

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 查看当前游戏的活跃、新增、留存、人均游戏时长和用户趋势。 |
| 场景描述 | 开发者需要判断成功获取后的用户是否启动游戏、持续返回并形成有效游玩。 |
| 输入／前置条件 | 与“曝光转化”使用相同账号、厂商、当前游戏和 Mac 权限；从页签切换进入，沿用时间与地区。 |

| 输出／后置条件 | 页面形成当前游戏、Mac、时间和地区下的用户质量快照；开发者可切换活跃或新增趋势，或返回曝光转化继续分析。 |
| 补充说明 | 1. 用户数据按账号去重；账号未满足当前游戏有效启动条件时不计入活跃或新增。<br>2. 留存率分母只包含已观察满相应天数的新增玩家；没有成熟 cohort 时显示“—”，不得显示 0%。<br>3. 单次不足 1 分钟的异常会话不计入游戏时长；总有效时长或活跃玩家数缺失时平均游戏时长显示“—”。<br>4. 查询为空时保留当前筛选并显示空态；失败时保留上一份成功数据、页签、筛选和滚动位置并允许重试。 |

##### 用户指标

| 指标 | 定义与公式 | 去重与窗口 | 无法计算 |
|---|---|---|---|
| 活跃玩家数 | 统计期内至少成功启动过一次当前游戏的账号数 | 按账号去重；固定 Mac | 无有效启动显示 0；数据缺失显示“—” |
| 新增玩家数 | 统计期内首次成功启动当前游戏的账号数 | 按账号首次成功启动时间归属统计期 | 无新增显示 0；数据缺失显示“—” |
| 次日留存 | 第 1 个自然日再次成功启动的成熟新增玩家数 ÷ 已观察满 1 日的新增玩家数 | 按账号去重；未成熟 cohort 不进入分母 | 无成熟分母显示“—” |
| 3 日留存 | 第 3 个自然日再次成功启动的成熟新增玩家数 ÷ 已观察满 3 日的新增玩家数 | 按账号去重；剔除观察期不足 3 日的 cohort | 无成熟分母显示“—” |
| 7 日留存 | 第 7 个自然日再次成功启动的成熟新增玩家数 ÷ 已观察满 7 日的新增玩家数 | 按账号去重；剔除观察期不足 7 日的 cohort | 无成熟分母显示“—” |
| 平均游戏时长 | 统计期内有效游戏会话总时长 ÷ 活跃玩家数 | 有效会话按账号归集；单次不足 1 分钟的异常会话不计入 | 分母为 0 或数据缺失显示“—” |

##### 角色权限与数据范围

| 账号状态／角色 | 权限与范围 | 禁止与越权 | 恢复 |
|---|---|---|---|
| 企业认证已通过且有经营数据与当前游戏权限 | 查看当前游戏的曝光转化与用户数据 | 不可跨厂商、跨游戏查询，不可修改数据 | 权限撤销后立即停止新查询 |
| 企业资格暂停且保留历史查看权 | 只读查看暂停前已授权游戏形成的历史聚合数据 | 不可查询暂停后新增数据，不可切换越权游戏 | 资格恢复后按最新授权恢复查询 |
| 个人、未提交、审核中、已驳回或无对应权限 | 不展示真实经营数据 | 服务端统一拒绝越权请求且不泄露数据是否存在 | 企业认证通过并获得厂商和游戏权限后生效 |

## 四、支撑及非功能需求

### 4.1 埋点与数据需求

**数据结论：** 改造开发者数据看板页面、页签、筛选、趋势和指标定义埋点；新增用户数据指标，不采集订单或结算页面事件。

#### 4.1.1 埋点事件

| 事件 | 页面／类型 | 触发与成功 | 参数 |
|---|---|---|---|
| publisher_dashboard_view | B 端／数据看板／改造 | 权限校验完成且默认页签首屏查询结束后上报一次；空态和失败分别记录结果 | vendor_id, qualification_status, game_id, platform, dashboard_tab, time_range, start_date, end_date, region_filter_type, region_filter_value, data_cutoff_at, result |
| publisher_dashboard_tab_click | B 端／页签／改造 | 点击“曝光转化”或“用户数据”且目标页签完成展示后上报 | vendor_id, game_id, dashboard_tab, result |
| publisher_dashboard_filter_change | B 端／筛选／改造 | 新筛选提交且当前页签查询结束后上报；失败保留旧数据并记录 error | vendor_id, game_id, platform, dashboard_tab, filter_name, filter_value, time_range, start_date, end_date, product_type, source_position, region_filter_type, region_filter_value, data_cutoff_at, result |
| publisher_dashboard_trend_metric_click | B 端／趋势／改造 | 切换曝光转化或用户趋势指标且目标序列完成展示后上报 | vendor_id, game_id, dashboard_tab, metric_name, time_range, start_date, end_date, region_filter_type, region_filter_value, data_cutoff_at, result |
| publisher_dashboard_metric_help_open | B 端／指标说明／新增 | 用户通过点击、Enter 或 Space 展开一个指标定义时上报；Hover 和 focus 预览不重复上报 | vendor_id, game_id, dashboard_tab, metric_name, input_method, result |

#### 4.1.2 参数说明

| 参数 | 类型／必填 | 说明 | 枚举／示例 |
|---|---|---|---|
| vendor_id | string／是 | 服务端从登录会话确定的厂商编号 | 例：VENDOR-STAR-001 |
| qualification_status | enum／是 | 当前企业资格状态 | approved＝已通过；suspended＝已暂停 |
| game_id | string／是 | 当前单游戏控制台绑定的稳定 Game ID | 例：GAME-48291 |
| platform | enum／是 | 当前页面固定平台 | mac＝Mac |
| dashboard_tab | enum／是 | 当前页签 | conversion＝曝光转化；users＝用户数据 |
| time_range | enum／是 | 当前已生效时间范围 | yesterday＝昨日；today＝今日；7d＝近 7 天；30d＝近 30 天；last_month＝上月；current_month＝本月；custom＝自定义 |
| start_date | date／是 | 当前已生效区间开始日期 | 例：2026-08-12 |
| end_date | date／是 | 当前已生效区间结束日期 | 例：2026-09-10 |
| product_type | enum／条件必填 | 曝光转化页当前商品筛选；用户数据页不上报 | all＝全部；base_game＝游戏本体；permanent_dlc＝永久 DLC |
| source_position | enum／条件必填 | 曝光转化页当前来源筛选；用户数据页不上报 | all＝全部；home＝首页推荐；discovery＝找游戏；ranking＝排行榜；search＝搜索；campaign＝专题活动；external＝站外活动；direct＝自然直达；other＝其他 |
| region_filter_type | enum／是 | 当前地区筛选层级 | all＝全部；scope＝发行范围；country_region＝具体国家／地区 |
| region_filter_value | string／是 | 发行范围用稳定枚举，具体国家／地区用代码，不上报本地化名称 | 例：all、global、domestic、JP、US、CN |
| filter_name | enum／是 | 本次变更的筛选项 | time_range＝时间；product_type＝商品；source_position＝来源；region_filter＝地区；reset＝重置 |
| filter_value | string／是 | 本次提交值；自定义日期用起止日组合 | 例：30d、JP、2026-08-01/2026-08-31 |
| metric_name | enum／是 | 趋势或指标定义对应指标 | impression＝有效曝光；card_ctr＝游戏卡点击率；detail_view＝详情页访问；detail_acquisition＝详情获取转化率；<br>cta_click＝购买／领取点击；order_create＝创建订单；acquisition_success＝成功获取；fulfillment_success＝履约成功；<br>overall_conversion＝曝光到获取转化率；source＝来源位置；active_players＝活跃玩家；new_players＝新增玩家；<br>retention_1d＝次日留存；retention_3d＝3 日留存；retention_7d＝7 日留存；avg_duration＝平均游戏时长 |
| input_method | enum／条件必填 | 指标定义打开方式，仅 publisher_dashboard_metric_help_open 上报 | click＝鼠标或触控点击；keyboard＝Enter 或 Space |
| data_cutoff_at | datetime／是 | 当前快照的数据截止时间 | 例：2026-09-10 23:59:59+08:00 |
| result | enum／是 | 页面或查询结果 | success＝成功；empty＝空结果；error＝失败；denied＝无权限 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 查询上下文 | 服务端从登录会话解析 vendor_id，并校验 game_id 属于当前厂商且账号有权管理；不信任 URL 或请求体中的厂商编号。平台固定 mac。 |
| 筛选作用域 | 时间与地区作用于两页签；商品与来源只作用于曝光转化。切换页签保留各自页面状态，服务端忽略用户数据请求中的商品与来源。 |
| 快照一致性 | 同一次查询返回统一 data_cutoff_at；页面上的指标、趋势和来源均基于同一截止时间。请求乱序时只应用最后一次有效请求结果。 |
| 去重与归因 | 曝光转化按入口队列和 7×24 小时窗口处理；用户数据按账号去重。登录前后只有取得合法关联依据时才能合并匿名访问者与账号。 |
| 留存成熟度 | 服务端按新增玩家首次成功启动日构建 cohort，分别剔除未观察满 1、3、7 个自然日的 cohort，再计算相应留存率。 |
| 历史迁移 | 旧页签 overview、orders、revenue 和非法值迁移为 conversion。旧时间 90d 的合法区间保留日期并转为 custom，缺失起止日时补为截止日前 89 日至截止日，非法区间回退 30d；不恢复 datePickerOpen、activeTooltip、日期草稿等瞬时 UI 状态。 |
| 无障碍 | 页签使用可识别选中态；指标问号有可读名称、aria-expanded 和说明关联；日期浮层为模态对话框并管理焦点；Esc 关闭后焦点回到触发控件。 |
| 安全 | 只返回当前厂商与当前游戏的聚合数据；不展示或上报玩家身份、设备号、支付账号、Key 明文或其他可识别交易信息。越权响应不得泄露记录是否存在。 |
| 兼容 | 支持桌面 Web；桌面筛选保持一行。390px 窄屏允许筛选栏和来源表在自身容器横向滚动，页面根节点不得横向溢出；日期浮层展示单月且同时可前后翻月；指标浮层不得被滚动容器裁切。 |
| 异常恢复 | 查询失败保留上一份成功数据、页签、筛选和滚动位置；日期取消或校验失败不修改已生效条件；重新请求不重复累计指标。 |

### 4.3 运营需求

| 需求项 | 具体要求 |
|---|---|
| 口径维护 | 数据团队维护指标口径、去重规则、归因窗口和数据截止时间；口径变更需可追溯，不能静默改写已出具的历史报表。 |
| 异常处理 | 数据延迟、缺失或分母不可用时返回明确状态；前端显示“—”及说明，不以 0 替代未知值。 |
| 隐私阈值 | 运营与数据团队维护来源和地区分组的统一最小展示阈值；低于阈值的数据隐藏比率或合并到“其他”。 |

### 4.4 法务、版权与合规需求

| 需求项 | 具体要求 |
|---|---|
| 法务 | 本需求不新增协议、资质、交易或结算规则。 |
| 版权 | 只展示当前厂商有权管理的游戏名称、商品和聚合数据。 |
| 数据合规 | 按最小必要原则返回聚合数据；账号去重、匿名标识关联及跨地区处理遵循平台现有隐私规范。 |
