## 一、文档概述

### 1.1 背景概述

- **解决对象：** 已签约厂商的发行、商务、运营和管理人员，以及平台发行运营与财务协作人员。
- **核心问题：** 开发者目前无法在同一处核对订单、领取、退款、收入、Key 供给、下载更新和首次启动；若直接建设复杂人群广告系统，不仅超出一期能力，也会掩盖“经营数据是否可信”这一更优先的问题。
- **当前方式：** 交易、Key、客户端行为和财务结算分散在不同系统或线下表格，时间、币种、测试数据和状态口径不一致。
- **本期目标：** 先交付可按游戏、SKU、地区、OS、渠道、日期查询的本厂商整体经营看板；明确预估收入与最终月结算的差异；同时用简化 Campaign／UTM 或人工资源位记录建立基础渠道归因。
- **平台参考：** 借鉴 WeGame 的发行数据、TapTap 登录后可见的商店概览指标和 Steamworks 的活动追踪／销售报表思路，不复制完整广告平台、人群圈选或算法投放能力。

### 1.2 需求边界

| 边界 | 一期范围 | 一期不做 |
|---|---|---|
| 产品边界 | 开发者后台整体经营看板、专题分析、简化渠道归因和聚合导出 | 新增 C 端投放页面、完整广告投放后台 |
| 业务边界 | 交易、退款、收入、结算、双类 Key、下载更新启动及渠道来源聚合 | 用运营估算替代财务结算、无来源数据的推测指标 |
| 运营边界 | 开发者管理轻量 Campaign／UTM 和提交人工资源需求；平台运营回填实际执行结果 | 自动人群投放、竞价、复杂排期与跨厂商比较 |
| 人力边界 | 数据、服务端、客户端、财务和发行运营分别提供权威事实，开发者消费本厂商聚合结果 | 在本模块新增退款审批、合同审批或财务制单团队流程 |
| 数据对象 | 订单、销量／领取、退款、原始收入、退款金额、渠道费、预估净收入、最终月结算 | 自造财务汇率、以看板预估值替代财务结算单 |
| Key | 外部 Key 库存／交付；盖世 Key 自助生成、渠道分配、兑换 | 无法取得的站外激活成功、第三方平台游玩数据 |
| 客户端 | 下载、更新、首次启动，支持 Windows／macOS／Linux | 在线时长、DAU、PCU、Crash 指标承诺 |
| 投放 | 简化 Campaign／UTM 渠道参数；人工资源位需求与执行结果 | 人群规则引擎、人群预估、频控、优先级、复杂排期、算法推荐、广告竞价 |
| 权限 | 开发者后台仅展示本厂商聚合数据，并按当前筛选导出聚合结果 | 用户明细导出、用户反查、跨厂商数据、小群体画像 |
| 退款 | 看板消费退款结果；退款资格中本地离线游玩时长联网补传，异常转人工审核 | 数据缺失时按 0 小时自动退款、在本模块处理用户退款工单 |

### 1.3 术语定义

| 术语 | 定义与口径 |
|---|---|
| 发行主键 | `vendor_id + game_id + app_id`。所有业务事实先归属厂商、游戏和应用，再按 SKU、地区、OS、渠道、日期聚合。 |
| 原始收入 | 支付成功订单的用户实付金额之和，按订单币种统计，未扣退款、渠道费或其他成本。 |
| 退款金额 | 退款成功的实际退款金额；申请中、失败或人工审核中不计入。 |
| 渠道费 | 支付／发行渠道返回或财务确认的费用；尚无可靠金额时显示 `--`，不得填 0。 |
| 预估净收入 | 同币种下 `原始收入 - 退款金额 - 渠道费`。任一必要项缺失时显示 `--`；仅用于运营观察，不是应结算金额。 |
| 最终月结算 | 财务锁定的月度结算单金额与状态，是对账和结算唯一依据；不得由日看板重算替代。 |
| 外部 Key | 厂商／第三方来源导入或接口同步的激活 Key；看板统计可用库存和平台成功交付。 |
| 盖世 Key | 平台为已授权游戏按批次生成的 Key，可分配给渠道并在盖世体系兑换；生成、分配、兑换均留存批次与结果。 |
| Campaign／UTM | 对发行渠道活动的简化归因对象，至少含 `campaign_id`、渠道及 UTM 来源／媒介／活动名；不包含人群或竞价策略。 |
| 数据新鲜度 | 指标最近完整批次、延迟状态和预计恢复时间；延迟、缺失或不适用统一显示 `--` 并给出原因。 |

## 二、产品方案

### 2.1 产品／方案简介

#### 2.1.1 整体经营指标

| 指标组 | 指标 | 计算口径 | 去重／排除 |
|---|---|---|---|
| 获取 | 订单数 | 支付成功的付费 `order_id` 去重数 | 排除取消、支付失败、测试订单 |
| 获取 | 销量 | 支付成功 SKU 件数之和；退款不回减，在退款组单列 | 排除测试及重复回调 |
| 获取 | 领取数 | 成功创建的零价 `claim_id` 去重数 | 排除失败领取、测试领取 |
| 退款 | 退款笔数 | 退款成功 `refund_id` 去重数 | 申请中、驳回、失败、人工审核中不计 |
| 退款 | 退款金额 | 退款成功实际金额按币种求和 | 不用申请金额替代成功金额 |
| 收入 | 原始收入 | 支付成功用户实付金额按币种求和 | 不扣退款、渠道费；排除测试订单 |
| 收入 | 渠道费 | 渠道／财务已返回的有效费用按币种求和 | 未返回显示 `--`，不得按 0 推断 |
| 收入 | 预估净收入 | 同币种原始收入－退款金额－渠道费 | 必要项不完整则为 `--` |
| 结算 | 最终月结算 | 财务锁定月结算单中的最终金额与币种 | 只展示锁定单；不由看板公式覆盖 |
| 外部 Key | 可用库存、成功交付、成功揭示 | 当前可用 Key 数；订单成功取得 Key 的交付记录数；用户首次成功查看明文的揭示记录数 | 交付、揭示和站外激活分别统计；无真实站外激活数据时显示 `--` |
| 盖世 Key | 生成、分配待确认、已交付、确认超时、兑换 | 成功生成 Key 数；渠道首次分配待确认数；受控下载或渠道确认／兑换佐证后的已交付数；到期未确认数；成功兑换数 | 按 `event_id` 去重；生成量按批次 `quantity`，渠道交付按 `allocation_id`，兑换按 `redemption_id`；分配待确认不得计入已交付，作废 Key 不计可用 |
| 客户端 | 下载、更新、首次启动 | 成功下载任务、成功更新任务、`uid + app_id` 历史首次成功启动 | 失败／取消不计成功；测试权益行为排除 |

#### 2.1.2 筛选维度与适用性

| 维度 | 数据定义 | 指标适用规则 |
|---|---|---|
| 游戏 | 当前开发者有权访问的 `game_id + app_id` | 全部指标适用 |
| SKU | 获取时来源快照中的 `sku_id` | 交易、退款、收入、Key 适用；无可靠 SKU 归属的客户端指标显示 `--` |
| 地区 | 交易／领取时固化的商业地区；Key 按分配渠道地区 | 客户端行为沿用对应权益来源地区，不从实时 IP 反推 |
| OS | 交易／领取记录客户端来源 OS；下载、更新、启动使用实际运行 OS | 最终月结算无 OS 拆分时显示 `--`；不得按游戏支持 OS 重复分摊订单 |
| 渠道 | 订单／领取固化的有效 Campaign 渠道或自然渠道；Key 使用分配渠道 | 无有效归因记为 `organic`，不得补写虚假 Campaign |
| 日期 | 订单支付、领取、退款成功、Key 动作、客户端成功事件的业务日期 | 最终结算按结算月；跨事件指标不强行使用同一发生时间 |

筛选变更后所有适用卡片、趋势、明细聚合和导出必须使用同一查询快照。某指标不适用当前筛选时显示 `--` 和“不支持该维度”，不得保留上一次数值。

#### 2.1.3 币种与结算

1. 金额先按原始币种分组汇总；单币种可显示合计，多币种默认展示分币种结果。
2. 仅当财务提供已锁定的汇率版本、基准币种和适用日期时，才能额外展示折算金额，并必须标明汇率版本；否则不得提供跨币种总额。
3. 预估净收入始终标记“预估”，不能用于开票、打款或合同结算；最终月结算以财务锁定结算单为准。
4. 月结算未生成显示“待财务出单”，已生成未锁定显示“核对中”，锁定后展示最终金额；缺失、失败或延迟显示 `--`。

#### 2.1.4 数据隔离、新鲜度与隐私

1. `is_test=true` 的测试订单、测试领取、测试权益、测试 Key 和其下载／启动行为全部排除在真实经营指标之外。
2. 开发者查询必须由服务端注入可访问 `vendor_id`，前端传入的厂商条件不能扩大范围；平台内部可保留用户级事实表，但开发者接口只返回满足聚合阈值的结果。
3. 页面展示“数据更新至”“批次状态”和指标级说明。延迟、上游缺失、计算失败、不适用均显示 `--`，真实零值显示 `0`。
4. 导出只导出当前筛选下的聚合行，不包含 `uid`、手机号、订单明细、设备标识、Key 明文或单用户行为链路。

#### 2.1.5 退款资格数据边界

退款策略中的 14 天／2 小时条件由交易退款模块判断，本模块只消费最终退款状态并展示聚合结果。客户端必须在离线期间本地累计可信游玩时长，联网后补传；当时长数据过旧、缺失、签名校验失败或多端冲突时，不得按 0 小时自动通过退款，必须进入人工审核并保留异常类型。开发者只能看到聚合退款结果和人工审核中数量，不得看到用户游玩明细。

## 三、功能需求

#### C 端影响（无新增页面）

不新增独立 C 端页面。既有交易、Key 兑换、下载、更新和启动流程需固化 `campaign_id`／渠道来源快照、实际 OS、地区和 `is_test`，离线游玩时长需在联网后按退款模块协议补传。

#### P04-04 下载、更新与首次启动分析

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 查看盖世直下游戏的成功下载、更新和首次成功启动。 |

## 四、数据采集与口径

**数据结论：** 涉及跨模块复用、补充和新增埋点；本模块以权威业务终态形成聚合看板，并用导出与测试隔离结果验证数据可信度。

### 4.1 数据来源

| 数据域 | 权威来源 | 本模块消费字段 | 刷新与异常 |
|---|---|---|---|
| 购买／领取／权益 | 交易与权益系统、`game_acquisition_result`、`direct_entitlement_result` | 发行主键、SKU、来源地区／OS／渠道快照、金额、币种、获取类型、`is_test` | 终态增量汇总；重复事件按 `event_id` 去重 |
| 退款 | 退款系统终态及人工审核状态 | `refund_id`、订单／领取关联、成功金额、币种、状态、异常类型 | 只有成功退款进入笔数和金额 |
| 外部 Key | 商品与 CDKEY 供给／交付系统 | 库存状态、Key 状态、交付／揭示结果、SKU、渠道、`is_test` | 库存快照标记更新时间；来源异常显示 `--` |

| 客户端 | `game_download_result`、`game_update_result`、`game_launch_result` | 游戏、版本、实际 OS／架构、任务／首次启动结果、Campaign、`is_test` | 成功终态聚合；离线事件按实际发生时间补传并标记接收时间 |

### 4.4 数据质量要求

| 校验项 | 验收方式 | 通过标准 |
|---|---|---|
| 主键贯通 | 抽取交易、Key、客户端各 20 条事实与聚合反查 | 均能还原 `vendor_id + game_id + app_id`，无跨厂商记录 |
| 测试隔离 | 创建测试订单／权益／Key 并完成下载启动 | 测试专项可查，所有真实经营指标增量为 0 |
| 金额公式 | 构造单币种支付、部分退款、渠道费及多币种样本 | 单币种公式准确；多币种无财务汇率时不出现合计 |
| 缺失显示 | 人工中断一个上游批次 | 受影响指标显示 `--` 与原因，不显示 0 或旧值 |
| 导出一致 | 同一 `query_snapshot_id` 比较页面与文件 | 维度、数值、币种、更新时间一致且无用户明细 |
| 首次启动 | 同一用户多次成功启动并跨 OS 重试 | `uid + app_id` 只计一次首次成功启动 |
| 退款异常 | 注入离线时长缺失、陈旧、签名失败、冲突样本 | 均进入人工审核，不以 0 小时自动通过 |

## 五、待确认项与上线约束

### 5.1 非功能要求

| 项目 | 要求 |
|---|---|
| 查询 | 常用 30 日单游戏聚合查询目标 P95≤3 秒；超时显示失败状态并可重试，不返回不完整结果。 |
| 导出 | 大文件异步生成，状态可查询；下载地址短期有效且绑定当前账号。 |
| 一致性 | 页面与导出以 `query_snapshot_id` 固定数据批次；迟到事件进入下一次重聚合，不静默改变已下载文件。 |
| 审计 | Key 生成／分配、Campaign、资源执行和导出均记录操作者、前后值、时间与结果。 |
| 隐私 | 开发者接口禁止返回用户级明细；聚合阈值、查询频率和组合维度需防差分反查。 |

### 5.2 运营与合规

| 项目 | 要求 |
|---|---|
| 渠道字典 | 平台统一维护渠道 ID、名称、地区、状态和 API 权限；停用渠道保留历史聚合。 |
| Key 管理 | 生成数量和渠道配额需受合同授权及平台额度限制；日志与导出不出现 Key 明文。 |
| 财务口径 | 预估字段、最终结算、汇率版本和数据更新时间必须可见；任何页面不得把预估净收入命名为“可提现”。 |
| 数据保留 | 聚合数据、财务引用和操作审计按合同、税务及隐私要求保留；用户级原始事实不向开发者开放。 |

### 5.3 待确认项

| 问题 | 默认建议 | 影响 | 是否阻塞 |
|---|---|---|---|
| Campaign 最近点击归因窗口 | 同一用户对同一游戏最近一次有效点击 7×24 小时；成功获取时固化来源 | 影响渠道订单、领取及后续转化归属 | 阻塞归因口径冻结 |
| 开发者聚合隐私阈值 | 默认分组用户数低于 10 时隐藏细分值，并限制高频组合查询 | 影响小渠道／小地区展示和导出 | 阻塞权限与接口验收 |
