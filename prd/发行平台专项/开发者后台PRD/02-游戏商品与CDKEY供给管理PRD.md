## 一、文档概述

### 1.1 背景概述

- **需求背景：** 平台既要接收 Steam、Epic、GOG 等外部平台 Key，也要让企业开发者生成盖世 Key，供自行合作的第三方渠道分发。
- **当前方式：** 外部 Key 由平台运营受控导入并用于平台订单；盖世 Key 缺少开发者自助管理渠道、批次、文件交付和 API 取码的完整链路。
- **问题：** 旧方案要求运营先建计划、配渠道和额度，并把渠道销售、结算混入平台；实际合作只需平台供码和兑换校验，商业交易由开发者与渠道处理。
- **证据：** 企业认证通过即开放渠道分销；渠道名由开发者自定义；平台不验证渠道身份，不采集第三方定价、订单、退款、拒付或结算。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | [已确认] 本文只含 B 端：开发者端游戏控制台、渠道管理、批次管理、分销数据、帮助教程，以及平台运营端商品／SKU、外部 Key 入站。不新增 C 端页面。 |
| 业务边界 | [已确认] 外部 Key 入站与盖世 Key 出站使用独立账本。盖世 Key 渠道分销只负责 Key 生成、文件/API 交付、兑换和审计，不处理渠道销售、售后或结算。 |
| 运营边界 | 平台运营维护 Product／SKU 和外部 Key 入站；不审批渠道或盖世 Key 批次，不配授权计划、地区、渠道配额，不执行渠道启停或风险暂停。 |
| 人力边界 | 企业开发者维护渠道和批次；第三方渠道接收文件或调用 API；平台服务端负责生成、发码、兑换和日志；安全、测试、数据分别负责凭据、验收和数据口径。 |

#### 一期不含

1. 盖世生成或补发 Steam、Epic、GOG 等外部平台 Key。
2. 外部 Key 与盖世 Key 间转换、调拨或混扣。
3. 平台审核渠道、校验渠道身份、配额审批或风险处置。
4. 第三方渠道的价格、终端订单、销量、退款、拒付、收入和结算。
5. 文件成功下载后再次查看、复制或下载同批明文 Key。
6. 复杂组织权限、自动结算和线上合同流程。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 外部 Key 入站 | External Key Supply | 外部平台或供应商生成 Key，经平台运营受控导入后，用于平台订单履约。 |
| 盖世 Key 出站 | GameHub Key Distribution | 盖世生成 Key，经开发者下载文件或第三方渠道 API 取码，用户再兑换为盖世权益。 |
| 渠道 | Channel | 企业开发者自定义的管理对象，用于归类批次和分销数据；平台不验证名称对应的真实渠道主体。 |
| 供给批次 | Supply Batch | 绑定一个渠道、一个销售项和一种供给方式的 Key 集合；供给方式创建后不可切换。 |
| 文件批次 | File Batch | 一次生成并下载 1—100,000 个 Key 的批次。成功下载后平台只留记录和指纹，不留明文文件或 Key。 |
| API 批次 | API Batch | 第三方渠道按订单逐个取码的批次。初始数量和每次追加均为 1—100,000，累计不限。 |
| 销售项 | Product／SKU | 渠道可分发的游戏本体或 DLC；由 `product_id + sku_id` 唯一确定。 |
| 发放量 | Issued Keys | API 成功返回的 Key 数，加文件批次成功下载的 Key 数。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 为企业开发者提供自助渠道建档、批次供码、兑换数据和接入教程；平台只承担可验证的 Key 能力。 |
| 目标用户 | 企业认证通过的开发者、第三方渠道、平台发行运营。 |
| 核心目标 | 开发者无需平台审批即可完成渠道供码；文件和 API 两种方式可独立管理、停用、续量和追溯。 |
| 使用场景 | 开发者与第三方自行达成合作后，先建渠道，再按销售项创建文件或 API 批次，最后查看发放与兑换数据。 |
| 功能概述 | 渠道管理、批次管理、文件下载、API 取码与续量、分销数据、帮助教程；商品／SKU 和外部 Key 入站沿用独立运营链。 |

#### 竞品借鉴结论

| 竞品 | 可借鉴 | 本期采用 | 不采用 |
|---|---|---|---|
| Steam Keys | 按产品和用途管理批次；敏感明文一次性交付；历史激活记录不被批次操作覆盖 | 批次化、一次下载、已发 Key 保留历史 | 由盖世生成 Steam Key 或复制其全部 Key 类型 |
| WeGame CDKey | 数量、有效期、备注、批次和渠道数据 | 渠道标签、批次字段、发放／兑换分层 | 固定额度、邮件发明文、未验证的销售结算模型 |
| 本期方案 | 企业开发者自行合作并供码 | 无审批、无计划、无渠道总额度；文件/API 双供给 | 把渠道销售额或结算写成平台数据 |

#### 对象与账本

| 关系 | 外部 Key 入站 | 盖世 Key 出站 |
|---|---|---|
| 主键 | `vendor_id + game_id + app_id + product_id + sku_id + external_key_batch_id` | `vendor_id + game_id + app_id + product_id + sku_id + channel_id + batch_id` |
| Key 生成方 | Steam／Epic／GOG／供应商 | 盖世兑换服务 |
| 供给方式 | 运营受控导入；平台订单交付 | 文件下载或 API 取码；用户兑换 |
| 历史保护 | 已交付／已揭示 Key 不回库 | 已发或已兑换 Key 不因渠道、批次停用或删除而回收 |

### 2.2 产品流程

企业认证通过后，开发者进入单游戏控制台，先建渠道，再建批次。文件批次下载一次；API 批次由渠道按接口取码，数量不足时在原批次追加。两种方式共用分销数据口径。

##### 渠道状态

| 状态 | 进入／退出 | 表现与操作 | 结果与恢复 |
|---|---|---|---|
| 待生效 | 已启用且未到开始时间；到时退出 | 可查看、编辑、停用、删除 | 到开始时间自动转合作中 |
| 合作中 | 已启用且在合作时间内 | 可查看、编辑、停用、删除 | 停用后停止 API 新取码 |

##### 批次状态

| 状态 | 适用范围与进入 | 表现与操作 | 结果与恢复 |
|---|---|---|---|
| 待生效 | API 已启用但未到开始时间 | 可查看、编辑、停用、删除及追加数量 | 到时且渠道有效后转供给中 |
| 供给中 | API 满足全部取码门禁 | 可取码、查看、编辑、停用、删除、追加数量 | 任一门禁失效后转对应状态 |
| 已停用 | 文件或 API 被手动停用 | 文件首次下载不受限；API 停止新取码 | 启用后按当前条件重算 |
| 已结束 | 已到结束时间 | 文件可完成一次下载；API 拒绝新取码 | 延长时间并启用后恢复 |
| 已用完 | API 剩余数量为 0 | 可查看、追加数量、停用、删除 | 追加后按其他门禁恢复 |
| 受渠道限制 | API 所属渠道未启用或不在合作期 | 可追加数量，也可查看、编辑、停用或删除 | 渠道恢复后自动重算 |
| 已下载 | 文件完整下载成功 | 可查看、编辑、停用、删除、看下载记录 | 不可再次下载同批 Key |
| 已删除 | 开发者确认删除 | 默认列表不显示 | 不可恢复；历史发放和兑换保留 |

##### API 方法

| 方法 | 路径 | 用途 | 结果与恢复 |
|---|---|---|---|
| POST | `/openapi/v1/cdkeys/allocate` | 按 `batch_id + channel_order_id` 分配一个 Key | 成功返回同一订单的 Key；重复请求内容一致时返回原结果，内容冲突返回 409 |
| GET | `/openapi/v1/cdkeys/orders/{channel_order_id}?batch_id={batch_id}` | 查询原订单取码结果 | 超时后先查原订单；查询不扣数量、不生成新 Key |

接口使用 `X-Client-Id`、`X-Timestamp`、`X-Nonce`、`X-Signature` 和 `Idempotency-Key`。Secret 不进 URL、请求体、普通日志或埋点。鉴权失败返回 401；幂等冲突返回 409；渠道或批次不可用返回 423；限流返回 429 并带 `Retry-After`。
