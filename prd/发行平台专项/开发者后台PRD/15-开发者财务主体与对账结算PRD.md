## 一、文档概述

### 1.1 背景概述

- **需求背景：** 游戏完成销售或 Key 履约后，开发者需要维护收款资料、核对账单、处理差异和发票，并追踪付款结果。
- **当前方式：** 财务主体、对账、发票和付款信息分散，开发者需要线下确认数据和进度。
- **问题：** 账单构成难追溯，差异缺少统一入口，付款失败或退回时不知道是否需要处理。
- **竞品参考：** TapTap 将“财务主体设置”和“财务对账”作为两个同级入口。本方案沿用场景划分，并补齐海外发行所需的多币种、三本账及付款追踪。
- **会议基准：** 一期保留基础收入看板；合同签约、资质核验和结算规则由商务线下确认。支付、退款和 Key 履约事实由对应业务系统提供。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 本期包含开发者端财务主体、对账结算、对账流水和结算详情；不新增平台财务后台或支付商工作台。 |
| 业务边界 | 覆盖财务资料首次配置与变更、账单确认、差异、条件式发票、付款状态和凭证。不包含合同自助签约、玩家支付、退款审批、自动分账或开发者主动提现。 |
| 数据边界 | 消费平台直销、外部 Key 采购、盖世 Key 渠道三类已确认业务事实；不修改订单、Key 或支付商终态。三类账本独立计算，可在结算单中分项汇总。 |
| 运营边界 | 平台财务审核主体、锁定账单、处理差异和发票、登记付款。本 PRD只定义开发者端回显及接口结果，不定义平台操作页面。 |
| 人力边界 | 商务维护合同与结算规则；财务处理审核、账单和付款；服务端生成账本与快照；前端实现查询和开发者操作；测试核对状态、金额和权限。 |

#### 一期不包含

1. 平台财务审核、支付商核账、账单生成和付款登记页面。
2. 支付商独立前台、自动出款、智能路由和自动税务服务。
3. 自助修改合同、结算币种或结算周期。
4. 玩家身份、订单详情、Key 明文、支付商密钥和内部最小货币单位字段展示。
5. 复杂组织角色配置页；页面消费账号中心返回的财务权限。

### 1.3 术语定义

| 术语／缩写 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 财务主体 | Finance Entity | 与平台结算的法律及收款主体。企业认证字段只读同步，银行和税务资料由开发者补充。 |
| 生效版本 | Effective Version | 已审核通过且当前用于结算的财务主体快照。新版本审核期间不覆盖旧版本。 |
| 结算单 | Statement | 按主体、账期、币种和规则版本聚合流水形成的对账对象。 |
| 三本账 | Three Ledgers | 平台直销、外部 Key 采购、盖世 Key 渠道三套独立账本。 |
| 对账流水 | Settlement Ledger Entry | 可逐笔还原账单金额的交易、退款、拒付、Key、费用、税费、调整等记录。 |
| 差异 | Dispute | 开发者对流水、遗漏交易、Key 数量、费用、税费或汇率提出的核查请求。 |
| 付款单 | Payout Order | 平台针对一张或多张已锁定结算单建立的付款对象。 |
| 付款尝试 | Payout Attempt | 同一付款单的每次打款执行记录，用于区分处理中、失败、退回和重试。 |
| 原币 | Transaction Currency | 交易发生时使用的币种。 |
| 结算币种 | Settlement Currency | 合同约定的付款币种，开发者端只读。 |
| 金额最小单位 | Minor Unit | 服务端存储金额的整数单位，如 USD 分、JPY 元；页面按币种精度展示。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | 以财务主体和账期结算两个场景，完成开发者从收款资料到付款结果的财务闭环。 |
| 目标用户 | 已入驻的游戏开发者、发行商及其财务人员。 |
| 核心目标 | 账单金额可由流水还原；开发者可确认或提出差异；发票和付款状态可追踪。 |
| 使用场景 | 首次配置、资料变更、月度核账、差异处理、发票提交、付款失败或退回处理、历史回溯。 |
| 功能概述 | 左侧只保留“财务主体”“对账结算”；对账、发票和付款按结算单聚合，流水使用次级页面，详情使用单层右侧抽屉。 |

#### 竞品借鉴与取舍

| 项目 | TapTap 表现 | 本方案 |
|---|---|---|
| 一级入口 | 财务主体设置、财务对账 | 沿用两个场景，命名为“财务主体”“对账结算”。 |
| 主体变更 | 配置、审核和变更历史集中管理 | 沿用，并保留旧生效版本。敏感变更只暂停付款。 |
| 对账 | 围绕账期处理结算单和发票 | 沿用，并在同一行补充付款状态与当前待办。 |
| 海外发行 | 本地资料以国内广告收益提现为主 | 增加多币种、SWIFT／BIC、税务居民地和跨境付款状态。 |
| 多业务来源 | 截图未体现三本账 | 平台直销、外部 Key 采购、盖世 Key 渠道独立核算。 |

### 2.2 产品流程

![结算流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@b6020381b3986348933c0b2049288521acb218e4/public/prd/developer-finance-settlement/15-settlement-flow.png)

*图 2.2-1：从财务主体配置到付款结果。*

流程说明：

1. 开发者配置财务主体，平台审核后生成生效版本。
2. 平台按合同周期生成结算单，开发者核对账单与流水。
3. 无误时确认账单；有误时提交差异，处理完成后重新确认。
4. 平台锁单；合同要求发票时，开发者提交并等待审核。
5. 平台付款后回写结果。失败或退回时，开发者按提示处理，平台在原付款单下重试。

##### 流水计算规则

| 规则 | 说明 |
|---|---|
| 金额类型 | 服务端使用整数最小单位或 Decimal 计算，不使用二进制浮点数。 |
| 折算 | 交易原币金额按账单保存的汇率和汇率版本折算为结算币种。 |
| 应结算 | 折算收入－退款／拒付－税费－支付费－平台分成＋采购或渠道项＋调整项。具体正负方向由流水类型定义。 |
| 可还原 | 同一结算单的关联流水汇总必须与账单构成一致；人工调整须保存金额、币种、原因、证据和操作人。 |
| 迟到数据 | 锁单后到达的退款或拒付进入下期调整，并关联原流水和原账单，不覆盖历史。 |
| 汇率缺失 | 流水不进入正式账单，状态进入平台异常处理；开发者端不得显示错误的 0 金额。 |

##### 差异类型与输入

| 差异类型 | 必填内容 | 处理规则 |
|---|---|---|
| 已有流水差异 | 一条或多条流水、期望值、说明，可上传附件 | 平台值只读，提交时保存所选流水快照。 |
| 交易遗漏 | 开发者侧订单号或业务参考号、金额、币种、说明 | 不强制选择平台流水；业务参考号至少填写一项。 |
| Key 数量差异 | Key 批次或渠道、平台数量、期望数量、说明 | 按外部 Key 或盖世 Key 账本核查。 |
| 费用／税费／汇率差异 | 关联流水或账单项、平台值、期望金额、说明 | 切换账单项后同步更新平台值，提交值不能为空。 |

##### 详情动作规则

| 动作 | 可用条件 | 成功结果 | 失败处理 |
|---|---|---|---|
| 确认账单 | 对账状态为待确认；财务主体已生效；有操作权限 | 进入已确认，记录时间和账号 | 保留原状态和抽屉内容 |
| 提交差异 | 状态允许；财务主体已生效 | 新建差异并进入有异议 | 定位首个错误，保留输入 |
| 补充材料 | 差异为需补资料 | 追加材料和时间线 | 原记录不覆盖 |
| 提交发票 | 已锁单且合同要求；发票待提交或已退回 | 进入审核中，保存提交快照 | 保留表单和附件状态 |
| 导出账单 | 有查看权限 | 下载当前账单版本 | 显示失败原因，可重试 |
| 下载付款凭证 | 付款已真实汇出且有回执 | 下载受控凭证 | 不生成空文件 |
| 前往财务主体 | 付款阻塞需修改收款资料 | 关闭抽屉并进入财务主体 | 保留返回上下文 |

### 4.2 技术需求

| 需求项 | 具体要求 |
|---|---|
| 金额精度 | 服务端使用整数最小单位或 Decimal；币种精度由币种表定义。页面、账单和导出读取同一结果。 |
| 快照 | 财务主体申请、账单、结算规则、汇率、差异、发票和付款尝试均保留不可变版本及关联关系。 |
| 幂等 | 主体提审、账单确认、差异、发票和导出须使用幂等键；重复点击不得生成重复对象。 |
| 并发 | 写操作校验版本号和最新状态。冲突时不覆盖，返回最新状态并提示刷新。 |
| 权限 | 按主体隔离数据；财务编辑、查看、导出和凭证下载分别校验。银行、税务和附件使用字段级权限。 |
| 脱敏 | 银行账号默认只显示末 4 位；日志和埋点不得记录完整账号、税号、玩家或 Key 明文。 |
| 附件 | 使用受控上传、预览和下载地址；校验格式、大小、数量、病毒扫描结果和权限。 |
| 导出 | 导出当前已应用筛选的全部结果；异步任务防重复；CSV 标准转义并防公式注入。 |
| 可访问性 | 抽屉和确认框支持焦点锁定、Esc 关闭和焦点恢复；键盘可完成主要操作。 |
| 响应式 | 1440px 桌面端无遮挡；390px 视口无根节点横向溢出，表格可在内容区横向滚动。 |
| 分页 | 结算单和流水每页 20 条；前后端分页、筛选、导出使用同一数据范围定义。 |
| 性能 | 列表首屏 P95 小于 2 秒；详情 P95 小于 1.5 秒；超时后可重试且不丢筛选。 |

## 六、测试要求

1. 左侧财务模块只有“财务主体”和“对账结算”两个入口；不存在“付款记录”一级入口或页内业务 Tab。
2. 财务主体首次配置、变更、补充、撤销和历史版本均可回溯；撤销须二次确认。
3. 银行国家或地区、账号或 SWIFT／BIC 变化后，未重传账户证明不能提交。
4. 每条结算记录同时展示对账、发票、付款和当前待办；三套状态互不覆盖。
5. 结算单和流水列表每页 20 条；筛选、列表、详情和导出使用同一数据范围。
6. 任一账单均可由关联流水汇总还原；三本账不跨来源混算。
7. 结算详情只有一层抽屉；当前待办区块默认展开，底部操作固定且符合状态和权限。
8. 财务主体从未生效时禁止确认和差异；主体变更导致付款暂停时仍可处理历史核账。
9. 差异四种输入模型、发票退回重提、付款失败、退回、部分付款和多次尝试均可追溯。
10. 开发者不能发起打款或标记到账；无真实汇出回执时不能下载凭证。

### 7.3 核心数据对象

| 对象 | 必要字段 |
|---|---|
| FinanceEntityVersion | 主体、银行、税务、合同引用、状态、生效时间、申请快照。 |
| SettlementRuleSnapshot | 结算模式、分成或采购规则、币种、税费、费用、汇率规则和生效时间。 |
| SettlementLedgerEntry | 业务来源、唯一流水号、订单／SKU／Key 链路、类型、原币金额、费用、汇率、折算金额和规则快照。 |
| Statement | 开发者、账期、版本、关联流水、构成、调整、应结算额、确认和锁定信息。 |
| Dispute | 类型、关联对象、平台值、期望值、附件和处理时间线。 |
| Invoice | 账单版本、发票号、日期、金额、币种、附件和审核记录。 |
| PayoutOrder | 关联结算单、待付余额、收款版本、付款条件和总体状态。 |
| PayoutAttempt | 每次金额、渠道、银行参考号、状态、回执和失败原因。 |
| AuditLog | 对象、前后值、原因、时间、操作者和复核人。 |
