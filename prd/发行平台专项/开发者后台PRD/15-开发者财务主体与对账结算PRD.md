## 一、文档概述

### 1.1 背景概述

- **需求背景：** 游戏和 CDKEY 产生销售后，开发者需维护收款资料并按月对账；运营需导出清单交财务线下处理。
- **当前方式：** 双方依赖线下表格，字段、分成口径和版本难统一。
- **问题：** 开发者难以追溯本体、DLC 和 CDKEY 结算构成；运营缺少按主体汇总、按游戏核账和维护分成规则的统一页面。
- **竞品参考：** TapTap 将“财务主体设置”和“财务对账”设为同级入口。本方案沿用该划分，补充 PC 游戏、DLC、CDKEY 和运营导出能力。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 开发者端包含“财务主体”“对账结算”；运营端包含“主体汇总”“游戏明细”和阶梯平台分成配置。 |
| 业务边界 | 覆盖财务主体资料变更、N+1 月账、结算明细、开发者确认、双方导出及平台分成配置；不含合同签约、发票、差异工单、主动提现、线上付款审批或自动打款。 |
| 运营边界 | 运营核账后导出清单，线下交财务对账和打款；本期不建设财务主体审核台、支付商工作台或付款结果页面。 |
| 人力边界 | 商务线下确认合同与初始结算信息；运营维护平台分成并导出；财务线下打款；服务端生成结算快照；前端提供查询、确认和导出。 |

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| 财务主体 | 与平台结算的企业及其收款账户。一个开发者仅有一个当前生效财务主体。 |
| 主体版本 | 财务主体资料提交审核时生成的不可变版本。新版本生效前不覆盖旧版本。 |
| 账户版本 | 与主体版本关联的银行账户快照，用于还原历史账单的收款信息。 |
| 账单月份 | 销售、退款与拒付归属的自然月，格式为 `YYYY-MM`。 |
| 结算月份 | 结算记录生成月份；一期固定为账单月份下一月，即 N+1。 |
| 结算项 | 按销售来源或冲减原因拆分的月度结算记录；游戏销售包含本体和 DLC。 |
| 实际到账金额 | 开发者端字段，对应平台扣除支付费、税费及退款／拒付后的实际入账结果，可为负数。 |
| 结算比例 | 开发者端字段，等于 `100%－平台分成比例`。CDKEY 和退款与拒付为 100%。 |
| 平台实收 | 运营端字段，等于 `用户实付－支付费－税费－退款与拒付`。 |
| 平台分成 | 游戏销售按平台分成规则计算；CDKEY 为 0；退款与拒付不计分成。 |
| 结算金额／应结算金额 | 开发者端称“结算金额”，运营端称“应结算金额”，均等于 `平台实收－平台分成`。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品定位 | 面向 PC 游戏厂商的财务资料与月度结算工作区。 |
| 目标用户 | 企业开发者财务人员、平台发行运营、线下财务人员。 |
| 核心目标 | 统一财务主体、结算字段、分成规则和导出数据，使开发者确认与平台核账可追溯。 |
| 使用场景 | 资料变更、月账核对、明细追溯、结算确认、运营汇总、规则配置、线下结算导出。 |
| 功能概述 | 开发者查看和变更唯一财务主体，按游戏核对结算；运营按主体或游戏核账，配置平台分成并导出。 |

| 平台操作 | 截图未覆盖运营结算 | 增加主体汇总、游戏明细、分成配置和线下导出。 |

### 3.2 B 端功能需求（发行平台运营后台）

#### 3.2.1 P16-01 财务结算

| 要素 | 内容说明 |

| 项目 | 规则 |
|---|---|
| 适用对象 | 按开发者、游戏和生效账单月配置；仅作用于游戏销售分成。 |

## 四、数据与支撑需求

### 4.1 数据结论

**数据结论：** 新增财务主体、结算确认、运营导出和阶梯平台分成埋点；复用统一账号、页面、结果和失败码参数。

| 项目 | 结论 |
|---|---|
| 数据建设 | 新增财务主体版本、结算快照、明细拆分、确认记录、导出记录和阶梯平台分成版本。 |
| 数据来源 | 游戏与 DLC 订单、CDKEY 渠道、支付商入账、支付费、税费、退款与拒付结果。 |

### 4.4 技术与非功能要求

| 需求项 | 具体要求 |
|---|---|
| 金额精度 | 服务端使用整数分或 Decimal；页面和导出读取同一结果，不使用二进制浮点数计算。 |
| 双端金额 | 服务端统一返回 `platform_received_minor`、`platform_share_minor`、`payable_minor`。开发者端分别显示为实际到账金额、不展示、结算金额；运营端显示为平台实收、平台分成、应结算金额。结算比例仅作解释，前端不参与计算。 |
| 结算快照 | 保存主体版本、账户版本、规则版本、汇率、金额、状态和确认信息；历史不可覆盖。 |
| N+1 | 服务端校验结算月份为账单月份下一月；异常记录不进入开发者正式列表。 |
| 幂等与并发 | 主体提审、账单确认、导出和规则保存使用幂等键，写入前校验版本与状态。批量确认全部成功才提交事务。 |
| 权限 | 按开发者隔离数据；运营查看、导出、规则维护分权；接口再次校验角色和对象范围。 |
| 敏感数据 | 银行账号、手机号、邮箱和附件不得写入埋点或普通日志；运营查看完整银行账号须有权限并留痕。 |
| 附件 | 使用受控上传和短时预览地址；校验类型、大小和访问权限。 |
| 导出 | 使用已应用筛选；不受分页限制；CSV 标准转义并防公式注入；导出记录保留操作人、时间、范围和结果。 |
| 分页 | 开发者列表、运营主体汇总和游戏明细均为每页 20 条。 |

### 4.5 外部数据与线下协作

| 依赖 | 具体要求 |

### 6.3 核心数据对象

| 对象 | 必要字段 |
|---|---|
| FinancialEntityVersion | 开发者、主体版本、账户版本、企业、联系人、银行账户、附件、状态、提交与审核信息。 |
| SettlementStatement | 开发者、游戏、账单月、结算月、结算项、金额、比例、主体／账户／规则版本、状态、确认信息。 |
| SettlementBreakdown | 结算记录、商品类型、商品或 DLC、CDKEY 渠道、开发者金额、平台金额。 |
| PlatformShareTierRule | 开发者、游戏、生效账单月、阶梯区间、平台分成比例、版本、原因和操作信息。 |
| ExportRecord | 端别、Tab、筛选、选中对象、导出数量、文件、操作人、时间和结果。 |
| AuditLog | 对象、操作、前后版本、原因、账号、时间和结果。 |
