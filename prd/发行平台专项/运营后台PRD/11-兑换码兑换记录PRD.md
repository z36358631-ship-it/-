## 一、文档概述

### 1.1 背景概述

**当前方式：** 客户端已有产品代码兑换入口，开发者分销数据只提供企业维度汇总，平台运营目前无法据此核对某位玩家的逐笔兑换结果。

本轮在《完整开发者与运营管理平台-合并版》的运营管理后台补充CDK兑换记录，关联兑换请求、核销及权益发放事实。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 合并版“运营管理后台→游戏发行管理”提供“CDK兑换记录”只读列表，直接展示完成时间与异常原因，不提供详情入口或详情抽屉；客户端兑换交互保持原样。开发者后台不开放玩家UID明细。 |
| 业务边界 | 仅查看盖世平台兑换码兑换游戏本体／DLC等约定权益的结果，不把订单售卖CDKEY的配码、交付或外部激活混为平台兑换。不新增补发、人工核销、改结果、导出、删除或查看明文。 |
| 运营边界 | 平台人员按授权范围查询与核对；正式码格式、已拥有是否核销、有效期和地区规则沿现行兑换业务确认，不由查询页制定。 |
| 人力边界 | 产品、设计定义页面；Web研发接入原后台，服务端提供兑换、核销、权益事实及权限；运营核对记录，测试检查筛选、状态、脱敏与越权。 |

### 1.3 术语定义

| 术语 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 内部码标识 | 无 | 不能用于兑换的稳定内部标识，供精确查询与关联；与只显示部分字符的脱敏码分别展示，均不暴露完整兑换码。 |
| 兑换记录 | 无 | 已提交至服务端的兑换请求及其结果；同一请求重试核对原记录，不重复计成功或发放权益。 |
| 兑换成功 | 无 | 真实核销及约定权益发放均已确认；不能仅按点击、客户端提示或订单创建判定。 |
| 待核对 | 无 | 服务端结果尚未确认或核销、发权事实未完整核对；未知不等于失败。 |

## 二、产品说明

### 2.1 产品／方案简介

为平台运营提供兑换记录查询，在合并版运营管理后台的游戏发行管理下沿用现有筛选和列表样式，直接在列表核对完成时间与异常原因，不在开发者分销报表添加玩家明细。

### 2.2 产品流程

![兑换记录流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@42b0ffb051d0e4ac744e66893e19faeeb73ec036/public/prd/developer-platform/00-flow.png)

进入固定Demo → 运营管理后台 → 游戏发行管理 → CDK兑换记录 → 设置条件并查询 → 在列表核对结果、完成时间及异常原因。

## 三、功能需求

### 3.2 B 端功能需求

#### 3.2.1 CDK兑换记录

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 查询逐笔兑换记录，核对核销和权益发放关联。 |
| 场景描述 | 平台运营按玩家UID、内部码标识、游戏、时间或结果，核对一次兑换是否成功及异常原因。 |
| 输入／前置条件 | 已登录运营后台，具有兑换记录查看权限及对应数据范围；查询由服务端校验授权。正式数据取兑换服务、核销及权益发放记录；Demo只展示本地只读样例，不连接真实CDK或权益服务。 |
| 需求描述 | **图示：**<br>![兑换记录](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@42b0ffb051d0e4ac744e66893e19faeeb73ec036/public/prd/developer-platform/01-records.png)<br>![兑换异常列表](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@42b0ffb051d0e4ac744e66893e19faeeb73ec036/public/prd/developer-platform/02-records-exceptions.png)<br>**详细说明：** 从合并版切换至“运营管理后台”，在“游戏发行管理”下点击“CDK兑换记录”，进入后该项选中，页面标题显示“CDK兑换记录”；原后台其他入口与页面沿用。<br>**展示说明：**<br>1. 筛选显示“玩家UID”“记录ID或内部码标识”“游戏”“请求时间”起止及“结果”，配“查询／重置”。文字和时间默认空，游戏默认“全部游戏”，结果默认“全部结果”。结果选项为全部结果、成功、失败、待核对；游戏仅含授权范围内对象。<br>2. 列表显示兑换记录ID、玩家UID、脱敏码及内部码标识、游戏名称及Game ID、商品／SKU与权益、批次／渠道、请求时间、兑换完成时间、结果和异常原因，不显示操作列或“详情”按钮。时间合并为一列并分别标注“请求”和“完成”；成功确认完成后显示兑换完成时间，不显示空的异常原因；失败及待核对的兑换完成时间显示“—”，异常原因显示对应真实原因。无法识别或尚未确认的字段显示“—”，不造游戏、批次、渠道或权益ID。失败与待核对用不同结果标签，异常原因在结果下方完整换行展示，不省略或另开详情。页面底部“Demo 演示说明”可展开或收起，只说明样例与正式接入边界，不改变业务状态。<br>3. 请求时间取本次服务端接收提交的时刻；请求时间及兑换完成时间均显示北京时间YYYY-MM-DD HH:mm:ss；按请求时间倒序，同秒按记录ID稳定降序。每页20条，显示总数、当前页及上一页／下一页；首尾页禁用对应翻页操作，无结果显示“暂无CDK兑换记录”，下方提示“请调整筛选条件后重新查询。”。<br>**交互说明：**<br>1. 玩家UID去首尾空白后精确匹配；记录ID或内部码标识去首尾空白后精确匹配其中任一字段，不检索原兑换码。两项文字均不限制输入长度；空或仅空白表示不限，不由搜索框定义真实CDK格式或长度。<br>2. 游戏为单选；请求时间按北京时间闭区间匹配，可只填开始或结束，均空表示全部时间。无效日期原位提示“请输入有效的北京时间。”；开始晚于结束原位提示“开始时间不能晚于结束时间。”，阻止查询并保留原列表。<br>3. 所有已填条件取交集。点击“查询”应用条件并回第1页；修改条件但未查询时不替换原结果。点击“重置”清空文字和时间、恢复全部游戏及全部结果并查询第1页；翻页使用上次已应用条件。<br>4. 查询中显示加载状态并阻止重复提交；成功后结果与本次条件对应，迟到响应不覆盖较新查询。查询失败保留筛选、原列表与页码，原位显示失败原因，可再次查询。<br>5. 直接在列表核对完成时间及异常原因，不打开详情抽屉。查询不核销、不发权、不修改兑换结果。 |
| 输出／后置条件 | 列表展示授权范围内的兑换事实及关联信息；玩家权益、原码状态、订单与开发者汇总不因查看改变。 |
| 补充说明 | 1. 无数据与加载失败分别呈现，不把读取失败显示为空记录。无权限显示“暂无查看权限”；会话失效或权限收回后停止读取并清除已展示的受限明细，不能继续查看原缓存。<br>2. 空输入、取消及未提交的客户端操作不生成业务兑换记录；已提交的失败和未知请求按真实结果留痕；不同新请求即使使用同一码，失败尝试也可分别留痕。重复同一请求核对同条记录，不重复核销、发权或计成功，已确认成功不被迟到失败覆盖。<br>3. 正式CDK规则、已拥有是否核销及重复、期限、地区结果由原服务确认；客户端Demo仍沿既有任意非空码激活规则，不将固定TEVI或模拟成功补造成真实兑换流水。 |

**结果与恢复**

| 结果 | 判定依据 | 页面表现 | 更新与限制 |
|---|---|---|---|
| 成功 | 真实核销与约定权益均已确认 | 列表显示兑换完成时间，不显示空的异常原因 | 同请求返回原结果；迟到失败不覆盖成功，不重复发权或计成功。 |
| 失败 | 服务端明确本次兑换失败 | 列表显示真实失败原因；兑换完成时间及未知字段为“—” | 不伪装为成功或发权；本页无重试兑换操作。 |
| 待核对 | 结果未知或核销、发权事实未完整确认 | 列表显示待核对原因；兑换完成时间及未知字段为“—” | 经原业务核实后更新原记录；本页不提供人工判成功或补发。 |

**权限与数据范围**

| 角色／条件 | 可见范围 | 禁止事项 |
|---|---|---|
| 有查看权限的平台运营 | 授权范围内的只读列表，查询时校验 | 不查看完整兑换码，不修改记录、核销或发权。 |
| 无权限／越权访问 | 不返回明细，提示无查看权限 | 直达路由或猜测记录ID不能绕过；共用UID不自动授予运营权限。 |
| 开发者 | 沿现有企业、游戏、渠道及SKU汇总 | 不开放本页及玩家UID明细，不改变原Key发放时间口径。 |

## 四、支撑及非功能需求

**数据结论：** 不涉及新增行为埋点或报表；本轮展示业务兑换记录。正式记录保留当前玩家UID、请求、内部码标识、核销及权益关联，结果由真实服务产生。请求ID、核销记录ID及权益发放ID保留在后台数据中供追溯，不单独开放详情展示。查询访问按后台既有审计规范记录访问人员、对象、时间和结果，不将完整兑换码写入日志、埋点或公开截图。

本页按请求时间查询；开发者分销数据仍按Key发放时间选定批次、统计截至查询时的累计兑换结果，发行量不等于销量。订单购买CDKEY的分配、交付、外部激活与本页平台兑换分别处理，不能混算。本地样例不构成正式核销、权限或事务验收证据。

## 五、待确认项

| 待确认问题 | 处理方向 | 未确认的影响 | 是否阻塞 |
|---|---|---|---|
| 正式兑换／核销／权益服务及关联标识 | 沿原服务确认请求ID、记录ID、内部码标识与核销、权益发放对应关系，不据Demo编造正式流水。 | 影响数据来源、成功判定及重复请求核对。 | 阻塞正式接入，不阻塞只读原型评审。 |
| 正式CDK格式、期限、地区、已拥有与同码跨UID规则 | 由硬件／权益侧给出原业务规则；不自定码长、奖励、核销或补偿策略。 | 影响真实校验、核销与失败分类；不影响本页既定查询方式。 | 阻塞正式兑换，不阻塞记录页面评审。 |
| 运营角色与数据范围 | 由现行后台权限负责人确认正式授权项及对象范围，服务端再次校验；开发者权限不扩大。 | 影响真实玩家明细的可见性及访问审计。 | 阻塞正式明细开放，不阻塞本地样例。 |
| 历史兑换记录可追溯性 | 核对原记录与关联字段；缺失显示“—”，不按客户端本地订单或原型行为补造历史成功。 | 影响历史查询完整性及异常归因。 | 阻塞缺失历史的完整追溯，不阻塞已确认记录展示。 |
