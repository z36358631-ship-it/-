## 一、文档概述

### 1.1 背景概述

**当前方式：** 客户端已有产品代码兑换入口，开发者分销数据只提供企业维度汇总，平台运营目前无法据此核对某位玩家的逐笔兑换结果。

本轮在既有发行平台运营后台补充兑换记录，关联兑换请求、核销及权益发放事实。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | 发行平台运营后台新增“兑换记录”一页及只读详情；客户端兑换交互保持原样。开发者后台不开放玩家UID明细。 |
| 业务边界 | 仅查看盖世平台兑换码兑换游戏本体／DLC等约定权益的结果，不把订单售卖CDKEY的配码、交付或外部激活混为平台兑换。不新增补发、人工核销、改结果、导出、删除或查看明文。 |
| 运营边界 | 平台人员按授权范围查询与核对；正式码格式、已拥有是否核销、有效期和地区规则沿现行兑换业务确认，不由查询页制定。 |
| 人力边界 | 产品、设计定义页面；Web研发接入原后台，服务端提供兑换、核销、权益事实及权限；运营核对记录，测试检查筛选、状态、脱敏与越权。 |

### 1.3 术语定义

| 术语 | 英文全称 | 定义与判断口径 |
|---|---|---|
| 内部码标识 | 无 | 不能用于兑换的稳定内部标识，供精确查询与关联；与只显示部分字符的脱敏码分别展示，均不暴露完整兑换码。 |
| 兑换记录 | 无 | 已提交至服务端的兑换请求及其结果；同一请求重试核对原记录，不重复计成功或发放权益。 |
| 兑换成功 | 无 | 真实核销及约定权益发放均已确认；不能仅按点击、客户端提示或订单创建判定。 |
| 待核对 | 无 | 服务端结果尚未确认或核销、发权事实未完整核对；未知不等于失败。 |

## 二、产品说明

### 2.1 产品／方案简介

为平台运营提供兑换记录查询与只读详情，沿现有后台导航、筛选、列表和详情样式呈现，不在开发者分销报表添加玩家明细。

### 2.2 产品流程

![兑换记录流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@70d23e30fdd88e3f822b7e271d45dd744fa2a508/public/prd/guanwanggaid-58-redemption-records-20261015/00-flow.png)

## 三、功能需求

### 3.2 B 端功能需求

#### 3.2.1 兑换记录

| 要素 | 内容说明 |
|---|---|
| 功能简介 | 查询逐笔兑换记录，核对核销和权益发放关联。 |
| 场景描述 | 平台运营按玩家UID、内部码标识、游戏、时间或结果，核对一次兑换是否成功及异常原因。 |
| 输入／前置条件 | 已登录运营后台，具有兑换记录查看权限及对应数据范围；列表和详情均由服务端校验授权。正式数据取兑换服务、核销及权益发放记录；Demo只展示本地只读样例，不连接真实CDK或权益服务。 |
| 需求描述 | **图示：**<br>![兑换记录](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@70d23e30fdd88e3f822b7e271d45dd744fa2a508/public/prd/guanwanggaid-58-redemption-records-20261015/01-records.png)<br>**详细说明：** 在既有发行平台运营后台导航增加“兑换记录”，进入后该项选中；认证内容、帮助中心、发行审核及财务结算沿用。<br>**展示说明：**<br>1. 筛选显示“玩家UID”“记录ID或内部码标识”“游戏”“请求时间”起止及“结果”，配“查询／重置”。文字和时间默认空，游戏默认“全部游戏”，结果默认“全部结果”。结果选项为全部结果、成功、失败、待核对；游戏仅含授权范围内对象。<br>2. 列表显示兑换记录ID、玩家UID、脱敏码及内部码标识、游戏名称及Game ID、商品／SKU与权益、批次／渠道、请求时间、结果及“详情”。无法识别或尚未确认的字段显示“—”，不造游戏、批次、渠道或权益ID。失败与待核对用不同结果标签。页面底部“Demo 演示说明”可展开或收起，只说明样例与正式接入边界，不改变业务状态。<br>3. 请求时间取本次服务端接收提交的时刻，显示北京时间YYYY-MM-DD HH:mm:ss；按请求时间倒序，同秒按记录ID稳定降序。每页20条，显示总数、当前页及上一页／下一页；首尾页禁用对应翻页操作，无结果显示“暂无兑换记录”，下方提示“请调整筛选条件后重新查询。”。<br>**交互说明：**<br>1. 玩家UID去首尾空白后精确匹配；记录ID或内部码标识去首尾空白后精确匹配其中任一字段，不检索原兑换码。两项文字均不限制输入长度；空或仅空白表示不限，不由搜索框定义真实CDK格式或长度。<br>2. 游戏为单选；请求时间按北京时间闭区间匹配，可只填开始或结束，均空表示全部时间。无效日期原位提示“请输入有效的北京时间。”；开始晚于结束原位提示“开始时间不能晚于结束时间。”，阻止查询并保留原列表。<br>3. 所有已填条件取交集。点击“查询”应用条件并回第1页；修改条件但未查询时不替换原结果。点击“重置”清空文字和时间、恢复全部游戏及全部结果并查询第1页；翻页使用上次已应用条件。<br>4. 查询中显示加载状态并阻止重复提交；成功后结果与本次条件对应，迟到响应不覆盖较新查询。查询失败保留筛选、原列表与页码，原位显示失败原因，可再次查询。<br>5. 点击某条“详情”查看该记录的只读信息；关闭后保留查询条件、已应用条件、页码和列表位置。查询和查看均不核销、不发权、不修改兑换结果。 |
| 输出／后置条件 | 列表与详情展示同一授权范围内的兑换事实及关联信息；玩家权益、原码状态、订单与开发者汇总不因查看改变。 |
| 补充说明 | 1. 无数据与加载失败分别呈现；详情读取失败显示原因，不复用上次记录冒充当前记录。无权限显示“暂无查看权限”；会话失效或权限收回后停止读取并清除已展示的受限明细，不能继续查看原缓存。<br>2. 空输入、取消及未提交的客户端操作不生成业务兑换记录；已提交的失败和未知请求按真实结果留痕；不同新请求即使使用同一码，失败尝试也可分别留痕。重复同一请求核对同条记录，不重复核销、发权或计成功，已确认成功不被迟到失败覆盖。<br>3. 正式CDK规则、已拥有是否核销及重复、期限、地区结果由原服务确认；客户端Demo仍沿既有任意非空码激活规则，不将固定TEVI或模拟成功补造成真实兑换流水。 |

**结果与恢复**

| 结果 | 判定依据 | 页面表现 | 更新与限制 |
|---|---|---|---|
| 成功 | 真实核销与约定权益均已确认 | 展示已确认关联ID及兑换完成时间 | 同请求返回原结果；迟到失败不覆盖成功，不重复发权或计成功。 |
| 失败 | 服务端明确本次兑换失败 | 展示真实失败原因；未知关联字段为“—” | 不伪装为成功或发权；本页无重试兑换操作。 |
| 待核对 | 结果未知或核销、发权事实未完整确认 | 展示已知信息和待核对原因；未知字段为“—” | 经原业务核实后更新原记录；本页不提供人工判成功或补发。 |

## 四、支撑及非功能需求

**数据结论：** 不涉及新增行为埋点或报表；本轮展示业务兑换记录。正式记录保留当前玩家UID、请求、内部码标识、核销及权益关联，结果由真实服务产生；查询与详情访问按后台既有审计规范记录访问人员、对象、时间和结果，不将完整兑换码写入日志、埋点或公开截图。

本页按请求时间查询；开发者分销数据仍按Key发放时间选定批次、统计截至查询时的累计兑换结果，发行量不等于销量。订单购买CDKEY的分配、交付、外部激活与本页平台兑换分别处理，不能混算。本地样例不构成正式核销、权限或事务验收证据。
