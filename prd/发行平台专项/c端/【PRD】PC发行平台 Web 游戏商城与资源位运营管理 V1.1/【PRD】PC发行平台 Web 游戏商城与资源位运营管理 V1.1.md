## 一、文档概述

### 1.1 背景概述

- **当前方式：** 玩家在 Web 浏览和购买，再到 GameFusion 客户端下载、运行；运营统一管理三端商城资源。
- **问题：** Web 的地区、账号与支付说明和客户端不一致，旧文档多处重复且保留密码登录等过期规则。
- **本期调整：** 对齐适用规则，保留网页浏览和客户端引导；不在网页加入兑换或本机任务。

### 1.2 需求边界

| 边界类型 | 范围说明 |
|---|---|
| 产品边界 | GameFusion Web 商城及 Web／macOS／Windows 资源位运营后台。网页提供浏览、账号、购买、订单和售后；本机下载、安装、更新、修复与启动由客户端执行。增加盖世游戏 App 扫码身份认证并复用原盖世 UID；GameHub 游戏库、分发、Steam／Epic 授权和会员权益不因此互通。 |
| 业务边界 | 1. 三端共用 GameFusion 账号、商品、订单、支付和权益；C 端与开发者端共用 UID，后台权限另校验。<br>2. 允许大陆 IP 访问；新账号验证后同卡确认地区，IP 仅推荐，完整注册成功后保存；已有账号直接登录原 UID 和地区。<br>3. 国内为手机号短信验证码、微信、QQ、盖世游戏 App；海外为邮箱验证码、Google、Apple、盖世游戏 App。三方不自动覆盖既有绑定，不新增独立绑定管理。商品与支付资格在购买时单独校验。<br>4. Web 暂不做 CDKey 兑换、购物车、愿望单、社区或本机游戏库。 |
| 运营边界 | 按展示端、地区、语言维护 Banner、促销专题、编辑推荐、新游和畅销。公共页及页脚文案由法务／商务提供，不在本期后台配置。手柄仅保留开发中入口，不做调参、配对、固件或账号迁移。 |
| 人力边界 | 服务端负责 Web、账号、商品、订单、权益、支付和资源配置；客户端负责协议唤起与本机能力；运营负责素材和推荐规则；UI、测试、数据分别核对页面、行为和事件；硬件侧提供 Connect 方案。 |

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| UID | 账号唯一标识，换绑及 App 扫码登录不变。 |
| 居住国家／地区与商城地区 | 新账号确认并保存具体国家／地区，IP 仅推荐；另按既有映射保存商城分组。资料页优先显示具体国家／地区的本地化名称且只读；旧账号无具体国家时沿用原商城地区，不补写、不重算。国家／地区选项不等于商品可售许可。 |
| 国内／海外登录版本 | 决定认证渠道，不等同于页面语言、当前 IP 或账号国家／地区；国内手机号短信验证码、微信、QQ、App，海外邮箱验证码、Google、Apple、App。 |
| 盖世游戏 App 登录 | 点击三方区入口打开二维码，经盖世游戏 App 扫描并手机确认后复用原盖世 UID；不直接拉起 App，不迁移平台授权、会员或硬件权益。 |
| 主题／卡片 | 主题按展示端、地区、语言、位置组织资源；卡片是主题下的展示项，游戏卡关联 AppID。 |
| 促销专题 | 独立运营文章，含封面、正文及有序关联游戏。 |
| BASE／Edition | BASE 为本体；Edition 为同游戏的销售版本，如 Standard／Deluxe。 |
| Bundle／DLC | Bundle 组合本体与附加内容，保留组成快照；DLC 依赖指定本体，购买前校验本体资格。 |
| 托管支付／入库 | 本轮仅展示 Stripe 支付占位；正式付款与权益确认后入库，GameFusion 不采集卡号或 CVV。 |
| 客户端交接 | Web 引导安装或尝试唤起 GameFusion 客户端，不执行本机游戏下载或启动。 |

## 二、产品说明

### 2.1 产品／方案简介

| 项目 | 说明 |
|---|---|
| 产品／方案定位 | Web 负责发现、交易和售后，客户端负责本机内容。 |
| 目标用户 | 网页游客、已登录玩家及三端商城运营。 |
| 核心目标 | 商品、订单和权益一致，购买后可继续到客户端。 |
| 使用场景 | 玩家浏览购买；运营按端配置资源。 |
| 功能概述 | 商城、账号、结算、订单、客户端下载、公共页、手柄占位和资源管理。 |

### 4.2 数据、安全与页面要求

| 需求项 | 具体要求 |
|---|---|
| 历史数据 | 订单保留商品、版本、组成、金额、币种、地区、折扣和协议快照，不随运营配置变化。新订单按 UID 归属，历史仅有邮箱的记录兼容原邮箱匹配；手机号不伪作邮箱，已有 UID 冲突时不跨账号合并。换绑邮箱保 UID 和订单归属。 |
| 结果依据 | 商品和结算取共享服务；支付、权益、退款按实际业务结果。跳转、请求发出、按钮点击或 Demo 成功不能代替正式成功。 |
| 安全与权限 | 前台只访问本人数据；后台校验角色和展示端范围。App 扫码不授予后台业务权限。页面、日志及埋点不记录手机号／邮箱明文、二维码原文、密码、验证码、认证凭据、卡号、CVV 或完整支付令牌；用户本人账号表单的必要显示除外。 |
| 响应式与操作 | 桌面、窄窗口和手机宽度下主图、金额、按钮及表单不遮挡；支持键盘、可见焦点及文字错误，关键操作不依赖悬停。 |
| 外部依赖 | 账号侧提供国内／海外验证码、三方绑定匹配、年龄、换绑与会话；App 侧提供扫码认证并确认原盖世 UID，正式协议及二维码生命周期待确认；商品侧提供媒体、组成、价格和可售性；支付侧接入 Stripe 并提供正式支付结果；权益侧确认入库；邮件承接邮箱验证、购买凭证和退款结果通知。 |
| 运营与法务 | 运营提供推荐／榜单来源、素材和端映射；法务／商务提供政策、公司主体、地区许可与正式文案。公共页不在本后台编辑。 |
