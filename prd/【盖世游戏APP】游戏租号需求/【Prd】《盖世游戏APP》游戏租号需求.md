## 二、背景与目标

### 2.1 需求背景

盖世游戏 Mac 端已完成游戏租号方案设计。<span style="background-color: #FEF794;">APP 横屏沿用已确认的 Mac 任务页信息骨架，竖屏复用同一组件、内容顺序和业务状态并做纵向适配；核心页继续使用 APP 原有导航，详情、结算、会员、订单、Steam 登录和售后等任务页不显示全局导航。</span>本期需要在不破坏“已有游戏优先启动/下载”的前提下，为没有当前游戏权益的用户补充低门槛租用、单游戏永久畅玩和会员游戏库能力，并形成“发现—购买—取号—登录—游玩—到期—售后”的闭环。

用户当前只能自行购买游戏、导入已有游戏，或离开盖世游戏寻找第三方租号服务。外部方案需要反复切换平台、复制账号密码、处理 Steam Guard，并且订单、到期和售后状态与盖世游戏割裂。本期通过一键上号主路径、手动登录兜底、跨方向状态连续和平台内售后，降低开始游玩的操作成本与信任成本。

已知条件：

1. <span style="background-color: #FEF794;">横竖屏共用权益、订单、账号、登录和到期状态；横屏继承 Mac 已确认任务页骨架，竖屏复用同一组件和业务顺序做纵向适配。</span>
2. 游戏是否加入会员游戏库决定可售 SKU；已经支付或正在使用的订单按订单快照履约。
3. 一键上号为主路径，账号、密码和验证码仅在有效使用单的短时授权内按需展示。
4. 租用临期只在服务端剩余时间准确达到15分钟时提醒一次，不再设置5分钟或1分钟提醒。

## 三、故事介绍

### 3.1 用户与运营场景

**场景一：普通游戏按时长租用**

用户在首页或游戏库看到“可租号”，进入详情后默认选择2小时租用；如果需要更长时间，可在“更多租期”中选择3—23小时、日租或周租。用户确认版本和价格后完成支付，系统分配同游戏同版本账号，并优先提供一键上号。

**场景二：会员游戏库的新用户体验**

游戏已加入会员游戏库，且用户仍有全平台一次的首次体验资格。详情页只展示“首次体验、单游戏永久畅玩、开通会员”；用户使用首次体验后，列表不再显示首次价，统一显示“可租号”，详情页只保留当前仍可购买的长期权益。

**场景三：会员用户畅玩**

有效会员进入会员游戏库或会员游戏详情，主操作直接显示“会员畅玩”。月度、年度和永久会员都在独立会员中心购买；单游戏订单页不嵌入会员购买 Tab。

**场景四：一键失败后手动登录**

用户支付并取号后选择一键上号；若一键失败，可切换到 Steam 手动登录。Steam 登录页保持主界面，用户按需打开“租号登录信息”浮层，复制账号、密码；Steam 提交账号密码后如要求验证，再获取并复制5位 Steam Guard 验证码。订单“登录信息”入口只打开独立凭据面板，不拉起 Steam。两处共用同一使用单、账号和有效验证码，不重复取号。

**场景五：临期、到期与售后**

租用剩余时间准确达到15分钟时，APP 顶部居中提醒一次“租用时间快结束了，是否继续畅玩？”。用户可进入当前游戏详情查看可用权益，原租期不会自动延长。到期 T0 未获得新权益时，系统结束游戏、撤销会话、清理凭据并释放账号；用户可在订单详情提交售后、查看退款四阶段或申请同游戏同版本换号。

### 3.2 价值分析

- 用户价值：在现有 APP 内用更低决策成本开始游戏；一键上号减少凭据操作，手动登录保证兼容性；订单、到期和售后状态可追踪。
- 平台价值：在不抢占已有游戏主路径的前提下新增租号、单游戏永久和会员收入，并复用既有账号池与后台能力。
- 运营价值：按地区、灰度、游戏、SKU、方向和登录方式观察完整漏斗，能够定位库存、支付、登录和启动问题。
- 风险控制：凭据展示、复制、验证码、会话撤销和账号释放均绑定有效使用单，降低明文泄露和账号复用异常。

### 3.3 核心体验路径

1. 租号：发现可租游戏 → 详情判断权益与 SKU → 选择套餐 → 确认订单 → 支付 → 分配账号 → 一键上号/手动登录 → 启动目标游戏 → 15分钟提醒一次 → 到期或售后。
2. 会员：详情/个人中心/会员游戏库 → 独立会员中心 → 选择月度/年度/永久 → 支付 → 更新会员状态 → 返回会员游戏库 → 会员畅玩。
3. 手动登录：有效使用单 → Steam 登录页 → 打开租号登录信息 → 复制账号密码 → Steam 提交 → 按需获取 Guard → 验证 → 启动结果校验。
4. 旋转：任一关键节点旋转设备 → <span style="background-color: #FEF794;">横屏使用 Mac 衍生骨架、竖屏使用同组件纵向布局</span> → 当前页面、套餐、订单、倒计时、输入和授权状态保持。

### 3.4 产品指标预测

| 指标 | 预期变化 | 主要驱动 | 主要风险 |
|---|---|---|---|
| 可租游戏详情进入率 | 上升 | 首页、玩游戏、游戏库和搜索统一曝光 | 曝光过强会干扰已有游戏用户 |
| 详情到支付转化率 | 上升 | 默认低承诺 SKU、更多租期折叠、价格快照 | 游戏价格和库存差异导致波动 |
| 支付后启动成功率 | 上升 | 一键上号为主、手动登录兜底 | Steam、供应商账号或验证码异常 |
| 会员购买占比 | 逐步上升 | 会员游戏库、个人中心会员状态和独立会员中心 | 用户混淆单游戏永久与永久会员 |
| 售后率 | 灰度早期可能上升后回落 | 新链路初期暴露账号与兼容问题 | 自动退款和换号能力不足 |

### 3.5 路径规划

| 阶段 | 范围 | 放量建议 | 进入下一阶段条件 |
|---|---|---|---|
| 联调 | 内部账号、指定游戏、竖横屏 | 内部白名单 | 支付、取号、登录、启动、到期、退款全链路通过 |
| 小流量灰度 | 指定地区与20%稳定分桶 | 首批游戏和账号池 | 无凭据泄露；分配成功率≥99%；启动成功率≥95% |
| 扩量 | 50%稳定分桶 | 增补游戏和库存 | 支付、库存、登录、退款告警稳定，客诉可处理 |
| 全量 | 100%或目标地区全量 | 按运营计划 | 关键指标连续7天稳定，回滚方案演练通过 |

| 4. 价格快照与资格 | — | 首次体验资格全平台共用且支付成功后核销。首次体验按游戏版本读取供应商2小时采购价 `C`：`C≤¥1.99` 时前端展示价为 `¥1.99`，`C>¥1.99` 时展示价为 `C×1.2` 并四舍五入保留2位小数；采购价只用于服务端计价，不返回客户端、埋点或普通日志。游戏订单锁定用户、地区、游戏、版本、SKU、原价、实付价、价格版本、会员库状态和首次资格30分钟。会员订单独立编号、独立支付和独立权益快照。 |
| 5. 库存、取号与使用单 | — | 复用账号健康、同游戏同版本库存、锁定、分配、换号、释放与异常隔离；APP 一键和手动登录共用同一使用单，重复点击或方向切换不得重复取号。供应商失败需返回可识别错误码，支付后不可履约进入自动退款。 |
| 6. 凭据与验证码 | — | 账号、密码和 Guard 只能由有效使用单通过专用短时授权接口获取；返回掩码状态、授权到期和验证码到期，不向普通订单接口、埋点、导出或后台普通详情返回明文。到期、退款、换号、结束或退后台按安全策略撤销授权。 |
| 7. 到期与提醒 | — | 服务端 `expire_at` 为唯一基准，并返回服务器时间；APP 仅消费 `expire_15m` 一次性提醒。T0 触发会话撤销、凭据清理、账号释放和使用单结束；回收失败账号进入异常池。 |
| 8. 售后与退款 | — | 复用五类售后、问题描述、启动结果、账号诊断、支付后72小时且累计游玩不超过30分钟的3天无理由资格、高频无理由退款风控、退款四阶段与同版本换号；APP 新增方向、客户端版本、登录方式和启动阶段信息，禁止携带明文凭据。 |
| 9. 操作记录与统计 | — | 商品、会员库、套餐、库存、订单、售后、退款、外放和灰度操作继续进入共用操作记录；统计新增 APP、竖/横屏、入口、SKU、登录方式、异常码维度。 |

#### 4.3.1 边界条件-内容侧

| 场景 | 触发条件 | 处理方式 | 提示文案 |
|---|---|---|---|
| 游戏加入会员游戏库 | 商品存在普通时租/日租/周租 | 保留原配置但对新创单失效；只开放首次体验、单游戏永久和会员引导 | 后台：“已加入会员游戏库，普通租期暂不生效” |
| 游戏移出会员游戏库 | 运营执行移出 | 校验原租期价格、库存和版本；全部有效才恢复，否则停止新创单并进入待修复 | 后台：“原租号配置校验失败，请修复后重新上架” |
| 商品下架或版本停用 | C 端仍有缓存 | 服务端拒绝新创单，客户端刷新详情；已支付订单按快照履约 | “当前版本暂不可购买” |
| 价格变化 | 用户已在确认订单 | 锁价期内不变；锁价失效或版本变化要求重新确认 | “价格已更新，请按新价格重新确认订单” |
| 库存不足 | 可售库存为0 | 新下单按钮置灰；支付后才发现不足则自动退款 | “暂时无可用账号” |

#### 4.3.2 边界条件-用户侧

| 场景 | 触发条件 | 处理方式 | 提示文案 |
|---|---|---|---|
| 已拥有/已导入游戏 | 本地或账号权益校验命中 | 主操作改为启动或下载，隐藏购买入口 | 无额外打扰 |
| 首次体验已使用 | 全平台资格已核销 | 列表显示“可租号”，详情隐藏首次体验 | 无 |

| 非目标游戏操作 | 租赁会话尝试获取、下载或启动其他游戏 | 立即拦截并引导单独获取权益 | “当前游戏未租用，请先获取游戏权益” |

| 网络中断 | 支付、登录或到期校验中断 | 保留非敏感本地状态，恢复后按订单号幂等查询 | “网络异常，请恢复后重试” |

> 数据安全：禁止在事件名、参数、日志、Crash 信息、Toast、订单导出和分析宽表中上报 Steam 账号、密码、Guard 验证码、短时授权 token 或其可逆变形。

### 9.2 待确认项

#### 必须确认（阻塞开发）

1. **首发地区与灰度初始值**：默认建议首发地区按运营确认、20%稳定分桶开始；影响2.3、3.5、4.3、7章。
2. **首发游戏与库存**：默认建议仅上架已完成一键、手动、Guard、启动、撤销和释放全链路抽检的游戏；影响4.2、4.3、7章。
3. **APP 支付能力**：需确认 Android/iOS 各地区可用支付方式、二维码能力和平台合规要求；默认按支付宝/微信展示中国大陆方案，海外由支付服务返回；影响4.2.4、4.2.5、附录A。
4. **退款与凭据合规**：需由法务确认3天无理由、Steam 平台条款、向用户展示账号密码/Guard及未成年人规则；默认未通过前只允许内部白名单；影响4.2.10、4.2.13、5章、7章。

#### 建议确认（影响完整度）

1. **业务转化目标**：默认灰度首周先建立按端、方向、地区、游戏和 SKU 的基线，首月再设转化目标；影响2.2、3.4、6章。
2. **海外会员价格与币种**：默认由后台按地区返回本币价格和版本，不由客户端换算；影响4.2.5、5章、附录A。
3. **15分钟提醒的系统推送补充**：默认只做 APP 内游戏内/外顶部提醒，不新增系统通知；影响4.2.11。

#### 可后续补充

1. 会员游戏库首批完整清单、上下架预告周期和多语言 FAQ 正文，可在内容配置完成后追加。
2. 灰度首周真实漏斗、账号复用、退款和客诉数据，可在第八章追加并更新目标值。
