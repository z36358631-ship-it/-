## 一、背景概述

### 1.1 背景概述

用户想低成本体验 PC 游戏时，需离开盖世游戏寻找第三方租号，账号登录、订单、到期和售后与 APP 割裂。本期把“发现可租游戏—购买权益—登录游玩—订单管理—售后”接入盖世游戏 APP，并复用 Mac 端交易、履约和运营后台能力。

当前方式是购买游戏、导入自有游戏，或跳转第三方租号平台；本需求增加低门槛体验，但不替换已有购买、获取、导入和启动路径。

成功指标口径：首期按入口、游戏、权益方案、地区和客户端统计详情到支付转化率、支付成功率、登录成功率、启动成功率、退款率及售后完成率；灰度首周建立基线，后续版本目标以首周数据为准。

### 1.2 需求边界

| 边界类型 | 本期约束 |
|---|---|
| 产品边界 | 覆盖 APP 首页、PC 游戏、社区、排行榜、游戏库、个人中心、搜索、游戏详情、确认订单、会员、订单、登录、提醒、售后、消息中心和支付结果；横竖屏共用业务状态。游戏库顶层为“PC游戏／复古游戏”，在PC游戏页Steam左侧新增“会员游戏”；PC游戏频道和会员中心的会员游戏库入口统一进入二级会员游戏库页。 |
| 业务边界 | 首期只售首次体验2小时、单游戏永久、会员周卡/月卡/季卡；2—23小时、日租、周租及续租属于后续热门游戏时租版本。CDKEY 只复用视觉骨架，不进入本需求。 |
| 运营边界 | 复用 Mac 租号后台，在业务页增加 APP（安卓端）与 Mac 页内 Tab并默认 APP；操作记录不增加端别 Tab。供应商只提供参考数据，C 端文案和上下架由运营控制。 |
| 人力边界 | APP、服务端、运营后台、支付、账号履约、数据、测试、客服与法务共同交付；不新建 APP 专属后台，不新增支付渠道，不支持用户出租账号。 |

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| 首次体验 | 每位用户在整个游戏平台终身仅可购买一次的2小时体验权益，从支付成功时间开始计时。 |
| 单游戏永久 | 对指定游戏标准版的长期游玩权益，不代表账号所有权，也不承诺固定使用同一账号。 |
| 会员 | 在有效期内游玩会员游戏库的权益，首期套餐为周卡、月卡、季卡。 |
| 使用单 | 权益启动时生成或复用的履约记录，用于账号绑定、有效期、登录、换号和回收。 |
| 游戏提示语 | 运营按游戏与语言维护的 C 端提示，展示在确认订单、订单卡和订单详情。 |
| 供应商特殊备注 | 第三方同步的内部参考信息，不直接展示给用户，也不覆盖游戏提示语。 |
| 3天无理由 | 满足支付后72小时、目标游戏累计成功运行不超过30分钟且订单快照允许时可申请的退款权益。 |

## 二、方案设计

### 2.1 产品／方案简介

1. 在现有内容入口展示租号价格或权益状态，点击游戏后统一进入详情。
2. 游戏详情按用户权益和商品状态展示“立即购买”“租号开玩”“登录游戏”等互斥动作；租号 SKU 只在确认订单选择。
3. 首期确认订单仅提供首次体验2小时、单游戏永久和开会员畅玩；支付成功后权益立即生效，每次启动时由服务端完成履约，C端不展示内部准备过程或中间状态。
4. 订单中心承接支付、有效期、登录信息、退款进度与售后；用户先选择申请退款或申请换号，退款与换号均进入运营人工审核，退款成功后允许再次购买，命中高频退款规则时先提示本单无3天无理由。
5. 后台复用 Mac 页面和交互，只增加端别隔离；游戏提示语、供应商目录、换号和退款规则按双端同一服务端口径执行。

### 2.2 产品流程

![首期主流程](https://cdn.jsdelivr.net/gh/z36358631-ship-it/-@0d801db4ebe463554bb7812412762c4e52211511/public/prd/app-rental/app-rental-current-flow.png)

首期路径为：发现租号 → 游戏详情 → 选择首次体验、单游戏永久或会员 → 支付 → 权益生效 → 登录与启动 → 订单与售后。会员发现路径为：游戏库“会员游戏”、PC游戏频道或会员中心“会员游戏库／查看全部” → 二级会员游戏库 → 游戏详情；从二级会员游戏库返回时恢复对应来源页面。支付、权益发放、账号准备或售后结果未知时，凭订单号查询服务端真值，禁止重复扣款、重复发放或重复退款。

Demo右下悬浮“Demo状态”提供“常规／多次购买”切换：“常规”演示未命中退款风险，“多次购买”演示命中退款风险并在点击“租号开玩”后出现退款权益提醒。该开关仅为演示工具，不属于APP产品页面，也不代表购买次数决定退款资格；线上始终以服务端订单风险快照和近30天已完成的3天无理由退款次数为准。切换只影响下一次租号购买演示，不追改已生成订单的风险或退款资格快照。

### 4.2 服务端与技术规则

1. 权益判断顺序为有效使用单、单游戏永久、有效会员且命中会员库、无权益；客户端只展示判定结果。
2. 首次体验在支付成功时核销全平台终身一次资格并开始2小时计时。用户主动退款不返还资格；平台原因从未成功履约并经人工审核完成退款时返还资格，资格恢复必须记录售后单和审核结果。
3. 待支付订单锁定 SKU、标准版、权益方案、游戏原价、订单金额、币种、资格快照和价格版本30分钟。Mac 开发稿虽删除部分 `price_version` 展示，APP 首期仍保留服务端价格版本与订单快照，避免半删除导致计价、埋点和对账不一致。
4. 首次体验和单游戏永久适用3天无理由：支付后72小时内、目标游戏累计成功运行不超过30分钟且下单快照允许。首次体验已到期仍可在该条件内申请；下载、登录失败和启动失败不计入成功运行时长。
5. 高频退款按近30天内已完成的3天无理由渠道退款次数判定，达到3笔时命中；购买次数、退款申请次数、处理中、拒绝或履约退款均不替代该计数。点击“租号开玩”时前置提醒，提交新订单前由服务端复核并写入订单风险快照；用户确认继续后，仅该新订单不享受平台额外3天无理由承诺，法定退款权利以及Steam登录失败、启动失败、账号异常等履约售后仍保留。
6. 同一订单同时只能存在一张进行中的售后单，申请退款与申请换号互斥。退款进入支付渠道前、换号新账号实际绑定前允许撤销；渠道退款成功后立即显示已退款，资源回收失败进入补偿任务且不回滚订单状态。
7. 退款后允许再次购买：首次体验主动退款不恢复购买资格；单游戏永久退款且权益撤销成功后允许重购；会员可续费并顺延有效期。首期不涉及时租重复购买。
8. 每次从游戏详情启动时，服务端幂等准备或复用账号，客户端不展示内部准备过程。账号池不足或其他履约异常不得由前端直接自动退款；保留当前权益与原绑定，引导用户申请售后，由运营人工审核退款或换号。
9. 支付、权益发放、账号准备、登录、退款、换号和通知发送均使用业务请求号幂等。结果未知时查询原记录，不得创建新订单、新使用单、重复售后、重复退款或重复触达。
10. `expire_at` 为有效期唯一时钟；客户端按服务端时间计算展示。剩余不超过24小时显示“X小时X分”，超过24小时显示“X天X小时”；旋转、休眠和前后台切换不改变时钟。
11. 游戏提示语按 `game_id + language` 返回并保存订单快照；当前语言无配置时取运营设置的默认语言，默认语言也为空则不返回占位。供应商特殊备注仅供后台查看，禁止直接下发 C 端。
12. 登录凭据采用短时授权、传输加密和默认脱敏；账号、密码、验证码不得写入持久化、截图缓存、日志或埋点。关闭、退后台、到期、退款、换号时清除授权。
13. 供应商价格以美元作为底层价值口径，后台与订单快照记录人民币和美元金额；新订单按最新同步价格与汇率计算，已创建订单不随汇率变化。C 端依据地区展示币种，不把不同语言金额拆成不同商品。
14. 游戏库Steam左侧“会员游戏”、PC游戏频道和会员中心的“会员游戏库”标题／“查看全部”、会员开通结果入口统一路由到二级会员游戏库；返回时恢复对应来源页、分类和滚动位置，横竖屏共用来源。
15. 通知按“订单＋事件＋渠道”生成唯一发送记录。到期前15分钟、订单到期和普通售后进度发送PUSH、站内信；退款与换号审核结果、退款到账发送PUSH、短信、站内信。任何渠道均不得携带登录凭据。

### 4.3 运营要求

1. 首期商品清单只配置首次体验2小时、单游戏永久及会员周卡、月卡、季卡；热门游戏时租配置不得提前外放到 APP。
2. 运营按游戏和语言提供简短提示语，并复核确认订单、订单卡和订单详情三处一致；供应商备注不能作为缺省文案。
3. 供应商只同步运营支持游戏名单。资料变化不自动上下架；异常空集、超时或局部失败保留上次正常结果并告警。
4. 客服准备登录、验证码、无资源、首次体验资格、3天无理由、高频退款、退款／换号售后进度、通知未达、换号待执行和退款后重购话术。
5. 灰度日报分别统计 APP 与 Mac，首期仅纳入首期权益，避免后续时租测试数据污染。

### 4.4 财务与法务要求

1. APP 支付方式只提供微信和支付宝。订单金额、底部需支付、支付请求、退款金额和财务对账必须同源，金额保留2位小数。
2. 会员不支持主动3天无理由，首次体验和单游戏永久按订单资格快照判断；履约异常退款不受高频退款限制影响。
3. 需完成共享账号来源、Steam及第三方平台条款、凭据展示、国内实名、海外地区、税费、退款告知和隐私留存评审。未通过的地区只开放内部白名单。
4. 供应商结算、渠道退款和权益撤销分别记录结果；渠道退款成功不能因账号回收失败回滚，差错进入日对账与人工补偿。

## 五、待确认项

1. **高频退款双端口径：**APP 采用“30天内3笔已完成3天无理由退款”，Mac 开发稿仍写“7天内3次全部退款”。推荐 Mac 同步改为30天、3笔、只统计3天无理由渠道退款成功，否则同一账号跨端会得到不同购买结果。
2. **价格版本：**Mac 开发稿只删除了部分 `price_version`，但仍保留30分钟锁价、订单快照和埋点字段。推荐双端继续保留服务端价格版本，只从不需要用户理解的后台展示中移除；若要彻底删除，需同时改计价、订单、埋点和对账。
3. **单游戏永久定价：**Mac 同一开发稿同时存在“最低售价与系数 x2、y2”和“Steam 原价15%—50%折扣”两套规则。推荐首期只保留一套服务端定价来源；产品、运营和财务确认前，不把任一公式写成 APP 最终价格规则。
4. **会员正式价格：**周卡、月卡、季卡的最终价格及促销策略需运营确认；交互默认选中周卡，不依赖推荐角标。
5. **国内实名门槛：**推荐沿用现有国内交易实名规则，海外不展示实名；需法务和支付最终确认。
6. **履约异常售后SLA：**账号池不足等履约异常已确定不做前端自动退款，需运营、客服和服务端确认人工审核首次响应、退款审核与换号处理时限，并配置超时告警。

## 六、后续版本：热门游戏时租

本章不属于首期开发、后台首期配置和首期埋点范围，只用于锁定后续产品方向。

1. 热门游戏采用时租模式，与首次体验、单游戏永久、会员方案分开配置，不在同一确认订单混售。
2. 租赁套餐包括按小时、日租、周租。按小时可选2—23个整数小时，默认2小时，并提供6小时、12小时、23小时快捷项；日租和周租按固定周期计费。
3. 确认订单仍只展示标准版，订单金额随套餐和小时数变化，底部“需支付”与支付请求保持一致。
4. 时租订单可重复购买；有效租期内再次购买属于续租，新时长从原 `expire_at` 顺延，不重置当前使用单。支付后才顺延，取消或失败不改变有效期。
5. 时租有效时搜索、首页和列表继续优先显示“已租号”；有效期超过24小时显示“X天X小时”。到期且无其他权益时重新展示租号入口。
6. 后续上线前需单独补充时租价格规则、库存预占、续租并发、跨套餐顺延、退款金额分摊、提醒策略和对应埋点，不得直接复用首期首次体验资格规则。
