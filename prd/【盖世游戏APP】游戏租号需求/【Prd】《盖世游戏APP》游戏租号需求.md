## 二、背景与目标

### 2.1 需求背景

用户没有目标游戏权益时，当前只能购买游戏、导入已有游戏，或离开盖世游戏寻找第三方租号服务。第三方方案需要切换平台、手动处理账号密码与 Steam Guard，订单、到期和售后状态也与盖世游戏割裂。

本期在不影响“已有游戏优先启动或下载”的前提下，补充低门槛租用、单游戏永久畅玩和会员游戏库，并形成“发现—选权益—支付—租赁生效—登录—游玩—到期—售后”闭环。

已确认条件：

1. APP 核心页沿用 V6.1.1 原结构，不新增全局导航，不重排与租号无关的模块。
2. 横竖屏共用游戏、权益、价格、订单、登录、租期和售后状态；旋转只重排，不重新创单、扣款、取号或获取 Guard。
3. 用户已有权益优先于价格；租号与 CDKEY 不是同类 SKU，禁止跨类型取绝对最低价。
4. 个人中心只保留一个“订单中心”；本期订单中心 Demo 只演示租号订单和租号状态。
5. 共用后台、账号池、支付、退款和结算能力沿用 Mac 端；APP 不新建专属租号后台。
6. <span style="background-color: #FEF794;"><span style="color:#3370FF;"><strong>每款游戏使用稳定售卖模式：热门游戏仅时租；非热门游戏仅首次体验、单游戏永久和会员入口，不按实时热度自动变化。</strong></span></span>

需求证据：

- 用户提供的个人中心与订单中心截图确认了统一入口及订单卡外壳。
- V6.1.1 使用说明手册确认了 APP 核心页结构。
- Mac 租号方案已确认租期、会员、取号、Steam 登录、临期、退款和换号规则。
- [高风险假设] APP 租号暂无正式业务基线，入口点击和购买转化目标需在灰度首周建立。

## 三、故事介绍

### 3.1 用户与运营场景

1. <span style="background-color: #FEF794;"><span style="color:#3370FF;"><strong>普通租号：符合首租资格的用户在首页 Banner 看到“¥1.9首租 / 99+ 在租”，首页小游戏卡看到“¥9.9租号 / 在租99+”，搜索游戏卡则按用户当前状态显示“已租号 / 可畅玩 / ¥X.X · 租号”之一；点击整卡进入详情，再点击“租号开玩”一次进入确认订单并选择 SKU。</strong></span></span>
2. <span style="background-color: #FEF794;"><span style="color:#3370FF;"><strong>状态收敛：同一游戏有有效租赁时显示“已租号”；没有有效租赁但已可直接游玩时显示“可畅玩”；首页与搜索不展示剩余时长、订单进度或“首次体验/会员畅玩”等权益来源。</strong></span></span> 首次资格、会员或永久权益仍在详情按实时资格处理。
3. 长期权益：用户可购买单游戏永久畅玩；会员中心首期只提供周卡、月卡、季卡，不提供永久会员。单游戏永久属于单款游戏权益，不得与会员套餐混淆。
4. 订单找回：用户从个人中心进入统一订单中心，在“全部订单 / 待支付 / 可使用”中查看租号订单，并在当前 Tab 内搜索游戏名称或订单编号。
5. 登录与游玩：租赁生效后优先一键上号；用户也可主动进入 Steam 手动登录并按需查看账号、密码和 Guard。部分游戏还需按具体配置继续使用 Rockstar Games 等第三方平台账号、密码和短时验证码。
6. 临期与售后：剩余时间首次跨入15分钟内时提醒一次；到期后结束租赁会话。用户可在订单详情提交四类问题售后和同版本换号；取号失败继续由系统自动退款。
7. 运营与客服：运营使用共用后台配置商品、会员库、套餐、地区和灰度；客服按订单、使用单和售后单定位问题，不读取明文凭据。

### 3.2 价值分析

- 用户价值：降低开始游玩的购买门槛和跨平台操作成本。
- 平台价值：新增租号、单游戏永久和会员收入，复用已有账号池与交易能力。
- 转化价值：租购价格分开表达，减少无效点击、价差退出和退款投诉。
- 运营价值：统一订单入口，减少入口维护、客服解释和用户找单成本。
- 风险：库存健康、凭据安全、Steam 条款、退款时效和海外地区规则必须在灰度前确认。

### 3.3 核心体验路径

1. 租号：入口 → 详情权益判断 → 点击租号开玩 → 确认订单选择 SKU → 支付 → 租赁生效 → 一键上号或手动登录 → 游玩 → 临期 → 到期或售后。
2. 会员：详情、个人中心或会员游戏库 → 会员中心 → 选择套餐 → 支付 → 权益生效 → 会员游戏库 → 会员畅玩。
3. 订单：个人中心 → 订单中心 → 当前 Tab 筛选或搜索 → 订单卡 → 订单详情 → 继续支付、登录游戏、继续畅玩或售后。
4. 恢复：支付、账号准备、登录或售后中断 → 保留订单号和非敏感结果 → 网络恢复 → 查询服务端真值 → 恢复原任务。

### 3.4 产品指标预测

| 指标 | 预期方向 | 主要原因 | 风险 |
|---|---|---|---|
| 租号详情进入率 | 上升 | 现有入口增加明确租号价格或状态 | 入口过强会干扰已有游戏路径 |
| 详情到支付转化率 | 上升 | 默认低承诺租期、价格快照、库存预校验 | 游戏价格和库存差异较大 |
| 价格曝光到支付成功率 | 上升 | 租购不跨类型取最低价 | 双价格表达占用更多信息空间 |
| 订单继续任务成功率 | 上升 | 统一入口和状态动作 | 状态聚合错误会把订单放入错误 Tab |
| 退款与客诉率 | 下降 | 支付、账号准备结果、租期和退款分别保留真值，客户端只展示可行动状态 | 供应商失败或退款超时会反向放大投诉 |
