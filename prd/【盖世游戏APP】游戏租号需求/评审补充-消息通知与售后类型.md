# 《盖世游戏APP》租号评审补充：消息通知与售后类型

> 本文只补充“申请退款／申请换号”和租号消息通知，未提及的租号规则沿用主PRD。

## 1. C端—申请售后页

| 六要素 | 内容 |
|---|---|
| 功能简介 | 用户先选择“申请退款”或“申请换号”，再提交对应原因和说明，避免退款与换号混在同一问题类型中。 |
| 场景描述 | 用户在可使用订单中遇到履约问题，或订单满足3天无理由资格，需要发起退款；账号异常时也可直接申请换号。 |
| 输入／前置条件 | 1. 用户已登录，订单属于当前用户且状态允许申请售后。<br>2. 同一订单没有进行中的售后单。<br>3. “3天无理由”仅首次体验、单游戏永久且订单资格快照有效时可选；会员订单不展示该原因。 |
| 需求描述 | **图示：**<br>1. `20-after-sales-refund-portrait.png`（申请退款）<br>2. `21-after-sales-replacement-portrait.png`（申请换号）<br>**详细说明：**保留现有订单摘要和售后任务页骨架，将原“问题类型”改为“售后诉求→具体原因”两级选择。<br>**展示说明：**<br>1. 顶部展示页面标题、订单编号、游戏名和填写状态。<br>2. “售后诉求”固定展示“申请退款、申请换号”，默认选中申请退款。<br>3. 申请退款展示“3天无理由、无法登录、无法启动、账号异常、其他问题”；申请换号展示“无法登录、账号异常／频繁掉线、游戏无法启动、其他问题”。<br>4. 退款展示预计退款金额和人工审核提示；换号展示“审核通过后，下次启动游戏时自动使用同游戏、同标准版、同地区的新账号”。<br>5. 3天无理由的补充说明选填；其余原因的问题描述必填，限制1—300字。底部按钮随诉求显示“提交退款申请”或“提交换号申请”。<br>**交互说明：**<br>1. 切换售后诉求后立即切换原因、提示和提交按钮；原原因不属于新诉求时，自动选中该诉求第一个可用原因。<br>2. 不满足3天无理由资格时该原因置灰，并展示不可用原因；其他履约退款原因仍可选择。<br>3. 点击提交时防重复提交；成功后关闭申请页、返回订单详情，提示“售后申请已提交”，订单按钮改为“售后详情”。<br>4. 提交失败时保留已选诉求、原因和输入内容，按钮恢复可点，并提示用户重试。 |
| 输出／后置条件 | 创建一张与订单绑定的售后单，记录售后诉求、具体原因、说明、申请时间和订单资格快照；进入人工审核队列。 |
| 补充说明 | **触发入口：**<br>1. 订单详情页“申请售后”。<br>**展示：**<br>1. 预计退款金额只作预估，最终退款金额和结果以审核及支付渠道为准。<br>**交互：**<br>1. 同一订单只能提交一种诉求；未提交前可自由切换，提交后从“售后详情”查看进度。<br>**异常情况：**<br>1. 重复点击、重复请求或已有进行中售后时不得新建第二张售后单。<br>2. 订单状态变化导致不可申请时，保留订单并提示“当前订单状态暂不支持申请售后”。 |

## 2. C端—售后详情弹窗

| 六要素 | 内容 |
|---|---|
| 功能简介 | 展示退款或换号的处理进度、审核结果和可撤销状态。 |
| 场景描述 | 用户提交售后后，从订单详情点击“售后详情”，确认平台是否受理、是否可撤销及最终结果。 |
| 输入／前置条件 | 当前订单已存在售后单，且售后单归属当前用户。 |
| 需求描述 | **详细说明：**同一弹窗根据售后诉求展示不同进度节点。<br>**展示说明：**<br>1. 公共信息包括售后诉求、具体原因、问题描述、提交时间和当前状态。<br>2. 退款进度为“退款申请已提交→平台审核中→退款原路到账”。<br>3. 换号进度为“换号申请已提交→平台审核中→下次启动生效”；审核通过显示“已同意，待下次启动”，不显示已立即换号。<br>4. 当前阶段允许撤销时显示“撤销售后”，不可撤销时不展示。<br>**交互说明：**<br>1. 用户撤销成功后关闭弹窗，订单恢复“申请售后”入口。<br>2. 退款进入支付渠道处理后不可撤销；换号实际执行后不可撤销。<br>3. 换号审核通过后，用户下次从游戏详情启动时获取新账号；新账号绑定成功后再撤销旧凭据。 |
| 输出／后置条件 | 用户获得明确的售后状态；退款成功后订单更新为已退款，换号成功后后续启动使用新账号。 |
| 补充说明 | **触发入口：**<br>1. 订单详情页“售后详情”。<br>**展示：**<br>1. 审核拒绝时展示拒绝原因；退款金额、到账时间以支付渠道结果为准。<br>**交互：**<br>1. 关闭弹窗返回原订单详情，不改变当前订单状态。<br>**异常情况：**<br>1. 换号审核通过但暂无同游戏、同版本、同地区账号时，显示“等待可用账号”，保留原账号绑定；新账号准备失败不得撤销旧凭据。<br>2. 进度查询失败时保留最近一次状态，提供重试，不展示空白或错误完成态。 |

## 3. C端—消息中心

| 六要素 | 内容 |
|---|---|
| 功能简介 | 在APP内集中展示租号订单、退款、换号和到期提醒，作为PUSH或短信未送达时的可追溯记录。 |
| 场景描述 | 用户收到到期提醒或售后状态变化后，需要确认事件、订单和后续动作。 |
| 输入／前置条件 | 用户已登录；服务端已生成对应订单或售后事件。 |
| 需求描述 | **图示：**<br>1. `22-rental-notifications-portrait.png`（租号消息中心）<br>**详细说明：**沿用APP现有消息中心骨架，增加租号订单与售后消息。<br>**展示说明：**<br>1. 顶部标题为“消息中心”，文字Tab为“全部、订单与售后”，默认选中“全部”。<br>2. 租号消息卡展示事件标题、简短结果、时间和未读圆点；示例包括换号审核已通过、退款申请已受理、退款已原路到账、租号权益将在15分钟后到期。<br>3. 消息正文只展示订单、游戏、金额和结果，不展示Steam账号、密码、验证码或其他登录凭据。<br>**交互说明：**<br>1. 点击“订单与售后”只筛选相关消息，不改变已读状态。<br>2. 点击消息标记为已读并进入对应订单详情；用户可在订单详情继续打开售后详情。<br>3. 返回消息中心时保留原Tab和滚动位置。 |
| 输出／后置条件 | 用户可在站内信中追溯租号关键事件，并进入对应订单处理后续操作。 |
| 补充说明 | **触发入口：**<br>1. 个人中心右上角“通知”。<br>2. PUSH点击或短信深链进入对应订单详情；未登录时先登录，成功后继续原目标。<br>**展示：**<br>1. 站内信发送成功即生成记录，不以PUSH或短信是否送达为前提。<br>**交互：**<br>1. 同一“订单＋事件”只生成一条站内信；重复回调不得重复展示。<br>**异常情况：**<br>1. 目标订单不存在或无权查看时停留消息中心，提示“订单信息不可用”。<br>2. 网络失败时保留本地已加载消息，重试后再刷新状态。 |

## 4. 消息通知规则

| 事件 | 通知渠道 | 触发时机 | 内容与结果 |
|---|---|---|---|
| 到期前15分钟 | PUSH、站内信 | 订单剩余有效期首次跨过15分钟阈值时 | 提醒游戏名和到期时间；同一租用周期只发送一次。 |
| 订单到期 | PUSH、站内信 | 服务端确认权益到期并结束租用时 | 告知租用结束，用户回到订单或游戏详情查看可用权益。 |
| 换号审核通过／拒绝 | PUSH、短信、站内信 | 审核结果落库后 | 通过时说明“待下次启动生效”；拒绝时说明结果并引导查看原因。 |
| 退款审核结果／退款到账 | PUSH、短信、站内信 | 审核结果落库、支付渠道确认到账时分别触发 | 分别发送审核结果和到账结果；到账金额以渠道回调为准。 |
| 普通售后进度 | PUSH、站内信 | 售后状态发生有效变化时 | 告知当前进度，引导查看售后详情。 |

### 4.1 通用规则

1. 按“订单＋事件＋渠道”生成唯一发送记录；重复业务回调不得重复触达。
2. PUSH或短信发送失败时按现有消息平台策略重试；站内信记录不回滚。后台可查看各渠道发送结果，首期不开放自定义模板。
3. 用户关闭系统通知时PUSH可记为不可达，但站内信仍生成；未绑定手机号、号码无效或用户退订短信时不发送短信，不影响其他渠道。
4. 三个渠道均不得包含Steam账号、密码、验证码、第三方账号或可直接登录的信息。
5. 全部退款和换号申请均进入运营人工审核；账号池不足等履约异常不做前端自动退款，不得绕过审核状态直接展示成功。

## 5. 售后状态与互斥规则

| 售后诉求 | 状态主链路 | 可撤销截止点 | 最终结果 |
|---|---|---|---|
| 申请退款 | 已提交→审核中→支付渠道处理中→已退款／已拒绝 | 支付渠道开始处理前 | 已退款则更新订单并原路退回；已拒绝则保留原权益。 |
| 申请换号 | 已提交→审核中→已同意待下次启动→已换号／已拒绝／等待可用账号 | 新账号实际绑定前 | 新账号绑定成功后撤销旧凭据；失败或缺货时保留原绑定。 |

1. 同一订单同时只能存在一张进行中的售后单，退款和换号互斥。
2. 已撤销、已拒绝、已退款或已换号属于终态；再次申请时重新校验订单状态和资格。
3. 售后状态变化必须同步订单详情、售后详情、站内信和外部通知，四处使用同一结果时间与状态口径。
