## 问题与证据

- 目标用户：已签约厂商的受邀开发者、平台发行运营、平台测试人员。
- 核心问题：缺少在独立主体／域名／数据库／账号边界下，覆盖 Windows、macOS、Linux 的 `Vendor → Game → APPID → Product/SKU → Key 或 Build → Release → 数据` 统一后台闭环。
- 用户当前解决方式：线下对接厂商资料与商务条件；既有 CDKEY 链路处理购买、订单、发 Key、激活和退款；会议确认已有包体管理流，但页面、状态和角色协作未形成完整书面规则。
- 证据与口径：09-01 游戏平台进度会为最高业务基准；结合本地交付文档、WeGame 官方公开文档、TapTap 个人开发者账号登录后可见页面、Steamworks 官方公开文档。TapTap 未开放能力和未完成开发者注册的 Steam 后台不得写成已实测。

## 当前范围

- 涉及端：开发者 Web 后台、平台发行运营 Web 后台、测试 Web 后台；官网 Demo 仅新增后台入口。C 端不新增独立页面，只消费后台生效结果。
- 涉及地区：一期以首个已签约厂商和合同授权地区为准，不在后台新增全球化入驻能力。
- 横竖屏：后台以桌面 Web 为主；官网入口覆盖桌面与 390px 手机响应式。
- 本期包含：4 份 PRD，分别覆盖开发者平台基础／游戏接入与资料、商品／外部 Key／盖世 Key 渠道分销、多平台包体／测试／发布、发行投放与数据分析；官网右上角保留“开发者平台”入口。
- 明确不包含：公众注册、在线合同、线上自动资质／定价／上架审核、税务／银行卡在线收集、复杂组织权限、通用多项目凭证、自动结算、心跳／实时踢线、病毒自动扫描、自动冒烟、问题单、Crash 收集、广告竞价、算法推荐及 C 端页面重做。
