## 问题与证据

- 目标用户：已签约厂商的受邀开发者、平台发行运营、平台测试人员。
- 核心问题：缺少单款乙方 Windows 游戏从资料建档、CDKEY 或包体供给、测试发布到精准投放与结果查看的统一后台闭环。
- 用户当前解决方式：线下对接厂商资料与商务条件；既有 CDKEY 链路处理购买、订单、发 Key、激活和退款；会议确认已有包体管理流，但页面、状态和角色协作未形成完整书面规则。
- 证据与口径：本地交付文档、2026-08-31 会议记录、Steamworks 官方文档、WeGame 开发者平台公开页面及本地截图；产品文档优先，不开展程序预研。

## 当前范围

- 涉及端：开发者 Web 后台、平台发行运营 Web 后台、测试 Web 后台；官网 Demo 仅新增后台入口。C 端不新增独立页面，只消费后台生效结果。
- 涉及地区：一期以首个已签约厂商和合同授权地区为准，不在后台新增全球化入驻能力。
- 横竖屏：后台以桌面 Web 为主；官网入口覆盖桌面与 390px 手机响应式。
- 本期包含：4 份 PRD，分别覆盖平台／厂商／游戏资料、CDKEY 商品与供给、包体测试发布、精准投放与发行数据；官网右上角新增“开发者平台”入口。
- 明确不包含：公众注册、在线合同、税务／银行卡、复杂组织权限、自动结算、Mac／Linux、多正式分支、开发者自助发布／回滚、广告竞价、算法推荐及 C 端页面重做。

## 待确认与风险

- 必须确认：实际 CDKEY 供应商／供给方式及接口能力；一期可复用资源位；可直接使用的用户标签；点击归因窗口。
- 默认建议：CDKEY 先按现有供应商 API 设计；资源位优先盘点首页和已有游戏推荐位；标签先开放地区、语言、设备／系统和本平台行为；点击归因采用同游戏最近有效点击 7×24 小时。
- 已知风险：41 张 PRD 图片的固定 SHA 与语法通过，但当前环境访问 jsDelivr 全部失败，尚不能证明公网 HTTP 可用或飞书已成功转存；正式交付前须补远程校验及至少一张飞书导入冒烟。
