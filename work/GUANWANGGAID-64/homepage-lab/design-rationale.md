# 盖世首页三个方向的设计思路

本轮参考收敛为用户提供的五张首页截图：233乐园PC推荐、小黑盒游戏库推荐、森空岛首页、3DM首页、TapTap首页。截图证明内容组织和入口位置，不能证明推荐算法、运营后台或转化效果；以下权重是待验证的设计判断。

盖世六至七成用户导入游戏、两至三成使用Steam、约一成使用秒玩。这是用户提供的结构，未在本轮重新测量。三方向分别验证付费、开玩、活跃；云端是前三类用户在本机受限时可选择的路径。

## 首页参考的共同点与差别

| 参考页面 | 截图中能看到的做法 | 本轮借鉴 |
|---|---|---|
| 233乐园PC推荐 | 最近在玩；导入/Steam/Epic/设置；大封面；工具和商城入口 | 将已有游戏、获取路径与新游戏发现衔接 |
| 小黑盒游戏库推荐 | 促销Banner；商城/喜加一等金刚区；价格、折扣和榜单标签 | 将游戏吸引力与购买理由放在一起 |
| 森空岛首页 | 活动Banner；玩家图文、作者和互动信息 | 用持续产生的玩家内容提供回访理由 |
| 3DM首页 | 左上签到；运营Banner；三条头条；原创专栏 | 签到独立轻入口，热点与专题分层 |
| TapTap首页 | 游戏日历等金刚入口；大图游戏卡；简短编辑理由 | 让玩法画面承担吸引力，工具入口保持清楚 |

共同保留一个运营资源位、四个稳定金刚入口和左上签到。运营位在三个方向承担不同任务，不再额外叠一个通用大Banner挤占首屏；签到进入现有任务中心。金刚入口为兼容性查询、喜加一、Steam折扣、Steam租号，租号始终进入权益页；弱设备在那里明确设备条件，首页云端主视觉则明确标注云端去向。

## 1、促进付费：让已有游戏的用户产生新的购买理由

小黑盒将促销Banner、商城入口与价格卡片连续展示，用户看中游戏后，能直接比较购买成本。盖世可以借鉴这种决策衔接，但付费对象要回到自己的账号和服务权益。

盖世大部分用户已有导入游戏，不能默认他们缺游戏。我们判断，更可能产生付费需求的场景是：想体验下一款、想在会员库换着玩，或本机运行受限想了解云端。已导入的同一款游戏不能包装成购买后才解锁。

用户关注点是【想玩什么—现有来源还缺什么—多少钱、得到什么—能否使用】。

**所以付费方向展示权重是：具体游戏与服务价值 ＞ 价格和使用条件 ＞ 体验或套餐入口 ＞ 优惠福利 ＞ 社区内容。**

Demo首屏用租号体验承接购买动机，再展示会员库、服务条件和优惠。弱设备首页优先解释云端路径。Steam折扣作为辅助，外部商店跳转不能记作盖世收入。

内容来源：运营选择推广商品和素材；价格、时长、资格、权益和库存应来自业务数据，不逐款编攻略。当前租号与会员价格是已确认历史Demo样例，并非当前在售。

## 2、促成本机开玩：看到想玩的，也知道这台手机能不能玩

233把最近在玩、导入入口与大封面放在一起，TapTap通过大图和简短理由展示游戏吸引力。它们提供了选游戏的线索；盖世还需要解决PC模拟器特有的设备与准备条件。

对于导入和Steam用户，能找到游戏并不等于能在手机上开始。首页需要把玩法画面、当前设备适配和准备状态连在一起：已准备的继续玩，未准备的进入准备，缺兼容记录的先查询。运营不能直接配置“完美兼容”。

用户关注点是【好不好玩—我的手机能不能运行—还差哪些准备—怎么开始】。

**所以开玩方向展示权重是：适配游戏及玩法画面 ＞ 当前设备兼容状态 ＞ 启动或准备入口 ＞ 本机可玩与适配记录 ＞ 相关内容。**

Demo以适配游戏主视觉为核心，后接本机可玩和适配记录。主视觉同时承担精选资源位，不再叠加另一个促销Banner；官方玩法片段手动播放，没有证据不称手机实测或最新适配。

内容来源：游戏媒体与资料库、设备识别、兼容记录、来源和准备状态按游戏ID匹配。运营可选择候选游戏，最终结论和操作由数据决定；无记录时显示缺省。

## 3、促进持续活跃：今天不玩，也有打开的理由

森空岛在活动Banner下持续展示玩家内容，3DM用签到、头条和专栏组织每日信息。可以借鉴它们提供不同阅读深度的方式，盖世不必复制完整资讯站或双列瀑布流。

用户今天可能没时间玩，但仍想看游戏动态、了解发售或领取福利。因此首页先提供有用的新内容，再用发售和限免订阅形成后续提醒，任务只作补充。

用户关注点是【今天有什么新内容—关注的游戏有什么动态—有没有优惠福利—怎样不错过】。

**所以活跃方向展示权重是：社区精选与当日动态 ＞ 游戏日历 ＞ 折扣及喜加一 ＞ 订阅提醒 ＞ 任务活动。**

Demo增加轻量发售日历运营Banner，与下方社区选帖分工；保留每页三条左文右图、整组翻页，以及日历、优惠、限免和提醒。左上签到复用任务中心，不另加积分或奖励规则。

内容来源：社区由运营从真实内容池选帖；发售、价格和限免来自数据源。运营决定选什么，不负责覆盖所有游戏。当前六条帖子仍是编辑样例，无内容可不展示；运营Banner缺素材或跳转无效时隐藏。

## 验证目标与边界

方向1验证服务选择与有效付费入口；方向2验证选中到准备/启动的链路；方向3验证内容继续浏览、订阅和后续回访。本轮为离线Demo与AI场景走查，没有真实用户反馈或已提升转化/留存的结论。
